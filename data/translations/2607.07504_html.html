LLM 培养的技能能否成为更好的人工智能数据科学家？跨数据科学工作流程的组件消融Do LLM-Generated Skills Make Better AI Data Scientists? A Component Ablation Across Data-Science Workflows

Wei-Jung Huang Independent ResearcherUnited States
摘要。Abstract.

产品数据科学家经常要求基于 LLM 的代理帮助执行重复执行任务，例如清理数据、编写 SQL、选择统计测试和格式化结果。可重用的技能文件旨在通过打包任务系列的指导来避免从头开始提示。专家编写的技能可以编码高质量的指导，但在许多数据科学任务系列中编写和维护它们会造成手动瓶颈。我们询问法学硕士生成的技能是否提供了一种有用的低管理替代方案：它们是否比单独的任务提示提高了性能？Product data scientists often ask LLM-based agents to help with recurring execution tasks such as cleaning data, writing SQL, choosing statistical tests, and formatting results. Reusable skill files are meant to avoid prompting from scratch by packaging guidance for a task family. Expert-written skills can encode high-quality guidance, but writing and maintaining them across many data-science task families creates a manual bottleneck. We ask whether LLM-generated skills offer a useful low-curation alternative: do they improve performance over the task prompt alone?

我们在四个生命周期阶段测试这个问题：数据准备、数据提取、统计分析和报告，每个阶段使用一个生成的技能。我们发现，与无技能提示相比，完整生成的技能没有可靠的改进。然后，我们通过消除不同的技能组成部分来询问该技能的任何部分是否有用。主要消融涵盖 56 个任务、9 个模型配置和 3 个提供程序，产生 7,560 次运行。We test this question across four lifecycle stages: data preparation, data extraction, statistical analysis, and reporting, using one generated skill per stage. We find no reliable improvement from full generated skills over No-Skill prompting. We then ask whether any part of the skill is useful by ablating different skill components. The main ablation covers 56 tasks, nine model configurations, and three providers, yielding 7,560 runs.

与单独提示使用任务相比，完整生成的技能或任何消融的技能变体都没有显着提高绩效；全部Compared with prompting using the task alone, neither the full generated skill nor any ablated skill variant significantly improves performance; allpp-值至少为 0.396，并且变体之间的总分布仅为 1.2 pp。补充令牌匹配控件添加了 1,512 次运行，并发现完整技能的表现与任务无关的技能格式内容类似。结果警告不要在每个数据科学工作流程中使用一项法学硕士生成的技能作为默认的单次提示策略。-values are at least 0.396, and the total spread across variants is only 1.2 pp. A supplemental token-matched control adds 1,512 runs and finds that Full skills perform similarly to task-irrelevant skill-formatted content. The results caution against using one LLM-generated skill per data-science workflow as a default single-shot prompting strategy.

1. 简介Introduction

产品数据科学家经常要求基于 LLM 的代理帮助执行重复执行任务：清理数据、编写 SQL、选择统计测试、计算效果大小和格式化报告。根据最近的数据科学自动化基准，我们将这些系统称为数据科学代理Product data scientists often ask LLM-based agents to help with recurring execution tasks: cleaning data, writing SQL, choosing statistical tests, computing effect sizes, and formatting reports. We refer to these systems as data-science agents, following recent benchmarks for data-science automation(Zhang et al., 2025; Lai et al., 2022)。对于这些系统，模型选择只是设计问题的一部分。另一部分是如何提供领域知识。. For these systems, model choice is only part of the design problem. The other part is how to supply domain knowledge.

最近的代理平台和基准测试使用可重用的技能文件，例如Recent agent platforms and benchmarks use reusable skill files, such as技能.mdSKILL.md，打包任务说明、示例和参考注释, to package task instructions, examples, and reference notes(Anthropic, 2025; Li et al., 2026)。对于数据科学代理来说，这构成了一个诱人的工作流程：为重复任务系列（例如数据准备、SQL 生成、统计分析和报告）编写一项技能，然后将其添加到未来的任务中。. For data-science agents, this makes a tempting workflow: write one skill for recurring task families such as data preparation, SQL generation, statistical analysis, and reporting, then prepend it to future tasks.

专家编写的技能可以编码高质量的指导，但它们要求从业者决定要包含的内容、编写示例和参考注释，并随着工具和任务约定的变化保持内容最新。当团队需要许多数据科学任务系列的指导时，这种手动过程的扩展性很差。 LLM 生成的技能提供了一种较低管理的替代方案：生成一次任务系列指导，然后在相关任务中重复使用它。问题是这个低管理版本在实践中是否有效。Expert-written skills can encode high-quality guidance, but they require practitioners to decide what to include, write examples and reference notes, and keep the content current as tools and task conventions change. This manual process scales poorly when teams need guidance for many data-science task families. LLM-generated skills offer a lower-curation alternative: generate task-family guidance once and reuse it across related tasks. The question is whether this low-curation version works in practice.

现有证据表明这并不能得到保证。技能台Existing evidence suggests that this is not guaranteed. SkillsBench(Li et al., 2026)（86 项任务，7,308 条轨迹）发现人工策划的技能可以显着提高绩效（(86 tasks, 7,308 trajectories) found that human-curated skills improve performance substantially (++16.2 页），而法学硕士生成的技能没有提供任何总体效益。然而，SkillsBench 并不专门评估数据科学工作流程的可重用技能。16.2 pp), while LLM-generated skills provide no aggregate benefit. However, SkillsBench does not specifically evaluate reusable skills for data-science workflows.

这个无效结果还引发了一个组件级问题：当法学硕士生成的技能无法提高性能时，是否每个组件都没有帮助，或者有用的部分是否被有害的部分抵消了？对于数据科学代理的构建者来说，询问法学硕士生成的技能是否对数据科学工作流程有帮助以及当它们没有帮助时会出现哪些故障模式是有用的。That null result also raises a component-level question: when an LLM-generated skill fails to improve performance, is every component unhelpful, or are useful sections canceled out by harmful ones? For builders of data-science agents, it is useful to ask both whether LLM-generated skills help on data-science workflows and which failure patterns appear when they do not.

我们在四个面向执行的数据科学生命周期阶段研究这些问题。每个阶段都由涵盖不同工作流程的任务系列表示：We study these questions across four execution-facing data-science lifecycle stages. Each stage is represented by a task family covering a distinct workflow:数据准备data preparation（空处理、重复数据删除、类型强制），(null handling, deduplication, type coercion),数据提取data extraction（SQL查询公式），(SQL query formulation),统计分析statistical analysis（假设检验、效应大小），以及(hypothesis testing, effect sizes), and报告reporting（结构化 JSON 报告）。这些工作流程代表数据科学代理的常见执行任务，并且它们的输出可以由确定性验证器检查。(structured JSON reporting). These workflows represent common execution tasks for data-science agents, and their outputs can be checked by deterministic verifiers.

我们的评估分为两部分。首先，我们将仅任务提示与每个阶段由法学硕士生成的完整技能进行比较。其次，我们消除了相同的技能来测试任何部分本身是否有帮助。我们使用简化的单次设置，以便比较集中在技能内容本身。部分Our evaluation has two parts. First, we compare task-only prompting with one full LLM-generated skill per stage. Second, we ablate the same skills to test whether any section helps on its own. We use a simplified single-shot setup so that the comparison focuses on the skill content itself. Section3描述了这种设计选择。describes this design choice.

  • •

3. 实验设计Experimental Design

3.1. 技能建设Skill Construction

我们使用启用扩展思维的 Gemini 2.5 Pro 编码代理在每个生命周期阶段生成一项技能（总共四项技能）。代理收到目标工作流程、所需的部分结构，以及We generated one skill per lifecycle stage (four skills total) using a Gemini 2.5 Pro coding agent with extended thinking enabled. The agent received the target workflow, required section structure, and技能.mdSKILL.md模式，并且它可以在编写每个完整技能之前研究目标领域和相关基准。每项技能都是在一次自主会话中生成的，无需人工编辑、候选者选择或迭代细化。这是我们研究的低管理工作流程：为任务系列生成一项技能，然后按书面形式重复使用它。schema, and it could research the target domains and related benchmarks before writing each Full skill. Each skill was produced in one autonomous session with no human editing, candidate selection, or iterative refinement. This is the low-curation workflow we study: generate one skill for a task family, then reuse it as written.

每个技能包含四个部分：Each skill contains four sections:

  • •

    路由Routing (∼\sim50 个令牌）：指定何时应用技能的激活触发器50 tokens): activation triggers specifying when to apply the skill

  • •

    核心程序Core Procedure (∼\sim190 个令牌）：分步工作流程说明190 tokens): step-by-step workflow instructions

  • •

    工作示例Worked Examples (∼\sim225 个令牌）：具体输入225 tokens): concrete input→\to输出演示output demonstrations

  • •

    参考注释Reference Notes (∼\sim225 个标记）：补充启发法和约定225 tokens): supplementary heuristics and conventions

这些部分对应于 Anthropic 代理技能文档中的内容类型These sections correspond to the content types in Anthropic’s Agent Skills documentation(Anthropic, 2025)。与 Anthropic 推荐的架构不同，Anthropic 将参考资料存储在按需加载的单独文件中，而我们将所有部分作为单个平面文件注入。我们做出这样的选择是为了隔离内容：实验测试生成的技能内容在模型看到它时是否有帮助，而不是测试单独的加载器是否可以在正确的时间检索正确的文件。因此，该研究不应被解读为选择性加载或渐进披露的评估。该格式还匹配常见的低管理实现：在没有用于多文件包的显式工具的情况下生成的单个 Markdown 文档。. Unlike Anthropic’s recommended architecture, which stores reference materials in separate files loaded on demand, we inject all sections as a single flat file. We make this choice to isolate content: the experiment tests whether generated skill content helps when the model sees it, not whether a separate loader can retrieve the right file at the right time. For this reason, the study should not be read as an evaluation of selective loading or progressive disclosure. The format also matches a common low-curation implementation: a single markdown document produced without explicit tooling for multi-file packages.

消融变体是通过从完整技能中机械删除部分来产生的，而不是通过单独的生成运行来产生。这对于因果解释很重要：技能变体仅在存在的部分方面有所不同。各部分被编写为独立的，因此删除不会留下悬空的交叉引用。这种设计让我们可以将完整技能与删除支持内容的变体进行比较，同时保持基本任务过程和生成源固定。The ablation variants are produced by mechanically deleting sections from the Full skill, not by separate generation runs. This matters for causal interpretation: the skill variants differ only in which sections are present. Sections are written to be self-contained, so deletion does not leave dangling cross-references. This design lets us compare the full skill against variants that remove supporting content, while keeping the basic task procedure and generation source fixed.

3.2. 消融条件Ablation Conditions

我们的消融将工作示例和参考注释视为两个独立的二元因素，而路由和核心程序保持不变。我们将路由和核心程序放在一起，因为如果没有激活触发器和程序步骤，其余部分就缺乏作为连贯技能发挥作用所需的上下文。在我们的设置中，路由也是多余的，因为每个技能仅与其匹配生命周期阶段的任务配对。这产生了四个技能条件加上一个无技能基线：Our ablation treats Worked Examples and Reference Notes as two independent binary factors, with Routing and Core Procedure held constant. We keep Routing and Core Procedure together because, without activation triggers and procedural steps, the remaining sections lack the context needed to function as a coherent skill. Routing is also redundant in our setup because each skill is only paired with tasks from its matching lifecycle stage. This yields four skill conditions plus a No-Skill baseline:

  1. (1)

    无技能No-Skill：仅任务提示: task prompt only

  2. (2)

    仅核心Core-Only：路由+核心流程: Routing + Core Procedure

  3. (3)

    核心+示例Core+Examples：路由+核心程序+工作示例: Routing + Core Procedure + Worked Examples

  4. (4)

    核心+参考Core+Refs：路由+核心流程+参考笔记: Routing + Core Procedure + Reference Notes

  5. (5)

    满Full: 所有四个部分: all four sections

使用固定模板（Skill content is injected unconditionally as a user-message prefix using a fixed template ([技能开始] ... [技能结束][SKILL START] ... [SKILL END]，后跟任务提示）适用于所有条件和提供者。, followed by the task prompt) across all conditions and providers.

无技能基线仅包含任务提示，没有注入的技能包装或控制文本。因此，比较是在单独的相同任务提示和预先添加生成的技能内容的相同任务提示之间进行的。The No-Skill baseline contains only the task prompt, with no injected skill wrapper or control text. Thus, the comparison is between the same task prompt alone and the same task prompt with generated skill content prepended.

长度控制测试了一种更简单的替代解释：模型可能会对长的、技能格式的前缀做出反应，而不是对有用的数据科学指导做出反应。为了测试这一点，我们添加了一个补充Length-Control tests a simpler alternative explanation: the model may react to a long, skill-formatted prefix rather than to useful data-science guidance. To test this, we add a supplemental长度控制Length-Control条件。对于每个生命周期阶段，我们创建一个与任务无关的办公用品设置技能，具有相同的注入包装器、markdown 风格的组织以及相应完整技能 1% 以内的分词器长度。condition. For each lifecycle stage, we create a task-irrelevant office-supply setup skill with the same injection wrapper, markdown-style organization, and tokenizer length within 1% of the corresponding Full skill.

我们使用连贯的办公用品指导，而不是随机的字符串，这可能会造成不切实际的干扰。该控件为模型提供了合理的程序说明、示例和注释，但没有一个旨在帮助数据清理、SQL、统计分析或报告。我们将其视为对照，而不是无害的安慰剂，因为不相关的指令仍然可以改变模型行为。将 Full 与 Length-Control 进行比较，可以估计生成的数据科学内容是否有助于添加类似的长的、技能格式的上下文。We use coherent office-supply guidance rather than random strings, which could create an unrealistic distraction. 我们的研究存在三个主要局限性。首先，范围窄。我们评估了一个领域中的 56 个单轮任务，只有 17 个任务落在信息丰富的 30% 到 80% 基线范围内。 95% 的引导 CI 跨度Our study has three main limitations. First, the scope is narrow. We evaluate 56 single-turn tasks in one domain, and only 17 tasks fall in the informative 30 to 80% baseline range. The 95% bootstrap CIs span±\pm4 至 6 个百分点，因此该研究可以排除中等的平均影响，但不能排除较小的影响（1 至 3 个百分点）。我们也不包括专家编写的或针对特定任务的阳性控制技能；该选择与我们测试的低管理工作流程相匹配，但未测量基准测试对精心编写的技能的敏感性。4 to 6 pp, so the study can rule out moderate average effects but not small effects (1 to 3 pp). We also do not include an expert-written or task-specific positive-control skill; that choice matches the low-curation workflow we test, but leaves the benchmark’s sensitivity to carefully authored skills unmeasured.

其次，该设置不是一个完整的数据科学代理。它省略了需要业务背景或利益相关者判断的多回合规划、工具使用、代码执行、内存、迭代修订和上游产品框架任务。技能放置也是固定的：技能作为用户消息内容预先添加，没有系统级优先级规则、检索门或模式/工具约束。因此，我们的研究结果最直接适用于单次、平面文件、法学硕士生成的、家庭级别的确定性可验证执行任务技能。Second, the setting is not a full data-science agent. It omits multi-turn planning, tool use, code execution, memory, iterative revision, and upstream product-framing tasks that require business context or stakeholder judgment. Skill placement is also fixed: skills are prepended as user-message content, with no system-level priority rule, retrieval gate, or schema/tool constraint. Our findings therefore apply most directly to single-shot, flat-file, LLM-generated, family-level skills on deterministically verifiable execution tasks.

第三，仍然存在一些令人困惑的问题。技能条件增加了提示长度（从无技能的平均 287 个输入标记增加到完整技能的 1,293 个）。长度控制条件减少了对长度单独解释零值的担忧，但它使用一个不相关的域，即办公用品设置，因此它无法表征所有形式的不相关上下文。每个生命周期阶段使用一项生成的技能还将部分效果与四个技能实例联系起来。每个阶段对多个生成的技能进行采样可以估计代际差异，但不再与我们研究的单一候选低管理工作流程相匹配。Third, several confounds remain. Skill conditions increase prompt length (from a mean of 287 input tokens for No-Skill to 1,293 for Full). The Length-Control condition reduces concern that length alone explains the null, but it uses one irrelevant domain, office-supply setup, so it cannot characterize all forms of unrelated context. The use of one generated skill per lifecycle stage also ties section effects to four skill instances. Sampling multiple generated skills per stage would estimate inter-generation variance, but would no longer match the one-candidate low-curation workflow we study.

作者身份也有重叠。 Gemini 2.5 Pro 协助撰写技能并起草自创的任务提示和初始黄金输出，Gemini 2.5 Pro 是评估的模型配置之一。确定性验证、固定黄金文件和任务内条件比较降低了评分直接奖励 Gemini 输出的风险。尽管如此，重叠可能会影响任务风格、格式约定或绝对难度，尤其是对于完全匹配的任务。更简洁的设计将任务创作、技能创作和模型评估分开。There is also an authorship overlap. Gemini 2.5 Pro assisted with skill writing and with drafting the self-authored task prompts and initial gold outputs, and Gemini 2.5 Pro is one of the evaluated model configurations. Deterministic validation, fixed gold files, and within-task condition comparisons reduce the risk that scoring directly rewards Gemini outputs. Still, the overlap could affect task style, formatting conventions, or absolute difficulty, especially for exact-match tasks. A cleaner design would separate task authoring, skill authoring, and model evaluation.

最后，条件翻转审查仅提供了有关机制的部分证据。它可以识别输出遵循任务指令的通用技能启发式的明显情况，但它无法统计技能被忽略、部分使用或与任务内部协调的所有情况。因此，我们将翻转分析报告为诊断性的，而不是完整的指令遵守分类法。Finally, the condition-flip review gives only partial evidence about mechanism. It can identify overt cases where the output follows a generic skill heuristic over the task instruction, but it cannot count all cases where the skill was ignored, partially used, or internally reconciled with the task. We therefore report the flip analysis as diagnostic rather than as a complete instruction-adherence taxonomy.

7. 结论Conclusion

我们评估了当技能直接作为平面提示内容注入时，低管理、法学硕士生成的技能是否可以提高数据科学代理在四个数据科学生命周期阶段的表现。在 56 个任务、九个模型配置和三个提供者中，完整生成的技能或任何消融的技能变体都没有显着优于仅任务基线。令牌匹配控制的性能也与完整技能类似，提示级任务高于技能指令并不能可靠地提高性能。零结果在技能组件和模型组中是一致的，并且与三种诊断模式一致：高基线的冗余、中等基线的冲突启发法以及低基线的统计推理瓶颈。We evaluated whether low-curation, LLM-generated skills improve data-science agent performance across four data-science lifecycle stages when skills are injected directly as flat prompt content. Across 56 tasks, nine model configurations, and three providers, neither the full generated skill nor any ablated skill variant significantly outperforms the task-only baseline. A token-matched control also performs similarly to the full skill, and a prompt-level task-over-skill directive does not reliably improve performance. The null result is consistent across skill components and model groups, and it aligns with three diagnostic patterns: redundancy at high baselines, conflicting heuristics at moderate baselines, and statistical-reasoning bottlenecks at low baselines.

对于构建数据科学代理的从业者来说，这些结果支持谨慎的默认设置：法学硕士生成的家庭级技能注入并没有提高这种单次设置中的性能。接下来的测试应该比较特定任务的技能、选择性加载、系统级优先级规则和执行反馈代理。For practitioners building data-science agents, these results support a cautious default: LLM-generated, family-level skill injection did not improve performance in this single-shot setting. The next tests should compare task-specific skills, selective loading, system-level priority rules, and execution-feedback agents.
