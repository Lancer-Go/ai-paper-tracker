内存可移植性的对照研究A Controlled Study of Memory Portability

Ankit Goyal Email: angoyal@linkedin.com    Jaideep Ray Email: jaray@linkedin.com
摘要Abstract

模型升级是例行公事；内存迁移则不然。代理可以保留相同的内存存储，但仍然会忘记：新模型可能会以不同的方式解释旧笔记，混合嵌入版本可能会破坏检索，并且在没有原始证据的情况下修复可能会失败。我们比较记忆时，相同的历史被逐字保存以进行长上下文阅读（LC-RAW），分为用于检索增强生成（RAG）的块，由模型压缩为自然语言注释（NOTES），或标准化为固定模式知识图（KG-fixed）。该研究使用了 48 个综合历史记录，其中包含随机答案代码、精确评分以及两个具有不到 100 亿个参数的开放权重模型。Model upgrades are routine; memory migrations are not. An agent can keep the same memory store and still forget: a new model may interpret old notes differently, mixed embedding versions may break retrieval, and repair may fail without the original evidence. We compare memory as the same history is preserved verbatim for long-context reading (LC-RAW), divided into chunks for retrieval-augmented generation (RAG), compressed by a model into natural-language notes (NOTES), or normalized into a fixed-schema knowledge graph (KG-fixed). The study uses 48 synthetic histories with randomized answer codes, exact scoring, and two open-weight models with sub 10 billion parameters.

1 简介Introduction

代理需要记忆，因为有用的工作很少适合一次交互。跨领域，这意味着回顾上周的项目决策，保留编码代理的存储库约定和早期工具结果，并跨会话携带偏好、承诺和未完成的任务。模型的上下文窗口提供临时工作上下文，但不是持久状态。随着历史的增长，每回合重播整个历史也会变得缓慢、昂贵，甚至最终不可能。因此，代理系统将选定的经验保留在模型之外，并在需要时带回相关部分。Agents need memory because useful work rarely fits inside one interaction. Across domains, this means recalling last week’s decisions for a project, preserving repository conventions and earlier tool outcomes for a coding agent, and carrying preferences, commitments, and unfinished tasks across sessions. The model’s context window provides temporary working context, but it is not durable state. Replaying an entire history on every turn also becomes slow, expensive, and eventually impossible as the history grows. Agent systems therefore persist selected experience outside the model and bring relevant parts back when needed.

该外部存储成为代理行为的一部分。我们研究四种常见的格式。That external store becomes part of the agent’s behavior. We study four common formats.长上下文原始历史记录 (LC-RAW)Long-context raw history (LC-RAW)保留完整的对话或事件历史记录。keeps the full conversation or event history.检索增强生成 (RAG)Retrieval-augmented generation (RAG)存储转录块并为每个查询检索一小部分。stores transcript chunks and retrieves a small set for each query.模型编写的综合注释（NOTES）Model-written consolidated notes (NOTES)存储压缩的自然语言摘要； NOTES 只是我们对这种格式的标签。stores compressed natural-language summaries; NOTES is simply our label for this format.固定模式知识图（KG-fixed）Fixed-schema knowledge graph (KG-fixed)在每个模型共享的模式下将事实存储为主语-谓语-宾语声明。每种格式都会做出不同的权衡：原始历史记录使用更多上下文，检索可能会错过正确的记录，注释可能会在压缩过程中遗漏证据，而固定模式只能表示其旨在保存的事实。因此，内存不仅仅是附加到代理的数据库。这是一个边界，可能会丢失过去经验和未来决策之间的信息。stores facts as subject–predicate–object claims under a schema shared by every model. Each format makes a different trade-off: raw history uses more context, retrieval can miss the right record, notes can omit evidence during compression, and a fixed schema can represent only the facts it was designed to hold. Memory is therefore not just a database attached to an agent. It is a boundary that can lose information between past experience and future decisions.

边界很重要，因为内存和模型具有不同的生命周期。一个有用的商店可能会积累数月或数年，而它周围的模型变化得更快。团队采用新的语言模型来衡量功能、延迟、成本、上下文长度、安全性或提供商可用性。当检索质量提高时，它们会取代嵌入模型，跨多个模型路由请求，并淘汰旧端点。每次改变后重建每一个历史记忆都可能代价高昂，而且原始证据可能不再存在。在实践中，新模式往往继承旧店。The boundary matters because memory and models have different lifetimes. A useful store may accumulate for months or years, while the models around it change much sooner. Teams adopt new language models for capability, latency, cost, context length, safety, or provider availability. They replace embedding models when retrieval quality improves, route requests across several models, and retire older endpoints. Rebuilding every historical memory after each change can be costly, and the original evidence may no longer exist. In practice, the new model often inherits the old store.

升级代理不应该让它忘记。然而，内存迁移并不总是简单的复制操作。新读者可能会以不同的方式解释另一个模型的注释。新的嵌入器可能会将记录和查询放置在不兼容的向量空间中。修复过程可能会发现合并丢弃了关键事实的唯一副本。部署仍然开始，数据库仍然返回结果，并且不会引发迁移错误。性能只会下降。Upgrading an agent should not make it forget. Yet a memory migration is not always a simple copy operation. A new reader may interpret another model’s notes differently. A new embedder may place records and queries in an incompatible vector space. A repair process may discover that consolidation discarded the only copy of a critical fact. The deployment still starts, the database still returns results, and nothing raises a migration error. Performance simply drops.

这是与普通基准精度不同的可靠性问题。开发人员需要知道当一个组件发生变化时，内存架构是否仍然可用，哪些快捷方式会默默地失败，以及必须保留哪些源数据以进行恢复。如果商店与创建它的模型紧密耦合，那么在第一天表现良好的商店从长远来看仍然可能是一个糟糕的设计。This is a different reliability problem from ordinary benchmark accuracy. Developers need to know whether a memory architecture remains usable when one component changes, which shortcuts fail silently, and what source data must be retained for recovery. A store that performs well on day one can still be a poor long-term design if it is tightly coupled to the model that created it.

4.3 在新模型看到任何内容之前检索可能会失败Retrieval can fail before the new model sees anything

在 RAG 架构中，检索管道有效地充当代理的长期记忆。因此，如果搜索系统一开始就无法提供正确的信息，就不可能评估新的读者模型继承过去经验的能力。即使在任何模型升级之前，我们测试的 RAG 管道也表现出严重的检索瓶颈。虽然我们的原始历史基线 (LC-RAW) 的精度达到 0.712 到 0.911 之间，但 RAG 设置仅达到 0.535 到 0.565。无论读者模型如何，搜索机制仅在大约 60% 的时间内成功地显示必要的证据。我们的诊断故障将 RAG 总准确率缺陷的 81% 直接归因于这种初始检索失误。在指责新的读取器模型“忘记”过去的交互之前，开发人员必须验证内存是否确实被检索和传递。In a RAG architecture, the retrieval pipeline effectively serves as the agent’s long-term memory. Consequently, evaluating a new reader model’s ability to inherit past experiences is impossible if the search system fails to deliver the right information in the first place. Even before any model upgrade, our tested RAG pipeline exhibited significant retrieval bottlenecks. While our raw history baseline (LC-RAW) achieves accuracies between 0.712 and 0.911, the RAG setup reaches only 0.535 to 0.565. The search mechanism successfully surfaces the necessary evidence only about 60% of the time, regardless of the reader model. Our diagnostic breakdown attributes 81% of RAG’s total accuracy deficit directly to this initial retrieval miss. Before blaming a new reader model for “forgetting” past interactions, developers must verify that the memory was actually retrieved and delivered.

我们并不认为 40% 的丢失率是 RAG 架构的普遍限制。我们的设计有意使用基于事件的块、余弦顶评估单级密集检索器We do not present this 40% miss rate as a universal limitation of RAG architectures. Our design intentionally evaluates a single-stage dense retriever using event-based chunks, cosine top-k=8k{=}8，并且没有重新排序或词法搜索。尽管更复杂的检索系统可能会产生更好的绝对性能，但基本设计原则仍然存在：分块和搜索性能必须独立于读者模型进行评估。一个能力很强的读者根本无法综合他从未收到过的证据。, and no reranker or lexical search. Although a more sophisticated retrieval system would likely yield better absolute performance, the fundamental design principle remains: chunking and search performance must be evaluated independently of the reader model. A highly capable reader simply cannot synthesize evidence it never receives.

当嵌入模型本身升级时，检索失败也会严重影响内存存储。随着系统的发展，团队经常采用更好的嵌入模型，但尝试通过在同一数据库中混合新旧向量来进行部分迁移会破坏检索机制。Retrieval failures also severely impact the memory store when the embedding model itself is upgraded. As systems evolve, teams frequently adopt better embedding models, but attempting a partial migration by mixing old and new vectors in the same database breaks the retrieval mechanism.

当我们用新的 v1.5 模型完全重新嵌入每个块时，与旧的 v1.0 索引相比，准确度跃升了 11.90 个点。然而，50/50 混合指数仅提高了 4.96 点，损失了近 60% 的潜在升级收益。由于新旧模型均输出 1024 维向量，因此系统会继续运行并静静地失败，不会触发任何维度兼容性错误。这种空间不兼容性会降低召回率和排名，从而有效地导致代理“忘记”存储为旧向量的经验。When we fully re-embed every chunk with the newer v1.5 model, accuracy jumps by 11.90 points compared to the old v1.0 index. However, a 50/50 mixed index captures an improvement of only 4.96 points, hemorrhaging nearly 60% of the potential upgrade gain. Because the old and new models both output 1024-dimensional vectors, the system continues running and fails silently without triggering any dimensional compatibility errors. This spatial incompatibility degrades recall and ranking, effectively causing the agent to “forget” the experiences stored as older vectors.

为了安全迁移，工程团队应该使用新的嵌入模型构建和测试一个完全独立的索引，仅在完成后进行切换。如果需要逐步过渡，系统必须隔离两个向量空间并根据已知的索引版本路由查询。虽然我们测量的确切精度损失属于我们特定的 v1.0 到 v1.5 测试，但潜在的空间不兼容性对增量 RAG 迁移构成了广泛的威胁。To migrate safely, engineering teams should build and test an entirely separate index with the new embedding model, cutting over only upon completion. If a gradual transition is necessary, systems must silo the two vector spaces and route queries based on the known index version. While the exact accuracy penalty we measured belongs to our specific v1.0-to-v1.5 test, the underlying spatial incompatibility poses a broad threat to incremental RAG migrations.

4.6 研究结果的范围和局限性Scope and limits of the findings

尽管这些发现提供了实用的设计信号，但它们受到此处测试的配置的限制。Although these findings provide practical design signals, they are bounded by the configurations tested here.

Deployment performance will depend on how well the schema represents the target task and how the store is read.

对于检索和修复，报告的值反映了特定的管道选择。 40% 的检索丢失率和 50/50 混合索引的降级适用于在两个相同维度嵌入空间之间迁移的单级密集检索器；其他检索系统和迁移计划可能会产生不同的保留级别。保留的原始历史记录仅支持在一个迁移方向上进行恢复，这表明重建还取决于修复模型的功能和资源限制。保留完整历史记录还会产生隐私、安全、保留和删除义务，这些义务必须在系统设计中解决。For retrieval and repair, the reported values reflect specific pipeline choices. The 40% retrieval miss rate and the degradation from a 50/50 mixed index apply to a single-stage dense retriever migrating between two same-dimensional embedding spaces; other retrieval systems and migration plans may produce different retention levels. 5 跨模型转换的代理内存兼容性Agent Memory Compatibility Across Model Transitions

一个有用的内存系统必须适用于当今的模型，并且在模型更改后仍然可用。A useful memory system must work with today’s model and remain usable after the model changes.

  1. 1.

    长期记忆需求塑造迁移行为。Long-term memory requirements shape migration behavior.我们的实验表明，当明确定义预期持续存在的信息时，模型转换更容易评估。模型更改后，不同类别的信息（例如事实、偏好、决策和未完成的任务）可能会表现出不同的故障模式。Our experiments suggest that model transitions are easier to assess when the information expected to persist is defined explicitly. Different classes of information, such as facts, preferences, decisions, and unfinished tasks, may exhibit different failure patterns after a model change.

  2. 2.

    内存表示以不同的方式失败。Memory representations fail in different ways.原始历史、检索到的段落、模型书写的笔记和结构化记录显示了在保真度、紧凑性和与新读者的兼容性方面的不同权衡。特别是，压缩表示可能会丢失迁移后无法重建的信息。Raw history, retrieved passages, model-written notes, and structured records showed different tradeoffs in fidelity, compactness, and compatibility with a new reader. In particular, compressed representations may lose information that cannot be reconstructed after migration.

  3. 3.

    可恢复性取决于系统保留的证据。Recoverability depends on the evidence retained by the system.我们观察到，当幸存内存仅包含派生摘要时，迁移失败更难分析。在政策允许的情况下，访问更完整的证据来源可以区分信息丢失和读者不兼容。We observed that migration failures are harder to analyze when the surviving memory contains only derived summaries. Access to a more complete evidence source, where permitted by policy, can make it possible to distinguish information loss from reader incompatibility.

  4. 4.

    内存来源改进了故障分析。Memory provenance improves failure analysis.用于构建内存存储的模型、提示、架构、嵌入模型、分块过程或索引配置的差异可能会影响后续模型对其的解释方式。记录此上下文使观察到的回归更容易归因。Differences in the model, prompt, schema, embedding model, chunking procedure, or index configuration used to construct a memory store can affect how a later model interprets it. Recording this context makes observed regressions easier to attribute.

  5. 5.

    兼容性特定于模型转换的方向。Compatibility is specific to the direction of the model transition.新模型读取早期模型生成的内存时的性能可能与相反方向的性能不同。因此，跨转换的平均可以隐藏大量的方向故障。Performance when a new model reads memory produced by an earlier model may differ from performance in the reverse direction. Averaging across transitions can therefore conceal substantial directional failures.

  6. 6.

    嵌入的变化会影响检索，而与读者的质量无关。Embedding changes can affect retrieval independently of reader quality.在我们的实验中，即使底层记忆内容没有改变，模型转换也可能改变呈现给读者的证据。因此，仅评估最终答案可能会错过迁移期间引入的检索回归。In our experiments, a model transition could alter the evidence presented to the reader even when the underlying memory content was unchanged. Evaluating only the final answer may therefore miss retrieval regressions introduced during migration.

  7. 7.

    迁移失败发生在内存路径的多个阶段。Migration failures arise at multiple stages of the memory path.观察到的错误可能是由于未保留信息、未检索到相关证据或读者未能正确使用检索到的证据而导致的。这些失效模式在实验上是不同的，否则可能会被混淆。Observed errors could result from information not being retained, relevant evidence not being retrieved, or the reader failing to use retrieved evidence correctly. These failure modes are experimentally distinct and may otherwise be conflated.

  8. 8.

    转换后检查提供了有用的兼容性证据。Post-transition checks provide useful evidence of compatibility.升级后的小型评估可能会立即暴露回归，而更广泛的实验可以更可靠地评估继承的记忆在现实历史和输出限制下是否仍然可用（附录Small evaluations after an upgrade can expose immediate regressions, while broader experiments provide a more reliable assessment of whether inherited memory remains usable under realistic history and output constraints (AppendixC).

内存最好被视为代理的长期存在的部分，而不是当前模型的临时输出。好的设计可以保留重要的证据，记录商店是如何建造的，并为未来的模型读取或重建它提供经过测试的路径。Memory is best treated as a long-lived part of the agent rather than temporary output from the current model. A good design preserves important evidence, records how the store was built, and provides a tested path for future models to read or rebuild it.

6 结论Conclusion

将模型升级视为内存迁移，而不是简单的替换。在旧存储上测试新模型，完全重建矢量索引，在策略允许的情况下保留受保护的源历史记录，并在选择修复之前确定信息在写入、检索或读取过程中是否丢失。Treat a model upgrade as a memory migration, not as a simple replacement. Test the new model on the old store, rebuild vector indexes completely, keep a protected source history when policy allows, and identify whether information was lost during writing, retrieval, or reading before choosing a repair.

耐用的内存系统应该比创建它的模型更耐用。未来的模型应该能够读取它，检查其来源，并在必要时重建它。评估代码、历史记录、存储、签署的研究计划和运行记录可根据要求提供。A durable memory system should outlast the model that created it.
