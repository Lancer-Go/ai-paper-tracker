评估软件演进下基于 LLM 的测试生成Evaluating LLM-Based Test Generation Under Software Evolution

Sabaat Haroon Virginia TechUSA , Mohammad Taha Khan Carnegie Mellon UniversityUSA and Muhammad Ali Gulzar Virginia TechUSA
摘要。Abstract.

大型语言模型 (LLM) 越来越多地用于自动化单元测试生成。然而，目前尚不清楚这些测试是否反映了程序行为的真实推理，或者只是再现了训练期间学到的表面模式。如果后者占主导地位，LLM 生成的测试可能会表现出重要的弱点，包括覆盖范围缩小、错过回归和未检测到的错误。因此，了解法学硕士如何为程序生成测试以及这些测试如何响应代码演变至关重要。在这项工作中，我们提出了程序演化下基于 LLM 的测试生成的大规模实证研究。使用自动化突变驱动框架，我们分析生成的测试如何对语义更改更改（SAC）和语义保留更改（SPC）做出反应。我们的评估涵盖八个法学硕士和源自广泛使用的基准的 22,374 个程序变体。Large Language Models (LLMs) are increasingly used for automated unit test generation. However, it remains unclear whether these tests reflect genuine reasoning about program behavior or simply reproduce superficial patterns learned during training. If the latter dominates, LLM-generated tests may exhibit important weaknesses, including reduced coverage, missed regressions, and undetected faults. Understanding how LLMs generate tests for a program and how those tests respond to code evolution is therefore essential. In this work, we present a large-scale empirical study of LLM-based test generation under program evolution. Using an automated mutation-driven framework, we analyze how generated tests react to semantic-altering changes (SAC) and semantic-preserving changes (SPC). Our evaluation spans eight LLMs and 22,374 program variants derived from widely used benchmarks.

法学硕士取得了强劲的基线结果，达到了 79% 的线路覆盖率和 76% 的分支覆盖率，并完全通过了原始程序的测试套件。然而，随着程序的发展，性能会下降。在 SAC 下，新生成的测试通过率下降至 66%，分支覆盖率下降至 60%。超过 99% 的失败 SAC 测试在执行修改区域时会通过原始程序，这表明与原始程序行为的残余对齐，而不是适应更新的语义。尽管功能不变，但 SPC 下的性能也会下降：测试通过率下降至 79%，分支覆盖率下降至 69%。 SPC 编辑通常会比 SAC 编辑引入更大的语法更改，同时保留语义，但它们会在生成的测试套件中引发更大的不稳定性。平均而言，模型会产生 1.2 倍多的新测试，同时丢弃许多基线测试，这表明对词汇变化的敏感性而不是真正的语义影响。总体而言，我们的研究结果表明，当前基于法学硕士的测试生成严重依赖于表面线索，并且随着程序的发展，很难保持回归意识。LLMs achieve strong baseline results, reaching 79% line coverage and 76% branch coverage with fully passing test suites on the original programs. However, performance degrades as programs evolve. Under SACs, the pass rate of newly generated tests drops to 66%, and branch coverage declines to 60%. More than 99% of failing SAC tests pass on the original program while executing the modified region, indicating residual alignment with the original program behavior rather than adaptation to the updated semantics. Performance also drops under SPCs, despite unchanged functionality: test pass rates fall to 79% and branch coverage to 69%. SPC edits typically introduce larger syntactic changes than SAC edits while preserving semantics, yet they trigger greater instability in generated test suites. On average, models produce 1.2× more new tests while discarding many baseline tests, suggesting sensitivity to lexical changes rather than true semantic impact. Overall, our findings show that current LLM-based test generation relies heavily on surface-level cues and struggles to maintain regression awareness as programs evolve.

1. 简介Introduction

大型语言模型 (LLM) 越来越多地集成到软件工程工作流程中，自动测试生成成为一个突出的用例Large Language Models (LLMs) are increasingly integrated into software engineering workflows, with automated test generation emerging as a prominent use case(Fan et al., 2023)。早期研究和基准测试表明，法学硕士可以为众所周知的公共编程任务生成语法有效且通常语义正确的测试用例. Early studies and benchmarks suggest that LLMs can generate syntactically valid and often semantically correct test cases for well-known public programming tasks(Chudic and Çalıklı, 2026; Xia et al., 2024; Lops et al., 2025; Jiang et al., 2024)。然而，生成完整且可靠的自动化测试套件需要对控制流、执行路径以及所提供实现的特定功能状态进行深入推理。现实世界的软件本质上是动态的，代码经常被重用、重构和稍微调整以服务于不同的功能目的。当开发人员向法学硕士提供此修改后的代码以生成高覆盖率测试套件时，他们希望生成的测试能够准确反映当前代码。. However, producing complete and reliable automated test suites requires deep reasoning about control flow, execution paths, and the specific functional state of the provided implementation. Real-world software is inherently dynamic, code is frequently reused, refactored, and slightly tweaked to serve different functional purposes. When developers supply this modified code to an LLM to generate a high-coverage test suite, they expect the resulting tests to accurately reflect the current code.

问题。Problem.当前基于 LLM 的测试生成的研究很大程度上忽视了代码演化如何影响模型的稳健性和行为Current studies on LLM-based test generation largely overlook how code evolution impacts model robustness and behavior(Siddiq et al., 2025; Jiang et al., 2024; Schäfer et al., 2023)。这一差距留下了一个关键问题：法学硕士是否真正理解所提供代码的语义，或者他们是否对预训练中看到的程序进行浅层模式复制？. This gap leaves a critical question: do LLMs genuinely comprehend the semantics of the provided code, or are they performing shallow pattern replication of programs seen in pre-training?

考虑这样一个场景：开发人员采用现有的开源功能并进行细微的语义更改修改以使其适应新的用例。即使明确提示为此新代码生成高覆盖率测试，理想的测试生成器（例如随机测试生成器Consider a scenario in which a developer takes an existing open-source function and makes a minor semantic-altering modification to adapt it to a new use case. Even when explicitly prompted to generate high-coverage tests for this new code, an ideal test generator (e.g., random test generators(Pacheco et al., 2007), 模糊器, Fuzzers(Manes et al., 2019; Xia et al., 2024)或符号执行or Symbolic execution(Cadar et al., 2008)）应适应所提供的逻辑。然而，如果法学硕士严重依赖记忆的结构，它可能会隐含地假设修改后的代码是原始程序的“有缺陷”版本。它还可能完全忽略代码更改的语义含义。因此，它可能会生成在所提供的代码上失败的测试用例，但矛盾的是在训练期间看到的原始的、未修改的版本上传递了。相反，如果开发人员应用语义保留突变，例如重命名变量或重构逻辑而不更改输出，则生成的测试覆盖率和通过率应保持稳定。如果法学硕士无法在这些无害的词汇变化下保持弹性，那么它在实际测试生成场景中的效用就会受到影响。) should adapt to the provided logic. However, if the LLM relies heavily on memorized structures, it may implicitly assume the modified code is a ”buggy” version of the original program. It may also completely overlook the semantic implication of the code change. Consequently, it might generate test cases that fail on the provided code but paradoxically pass on the original, unmodified version seen during training. Conversely, if a developer applies a semantic-preserving mutation, such as renaming variables or refactoring logic without changing the output, the generated test coverage and passing rates should remain stable. If an LLM cannot maintain resilience under these harmless lexical changes, its utility in real-world test generation scenarios is compromised.

目前的技术水平。Current State of the Art.传统测试生成系统Traditional test generation systems(Fraser and Arcuri, 2011; Lukasczyk et al., 2020; Kovalenko and others, 2023; Rho et al., 2024)和模糊器and fuzzers(Xia et al., 2024; Manes et al., 2019)，旨在最大化代码覆盖率，而现代 LLM 代码生成基准（例如 HumanEval、LiveCodeBench）几乎完全专注于代码生成任务中的功能正确性, are designed to maximize code coverage, while modern LLM code generation benchmarks (e.g., HumanEval, LiveCodeBench) focus almost exclusively on functional correctness in code generation tasks(Du et al., 2024)。这两种方法都没有描述法学硕士的测试生成行为如何随着软件的发展而变化。尽管突变测试是评估测试套件充分性的标准技术，但它尚未系统地适应于评估程序更改下基于 LLM 的测试生成。目前尚不清楚法学硕士是否能够成功地使测试适应功能变化，同时保持对不影响行为的变化的弹性。. Neither approach characterizes how an LLM’s test generation behavior shifts as software evolves. Although mutation testing is a standard technique for assessing test suite adequacy, it has not been systematically adapted to evaluate LLM-based test generation under program changes. It is currently unknown whether LLMs can successfully adapt tests to functional changes while remaining resilient against changes that do not affect behavior.

贡献。Contributions.评估基于 LLM 的测试生成的一个挑战是区分真正的语义推理与训练期间观察到的模式的一致性。仅靠静态基准的高覆盖率无法解决这个问题。模型可能看起来有效，只是因为被测试的程序类似于训练期间遇到的实现，允许它重现熟悉的测试结构，而无需推理特定的代码实例。为了解决这一限制，我们评估了受控程序变更下的法学硕士行为。A challenge in evaluating LLM-based test generation is distinguishing genuine semantic reasoning from alignment with patterns observed during training. High coverage on static benchmarks alone cannot resolve this question. A model may appear effective simply because the program under test resembles implementations encountered during training, allowing it to reproduce familiar test structures without reasoning about the specific code instance. To address this limitation, we evaluate LLM behavior under controlled program changes.

我们引入了一个突变驱动的评估框架，该框架应用两类代码更改。We introduce a mutation-driven evaluation framework that applies two classes of code changes.语义改变的变化Semantic-altering changes（SAC）产生具有修改行为的程序变体，要求测试适应新的语义。(SACs) produce program variants with modified behavior, requiring tests to adapt to new semantics.语义保留的变化Semantic-preserving changes(SPC) 修改代码表面，同时保留功能。由于程序行为保持不变，SPC 下的降级揭示了对结构或词汇变化的敏感性，而不是语义推理。通过分析两种变更类型下的 LLM 行为，我们可以区分性能差异是否源于语义误解或对肤浅代码模式的依赖。这种双重视角使我们能够描述基于 LLM 的测试生成的三个属性：对语义变化的敏感性、对非功能性结构变化的弹性以及在不断发展的程序中生成的测试套件的稳定性。(SPCs) modify the code surface while preserving functionality. Because the program behavior remains unchanged, degradation under SPCs reveals sensitivity to structural or lexical variation rather than semantic reasoning. By analyzing LLM behavior under both change types, we isolate whether performance differences arise from semantic misunderstanding or reliance on superficial code patterns. This dual perspective allows us to characterize three properties of LLM-based test generation: sensitivity to semantic change, resilience to non-functional structural change, and stability of generated test suites across evolving programs.

我们设计了一个自动化的端到端评估框架，可以生成基线测试、测量覆盖范围、注入 SAC 和 SPC，并评估跨程序变体的测试质量。除了覆盖率指标之外，我们还分析失败的测试，以确定它们的断言是否与变异的程序行为或原始程序语义一致。这种分析使我们能够直接评估 LLM 生成的测试是否反映了有关程序行为或浅层模式复制的真实推理 - 静态公共基准无法提供的见解。We design an automated end-to-end evaluation framework that generates baseline tests, measures coverage, injects SACs and SPCs, and evaluates test quality across program variants. Beyond coverage metrics, we analyze failing tests to determine whether their assertions align with the mutated program behavior or with the original program semantics. This analysis enables us to directly assess whether LLM-generated tests reflect true reasoning about program behavior or shallow pattern replication—insights that static public benchmarks cannot provide.

Consequently, the average test match rate between the baseline and the mutated code is a mere 29.3%. Although semantic-preserving changes leave the underlying program semantics unchanged, LLMs exhibit even higher churn (22.7 tests per evaluation), generating 11.8 new tests and discarding 10.9 existing ones. And since the overall coverage of the regenerated test suite after SPCs always decreases, the discarded tests were more coverage-effective than the newly generated ones.

6. 讨论Discussion

我们的研究结果揭示了关于不断发展的代码下基于 LLM 的测试生成行为的两个关键见解。首先，这些模型严重依赖于表面层的句法线索，而不是变化的真正语义影响。因此，即使程序行为保持不变，结构重构也会显着破坏生成的测试套件。其次，更大的表面级编辑似乎使模型远离简单的模式匹配，并鼓励它们尝试对代码逻辑进行更深入的推理。这表明代码更改的程度强烈影响法学硕士如何解释和响应修改后的程序。The results of our study reveal two key insights about the behavior of LLM-based test generation under evolving code. First, the models rely heavily on surface-level syntactic cues rather than the true semantic impact of a change. As a result, even when program behavior remains unchanged, structural refactorings can significantly disrupt the generated test suites. Second, larger surface-level edits appear to push the models away from simple pattern matching and encourage them to attempt deeper reasoning about the code logic. This suggests that the magnitude of code changes strongly influences how LLMs interpret and respond to modified programs.

这些观察结果指出了改进法学硕士驱动的测试生成的潜在方向。一种有前途的方法是在将代码更改呈现给模型之前对其进行预处理。例如，计算代码差异并明确突出显示修改的区域可以帮助引导模型将注意力集中到程序的各个部分。先前关于生成代码差异和自动提交消息的自然语言摘要的工作These observations point toward potential directions for improving the LLM-driven test generation. One promising approach is to preprocess code changes before presenting them to the model. For example, computing a code diff and explicitly highlighting the modified regions could help guide the model’s attention toward the parts of the program. Prior work on generating natural language summaries of code diffs and automated commit messages(Lin and others, 2024; Zhang et al., 2024)也可能有助于传达修改背后的意图may also help communicate the intent behind modifications(Fang et al., 2025)，使模型能够更好地理解程序行为是如何演变的。此外，静态程序分析技术可以提取结构信息，例如程序版本之间的控制流和数据流差异，从而提供有关更改的功能影响的更清晰的信号。 总的来说，这些方向表明未来的系统应该纳入帮助法学硕士推理代码更改的幅度和性质的机制，而不是仅仅依赖于原始源代码输入。, enabling the model to better understand how program behavior has evolved. Additionally, static program analysis techniques could extract structural information such as control-flow and data-flow differences between program versions, providing a clearer signal about the functional impact of the change. Overall, these directions suggest that future systems should incorporate mechanisms that help LLMs reason about the magnitude and nature of code changes rather than relying solely on raw source code inputs.

7. 有效性的威胁Threats to Validity

内部有效性：Internal Validity:为了降低 SPC 期间添加意外功能变化的风险，我们根据原始基线测试套件测试更新后的代码，并验证原始代码的 100% 通过率，确保 SPC 行为中立，不会导致任何功能变化。另一个威胁是大型语言模型固有的非确定性。模型输出可能因尝试而异，可能会影响测试通过率和覆盖率指标。我们通过为每个生成任务使用新的、独立的模型实例来解决这个问题，以防止上下文泄漏，严格评估即时输出以捕获模型的基线推理。To mitigate the risk of adding unintended functional shifts during SPCs, we test updated code against the original baseline test suites and verify a 100% pass rate on the original code, ensuring that SPCs are behavior-neutral and do not cause any functional shifts. Another threat is the inherent non-determinism of Large Language Models. Model outputs can vary across attempts, potentially affecting test pass rates and coverage metrics. We addressed this by using fresh, independent model instances for each generation task to prevent context leakage, strictly evaluating immediate outputs to capture the models’ baseline reasoning.

外部有效性：External Validity:我们的评估基于来自 Project CodeNet 数据集的 22,374 个程序变体，特别关注 Java 和 Python 实现。虽然这些代表了广泛使用的语言和常见的算法任务，但研究结果可能无法完全推广到存在深层上下文依赖关系的高度复杂的多文件企业代码库。然而，由于模型已经很难在这些相对简单、独立的程序上维持语义基础，因此我们认为观察到的性能下降是保守的基线，引入更大的架构复杂性可能只会进一步降低测试可靠性。此外，我们的研究评估了 8 个最先进的法学硕士的特定子集。随着模型架构的快速发展，未来的迭代可能会对代码发展表现出不同的敏感性。Our evaluation is grounded in 22,374 program variants sourced from the Project CodeNet dataset, focusing specifically on Java and Python implementations. While these represent widely used languages and common algorithmic tasks, the findings may not fully generalize to highly complex, multi-file enterprise codebases where deep contextual dependencies exist. However, because the models already struggle to maintain semantic grounding on these relatively simple, self-contained programs, we consider our observed performance degradation to be a conservative baseline, introducing greater architectural complexity would likely only further reduce test reliability. Additionally, our study evaluates a specific subset of 8 state-of-the-art LLMs. As model architectures rapidly evolve, future iterations could display different sensitivities to code evolution.

构造有效性：Construct Validity:我们依靠线路覆盖率、分支覆盖率和测试通过率来评估测试套件的质量。虽然这些是标准的测试质量指标，但它们并不能完全捕获测试套件的故障查找能力或确切的开发人员意图。然而，在评估语义基础和残差对齐的背景下，这些指标与我们的故障归因分析相结合，为量化模型对功能和结构变化的敏感性提供了一个稳健且客观的框架。We relied on line coverage, branch coverage, and test pass rates to evaluate test suite quality. While these are standard test quality metrics, they do not fully capture a test suite’s fault-finding capability or the exact developer intent. However, in the context of evaluating semantic grounding and residual alignment, these metrics, combined with our failure attribution analysis, provide a robust and objective framework for quantifying the models’ sensitivity to functional and structural changes.

8. 结论Conclusion

我们研究了代码更改如何影响基于 LLM 的测试生成的可靠性。我们对超过 22,374 个程序变体使用自动突变驱动的评估框架，评估语义改变和语义保留变化下的模型行为。虽然法学硕士在未修改的程序上实现了强大的基线性能（完全通过测试的 79.3% 行覆盖率和 76.1% 分支覆盖率），但一旦引入代码更改，测试质量就会大幅下降。在语义改变的变化下，许多生成的测试仍然与原始程序行为保持一致，超过 99% 的失败测试通过了原始代码。在保留语义的变化下，尽管功能不变，覆盖率和通过率却下降。这些结果表明，当前基于 LLM 的测试生成无法推理代码更改的语义影响，而是主要响应代码中语法差异的大小。We examined how code changes affect the reliability of LLM-based test generation. Using an automated mutation-driven evaluation framework on over 22,374 program variants, we evaluate model behavior under both semantic-altering and semantic-preserving changes. While LLMs achieve strong baseline performance on unmodified programs (79.3% line and 76.1% branch coverage with fully passing tests), test quality degrades substantially once code changes are introduced. Under semantic-altering changes, many generated tests remain aligned with the original program behavior, with over 99% of failing tests passing on the original code. Under semantic-preserving changes, coverage and pass rates decline despite unchanged functionality. These results suggest that current LLM-based test generation fails to reason about the semantic impact of code changes and instead responds mainly to the magnitude of syntactic differences in the code.
