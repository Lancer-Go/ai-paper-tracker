摘要。Abstract.

矩阵扩展已成为现代 CPU 的一项基本功能，可满足人工智能工作负载不断增长的需求。然而，现有的设计常常会产生大量的硬件和软件设计开销。与CPU管道的紧密耦合使不同CPU之间的集成变得复杂，而细粒度同步指令阻碍了高性能内核的开发。Matrix extensions have emerged as an essential feature in modern CPUs to address the surging demands of AI workloads. However, existing designs often incur substantial hardware and software design overhead. Tight coupling with the CPU pipeline complicates integration across diverse CPUs, while fine-grained synchronous instructions hinder the development of high-performance kernels.

本文提出了一种统一的、可配置的CPU矩阵扩展架构。通过将矩阵单元与 CPU 管道解耦，该设计可实现低开销集成，同时保持与现有计算和内存资源的密切协调。可配置矩阵单元支持混合精度运算，并适应不同的计算需求和内存带宽限制。具有灵活粒度的异步矩阵乘法抽象隐藏了硬件细节，简化了矩阵向量重叠，并支持统一的软件堆栈。This paper proposes a unified and configurable CPU matrix extension architecture. By decoupling matrix units from the CPU pipeline, the design enables low-overhead integration while maintaining close coordination with existing compute and memory resources. The configurable matrix unit supports mixed-precision operations and adapts to diverse compute demands and memory bandwidth constraints. An asynchronous matrix multiplication abstraction with flexible granularity conceals hardware details, simplifies matrix-vector overlap, and supports a unified software stack.

1. 简介Introduction

人工智能技术的快速发展推动了自然语言处理、计算机视觉、多模态生成和体现智能等领域的广泛部署，涵盖从边缘设备到数据中心的平台The rapid advancement of AI technologies has driven widespread deployment across domains such as natural language processing, computer vision, multimodal generation, and embodied intelligence, spanning platforms from edge devices to data centers(Reddi et al., 2020; Martínez et al., 2026)。作为通用计算系统的基础组件，CPU 在执行各种人工智能任务中继续发挥着关键作用. As a foundational component of general-purpose computing systems, CPUs continue to play a critical role in executing diverse AI tasks(Chen et al., 2025)。为了满足矩阵密集型计算不断增长的需求，CPU 供应商集成了矩阵扩展，包括 Intel AMX. To address the surging demand for matrix-intensive computation, CPU vendors have integrated matrix extensions including Intel AMX(Intel, 2024), 手臂中小企业, Arm SME(Remke and Breuer, 2024)、IBM MMA, and IBM MMA(Moreira et al., 2021)转化为产品。 RISC-V社区还提出了IME等多个矩阵扩展标准into products. The RISC-V community has also proposed several matrix extension standards such as IME(Araujo et al., 2025),VME, VME(Favor, 2025)，和 AME, and AME(Sene and Tomsich, 2023)。这些扩展有效地利用现有的计算和内存资源，特别是向量单元和缓存子系统，以适度的面积和功耗开销显着增强人工智能性能。. These extensions effectively leverage existing compute and memory resources, particularly vector units and cache subsystems, to significantly enhance AI performance with modest area and power overheads.

然而，现有的CPU矩阵扩展对硬件集成和软件可编程性提出了挑战However, existing CPU matrix extensions pose challenges for hardware integration and software programmability(Van Delm et al., 2025)。在架构上，矩阵单元通常与 CPU 管道紧密耦合，需要与向量寄存器文件或加载存储单元密切交互。细粒度同步矩阵指令引入了大量的结构和数据危险，增加了集成复杂性和验证工作量。这种耦合限制了跨微架构的可移植性。在软件方面，人工智能工作负载通常将矩阵乘法与大量逐元素运算相结合，需要矩阵和向量单元之间的密切协调。在单个指令流中表达这种细粒度的交错给程序员和编译器带来了巨大的负担，使内核设计和调度变得复杂。. Architecturally, matrix units are often tightly coupled with the CPU pipeline, entailing close interaction with vector register files or load-store units. Fine-grained synchronous matrix instructions introduce substantial structural and data hazards, increasing integration complexity and verification effort. This coupling limits portability across microarchitectures. On the software side, AI workloads typically combine matrix multiplication with a large number of element-wise operations, requiring close coordination between matrix and vector units. Expressing such fine-grained interleaving within a single instruction stream places significant burden on both programmers and compilers, complicating kernel design and scheduling.

为了应对这些挑战，本文提出了一种统一的、可配置的CPU矩阵扩展架构，旨在实现跨平台的敏捷集成和高效执行。矩阵单元与 CPU 管道仔细解耦，以避免对寄存器文件和内存路径进行侵入性修改，从而降低协同设计和验证的复杂性。为了适应不同的计算和带宽约束，它支持由计算带宽约束模型引导的灵活的微架构配置，并且可以从 0.5 TOPS 扩展到 32 TOPS，以保证资源利用率和平台适应性。矩阵单元支持FP8/INT8/FP16/BF16/TF32混合精度计算，以满足不同的精度和性能要求。对于ISA和编程模型，仅定义了异步矩阵乘法和同步原语，形成支持灵活粒度的最小且统一的接口。这种抽象隐藏了特定于硬件的细节，并简化了重叠矩阵向量执行的编程，提高了可编程性并支持可移植的软件堆栈。To address these challenges, this paper proposes a unified and configurable CPU matrix extension architecture designed for agile integration and efficient execution across platforms. The matrix unit is carefully decoupled from the CPU pipeline to avoid intrusive modifications to register files and memory paths, reducing co-design and verification complexity. To accommodate diverse compute and bandwidth constraints, it supports flexible microarchitectural configurations guided by a compute-bandwidth constraint model, and can be scaled from 0.5 to 32 TOPS to guarantee resource utilization and platform adaptability. The matrix unit supports FP8/INT8/FP16/BF16/TF32 mixed-precision computing to meet varying accuracy and performance requirements. As for ISA and programming model, only an asynchronous matrix multiplication and a synchronization primitive are defined, forming a minimal and unified interface that supports flexible granularity. This abstraction hides hardware-specific details and simplifies the programming of overlapped matrix-vector execution, improving programmability and enabling a portable software stack.

2. 背景Background

2.1. 人工智能工作负载AI Workloads

人工智能工作负载已广泛部署在从边缘设备到数据中心的各种计算平台上。典型的模型由具有异构特征的层组成。计算密集型层（例如，线性、注意力、卷积）以矩阵乘法为主，而逐元素操作（例如，激活、（去）量化、归一化）通常是内存密集型的。AI workloads have been widely deployed across diverse computing platforms, from edge devices to data centers. Typical models consist of layers with heterogeneous characteristics. Compute-intensive layers (e.g., linear, attention, convolution) are dominated by matrix multiplications, while element-wise operations (e.g., activation, (de)quantization, normalization) are generally memory intensive.

Kernel fusion(Lefaudeux et al., 2022; Dao et al., 2022; Dao, 2023)通过利用数据局部性并将运算符融合到平铺管道中来增强整体性能，从而减少内存流量并提高资源利用率。enhances overall performance by exploiting data locality and fusing operators into tiled pipelines, thereby reducing memory traffic and improving resource utilization.

2.2. 相关工作Related Work

近年来，CPU 供应商（包括 Intel、Arm 和 IBM）以及 RISC-V 社区都引入了矩阵扩展，以增强通用处理器上的 AI 功能。这些扩展通常采用细粒度同步矩阵指令，并且在寄存器架构、执行模型和集成策略方面有所不同，如图所示In recent years, CPU vendors - including Intel, Arm, and IBM - as well as the RISC-V community have introduced matrix extensions to enhance AI capabilities on general-purpose processors. These extensions typically employ fine-grained synchronous matrix instructions and differ in register architectures, execution models, and integration strategies, as illustrated in Figure2.

IBM MMA 和 RISC-V IME 重用向量单元的数据路径，将向量寄存器文件的一部分重新用作累加器，并将矩阵运算限制为向量寄存器。因此，寄存器大小和带宽限制了矩阵运算的粒度和吞吐量。 IBM Power10 S1022 在 4 GHz 时提供 2 TOPS 的每核 INT8 峰值。IBM MMA and RISC-V IME reuse the data path of the vector unit, repurposing part of the vector register file as accumulators and restricting matrix operations to vector registers. As a result, register size and bandwidth limit the granularity and throughput of matrix operations. IBM Power10 S1022 delivers a per-core INT8 peak of 2 TOPS at 4 GHz.

Arm SME 和 RISC-V VME 引入了专用累加器寄存器，使更大的矩阵单元与向量寄存器组织解耦。 Apple M4 在性能和效率核心上都实现了 SME，其中性能核心实现了每核心 INT8 峰值 4 TOPS。Arm SME and RISC-V VME introduce dedicated accumulator registers, enabling larger matrix units decoupled from vector register organization. Apple M4 implements SME on both performance and efficiency cores, with the performance core achieving a per-core INT8 peak of 4 TOPS.

Intel AMX 和 RISC-V AME 通过引入切片寄存器和专用加载存储路径将矩阵单元与矢量管道解耦，从而实现更大的矩阵运算。 Sapphire Rapids 和 Emerald Rapids 的每核 INT8 峰值为 2 TOPS/GHz，而 Xeon 8580 在 TDP 限制下在 2.3 GHz 时达到 4.6 TOPS。Intel AMX and RISC-V AME decouple the matrix unit from the vector pipeline by introducing tile registers and dedicated load–store paths, enabling larger matrix operations. Sapphire Rapids and Emerald Rapids deliver a per-core INT8 peak of 2 TOPS/GHz, with the Xeon 8580 reaching 4.6 TOPS at 2.3 GHz under TDP limits.

学术界还探索了两种可配置形式的CPU矩阵单元The academic community has also explored CPU matrix units in both configurable forms(Genc et al., 2021; Yi et al., 2025)和固定大小的实现and fixed-size implementations(Qin et al., 2020; Houshmand et al., 2023; Conti et al., 2024; Gao et al., 2025)。然而，这些设计通常缺乏与现有 CPU 矢量单元的密切合作，并且提供的可扩展性和精度支持有限。相比之下，这项工作引入了一种适应性强、可配置的CPU矩阵扩展，为开源社区提供了实用的实现。. However, these designs typically lack close cooperation with existing CPU vector units and offer limited scalability and precision support. In comparison, this work introduces an adaptable and configurable CPU matrix extension, providing the open-source community with a practical implementation.

2.3. 动机Motivation

尽管现有的 CPU 矩阵扩展已经实现了吞吐量的显着提高，但硬件集成和软件可编程性方面的关键挑战仍然限制了它们在不同 CPU 和工作负载中的广泛适用性和高效执行。Although existing CPU matrix extensions have achieved significant throughput improvements, key challenges in hardware integration and software programmability still restrict their broad applicability and efficient execution across diverse CPU and workloads.

对于硬件集成，大多数现有设计将矩阵单元与 CPU 管道紧密耦合，需要跨指令解码、调度和执行阶段进行侵入性修改。矩阵单元通常与矢量寄存器文件或加载存储单元交互，创建复杂的控制路径和冗余状态管理，增加集成和验证成本。在 Arm SME、IBM MMA 和 RISC-V IME/VME 中，矩阵和向量指令争夺向量寄存器，从而导致结构和数据危险。尽管英特尔 AMX 和 RISC-V AME 引入了独立的块寄存器并支持直接访问 L1D 或 L2 缓存，但它们仍然受到同步语义的限制，这需要进行修改，以通过停止潜在冲突的指令或解决加载存储单元内的地址冲突来确保矩阵和标量/向量内存操作之间的正确性。For hardware integration, most existing designs tightly couple matrix units with the CPU pipeline, necessitating invasive modifications across instruction decode, dispatch, and execution stages. Matrix units often interact with vector register files or load-store units, creating complex control paths and redundant state management, increasing integration and verification cost. In Arm SME, IBM MMA, and RISC-V IME/VME, matrix and vector instructions contend for vector registers, resulting in structural and data hazards. Although Intel AMX and RISC-V AME introduce independent tile registers and enable direct access to L1D or L2 cache, they remain constrained by synchronous semantics, which require modifications to ensure correctness between matrix and scalar/vector memory operations either by stalling potentially conflicting instructions or by resolving address conflicts within the load-store unit.

对于软件可编程性，大多数CPU矩阵扩展采用细粒度同步矩阵指令，迫使程序员手动编排矩阵和内存操作之间的调度。此外，在人工智能工作负载中，矩阵和元素级内核通常需要重叠执行，编程复杂性显着增加。开发人员必须在单个指令流中表达内存、矩阵和向量任务，并使所有功能单元在有限的指令窗口内保持忙碌。此外，矩阵扩展 ISA 和软件接口之间的差异阻碍了统一抽象，要求开发人员执行特定于微架构的优化，并加剧了软件碎片化。For software programmability, most CPU matrix extensions adopt fine-grained synchronous matrix instructions, forcing programmers to manually orchestrate scheduling between matrix and memory operations. Moreover, in AI workloads where matrix and element-wise kernels often require overlapped execution, programming complexity increases significantly. Developers must express memory, matrix, and vector tasks within a single instruction stream and keep all functional units busy within a limited instruction window. Furthermore, disparities among matrix-extension ISAs and software interfaces hinder unified abstractions, requiring developers to perform microarchitecture-specific optimizations and exacerbating software fragmentation.

本文提出了一种统一且可配置的 CPU 矩阵扩展架构，旨在以最小的设计开销实现敏捷的跨平台集成和高效执行。This paper proposes a unified and configurable CPU matrix-extension architecture, designed to enable agile cross-platform integration and efficient execution with minimal design overhead.

3. 架构概述Architecture Overview

本文基于三个关键设计原则，提出了一种统一且可配置的 CPU 矩阵扩展： (1)矩阵单元和CPU流水线之间的结构解耦，无需对解码器、指令发布逻辑、寄存器文件或加载存储单元进行侵入性修改； (2)矩阵单元内的可配置微架构参数，以适应跨平台的不同计算需求和存储系统约束； (3)异步矩阵乘法指令的抽象，实现灵活粒度的融合调度，简化编程模型，提高执行效率。This paper proposes a unified and configurable CPU matrix extension, based on three key design principles: (1) Structural decoupling between the matrix unit and the CPU pipeline, without intrusive modifications to the decoder, instruction issue logic, register file, or load–store units; (2) Configurable microarchitectural parameters within the matrix unit to accommodate diverse computational requirements and memory system constraints across platforms; (3) An abstraction for asynchronous matrix-multiplication instructions that enables fusion scheduling with flexible granularity, which simplifies the programming model and improves execution efficiency.

Depending on ISA and microarchitectural support, the CPU dispatches these instructions via a RoCC-like or CSR-based interface, with registers defined inTable 1。矩阵单元通过平台适应性互连独立于 CPU 的加载存储单元连接到高速缓存或内存。这种设计降低了集成复杂性，支持跨 CPU 的快速部署，并允许为嵌入式、边缘和高性能平台进行灵活的微架构配置。. The matrix unit connects to cache or memory independently of the CPU’s load–store unit through a platform-adaptable interconnect. This design reduces integration complexity, supports rapid deployment across CPUs, and allows flexible microarchitectural configuration for embedded, edge, and high-performance platforms.

4.1. 矩阵单元微架构Matrix Unit Microarchitecture

如图所示As illustrated in Figure4，矩阵单元主要由内存加载器、暂存器、数据控制器和 PE 阵列组成。, the matrix unit consists primarily of the Memory Loader, Scratchpad, Data Controller, and PE Array.

内存加载器Memory Loader生成内存访问请求并处理矩阵计算的所有数据读写。在其中，请求生成器将矩阵乘法指令描述的张量转换为内存和暂存器地址，生成并发出相应的请求。数据重新排序模块接收返回的数据并根据需要重新排序，并将其写入目标存储。generates memory access requests and handles all data reads and writes for matrix computations. Within it, the Request Generator translates the tensor described by matrix multiplication instructions into memory and Scratchpad addresses, generating and issuing the corresponding requests. The Data Reorder module receives the returned data and reorder it as required, and writes it to the target storage.

便签本Scratchpad临时存储矩阵分区，以提高矩阵单元中的数据重用。累加结果可以保留在暂存器中，从而减少写回高精度结果的需要。多组暂存器进一步实现了数据加载和计算任务的重叠。temporarily stores matrix partitions to improve data reuse in the matrix unit. Accumulation results can remain resident in the Scratchpad, thereby reducing the need to write back high-precision results. A multi-bank Scratchpad further enables overlapping of data loading and computation tasks.

数据控制者Data Controller向计算数组提供数据。实例化了三个数据控制器：两个专用于矩阵乘法中的源矩阵 A 和 B，一个专用于偏置和累加矩阵 C。supplies data to the computation array. Three Data Controllers are instantiated: two dedicated to source matrices A and B in matrix multiplication, and one dedicated to bias and accumulation matrix C.

聚乙烯阵列PE Array结合了外积和向量点积运算，其中操作数 A 和 B 分别在数组中按行和列广播。每个PE执行内积运算，并支持TF32、BF16、FP16、INT8和FP8格式的混合精度计算。在每个 PE 中，乘法结果与公共指数对齐、截断并累加。 PE被组织成六级流水线，以14nm工艺节点实现2GHz工作频率。combines outer-product and vector dot-product operations, where operands A and B are broadcast row-wise and column-wise across the array, respectively. Each PE performs inner-product operations and supports mixed-precision computing for TF32, BF16, FP16, INT8, and FP8 formats. Within each PE, multiplication results are aligned to a common exponent, truncated, and accumulated. The PE is organized into a six-stage pipeline to achieve a 2 GHz operating frequency with 14nm process node.

6. 结论Conclusion

总体而言，本文提出了一种统一的、可配置的CPU矩阵扩展架构，有助于敏捷的跨平台集成和高效的执行。该架构已部署在多个开源CPU平台上，在不同的配置和工作负载下始终如一地提供高性能，从而证实了其适应性和可扩展性。这一贡献为开源社区提供了 CPU 矩阵扩展的实用解决方案。未来的工作将继续探索 CPU 矩阵扩展的潜力。Overall, this paper presents a unified and configurable CPU matrix extension architecture that facilitates agile cross-platform integration and efficient execution. The architecture has been deployed across multiple open-source CPU platforms, consistently delivering high performance under diverse configurations and workloads, thereby confirming its adaptability and scalability. This contribution offers the open-source community a practical solution for CPU matrix extensions. Future work will continue to explore the potential of CPU matrix extensions.
