摘要Abstract

许多日常编程任务抵制基于干净规则的实现，例如对重要日志行发出警报、修复格式错误的 JSON 或按意图对搜索结果进行排名，并且越来越多地外包给大型语言模型 API，但以局部性、可重复性和价格为代价。我们建议Many everyday programming tasks resist clean rule-based implementation, such as alerting on important log lines, repairing malformed JSON, or ranking search results by intent, and are increasingly outsourced to large language model APIs at the cost of locality, reproducibility, and price. We propose模糊函数规划fuzzy-function programming：将这样的函数从自然语言规范编译为紧凑的、本地可执行的神经工件。我们用程序权重 (PAW) 实例化了这种范例，其中在 FuzzyBench（我们发布的 10M 示例数据集）上训练的 4B 编译器，为冻结的轻量级解释器发出参数高效的适配器。执行 PAW 程序的 0.6B Qwen3 解释器与 Qwen3-32B 直接提示的性能相匹配，同时使用大约五十分之一的推理内存，并在 MacBook M3 上以 30 token/s 的速度运行。 PAW 根据每个输入重新构建基础模型: compiling such a function from a natural-language specification into a compact, locally-executable neural artifact. We instantiate this paradigm with Program-as-Weights (PAW), in which a 4B compiler trained on FuzzyBench, a 10M-example dataset we release, emits parameter-efficient adapters for a frozen, lightweight interpreter. A 0.6B Qwen3 interpreter executing PAW programs matches the performance of direct prompting of Qwen3-32B, while using roughly one fiftieth of the inference memory and running at 30 tokens/s on a MacBook M3. PAW reframes the foundation model from a per-input问题解决者problem solver变成一个into a工具制造商tool builder：每个函数定义调用一次，它会生成一个小的可重用工件，每个函数应用程序的后续调用都是廉价且离线的。: invoked once per function definition, it produces a small reusable artifact whose subsequent calls per function application are cheap and offline.

1 简介Introduction

从历史上看，编程一直是用为此目的而设计的正式语言（编程语言）编写明确的规则。函数由代码定义，计算机确定性地执行它。对于许多任务来说，这种范例工作得很好：对数字进行排序、处理结构化数据、计算矩阵乘积。然而，现实世界中的一大类函数无法进行精确的规范。例如，考虑过滤计算机日志以仅在重要的日志行或消息上提醒某人、修复格式错误的 JSON，或按意图对搜索结果进行排名。即使是看似“简单”的任务，例如编写正则表达式来解析具有许多边缘情况的文本，也被证明是脆弱的。除了规范不足之外，现实世界的输入也很嘈杂：拼写错误和格式漂移经常破坏手写的规则和正则表达式。这些是Programming has historically been about writing explicit rules in a formal language designed for the purpose, a programming language. A function is defined by code, and the computer executes it deterministically. For many tasks, this paradigm works beautifully: sorting numbers, processing structured data, computing matrix products. Yet a large class of real-world functions resists precise specification. Consider, for instance, filtering a computer log to alert someone only on the log lines or messages that matter, repairing malformed JSON, or ranking search results by intent. Even apparently “simple” tasks, such as writing a regular expression to parse text with many edge cases, prove brittle. Beyond underspecification, real-world inputs are noisy: typos and format drift routinely break hand-written rules and regexes. These are模糊函数fuzzy functions (Rubio Manzano, 2012)：人类直观地发现的问题，但无法通过清晰的符号规则完全捕获。: problems that humans find intuitive but that cannot be fully captured by crisp symbolic rules.

11 结论Conclusion

我们引入了程序即权重（Program-as-Weights），这是一种编程范例，其中模糊函数被编译成一个小的神经二进制文件并在固定解释器上本地执行。在 FuzzyBench 上，执行 PAW 程序的 0.6B 参数解释器与 Qwen3-32B 提示相匹配We introduced Program-as-Weights, a programming paradigm in which a fuzzy function is compiled once into a small neural binary and executed locally on a fixed interpreter. On FuzzyBench, a 0.6B-parameter interpreter executing PAW programs matches Qwen3-32B prompting at∼\sim50×\times推理内存更少，在具有量化 GGUF 的 MacBook M3 上以 30 tok/s 的速度运行；我们通过五个案例研究来说明这一范式。通过仅将编译器替换为视觉语言模型，相同的抽象扩展到图像条件模糊任务。我们希望 Program-as-Weights 能够为小型 LM 作为运行时的未来做出贡献less inference memory and runs at 30 tok/s on a MacBook M3 with quantized GGUF; we illustrate the paradigm through five case studies. The same abstraction extends to image-conditioned fuzzy tasks by swapping only the compiler for a vision-language model. We hope Program-as-Weights contributes to a future in which small LMs serve as the runtime(Belcak et al., 2025)，大型模型编译，小型模型执行，基础模型的角色从每个输入转变, where large models compile and small models execute, and the role of foundation models shifts from per-input问题解决者problem solver按功能to per-function工具制造商tool builder.
