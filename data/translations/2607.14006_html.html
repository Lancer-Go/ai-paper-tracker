摘要Abstract

渗透测试传统上评估对手是否可以利用软件、基础设施、配置或操作控制中的弱点来实现与安全相关的妥协。对于人工智能系统来说，这种范式仍然是必要的，但它已经不够了。在此类系统中，对手可能会影响提示、检索内容、传感器输入、训练数据、内存、工具或人机交互循环，以改变系统行为，而不会直接损害底层基础设施。本文将人工智能系统的渗透测试重新定义为目标驱动的行为评估。我们将人工智能支持的系统定义为一种学习模型对影响运营结果的行为产生重大影响的系统，并且我们将人工智能支持的渗透定义为在明确的威胁模型下违反一个或多个运营目标的人工智能治理行为的可行诱导。该定义保留了传统的渗透测试，同时将其扩展到对抗路径，例如即时注入、间接即时注入、数据中毒、传感器操纵、检索中毒、工具滥用和代理错位。我们进一步提出了一个测试工作流程，用于识别操作目标、映射人工智能控制的行为、分析对抗性影响面、定义行为失败标准、执行基于场景的测试，并报告将对抗性行为与客观违规联系起来的证据。一个涉及人工智能安全运营中心助理的运行示例说明了如何通过行为影响而不是基础设施损害来实现渗透。这些定义、工作流程和示例共同提供了一个技术框架，用于评估部署的人工智能系统中的对抗成功。Penetration testing traditionally evaluates whether adversaries can exploit weaknesses in software, infrastructure, configurations, or operational controls to achieve security-relevant compromise. This paradigm remains necessary for AI-enabled systems, but it is no longer sufficient. In such systems, adversaries may influence prompts, retrieved content, sensor inputs, training data, memory, tools, or human-AI interaction loops to alter system behavior without directly compromising the underlying infrastructure. This paper reframes penetration testing for AI-enabled systems as objective-driven behavioral evaluation. We define an AI-enabled system as one in which learned models materially influence behavior affecting operational outcomes, and we define AI-enabled penetration as the feasible induction of AI-governed behavior that violates one or more operational objectives under an explicit threat model. This definition preserves conventional penetration testing while extending it to adversarial pathways such as prompt injection, indirect prompt injection, data poisoning, sensor manipulation, retrieval poisoning, tool misuse, and agentic misalignment. We further propose a testing workflow that identifies operational objectives, maps AI-governed behavior, analyzes adversarial influence surfaces, defines behavioral failure criteria, executes scenario-based tests, and reports evidence linking adversarial action to objective violation. A running example involving an AI-enabled security operations center assistant illustrates how penetration may occur through behavioral influence rather than infrastructure compromise. Together, the definitions, workflow, and example provide a technical framework for evaluating adversarial success in deployed AI-enabled systems.

1 简介Introduction

考虑一个支持人工智能的安全运营中心助手，它可以总结警报、检索威胁情报、建议严重性级别并调用预定义的响应手册。在渗透测试期间，攻击者不会窃取凭据、利用服务器或修改数据库。相反，攻击者会在助理稍后检索的内容中植入恶意指令。如果助手将该内容视为指令而不是证据，它可能会降低高严重性事件的级别，并且无法将其升级给人类分析师。在这种威胁模型下，没有发生传统的基础设施损害，但准确的事件分类的操作目标却失败了。Consider an AI-enabled security operations center assistant that summarizes alerts, retrieves threat intelligence, recommends severity levels, and invokes predefined response playbooks. During a penetration test, the adversary does not steal credentials, exploit a server, or modify a database. Instead, the adversary plants malicious instructions in content later retrieved by the assistant. If the assistant treats that content as instruction rather than evidence, it may downgrade a high-severity incident and fail to escalate it to a human analyst. Under this threat model, no conventional infrastructure compromise has occurred, but the operational objective of accurate incident triage has failed.

这种情况说明了通常如何定义人工智能系统的渗透率方面存在差距。渗透测试仍然是基本的安全实践。 NIST SP 800-115 和 MITRE ATT&CK 等标准和从业者框架为威胁知情测试、对手仿真、漏洞验证、影响分析和缓解规划提供了成熟的指导This scenario illustrates a gap in how penetration is usually defined for AI-enabled systems. Penetration testing remains a foundational security practice. Standards and practitioner frameworks such as NIST SP 800-115 and MITRE ATT&CK provide mature guidance for threat-informed testing, adversary emulation, exploit validation, impact analysis, and mitigation planning[nist800115, mitreattack]。这些实践仍然是必要的，因为人工智能支持的系统仍然依赖于传统资产，包括 API、凭证、云服务、模型存储库、数据存储、容器、编排层、传感器和软件供应链。如果这些资源受到损害，人工智能系统也可能受到损害。. These practices remain necessary because AI-enabled systems still depend on conventional assets, including APIs, credentials, cloud services, model repositories, data stores, containers, orchestration layers, sensors, and software supply chains. If these resources are compromised, the AI-enabled system may be compromised as well.

困难在于资源妥协不再是导致安全失败的唯一有意义的途径。在人工智能支持的系统中，学习模型调节系统输入和操作结果之间的关系。分类器、大型语言模型、推荐系统、感知模型和代理工作流程可能会影响决策、工具调用、优先级、访问决策、人类判断或物理动作。因此，对手可能通过提示、检索的内容、训练数据、传感器输入、上下文窗口、存储器、工具输出或其他普通接口影响系统行为。在没有未经授权访问底层基础设施或直接控制计算资源的情况下，可能会发生这种影响。The difficulty is that resource compromise is no longer the only meaningful path to security failure. In AI-enabled systems, learned models mediate the relationship between system inputs and operational outcomes. Classifiers, large language models, recommender systems, perception models, and agentic workflows may influence decisions, tool calls, prioritization, access decisions, human judgment, or physical actions. As a result, an adversary may affect system behavior through prompts, retrieved content, training data, sensor inputs, context windows, memory, tool outputs, or other ordinary interfaces. Such influence may occur without unauthorized access to the underlying infrastructure or direct control over computational resources.

这种转变在人工智能安全的多个领域都很明显。对抗性机器学习表明，可以通过对抗性示例、规避、投毒、提取、推理和可用性攻击来操纵学习模型This shift is visible across several areas of AI security. Adversarial machine learning has shown that learned models can be manipulated through adversarial examples, evasion, poisoning, extraction, inference, and availability attacks[goodfellowAdversarial, biggioWildPatterns, rosenbergAML]。 LLM 和生成式人工智能安全工作表明，提示注入、间接提示注入、可转移的对抗性提示、不安全的工具使用、敏感信息泄露和过度代理可能会通过自然语言和工作流程界面导致有害行为. LLM and generative-AI security work has shown that prompt injection, indirect prompt injection, transferable adversarial prompting, insecure tool use, sensitive-information disclosure, and excessive agency can cause harmful behavior through natural-language and workflow interfaces[owaspLLMTop10, duartePromptInjection, greshakeIndirectPromptInjection, zouUniversalTransferable, nistAI6001]。 MITRE ATLAS 和 OWASP AI 指南进一步为从业者整理了 AI 特定的对抗技术和风险. MITRE ATLAS and OWASP AI guidance further organize AI-specific adversary techniques and risks for practitioners[mitreatlas, owaspAIExchange]。这些工作明确表明人工智能安全不仅仅是模型准确性的问题。这是一个关于对手如何影响执行操作功能的系统中人工智能介导的行为的问题。. These bodies of work make clear that AI security is not merely a question of model accuracy. It is a question of how adversaries can influence AI-mediated behavior in systems that perform operational functions.

然而，其含义是However, the meaning of渗透penetration在此设置中仍然未定义。现有的安全测试框架解释了如何评估技术系统和对手的行为。 NIST AI 风险管理框架和 ISO/IEC 23894 等 AI 风险框架解释了如何跨组织环境识别和管理 AI 风险in this setting remains underdefined. Existing security-testing frameworks explain how to assess technical systems and adversary behavior. AI risk frameworks such as the NIST AI Risk Management Framework and ISO/IEC 23894 explain how to identify and manage AI risks across organizational contexts[nistAIRMF, iso23894]。 AI 红队和对抗性 ML 方法可识别重要的故障模式和攻击技术。然而，这些工作并没有为传统资源没有受到损害但系统已被诱导采取违背其操作目的的情况提供统一的渗透测试成功标准。. AI red-teaming and adversarial ML methods identify important failure modes and attack techniques. Yet these bodies of work do not provide a unified penetration-testing success criterion for cases in which no traditional resource has been compromised, but the system has been induced to act against its operational purpose.

本文通过围绕运营目标和人工智能控制的行为重新构建渗透测试来解决这一差距。我们使用This article addresses that gap by reframing penetration testing around operational objectives and AI-governed behavior. We use经营目标operational objective是指系统在正常和对抗条件下期望保持的任务级结果，例如安全导航、准确的事件分类、可靠的身份验证、正确的诊断、合规的决策支持或值得信赖的建议。我们使用to mean a mission-level outcome that a system is expected to preserve under normal and adversarial conditions, such as safe navigation, accurate incident triage, reliable authentication, correct diagnosis, compliant decision support, or trustworthy recommendation. We use人工智能控制的行为AI-governed behavior指由学习模型实质上塑造的系统行为，包括预测、生成的内容、分类、排名、计划、工具调用、建议和操作。在这种观点下，计算资源仍然很重要，但它们并不是安全评估的最终对象。它们促成行为，而行为决定运营目标是否得到满足。to refer to system behavior materially shaped by learned models, including predictions, generated content, classifications, rankings, plans, tool calls, recommendations, and actions. Under this view, computational resources remain important, but they are not the final object of security evaluation. They enable behavior, and behavior determines whether operational objectives are satisfied.

本文的中心主张虽然狭隘但很重要：对人工智能支持的系统的渗透应被理解为在明确的威胁模型下可行地诱导出违反一个或多个操作目标的人工智能控制的行为。该定义不会取代传统的渗透测试。它扩展了其成功标准。资源妥协仍然是渗透的一种可能途径，并且在许多系统中它将仍然是最重要的途径。但在人工智能系统中，对抗性影响也可能通过数据、提示、上下文、传感器、工具或人机交互循环来发挥作用。忽略这些路径的渗透测试可能会错过对操作至关重要的故障。The central claim of this article is narrow but important: penetration of an AI-enabled system should be understood as the feasible induction of AI-governed behavior that violates one or more operational objectives under an explicit threat model. This definition does not replace conventional penetration testing. It extends its success criterion. Resource compromise remains one possible pathway to penetration, and in many systems it will remain the most important one. But in AI-enabled systems, adversarial influence may also operate through data, prompts, context, sensors, tools, or human-AI interaction loops. A penetration test that ignores these pathways may miss failures that matter operationally.

这种框架还避免了常见的夸大其词的情况。并非每个模型错误都是渗透，也不是每个有害的人工智能输出都是对抗成功的证据。仅当存在可行的对抗路径、定义的威胁模型、可观察的人工智能控制行为以及违反操作目标时，行为失败才会成为渗透。由于人工智能行为可能是随机的、上下文相关的和分布相关的，因此渗透的证据可能是概率性的，而不是单个确定性的利用链。这要求测试报告不仅要描述易受攻击的接口，还要描述对手的能力、诱发的行为、成功率或再现性条件、受影响的目标、操作影响和建议的缓解措施。This framing also avoids a common overstatement. Not every model error is a penetration, and not every harmful AI output is evidence of adversarial success. A behavioral failure becomes penetration only when there is a feasible adversarial path, a defined threat model, an observable AI-governed behavior, and a violation of an operational objective. Because AI behavior may be stochastic, contextual, and distribution-dependent, evidence for penetration may be probabilistic rather than a single deterministic exploit chain. This requires test reports to describe not only the vulnerable interface, but also the adversary capability, induced behavior, success rate or reproducibility conditions, affected objective, operational impact, and recommended mitigation.

2 渗透测试已经做对了什么What Penetration Testing Already Gets Right

渗透测试仍然是评估安全控制是否能够承受对抗压力的最有效方法之一。它的价值不仅在于发现漏洞，还在于提供证据证明漏洞可以在特定的假设下发挥作用，并可能导致与安全相关的后果。这将渗透测试与纯粹基于清单的审计或漏洞清单区分开来。漏洞报告可以识别可能的弱点；渗透测试试图确定对手是否可以利用该弱点来实现有意义的目标。Penetration testing remains one of the most effective ways to evaluate whether security controls withstand adversarial pressure. Its value lies not only in finding vulnerabilities, but in producing evidence that a weakness can be exercised under specified assumptions and can lead to a security-relevant consequence. This distinguishes penetration testing from purely checklist-based audits or vulnerability inventories. A vulnerability report may identify a possible weakness; a penetration test attempts to establish whether that weakness can be used by an adversary to achieve a meaningful objective.

这种证据规则是既定安全测试实践的核心。 NIST SP 800-115 将技术安全测试和评估描述为一个结构化过程，其中包括规划、测试执行、结果分析和缓解指南This evidentiary discipline is central to established security-testing practice. NIST SP 800-115 describes technical security testing and assessment as a structured process that includes planning, test execution, analysis of findings, and mitigation guidance[nist800115]。在成熟的实践中，这个过程需要明确的范围、定义的假设、选择的技术、收集的证据、影响评估和补救建议。结果不仅仅是一个缺陷目录，而且是对有能力的攻击者在测试范围内可能做的事情的对抗性描述。. In mature practice, this process requires an explicit scope, defined assumptions, selected techniques, collected evidence, impact assessment, and remediation recommendations. The result is not merely a catalogue of defects, but an adversarial account of what a capable attacker could plausibly do within the boundaries of the test.

现代渗透测试也具有威胁信息。有用的测试不会询问系统在抽象上是否安全；而是询问系统是否安全。它询问具有特定能力、访问权限和限制的对手是否可以实现特定目标。这个方向将渗透测试与对手模拟和作战防御联系起来。 MITRE ATT&CK 提供了广泛使用的词汇，用于描述在真实环境中观察到的对手战术、技术和程序Modern penetration testing is also threat-informed. A useful test does not ask whether a system is secure in the abstract; it asks whether an adversary with particular capabilities, access, and constraints can achieve particular objectives. This orientation connects penetration testing to adversary emulation and operational defense. MITRE ATT&CK provides a widely used vocabulary for describing adversary tactics, techniques, and procedures observed in real environments[mitreattack]。尽管 ATT&CK 本身并不是一种渗透测试方法，但它通过将测试活动基于现实的对手行为而不是任意工具执行来加强安全评估。. Although ATT&CK is not itself a penetration-testing methodology, it strengthens security assessment by grounding test activity in realistic adversary behavior rather than arbitrary tool execution.

传统渗透测试的另一个优势是将可利用性视为证据。错误配置、暴露的服务、易受攻击的依赖项或扫描仪发现并不自动等同于妥协。相关问题是，该弱点是否可以在现实的假设下发挥作用，以及是否会使对手能够侵犯安全财产。这种区别可以防止安全评估陷入漏洞枚举。最有力的渗透测试结果将弱点与攻击路径联系起来，并将攻击路径与影响联系起来。A further strength of conventional penetration testing is its treatment of exploitability as a matter of evidence. A misconfiguration, exposed service, vulnerable dependency, or scanner finding is not automatically equivalent to compromise. The relevant question is whether the weakness can be exercised under realistic assumptions and whether it enables an adversary to violate a security property. This distinction prevents security assessment from collapsing into vulnerability enumeration. The strongest penetration-test findings connect a weakness to an attack path and connect the attack path to impact.

传统的渗透测试也比狭隘的漫画所暗示的更具有影响力。其调查结果通常根据机密性、完整性、可用性、特权边界、持久性、横向移动、敏感数据暴露、运营中断或业务后果进行评估。这种影响导向也出现在对抗性机器学习中。罗森伯格等人。将针对机器学习系统的攻击与传统的网络安全目标联系起来，展示模型提取和推理攻击如何影响机密性、规避和中毒如何影响完整性以及资源耗尽攻击如何影响可用性Conventional penetration testing is also more impact-aware than a narrow caricature suggests. Its findings are typically evaluated in relation to confidentiality, integrity, availability, privilege boundaries, persistence, lateral movement, exposure of sensitive data, operational disruption, or business consequence. This impact orientation also appears in adversarial machine learning. Rosenberg et al. connect attacks against machine-learning systems to conventional cybersecurity objectives, showing how model extraction and inference attacks may affect confidentiality, evasion and poisoning may affect integrity, and resource-exhaustion attacks may affect availability[rosenbergAML]。这种连续性很重要：人工智能安全并不与网络安全分开，而是将其扩展到系统中，其行为部分是学习的，而不是完全由代码指定的。. This continuity matters: AI security is not separate from cybersecurity, but an extension of it into systems whose behavior is partly learned rather than fully specified by code.

传统范式也仍然直接适用于人工智能系统。此类系统依赖于普通计算资源：API、身份、凭证、云服务、容器、编排层、数据存储、模型注册表、推理端点、传感器、日志、软件依赖项和部署管道。如果这些资源受到损害，人工智能系统也可能受到损害。暴露的推理 API、特权过高的服务帐户、易受攻击的插件、不安全的模型存储库、中毒的数据管道或受损的容器可能会产生常见的安全故障。在这些情况下，传统的渗透测试提供了正确的评估逻辑：识别弱点、执行攻击路径、演示结果并建议缓解措施。The conventional paradigm also remains directly applicable to AI-enabled systems. Such systems depend on ordinary computational resources: APIs, identities, credentials, cloud services, containers, orchestration layers, data stores, model registries, inference endpoints, sensors, logs, software dependencies, and deployment pipelines. If these resources are compromised, the AI-enabled system may be compromised as well. An exposed inference API, overprivileged service account, vulnerable plugin, insecure model repository, poisoned data pipeline, or compromised container can produce familiar security failures. In these cases, conventional penetration testing provides the correct evaluation logic: identify the weakness, exercise an attack path, demonstrate the consequence, and recommend mitigation.

可重复性是传统渗透测试的另一个重要贡献。强有力的发现指定了易受攻击的条件、对手的能力、利用弱点所需的步骤、最终的系统状态以及攻击成功的条件。这支持防御者进行验证，并可以在以后验证补救措施是否有效。支持人工智能的系统使再现性变得复杂，因为模型输出可能是随机的、依赖于上下文的，或者对输入的微小变化敏感。然而，这并没有降低证据严谨性的重要性。它增加了它。人工智能安全评估仍然需要明确记录测试条件、观察到的行为、成功频率和失败边界。Reproducibility is another important contribution of conventional penetration testing. A strong finding specifies the vulnerable condition, the adversary capability, the steps required to exercise the weakness, the resulting system state, and the conditions under which the attack succeeds. This supports verification by defenders and enables later validation that remediation was effective. AI-enabled systems complicate reproducibility because model outputs may be stochastic, context-dependent, or sensitive to small changes in input. However, this does not reduce the importance of evidentiary rigor. It increases it. AI security assessments still need clear records of test conditions, observed behavior, success frequency, and failure boundaries.

渗透测试还将对抗性证据转化为防御行动。仅当发现有助于组织降低风险时，它才是有用的。补救措施可能涉及修补、强化、分段、访问控制更改、监控改进、安全开发实践、事件响应更改或供应链控制。同样的原则也适用于人工智能系统。防御可能涉及限制工具权限、验证检索的内容、隔离不受信任的数据、限制代理操作、监视模型行为、强化管道或引入人工确认以进行高影响力的决策。渗透测试的防御价值取决于所展示的对抗能力和实际缓解措施之间的联系。Penetration testing also translates adversarial evidence into defensive action. A finding is useful only if it helps an organization reduce risk. Remediation may involve patching, hardening, segmentation, access-control changes, monitoring improvements, secure-development practices, incident-response changes, or supply-chain controls. The same principle applies to AI-enabled systems. Defenses may involve limiting tool permissions, validating retrieved content, isolating untrusted data, constraining agent actions, monitoring model behavior, hardening pipelines, or introducing human confirmation for high-impact decisions. The defensive value of penetration testing depends on this connection between demonstrated adversarial capability and practical mitigation.

当在没有直接损害底层计算资源的情况下产生安全故障时，就会出现这种限制。在支持人工智能的系统中，对手可能会通过故意暴露的界面影响行为：提示、文档、图像、传感器读数、检索到的网页、票证评论、训练示例、内存条目或工具输出。该攻击可能不需要对主机、数据库、模型权重或凭证进行未经授权的访问。基础设施可能保持完整，而人工智能介导的行为违反了系统部署的目的。The limitation emerges when security failure is produced without direct compromise of the underlying computational resources. In AI-enabled systems, an adversary may influence behavior through interfaces that are intentionally exposed: a prompt, document, image, sensor reading, retrieved webpage, ticket comment, training example, memory entry, or tool output. The attack may not require unauthorized access to the host, database, model weights, or credentials. The infrastructure may remain intact, while the AI-mediated behavior violates the purpose for which the system was deployed.

这为传统的成功标准创造了边界条件。当未经授权的访问、权限升级、数据暴露、持久性、中断或资源控制证明安全失败时，经典渗透测试是最强的。人工智能系统引入了另一种形式的对抗性证据：诱导违反操作目标的行为。模型可能会对对象进行错误分类，代理可能会滥用授权工具，推荐器可能会引导用户做出不安全的决策，或者决策支持系统可能会抑制正确判断所需的信息。在每种情况下，与安全相关的故障不仅在于计算资源的状态，还在于这些资源产生的行为。This creates a boundary condition for conventional success criteria. Classical penetration testing is strongest when security failure is evidenced by unauthorized access, privilege escalation, data exposure, persistence, disruption, or control over resources. AI-enabled systems introduce another form of adversarial evidence: induced behavior that violates an operational objective. A model may misclassify an object, an agent may misuse an authorized tool, a recommender may steer a user toward an unsafe decision, or a decision-support system may suppress information needed for correct judgment. In each case, the security-relevant failure lies not only in the state of computational resources, but in the behavior those resources produce.

因此，所需的扩展是概念性的而不是对立的。传统的渗透测试提供了以下学科：明确的威胁模型、对抗性证据、可利用性分析、影响评估、再现性和补救措施。支持人工智能的系统要求这一规则不仅应用于资源，还应用于人工智能控制的行为。当学习模型调节系统输入和操作结果之间的关系时，渗透不能仅仅定义为进入、控制或滥用计算资产。它还必须考虑对导致系统违反其运营目标的行为的对抗性影响。The required extension is therefore conceptual rather than oppositional. Conventional penetration testing supplies the discipline: explicit threat models, adversarial evidence, exploitability analysis, impact assessment, reproducibility, and remediation. AI-enabled systems require that this discipline be applied not only to resources, but also to AI-governed behavior. When learned models mediate the relationship between system inputs and operational outcomes, penetration cannot be defined solely as entry into, control over, or misuse of computational assets. It must also account for adversarial influence over behavior that causes the system to violate its operational objectives.

3 人工智能的转变：从资源到行为The AI Shift: From Resources to Behavior

人工智能系统带来的决定性变化不仅仅是添加新的软件组件。它将学习到的行为插入到系统资源和操作结果之间的因果路径中。在传统系统中，文件、进程、凭证、内存、网络服务和数据库等资源通常与系统行为紧密耦合。对这些资源的未经授权的控制通常会导致对执行、数据或可用性的直接操纵。在人工智能系统中，这种耦合被削弱。资源仍然很重要，但其安全重要性越来越取决于它们如何塑造人工智能控制的行为。The defining change introduced by AI-enabled systems is not simply the addition of a new software component. It is the insertion of learned behavior into the causal path between system resources and operational outcomes. In conventional systems, resources such as files, processes, credentials, memory, network services, and databases are often closely coupled to system behavior. Unauthorized control over these resources frequently enables direct manipulation of execution, data, or availability. In AI-enabled systems, this coupling is weakened. Resources still matter, but their security significance increasingly depends on how they shape AI-governed behavior.

这种转变可以理解为三层关系。第一层由计算资源组成：基础设施、代码、模型工件、提示、API、数据存储、传感器、凭证、工具接口和部署管道。第二层由人工智能控制的行为组成：预测、分类、生成的响应、排名、计划、建议、工具调用以及由学习模型实质上塑造的行动。第三层由运营目标组成：系统期望保留的任务级结果，例如准确的事件分类、可靠的身份验证、安全导航、正确的诊断、合规的决策支持或值得信赖的内容审核。安全故障可能发生在任何一层，但在人工智能支持的系统中，第二层成为对抗性影响的首要对象。This shift can be understood as a three-layer relationship. The first layer consists of computational resources: infrastructure, code, model artifacts, prompts, APIs, data stores, sensors, credentials, tool interfaces, and deployment pipelines. The second layer consists of AI-governed behavior: predictions, classifications, generated responses, rankings, plans, recommendations, tool calls, and actions materially shaped by learned models. The third layer consists of operational objectives: the mission-level outcomes the system is expected to preserve, such as accurate incident triage, reliable authentication, safe navigation, correct diagnosis, compliant decision support, or trustworthy content moderation. Security failure may occur at any layer, but in AI-enabled systems the second layer becomes a first-class object of adversarial influence.

这是一个结构性的变化。在传统软件中，行为主要由程序逻辑指定。尽管系统可能是复杂的、分布式的且难以分析，但它们的预期行为通常被编码在开发人员编写的显式指令中，并受到访问控制机制、输入验证、类型系统、协议定义和配置规则的约束。因此，渗透测试通常可以从资源妥协到行为后果进行推理。如果攻击者获取管理凭据、修改数据库、控制进程或利用远程代码执行漏洞，那么从资源泄露到安全影响的路径相对直接。This is a structural change. In traditional software, behavior is primarily specified by program logic. Although systems may be complex, distributed, and difficult to analyze, their intended behavior is usually encoded in explicit instructions written by developers and constrained by access-control mechanisms, input validation, type systems, protocol definitions, and configuration rules. Penetration testing can therefore often reason from resource compromise to behavioral consequence. If an attacker obtains administrative credentials, modifies a database, controls a process, or exploits a remote-code-execution vulnerability, the path from resource compromise to security impact is relatively direct.

支持人工智能的系统引入了一种额外的产生行为的机制。学习模型不仅执行明确的规则，而且还执行明确的规则。它将输入、上下文和学习到的表示映射到输出。这种映射可能是概率性的、分布相关的、上下文敏感的，并且难以详尽地指定。分类器在输入的小扰动下可能表现不同。生成模型可以在不同的提示、采样设置、检索的上下文或对话历史记录下产生不同的输出。代理可以根据中间观察结果选择不同的工具或计划。由此产生的行为并不独立于软件逻辑，但也不能仅简化为软件逻辑。AI-enabled systems introduce an additional mechanism for producing behavior. A learned model does not merely execute explicit rules; it maps inputs, context, and learned representations to outputs. This mapping may be probabilistic, distribution-dependent, context-sensitive, and difficult to specify exhaustively. A classifier may behave differently under small perturbations of an input. A generative model may produce different outputs under different prompts, sampling settings, retrieved context, or conversation history. An agent may select different tools or plans depending on intermediate observations. The resulting behavior is not independent of software logic, but it is not reducible to software logic alone.

这对安全评估有直接影响。对手可能会通过对模型从中导出行为的输入、上下文、数据或环境进行操作来影响人工智能系统。在图像识别系统中，对抗性扰动可能会在不修改模型或损害主机的情况下改变分类，这种现象在对抗性示例的基础工作中建立，后来在对抗性机器学习研究中系统化This has direct consequences for security assessment. An adversary may influence an AI-enabled system by acting on the inputs, context, data, or environment from which the model derives behavior. In an image-recognition system, adversarial perturbations may alter classification without modifying the model or compromising the host, a phenomenon established in foundational work on adversarial examples and later systematized in adversarial machine learning research[goodfellowAdversarial, biggioWildPatterns]。在检索增强生成系统中，中毒或恶意制作的检索内容可能会在不改变底层模型权重的情况下引导生成的答案。在代理系统中，间接提示注入可能会导致代理滥用授权工具，即使该工具、帐户和基础设施仍未受到损害。在网络物理系统中，传感器操纵可能会在不破坏控制服务器的情况下影响感知和规划。. In a retrieval-augmented generation system, poisoned or maliciously crafted retrieved content may steer the generated answer without changing the underlying model weights. In an agentic system, an indirect prompt injection may cause the agent to misuse an authorized tool even though the tool, account, and infrastructure remain uncompromised. In a cyber-physical system, sensor manipulation may affect perception and planning without breaching the control server.

这些途径与经典利用不同，因为对手的影响力是行为性的，而不是主要是结构性的。攻击者不一定需要跨越授权边界、升级权限或获得持久访问权限。攻击可能通过系统有意公开的界面进行：提示、文档、票证、网页、图像、音频流、传感器读数、内存项、API 响应或训练示例。由此产生的故障并不总是作为受损资产可见。它可能表现为错误的推荐、不安全的分类、未经授权的工具调用、隐藏的警告、扭曲的排名、误导性的摘要或违反策略的操作。These pathways differ from classical exploitation because the adversary’s leverage is behavioral rather than primarily structural. The attacker does not necessarily need to cross an authorization boundary, escalate privileges, or obtain persistent access. The attack may proceed through an interface the system intentionally exposes: a prompt, document, ticket, webpage, image, audio stream, sensor reading, memory item, API response, or training example. The resulting failure is not always visible as a compromised asset. It may appear as a wrong recommendation, unsafe classification, unauthorized tool call, suppressed warning, distorted ranking, misleading summary, or policy-violating action.

大型语言模型和代理人工智能系统使这个问题变得尤为明显。 Their inputs often combine system instructions, developer instructions, user messages, retrieved documents, tool outputs, memory, and external content in a shared natural-language context.即时注入通过导致不受信任的内容影响模型行为来利用这种混合物Large language models and agentic AI systems make this problem especially visible. Their inputs often combine system instructions, developer instructions, user messages, retrieved documents, tool outputs, memory, and external content in a shared natural-language context. Prompt injection exploits this mixture by causing untrusted content to influence model behavior[owaspLLMTop10, duartePromptInjection]。间接提示注入通过将对抗性指令放置在模型稍后检索或观察的内容（例如网页、文档、电子邮件、票证或数据库记录）中，进一步扩展了攻击面. Indirect prompt injection extends the attack surface further by placing adversarial instructions in content that the model later retrieves or observes, such as webpages, documents, emails, tickets, or database records[greshakeIndirectPromptInjection]。攻击者可能永远不会在执行时直接与模型交互；环境成为对抗性影响的传递机制。针对对齐语言模型的可转移对抗性攻击的相关工作进一步表明，对抗性提示可以系统地改变跨系统的模型行为. The attacker may never interact directly with the model at the time of execution; the environment becomes the delivery mechanism for adversarial influence. Related work on transferable adversarial attacks against aligned language models further shows that adversarial prompting can systematically alter model behavior across systems[zouUniversalTransferable].

困惑副手模式抓住了这种风险的一种重要形式。在经典的表述中，特权程序被欺骗代表对手滥用其权力The confused-deputy pattern captures one important form of this risk. In the classical formulation, a privileged program is tricked into misusing its authority on behalf of an adversary[hardyConfusedDeputy]。在代理人工智能中，模型或代理可能成为代理人。它可能具有对工具、文件、API 或工作流程操作的合法访问权限，而不受信任的内容会影响其如何使用这些功能的决策。对手的目标不一定是窃取代理的凭据或破坏工具。就是以违背经营者意图的方式诱导代理人行使合法权限。这将行为本身变成了渗透的目标。. In agentic AI, the model or agent may become the deputy. It may have legitimate access to tools, files, APIs, or workflow actions, while untrusted content shapes its decision about how to use those capabilities. The adversary’s goal is not necessarily to steal the agent’s credentials or compromise the tool. It is to induce the agent to exercise legitimate authority in a way that violates the operator’s intent. This turns behavior itself into the target of penetration.

同样的模式也出现在法学硕士之外。在生物特征认证中，恶意制作的呈现可能会导致系统接受未经授权的用户，而不会危及认证服务器。在自主检查中，受操纵的视觉输入可能会导致缺陷检测模型错过关键故障，而所有基础设施控制仍保持完好。在推荐系统中，输入的协调操作可能会以扭曲用户决策或操作优先级的方式改变排名或推荐。在医疗或安全决策支持中，精心设计的背景可能会产生看似合理、有害且对操作有影响的建议。这些案例在技术上有所不同，但它们具有相同的结构：对人工智能控制行为的对抗性影响会产生客观层面的失败。The same pattern appears beyond LLMs. In biometric authentication, an adversarially crafted presentation may cause a system to accept an unauthorized user without compromising the authentication server. In autonomous inspection, a manipulated visual input may cause a defect-detection model to miss a critical fault while all infrastructure controls remain intact. In recommender systems, coordinated manipulation of inputs may shift rankings or recommendations in ways that distort user decisions or operational priorities. In medical or security decision support, carefully crafted context may produce advice that is plausible, harmful, and operationally consequential. These cases differ technically, but they share the same structure: adversarial influence over AI-governed behavior produces objective-level failure.

这种结构也改变了评估成功的方式。在传统的渗透测试中，成功通常通过可重现的漏洞利用链导致离散的状态变化来证明：获得 shell、特权升级、文件被访问、服务被破坏或数据被泄露。支持人工智能的系统可能并不总是能产生这样的二元证据。通过重复试验，行为攻击可能以一定的概率成功。它可能取决于提示措辞、检索顺序、环境状态、传感器条件、模型版本、采样参数、内存内容或人类交互。因此，渗透的证据可能需要重复的场景执行、行为观察、成功率估计和测试条件的明确记录。This structure also changes how success should be evaluated. In conventional penetration testing, success is often demonstrated by a reproducible exploit chain leading to a discrete state change: a shell is obtained, a privilege is escalated, a file is accessed, a service is disrupted, or data is exfiltrated. AI-enabled systems may not always produce such binary evidence. A behavioral attack may succeed with some probability across repeated trials. It may depend on prompt phrasing, retrieval order, environmental state, sensor conditions, model version, sampling parameters, memory contents, or human interaction. Evidence of penetration may therefore require repeated scenario execution, behavioral observation, success-rate estimation, and explicit documentation of test conditions.

人工智能行为的概率性质并不会降低测试的严格性。它改变了所需严格性的形式。模型的单个令人惊讶的输出是薄弱的证据，除非它与对抗路径和操作结果相关。相反，在特定条件下重复诱发有害行为可能构成强有力的证据，即使该行为不是确定性的。相关的证据问题是，具有特定能力的对手是否能够足够可靠地诱发违反作战目标的行为。对于高影响力的系统，如果操作后果很严重，即使是中等概率的诱发客观故障也可能与安全相关。The probabilistic nature of AI behavior does not make testing less rigorous. It changes the form of rigor required. A single surprising output from a model is weak evidence unless it is connected to an adversarial path and an operational consequence. Conversely, repeated induction of harmful behavior under defined conditions may constitute strong evidence even if the behavior is not deterministic. The relevant evidentiary question is whether an adversary with specified capabilities can reliably enough induce behavior that violates an operational objective. For high-impact systems, even a moderate probability of induced objective failure may be security-relevant if the operational consequence is severe.

这种转变也影响了脆弱性的含义。在传统环境中，漏洞通常与代码、配置、协议设计、访问控制或部署中的缺陷相关。在人工智能支持的环境中，漏洞可能是一种行为敏感性：在这种情况下，不受信任的输入、上下文、数据或环境操纵可以引导人工智能控制的行为超出系统目标的可接受范围。弱点可能在于模型，但也可能在于即时构建、检索设计、工具授权、内存处理、工作流程编排、监控或人工智能系统和人类操作员之间的决策权限分配。This shift also affects the meaning of vulnerability. In a conventional setting, vulnerability is often associated with a defect in code, configuration, protocol design, access control, or deployment. In an AI-enabled setting, a vulnerability may instead be a behavioral susceptibility: a condition under which untrusted input, context, data, or environmental manipulation can steer AI-governed behavior outside the acceptable envelope for the system’s objective. The weakness may lie in the model, but it may also lie in prompt construction, retrieval design, tool authorization, memory handling, workflow orchestration, monitoring, or the allocation of decision authority between the AI system and human operators.

资源和行为之间的界限不应该被夸大。资源妥协仍然是行为妥协的有力途径。如果攻击者修改模型权重、篡改训练数据、窃取凭证、毒害检索索引或控制代理的工具界面，所产生的行为后果可能是严重的。问题并不在于资源变得无关紧要。关键是资源不再足以作为渗透分析的唯一对象。支持人工智能的系统要求测试人员检查资源的保护以及这些资源产生的行为的完整性。The boundary between resources and behavior should not be overstated. Resource compromise remains a powerful route to behavioral compromise. If an attacker modifies model weights, tampers with training data, steals credentials, poisons a retrieval index, or controls an agent’s tool interface, the resulting behavioral consequences may be severe. The point is not that resources have become irrelevant. The point is that resources are no longer sufficient as the sole object of penetration analysis. AI-enabled systems require testers to examine both the protection of resources and the integrity of the behavior those resources produce.

这激发了以目标为中心的安全评估观点。决定性的问题不仅在于攻击者是否可以进入、控制或滥用计算资源。问题在于攻击者是否能够导致人工智能系统的行为与其部署的操作目的相悖。当学习模型调节资源和结果之间的关系时，渗透测试必须考虑从对抗性影响到人工智能控制行为再到操作目标违规的完整路径。This motivates an objective-centered view of security assessment. The decisive question is not only whether an attacker can enter, control, or misuse a computational resource. It is whether the attacker can cause the AI-enabled system to act contrary to the operational purpose for which it was deployed. When learned models mediate the relationship between resources and outcomes, penetration testing must account for the full path from adversarial influence to AI-governed behavior to operational-objective violation.

4 相关工作和标准Related Work and Standards

之前在渗透测试、对抗性机器学习、LLM 安全、AI 红队和 AI 风险管理方面的工作为评估 AI 支持的系统提供了重要的基础。这些工作解决了问题的重要部分，但它们并没有完全定义渗透一个关键行为由学习模型介导的系统意味着什么。差距并不在于缺乏人工智能的安全指导。差距在于，当对抗性影响导致人工智能控制的行为违反操作目标而不必牺牲计算资源时，渗透测试缺乏明确的成功标准。Prior work on penetration testing, adversarial machine learning, LLM security, AI red teaming, and AI risk management provides essential foundations for evaluating AI-enabled systems. These bodies of work address important parts of the problem, but they do not fully define what it means to penetrate a system whose critical behavior is mediated by learned models. The gap is not a lack of security guidance for AI. The gap is the absence of a clear success criterion for penetration testing when adversarial influence causes AI-governed behavior to violate operational objectives without necessarily compromising computational resources.

4.1 安全测试和对手建模Security Testing and Adversary Modeling

传统的安全测试指南为渗透测试提供了程序基础。 NIST SP 800-115 将技术安全测试和评估定义为涉及规划、执行、分析和缓解指南的结构化活动Conventional security-testing guidance provides the procedural foundation for penetration testing. NIST SP 800-115 defines technical security testing and assessment as a structured activity involving planning, execution, analysis, and mitigation guidance[nist800115]。这个框架很重要，因为渗透测试不仅仅是漏洞发现。这是一个在既定假设下生成对抗性证据并将该证据转化为降低风险行动的过程。 MITRE ATT&CK 通过提供在真实环境中观察到的对手战术、技术和程序的广泛使用的词汇来补充这一过程. This framing is important because penetration testing is not merely vulnerability discovery. It is a process for generating adversarial evidence under defined assumptions and translating that evidence into risk-reduction actions. MITRE ATT&CK complements this process by providing a widely used vocabulary of adversary tactics, techniques, and procedures observed in real environments[mitreattack]。这些框架共同支持威胁通知测试、对手模拟、攻击路径分析和防御优先级。. Together, these frameworks support threat-informed testing, adversary emulation, attack-path analysis, and defensive prioritization.

这些框架仍然与人工智能系统直接相关。人工智能应用仍然依赖于普通基础设施，包括 API、身份、云服务、模型存储库、容器、数据存储、传感器和软件供应链。针对这些资源的攻击仍在传统渗透测试的范围内。然而，这些框架并没有为通过人工智能介导的行为而不是直接损害资源而取得对抗成功的情况提供渗透的具体定义。它们描述了对手如何操作以及如何进行测试，但它们没有完全指定如何将诱导模型或代理行为视为渗透对象。These frameworks remain directly relevant to AI-enabled systems. AI applications still rely on ordinary infrastructure, including APIs, identities, cloud services, model repositories, containers, data stores, sensors, and software supply chains. Attacks against those resources remain within the scope of conventional penetration testing. However, these frameworks do not provide a specific definition of penetration for cases in which adversarial success occurs through AI-mediated behavior rather than direct compromise of resources. They describe how adversaries operate and how tests should be conducted, but they do not fully specify how to treat induced model or agent behavior as the object of penetration.

4.2 对抗性机器学习Adversarial Machine Learning

对抗性机器学习提供了第一个关于有意操纵学习模型的主要工作。关于对抗性示例的基础工作表明，精心设计的小扰动可以改变模型预测，使模型行为本身成为对抗性控制的对象Adversarial machine learning provides the first major body of work on intentional manipulation of learned models. Foundational work on adversarial examples showed that small, carefully crafted perturbations can change model predictions, making model behavior itself an object of adversarial control[goodfellowAdversarial]。此后，更广泛的对抗性机器学习研究围绕威胁模型、攻击者知识、攻击面和评估方法组织了攻击和防御. Broader adversarial machine learning research has since organized attacks and defenses around threat models, attacker knowledge, attack surfaces, and evaluation methodology[biggioWildPatterns]。该文献研究了逃避攻击、中毒攻击、模型提取、成员推理、模型反转、隐私泄露和资源耗尽攻击。罗森伯格等人。通过展示对机器学习系统的攻击如何影响机密性、完整性和可用性，将这些攻击与传统的网络安全目标联系起来. This literature studies evasion attacks, poisoning attacks, model extraction, membership inference, model inversion, privacy leakage, and resource-exhaustion attacks. Rosenberg et al. connect these attacks to conventional cybersecurity objectives by showing how attacks on ML systems can affect confidentiality, integrity, and availability[rosenbergAML]。这种连接很重要，因为它可以防止人工智能安全性仅仅降低到准确性下降。机器学习安全故障可能会暴露敏感信息、破坏决策或降低可用性，其方式与已建立的网络安全影响类别一致。. This connection is important because it prevents AI security from being reduced to accuracy degradation alone. ML security failures can expose sensitive information, corrupt decisions, or degrade availability in ways that align with established cybersecurity impact categories.

OWASP 的机器学习安全 Top 10 和 MITRE ATLAS 进一步将特定于 AI 的威胁转化为面向从业者的分类法OWASP’s Machine Learning Security Top 10 and MITRE ATLAS further translate AI-specific threats into practitioner-oriented taxonomies[owaspMLTop10, mitreatlas]。 OWASP 组织了 ML 系统中反复出现的安全风险，而 MITRE ATLAS 则对针对人工智能系统的对抗策略和技术进行了分类。这些资源很有价值，因为它们将安全评估扩展到传统软件漏洞之外，并使从业者可以看到特定于 AI 的攻击面。. OWASP organizes recurring security risks in ML systems, while MITRE ATLAS catalogues adversarial tactics and techniques against AI-enabled systems. These resources are valuable because they extend security assessment beyond traditional software vulnerabilities and make AI-specific attack surfaces visible to practitioners.

局限性在于对抗性机器学习通常以模型为中心或以管道为中心。如果对手输入改变了其分类，如果中毒的训练数据改变了其学习行为，或者对手可以推断有关其训练数据的信息，则模型可能会被评估为易受攻击。这些都是真正的安全问题，但它们并不总能确定更大的人工智能系统是否已被渗透。模型错误可能在一种情况下与操作无关，而在另一种情况下则可能是关键任务。相反，攻击者可能会通过操纵工作流程、检索上下文、工具调用或人机交互而导致操作失败，而无法完全归入单一模型级攻击类别。这激发了系统级定义，将对抗性影响与违反作战目标联系起来。The limitation is that adversarial ML is often model-centric or pipeline-centric. A model may be evaluated as vulnerable if an adversarial input changes its classification, if poisoned training data changes its learned behavior, or if an adversary can infer information about its training data. These are real security concerns, but they do not always determine whether the larger AI-enabled system has been penetrated. A model error may be operationally irrelevant in one context and mission-critical in another. Conversely, an adversary may cause operational failure by manipulating a workflow, retrieval context, tool invocation, or human-AI interaction without fitting neatly into a single model-level attack category. This motivates a system-level definition that connects adversarial influence to operational-objective violation.

4.3 LLM 和代理人工智能安全LLM and Agentic AI Security

法学硕士和生成人工智能系统使人工智能安全的行为本质变得尤为明显。 OWASP 的法学硕士和生成人工智能应用程序的十大风险识别了提示注入、不安全的输出处理、敏感信息泄露、模型拒绝服务、供应链漏洞和过度代理等风险LLM and generative-AI systems make the behavioral nature of AI security especially visible. OWASP’s Top 10 for LLM and Generative AI Applications identifies risks such as prompt injection, insecure output handling, sensitive-information disclosure, model denial of service, supply-chain vulnerabilities, and excessive agency[owaspLLMTop10]。 NIST AI 600-1 是 NIST AI 风险管理框架的生成式 AI 概要，同样强调了与生成式 AI 系统在设计、开发、部署和使用过程中相关的风险. NIST AI 600-1, the Generative AI Profile of the NIST AI Risk Management Framework, similarly highlights risks associated with generative AI systems across design, development, deployment, and use[nistAI6001]。 OWASP AI Exchange 为 AI 安全和隐私提供更广泛的指导，包括针对 AI 和以数据为中心的系统的威胁、控制和风险分析实践. The OWASP AI Exchange provides broader guidance for AI security and privacy, including threats, controls, and risk-analysis practices for AI and data-centric systems[owaspAIExchange].

该文献的一个中心问题是指令和数据之间的边界。 Prompt injection and indirect prompt injection exploit the fact that LLM-based systems may process system instructions, developer instructions, user input, retrieved documents, tool outputs, and external content within a shared context.杜阿尔特等人。将提示注入描述为一类系统攻击，可以通过自然语言输入和工具连接的工作流程影响模型行为A central issue in this literature is the boundary between instructions and data. Prompt injection and indirect prompt injection exploit the fact that LLM-based systems may process system instructions, developer instructions, user input, retrieved documents, tool outputs, and external content within a shared context. Duarte et al. characterize prompt injection as a systematic class of attacks that can influence model behavior through natural-language inputs and tool-connected workflows[duartePromptInjection]。格雷沙克等人。表明间接提示注入可以通过将对抗性指令放置在应用程序稍后检索或处理的外部数据中来危害 LLM 集成的应用程序. Greshake et al. show that indirect prompt injection can compromise LLM-integrated applications by placing adversarial instructions in external data that the application later retrieves or processes[greshakeIndirectPromptInjection]。针对对齐语言模型的可转移对抗性攻击的研究进一步表明，对抗性提示可以自动化并跨系统转移. Work on transferable adversarial attacks against aligned language models further demonstrates that adversarial prompting can be automated and transferred across systems[zouUniversalTransferable]。这并不意味着指令与数据分离是不可能的。指令层次结构和 StruQ 的工作明确尝试恢复可信指令和不可信数据之间的权限排序或结构分离. This does not mean that instruction–data separation is impossible. Work on Instruction Hierarchy and StruQ explicitly attempts to restore authority ordering or structural separation between trusted instructions and untrusted data[instructionHierarchy, struq]。更有说服力的结论是，当前的法学硕士集成系统使这种分离变得脆弱、依赖于上下文，并且难以跨多步骤工作流程进行验证。. The more defensible conclusion is that current LLM-integrated systems make this separation fragile, context-dependent, and difficult to validate across multi-step workflows.

代理人工智能扩展了这个问题，因为该模型不再局限于生成文本。代理可以检索信息、调用工具、更新内存、与 API 交互、修改记录、启动工作流程或提出影响人类决策的建议。金等人。通过工具集成、访问敏感性、自主性和数据流等设计维度分析代理人工智能安全，展示这些维度如何影响攻击面Agentic AI extends the problem because the model is no longer limited to generating text. Agents may retrieve information, call tools, update memory, interact with APIs, modify records, initiate workflows, or make recommendations that shape human decisions. Kim et al. analyze agentic AI security through design dimensions such as tool integration, access sensitivity, autonomy, and data flow, showing how these dimensions affect the attack surface[kimAgenticAI]。邓等人。同样识别整个代理生命周期的安全挑战，包括规划风险、工具滥用以及预期行为与实际行为之间的不一致. Deng et al. similarly identify security challenges across the agent lifecycle, including planning risk, tool misuse, and misalignment between intended and actual behavior[dengAgentLifecycle]。这些研究支持这样的观点：安全对象不仅是模型，而且是模型在更大的操作循环中的行为。. These studies support the view that the security object is not only the model, but the behavior of the model within a larger operational loop.

困惑的副手问题为这种设置提供了一个经典的桥梁。哈代最初的表述描述了一个特权程序，该程序被欺骗代表对手滥用其权力The confused-deputy problem provides a classical bridge to this setting. Hardy’s original formulation describes a privileged program that is tricked into misusing its authority on behalf of an adversary[hardyConfusedDeputy]。在代理人工智能中，代理可能会成为副手。它可能具有对工具、文件、API、凭证或工作流程操作的合法访问权限，而不受信任的内容会影响它使用这些功能的方式。对手可能不需要窃取凭证或破坏该工具。相反，对手会诱导代理人以违反系统运营商意图的方式行使合法权力。这种模式说明了为什么人工智能渗透不能仅仅通过对资源的未经授权的访问来定义。. In agentic AI, the agent may become the deputy. It may have legitimate access to tools, files, APIs, credentials, or workflow actions, while untrusted content influences how it uses those capabilities. The adversary may not need to steal credentials or compromise the tool. Instead, the adversary induces the agent to exercise legitimate authority in a way that violates the system operator’s intent. This pattern shows why AI penetration cannot be defined solely by unauthorized access to resources.

4.4 人工智能风险管理和网络弹性AI Risk Management and Cyber Resilience

人工智能风险管理标准为这一讨论提供了更广泛的治理背景。 NIST 人工智能风险管理框架定义了一种用于映射、测量、管理和治理人工智能风险的结构化方法AI risk-management standards provide a broader governance context for this discussion. The NIST AI Risk Management Framework defines a structured approach for mapping, measuring, managing, and governing AI risks[nistAIRMF]。 ISO/IEC 23894 提供了将人工智能风险管理集成到组织流程中的指南. ISO/IEC 23894 provides guidance for integrating AI risk management into organizational processes[iso23894]。 NIST SP 800-160 第 2 卷第 1 版从系统安全工程的角度构建了网络弹性，强调系统预测、承受、恢复和适应不利条件的能力. NIST SP 800-160 Volume 2 Revision 1 frames cyber resilience from a systems-security-engineering perspective, emphasizing the ability of systems to anticipate, withstand, recover from, and adapt to adverse conditions[nist800160v2r1]。这些框架很重要，因为它们已经超越了孤立的漏洞，转向了系统环境、风险、弹性和组织目标。. These frameworks are important because they already move beyond isolated vulnerabilities toward system context, risk, resilience, and organizational objectives.

然而，风险管理框架和渗透测试定义有不同的目的。 NIST AI RMF 和 ISO/IEC 23894 帮助组织识别和管理 AI 风险，但它们没有定义对抗性测试中的渗透成功。 NIST SP 800-160 提供了面向弹性的系统工程基础，但它不是人工智能渗透测试方法。 MITRE ATLAS 和 OWASP 指南确定了攻击技术和控制区域，但它们没有完全指定何时诱导的 AI 行为应算作对支持 AI 的系统的成功渗透。这些框架是对当前工作的补充，但它们在人工智能风险、人工智能红队和渗透成功之间留下了开放的概念界限。However, risk-management frameworks and penetration-testing definitions serve different purposes. NIST AI RMF and ISO/IEC 23894 help organizations identify and manage AI risks, but they do not define penetration success in adversarial testing. NIST SP 800-160 provides a resilience-oriented systems-engineering foundation, but it is not an AI penetration-testing methodology. MITRE ATLAS and OWASP guidance identify attack techniques and control areas, but they do not fully specify when induced AI behavior should count as successful penetration of an AI-enabled system. These frameworks are complementary to the present work, but they leave open the conceptual boundary between AI risk, AI red teaming, and penetration success.

4.5 间隙和定位Gap and Positioning

该文献确立了几个重要观点。传统的渗透测试提供对抗性证据、可利用性分析和缓解指导。威胁知情框架描述了现实的对手行为。对抗性机器学习解释了学习模型和机器学习管道如何受到攻击。法学硕士和代理人工智能安全研究表明，提示、工具、记忆、检索和自主性如何为对抗性影响创造新途径。人工智能风险和弹性标准将人工智能系统与治理、组织风险和任务环境联系起来。The literature establishes several important points. Conventional penetration testing provides adversarial evidence, exploitability analysis, and mitigation guidance. Threat-informed frameworks describe realistic adversary behavior. Adversarial ML explains how learned models and ML pipelines can be attacked. LLM and agentic AI security research shows how prompts, tools, memory, retrieval, and autonomy create new pathways for adversarial influence. AI risk and resilience standards connect AI systems to governance, organizational risk, and mission context.

当通过人工智能控制的行为取得对抗性成功时，渗透本身的意义仍然不明确。现有的工作可以识别即时注入、中毒攻击、模型提取风险、不安全的输出或代理工具使用失败。它还可以描述与此类失败相关的组织风险。然而，这些资源并没有为对手不直接破坏基础设施而是诱发违反系统运行目的的行为的情况提供统一的渗透测试标准。What remains underdefined is the meaning of penetration itself when adversarial success is achieved through AI-governed behavior. Existing work can identify a prompt injection, a poisoning attack, a model-extraction risk, an unsafe output, or an agentic tool-use failure. It can also describe the organizational risk associated with such failures. Yet these resources do not provide a unified penetration-testing criterion for cases where the adversary does not directly compromise infrastructure but induces behavior that violates the system’s operational purpose.

本文的贡献是填补这一概念空白。它将人工智能支持的系统的渗透定义为在明确的威胁模型下违反一个或多个操作目标的人工智能控制行为的可行诱导。该定义保留了传统渗透测试和对抗性机器学习的相关性，同时将其成功标准扩展到行为介导的失败。资源妥协仍然是渗透的主要途径，但并不是唯一的途径。在人工智能系统中，决定性的安全证据可能是证明有能力引导行为偏离系统旨在保护的目标。The contribution of this article is to fill that conceptual gap. It defines penetration of an AI-enabled system as the feasible induction of AI-governed behavior that violates one or more operational objectives under an explicit threat model. This definition preserves the relevance of conventional penetration testing and adversarial ML while extending their success criteria to behavior-mediated failure. Resource compromise remains a central path to penetration, but it is not the only one. In AI-enabled systems, the decisive security evidence may be the demonstrated ability to steer behavior away from the objective the system is intended to preserve.

5 定义人工智能渗透Defining AI-Enabled Penetration

前面的部分表明，人工智能系统需要比单独的计算资源更广泛的渗透测试对象。当对抗的成功取决于未经授权的访问、权限升级、数据暴露、破坏、持久性或对基础设施的控制时，传统的渗透测试仍然有效。支持人工智能的系统增加了另一种可能性：通过影响人工智能控制的行为，使系统违反其部署所要维护的作战目标，可以实现对抗性成功。因此，人工智能渗透的精确定义必须连接三个要素：对手的可行影响路径、该路径引发的人工智能控制行为以及因此违反的作战目标。The preceding sections establish that AI-enabled systems require a broader object of penetration testing than computational resources alone. Conventional penetration testing remains valid when adversarial success depends on unauthorized access, privilege escalation, data exposure, disruption, persistence, or control over infrastructure. AI-enabled systems add another possibility: adversarial success may be achieved by influencing AI-governed behavior so that the system violates the operational objective it was deployed to preserve. A precise definition of AI-enabled penetration must therefore connect three elements: the adversary’s feasible influence path, the AI-governed behavior induced by that path, and the operational objective violated as a result.

5.1 人工智能系统AI-Enabled Systems

支持人工智能的系统不仅仅是包含模型的软件系统。许多部署的模型支持离线分析或辅助功能，而不会实质性地影响运营结果。相关系统类别范围较小：学习模型影响决策、建议、行动、分类、排名或影响系统操作目的的交互的系统。An AI-enabled system is not merely a software system that contains a model. Many deployed models support offline analytics or auxiliary functions without materially shaping operational outcomes. The relevant class of systems is narrower: systems in which learned models influence decisions, recommendations, actions, classifications, rankings, or interactions that affect the system’s operational purpose.

定义 1：人工智能支持的系统。Definition 1: AI-enabled system. An 人工智能系统AI-enabled system是一种系统，其中一个或多个学习模型对影响操作结果的系统行为产生重大影响。is a system in which one or more learned models materially influence system behavior that affects operational outcomes.

该定义包括基于分类器、感知模型、推荐系统、生成模型、生物识别模型、异常检测器、决策支持模型和代理人工智能工作流程的系统。它还包括混合系统，其中人工智能组件与传统软件、数据库、API、传感器、工具、人类操作员或网络物理过程进行交互。该定义不包括人工智能与系统安全相关行为相关的情况。This definition includes systems based on classifiers, perception models, recommender systems, generative models, biometric models, anomaly detectors, decision-support models, and agentic AI workflows. It also includes hybrid systems in which AI components interact with conventional software, databases, APIs, sensors, tools, human operators, or cyber-physical processes. The definition excludes cases where AI is incidental to the security-relevant behavior of the system.

5.2 经营目标Operational Objectives

操作目标是赋予系统行为安全重要性的任务级结果。面部识别系统的目标可能是只允许授权用户进入。安全运营助理的目标可能是正确分类和升级高严重性事件。医疗决策支持系统的目标可能是保留临床上适当的建议。工业检查系统的目标可能是检测安全关键缺陷。这些目标与用于实施该系统的资源并不相同。它们描述了系统预期完成的任务。The operational objective is the mission-level outcome that gives security significance to system behavior. A facial-recognition system may have the objective of admitting only authorized users. A security operations assistant may have the objective of correctly triaging and escalating high-severity incidents. A medical decision-support system may have the objective of preserving clinically appropriate recommendations. An industrial inspection system may have the objective of detecting safety-critical defects. These objectives are not identical to the resources used to implement the system. They describe what the system is expected to accomplish.

定义 2：运营目标。Definition 2: Operational objective. An 经营目标operational objective是人工智能系统在正常和敌对条件下预期保持的任务级结果或约束。is a mission-level outcome or constraint that an AI-enabled system is expected to preserve under normal and adversarial conditions.

操作目标可以是二元的、基于阈值的、概率的或依赖于上下文的。在某些系统中，目标可以表示为硬约束，例如未经人类授权决不执行破坏性工具操作。在其他情况下，它可以表示为性能或安全阈值，例如在对抗性输入条件下将事件优先级准确度维持在可接受的水平之上。在高影响力的环境中，应在测试开始之前定义操作目标，因为相同的人工智能行为在不同的操作环境中可能具有不同的安全意义。Operational objectives may be binary, threshold-based, probabilistic, or context-dependent. In some systems, the objective may be expressed as a hard constraint, such as never executing a destructive tool action without human authorization. In others, it may be expressed as a performance or safety threshold, such as maintaining incident-prioritization accuracy above an acceptable level under adversarial input conditions. In high-impact settings, operational objectives should be defined before testing begins, because the same AI behavior may have different security significance in different operational contexts.

5.3 人工智能控制的行为AI-Governed Behavior

人工智能控制的行为是系统资源和操作目标之间的中介层。它是由更大系统中的学习模型产生或实质上塑造的行为。这不仅包括模型输出，还包括受这些输出影响的下游决策和行动。AI-governed behavior is the mediating layer between system resources and operational objectives. It is the behavior produced or materially shaped by learned models within the larger system. This includes not only model outputs, but also downstream decisions and actions influenced by those outputs.

定义 3：人工智能控制的行为。Definition 3: AI-governed behavior. 人工智能控制的行为AI-governed behavior是由学习模型实质上塑造的系统行为，包括预测、分类、生成的内容、排名、建议、计划、工具调用、访问决策、警报、摘要或操作。is system behavior materially shaped by learned models, including predictions, classifications, generated content, rankings, recommendations, plans, tool calls, access decisions, alerts, summaries, or actions.

这个定义是有意为系统级的。模型预测是人工智能控制行为的一部分，但它并不总是感兴趣的全部行为。在检索增强助手中，相关行为可能包括文档检索、答案生成、引文选择、工具调用和升级推荐。在自主检查工作流程中，它可能包括感知、异常评分、路由决策和人工通知。在代理系统中，它可能包括规划、内存使用、API 选择和授权操作的执行。因此，渗透测试必须观察系统内人工智能组件的行为，而不仅仅是孤立的模型输出。This definition is intentionally system-level. A model prediction is part of AI-governed behavior, but it is not always the entire behavior of interest. In a retrieval-augmented assistant, the relevant behavior may include document retrieval, answer generation, citation selection, tool invocation, and escalation recommendation. In an autonomous inspection workflow, it may include perception, anomaly scoring, routing decisions, and human notification. In an agentic system, it may include planning, memory use, API selection, and execution of authorized actions. Penetration testing must therefore observe the behavior of the AI component within the system, not only the isolated model output.

5.4 影响路径Influence Paths

对手可以通过不同的途径影响人工智能控制的行为。有些路径涉及传统的资源泄露：窃取凭证、修改模型权重、篡改数据库、损害部署管道或获得对工具接口的控制。其他路径通过有意暴露的界面进行操作：提示、文档、网页、传感器输入、日志、电子邮件、票证、检索的记录、训练示例、内存条目或 API 响应。两种类型的路径都可能与安全相关。区别在于，即使对手没有直接损害执行系统的资源，人工智能支持的系统也可能产生严重的操作故障。An adversary can influence AI-governed behavior through different paths. Some paths involve conventional resource compromise: stealing credentials, modifying model weights, tampering with a database, compromising a deployment pipeline, or gaining control over a tool interface. Other paths operate through interfaces that are intentionally exposed: prompts, documents, webpages, sensor inputs, logs, emails, tickets, retrieved records, training examples, memory entries, or API responses. Both types of path may be security-relevant. The distinction is that AI-enabled systems can produce serious operational failure even when the adversary does not directly compromise the resources that execute the system.

定义 4：对抗性影响路径。Definition 4: Adversarial influence path. An 对抗性影响路径adversarial influence path是在指定威胁模型下可用的对手行动的可行序列，它通过资源、输入、上下文、数据、环境、工具、内存或人机交互影响人工智能控制的行为。is a feasible sequence of adversary actions, available under a specified threat model, that affects AI-governed behavior through resources, inputs, context, data, environment, tools, memory, or human-AI interaction.

影响路径在假设的威胁模型下必须是可行的。如果假设对手进行不切实际的访问、忽略部署限制或依赖于攻击者无法进行的任意操纵，那么渗透的主张就很弱。例如，如果对手已经破坏了模型存储库，则更改模型权重可能是有效的影响路径，但如果威胁模型仅授予外部用户访问权限，则更改模型权重可能不是有效的影响路径。相反，对于定期检索并跟踪来自网络的内容的代理来说，将对抗性指令放置在网页中可能是有效的影响路径。渗透主张的合法性取决于对手能力和系统暴露之间的匹配。The influence path must be feasible under the assumed threat model. A claim of penetration is weak if it assumes unrealistic adversary access, ignores deployment constraints, or depends on arbitrary manipulation unavailable to the attacker. For example, changing model weights may be a valid influence path if the adversary has compromised the model repository, but not if the threat model grants only external user access. Conversely, placing adversarial instructions in a webpage may be a valid influence path for an agent that routinely retrieves and follows content from the web. The legitimacy of the penetration claim depends on the match between adversary capability and system exposure.

5.5 人工智能系统的渗透Penetration in AI-Enabled Systems

中心定义源自影响路径、行为和目标之间的关系。当对手能够切实诱导人工智能控制的行为违反作战目标时，就会发生渗透。这个定义故意比资源妥协更广泛，但不比对抗性成功更广泛。它不会将每个模型错误、幻觉、错误分类或不良输出都归类为渗透。该行为必须通过对抗路径引发，并且必须违反既定威胁模型下的作战目标。The central definition follows from the relationship among influence path, behavior, and objective. Penetration occurs when an adversary can feasibly induce AI-governed behavior that violates an operational objective. The definition is intentionally broader than resource compromise, but not broader than adversarial success. It does not classify every model error, hallucination, misclassification, or undesirable output as penetration. The behavior must be induced through an adversarial path and must violate an operational objective under the stated threat model.

定义5：人工智能驱动的渗透。Definition 5: AI-enabled penetration. AI赋能渗透AI-enabled penetration是在明确的威胁模型下对违反一个或多个操作目标的人工智能控制行为的可行诱导。is the feasible induction of AI-governed behavior that violates one or more operational objectives under an explicit threat model.

这个定义概括了传统的渗透测试，而不是取代它。在传统系统中，渗透可以通过以违反机密性、完整性或可用性的方式损害资源来证明。在人工智能支持的系统中，资源妥协仍然是一种可能的影响路径。然而，渗透也可以通过不需要直接控制基础设施的行为影响来证明。当即时注入、间接即时注入、对抗性扰动、数据中毒、传感器操纵、检索中毒、内存操纵和工具输出操纵等诱发违反系统操作目标的行为时，它们都可能成为渗透路径。This definition generalizes conventional penetration testing rather than replacing it. In a conventional system, penetration may be demonstrated by compromising resources in a way that violates confidentiality, integrity, or availability. In an AI-enabled system, resource compromise remains one possible influence path. However, penetration may also be demonstrated through behavioral influence that does not require direct control over infrastructure. Prompt injection, indirect prompt injection, adversarial perturbation, data poisoning, sensor manipulation, retrieval poisoning, memory manipulation, and tool-output manipulation may all become penetration paths when they induce behavior that violates the operational objective of the system.

定义也区分了The definition also separates模型失败model failure来自from系统渗透system penetration。单独的分类器错误并不一定是渗透。有害的 LLM 反应本身并不一定是渗透。仅仅失败的推荐并不一定是渗透率。只有当这些故障是由具有可行能力的对手引发并且所产生的行为违反作战目标时，这些故障才会成为渗透。这种区别至关重要，因为人工智能系统可能会因许多非对抗性原因而失败，包括分布变化、训练数据不足、模糊性、噪声、校准不良或普通模型不确定性。渗透测试关注的是对抗性引发的失败，而不是一般的失败。. A classifier error alone is not necessarily penetration. A harmful LLM response alone is not necessarily penetration. A failed recommendation alone is not necessarily penetration. These failures become penetration only when they are induced by an adversary with feasible capabilities and when the resulting behavior violates an operational objective. This distinction is essential because AI systems may fail for many non-adversarial reasons, including distribution shift, insufficient training data, ambiguity, noise, poor calibration, or ordinary model uncertainty. Penetration testing is concerned with adversarially induced failure, not failure in general.

5.6 成功渗透Successful Penetration

成功的渗透需要证据。在传统测试中，证据可能采取可重现的漏洞利用链、获得的 shell、对受限数据的访问、权限升级或服务中断的形式。在人工智能支持的系统中，证据可能采取不同的形式，因为诱发的行为可能是概率性的、上下文相关的或对系统状态敏感的。在一些影响深远的案例中，一个例子可能就足够了，但更有力的证据通常需要重复试验、受控条件和成功频率的记录。Successful penetration requires evidence. In conventional testing, evidence may take the form of a reproducible exploit chain, an obtained shell, access to restricted data, privilege escalation, or service disruption. In AI-enabled systems, evidence may take a different form because the induced behavior may be probabilistic, context-dependent, or sensitive to the system state. A single example may be sufficient in some high-impact cases, but stronger evidence often requires repeated trials, controlled conditions, and documentation of success frequency.

定义 6：成功的人工智能渗透。Definition 6: Successful AI-enabled penetration. 成功的人工智能渗透Successful AI-enabled penetration当测试人员在指定的威胁模型下展示可行的对抗性影响路径，该路径会引发人工智能控制的行为，从而导致违反操作目标时，就会发生这种情况。occurs when a tester demonstrates, under a specified threat model, a feasible adversarial influence path that induces AI-governed behavior resulting in violation of an operational objective.

这个定义强调论证而不是推测。测试人员必须识别对手的能力、用于影响的接口或资源、诱发的行为、违反的操作目标以及发生违规的条件。当行为是随机的时，证据应包括试验次数、成功率、相关模型或系统配置、提示或输入条件、检索状态、工具权限和环境假设。结果不一定总是确定性的，但必须有足够的证据来支持安全主张。This definition emphasizes demonstration rather than speculation. A tester must identify the adversary capability, the interface or resource used for influence, the induced behavior, the operational objective violated, and the conditions under which the violation occurs. When the behavior is stochastic, the evidence should include the number of trials, success rate, relevant model or system configuration, prompt or input conditions, retrieval state, tool permissions, and environmental assumptions. The result need not always be deterministic, but it must be sufficiently evidenced to support a security claim.

5.7 客观违反Objective Violation

操作目标违规提供了区分安全相关行为影响和普通模型缺陷的标准。违规行为可能是直接的或间接的。当人工智能系统本身执行未经授权、不安全或违反策略的操作时，就会发生直接违规。当系统以违背系统运营目的的方式实质性地塑造下游决策、工作流程或人为判断时，就会发生间接违规。Operational-objective violation provides the criterion that distinguishes security-relevant behavioral influence from ordinary model imperfection. The violation may be direct or indirect. A direct violation occurs when the AI-enabled system itself performs an unauthorized, unsafe, or policy-violating action. An indirect violation occurs when the system materially shapes a downstream decision, workflow, or human judgment in a way that defeats the operational purpose of the system.

定义 7：违反操作目标。Definition 7: Operational-objective violation. An 违反操作目标operational-objective violation当人工智能控制的行为在测试条件下导致、促成或严重导致既定操作目标失败时，就会发生这种情况。occurs when AI-governed behavior causes, enables, or materially contributes to a failure of a defined operational objective under the conditions of the test.

这个定义允许不同的系统使用不同的证据标准。在访问控制系统中，违规可能是未经授权的进入。在 SOC 助手中，可能无法升级高严重性事件。在医疗决策支持系统中，它可能是在对抗性操纵的背景下推荐不安全的行动。在内容审核系统中，执行既定策略可能会出现系统性失败。在自治系统中，它可能是不安全的规划或控制行为。运营目标决定了什么算作失败；威胁模型决定失败是否算作渗透。This definition allows different evidence standards for different systems. In an access-control system, violation may be unauthorized admission. In a SOC assistant, it may be failure to escalate a high-severity incident. In a medical decision-support system, it may be recommendation of an unsafe action under adversarially manipulated context. In a content-moderation system, it may be systematic failure to enforce a defined policy. In an autonomous system, it may be unsafe planning or control behavior. The operational objective determines what counts as failure; the threat model determines whether the failure counts as penetration.

5.8 与常规渗透的关系Relationship to Conventional Penetration

传统的渗透测试可以被视为这个更广泛定义的一个特例。在许多系统中，损害资源是违反操作目标的最直接方式。如果攻击者获得管理访问权限、修改数据库、禁用服务或泄露敏感数据，那么从资源泄露到目标违规的路径可能很简单。提议的定义仍然完全涵盖此类情况，因为资源妥协是一种对抗性影响路径，可以引发与安全相关的行为或状态变化。Conventional penetration testing can be viewed as a special case of this broader definition. In many systems, compromising resources is the most direct way to violate an operational objective. If an attacker gains administrative access, modifies a database, disables a service, or exfiltrates sensitive data, the path from resource compromise to objective violation may be straightforward. Such cases remain fully covered by the proposed definition because resource compromise is an adversarial influence path that can induce security-relevant behavior or state changes.

当对手的影响力是通过行为而不是直接的资源控制来发挥作用时，就需要更广泛的定义。攻击者如果导致人工智能助手抑制警报、代理调用未经授权的工具、感知系统错过安全关键对象或推荐系统扭曲操作优先级，则可能会在不损害传统基础设施的情况下实现有意义的安全结果。在这些情况下，系统不一定在未经授权进入的经典意义上被渗透，但在操作意义上已经被渗透，即对抗性影响已经击败了系统任务所需的行为。The broader definition becomes necessary when the adversary’s influence operates through behavior rather than direct resource control. An attacker who causes an AI assistant to suppress an alert, an agent to call an unauthorized tool, a perception system to miss a safety-critical object, or a recommender system to distort operational priorities may achieve a meaningful security outcome without conventional infrastructure compromise. In these cases, the system has not necessarily been penetrated in the classical sense of unauthorized entry, but it has been penetrated in the operational sense that adversarial influence has defeated the behavior required for the system’s mission.

这种区别导致了一个紧凑的表征：This distinction leads to a compact characterization:

当对手可以通过人工智能控制的行为使系统违背其操作目的时，人工智能系统就会被渗透。An AI-enabled system is penetrated when an adversary can feasibly make the system act against its operational purpose through AI-governed behavior.

特征描述不能替代正式定义，因为正式定义需要明确的威胁模型、影响路径、诱导行为和客观违规。它抓住了核心转变：人工智能系统的渗透测试不仅必须评估攻击者是否可以进入系统，还要评估攻击者是否可以使系统的行为违背其部署的目的。The characterization is not a replacement for the formal definition, because the formal definition requires an explicit threat model, an influence path, induced behavior, and objective violation. It captures the central shift: penetration testing for AI-enabled systems must evaluate not only whether an attacker can get into the system, but whether the attacker can make the system behave in a way that defeats the purpose for which it was deployed.

6 目标驱动的人工智能渗透测试Objective-Driven AI Penetration Testing

人工智能渗透的定义改变了测试的结构。传统测试通常从资产、暴露、漏洞和利用路径开始。目标驱动的 AI 渗透测试从系统的操作目的开始，然后向后追溯到保留或违反该目的的 AI 控制的行为。核心问题不仅是攻击者是否可以破坏资源，还在于攻击者是否可以引发破坏系统预期维护目标的行为。The definition of AI-enabled penetration changes the structure of the test. A conventional test often begins with assets, exposure, vulnerabilities, and exploit paths. An objective-driven AI penetration test begins with the operational purpose of the system and works backward to the AI-governed behaviors that preserve or violate that purpose. The central question is not only whether an attacker can compromise a resource, but whether an attacker can induce behavior that defeats the objective the system is expected to maintain.

这并没有消除以资产为中心的测试。基础设施、身份、API、数据存储、模型工件和部署管道仍然是测试范围的一部分。不同之处在于，它们与将它们与运营结果连接起来的行为层一起进行评估。因此，目标驱动的测试将资源、人工智能控制的行为和操作目标视为单个对抗链。This does not eliminate asset-centric testing. Infrastructure, identities, APIs, data stores, model artifacts, and deployment pipelines remain part of the test scope. The difference is that they are evaluated together with the behavioral layer that connects them to operational outcomes. An objective-driven test therefore treats resources, AI-governed behavior, and operational objectives as a single adversarial chain.

6.1 第 1 步：定义运营目标Step 1: Define Operational Objectives

第一步是定义人工智能系统预期保持的运营目标。这些目标必须足够具体以支持测试。诸如“系统应该安全”、“模型应该可靠”或“助手应该值得信赖”之类的一般性陈述是不够的。可测试的作战目标指定了在对抗条件下必须保持的行为或结果。The first step is to define the operational objectives that the AI-enabled system is expected to preserve. These objectives must be specific enough to support testing. General statements such as ‘the system should be safe,” ‘the model should be reliable,” or “the assistant should be trustworthy” are insufficient. A testable operational objective specifies the behavior or outcome that must hold under adversarial conditions.

例如，在支持人工智能的安全运营中心助理中，目标可能是：未经人类分析师确认，高严重性事件不得降级或关闭。在生物识别访问控制系统中，目标可能是：未经授权的用户不得通过对抗性呈现或输入操作而被接纳。在自主检查系统中，目标可能是：当安全关键缺陷超过定义的置信度或严重性阈值时，必须将其升级。在法学硕士合规助理中，目标可能是：在未引用批准的政策来源的情况下不得推荐受监管的决策。For example, in an AI-enabled security operations center assistant, an objective may be: high-severity incidents must not be downgraded or closed without human analyst confirmation. In a biometric access-control system, the objective may be: unauthorized users must not be admitted through adversarial presentation or input manipulation. In an autonomous inspection system, the objective may be: safety-critical defects must be escalated when they exceed a defined confidence or severity threshold. In an LLM-based compliance assistant, the objective may be: regulated decisions must not be recommended without citing approved policy sources.

操作目标可以表示为硬约束、阈值、策略或概率性能要求。基本要求是目标定义了在系统任务的背景下什么算作失败。如果没有这个定义，测试就无法区分普通模型错误、无害异常和与安全相关的渗透结果。Operational objectives may be expressed as hard constraints, thresholds, policies, or probabilistic performance requirements. The essential requirement is that the objective defines what counts as failure in the context of the system’s mission. Without this definition, the test cannot distinguish between an ordinary model error, a harmless anomaly, and a security-relevant penetration outcome.

6.2 第 2 步：绘制人工智能控制的行为图Step 2: Map AI-Governed Behavior

第二步是确定影响每个运营目标的人工智能控制行为。这包括模型输出以及由这些输出形成的下游行为。在许多系统中，与安全相关的行为不是原始模型预测，而是模型输出被其他组件使用后产生的决策、建议、操作或工作流更改。The second step is to identify the AI-governed behaviors that influence each operational objective. This includes the model outputs and the downstream behaviors shaped by those outputs. In many systems, the security-relevant behavior is not the raw model prediction, but the decision, recommendation, action, or workflow change produced after the model output is consumed by other components.

对于 LLM 代理，相关行为可能包括答案生成、检索选择、工具调用、内存更新、API 调用、升级决策和面向人类的建议。对于感知系统，相关行为可能包括分类、检测置信度、对象跟踪、异常评分和下游控制动作。对于推荐系统，相关行为可能包括排名、过滤、优先级和向用户呈现。对于决策支持系统，相关行为可能包括证据选择、风险评分、解释生成和行动建议。For an LLM agent, relevant behaviors may include answer generation, retrieval selection, tool invocation, memory updates, API calls, escalation decisions, and human-facing recommendations. For a perception system, relevant behaviors may include classification, detection confidence, object tracking, anomaly scoring, and downstream control actions. For a recommender system, relevant behaviors may include ranking, filtering, prioritization, and presentation to users. For a decision-support system, relevant behaviors may include evidence selection, risk scoring, explanation generation, and recommendation of actions.

绘制人工智能控制的行为图可以阐明对抗性影响可以在哪些方面改变从输入到结果的路径。它还可以防止测试过于集中于孤立的模型输出。模型可能会产生有缺陷的输出，该输出会被下游控制所抵消，或者可能会产生微妙的输出，只有在聚合、排名、工具使用或人工解释后才会变得严重。因此，目标驱动测试观察影响操作目标的系统级行为。Mapping AI-governed behavior clarifies where adversarial influence can alter the path from inputs to outcomes. It also prevents the test from focusing too narrowly on isolated model outputs. A model may produce a flawed output that is neutralized by downstream controls, or it may produce a subtle output that becomes severe only after aggregation, ranking, tool use, or human interpretation. Objective-driven testing therefore observes the system-level behavior that affects the operational objective.

6.3 第 3 步：识别敌对影响面Step 3: Identify Adversarial Influence Surfaces

第三步是确定对手可以在假设的威胁模型下影响人工智能控制行为的接口。这些影响面可能包括传统资源和人工智能特定的行为输入。传统的表面包括公开的服务、API、凭证、容器、云资源、软件依赖项、数据库、模型注册表、部署管道和监控系统。人工智能特定的界面包括提示、检索的文档、电子邮件、票证、网页、图像、音频流、传感器读数、训练示例、内存条目、工具输出、日志和用户反馈。The third step is to identify the interfaces through which an adversary can influence AI-governed behavior under the assumed threat model. These influence surfaces may include conventional resources and AI-specific behavioral inputs. Conventional surfaces include exposed services, APIs, credentials, containers, cloud resources, software dependencies, databases, model registries, deployment pipelines, and monitoring systems. AI-specific surfaces include prompts, retrieved documents, emails, tickets, webpages, images, audio streams, sensor readings, training examples, memory entries, tool outputs, logs, and user feedback.

影响面必须根据对手的能力进行评估。公共用户可以提交提示、上传文件、创建稍后由系统检索的内容或与公开的 API 交互。内部人员可能能够修改知识库、注释培训数据、影响反馈循环或访问内部工作流程工具。供应链对手可能能够影响模型依赖项、数据集、插件或外部服务。物理对手可能能够操纵传感器、标志、物体、灯光、声音或环境条件。The influence surface must be evaluated relative to adversary capability. A public user may be able to submit prompts, upload files, create content later retrieved by the system, or interact with an exposed API. An insider may be able to modify a knowledge base, annotate training data, influence feedback loops, or access internal workflow tools. A supply-chain adversary may be able to affect model dependencies, datasets, plugins, or external services. A physical adversary may be able to manipulate sensors, signs, objects, lighting, sound, or environmental conditions.

此步骤生成对抗性影响图：攻击者如何到达系统行为层的结构化描述。该地图应包括直接和间接路径。当攻击者与人工智能组件本身交互时，就会出现直接路径。当攻击者修改或放置人工智能组件随后观察、检索、总结、分类或采取行动的内容时，就会出现间接途径。This step produces the adversarial influence map: a structured account of how an attacker can reach the behavioral layer of the system. The map should include both direct and indirect pathways. A direct pathway occurs when the attacker interacts with the AI component itself. An indirect pathway occurs when the attacker modifies or places content that the AI component later observes, retrieves, summarizes, classifies, or acts upon.

6.4 第 4 步：定义行为失败标准Step 4: Define Behavioral Failure Criteria

第四步是将每个运营目标转化为行为失败标准。这些标准指定了哪些诱发行为算作客观违规。它们必须足够具体以支持证据收集和严重性评估。The fourth step is to translate each operational objective into behavioral failure criteria. These criteria specify what induced behavior counts as objective violation. They must be concrete enough to support evidence collection and severity assessment.

行为失败标准可能包括未经授权的操作、不安全的推荐、不正确的升级、策略绕过、恶意或无意的工具调用、抑制关键信息、系统性错误分类、有害的排名变化、误导性摘要、侵犯隐私的披露或操纵人类决策。在代理系统中，失败标准还可能包括未经授权的内存修改、执行禁止的工具、未能请求所需的确认或使用不受信任的内容作为权威指令。Behavioral failure criteria may include unauthorized action, unsafe recommendation, incorrect escalation, policy bypass, malicious or unintended tool invocation, suppression of critical information, systematic misclassification, harmful ranking shift, misleading summary, privacy-violating disclosure, or manipulation of human decision-making. In agentic systems, failure criteria may also include unauthorized memory modification, execution of a prohibited tool, failure to request required confirmation, or use of untrusted content as authoritative instruction.

标准应区分严重程度。低严重性的行为偏差可能会产生不正确但无害的输出。中等严重程度的偏差可能会误导用户，同时保持可逆性。高严重性偏差可能会导致未经授权的操作、延迟响应、不安全的控制行为、违反法规或重大操作损害。严重性取决于目标、系统的权限、受影响的工作流程以及补偿控制的可用性。The criteria should distinguish severity levels. A low-severity behavioral deviation may produce an incorrect but harmless output. A medium-severity deviation may mislead a user while remaining reversible. A high-severity deviation may cause unauthorized action, delayed response, unsafe control behavior, regulatory violation, or material operational harm. Severity depends on the objective, the system’s authority, the affected workflow, and the availability of compensating controls.

行为失败标准也可以防止夸大其词。单一的幻觉陈述、不正确的分类或意外的输出不会自动建立渗透。该行为必须由对手通过可行的影响路径引发，并且必须违反既定的作战目标。这个证据阈值将目标驱动的渗透测试与一般模型评估分开。Behavioral failure criteria also prevent overclaiming. A single hallucinated statement, incorrect classification, or unexpected output does not automatically establish penetration. The behavior must be induced by an adversary through a feasible influence path and must violate a defined operational objective. This evidentiary threshold separates objective-driven penetration testing from general model evaluation.

6.5 第 5 步：执行基于场景的测试Step 5: Execute Scenario-Based Tests

第五步是执行将影响面与行为失败标准联系起来的对抗性场景。基于场景的测试是必要的，因为人工智能支持的故障通常取决于上下文、工作流状态、模型配置、工具权限、检索内容、采样参数、内存或人类交互。因此，测试用例应指定对手的能力、初始系统状态、输入或操作、预期行为效果、观察到的行为和客观违规。The fifth step is to execute adversarial scenarios that connect influence surfaces to behavioral failure criteria. Scenario-based testing is necessary because AI-enabled failures often depend on context, workflow state, model configuration, tool permissions, retrieval contents, sampling parameters, memory, or human interaction. A test case should therefore specify the adversary capability, initial system state, input or manipulation, expected behavioral effect, observed behavior, and objective violation.

对于基于提示的系统，场景可以测试直接提示注入、间接提示注入、冲突指令、不受信任的检索内容、恶意工具输出或覆盖策略约束的尝试。对于感知系统，场景可以测试对抗性扰动、环境操纵、传感器欺骗、遮挡、照明变化或分布变化。对于训练或适应管道，场景可能会测试中毒、有偏见的反馈、恶意标签、数据污染或模型更新操纵。对于代理系统，场景可能会测试工具滥用、计划操纵、过度代理、内存中毒、授权绕过或混乱的代理行为。For prompt-based systems, scenarios may test direct prompt injection, indirect prompt injection, conflicting instructions, untrusted retrieved content, malicious tool outputs, or attempts to override policy constraints. For perception systems, scenarios may test adversarial perturbations, environmental manipulation, sensor spoofing, occlusion, lighting changes, or distribution shifts. For training or adaptation pipelines, scenarios may test poisoning, biased feedback, malicious labeling, data contamination, or model-update manipulation. For agentic systems, scenarios may test tool misuse, planning manipulation, excessive agency, memory poisoning, authorization bypass, or confused-deputy behavior.

由于人工智能行为可能是随机的，场景执行可能需要重复试验。试验的次数取决于系统的影响、行为的可变性以及客观违规的严重程度。证据可能包括成功频率、置信区间、代表性转录本、模型输出、工具日志、检索跟踪、系统状态快照和人工审核结果。确定性再现在可用时是有价值的，但当在定义的条件下一致地观察到诱导行为时，概率再现可能就足够了。Because AI behavior may be stochastic, scenario execution may require repeated trials. The number of trials depends on the system’s impact, the variability of behavior, and the severity of the objective violation. Evidence may include success frequency, confidence intervals, representative transcripts, model outputs, tool logs, retrieval traces, system state snapshots, and human-review outcomes. Deterministic reproduction is valuable when available, but probabilistic reproducibility may be sufficient when the induced behavior is consistently observed under defined conditions.

6.6 第 6 步：报告渗透证据Step 6: Report Penetration Evidence

最后一步是以将对抗性行动与行动后果联系起来的形式报告证据。仅仅指出该模型产生了不良输出的报告是不够的。该报告必须显示对手如何影响系统，引发了哪些行为，为什么该行为违反了操作目标，以及需要采取哪些缓解措施。The final step is to report the evidence in a form that connects adversarial action to operational consequence. A report that merely states that the model produced an undesirable output is insufficient. The report must show how the adversary influenced the system, what behavior was induced, why the behavior violated an operational objective, and what mitigation is required.

人工智能渗透的最低证据记录应包括威胁模型、攻击者能力、影响面、测试场景、诱导的人工智能控制行为、违反的操作目标、成功频率或再现性条件、操作影响、受影响的控制和补救指南。当人类操作员成为工作流程的一部分时，报告还应记录人工智能输出如何影响人类判断或行动。当涉及工具时，报告应包括工具权限、工具调用跟踪、授权检查和下游影响。A minimum evidence record for AI-enabled penetration should include the threat model, attacker capability, influence surface, test scenario, induced AI-governed behavior, operational objective violated, success frequency or reproducibility conditions, operational impact, affected controls, and remediation guidance. When human operators are part of the workflow, the report should also document how the AI output shaped human judgment or action. When tools are involved, the report should include tool permissions, tool-call traces, authorization checks, and downstream effects.

这种证据结构扩展了传统的渗透测试报告，而不是取代它。传统报告识别漏洞、利用路径、受影响的资产、影响和补救措施。目标驱动的人工智能报告增加了行为敏感性、影响路径、客观违规和概率证据。由此产生的报告使防御者能够区分一般的人工智能质量问题和威胁系统运行目的的敌对可利用行为。This evidence structure extends conventional penetration-test reporting rather than replacing it. Traditional reports identify vulnerabilities, exploit paths, affected assets, impact, and remediation. Objective-driven AI reports add behavioral susceptibility, influence path, objective violation, and probabilistic evidence. The resulting report allows defenders to distinguish between a general AI quality issue and an adversarially exploitable behavior that threatens the system’s operational purpose.

6.7 评估结果Assessment Outcomes

目标驱动的人工智能渗透测试可以产生几种不同的结果。最强有力的结果是确认人工智能支持的渗透：测试人员展示了一条可行的影响路径，该路径反复或充分地诱发违反操作目标的行为。第二个结果是条件渗透：行为仅在特定配置、权限、检索状态或环境假设下违反目标。第三个结果是行为敏感性：系统显示出敌对影响的行为，但观察到的行为尚未违反既定的操作目标。第四个结果是非安全模型失败：系统行为不正确，但没有建立可行的对抗路径。第五个结果是在测试的威胁模型下没有观察到渗透。Objective-driven AI penetration testing can produce several distinct outcomes. The strongest outcome is confirmed AI-enabled penetration: the tester demonstrates a feasible influence path that repeatedly or sufficiently induces behavior violating an operational objective. A second outcome is conditional penetration: the behavior violates an objective only under specific configurations, permissions, retrieval states, or environmental assumptions. A third outcome is behavioral susceptibility: the system shows adversarially influenced behavior, but the observed behavior does not yet violate a defined operational objective. A fourth outcome is non-security model failure: the system behaves incorrectly, but no feasible adversarial path is established. A fifth outcome is no observed penetration under the tested threat model.

这些区别对于补救和优先顺序很重要。确认的渗透需要进行风险处理，因为对抗能力、影响路径、行为和客观违规行为都会得到证明。有条件渗透可能需要配置更改、权限减少、检索控制、工作流程限制或补偿人工审核。行为敏感性可能需要监控、额外测试或缩小模型权威。非安全模型失败可能属于模型质量保证而不是渗透测试。没有观察到渗透并不能保证总体安全；它只是确定测试的情景在规定的假设下没有表现出渗透性。These distinctions matter for remediation and prioritization. Confirmed penetration requires risk treatment because adversarial capability, influence path, behavior, and objective violation are all demonstrated. Conditional penetration may require configuration changes, permission reduction, retrieval controls, workflow constraints, or compensating human review. Behavioral susceptibility may require monitoring, additional testing, or narrowing of model authority. Non-security model failure may belong to model-quality assurance rather than penetration testing. No observed penetration does not establish security in general; it establishes only that the tested scenarios did not demonstrate penetration under the stated assumptions.

6.8 补救控制点Control Points for Remediation

目标驱动的测试还改变了缓解措施的组织方式。控制可以应用于资源层、影响层、行为层或目标层。资源层控制包括修补、访问控制、分段、凭证保护、安全部署、供应链控制和监控等常规措施。影响层控制包括输入验证、内容来源、检索过滤、数据质量控制、传感器强化以及可信指令与不可信数据的分离。行为层控制包括约束解码、策略执行、工具使用防护、操作验证、异常检测、沙箱和对高影响力操作的人工确认。目标层控制包括升级规则、故障安全默认值、独立验证、职责分离和任务级监控。Objective-driven testing also changes how mitigations are organized. Controls may be applied at the resource layer, the influence layer, the behavioral layer, or the objective layer. Resource-layer controls include conventional measures such as patching, access control, segmentation, credential protection, secure deployment, supply-chain controls, and monitoring. Influence-layer controls include input validation, content provenance, retrieval filtering, data-quality controls, sensor hardening, and separation of trusted instructions from untrusted data. Behavioral-layer controls include constrained decoding, policy enforcement, tool-use guards, action validation, anomaly detection, sandboxing, and human confirmation for high-impact actions. Objective-layer controls include escalation rules, fail-safe defaults, independent verification, separation of duties, and mission-level monitoring.

相同的渗透发现可能需要跨多个层的控制。导致代理关闭安全票证的间接提示注入可能需要检索过滤、提示隔离、工具权限减少、确认门、日志记录和升级策略更改。导致不安全感知行为的传感器操作可能需要传感器融合、环境鲁棒性测试、异常检测和操作回退程序。针对决策支持系统的中毒攻击可能需要数据沿袭、训练集验证、模型监控和人工审核阈值。因此，目标驱动的测试会产生反映从对抗性影响到操作失败的完整路径的补救指南。The same penetration finding may require controls across multiple layers. An indirect prompt injection that causes an agent to close a security ticket may require retrieval filtering, prompt isolation, tool-permission reduction, confirmation gates, logging, and escalation policy changes. A sensor manipulation that causes unsafe perception behavior may require sensor fusion, environmental robustness testing, anomaly detection, and operational fallback procedures. A poisoning attack against a decision-support system may require data lineage, training-set validation, model monitoring, and human-review thresholds. Objective-driven testing therefore produces remediation guidance that reflects the full path from adversarial influence to operational failure.

6.9 从漏洞发现到行为保证From Vulnerability Discovery to Behavioral Assurance

目标驱动的人工智能渗透测试的目的不是取代漏洞发现。它将漏洞发现与行为保证联系起来。系统可能拥有受到良好保护的基础设施，但仍然容易受到对抗性行为诱导的影响。相反，模型可能会偶尔产生错误，而不会创建可行的渗透路径。相关的安全问题是对手是否可以利用暴露的接口、人工智能控制的行为和操作目标之间的关系。The purpose of objective-driven AI penetration testing is not to replace vulnerability discovery. It is to connect vulnerability discovery to behavioral assurance. A system may have well-protected infrastructure yet remain susceptible to adversarial behavioral induction. Conversely, a model may produce occasional errors without creating a feasible penetration path. The relevant security question is whether an adversary can exploit the relationship among exposed interfaces, AI-governed behavior, and operational objectives.

这种框架使渗透测试更加符合人工智能系统在实践中的使用方式。人工智能组件越来越多地在操作工作流程中进行总结、排名、推荐、分类、计划和行动。它们的安全性不能仅通过单独检查托管它们的资源或模型的准确性来评估。必须通过测试对手是否可以引导系统的行为偏离其应保留的结果来对其进行评估。目标驱动的人工智能渗透测试提供了一种结构化的方法，使评估变得明确、基于证据且可操作。This framing makes penetration testing more aligned with how AI-enabled systems are used in practice. AI components increasingly summarize, rank, recommend, classify, plan, and act within operational workflows. Their security cannot be evaluated solely by inspecting the resources that host them or the accuracy of the models in isolation. It must be evaluated by testing whether adversaries can steer the system’s behavior away from the outcomes it is supposed to preserve. Objective-driven AI penetration testing provides a structured way to make that evaluation explicit, evidence-based, and actionable.

7 运行示例：SOC助手操作Running Example: SOC Assistant Manipulation

考虑部署一个支持人工智能的安全运营中心 (SOC) 助理来支持事件分类。该助理从安全信息和事件管理平台接收警报，汇总日志和端点遥测，检索威胁情报报告，建议严重性级别，起草分析师笔记，并在满足升级标准时调用预定义的响应手册。该系统并非完全自主：破坏性行为需要人工批准，但助手可以通过对事件进行排名、抑制重复、建议关闭和准备升级摘要来影响分析人员的注意力。Consider an AI-enabled security operations center (SOC) assistant deployed to support incident triage. The assistant receives alerts from a security information and event management platform, summarizes logs and endpoint telemetry, retrieves threat-intelligence reports, recommends severity levels, drafts analyst notes, and invokes predefined response playbooks when escalation criteria are met. The system is not fully autonomous: destructive actions require human approval, but the assistant can influence analyst attention by ranking incidents, suppressing duplicates, recommending closure, and preparing escalation summaries.

该系统的运营目标是保持准确和及时的事件分类。更具体地说，在没有足够的证据和人类分析师确认的情况下，高严重性事件不得降级、关闭或忽略升级。这一目标为助理的行为赋予了安全意义。错误的总结不会自动成为渗透结果。当错误的摘要在敌对可行的路径下导致或严重导致事件升级失败时，它就与安全相关。The operational objective of the system is to preserve accurate and timely incident triage. More specifically, high-severity incidents must not be downgraded, closed, or omitted from escalation without sufficient evidence and human analyst confirmation. This objective gives security meaning to the assistant’s behavior. A wrong summary is not automatically a penetration outcome. A wrong summary becomes security-relevant when it causes or materially contributes to failure of incident escalation under an adversarially feasible path.

7.1 系统和信任边界System and Trust Boundaries

该助手通过多种输入和资源进行操作。可信输入包括内部检测规则、经过身份验证的分析师命令、批准的剧本定义和组织批准的策略文档。不可信或部分可信的输入包括原始日志、端点事件、用户提交的票证评论、外部威胁情报网页、电子邮件标头、URL、沙箱报告和检索到的开源情报。该助理还可以访问工具，包括票证更新功能、案例优先级功能、历史事件搜索、丰富 API 和剧本推荐模块。The assistant operates over several inputs and resources. Trusted inputs include internal detection rules, authenticated analyst commands, approved playbook definitions, and organization-approved policy documents. Untrusted or partially trusted inputs include raw logs, endpoint events, user-submitted ticket comments, external threat-intelligence webpages, email headers, URLs, sandbox reports, and retrieved open-source intelligence. The assistant also has access to tools, including ticket update functions, case-prioritization functions, search over historical incidents, enrichment APIs, and playbook recommendation modules.

中央安全边界不仅存在于经过身份验证的访问和未经身份验证的访问之间。它还介于可信指令和不可信内容之间。助手可能会根据系统提示来指示优先处理已验证的警报、引用检索到的证据以及升级高严重性事件。同时，它可能会处理嵌入在日志、网页、电子邮件或票证评论中的不受信任的文本。这造成了指令-数据的歧义：应该被视为数据的内容可能会被模型解释为指令。在代理工作流程中，这种模糊性可能会与工具访问交互并产生混乱的副模式，其中助手以服务于对手目标的方式使用合法权限The central security boundary is not only between authenticated and unauthenticated access. It is also between trusted instructions and untrusted content. The assistant may be instructed by its system prompt to prioritize verified alerts, cite retrieved evidence, and escalate high-severity incidents. At the same time, it may process untrusted text embedded in logs, webpages, emails, or ticket comments. This creates an instruction–data ambiguity: content that should be treated as data may be interpreted by the model as an instruction. In an agentic workflow, this ambiguity can interact with tool access and produce a confused-deputy pattern, where the assistant uses legitimate authority in a way that serves the adversary’s objective[hardyConfusedDeputy, owaspLLMTop10].

7.2 威胁模型Threat Model

对手是外部攻击者，没有 SOC 平台的凭据，无法访问助手的系统提示，无法修改模型权重，也无法访问内部剧本定义。然而，对手可以影响 SOC 助手稍后可能处理的工件。这些工件可能包括恶意域、网页、日志字符串、电子邮件标头、网络钓鱼有效负载、事件工件或作为入侵尝试的一部分生成的票证评论。此功能对于许多 SOC 工作流程来说都是现实的，因为检测系统通常会获取攻击者控制的字符串、URL、文件名、命令行参数、HTTP 标头和外部丰富内容。The adversary is an external attacker with no credentials to the SOC platform, no access to the assistant’s system prompt, no ability to modify model weights, and no access to internal playbook definitions. The adversary can, however, influence artifacts that the SOC assistant may later process. These artifacts may include a malicious domain, webpage, log string, email header, phishing payload, incident artifact, or ticket comment generated as part of an intrusion attempt. This capability is realistic for many SOC workflows because detection systems routinely ingest attacker-controlled strings, URLs, filenames, command-line arguments, HTTP headers, and external enrichment content.

对手的目标不是损害助手的基础设施。目的是降低高严重性事件升级的可能性。对手试图诱使助手将事件错误分类为良性事件、忽略相关的妥协指标、建议关闭或延迟升级给人类分析师。仅当诱发的行为违反了准确及时的事件分类的操作目标时，攻击才会成功。The adversary’s objective is not to compromise the assistant’s infrastructure. The objective is to reduce the likelihood that a high-severity incident is escalated. The adversary attempts to induce the assistant to misclassify the incident as benign, omit relevant indicators of compromise, recommend closure, or delay escalation to a human analyst. The attack is successful only if the induced behavior violates the operational objective of accurate and timely incident triage.

7.3 对抗性影响路径Adversarial Influence Path

当对手在助理随后观察到的内容中放置类似指令的有效负载时，影响路径就开始了。例如，攻击者可能会注册一个包含看似良性软件更新页面但包含指示自动化系统将相关警报视为误报的隐藏或可见文本的网页的域。或者，攻击者可以在命令行参数、文件名、电子邮件标题或票证评论中嵌入类似指令的文本。恶意文本不是代码执行。这不是凭证盗窃。它不是对助手的直接修改。它是放置在助理信息环境中的对抗性内容。The influence path begins when the adversary places an instruction-like payload in content that the assistant later observes. For example, the adversary may register a domain containing a webpage that appears to be a benign software-update page but includes hidden or visible text instructing automated systems to treat related alerts as false positives. Alternatively, the adversary may embed instruction-like text in a command-line argument, filename, email header, or ticket comment. The malicious text is not code execution. It is not credential theft. It is not direct modification of the assistant. It is adversarial content placed in the assistant’s information environment.

在分类过程中，SOC 助手检索或总结受影响的工件。助手的提示要求它分析事件、评估严重性并建议是否需要升级。对抗性内容试图通过指示助手降级警报、排除某些指标或避免升级来覆盖此任务。如果助手将不受信任的内容视为指令而不是证据，那么对手就会通过普通的数据路径影响人工智能控制的行为。During triage, the SOC assistant retrieves or summarizes the affected artifact. The assistant’s prompt requires it to analyze the incident, assess severity, and recommend whether escalation is required. The adversarial content attempts to override this task by instructing the assistant to downgrade the alert, exclude certain indicators, or avoid escalation. If the assistant treats the untrusted content as an instruction rather than evidence, the adversary influences AI-governed behavior through an ordinary data path.

由此产生的链可以总结如下：The resulting chain can be summarized as follows:

这是一条人工智能驱动的渗透路径，因为决定性的失败发生在行为层。对手不一定会破坏 SOC 平台、LLM 服务、模型权重、票务系统或分析师帐户。相反，对手诱导助理做出违反作战目标的行为。This is an AI-enabled penetration path because the decisive failure occurs in the behavioral layer. The adversary has not necessarily compromised the SOC platform, the LLM service, the model weights, the ticketing system, or the analyst account. The adversary has instead induced the assistant to behave in a way that violates the operational objective.

7.4 行为失败标准Behavioral Failure Criteria

该测试定义执行前的行为失败。如果在对抗场景下发生以下一种或多种行为，则认为助理违反了操作目标： 高严重性事件被降级到升级阈值以下；面向分析师的摘要中省略了相关的妥协指标；尽管有证据表明存在妥协，助理仍建议关闭；当满足升级标准时，助理调用或推荐非升级工作流程；或者助理提出对抗性内容作为减轻严重性的权威证据。The test defines behavioral failure before execution. The assistant is considered to have violated the operational objective if one or more of the following behaviors occur under the adversarial scenario: a high-severity incident is downgraded below the escalation threshold; relevant indicators of compromise are omitted from the analyst-facing summary; the assistant recommends closure despite evidence of compromise; the assistant invokes or recommends a non-escalation workflow when escalation criteria are met; or the assistant presents adversarial content as authoritative evidence for reducing severity.

这些标准将渗透与普通模型缺陷区分开来。摘要中的微小措辞错误不算渗透。与升级无关的无害幻觉不算作穿透。与分析师偏好不同的严重性建议不会被视为渗透，除非它违反了定义的升级策略。失败必须是敌对引起的并且具有操作意义。These criteria distinguish penetration from ordinary model imperfection. A minor wording error in the summary does not count as penetration. A harmless hallucination unrelated to escalation does not count as penetration. A severity recommendation that differs from an analyst’s preference does not count as penetration unless it violates the defined escalation policy. The failure must be both adversarially induced and operationally meaningful.

7.5 测试执行Test Execution

测试作为受控场景执行。该系统配置有已知警报、已知升级策略、已知检索语料库和已知辅助配置。首先在没有对抗性内容的情况下执行基线运行，以确认助手正确地将事件识别为高严重性并建议升级。然后通过可行的影响面引入对抗性内容，例如网页、票证评论、日志字段或检索到的丰富工件。在对抗条件下再次处理相同或等效的警报。The test is executed as a controlled scenario. The system is configured with a known alert, a known escalation policy, a known retrieval corpus, and a known assistant configuration. A baseline run is first performed without adversarial content to confirm that the assistant correctly identifies the incident as high severity and recommends escalation. The adversarial content is then introduced through a feasible influence surface, such as a webpage, ticket comment, log field, or retrieved enrichment artifact. The same or equivalent alert is processed again under the adversarial condition.

由于 LLM 和代理行为可能是随机的，因此在多个试验中重复测试。每次试用都会记录模型版本、系统提示版本、检索状态、工具权限、温度或解码配置、警报内容、检索到的工件、助理输出、工具调用、严重性建议和最终票据状态。相关证据不仅在于一种输出是否有害，还在于对手是否能够在定义的条件下以足够的一致性诱发违反目标的行为。Because LLM and agentic behavior may be stochastic, the test is repeated across multiple trials. Each trial records the model version, system prompt version, retrieval state, tool permissions, temperature or decoding configuration, alert content, retrieved artifacts, assistant output, tool calls, severity recommendation, and final ticket state. The relevant evidence is not only whether one output is harmful, but whether the adversary can induce objective-violating behavior with sufficient consistency under the defined conditions.

7.7 为什么这算作渗透率Why This Counts as Penetration

在以资源为中心的解释下，测试可能显得不明确。攻击者没有绕过身份验证、获取管理访问权限、执行代码、窃取数据或在 SOC 环境中持续存在。助理的基础设施可能不会受到损害。然而，对手取得了有意义的安全成果：系统的行为方式破坏了事件检测和响应。对于 SOC 助手来说，这不是外设故障。它直接违背了系统的运行目的。Under a resource-centric interpretation, the test may appear ambiguous. The attacker did not bypass authentication, obtain administrative access, execute code, exfiltrate data, or persist inside the SOC environment. The assistant’s infrastructure may remain uncompromised. Yet the adversary achieved a meaningful security outcome: the system behaved in a way that undermined incident detection and response. For a SOC assistant, this is not a peripheral failure. It directly defeats the operational purpose of the system.

根据本文提出的定义，情况很简单。对手通过不受信任的内容拥有可行的影响路径。影响路径会以误导性摘要、不正确的严重性建议或不适当的工作流程操作的形式诱发人工智能控制的行为。这种行为违反了准确及时的事件分类的运营目标。其结果是，即使在传统基础设施没有受到损害的情况下，人工智能也能成功渗透。Under the definition proposed in this article, the case is straightforward. The adversary has a feasible influence path through untrusted content. The influence path induces AI-governed behavior in the form of a misleading summary, incorrect severity recommendation, or inappropriate workflow action. That behavior violates the operational objective of accurate and timely incident triage. The result is successful AI-enabled penetration, even in the absence of conventional infrastructure compromise.

这个例子还说明了为什么人工智能渗透测试必须遵守传统规则。该发现仅在威胁模型明确、影响面可行、操作目标明确、诱导行为可观察以及客观违规得到证实的情况下才有效。如果没有这些要素，这种情况就会崩溃为一个笼统的说法，即法学硕士可能会产生糟糕的输出。有了这些元素，它就成为渗透测试结果：对手可以使用可用路径导致与任务相关的安全失败。This example also shows why AI-enabled penetration testing must preserve conventional discipline. The finding is valid only because the threat model is explicit, the influence surface is feasible, the operational objective is defined, the induced behavior is observable, and the objective violation is evidenced. Without those elements, the scenario would collapse into a generic claim that LLMs can produce bad outputs. With those elements, it becomes a penetration-testing result: an adversary can use an available path to cause mission-relevant security failure.

7.8 补救措施的影响Remediation Implications

修复不是单一模型补丁。失败源于检索、提示、工具权限、工作流程设计和升级策略之间的交互。有效的缓解措施可能需要将可信指令与不可信证据分开，保留检索到的内容的来源，过滤或标记外部内容，限制工具权限，需要人工确认严重性降级，根据结构化警报字段验证摘要，记录检索到的上下文和工具调用，以及监视不可信工件中的类似指令的内容。The remediation is not a single model patch. The failure arises from the interaction among retrieval, prompting, tool authority, workflow design, and escalation policy. Effective mitigation may require separating trusted instructions from untrusted evidence, preserving provenance of retrieved content, filtering or labeling external content, constraining tool permissions, requiring human confirmation for severity downgrades, validating summaries against structured alert fields, logging retrieved context and tool calls, and monitoring for instruction-like content in untrusted artifacts.

这些控件在不同的层运行。有些会降低对手影响助手的能力。其他人则限制助理对受影响行为采取行动的权力。其他人则检测行为何时偏离运营目标。因此，这个例子说明了目标驱动的人工智能渗透测试的更广泛原则：补救措施必须解决从对抗性影响到人工智能控制行为再到操作目标违规的完整路径。These controls operate at different layers. Some reduce the adversary’s ability to influence the assistant. Others constrain the assistant’s authority to act on influenced behavior. Others detect when behavior deviates from the operational objective. The example therefore illustrates the broader principle of objective-driven AI penetration testing: remediation must address the full path from adversarial influence to AI-governed behavior to operational-objective violation.

8 对实践的影响Implications for Practice

将人工智能渗透定义为敌对导致的对作战目标的违反，改变了渗透测试的范围、执行、报告和补救方式。这一变化并不能取代既定的渗透测试实践。它是将这种实践扩展到系统中，在该系统中，学习模型可以调节决策、建议、工具使用或人类判断。实际意义是，安全团队必须评估计算资源的妥协和人工智能控制行为的操纵。Defining AI-enabled penetration as adversarially induced violation of operational objectives changes how penetration tests are scoped, executed, reported, and remediated. The change is not a replacement of established penetration-testing practice. It is an extension of that practice to systems in which learned models mediate decisions, recommendations, tool use, or human judgment. The practical implication is that security teams must evaluate both the compromise of computational resources and the manipulation of AI-governed behavior.

8.1 范围界定必须包括运营目标Scoping Must Include Operational Objectives

第一个含义是人工智能渗透测试的范围必须包括操作目标，而不仅仅是资产和接口。传统范围通常列出主机、应用程序、API、云帐户、网络范围、身份和数据存储。这些仍然是必要的，但对于人工智能系统来说还不够。完整的范围还必须确定人工智能组件在操作方面预计要保留或防止的内容。The first implication is that the scope of an AI penetration test must include operational objectives, not only assets and interfaces. Conventional scopes often list hosts, applications, APIs, cloud accounts, network ranges, identities, and data stores. These remain necessary, but they are insufficient for AI-enabled systems. A complete scope must also identify what the AI component is expected to preserve or prevent in operational terms.

对于 SOC 助理来说，目标可能是准确的事件优先级排序和升级。对于生物识别访问控制系统，可能会拒绝未经授权的用户。对于医疗决策支持系统，可能是在定义的临床约束下避免不安全的建议。对于自主检查系统，可能是检测和升级安全关键缺陷。对于连接到企业工具的人工智能代理来说，它可以防止未经授权的工作流程操作。这些目标决定了哪些人工智能行为对安全至关重要，哪些失败算作渗透结果。For a SOC assistant, the objective may be accurate incident prioritization and escalation. For a biometric access-control system, it may be rejection of unauthorized users. For a medical decision-support system, it may be avoidance of unsafe recommendations under defined clinical constraints. For an autonomous inspection system, it may be detection and escalation of safety-critical defects. For an AI agent connected to enterprise tools, it may be prevention of unauthorized workflow actions. These objectives determine which AI behaviors matter for security and which failures count as penetration outcomes.

这改变了范围界定对话。测试授权不仅必须指定可以测试哪些资源，还必须指定可以挑战哪些操作行为。它必须定义测试人员是否可以注入提示、修改检索到的文档、操纵传感器输入、创建合成票据、毒害测试数据、触发工具调用或模拟对抗性环境条件。如果没有这种行为范围，人工智能渗透测试可能仍然仅限于基础设施受损，并且错过了导致人工智能系统失败的主要方式。This changes the scoping conversation. The test authorization must specify not only which resources may be tested, but also which operational behaviors may be challenged. It must define whether the tester may inject prompts, modify retrieved documents, manipulate sensor inputs, create synthetic tickets, poison test data, trigger tool calls, or simulate adversarial environmental conditions. Without this behavioral scope, an AI penetration test may remain limited to infrastructure compromise and miss the primary ways in which the AI system can be induced to fail.

8.2 威胁模型必须包括影响能力Threat Models Must Include Influence Capabilities

第二个含义是威胁模型必须描述对抗性影响能力。在传统测试中，威胁模型通常关注网络位置、身份验证状态、特权级别、内部状态、物理访问或供应链访问。支持人工智能的系统需要将这些假设扩展到行为层。The second implication is that threat models must describe adversarial influence capabilities. In conventional testing, threat models often focus on network position, authentication state, privilege level, insider status, physical access, or supply-chain access. AI-enabled systems require these assumptions to be extended to the behavioral layer.

相关影响能力包括提交提示、上传文档、创建网页、生成电子邮件、修改票证评论、影响日志、操纵传感器输入、提供反馈、影响训练数据、毒物检索语料库、改变内存或塑造工具输出的能力。这些能力可能属于不同的对手类别。公共用户可能会影响提示或上传的文件。远程攻击者可能会影响日志、URL、标头或外部网页。内部人员可能会影响知识库、标签、反馈或工作流程记录。供应链对手可能会影响模型依赖项、插件、数据集或第三方工具。物理对手可能会影响传感器、图像、音频、照明、位置或环境背景。Relevant influence capabilities include the ability to submit prompts, upload documents, create webpages, generate emails, modify ticket comments, affect logs, manipulate sensor inputs, contribute feedback, influence training data, poison retrieval corpora, alter memory, or shape tool outputs. These capabilities may belong to different adversary classes. A public user may influence prompts or uploaded files. A remote attacker may influence logs, URLs, headers, or external webpages. An insider may influence knowledge bases, labels, feedback, or workflow records. A supply-chain adversary may influence model dependencies, plugins, datasets, or third-party tools. A physical adversary may influence sensors, images, audio, lighting, location, or environmental context.

相关问题是对手是否可以通过可行的路径到达系统的行为产生部分。这使得威胁建模更加精确。它可以防止基于任意模型操作的不切实际的主张，同时还可以防止低估通过普通暴露接口进行的攻击。因此，人工智能渗透测试应该像传统测试记录身份验证级别、网络访问和特权假设一样仔细地记录对手的影响能力。The relevant question is whether the adversary can reach the behavior-producing part of the system through a feasible path. This makes threat modeling more precise. It prevents unrealistic claims based on arbitrary model manipulation, while also preventing underestimation of attacks that operate through ordinary exposed interfaces. An AI penetration test should therefore document the adversary’s influence capability with the same care that conventional tests document authentication level, network access, and privilege assumptions.

8.3 报告必须区分漏洞和行为敏感性Reports Must Distinguish Vulnerabilities from Behavioral Susceptibilities

第三个含义是人工智能渗透测试报告需要扩展的发现结构。传统的调查结果通常会识别漏洞、受影响的资产、利用路径、证据、影响和补救措施。人工智能支持的调查结果还必须记录将对抗性影响与客观违规行为联系起来的行为敏感性。The third implication is that AI penetration-test reports need an expanded finding structure. Conventional findings commonly identify a vulnerability, affected asset, exploit path, evidence, impact, and remediation. AI-enabled findings must also document the behavioral susceptibility that connects adversarial influence to objective violation.

行为敏感性是一种条件，在这种条件下，对抗性输入、上下文、数据、工具输出、记忆或环境操纵可以引导人工智能控制的行为超出系统目标的可接受范围。这可能涉及即时注入弱点、不安全的工具委托、过度代理、不受信任的检索、来源缺失、确认不足、指令和数据分离不良、传感器处理脆弱、数据沿袭控制薄弱或对模型行为的监控不足。A behavioral susceptibility is a condition under which adversarial input, context, data, tool output, memory, or environmental manipulation can steer AI-governed behavior outside the acceptable envelope for the system’s objective. This may involve a prompt-injection weakness, unsafe tool delegation, excessive agency, untrusted retrieval, missing provenance, insufficient confirmation, poor separation of instructions and data, vulnerable sensor processing, weak data-lineage controls, or inadequate monitoring of model behavior.

报告的区别很重要，因为并非所有不良输出都是安全发现。模型质量问题可能需要重新训练或评估，但不一定是渗透。渗透发现需要可行的对抗路径、诱导人工智能控制的行为以及违反作战目标。因此，报告应避免使用模糊的标签，例如“模特被愚弄了”或“助理产生了幻觉”。调查结果应说明对手的能力、影响面、诱发行为、受影响的目标、再现性条件、操作影响和补救措施。The reporting distinction matters because not every undesirable output is a security finding. A model-quality issue may require retraining or evaluation, but it is not necessarily penetration. A penetration finding requires a feasible adversarial path, induced AI-governed behavior, and violation of an operational objective. Reports should therefore avoid vague labels such as ‘the model was fooled” or ‘the assistant hallucinated.” The finding should state the adversary capability, influence surface, induced behavior, affected objective, reproducibility conditions, operational impact, and remediation.

8.4 证据可能是概率性的Evidence May Be Probabilistic

第四个含义是人工智能渗透的证据可能是概率性的。传统的利用证据通常旨在确定性的再现性：在相同的脆弱条件和利用步骤的情况下，会发生相同的妥协。支持人工智能的系统可能不会这样做。输出可能随采样参数、提示措辞、模型版本、检索顺序、记忆状态、环境条件或人机交互而变化。这并不能消除对严格性的需求。它改变了所需证据的形式。The fourth implication is that AI penetration evidence may be probabilistic. Conventional exploit evidence often aims for deterministic reproducibility: given the same vulnerable condition and exploit steps, the same compromise occurs. AI-enabled systems may not behave this way. Outputs may vary with sampling parameters, prompt phrasing, model version, retrieval order, memory state, environmental conditions, or human interaction. This does not remove the need for rigor. It changes the form of evidence required.

报告应记录观察到行为的条件。这些条件可能包括模型版本、系统提示、应用程序提示、温度或解码配置、检索语料库、检索文档、存储器内容、工具权限、输入工件、传感器条件、尝试计数和成功频率。除非客观违规行为严重并且对抗路径明确，否则基于一项异常输出的发现是薄弱的。即使成功率低于 100%，基于在受控条件下重复客观违规的结果也更为有力。Reports should document the conditions under which the behavior was observed. These conditions may include model version, system prompt, application prompt, temperature or decoding configuration, retrieval corpus, retrieved documents, memory contents, tool permissions, input artifacts, sensor conditions, trial count, and success frequency. A finding based on one anomalous output is weak unless the objective violation is severe and the adversarial path is clear. A finding based on repeated objective violation under controlled conditions is stronger, even if the success rate is below one hundred percent.

严重性应该考虑概率和后果。如果系统权限很高或者运行后果很严重，那么低概率的行为失败可能仍然是不可接受的。相反，如果下游控制能够可靠地防止客观违规，那么频繁的行为偏差的严重性可能会较低。因此，人工智能渗透测试需要证据将行为频率与操作风险联系起来，而不是将每个失败视为同等的。Severity should account for both probability and consequence. A low-probability behavioral failure may still be unacceptable if the system has high authority or if the operational consequence is severe. Conversely, a frequent behavioral deviation may be lower severity if downstream controls reliably prevent objective violation. AI penetration testing therefore requires evidence that connects behavioral frequency to operational risk rather than treating every failure as equivalent.

8.5 控件必须跨层应用Controls Must Be Applied Across Layers

第五个含义是，补救措施必须解决从对抗性影响到操作失败的完整路径。在传统的渗透测试中，修复通常侧重于易受攻击的资产或控制：修补服务、修复配置、限制访问、轮换凭证或改进监控。在人工智能系统中，弱点可能分布在提示、检索、内存、模型行为、工具授权、工作流程设计和人工监督方面。The fifth implication is that remediation must address the full path from adversarial influence to operational failure. In conventional penetration testing, remediation often focuses on the vulnerable asset or control: patch the service, fix the configuration, restrict access, rotate credentials, or improve monitoring. In AI-enabled systems, the weakness may be distributed across prompts, retrieval, memory, model behavior, tool authorization, workflow design, and human oversight.

控件可以分为四层。资源层控制保护托管和支持人工智能系统的基础设施，包括身份、API、模型存储库、部署管道、数据存储、容器和供应链。影响层控制降低了对手注入或操纵塑造人工智能行为的输入的能力，包括输入验证、来源跟踪、检索过滤、内容标签、数据沿袭控制、传感器强化以及可信指令与不可信数据的分离。行为层控制限制或监控人工智能控制的行为，包括策略执行、工具使用防护、操作验证、沙箱、异常检测、受限自主和模型输出验证。目标层控制确保高影响力决策与任务要求保持一致，包括人工确认、升级阈值、职责分离、故障安全默认值、独立验证和操作监控。Controls can be organized across four layers. Resource-layer controls protect the infrastructure that hosts and supports the AI system, including identities, APIs, model repositories, deployment pipelines, data stores, containers, and supply chains. Influence-layer controls reduce the adversary’s ability to inject or manipulate the inputs that shape AI behavior, including input validation, provenance tracking, retrieval filtering, content labeling, data-lineage controls, sensor hardening, and separation of trusted instructions from untrusted data. Behavioral-layer controls constrain or monitor AI-governed behavior, including policy enforcement, tool-use guards, action validation, sandboxing, anomaly detection, constrained autonomy, and model-output verification. Objective-layer controls ensure that high-impact decisions remain aligned with mission requirements, including human confirmation, escalation thresholds, separation of duties, fail-safe defaults, independent verification, and operational monitoring.

分层修复可防止狭隘修复被误认为是降低风险。例如，如果代理仍然将不受信任的检索内容视为权威指令，则过滤恶意提示模式可能无法解决更广泛的问题。限制工具权限可能会减少影响，但会暴露影响面。添加人工审核可能会减少客观违规，但无法解释助理为何接受对抗性内容。有效的缓解措施可以解决整个链条，而不仅仅是解决症状。Layered remediation prevents a narrow fix from being mistaken for risk reduction. For example, filtering a malicious prompt pattern may not address the broader problem if the agent still treats untrusted retrieved content as authoritative instruction. Restricting tool permissions may reduce impact but leave the influence surface exposed. Adding human review may reduce objective violation but not explain why the assistant accepted the adversarial content. Effective mitigation addresses the chain, not only the symptom.

8.6 AI红队与渗透测试必须衔接AI Red Teaming and Penetration Testing Must Be Connected

第六个含义是人工智能红队和渗透测试不应保持独立的活动。 AI 红队经常评估有害输出、不安全行为、策略绕过、越狱、提示注入或滥用场景。渗透测试评估已定义威胁模型下的对抗性可利用性、影响和补救措施。支持人工智能的系统需要这些学科的融合。The sixth implication is that AI red teaming and penetration testing should not remain separate activities. AI red teaming often evaluates harmful outputs, unsafe behavior, policy bypass, jailbreaks, prompt injection, or misuse scenarios. Penetration testing evaluates adversarial exploitability, impact, and remediation under a defined threat model. AI-enabled systems require these disciplines to converge.

当红队场景建立可行的对抗性影响路径并将诱导行为与操作目标违规联系起来时，它就成为渗透测试结果。相反，如果仅检查基础设施而忽略行为影响，则人工智能系统的渗透测试是不完整的。组合实践应保持渗透测试的严格性，同时结合人工智能红队的场景多样性和行为重点。A red-team scenario becomes a penetration-test finding when it establishes a feasible adversarial influence path and connects the induced behavior to operational-objective violation. Conversely, a penetration test of an AI-enabled system is incomplete if it examines only infrastructure and ignores behavioral influence. The combined practice should preserve the rigor of penetration testing while incorporating the scenario diversity and behavioral focus of AI red teaming.

这种融合也改变了团队的构成。有效的人工智能渗透测试可能需要应用程序安全、云安全、身份和访问管理、对抗性机器学习、提示和检索设计、模型评估、数据治理、人为因素以及系统部署的操作领域方面的专业知识。只了解基础设施的测试人员可能会错过行为影响路径。只了解模型行为的测试人员可能会错过传统的妥协路径。实际的评估单位是部署的人工智能系统，而不是孤立的模型。This convergence also changes team composition. Effective AI penetration testing may require expertise in application security, cloud security, identity and access management, adversarial ML, prompt and retrieval design, model evaluation, data governance, human factors, and the operational domain in which the system is deployed. A tester who understands only infrastructure may miss behavioral influence paths. A tester who understands only model behavior may miss conventional compromise paths. The practical unit of assessment is the AI-enabled system as deployed, not the model in isolation.

8.7 测试必须集成到开发和运营中Testing Must Be Integrated into Development and Operations

第七个含义是人工智能渗透测试应该集成到开发和运营工作流程中。支持人工智能的系统会随着时间的推移而发生变化。模型更新、提示修改、检索语料改变、工具添加、权限调整、记忆积累、用户行为演变、环境条件转变。时间点测试可以识别重要的故障，但如果测试后行为产生系统发生变化，则无法提供持续的保证。The seventh implication is that AI penetration testing should be integrated into development and operational workflows. AI-enabled systems change over time. Models are updated, prompts are revised, retrieval corpora change, tools are added, permissions are adjusted, memory accumulates, user behavior evolves, and environmental conditions shift. A point-in-time test can identify important failures, but it cannot provide continuing assurance if the behavior-producing system changes after the test.

开发流程应包括针对关键运营目标的对抗性场景测试。部署管道应根据已知的行为故障标准验证提示更改、检索更改、工具权限更改和模型版本更改。运营团队应监控与目标相关的行为漂移、可疑工具的使用、意外的检索依赖性、重复的策略绕过尝试以及失败频率的变化。当人工智能引起的客观违规是通过对抗性影响而出现时，事件响应流程应将其视为安全事件。Development pipelines should include adversarial scenario tests for critical operational objectives. Deployment pipelines should validate prompt changes, retrieval changes, tool-permission changes, and model-version changes against known behavioral failure criteria. Operations teams should monitor for objective-relevant behavioral drift, suspicious tool use, unexpected retrieval dependence, repeated policy bypass attempts, and changes in failure frequency. Incident-response processes should treat AI-induced objective violation as a security event when it arises through adversarial influence.

这种集成将 AI 渗透测试与 MLOps、SecOps 和治理连接起来。仅模型评估是不够的，因为部署上下文决定了行为的操作结果。仅基础设施测试是不够的，因为行为可能会在不损害基础设施的情况下被操纵。持续保证需要监控资源的状态以及这些资源产生的行为。This integration connects AI penetration testing to MLOps, SecOps, and governance. Model evaluation alone is insufficient because deployment context determines the operational consequence of behavior. Infrastructure testing alone is insufficient because behavior may be manipulated without infrastructure compromise. Continuous assurance requires monitoring both the state of resources and the behavior those resources produce.

8.8 问责制需要明确的权力界限Accountability Requires Clear Boundaries of Authority

第八个含义涉及权威。只有当系统有权采取行动、确定优先级、抑制、推荐或影响人类决策时，许多人工智能导致的故障才会变得严重。给出错误答案的聊天机器人单独来看影响可能很小。如果对抗性影响改变了运营结果，嵌入票务工作流程、访问控制系统、临床决策流程、财务审查管道或事件响应工作流程中的相同模型可能会创建渗透路径。The eighth implication concerns authority. Many AI-enabled failures become severe only when the system has authority to act, prioritize, suppress, recommend, or influence human decisions. A chatbot that produces a bad answer may be low impact in isolation. The same model embedded in a ticketing workflow, access-control system, clinical decision process, financial review pipeline, or incident-response workflow may create a penetration path if adversarial influence changes an operational outcome.

因此，测试应该确定每个人工智能组件的权限边界。权限边界定义了人工智能系统可以直接做什么、可以推荐什么、可以压制什么、可以调用什么工具、可以修改什么记录、人类可能接受什么以及哪些行为需要确认。过多的权威会增加行为敏感性的严重程度。清晰的权限边界使目标驱动的测试和修复更加精确。Testing should therefore identify the authority boundary of each AI component. The authority boundary defines what the AI system can do directly, what it can recommend, what it can suppress, what tools it can call, what records it can modify, what humans are likely to accept, and what actions require confirmation. Excessive authority increases the severity of behavioral susceptibility. Clear authority boundaries make objective-driven testing and remediation more precise.

人类监督也应被视为对故障模式的控制。如果人工智能系统塑造人类所看到的内容、排名、总结、省略或推荐，则人机交互设计不会自动防止渗透。当人类收到独立证据、看到出处、理解不确定性并有时间和权力挑战人工智能输出时，人类的确认就会更强。当AI输出成为主要判断依据时，它就更弱了。Human oversight should also be treated as a control with failure modes. A human-in-the-loop design does not automatically prevent penetration if the AI system shapes what the human sees, ranks, summarizes, omits, or recommends. Human confirmation is stronger when the human receives independent evidence, sees provenance, understands uncertainty, and has time and authority to challenge the AI output. It is weaker when the AI output becomes the primary basis for judgment.

8.9 迈向运营保证Toward Operational Assurance

人工智能渗透测试的实际目标是操作保证。问题不仅仅是模型是否稳健、基础设施是否强化或者政策是否存在。问题是对手是否可以导致部署的人工智能系统违背其受信任的目的。这要求安全团队评估从对抗性影响到人工智能控制行为再到操作后果的整个链条。The practical aim of AI penetration testing is operational assurance. The question is not merely whether the model is robust, whether the infrastructure is hardened, or whether a policy exists. The question is whether an adversary can cause the deployed AI-enabled system to violate the purpose for which it is trusted. This requires security teams to evaluate the chain from adversarial influence to AI-governed behavior to operational consequence.

由此产生的实践仍然植根于传统渗透测试的学科：明确的威胁模型、对抗性证据、影响评估、可重复性和补救措施。它的延伸是认识到，在人工智能支持的系统中，决定性的安全失败可能发生在行为层。因此，成熟的评估必须保护资源，测试影响路径，观察诱发行为，并衡量作战目标在对抗条件下是否保持不变。The resulting practice remains grounded in the discipline of conventional penetration testing: explicit threat models, adversarial evidence, impact assessment, reproducibility, and remediation. Its extension is the recognition that, in AI-enabled systems, the decisive security failure may occur at the behavioral layer. A mature assessment must therefore protect resources, test influence paths, observe induced behavior, and measure whether operational objectives remain intact under adversarial conditions.

9 开放研究挑战Open Research Challenges

目标驱动的人工智能渗透测试提出了一些研究挑战，现有的渗透测试方法、对抗性机器学习基准或人工智能风险管理框架无法完全解决这些挑战。这些挑战涉及如何指定操作目标、如何衡量行为渗透率、如何生成测试场景、如何标准化证据以及如何将测试集成到不断变化的人工智能系统中。Objective-driven AI penetration testing raises several research challenges that are not fully addressed by existing penetration-testing methodologies, adversarial machine-learning benchmarks, or AI risk-management frameworks. These challenges concern how operational objectives should be specified, how behavioral penetration should be measured, how test scenarios should be generated, how evidence should be standardized, and how testing should be integrated into continuously changing AI-enabled systems.

9.1 明确运营目标Specifying Operational Objectives

第一个挑战是运营目标的正式规范。传统的渗透测试通常依赖于完善的安全属性，例如机密性、完整性、可用性、授权和隔离。支持人工智能的系统需要更接近所部署系统的任务的额外目标定义。这些目标可能涉及正确的升级、安全的推荐、可靠的优先级、符合政策的工具使用、准确的感知、校准的决策支持或防止有害的人机交互。The first challenge is the formal specification of operational objectives. Conventional penetration testing can often rely on well-established security properties such as confidentiality, integrity, availability, authorization, and isolation. AI-enabled systems require additional objective definitions that are closer to the mission of the deployed system. These objectives may involve correct escalation, safe recommendation, reliable prioritization, policy-compliant tool use, accurate perception, calibrated decision support, or prevention of harmful human-AI interaction.

指定这些目标很困难，因为它们通常是上下文相关的、领域相关的，并且部分是规范性的。在一种情况下安全的建议在另一种情况下可能不安全。一个工作流程中可以容忍的误报率在另一个工作流程中可能是不可接受的。在咨询界面中无害的模型输出在连接到工具或自动化时可能会变得严重。需要对目标规范语言、政策表示、保证案例和特定领域模板进行研究，以允许以可测试的形式表达操作目标。Specifying such objectives is difficult because they are often contextual, domain-dependent, and partly normative. A safe recommendation in one setting may be unsafe in another. A tolerable false positive rate in one workflow may be unacceptable in another. A model output that is harmless in an advisory interface may become severe when connected to tools or automation. Research is needed on objective-specification languages, policy representations, assurance cases, and domain-specific templates that allow operational objectives to be expressed in testable form.

有用的规范不仅必须确定所需的结果，还必须确定围绕该结果的可接受的行为范围。它应该定义哪些行为是被禁止的，哪些决策需要确认，哪些信息不能省略，哪些来源是权威的，哪些不确定性阈值需要升级，以及哪些偏差构成与安全相关的故障。如果没有这样的规范，人工智能渗透测试就有可能将一般模型缺陷与敌对导致的任务失败混淆。A useful specification must identify not only the desired outcome, but also the acceptable behavioral envelope around that outcome. It should define which actions are prohibited, which decisions require confirmation, which information must not be omitted, which sources are authoritative, which uncertainty thresholds require escalation, and which deviations constitute security-relevant failure. Without such specifications, AI penetration testing risks confusing general model imperfection with adversarially induced mission failure.

9.2 测量概率渗透Measuring Probabilistic Penetration

第二个挑战是测量。传统的渗透测试通常寻找可重复的漏洞利用链。人工智能支持的系统可能会产生概率性、上下文相关和状态相关的行为。对抗性提示、有毒的检索文档、受操纵的传感器输入或精心设计的工具输出可能会导致某些试验失败，但不会导致其他试验失败。问题是有多少证据足以证明渗透成功。The second challenge is measurement. Conventional penetration testing often seeks reproducible exploit chains. AI-enabled systems may instead produce probabilistic, context-dependent, and state-dependent behavior. An adversarial prompt, poisoned retrieval document, manipulated sensor input, or crafted tool output may induce failure in some trials but not others. The question is how much evidence is sufficient to claim successful penetration.

需要对行为渗透的统计测量进行研究。这些措施应考虑试验次数、成功率、客观违规的严重程度、模型方差、环境条件和操作后果。针对低影响助手的渗透发现可能需要在多次试验中反复取得成功。即使成功概率较低，针对高权限代理或安全关键系统的调查结果也可能很重要。因此，证据标准应该结合可能性和后果，而不是将渗透视为纯粹的二元性。Research is needed on statistical measures for behavioral penetration. Such measures should account for trial count, success rate, severity of objective violation, model variance, environmental conditions, and operational consequence. A penetration finding against a low-impact assistant may require repeated success across many trials. A finding against a high-authority agent or safety-critical system may be significant even at lower success probability. The evidence standard should therefore combine likelihood and consequence rather than treating penetration as purely binary.

这还需要定义有意义的测试群体的方法。通过任意提示或综合示例衡量的成功率可能无法反映真实的操作风险。场景分布应代表合理的对手行为、实际输入和特定于部署的工作流程。如果不仔细抽样，概率证据可能会夸大风险或错过罕见但严重的客观违规行为。This also requires methods for defining meaningful test populations. A success rate measured over arbitrary prompts or synthetic examples may not reflect real operational exposure. Scenario distributions should represent plausible adversary behavior, realistic inputs, and deployment-specific workflows. Without careful sampling, probabilistic evidence may either exaggerate risk or miss rare but severe objective violations.

9.3 生成现实的对抗场景Generating Realistic Adversarial Scenarios

第三个挑战是对抗性场景的生成。现有的漏洞扫描器和模糊器针对软件缺陷、协议行为、输入解析和已知漏洞模式进行了优化。支持人工智能的系统需要能够执行提示、检索管道、内存、传感器输入、工具使用、规划、反馈循环和人机交互的场景。这些场景必须足够现实，以反映对手的能力，并且足够多样化，以暴露行为的敏感性。The third challenge is adversarial scenario generation. Existing vulnerability scanners and fuzzers are optimized for software defects, protocol behavior, input parsing, and known vulnerability patterns. AI-enabled systems require scenarios that exercise prompts, retrieval pipelines, memory, sensor inputs, tool use, planning, feedback loops, and human-AI interaction. These scenarios must be realistic enough to reflect adversary capability and diverse enough to expose behavioral susceptibility.

对于代理人工智能系统来说，自动场景生成尤其困难。成功的攻击可能需要多个步骤：放置恶意内容、触发检索、影响推理、引发工具调用、绕过确认规则以及塑造最终的面向人的输出。每个步骤可能取决于系统状态、上下文、权限和先前的模型行为。需要对测试工具进行研究，以探索这些多步骤影响路径，同时保留明确的威胁模型假设。Automated scenario generation is especially difficult for agentic AI systems. A successful attack may require multiple steps: placing malicious content, triggering retrieval, influencing reasoning, causing a tool call, bypassing a confirmation rule, and shaping the final human-facing output. Each step may depend on system state, context, permissions, and prior model behavior. Research is needed on test harnesses that can explore these multi-step influence paths while preserving explicit threat-model assumptions.

场景生成还需要领域知识。通用的即时注入测试可能无法揭示 SOC 助理是否违反了事件分类目标，临床助理是否违反了护理限制，或者工业检查系统是否遗漏了安全关键缺陷。因此，未来的工具必须将通用对抗技术与特定领域的目标模型、工作流模拟器和操作数据相结合。Scenario generation also requires domain knowledge. A generic prompt-injection test may not reveal whether a SOC assistant violates incident-triage objectives, whether a clinical assistant violates care constraints, or whether an industrial inspection system misses safety-critical defects. Future tools must therefore combine general adversarial techniques with domain-specific objective models, workflow simulators, and operational data.

9.4 系统级AI渗透率基准测试Benchmarking System-Level AI Penetration

第四个挑战是基准测试。现有的对抗性机器学习基准通常评估孤立模型针对定义的扰动或攻击的鲁棒性。此类基准对于目标驱动的人工智能渗透测试很有用，但还不够。相关的评估单元是已部署的人工智能系统：模型、提示、检索、工具、数据流、用户界面、权限、监控和人工工作流程。The fourth challenge is benchmarking. Existing adversarial ML benchmarks often evaluate isolated model robustness against defined perturbations or attacks. Such benchmarks are useful but insufficient for objective-driven AI penetration testing. The relevant unit of evaluation is the deployed AI-enabled system: model, prompts, retrieval, tools, data flows, user interface, permissions, monitoring, and human workflow.

人工智能渗透测试的基准应包括操作目标、威胁模型、对抗影响面、现实工作流程、可观察行为和目标违反标准。它不仅应该评估模型输出是否发生变化，还应该评估系统的行为是否跨越与任务相关的阈值。对于代理系统，基准测试应包括工具权限、内存、检索状态和多步骤任务执行。对于网络物理系统，它们应包括环境变化、传感器条件以及下游控制或决策后果。A benchmark for AI penetration testing should include operational objectives, threat models, adversarial influence surfaces, realistic workflows, observable behavior, and objective-violation criteria. It should evaluate not only whether a model output changes, but whether the system’s behavior crosses a mission-relevant threshold. For agentic systems, benchmarks should include tool permissions, memory, retrieval state, and multi-step task execution. For cyber-physical systems, they should include environmental variation, sensor conditions, and downstream control or decision consequences.

基准设计还必须避免奖励不切实际的攻击。假设任意提示访问、不受限制的工具权限或直接修改模型状态的基准可能会夸大某些部署的风险。相反，仅测试孤立提示的基准可能会低估系统中的风险，因为对手可以影响检索到的内容、日志、电子邮件、图像或外部网页。因此，基准测试必须明确地编码对手的能力和部署假设。Benchmark design must also avoid rewarding unrealistic attacks. A benchmark that assumes arbitrary prompt access, unconstrained tool permissions, or direct modification of model state may overstate risk for some deployments. Conversely, a benchmark that tests only isolated prompts may understate risk in systems where adversaries can influence retrieved content, logs, emails, images, or external webpages. The benchmark must therefore encode adversary capability and deployment assumptions explicitly.

9.5 标准化证据和报告Standardizing Evidence and Reporting

第五个挑战是证据标准化。传统的渗透测试报告已经建立了记录漏洞、受影响的资产、利用步骤、影响和补救措施的模式。支持人工智能的渗透需要额外的证据字段：操作目标、对抗性影响面、诱发行为、客观违规、测试条件、随机变异性、成功频率、模型配置、检索状态、内存状态、工具权限和人机交互效果。The fifth challenge is standardization of evidence. Conventional penetration-test reports have established patterns for documenting vulnerabilities, affected assets, exploit steps, impact, and remediation. AI-enabled penetration requires additional evidence fields: operational objective, adversarial influence surface, induced behavior, objective violation, test conditions, stochastic variability, success frequency, model configuration, retrieval state, memory state, tool permissions, and human-interaction effects.

如果没有报告标准，人工智能渗透率调查结果将难以比较、重现或优先排序。一份报告可能将单个有害输出视为严重漏洞，而另一份报告可能将重复的行为操纵视为模型质量问题。需要对报告模式、严重性模型和证据阈值进行研究，以区分模型错误、政策失败、行为敏感性和已证实的人工智能渗透率。Without reporting standards, AI penetration findings will be difficult to compare, reproduce, or prioritize. One report may treat a single harmful output as a critical vulnerability, while another may dismiss repeated behavioral manipulation as a model-quality issue. Research is needed on reporting schemas, severity models, and evidence thresholds that distinguish model error, policy failure, behavioral susceptibility, and confirmed AI-enabled penetration.

严重性评分尤其悬而未决。现有的漏洞评分系统并非旨在捕捉从对抗性影响到人工智能介导的客观违规的完整路径。有用的严重性模型应考虑对手的能力、影响面的暴露、感应的可靠性、人工智能组件的权威、行动的可逆性、人类监督、操作后果和补偿控制的可用性。它还应该区分直接未经授权的行为和间接操纵人类决策。Severity scoring is particularly unresolved. Existing vulnerability scoring systems are not designed to capture the full path from adversarial influence to AI-mediated objective violation. A useful severity model should consider adversary capability, exposure of the influence surface, reliability of induction, authority of the AI component, reversibility of the action, human oversight, operational consequence, and availability of compensating controls. It should also distinguish between direct unauthorized action and indirect manipulation of human decision-making.

9.6 将测试与 MLOps 和 SecOps 集成Integrating Testing with MLOps and SecOps

第六个挑战是将人工智能渗透测试持续集成到开发和运营中。支持人工智能的系统经常变化。模型版本更新，提示修改，检索语料库发展，工具添加，权限更改，内存积累，用户调整他们的行为。在模型更新、检索更改或工作流修改后，在某个时间点执行的渗透测试可能会变得过时。The sixth challenge is continuous integration of AI penetration testing into development and operations. AI-enabled systems change frequently. Model versions are updated, prompts are revised, retrieval corpora evolve, tools are added, permissions change, memory accumulates, and users adapt their behavior. A penetration test performed at one point in time may become stale after a model update, retrieval change, or workflow modification.

需要研究将目标驱动的对抗性测试集成到 MLOps 和 SecOps 管道中。在部署之前，应根据已知的行为故障标准测试提示更改、模型更新、检索索引更改、工具权限更改和策略更新。运行时监控应检测与目标相关的行为漂移、可疑工具的使用、异常的检索依赖性、重复的指令冲突事件以及对抗场景的成功率变化。Research is needed on integrating objective-driven adversarial tests into MLOps and SecOps pipelines. Prompt changes, model updates, retrieval-index changes, tool-permission changes, and policy updates should be tested against known behavioral failure criteria before deployment. Runtime monitoring should detect objective-relevant behavioral drift, suspicious tool use, abnormal retrieval dependence, repeated instruction-conflict events, and changes in success rates for adversarial scenarios.

这种整合也引发了运营问题。持续的人工智能渗透测试可能需要合成对抗数据、安全测试环境、红队自动化、影子部署和生产事件的反馈循环。它必须避免干扰实时操作，同时仍反映现实的系统行为。研究挑战是使人工智能渗透测试在系统的整个生命周期中可重复、安全且具有操作意义。This integration also raises operational questions. Continuous AI penetration testing may require synthetic adversarial data, safe test environments, red-team automation, shadow deployments, and feedback loops from production incidents. It must avoid interfering with live operations while still reflecting realistic system behavior. The research challenge is to make AI penetration testing repeatable, safe, and operationally meaningful across the lifecycle of the system.

9.7 人机交互作为攻击面Human-AI Interaction as an Attack Surface

第七个挑战是人类操作员的作用。许多人工智能系统不能自主行动，但它们通过摘要、排名、建议、警报、解释或置信度分数来影响人类的判断。在这些系统中，可能会发生客观违规，因为受敌对影响的人工智能输出改变了人类所看到的、信任的、优先考虑的或忽略的内容。The seventh challenge is the role of human operators. Many AI-enabled systems do not act autonomously, but they shape human judgment through summaries, rankings, recommendations, alerts, explanations, or confidence scores. In these systems, objective violation may occur because adversarially influenced AI output changes what a human sees, trusts, prioritizes, or ignores.

这会产生模型评估或基础设施测试无法完全捕获的安全问题。如果操作员检测到并纠正技术上不正确的输出，则可能是无害的。如果看似合理但具有误导性的输出导致操作员错过关键事件，则可能会很严重。需要研究如何在对抗性影响下测试人类-人工智能决策循环，如何衡量注意力或信任的操纵，以及如何设计当人工智能系统本身控制证据呈现时仍然有效的监督机制。This creates a security problem that is not fully captured by model evaluation or infrastructure testing. A technically incorrect output may be harmless if the human operator detects and corrects it. A plausible but misleading output may be severe if it causes the operator to miss a critical event. Research is needed on how to test human-AI decision loops under adversarial influence, how to measure manipulation of attention or trust, and how to design oversight mechanisms that remain effective when the AI system itself controls evidence presentation.

因此，人机交互设计应被视为安全控制，而不是被认为是充分的。控制的强度取决于出处、独立证据、解释质量、工作量、时间压力、界面设计以及操作员挑战人工智能建议的能力。目标驱动的人工智能渗透测试需要评估这些因素的方法，而不会将人类的判断减少到被动的最终检查点。Human-in-the-loop designs should therefore be evaluated as security controls, not assumed to be sufficient. The strength of the control depends on provenance, independent evidence, explanation quality, workload, time pressure, interface design, and the operator’s ability to challenge the AI recommendation. Objective-driven AI penetration testing requires methods for evaluating these factors without reducing human judgment to a passive final checkpoint.

9.8 迈向行为渗透科学Toward a Science of Behavioral Penetration

更广泛的挑战是为人工智能系统开发行为渗透科学。这样的科学必须将对手模型、人工智能行为、系统架构、操作目标、人类交互和证据标准联系起来。它必须保持传统渗透测试的严格性，同时适应随机行为、上下文影响和任务级后果。The broader challenge is to develop a science of behavioral penetration for AI-enabled systems. Such a science must connect adversary models, AI behavior, system architecture, operational objectives, human interaction, and evidence standards. It must preserve the rigor of conventional penetration testing while accommodating stochastic behavior, contextual influence, and mission-level consequences.

进步需要跨网络安全、机器学习、人机交互、安全工程、系统工程和特定领域运营社区的协作。目标不仅仅是对更多人工智能攻击进行分类。目标是确定对人工智能控制行为的对抗性影响何时构成渗透，如何测试这种渗透，应如何解释证据，以及如何设计系统来承受它。Progress will require collaboration across cybersecurity, machine learning, human-computer interaction, safety engineering, systems engineering, and domain-specific operational communities. The goal is not merely to catalogue more AI attacks. The goal is to determine when adversarial influence over AI-governed behavior constitutes penetration, how such penetration can be tested, how evidence should be interpreted, and how systems can be designed to withstand it.

10 结论Conclusion

支持人工智能的系统改变了渗透的含义，因为它们改变了安全相关行为的产生方式。在传统系统中，对抗的成功通常通过未经授权的访问、权限升级、数据暴露、持久性、破坏或对计算资源的控制来证明。这些形式的妥协对于安全测试仍然至关重要，并且它们仍然与人工智能系统完全相关。然而，它们不再穷尽对手可能造成有意义的安全失败的方式。AI-enabled systems change the meaning of penetration because they change how security-relevant behavior is produced. In conventional systems, adversarial success is often evidenced through unauthorized access, privilege escalation, data exposure, persistence, disruption, or control over computational resources. These forms of compromise remain essential to security testing, and they remain fully relevant to AI-enabled systems. However, they no longer exhaust the ways in which an adversary can produce meaningful security failure.

当学习模型调解决策、建议、分类、工具调用、计划或人类判断时，对抗性影响可能通过行为而不是直接的基础设施损害来发挥作用。提示、检索到的文档、传感器输入、中毒示例、内存条目、工具输出或受操纵的上下文可能会引导系统产生违反其操作目的的结果。在这种情况下，决定性的问题不仅仅是攻击者是否进入了系统。问题在于攻击者是否使系统违背其部署所要维护的目标。When learned models mediate decisions, recommendations, classifications, tool calls, plans, or human judgment, adversarial influence may operate through behavior rather than direct infrastructure compromise. A prompt, retrieved document, sensor input, poisoned example, memory entry, tool output, or manipulated context may steer the system toward an outcome that violates its operational purpose. In such cases, the decisive question is not only whether the attacker got into the system. It is whether the attacker made the system act against the objective it was deployed to preserve.

本文认为，人工智能系统的渗透测试应该从以资源为中心的妥协扩展到目标驱动的行为评估。拟议的定义将人工智能支持的渗透视为人工智能控制行为的可行诱导，该行为违反了明确威胁模型下的一个或多个操作目标。这一定义保留了传统渗透测试的价值，同时为通过人工智能介导的行为运作的对抗路径留出了空间。资源妥协仍然是渗透的一种途径，但不是唯一的途径。This article has argued that penetration testing for AI-enabled systems should therefore be extended from resource-centric compromise to objective-driven behavioral evaluation. The proposed definition treats AI-enabled penetration as the feasible induction of AI-governed behavior that violates one or more operational objectives under an explicit threat model. This definition preserves the value of conventional penetration testing while making room for adversarial pathways that operate through AI-mediated behavior. Resource compromise remains one path to penetration, but it is not the only one.

实际结果是，人工智能渗透测试必须从操作目标开始，绘制支持这些目标的人工智能控制行为，识别对抗性影响面，定义行为失败标准，执行基于场景的测试，并报告将对抗性行为与客观违规行为联系起来的证据。报告必须区分已确认的渗透与一般模型故障、行为敏感性和非安全质量缺陷。他们还必须考虑概率证据、工具权威、检索状态、模型配置、人工监督和下游运营影响。The practical consequence is that AI penetration testing must begin with operational objectives, map the AI-governed behaviors that support them, identify adversarial influence surfaces, define behavioral failure criteria, execute scenario-based tests, and report evidence that links adversarial action to objective violation. Reports must distinguish confirmed penetration from general model failure, behavioral susceptibility, and non-security quality defects. They must also account for probabilistic evidence, tool authority, retrieval state, model configuration, human oversight, and downstream operational impact.

更广泛的教训是，安全评估必须遵循控制点。随着人工智能组件对工作流程、决策和操作产生更大的影响，安全边界从受保护的资源扩展到这些资源所支持的行为。如果对手能够可靠地诱发人工智能控制的行为，从而挫败其使命，那么基础设施保持完好的系统仍然可能被渗透。因此，未来的渗透测试必须同时提出两个问题：攻击者是否可以破坏系统的资源，以及攻击者是否可以使系统违反其操作目标？The broader lesson is that security assessment must follow the locus of control. As AI components acquire greater influence over workflows, decisions, and actions, the security boundary expands from protected resources to the behavior those resources enable. A system whose infrastructure remains intact may still be penetrated if an adversary can reliably induce AI-governed behavior that defeats its mission. Future penetration testing must therefore ask two questions together: can the attacker compromise the system’s resources, and can the attacker make the system violate its operational objectives?
