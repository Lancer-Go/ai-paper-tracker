1 简介Introduction

终端代理利用命令行界面 (CLI) 作为通用操作空间，使大型语言模型 (LLM) 能够跨计算系统执行复杂的长期任务Terminal agents leverage the command-line interface (CLI) as a universal action space, enabling large language models (LLMs) to execute complex, long-horizon tasks across computing systems(Jimenez et al., 2024; Team, 2025; Merrill et al., 2026)。然而，他们的能力仍然从根本上受到缺乏高质量、多样化的培训轨迹的限制。由于手动管理可执行终端任务成本高昂且难以扩展. Yet their capabilities remain fundamentally limited by the scarcity of high-quality, diverse trajectories for training. Since manually curating executable terminal tasks is expensive and difficult to scale(Lin et al., 2018; Merrill et al., 2026)，最近的工作转向大规模终端任务合成作为可扩展轨迹收集的途径。, recent work has turned to large-scale terminal task synthesis as a path toward scalable trajectory collection.

要了解为什么此类轨迹对训练有用，了解终端代理的实际操作方式会有所帮助。在执行过程中，终端代理不会一次性规划整个环境。相反，它通过与一系列中间序列的逐步交互来起作用To understand what makes such trajectories useful for training, it helps to look at how terminal agents actually operate. During execution, a terminal agent does not plan over the entire environment in a single shot. Instead, it acts through step-by-step interaction with a sequence of intermediate场景scenarios，应用一个, applying a技能skill在每个场景中取得进展。因此，执行轨迹由两个维度共同表征：它所经历的场景和它所运用的技能。因此，训练终端代理相当于学习在不同的部分场景中应用适当的技能，这反过来又需要在两个维度上都有不同的轨迹。at each scenario to make progress. An execution trajectory is therefore jointly characterized by two dimensions: the scenarios it traverses and the skills it exercises. Training terminal agents thus amounts to learning to apply appropriate skills across diverse partial scenarios, which in turn requires trajectories that are diverse along both dimensions.

然而，现有的工作主要是通过 LLM 生成的分类法扩大域覆盖范围来扩展终端任务实例，这通常与现实世界的使用有所不同Existing efforts, however, primarily scale terminal task instances, either by broadening domain coverage via LLM-generated taxonomies, which often diverge from real-world usage(Pi et al., 2026; Zhu et al., 2026)，或者从真实的 GitHub 存储库中派生任务实例，并将健康的环境转变为有缺陷的状态, or by deriving task instances from real GitHub repositories and inverting healthy environments into buggy states(Wu et al., 2026; Lin et al., 2026; Chen et al., 2026)，其范围仍然狭窄于软件工程领域，例如问题解决和功能开发, which remain narrowly scoped to software-engineering domains such as issue resolution and feature development(Yang et al., 2025b; Zhang et al., 2025; Wang et al., 2025a)。这些方法对结果轨迹背后的场景或技能构成提供有限的明确控制。. These approaches provide limited explicit control over the scenario or skill composition underlying the resulting trajectories.

3.1 概述Overview

技能合成器SkillSynth通过三个阶段综合不同的终端任务实例。我们首先构建一个以场景为中介的技能图，其中节点是场景，有向边代表从前置条件到后置场景的技能（§synthesizes diverse terminal task instances through three stages.
