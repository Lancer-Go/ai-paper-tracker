1 简介Introduction

大型语言模型 (LLM) 代理在各种任务中表现出了卓越的能力Large Language Model (LLM) agents have demonstrated remarkable capabilities across various tasks(Shi et al., 2024; Kagaya et al., 2024)，导致人们对其应用于更复杂、长期任务的兴趣日益浓厚, leading to a growing interest in their application to more complex, long-horizon tasks(Zheng et al., 2024; Zhou et al., 2025)。 这种长视野属性本质上要求代理适应多个轮次和会话，这一要求大大超出了具有有限上下文窗口的法学硕士的能力. Such long-horizon properties inherently require the agent to adapt to multiple turns and sessions, a demand that significantly exceeds the ability of LLMs with finite context windows(Wang et al., 2024)。为了弥补这一差距，法学硕士代理人越来越多地使用外部记忆库来存储可检索的经验，以进行长期推理和任务执行. To bridge this gap, LLM agents are increasingly augmented with external memory banks to store retrievable experiences for long-horizon reasoning and task execution(Xu et al., 2026; Chhikara et al., 2025).

虽然这些内存模块对于当前的代理工作流程是不可或缺的，但它们也暴露了新的攻击面。具体来说，注入的恶意数据随后可被利用来持续劫持代理的行为，从而导致恶意模式和有害结果。因此，准确理解面向内存的攻击如何运作其成功条件是安全代理系统的重要先决条件。While indispensable to current agentic workflows, these memory modules also expose novel attack surfaces. Specifically, injected malicious data can be subsequently exploited to persistently hijack the agent’s behavior, leading to malicious patterns and harmful outcomes. Consequently, developing a precise understanding of how memory-oriented attacks operate their successful conditions is an important prerequisite for safe agent systems.

2.1 记忆增强 LLM 代理Memory-Augmented LLM Agents

记忆增强大语言模型（LLM）代理可以大致分为两个范例Memory-augmented large language model (LLM) agents can be broadly categorized into two paradigms(Hu et al., 2025)：检索增强生成（RAG）: Retrieval-Augmented Generation (RAG)(Gao et al., 2023)和长期记忆 (LTM) 系统and Long-Term Memory (LTM) systems(Xu et al., 2026; Chhikara et al., 2025)。其中，RAG 已成为实际代理部署的主流内存机制. Among these, RAG has emerged as the prevailing memory mechanism for practical agent deployment(Liu et al., 2026)。代表性系统维护任务相关上下文的外部存储，包括过去的执行轨迹、反思反馈、自传流或可重用的程序技能. Representative systems maintain an external store of task-relevant context, encompassing past execution trajectories, reflective feedback, autobiographical streams, or reusable procedural skills(Shinn et al., 2023; Park et al., 2023; Packer et al., 2023; Wang et al., 2023)。特定领域的代理随后可以检索这些存储的经验作为上下文演示，以指导和完善未来的行为. Domain-specific agents can subsequently retrieve these stored experiences as in-context demonstrations to guide and refine future behavior(Shi et al., 2024; Kagaya et al., 2024).

与将内存视为静态外部存储的 RAG 机制不同，LTM 系统旨在通过环境反馈不断更新和发展持久性知识Unlike RAG mechanisms that treat memory as a static external store, LTM systems aim to continuously update and evolve persistent knowledge through environmental feedback(Xu et al., 2026; Chhikara et al., 2025)。然而，与成熟的RAG范式相比，LTM系统的研究仍处于起步阶段，缺乏对统一架构或标准化设计原则的共识. Nevertheless, in contrast to the well-established RAG paradigm, research on LTM systems remains in its nascent stages, lacking a consensus on unified architectures or standardized design principles(Hu et al., 2025)。因此，这项工作主要关注基于 RAG 的内存，而不是新兴的 LTM 系统。. Therefore, this work primarily focuses on RAG-based memory rather than emerging LTM systems.

2.2 LLM 代理中的直接内存中毒攻击Direct Memory Poisoning Attacks in LLM Agents

直接内存中毒攻击的主要区别在于对手假定的写入访问。其中一项工作采用白盒设置，允许对手通过恶意演示或捏造任务记录来直接破坏内存库Direct memory poisoning attacks differ primarily in the adversary’s presumed write access. One line of work assumes a white-box setting, allowing adversaries to directly corrupt the memory bank with malicious demonstrations or fabricated task records(Chen et al., 2024; Srivastava and He, 2025)。虽然在受控设置中有效，但对底层检索存储的直接写入访问的假设很少适用于外部用户缺乏数据库级权限的实际部署代理系统。 为了与现实世界的安全限制保持一致，后续工作通过过渡到更现实的仅查询设置来推进该领域，要求代理自行生成中毒记录以响应看似良性的提示. While effective in controlled setups, the assumption of direct write access to the underlying retrieval store is rarely applicable to practical, deployed agent systems, where external users lack database-level privileges. To align with real-world security constraints, a subsequent line of work advanced the field by transitioning to a more realistic query-only setting, requiring the agent to generate poisoned records itself in response to benign-looking prompts(Dong et al., 2026; Piehl et al., 2026)。尽管与我们的模型一致，但之前的工作使用显式有效负载针对小型、未经审计的记忆，因此尚不清楚它们是否可以逃避审计并赢得顶级奖项。. 局限性Limitations

我们的研究有两个范围限制。首先，我们关注基于 RAG 的 LLM 代理，其中通过相似性检索记忆并重新用作演示，但不评估更广泛的长期记忆架构，例如基于图的记忆或分层记忆。延伸Our study has two scope limitations. First, we focus on RAG-based LLM agents, where memories are retrieved by similarity and reused as demonstrations, but do not evaluate broader long-term memory architectures such as graph-based memory or hierarchical memory. Extending黑手党MAFIA这些架构需要特定于架构的威胁模型和攻击制定，我们将其留给未来的工作。to these architectures would require an architecture-specific threat model and attack formulation, which we leave to future work.

其次，我们的防御评估涵盖写入时输入审核和检索后内存一致性检查。我们的检索器分析还检查了实体感知检索。但是，我们不会评估更广泛的系统级防御，例如基于来源的执行、访问控制和信息流控制。评估它们需要修改代理的内存架构、权限模型和执行管道，以及具有特定于部署的授权和来源假设的威胁模型。我们将他们的系统评估留给未来的工作。Second, our defense evaluation covers write-time input auditing and post-retrieval memory consistency checking. Our retriever analysis also examines entity-aware retrieval. However, we do not evaluate broader system-level defenses such as provenance-based enforcement, access control, and information-flow control. Evaluating them requires modifications to the agents’ memory architecture, permission model, and execution pipeline, as well as a threat model with deployment-specific authorization and provenance assumptions. We leave their systematic evaluation to future work.

道德考虑Ethical Considerations

为什么要发表一项令人反感的研究。Why publish an offensive study.

我们研究内存中毒，以揭示当前内存代理防御方式的具体差距：当今的操作员经常依赖即时级别的审核，并将检索时间检测视为足够。通过使攻击面变得明确，我们的结果激发了更强大的系统级防御（例如来源、写入隔离和检索后验证），而不是强化错误的安全感。We study memory poisoning to expose a concrete gap in how current memory agents are defended: operators today often rely on prompt-level audits and treat retrieval-time detection as sufficient. By making the attack surface explicit, our results motivate stronger system-level defenses (e.g., provenance, write isolation, and post-retrieval verification) rather than reinforcing a false sense of security.

实验范围、数据和工件使用。Experimental scope, data, and artifact use.

所有实验均在公开可用数据的基准环境中进行 - MIMIC-III 和 eICU，根据 EHRAgent 的标准凭证访问（两者均由 HIPAA 安全港下的数据提供商在源头进行去识别；我们没有进行额外的数据收集，也没有引入新的个人识别信息）、RAP 的 WebShop 以及基于 DS-1000、MBPP 和 HumanEval 构建的数据解释器体验池（标准公共代码基准，不包含个人或攻击性内容）知识）——而不是针对任何已部署的服务。我们仅使用公开可用的工件（数据集、模型和代码资源），通过其官方渠道分发并根据其适用的许可、凭证和访问条件使用。据我们所知，我们对这些工件的使用符合标准研究目的的预期用途和访问条件，并且不涉及研究范围之外的用途。All experiments are conducted in benchmark environments on publicly available data—MIMIC-III and eICU under their standard credentialed access for EHRAgent (both are de-identified at source by the data providers under HIPAA Safe Harbor; we performed no additional data collection and introduced no new personally identifying information), WebShop for RAP, and the Data Interpreter ExperiencePool built from DS-1000, MBPP, and HumanEval (standard public code benchmarks without personal or offensive content to our knowledge)—rather than against any deployed service. We used only publicly available artifacts (datasets, models, and code resources), distributed through their official channels and used in accordance with their applicable licensing, credentialing, and access conditions. To the best of our knowledge, our use of these artifacts is consistent with their intended use and access conditions for standard research purposes, and does not involve uses outside the scope of research.

发布和滥用注意事项。Release and misuse considerations.

我们意识到攻击性记忆中毒研究的双重用途性质。为了限制滥用，我们围绕防御方向的讨论构建我们的结果，并明确指出更广泛的防御框架（例如，基于来源的执行和信息流控制）作为未来的工作，并且我们不针对或释放任何面向生产的资产；我们的有效负载是基准任务中的合成项目，而不是可用于真实用户或患者的指令。该攻击还需要仅查询访问以及代理的普通写回路径，这与之前的仅查询中毒工作所假设的威胁面相同，而不是零成本功能。We are aware of the dual-use nature of an offensive memory-poisoning study. To limit misuse, we frame our results around a discussion of defense directions and explicitly point to broader defense frameworks (e.g., provenance-based enforcement and information-flow control) as future work, and we do not target or release any production-facing assets; our payloads are synthetic items in benchmark tasks rather than instructions usable against real users or patients. The attack also requires query-only access together with the ordinary write-back path of the agent, which is the same threat surface assumed by prior query-only poisoning work and not a zero-cost capability.

更安全的内存系统的建议。Recommendations for safer memory systems.

我们的研究结果表明，记录级即时审核不应被视为对长期代理记忆的充分防御。内存操作员应将此类审核与系统级机制结合起来——写入隔离和最小权限写入策略、来源跟踪、针对原始交互的语义一致性检查以及允许存储的演示影响对外部状态的操作之前的检索后验证。Our findings suggest that record-level prompt audits should not be treated as a sufficient defense for long-lived agent memory. Memory operators should combine such audits with system-level mechanisms—write isolation and least-privilege write policies, provenance tracking, semantic consistency checks against the originating interaction, and post-retrieval verification before stored demonstrations are allowed to influence actions over external state.
