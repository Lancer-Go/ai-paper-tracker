1. 简介Introduction

It lives in unstructured sources such as books, enterprise and legal documents, web pages, SEC filings, earnings calls, and PDFs. The evidence required to answer questions over these sources is scattered across many documents. Consider this question: which cast members worked with both Alfred Hitchcock and Martin Scorsese? Over Wikipedia, answering it requires enumerating each director’s films from their pages, extracting cast members from each film’s page, connecting the resulting director-film and film-cast relations, and intersecting the two cast sets. This flow is general: at each step, evidence is gathered from documents, assembled into intermediate entities, attributes, and relations, and passed to later steps. The answer is not a set of retrieved passages. It is a latent structured dataset, constructed step by step from sparse evidence inside many large documents. We call this pattern数据推理data reasoning.

Many of the questions real users ask follow exactly the data reasoning pattern(Wolfson et al., 2026)。 个人问题在数量上占主导地位，数百万人通过开放网络提出这些问题。专业问题的风险更高，目标是企业档案和公共政府记录. Professional questions carry higher stakes and target enterprise archives and public government records(Opsahl-Ong et al., 2026)。 一位金融分析师可能会问，哪些公司在财报电话会议上将供应链归咎于供应链，但却在年度报告中报告库存上升，将长达一小时的文字记录中的一句话与一份冗长的文件中的一行内容相匹配。卫生部门可能会询问哪些供应商出现在多个城市的食品召回通知和餐厅检查报告中，供应商名称分散在冗长的检查叙述中。回答任一问题都意味着分多个步骤分散数百个文档。. Answering either means fanning out over hundreds of documents in multiple steps.

Once structure covers a question, the agent skips every document open, so the saving reaches orders of magnitude for real questions that fan out over hundreds of documents. While LLMs are excellent at capturing such structure, structuring everything in advance is infeasible. Documents contain orders of magnitude more entities, attributes, and relations than any workload will use, and extracting them all is an unbounded decode. 两种见解将这个死胡同变成了机遇。首先，在工作负载级别，相关查询重新打开相同的文档并重复大部分相同的工作，而每个查询都会揭示哪些结构和关系很重要。 这种语义局部性是常态，而不是例外。从用户的角度来看，对话变成了调查，并且用户拥有相似的兴趣。从数据的角度来看，相同的文档会被一遍又一遍地打开，因为它们包含查询所需的许多相关事实和证据。 其次，在推理级别，一旦代理加载文档，其预填充就已经被计算并且其 KV 缓存条目已经存在。精心的提示结构，共享前缀服务Two insights turn this dead end into an opportunity. First, at the workload level, related queries reopen the same documents and repeat much of the same work, while each query reveals which structure and relations matter. This semantic locality is the norm, not the exception. From the user’s side, conversations become investigations and users hold similar interests. From the data’s side, the same documents get opened over and over because they hold many related facts and evidence that queries need. Second, at the inference level, once the agent loads a document, its prefill has already been computed and its KV-cache entries already exist. With careful prompt structure, shared-prefix serving(Kwon et al., 2023; Zheng et al., 2024)和 API 提示缓存，同一上下文上的第二代避免或大幅减少了重复的预填充成本，使解码令牌成为主要的额外工作。我们给这个解码一个固定的预算，这个预算相对于它节省的预填充来说很小，但足以产生可重用的结构。这两个见解共同表明了一种比缓存更强大的举措。仅当返回确切的问题时，缓存的答案才有帮助。推测有用的结构更进一步：在加载文档并付费时，提取相关但不同的未来查询所需的有根据的证据。, and API prompt caching, a second generation over the same context avoids or sharply reduces repeated prefill cost, leaving decoded tokens as the main additional work. We give this decode a fixed budget that is small relative to the prefill it saves, yet sufficient to produce reusable structure. Together, the two insights suggest a move stronger than caching. Cached answers help only when the exact question returns. Speculating about useful structures goes much further: While the document is loaded and paid for, extract grounded evidence that related but distinct future queries will need.

用于令牌/成本高效的数据推理的代理数据破解。Agentic Data Cracking for Token/Cost-Efficient Data Reasoning.我们介绍We introduce代理数据破解agentic data cracking，一种将数据库破解和自适应数据系统的查询驱动哲学引入人工智能推理的方法, an approach that brings the query-driven philosophy of database cracking and adaptive data systems to AI reasoning(Salles et al., 2007; Idreos et al., 2007)。该系统绝不会仅仅为了提取结构而打开文档。相反，每当推理代理打开一个答案时，破解子代理就会以低边际成本从已加载的上下文中分叉。它推测可能服务于未来查询的有根据的、有证据支持的实体、属性和关系。系统对这些破解的对象进行验证和编目。稍后的查询通过结构化读取重用它们，避免文档完全打开，并在错过时回退到原始文档。与重新组织关系的数据库破解不同，代理数据破解在不存在的情况下创建有用的结构。 这种结构是自适应的，因为观察到的查询指导值得提取的内容，而代理是因为推理子代理（而不是固定的提取器或模式）使用语义理解来读取每个文档并推测要提取的内容。. The system never opens documents solely to extract structure. Instead, whenever the reasoning agent opens one to answer, a cracking sub-agent forks from the already-loaded context at low marginal cost. It speculates about grounded, evidence-backed entities, attributes, and relations likely to serve future queries. The system validates and catalogs these cracked objects. Later queries reuse them via structured reads, avoiding document opens entirely, and fall back to original documents on a miss. Unlike database cracking, which reorganizes relations, agentic data cracking creates useful structure where none exists. This structuring is adaptive because observed queries guide what is worth extracting, and agentic because a reasoning sub-agent, not a fixed extractor or schema, uses semantic understanding to read each document and speculate about what to extract.

潜在数据推理任务。Latent Data Reasoning Tasks.语言建模的一个重大进步是能够将复杂的任务分解为更小的推理步骤序列。 推理任务采取不同的形式：解决 IOI/ICPC 问题、构建数据科学管道以及解决大型非结构化语料库（例如网络、维基百科）的知识密集型问题A major advance in language modeling has been the ability to decompose complex tasks into sequences of smaller reasoning steps. Reasoning tasks take distinct forms: solving IOI/ICPC problems, constructing data science pipelines, and resolving knowledge-intensive questions over large unstructured corpora (e.g., the web, Wikipedia(Zhu et al., 2024)、企业文档集, and enterprise document collections(Opsahl-Ong et al., 2026)）。 在本文中，我们重点关注推理任务，这些任务需要代理从非结构化文档中提取知识，在每个步骤中构建中间数据和支持证据，并将这些工件传递到后续步骤。在这些任务中，答案来自对构造的中间数据的推理，而不是检索单个事实。我们称这个类为). In this paper, we focus on reasoning tasks that require an agent to extract knowledge from unstructured documents, construct intermediate data and supporting evidence at each step, and pass those artifacts to later steps. In these tasks, the answer comes from reasoning over the constructed intermediate data rather than retrieving a single fact. We call this class潜在结构化数据推理latent structured data reasoning, 或, or数据推理data reasoning为简洁起见。for brevity.

6. 讨论Discussion

设计决策、限制和未来的工作。Design Decisions, Limitations, and Future Work.我们公开受限的读取函数而不是完整的 SQL 空间。这使得工具界面较小、回退明确且生成的查询可靠。但是，SQL 支持计数、聚合、连接和直接多跳查询。安全地公开这些功能仍然是未来有趣的工作。我们当前的系统假设一个静态语料库。可以通过删除受影响的破解对象或从更改中逐步完善它们来处理编辑。We expose constrained read functions rather than the full SQL space. This keeps the tool interface small, fallbacks explicit, and generated queries reliable. However, SQL supports counting, aggregation, joins, and direct multi-hop queries. Safely exposing these capabilities remains interesting future work. Our current system assumes a static corpus. Edits could be handled by dropping the affected cracked objects or incrementally refining them from the changes.

我们的基准测试使用开放的、经过普遍训练的维基百科内容。特定于模型和组织的私人办公文档是看不到的。它们还会跨用户和工作流程重复查询，这使得它们成为跨查询重用的更有趣的工作负载。为了反映现实世界的工作负载，我们需要能够捕获文档查询的长期历史记录的基准，最好是从已部署的系统中提取。此类基准测试将为改进单个查询和长期运行的现实系统提供巨大且实用的机会。Our benchmarks use open, commonly trained-on Wikipedia content. Private office documents are unseen by the model and organization-specific. They are also repeatedly queried across users and workflows, making them an even more interesting workload for cross-query reuse. To reflect real-world workloads, we need benchmarks that capture the long history of queries over a document, ideally drawn from deployed systems. Such benchmarks would expose a large and practical opportunity to improve both individual queries and long-running real-world systems.

7. 结论Conclusion

代理数据推理可以回答非结构化语料库上的复杂问题，但反复阅读文档会导致成本高昂。我们引入了代理数据破解。它使用观察到的查询来推测有用的结构，并从推理过程中已打开的文档中提取它。未来的查询可以重用这个结构。该设计两次利用局部性：相关查询重用提取的结构，而破解本身则重用文档的 KV 缓存。我们表明，代理数据破解可以减少令牌使用和 API 成本，同时保持答案质量。与理想的完全结构化存储之间的剩余差距表明数据系统有广阔的机会来改进代理推理，特别是在跨查询出现有用结构的工作负载中。该方向将语义网、实体解析和自适应数据系统数十年的工作与现代代理的推理能力联系起来。结合这些基础可以使代理推理更具可扩展性和可靠性。代理数据破解是实现这种用于人工智能推理的自适应数据系统的第一步。除了我们的系统之外，这个想法还适用于系统对大型非结构化文档进行重复推理的任何地方。Agentic data reasoning can answer complex questions over unstructured corpora, but repeatedly reading documents makes it expensive. We introduced agentic data cracking. It uses observed queries to speculate about useful structure and extract it from documents already opened during reasoning. Future queries can then reuse this structure. The design exploits locality twice: related queries reuse extracted structure, and cracking itself reuses the document’s KV cache. We showed that agentic data cracking reduces token usage and API cost while preserving answer quality. The remaining gap to an ideal fully structured store suggests a broad opportunity for data systems to improve agentic reasoning, especially in workloads where useful structure emerges across queries. This direction connects decades of work on the Semantic Web, entity resolution, and adaptive data systems with the reasoning ability of modern agents. Combining these foundations can make agentic reasoning more scalable and reliable. Agentic data cracking is an initial step toward such adaptive data systems for AI reasoning. Beyond our system, the idea applies wherever systems repeatedly reason over large unstructured documents.
