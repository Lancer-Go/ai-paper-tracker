1 简介Introduction

深度学习研究工作流程从根本上来说是迭代的：研究人员设计实验，启动 GPU 训练（通常持续数小时到数天），分析结果，调整超参数或模型架构，然后重复。在一篇论文提交之前，这个循环可能会重复数百次。尽管这个循环的大部分内容都是机械性质的，但它仍然绝大多数是手动的——研究人员必须在场检查训练完成情况、解释结果并决定下一步。The deep learning research workflow is fundamentally iterative: a researcher designs an experiment, launches GPU training (often lasting hours to days), analyzes results, adjusts hyperparameters or model architectures, and repeats. Before a single paper submission, this cycle may be repeated hundreds of times. Despite the mechanical nature of much of this loop, it remains overwhelmingly manual — researchers must be present to check training completion, interpret results, and decide on next steps.

3.2 零成本监控Zero-Cost Monitoring

我们设计的核心见解是，在 GPU 训练期间（占典型实验周期中 90-99% 的挂钟时间），法学硕士没有任何有用的贡献。训练过程遵循预定的时间表，中间结果（损失曲线、验证指标）由训练脚本自动写入日志文件。The central insight of our design is that during GPU training — which constitutes 90–99% of wall-clock time in a typical experiment cycle — the LLM has nothing useful to contribute. The training process follows a predetermined schedule, and intermediate results (loss curves, validation metrics) are written to log files automatically by the training script.

我们通过实施一个监控阶段来利用这一观察结果We exploit this observation by implementing a monitoring phase that makes零zeroLLM API 调用。相反，会按照可配置的时间间隔（默认值：15 分钟）执行三个轻量级操作系统级别检查：LLM API calls. Instead, three lightweight OS-level checks are performed at configurable intervals (default: 15 minutes):

    进程活跃度Process liveness: 杀死-0 $PIDkill -0 $PID检查训练过程是否仍在运行。这是一个成本可以忽略不计的单个系统调用。checks whether the training process is still running. This is a single syscall with negligible cost.

3.3 两层恒定大小存储器Two-Tier Constant-Size Memory

长期运行的 LLM 代理面临一个基本问题：累积的上下文无限增长，导致 (a) 随着上下文长度的增加，LLM 性能下降；(b) API 成本与上下文大小成正比；(c) 最终上下文窗口溢出。Long-running LLM agents face a fundamental problem: accumulated context grows without bound, leading to (a) degraded LLM performance as context length increases, (b) escalating API costs proportional to context size, and (c) eventual context window overflow.

我们用一个两层内存系统来解决这个问题We address this with a two-tier memory system bounded at∼\sim5,000 个字符（5,000 characters (∼\sim1,500 个令牌），无论运行时间长短如何都保持不变：1,500 tokens), maintained constant regardless of runtime duration:

第 1 级：项目简介（Tier 1: Project Brief (BB).

人类编写的冻结文档，描述研究目标、代码库结构、约束条件和成功标准。最大大小：3,000 个字符。代理无法修改该层级，确保研究方向保持稳定。A human-authored, frozen document describing the research goal, codebase structure, constraints, and success criteria. Maximum size: 3,000 characters. The agent cannot modify this tier, ensuring the research direction remains stable.

第 2 层：内存日志 (Tier 2: Memory Log (MM).

代理维护的滚动日志包含两个部分：An agent-maintained rolling log with two sections:

  • •

    主要结果Key Results：记录重要实验结果的里程碑条目（例如，“Exp003：ViT-B/16，lr=3e-4 + cosine，acc=77.9% - 新最佳！”）。自动压缩：当该部分超过 1,200 个字符时，最旧的条目将被删除。: Milestone entries recording significant experimental outcomes (e.g., “Exp003: ViT-B/16, lr=3e-4 + cosine, acc=77.9% — new best!”). Auto-compacted: when the section exceeds 1,200 characters, the oldest entry is removed.

  • •

    最近的决定Recent Decisions：代理对每个决定的推理日志。自动压缩：仅保留最近的 15 个条目，无论总字符数是多少。: A log of the agent’s reasoning for each decision. Auto-compacted: only the most recent 15 entries are retained, regardless of total character count.

压缩在设计上是有损的——代理保留最有价值的信息（最近的决策和最佳结果），同时丢弃常规条目。这反映了人类研究人员如何维持心理模型：记住关键里程碑和最近的背景，同时忘记日常细节。The compaction is lossy by design — the agent retains the most valuable information (recent decisions and best results) while discarding routine entries. This mirrors how human researchers maintain a mental model: remembering key milestones and recent context while forgetting routine details.

3.5 安全机制Safety Mechanisms

强制试运行。Mandatory Dry-Run.

在任何真正的训练启动之前，代码代理必须执行短暂的空运行（通常是 2 个前后步骤），以验证代码运行时没有错误。这会在投入 GPU 时间之前捕获配置错误、缺失导入和张量形状不匹配。Before any real training launch, the Code Agent must execute a short dry-run (typically 2 forward-backward steps) to verify that the code runs without errors. This catches configuration mistakes, missing imports, and tensor shape mismatches before committing GPU hours.

受保护的文件。Protected Files.

关键状态文件（Critical state files (状态.jsonstate.json, MEMORY_LOG.md, 项目简介.mdPROJECT_BRIEF.md）不能被工作代理覆盖，从而防止代理内存或配置的意外损坏。) cannot be overwritten by worker agents, preventing accidental corruption of the agent’s memory or configuration.

人为覆盖。Human Override.

提供了三种干预机制：（1）aThree intervention mechanisms are provided: (1) aHUMAN_DIRECTIVE.md在每个周期开始时消耗的具有最高优先级的文件，(2) 命令行file consumed at the start of each cycle with highest priority, (2) a command-line--指令--directive一次性指令的标志，以及（3）直接修改flag for one-time instructions, and (3) direct modification ofMEMORY_LOG.md永久的行为改变。for permanent behavioral changes.

防烧伤保护。Anti-Burn Protection.

如果连续的循环没有产生有意义的输出（例如，重复错误或空结果），则冷却间隔会呈指数增加（最多 30 分钟），以防止浪费令牌消耗。If consecutive cycles produce no meaningful output (e.g., repeated errors or empty results), the cooldown interval is exponentially increased (up to 30 minutes) to prevent wasteful token consumption.

4 实验Experiments

我们通过跨多个研究项目的长期部署来评估 Deep Researcher Agent。由于自主研究代理的性质，我们的评估侧重于运营指标和成本效率，而不是固定任务的基准分数。We evaluate Deep Researcher Agent through long-term deployment across multiple research projects. Due to the nature of autonomous research agents, our evaluation focuses on operational metrics and cost efficiency rather than benchmark scores on fixed tasks.

4.1 部署设置Deployment Setup

该框架部署在 4 个配备 NVIDIA L20X 144GB GPU 的 GPU 服务器上的 4 个并发深度学习研究项目中。每个项目在持久 tmux 会话中运行一个独立的代理实例。 LLM骨干是Claude SonnetThe framework was deployed across 4 concurrent deep learning research projects on 4 GPU servers equipped with NVIDIA L20X 144GB GPUs. Each project ran an independent agent instance in a persistent tmux session. The LLM backbone was Claude Sonnet[2]启用 Anthropic 的提示缓存。项目跨越不同领域，包括生成建模、多模态学习和自监督表示学习。with Anthropic’s prompt caching enabled. Projects spanned diverse domains including generative modeling, multi-modal learning, and self-supervised representation learning.

Day-to-day decisions such as hyperparameter exploration, learning rate scheduling, and regularization strategies were fully autonomous.

5 局限性和未来的工作Limitations and Future Work

单 GPU 范围。Single-GPU Scope.

当前的开源版本支持单 GPU 实验。计划在未来版本中提供多 GPU 分布式训练 (DDP) 和多服务器编排。The current open-source release supports single-GPU experiments. Multi-GPU distributed training (DDP) and multi-server orchestration are planned for future releases.

公制提取。Metric Extraction.

用于指标提取的日志解析依赖于正则表达式模式匹配，这可能会丢失自定义指标格式。结构化日志记录格式（例如 JSON Lines）将提高稳健性。Log parsing for metric extraction relies on regex pattern matching, which may miss custom metric formats. Structured logging formats (e.g., JSON Lines) would improve robustness.

探索策略。Exploration Strategy.

Agent 的实验规划依赖于 LLM 的推理能力，没有贝叶斯优化等正式的探索策略。集成结构化搜索方法可以提高超参数优化的样本效率。The agent’s experiment planning relies on the LLM’s reasoning capabilities without formal exploration strategies such as Bayesian optimization. Integrating structured search methods could improve sample efficiency for hyperparameter optimization.

评估方法。Evaluation Methodology.

评估自主研究代理仍然是一个开放的挑战。与可以在固定基准上进行测试的软件工程代理不同Evaluating autonomous research agents remains an open challenge. Unlike software engineering agents that can be tested on fixed benchmarks[9]，研究代理在开放式领域中运作，其中“正确的”下一个实验是不确定的。为长期运行的研究代理制定标准化评估协议是未来工作的一个重要方向。, research agents operate in open-ended domains where the “correct” next experiment is undefined. Developing standardized evaluation protocols for long-running research agents is an important direction for future work.

我们推出了 Deep Researcher Agent，这是一个用于 24/7 深度学习实验的自主框架。我们的三项关键创新——零成本监控、两层恒定大小内存和最小工具集领导者-工作者架构——共同使持续的法学硕士驱动的研究在经济上可行，平均每 24 小时周期成本为 0.08 美元。该系统在 4 个并发研究项目中持续部署超过 30 天，自主完成了 500 多个实验周期，并通过 200 多个全自动实验，在一个项目中实现了比基线 52% 的指标改进。我们将完整的框架作为开源软件发布在We presented Deep Researcher Agent, an autonomous framework for 24/7 deep learning experimentation. Our three key innovations — Zero-Cost Monitoring, Two-Tier Constant-Size Memory, and Minimal-Toolset Leader-Worker Architecture — collectively make continuous LLM-driven research economically viable at an average cost of $0.08 per 24-hour cycle. Over 30+ days of sustained deployment across 4 concurrent research projects, the system autonomously completed 500+ experiment cycles and achieved a 52% metric improvement over baseline in one project through 200+ fully automated experiments.
