3.3 可扩展性和可扩展性Extensibility and Scalability

InfoSeeker 被设计为可扩展的，只需对系统进行最小的更改即可插入新的管理器和工作代理。这种可扩展性直接源于近乎可分解的架构，其中管理器是具有隔离的任务执行上下文的封装单元。具体来说，主机仅通过阶跃响应对与管理器进行通信InfoSeeker is designed to be extensible, enabling new manager and worker agents to be plugged in with minimal changes to the system. This extensibility arises directly from the near-decomposable architecture where managers are encapsulated units with isolated task execution contexts. Specifically, the host communicates with managers exclusively via step–response pairs(qt,yt)(q_{t},y_{t})并且从不访问管理器内部状态、子任务或工具跟踪。因此，引入新的管理器不需要修改主机级推理或控制逻辑，只要管理器遵循相同的输入输出协议即可。现有的管理器继续保持不变，主机在执行过程中可以在异构管理器中自由选择。and never accesses manager-internal states, subtasks, or tool traces. As a result, introducing a new manager does not require modifying host-level reasoning or control logic, as long as the manager conforms to the same input–output protocol. Existing managers continue to operate unchanged, and the host can freely select among heterogeneous managers during execution.

同样，每个管理器维护自己的工作池和执行上下文，允许在本地添加新的工作器类型或工具集成，而不会影响其他管理器或主机。这种隔离确保扩展保持模块化，并且不会增加全局上下文耦合或协调复杂性。重要的是，每个管理器都被设计为专注于单个任务域（例如，网络搜索、代码执行、文件系统交互）。这种单一职责设计提高了稳健性和可解释性，因为管理人员可以不受干扰地采用特定领域的分解策略、验证启发式和聚合逻辑。它还有助于有针对性的改进和调试，因为对一个管理器的增强不会将意外的影响传播给其他管理器。Similarly, each manager maintains its own worker pool and execution context, allowing new worker types or tool integrations to be added locally without affecting other managers or the host. This isolation ensures that extensions remain modular and do not increase global context coupling or coordination complexity. Importantly, each manager is designed to specialise in a single task domain (e.g., web search, code execution, file system interaction). This single-responsibility design improves robustness and interpretability, as managers can employ domain-specific decomposition strategies, validation heuristics, and aggregation logic without interference. It also facilitates targeted improvement and debugging, since enhancements to one manager do not propagate unintended effects to others.

6 结论Conclusion

虽然代理搜索最近的进步是由对深度推理的强调推动的，但现实世界的信息检索日益表现为广泛综合的挑战。在这些设置中，系统的最终质量取决于其跨大量异构源协调发现、验证和总结的能力。我们的工作表明，仅仅扩展上下文窗口或模型规模无法解决广域综合固有的结构病理学问题。为了弥补这一差距，我们引入了 InfoSeeker，这是一个可操作近可分解性原则的框架。通过分层解耦功能执行，我们的设计实现了推理深度和执行宽度的独立扩展。我们的实证结果证实了有效性和效率的同时提高。While recent strides in agentic search have been driven by an emphasis on deep reasoning, real-world information retrieval increasingly manifests as a challenge of wide synthesis. In these settings, the ultimate quality of the system is determined by its ability to orchestrate discovery, verification, and summarisation across a vast array of heterogeneous sources. Our work demonstrates that merely expanding context windows or model scale fails to address the structural pathologies inherent to wide-domain synthesis. To bridge this gap, we introduce InfoSeeker, a framework that operationalises the principle of near-decomposability. By hierarchically decoupling functional execution, our design enables the independent scaling of reasoning depth and execution width. Our empirical results confirm simultaneous gains in both effectiveness and efficiency.

局限性和未来的工作Limitations and Future Work

我们的系统依赖于通过 API 访问骨干语言模型和外部工具，因此其性能受到 API 可用性、速率限制、并发宽度和相关成本的限制。此外，当前的设计依赖于手动调整的提示和强大的骨干法学硕士，这可能会影响不同骨干模型的通用性。Our system relies on access to backbone language models and external tools through APIs, and its performance is therefore constrained by API availability, rate limits, concurrency width and associated costs. In addition, the current design depends on hand-tuned prompts and strong backbone LLMs, which may affect generality across different backbone models.

未来的工作包括自动学习任务分解和协调策略，例如通过多智能体强化学习，而不是主要依赖于主干模型的本机功能和上下文学习。我们还计划探索训练较小或专门的模型，以降低推理成本和延迟，从而实现更高效和可扩展的部署。Future work includes learning task decompositions and coordination policies automatically, for example via multi-agent reinforcement learning, rather than depending primarily on the backbone model’s native capabilities and in-context learning. We also plan to explore training smaller or specialised models to reduce inference cost and latency, enabling more efficient and scalable deployment.

附录DAppendix D具有相同工具访问权限的单代理基线Single-Agent Baseline with Identical Tool Access

为了隔离所提出的框架的贡献，我们使用与分层系统相同的工具访问和骨干模型来评估单代理基线。具体来说，我们使用 GPT-5.1（与 Host/Manager 主干相同）和 GPT-5-mini（与 Worker 主干相同），两者都授予对搜索、浏览器、文件系统和代码工具的相同访问权限。To isolate the contribution of the proposed framework, we evaluate single-agent baselines using the same tool access and backbone models as the hierarchical system. Specifically, we use GPT-5.1 (identical to the Host/Manager backbone) and GPT-5-mini (identical to the Worker backbone), both granted identical access to the search, browser, filesystem, and code tools.

表Table5报告 WideSearch-en 基准测试的结果。分层系统在所有指标上都显着优于单代理基线。reports the results on the WideSearch-en benchmark. The hierarchical system significantly outperforms both single-agent baselines across all metrics.

这些结果表明，性能改进主要来自分层架构，而不是仅来自主干模型功能。即使使用相同的工具和相同的前沿模型为主机和管理器提供支持，单代理配置也只能实现 6.00% 的成功率和 35.74% 的项目 F1，远低于分层系统的 12.50% 的成功率和 75.21% 的项目 F1。These results indicate that performance improvements arise primarily from the hierarchical architecture rather than from backbone model capability alone. Even with identical tools and the same frontier model powering the Host and Managers, the single-agent configuration achieves only 6.00% success rate and 35.74% Item F1, substantially below the hierarchical system’s 12.50% success rate and 75.21% Item F1.

WideSearch 任务需要协调多个来源的证据并执行大规模聚合。分层架构将这种复杂性分布在具有隔离上下文的专用模块之间，这有助于减轻单个共享上下文的限制。WideSearch tasks require coordinating evidence across many sources and performing large-scale aggregation. The hierarchical architecture distributes this complexity across specialized modules with isolated contexts, which helps mitigate the limitations of a single shared context.

值得注意的是，超过 80% 的代币消耗发生在 GPT-5-mini Workers 中，但分层系统仍然超越了更强的 GPT-5.1 单代理基线。这表明架构设计在性能和成本效率方面发挥着关键作用。Notably, more than 80% of token consumption occurs in GPT-5-mini Workers, yet the hierarchical system still surpasses the stronger GPT-5.1 single-agent baseline. This suggests that the architectural design plays a key role in both performance and cost efficiency.
