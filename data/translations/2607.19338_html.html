1 简介Introduction

最近的工作已经将代码生成从孤立的编程问题转向软件工程代理，这些代理可以检查存储库、编辑文件、执行命令、运行测试和迭代故障Recent work has moved code generation beyond isolated programming problems toward software-engineering agents that inspect repositories, edit files, execute commands, run tests, and iterate on failures(Jimenez et al., 2024; Yang et al., 2024; Jain et al., 2024; Wang et al., 2025; Pan et al., 2025; Ye et al., 2026)。这种转变在前沿模型报告中也很明显，其中编码能力越来越多地通过存储库级补丁生成、终端使用、沙盒执行和长期代理工作流程进行评估. This shift is also visible in frontier-model reports, where coding capability is increasingly evaluated through repository-level patch generation, terminal use, sandboxed execution, and long-horizon agentic workflows(OpenAI, 2025b; a; Anthropic, 2025b; Google DeepMind, 2025)。随着编码代理成为交互式系统而不是一次性生成器，推理不再是单个模型调用。每次失败的尝试都会创建一个新的决策点：代理是否应该使用执行反馈修复现有解决方案，从不同的计划开始，还是调用更强大的模型？考虑开发人员要求代理实现解析器。便宜的型号可能 生成未通过隐藏边界情况测试的代码。一种合理的回应是 使用错误反馈修补现有逻辑；另一种是丢弃 脆弱的战略并产生新的实施；第三种方法是调用 如果失败表明存在更深层次的算法问题，则模型会更强。这些 响应有不同的成本，最便宜的有用的下一步取决于 实例。. As coding agents become interactive systems rather than one-shot generators, inference is no longer a single model call. Each failed attempt creates a new decision point: should the agent repair the existing solution using execution feedback, start over with a different plan, or invoke a stronger model? Consider a developer asking an agent to implement a parser. A cheap model may produce code that fails a hidden boundary-case test. One reasonable response is to patch the existing logic using the error feedback; another is to discard the brittle strategy and generate a fresh implementation; a third is to call a stronger model if the failure suggests a deeper algorithmic issue. These responses have different costs, and the cheapest useful next step depends on the instance.

因此，通过路由和级联研究了成本感知的 LLM 推理。路由器在生成之前将每个查询分配给弱或强模型，而级联首先尝试便宜的模型，并将不确定的情况推迟到更强的模型Cost-aware LLM inference has therefore been studied through routing and cascading. Routers assign each query to a weak or strong model before generation, while cascades try a cheap model first and defer uncertain cases to a stronger model(Chen et al., 2024a; Ding et al., 2024; Ong et al., 2025; Dekoninck et al., 2025; Valkanas et al., 2025)。这些抽象很强大，但它们通常主要将弱模型的失败视为需要更强大的模型参数的证据。这可以留下有用的廉价型号容量。最近关于测试时间缩放的工作提出了更广泛的观点：对于许多推理任务，将更多的推理时间计算分配给同一模型可以与切换到更大的模型竞争. These abstractions are powerful, but they often treat a weak model’s failure primarily as evidence that more capable model parameters are needed. This can leave useful cheap-model capacity on the table. Recent work on test-time scaling suggests a broader view: for many reasoning tasks, allocating more inference-time computation to the same model can be competitive with switching to a larger model(Snell et al., 2025)。编码代理使这种区别变得特别具体，因为失败的执行本身就可以提供信息。编译器错误、断言失败、输出错误、超时或被拒绝的补丁可能会将未指定的编程问题转变为已诊断的修复问题。在这种情况下，再进行一次带有正确反馈的廉价调用可能比立即升级更有效地利用小模型。因此，相关决定不仅是. Coding agents make this distinction especially concrete because failed execution is itself informative. A compiler error, failed assertion, wrong output, timeout, or rejected patch can turn an underspecified programming problem into a diagnosed repair problem. In such cases, spending another cheap call with the right feedback may exploit the small model more effectively than immediately escalating. Thus the relevant decision is not only哪个型号which model打电话，但是to call, but哪个恢复动作which recovery action采取。to take.

这激发了编码代理推理的恢复动作视图。 Claude Code 和 Codex 等生产编码代理公开了更广泛的交互模式：它们读取代码库、编辑文件、运行命令或测试，并根据工具反馈继续This motivates a recovery-action view of coding-agent inference. Production coding agents such as Claude Code and Codex expose the broader interaction pattern: they read codebases, edit files, run commands or tests, and continue from tool feedback(Anthropic, 2025a; OpenAI, 2025a)。我们用一个三动作故障后路由器来实例化这个想法。廉价模型失败后，路由器会观察问题陈述、执行结论和 stderr 跟踪，然后在其中进行选择. We instantiate this idea with a three-action post-failure router. After a cheap model fails, the router observes the problem statement, execution verdict, and stderr trace, then chooses among反映reflect（使用反馈进行修改），(revise using feedback),重新计划replan（用新计划中的廉价模型再次求解），并且(solve again with the cheap model from a fresh plan), and升级escalate（遵循更强的模型）。我们选择这些行动作为最小的一阶恢复集，而不是代理干预的详尽分类。它们涵盖了三种常见的故障后假设：当前轨迹可能可以使用执行反馈进行本地修复，轨迹可能是错误的，但廉价模型仍然可以从新计划中成功，或者失败可能反映了需要更强大模型的能力差距。先前的工作支持每个轴：反馈驱动的代码修复和迭代反思激励(defer to a stronger model). We choose these actions as a minimal first-order recovery set rather than an exhaustive taxonomy of agent interventions. They span three common post-failure hypotheses: the current trajectory may be locally repairable using execution feedback, the trajectory may be wrong but the cheap model may still succeed from a fresh plan, or the failure may reflect a capability gap requiring a stronger model. Prior work supports each axis: feedback-driven code repair and iterative reflection motivate反映reflect (Shinn et al., 2023; Chen et al., 2024b; Zhong et al., 2024; Li et al., 2025);测试时计算缩放和重复采样激励; test-time compute scaling and repeated sampling motivate重新计划replan (Snell et al., 2025; Brown et al., 2024);以及具有成本意识的路由和级联激励; and cost-aware routing and cascading motivate升级escalate (Chen et al., 2024a; Ding et al., 2024; Ong et al., 2025; Valkanas et al., 2025)。我们的成功行动分析表明，这些行动没有严格的顺序：. Our successful-action analysis suggests that these actions are not strictly ordered:反映reflect和and重新计划replan比便宜得多are much cheaper than升级escalate，但它们并非一律更差；有些示例可以通过廉价的恢复操作来解决，有些需要升级，有些则无法通过任何可用的操作来解决。我们通过用最便宜的成功恢复操作标记每个示例来从执行部署中训练路由器，并通过解决率而不是简单的分类准确性来评估决策，因为多个操作可能会解决相同的任务。, but they are not uniformly worse; some examples are solved by cheap recovery actions, some require escalation, and some are not solved by any available action. We train the router from execution rollouts by labeling each example with the cheapest successful recovery action, and evaluate decisions by solve rate rather than plain classification accuracy because multiple actions may solve the same task.

除了选择正确的恢复操作之外，部署还带来了另一个挑战：所需的成本质量权衡可能会因用户、工作负载和运营预算而变化。一些预算感知路由方法通过训练目标或约束优化问题中内置的预算或成本目标来优化策略Beyond choosing the right recovery action, deployment adds another challenge: the desired cost-quality trade-off may change across users, workloads, and operating budgets. Some budget-aware routing methods optimize policies with a budget or cost target built into the training objective or constrained optimization problem(Zhang et al., 2026)。另外，共形级联方法表明校准可以提供部署时间保证，但它们通常校准接受/推迟或停止/升级决策的标量阈值. Separately, conformal cascade methods show that calibration can provide deployment-time guarantees, but they typically calibrate scalar thresholds for accept/defer or stop/escalate decisions(Jung et al., 2025; Valkanas et al., 2025)。我们的设置需要对成功模式非单调的异构恢复操作进行预算控制。我们通过在单个经过训练的路由器之上放置一个保形风险控制（CRC）层来解决这个问题. Our setting requires budget control over heterogeneous recovery actions whose success patterns are non-monotone. We address this by placing a Conformal Risk Control (CRC) layer on top of a single trained router(Angelopoulos et al., 2024)。 CRC 校准部署时间成本损失，将路由器从不受约束的 argmax 转向更便宜的操作，从而在可交换性下产生边际预期成本控制，而无需针对每个预算重新训练路由器。重要的是，保证涉及成本而不是解决率，因此恢复操作可以具有非单调的成功模式。结果是一个离散的、预算可控的边界：更严格的预算选择更便宜的恢复行为，而更宽松的预算允许更积极地使用升级。. CRC calibrates a deployment-time cost penalty that shifts the router from unconstrained argmax toward cheaper actions, yielding marginal expected-cost control under exchangeability without retraining the router for each budget. Importantly, the guarantee concerns cost rather than solve rate, so the recovery actions can have non-monotone success patterns. The result is a discrete, budget-controllable frontier: tighter budgets select cheaper recovery behavior, while looser budgets permit more aggressive use of escalation.

6 结论Conclusion

我们研究了编码代理的预算可控恢复路由。我们没有将失败的廉价模型尝试视为二元延迟决策，而是将恢复制定为异构操作中的选择。这种表述符合可执行编码环境的核心属性：失败提供诊断反馈，最便宜的有用的下一步并不总是最强大的模型。We studied budget-controllable recovery routing for coding agents. Instead of treating a failed cheap-model attempt as a binary defer decision, we formulate recovery as a choice among heterogeneous actions. This formulation matches a central property of executable coding environments: failures provide diagnostic feedback, and the cheapest useful next step is not always the strongest model.

我们的结果提供了证据，表明廉价的恢复和模型升级可以对保留的编码故障起到补充作用，并且学习的恢复路由器可以优于固定操作和仅提示路由基线。添加 CRC 校准层可将同一受过训练的路由器转变为一系列具有边际预期成本控制的预算操作点，从而允许在不重新训练路由器的情况下更改部署预算。Our results provide evidence that cheap recovery and model escalation can be complementary on held-out coding failures, and that a learned recovery router can outperform fixed-action and prompt-only routing baselines. Adding a CRC calibration layer turns the same trained router into a family of budgeted operating points with marginal expected-cost control, allowing deployment budgets to change without retraining the router.

这项研究也有明显的局限性。我们将恢复建模为单个故障后决策，而部署的编码代理通常会经过多轮恢复。最便宜的成功训练标签是一个有用的代理，而不是每个动作成功概率的校准估计。 CRC 控制预期恢复成本而不是解决率，因此质量改进仍然是经验性的。未来的工作应该将恢复路由扩展到多步代理轨迹和更丰富的部署约束。The study also has clear limitations. We model recovery as a single post-failure decision, while deployed coding agents often recover over multiple rounds. The cheapest-successful training label is a useful proxy rather than a calibrated estimate of each action’s success probability. CRC controls expected recovery cost rather than solve rate, so quality improvements remain empirical. Future work should extend recovery routing to multi-step agent trajectories and richer deployment constraints.
