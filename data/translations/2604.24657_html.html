特工沃德AgentWard：自主人工智能代理的生命周期安全架构: A Lifecycle Security Architecture for Autonomous AI Agents

Yixiang Zhang, Xinhao Deng, Jiaqing Wu, Yue Xiao, Ke Xu, Qi Li
摘要Abstract

自主人工智能代理将大型语言模型扩展到完整的运行时系统，该系统加载技能、摄取外部内容、维护内存、规划多步骤操作并调用特权工具。在此类系统中，安全故障很少局限于单个接口；相反，它们可以在初始化、输入处理、内存、决策和执行中传播，通常只有当有害影响在环境中出现时才会变得明显。 本文介绍了Autonomous AI agents extend large language models into full runtime systems that load skills, ingest external content, maintain memory, plan multi-step actions, and invoke privileged tools. In such systems, security failures rarely remain confined to a single interface; instead, they can propagate across initialization, input processing, memory, decision-making, and execution, often becoming apparent only when harmful effects materialize in the environment. This paper presents特工沃德AgentWard，一种面向生命周期的深度防御架构，系统地组织跨这五个阶段的保护。, a lifecycle-oriented, defense-in-depth architecture that systematically organizes protection across these five stages.特工沃德AgentWard将特定阶段的异构控制与跨层协调相集成，从而能够沿着传播路径拦截威胁，同时保护关键资产。 我们详细介绍了五个协调保护层的设计原理和架构，并在 OpenClaw 上实现了一个插件原生原型以证明实际可行性。这一视角为构建运行时安全控制、管理信任传播以及在自主人工智能代理中实施执行遏制提供了具体的蓝图。integrates stage-specific, heterogeneous controls with cross-layer coordination, enabling threats to be intercepted along their propagation paths while safeguarding critical assets. We detail the design rationale and architecture of five coordinated protection layers, and implement a plugin-native prototype on OpenClaw to demonstrate practical feasibility. This perspective provides a concrete blueprint for structuring runtime security controls, managing trust propagation, and enforcing execution containment in autonomous AI agents.

I 简介Introduction

大型语言模型（LLM）集成系统已经从纯文本问答聊天机器人发展到能够执行脚本生成和网络搜索等短期任务的工具增强代理，最近又发展到可以委派和执行端到端任务（包括项目管理和综合研究）的高度自治的运行时系统Large language model (LLM)-integrated systems have evolved from text-only question–answering chatbots to tool-augmented agents capable of short-term tasks, such as script generation and web search, and more recently to highly autonomous runtime systems that can delegate and execute end-to-end tasks, including project management and comprehensive research[19, 13, 15]。 这一进步不仅是由基础模型的规划和工具使用能力的进步推动的，也是由代理架构的演变推动的。系统已经从简单的工具调用管道发展到更复杂的设计，支持动态技能获取、长期记忆和持久工作空间，从而实现更复杂和持续的代理行为. This progression is driven not only by advances in planning and tool-use capabilities of foundation models, but also by the evolution of agent architectures. Systems have evolved from simple tool-invocation pipelines to more sophisticated designs that support dynamic skill acquisition, long-term memory, and persistent workspaces, thereby enabling more complex and sustained agent behaviors[12]。 开爪. OpenClaw[4, 15]体现了这一趋势。它支持社区贡献的技能，在跨会话的持久工作空间中维护结构化的短期和长期记忆，并通过在实际运行时权限下对主机工具的受控访问来执行特权任务。exemplifies this trend. It supports community-contributed skills, maintains structured short- and long-term memory within a persistent workspace across sessions, and executes privileged tasks through controlled access to host tools under real runtime permissions.

这种架构和功能的演变拓宽了安全边界，从内容安全到完整的运行时系统安全。在传统的聊天机器人设置中，安全问题主要集中在不安全的输入或输出上；通过工具集成，源自用户和模型外部的间接提示注入和工具选择操作可能会进一步产生风险This architectural and capability evolution broadens the security boundary from content safety to full runtime system security. In traditional chatbot settings, security concerns primarily focus on unsafe inputs or outputs; with tool integration, risks can further arise from indirect prompt injection and tool-selection manipulation originating outside both the user and the model[6, 8, 3]。 自主代理通过引入复杂的运行时模块、中间状态、动态执行路径和扩展特权来放大这些风险，这些共同扩大了攻击面并增加了故障的潜在影响。因此，技能受损、内存中毒或局部推理错误可能会升级为文件修改、服务中断或数据泄露. Autonomous agents amplify these risks by introducing complex runtime modules, intermediate states, dynamic execution paths, and expanded privileges, which together enlarge the attack surface and increase the potential impact of failures. As a result, compromised skills, poisoned memory, or localized reasoning errors can escalate into file modification, service disruption, or data exfiltration[9, 5, 17, 1]。这些威胁通常会在运行时管道中传播：攻击可能会在一个阶段进入，持续通过中间状态，并在稍后表现为有害执行。此类模式超出了逐点防御的范围，例如输入过滤和端到端运行时安全性调用。例如，多步间接提示注入可能会逃避输入级分析、毒害内存，并随后触发有害操作，而内存完整性检查和行为级分析可以在攻击成功之前暴露异常状态和不一致的执行模式。. These threats often propagate across the runtime pipeline: an attack may enter at one stage, persist through intermediate state, and manifest only later as harmful execution. Such patterns exceed the scope of pointwise defenses such as input filtering and call for end-to-end runtime security. For instance, a multi-step indirect prompt injection may evade input-level analysis, poison memory, and later trigger harmful actions, whereas memory integrity checks and behavior-level analysis can expose anomalous state and inconsistent execution patterns before the attack succeeds.

The framework organizes protection into five coordinated layers aligned with these stages, providing comprehensive coverage while disrupting attack propagation paths and safeguarding critical assets:

Collectively, these layers isolate typical risk propagation paths and reinforce one another, thereby enhancing overall system robustness.

II 威胁的生命周期安全视图A Lifecycle Security View of Threats

自主人工智能代理充当为完成任务而设计的迭代系统。由初始提示触发，代理利用大型语言模型（LLM）对外部知识和操作指导进行推理，维护其内部状态，并在反馈驱动的循环中重复调用工具，直到完成任务。这个运行时过程可以分为五个不同的阶段：初始化、输入、内存、决策和执行Autonomous AI agents function as iterative systems designed for task completion. Triggered by an initial prompt, the agent leverages a large language model (LLM) to reason over external knowledge and operational guidance, maintains its internal state, and repeatedly invokes tools in a feedback-driven loop until the task is accomplished. This runtime process can be broken down into five distinct stages: initialization, input, memory, decision, and execution[4].

在初始化阶段，代理通过加载必要的配置、插件、技能和其他能力来建立其运行环境。这些组件提供执行复杂任务所需的外部知识和工具接口。 在输入阶段，各种输入，例如提示、文档、网页、检索结果、工具响应等，都被合并到当前上下文中。 在记忆阶段，短期记忆和长期记忆都受到管理。短期记忆在会话内维护，当对话超出模型的上下文窗口时可能会被压缩，而长期记忆则持久存储并在会话之间共享，并在必要时检索。此外，用户偏好和规则可以写入工作区文件中，例如At the initialization stage, the agent establishes its operating environment by loading necessary configurations, plugins, skills, and other capabilities. These components provide the external knowledge and tool interfaces required for performing complex tasks. During the input stage, various inputs, such as prompts, documents, webpages, retrieval results, and tool responses, are incorporated into the current context. In the memory stage, both short-term and long-term memory are managed. Short-term memory is maintained within the session and may be compressed when the dialogue exceeds the model’s context window, while long-term memory is persistently stored and shared across sessions, retrieved as necessary. Additionally, user preferences and rules may be written into workspace files, such as代理.mdAGENTS.md和and用户名.mdUSER.md。 决策阶段将可用技能、可调用工具、会话历史记录、内存和当前用户请求集成到模型输入中，以进行推理、计划制定和工具选择。 最后，在执行阶段，代理将其决策转化为具体行动，产生完成任务的外部副作用。. The decision stage integrates available skills, callable tools, session history, memory, and the current user request into model inputs for reasoning, plan formulation, and tool selection. Finally, during the execution stage, the agent translates its decisions into concrete actions, producing external side effects that complete the task.

Ⅱ-AII-A 对代理生命周期的威胁Threats to Agents Lifecycle

这五个生命周期阶段暴露了不同的安全问题。在初始化时，关键问题是代理是否从值得信赖的基线开始，因为恶意插件、中毒技能、不安全的依赖项或过度特权的配置可能会在任何任务开始之前损害功能集These five lifecycle stages expose distinct security problems. At initialization, the key concern is whether the agent begins from a trustworthy baseline, since malicious plugins, poisoned skills, unsafe dependencies, or over-privileged configurations can compromise the capability set before any task begins[9, 10]。 在输入时，核心问题是不受信任的外部内容是否作为被动数据被允许进入工作上下文，或者被误解为可操作的控制信号，从而实现间接提示注入和相关的上下文污染攻击. At input, the central problem is whether untrusted external content is admitted into the working context as passive data or misinterpreted as actionable control signals, enabling indirect prompt injection and related context-contamination attacks[6, 8, 2]。 在内存中，风险从短暂的影响转变为持续的损坏，因为对会话状态或长期内存的不安全更新可能会将本地操作转变为持久的行为偏差. At memory, the risk shifts from transient influence to persistent corruption, because unsafe updates to session state or long-term memory can turn a local manipulation into durable behavioral bias[5, 14, 17]。 在决策时，主要问题是代理的计划、工具选择和参数是否与授权任务保持一致. At decision, the main problem is whether the agent’s plan, tool choice, and parameters remain aligned with the authorized task[16, 18]。 在执行时，这些上游偏差会变成具体的外部影响，包括不安全的命令执行、未经授权的文件或服务修改、数据泄露和资源滥用. At execution, those upstream deviations become concrete external effects, including unsafe command execution, unauthorized file or service modification, data exfiltration, and resource abuse[7, 1].

Ⅱ-BII-B 跨阶段风险传播Cross-Stage Risk Propagation

在自主代理中，许多真正的攻击不会停留在它们首次出现的阶段，而是沿着生命周期演变为跨阶段的威胁轨迹。因此，诸如提示注入之类的常见技术可以更好地理解为进入运行时和改变中间状态的机制，而不是最终危害本身。威胁可能来自多个点，包括受损的初始化工件、不受信任的外部输入、中毒的内存或内部生成的决策错误（例如幻觉和客观漂移）。一旦上下文、内存或计划状态被破坏，这些中间状态不仅成为攻击的受害者，而且成为将风险传播到后续阶段的中继点。例如，在输入时引入的恶意内容可能首先毒害存储器，并且中毒的存储器随后可能重新进入检索和上下文构建，从而使后续决策产生偏差。当这些决策转化为输出和行动时，威胁会进一步放大为面向用户的错误响应、未经授权的计划、不安全的工具调用或有害的执行结果。因此，自主代理威胁应被理解为整个生命周期中复杂、持久且部分隐藏的传播路径，而不是绑定到单个接口的孤立攻击实例In autonomous agents, many real attacks do not remain local to the stage where they first appear, but instead evolve as cross-stage threat trajectories along the lifecycle. Common techniques such as prompt injection are therefore better understood as mechanisms for entering the runtime and altering intermediate state than as the final harm itself. Threats may originate from multiple points, including compromised initialization artifacts, untrusted external inputs, poisoned memory, or internally generated decision errors such as hallucination and objective drift. Once context, memory, or planning state is corrupted, these intermediate states become not only victims of attack but also relay points that propagate risk into later stages. For example, malicious content introduced at input may first poison memory, and the poisoned memory may later re-enter retrieval and context construction, thereby biasing subsequent decisions. As those decisions are translated into outputs and actions, the threat is further amplified into false user-facing responses, unauthorized plans, unsafe tool calls, or harmful execution outcomes. Autonomous-agent threats should therefore be understood as complex, persistent, and partially hidden paths of propagation across the lifecycle rather than as isolated attack instances tied to a single interface[6, 5, 14].

Ⅲ-AIII-A 设计原理Design Rationale

的设计The design of特工沃德AgentWard以四个实际问题为指导： 框架应该保护什么？ 框架应该采取什么安全态势？ 防御应该如何组织？ 这些问题激发了四个互补的设计原则：全生命周期覆盖、零信任执行、异构防御和跨层协调。is guided by four practical questions: What should the framework protect? What security posture should the framework adopt? How should the defenses be organized? These questions motivate four complementary design principles: full-lifecycle coverage, zero-trust enforcement, heterogeneous defense, and cross-layer coordination.

全生命周期覆盖Full-lifecycle Coverage: 特工沃德AgentWard旨在保护整个代理运行时系统，包括代理、其托管的资产、其运行的环境以及其服务的用户。它还旨在在可能的攻击传播路径造成外部损害之前中断它们。为此，aims to protect the entire agent runtime system, including the agent, the assets it hosts, the environment in which it operates, and the users it serves. It also aims to interrupt plausible attack propagation paths before they result in external harm. To this end,特工沃德AgentWard涵盖自治代理的整个生命周期，从初始化到执行。这种设计是必要的，因为针对自主代理的威胁通常跨越阶段边界，而不是局限于单个接口。因此，全生命周期覆盖减少了运行时管道中的盲点，并使攻击能够在传播路径上的多个点被拦截。covers the full lifecycle of an autonomous agent, from initialization to execution. This design is necessary because threats against autonomous agents often cross stage boundaries rather than remaining confined to a single interface. Full-lifecycle coverage therefore reduces blind spots in the runtime pipeline and enables attacks to be intercepted at multiple points along their propagation paths.

零信任执行Zero-trust Enforcement: 特工沃德AgentWard采用最坏情况的运行时态势：攻击可能在任何阶段进入，污染任何对象，并通过任何接口传播。考虑到运行时攻击的多样性和隐蔽性，每一层都应该假设上游组件、保留状态和外部信号可能已经受到损害或受到敌对影响。因此，每一层都在零信任状态下评估本地输入、状态、信号和行为，而不是仅仅依赖于先前层做出的允许决策。因此，较早的允许决策不会自动授予下游通道，并且后面的层仍然可以在故障安全状态下阻止、限制或升级危险行为。adopts a worst-case runtime posture: an attack may enter at any stage, contaminate any object, and propagate through any interface. Given the diversity and stealthiness of runtime attacks, each layer should assume that upstream components, retained state, and external signals may already be compromised or adversarially influenced. Accordingly, every layer evaluates local inputs, states, signals, and behaviors under a zero-trust posture, rather than relying solely on allow decisions made by preceding layers. As a result, an earlier allow decision does not automatically grant downstream passage, and later layers can still block, constrain, or escalate risky behavior under a fail-safe posture.

异构防御Heterogeneous Defense： 鉴于攻击技术和传播路径的多样性，任何单一类别的防御机制都不足以提供全面的保护。如果所有层都依赖于类似的检测逻辑或干预策略，攻击者可能会利用常见的旁路模式，导致整个框架出现相关故障。为了提高鲁棒性并减少共同的故障模式，: Given the diversity of attack techniques and propagation paths, no single class of defense mechanism is sufficient for comprehensive protection. If all layers rely on similar detection logic or intervention strategies, an attacker may exploit a common bypass pattern that causes correlated failures across the framework. To improve robustness and reduce shared failure modes,特工沃德AgentWard采用跨层异构机制。这些机制基于不同的防御原则，保护不同的安全对象，利用不同形式的证据，并通过不同的手段干预危险行为。employs heterogeneous mechanisms across layers. These mechanisms are grounded in different defensive principles, protect different security objects, leverage different forms of evidence, and intervene in risky behavior through different means.

跨层协调Cross-layer Coordination： 尽管每一层都做出本地安全决策，但这些层不应该孤立运行。从全球角度来看，一次攻击可能会跨多个阶段传播，在一个阶段留下微弱的信号，而在另一个阶段只表现出有害影响。单阶段观察可能会显得可疑，但不足以做出自信的决定；通过共享背景和积累风险证据，: Although each layer makes local security decisions, the layers should not operate in isolation. From a global perspective, an attack may propagate across multiple stages, leave weak signals in one stage, and only manifest harmful effects in another. Ⅲ-CIII-C 跨层协调Cross-layer Coordination

跨层协调对于保护自主代理免受复杂攻击链和隐秘多轮攻击至关重要。在Cross-layer coordination is essential for defending autonomous agents against complex attack chains and stealthy multi-turn attacks. In特工沃德AgentWard，每一层不仅应该做出本地安全决策，还应该将其观察结果贡献给共享安全上下文。该上下文记录了会话级风险证据、信任注释以及对关键攻击面的特定层判断，包括技能、内存、工具、任务和执行请求。, each layer should not only make local security decisions, but also contribute its observations to a shared security context. This context records session-level risk evidence, trust annotations, and layer-specific judgments over key attack surfaces, including skills, memory, tools, tasks, and execution requests.特工沃德AgentWard还应维护一个攻击路径知识库，以捕获风险如何进入生命周期、跨阶段传播以及导致有害结果。这种设计允许框架将威胁视为不断发展的轨迹而不是孤立的事件。should also maintain an attack-path knowledge base that captures how risks enter the lifecycle, propagate across stages, and lead to harmful outcomes. This design allows the framework to reason about threats as evolving trajectories rather than isolated events.

这种协调有两个主要目的。首先，它可以实现会话级风险累积。单层可能会观察到薄弱或模糊的证据，例如可疑的输入内容、不确定的内存更新或不寻常的规划决策，但证据可能不足以证明立即阻止的合理性。通过将这些信号向前传送，后面的层可以将它们与新的观察结果聚合起来，并形成更可靠的评估。例如，如果输入清理层将文档标记为不明确，但无法确认提示注入尝试，则认知保护层和决策调整层可以在评估是否应保留、检索内容或用于证明高风险操作的合理性时重用此标记。累积的风险上下文也可以由执行控制层继承，执行控制层可以应用更严格的执行策略，例如减少工具权限、额外的审批门、沙盒执行或细粒度的运行时监控。这样，不确定的风险可以逐步升级并转化为更强的下游控制，而不是在阶段边界被丢弃。This coordination serves two main purposes. First, it enables session-level risk accumulation. A single layer may observe weak or ambiguous evidence, such as suspicious input content, an uncertain memory update, or an unusual planning decision, but the evidence may be insufficient to justify immediate blocking. By carrying these signals forward, later layers can aggregate them with new observations and form a more reliable assessment. For example, if the Input Sanitization Layer marks a document as ambiguous but cannot confirm a prompt injection attempt, the Cognition Protection Layer and Decision Alignment Layer can reuse this marker when evaluating whether the content should be persisted, retrieved, or used to justify a high-risk action. The accumulated risk context can also be inherited by the Execution Control Layer, which may apply stricter execution policies, such as reduced tool permissions, additional approval gates, sandboxed execution, or fine-grained runtime monitoring. In this way, uncertain risks can be progressively escalated and translated into stronger downstream controls instead of being discarded at stage boundaries.

其次，跨层协调可以实现历史感知的防御适应。由于自主代理通过跨回合、任务和会话的迭代生命周期循环进行操作，因此安全判断不应被视为在单个阶段或交互后消失的一次性决策。相反，可以重用在先前生命周期迭代中积累的风险概况和攻击路径知识来完善未来对类似行为的评估。如果之前观察到特定的注入模式、内存中毒策略或不安全的工具使用顺序，则相应的证据应该为后续分析提供信息，并允许相关层应用更保守的判断。这种适应也可以跨层不对称。攻击可能会绕过早期语义检查和内存验证，但随后在尝试触发高风险操作时会被执行控制层拦截。由此产生的证据不应保留在执行过程中；相反，它应该被抽象为可重用的攻击路径知识，并传播回早期层，从而能够在以后的生命周期迭代中更早地识别类似的策略。Second, cross-layer coordination enables history-aware defense adaptation. Since autonomous agents operate through iterative lifecycle loops across turns, tasks, and sessions, security judgments should not be treated as one-time decisions that disappear after a single stage or interaction. Instead, risk profiles and attack-path knowledge accumulated in previous lifecycle iterations can be reused to refine future assessments of similar behaviors. If a particular injection pattern, memory-poisoning strategy, or unsafe tool-use sequence has been observed before, the corresponding evidence should inform subsequent analysis and allow relevant layers to apply more conservative judgments. This adaptation can also be asymmetric across layers. An attack may bypass early semantic checks and memory validation, but later be intercepted by the Execution Control Layer when it attempts to trigger a high-risk operation. The resulting evidence should not remain local to execution; rather, it should be abstracted into reusable attack-path knowledge and propagated back to earlier layers, enabling earlier recognition of similar tactics in later lifecycle iterations.

通过共享安全状态和可重用的攻击知识连接层本地判断，跨层协调降低了孤立层故障的风险。它允许微弱信号在会话中累积，使先前的经验能够改善跨生命周期迭代的未来防御，并允许异构层在整个代理生命周期中相互加强。By connecting layer-local judgments through shared security state and reusable attack knowledge, cross-layer coordination reduces the risk of isolated layer failures. It allows weak signals to accumulate within a session, enables prior experience to improve future defenses across lifecycle iterations, and allows heterogeneous layers to reinforce one another throughout the agent lifecycle.

This scope is sufficient for the two case studies below, which aim to demonstrate layered interception and cross-stage coordination in a running agent system rather than to provide exhaustive benchmark coverage.

IV-B 案例研究Case Studies

我们不是每层展示一个案例，而是检查两个跨越多个边界的生命周期攻击链。这个组织使框架的作用更加清晰：Rather than presenting one case per layer, we examine two lifecycle attack chains that cross multiple boundaries. This organization makes the framework’s role clearer:特工沃德AgentWard当早期发现限制了后续阶段可以存储、计划或执行的内容时，它是最有用的，而不是保留没有下游影响的本地信号。is most useful when an early finding constrains what later stages may store, plan, or execute, instead of remaining a local signal with no downstream effect.

IV-B1 案例一：恶意技术未经授权访问数据Case 1: Malicious Skill to Unauthorized Data Access

第一种情况涉及用户安装的技能，其描述看似良性，而其文件包含混淆的指令，这些指令引导代理进行未经授权的凭据访问或数据导出The first case involves a user-installed skill whose description appears benign, while its files contain obfuscated instructions that steer the agent toward unauthorized credential access or data export[9]。攻击首先出现在运行时供应链边界，基础扫描层在第一个推理轮之前检查技能。该层检测到声明的能力与实际技能内容之间不匹配，但证据被部分隐藏，可能不足以立即阻止。因此，它将发现结果记录为风险标记，并将警告传播到下游层。. The attack first appears at the runtime-supply chain boundary, where the Foundation Scan Layer inspects the skill before the first reasoning turn. The layer detects a mismatch between the declared capability and the actual skill content, but the evidence is partially concealed and may be insufficient for immediate blocking. It therefore records the finding as a risk marker and propagates the warning to downstream layers.

受此技能的影响，良性编程任务逐渐转向读取敏感文件、打包其内容并准备传输到外部目的地。在决策阶段，决策调整层会比较原始用户意图、接受的上下文、基础扫描警告和建议的操作。此次审查发现，新出现的计划超出了授权任务，并且与用户的意图相冲突。然后，累积的风险将由执行控制层继承，该层对会话应用更严格的工具权限。当代理尝试读取敏感文件或调用高风险命令时，该操作会在影响环境之前被阻止。Influenced by this skill, a benign programming task gradually shifts toward reading a sensitive file, packaging its contents, and preparing transmission to an external destination. At the decision stage, the Decision Alignment Layer compares the original user intent, the accepted context, the Foundation Scan warning, and the proposed action. This review identifies that the emerging plan exceeds the authorized task and conflicts with the user’s intent. The accumulated risk is then inherited by the Execution Control Layer, which applies stricter tool permissions for the session. When the agent attempts to read the sensitive file or invoke a high-risk command, the action is blocked before it affects the environment.

这一案例说明初始化风险不能作为一次性筛选问题来处理。恶意技能作为能力工件进入，但其有害影响只有在影响计划或达到执行后才可能显现出来。This case illustrates that initialization risk cannot be handled as a one-time screening problem. A malicious skill enters as a capability artifact, but its harmful effect may only become visible after it influences planning or reaches execution.特工沃德AgentWard保持跨层的连续性：初始化警告会降低下游信任，决策调整会暴露未经授权的计划偏差，执行控制通过最终权限执行来限制剩余的爆炸半径。preserves continuity across layers: an initialization warning lowers downstream trust, decision alignment exposes unauthorized plan drift, and execution control limits the remaining blast radius through final permission enforcement.

IV-B2 案例2：间接即时注入持久后门和DoSCase 2: Indirect Prompt Injection to Persistent Backdoor and DoS

当网页或工具结果包含间接提示注入时，第二种情况开始，该注入看起来足够良性，可以进入工作上下文，特别是在仅检测输入过滤的情况下。这种攻击首先跨越指令数据边界。输入清理层检查返回内容中的提示模板标记、越狱短语和危险指令模式。当识别出可疑内容时，该层可以警告代理、暂时限制工具调用权限，或防止持久保存受污染的工具结果和派生响应The second case begins when a webpage or tool result contains an indirect prompt injection that appears sufficiently benign to enter the working context, especially under detection-only input filtering. This attack first crosses the instruction-data boundary. The Input Sanitization Layer examines returned content for prompt-template markers, jailbreak phrases, and dangerous instruction patterns. When suspicious content is identified, the layer can warn the agent, temporarily restrict tool-call permissions, or prevent contaminated tool results and derived responses from being persisted[16, 2]。 如果受污染的内容仍然影响会话，则攻击可能会从短暂的上下文操纵升级为持久的危害。典型的下一步是将恶意指令写入持久状态工件，例如. If the contaminated content still influences the session, the attack may escalate from transient context manipulation to persistent compromise. A typical next step is to write malicious instructions into durable state artifacts, such as内存.mdMEMORY.md, 代理.mdAGENTS.md，或相关的工作区文件。认知保护层在工具边界检查这些状态更改操作并阻止可疑的内存突变，从而防止注入的指令在以后的会话中成为可信上下文, or related workspace files. The Cognition Protection Layer inspects these state-changing operations at the tool boundary and blocks suspicious memory mutations, preventing the injected instructions from becoming trusted context in later sessions[5, 14, 17]。在此链中，写入端干预至关重要，因为它可以防止未来的内存加载步骤重新激活后门。. In this chain, the write-side intervention is critical because it prevents a future memory-loading step from reactivating the backdoor.

如果此持久性路径保持打开状态，则可以在以后的对话中检索中毒内存并引导代理进行有害行为，例如发出创建拒绝服务循环的命令。If this persistence path were left open, the poisoned memory could be retrieved in a later conversation and steer the agent toward harmful behavior, such as issuing commands that create a denial-of-service loop.特工沃德AgentWard因此将攻击限制在两个时间范围内。当尝试持久化时，认知保护会阻止长期状态损坏，而如果在运行时仍然提出有害操作，执行控制会阻止最终命令模式。这个案例凸显了内存在生命周期安全中的独特作用：内存既是中毒的目标，也是未来妥协的中继点。因此，保护​​它不仅会改变当前的交互，还会改变后续会话的攻击面。therefore constrains the attack at two temporal horizons. Cognition Protection blocks long-lived state corruption when persistence is attempted, while Execution Control blocks the final command pattern if a harmful action is still proposed at runtime. This case highlights the distinctive role of memory in lifecycle security: memory is both a target of poisoning and a relay point for future compromise. Protecting it therefore changes not only the current interaction, but also the attack surface of subsequent sessions.

架构教训是，当威胁持续存在时，仅输入过滤是不够的。生命周期防御既需要专用的认知边界以防止受污染状态变得持久，又需要硬执行边界以在绕过早期防御时遏制有害的重新激活。The architectural lesson is that input filtering alone is insufficient when threats can persist across time. A lifecycle defense requires both a dedicated cognition boundary to prevent contaminated state from becoming durable, and a hard execution boundary to contain harmful reactivation if earlier defenses are bypassed.

V 结论Conclusion

自主代理应作为具有显式运行时控制的端到端系统进行保护。实用的防御架构始于观察到不同的生命周期阶段保护不同的资产，因此需要不同的控制方式。初始化和执行需要确定性的执行。输入、内存和决策阶段受益于语义推理，但前提是相应的保护层将其输出保留为结构化安全状态。Autonomous agents should be secured as end-to-end systems with explicit runtime controls. A practical defense architecture starts from the observation that different lifecycle stages protect different assets and therefore require different control styles. Initialization and execution demand deterministic enforcement. Input, memory, and decision stages benefit from semantic reasoning, but only when the corresponding protection layers preserve their outputs as structured security state.

这是建筑学的核心课程That is the central architectural lesson of特工沃德AgentWard。它的价值在于结合了用于运行时事件的统一适配器层、与生命周期一致的五个保护层、可重用的检测功能以及用于警告、策略标志和干预指令的小型共享控制词汇。如果代理构建者可以将职责映射到这些层，跨阶段保留出处和信任标签，限制持久状态转换，在行动之前验证计划，并在边缘强制执行硬执行边界，那么他们将能够更好地部署有用的代理，而无需假设任何单个模型或护栏都会保存它们。通往值得信赖的自主代理的道路是架构清晰性与协调的生命周期控制相结合。. Its value lies in combining a unified adapter layer for runtime events, five protection layers aligned with the lifecycle, reusable detection capabilities, and a small shared control vocabulary for warnings, policy flags, and intervention directives. If agent builders can map responsibilities to those layers, preserve provenance and trust labels across stages, restrict durable state transitions, validate plans before action, and enforce hard execution boundaries at the edge, they will be better positioned to deploy useful agents without assuming that any single model or guardrail will save them. The path to trustworthy autonomous agents is architectural clarity combined with coordinated lifecycle control.
