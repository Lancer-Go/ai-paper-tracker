1 简介1 Introduction

大型语言模型 (LLM) 代理越来越多地部署在软件工程、研究协助和计算机使用等现实世界任务中。随着这些系统的改进，用户期望他们解决的任务也变得越来越困难：它们涉及更长的视野、更大的有效工作记忆以及大量的探索和回溯。许多这样的任务自然适合分而治之。例如，大型软件变更可以分解为代码调查和编辑子问题；研究任务可以分为检索、综合和验证阶段；长文档或日志语料库可以分为可管理的片段并并行处理。Large language model (LLM) agents are increasingly deployed on real-world tasks such as software engineering, research assistance, and computer use. As these systems improve, the tasks users expect them to solve are also becoming harder: they involve longer horizons, larger effective working memory, and substantial exploration and backtracking. Many such tasks are naturally amenable to divide-and-conquer. For instance, a large software change can be decomposed into code investigation and editing subproblems; a research task can be split into retrieval, synthesis, and verification stages; a long document or log corpus can be partitioned into manageable pieces and processed in parallel.

这引起了人们的兴趣This has led to interest in递归的recursive代理系统（Anthropic，2025；OpenAI，2026；Sun 等人，2025；Zhang 等人，2025），其中代理可以生成子代理来解决具有新上下文的子任务。递归执行有几个优点。agent systems (Anthropic, 2025; OpenAI, 2026; Sun et al., 2025; Zhang et al., 2025), in which an agent can spawn sub-agents to solve subtasks with fresh contexts. 然而，大多数现有的递归和多智能体系统将递归纯粹视为围绕预训练模型的推理时间支架（Prasad 等人，2024 年；Geng 和 Neubig，2026 年；Wu 等人，2023 年）。模型本身通常没有经过训练来决定委托何时有用、如何制定有效的子任务、如何跨执行树级别传达信息或如何将子代理输出组合成最终解决方案。如果递归执行将成为核心测试时原语，那么应该训练策略以很好地使用它。因此，之前的工作表明，在循环中使用推理时间支架的训练模型确实使它们更适合使用推理时间支架进行部署（Wu 等人，2026 年；LM-Provers 等人，2026 年；Kimi Team 等人，2026 年）。这就提出了一个核心问题：However, most existing recursive and multi-agent systems treat recursion purely as an inference-time scaffold wrapped around a pretrained model (Prasad et al., 2024; Geng & Neubig, 2026; Wu et al., 2023). The model itself is typically not trained to decide when delegation is useful, how to formulate effective subtasks, how to communicate information across levels of the execution tree, or how to combine sub-agent outputs into a final solution. If recursive execution is going to be a core test-time primitive, then the policy should be trained to use it well. As such, prior work shows training models with inference-time scaffolds in the loop does make them more amenable to deployment with inference-time scaffolds (Wu et al., 2026; LM-Provers et al., 2026; Kimi Team et al., 2026). This raises a central question:我们应该如何训练模型来有效地利用递归推理？how should we train a model to exploit recursive inference effectively?

2.2 递归代理优化（RAO）2.2 Recursive Agent Optimization (RAO)

根任务的推出会生成一个执行树，其节点对应于同一策略的递归实例化副本。 RAO 联合训练这棵树中的所有节点。在较高层面上，RAO 将每个节点定义的本地奖励与递归生成的执行树上的策略优化相结合。A rollout on a root task produces an execution tree whose nodes correspond to recursively instantiated copies of the same policy. RAO trains all nodes in this tree jointly. At a high level, RAO combines a local reward defined at each node with policy optimization over recursively generated execution trees.

2.2.1 本地节点奖励2.2.1 Local Node Reward

递归代理应该学会解决分配的任务，并在有用时有效地进行委托。理想情况下，我们可以利用节点本地信用分配：子代理应该接收来自其自己分配的任务及其委托的子任务是否成功解决的信号，而不是依赖于根代理的结果级别奖励。这种本地信号可以大大改善分解的信用分配，特别是在训练的早期，当根任务成功可能很少或当初始化的策略尚未有意义地使用委托时。同时，在许多环境中，细粒度的验证不可用或昂贵，因此中间子代理的直接成功信号可能并不总是可观察到的。A recursive agent should learn both to solve its assigned task and, when useful, to delegate productively. Ideally, we can take advantage of node-local credit assignment: a sub-agent should receive signal from whether its own assigned task and its delegated sub-tasks were solved successfully, rather than relying on the root agent’s outcome-level reward. Such local signals can substantially improve credit assignment for decomposition, especially early in training when root-task success may be rare or when the initialized policy does not yet make meaningful use of delegation. 7 结论7 Conclusion

我们引入了递归代理优化 (RAO)，这是一种强化学习方法，用于训练语言模型代理使用递归委托作为学习的推理时间原语。 RAO 不是将固定模型包装在手工设计的递归支架中，而是在动态生成的执行树的所有节点上训练单个共享策略。由此产生的代理不仅学习解决分配的任务，还学习决定何时委托、如何指定有用的子任务、如何协调自身的递归副本以及如何聚合其输出。在三个领域中，RAO 始终如一地解锁了仅从平面单代理执行中难以获得的功能，包括更高的成功率、尽可能利用并行性、泛化到更困难的问题以及解决远远超出模型上下文窗口的任务。We introduced Recursive Agent Optimization (RAO), a reinforcement learning approach for training language-model agents to use recursive delegation as a learned inference-time primitive. Rather than wrapping a fixed model in a hand-designed recursive scaffold, RAO trains a single shared policy across all nodes of a dynamically generated execution tree. The resulting agent learns not only to solve assigned tasks, but also to decide when to delegate, how to specify useful sub-tasks, how to coordinate recursive copies of itself, and how to aggregate their outputs. Across three domains, RAO consistently unlocks capabilities that are difficult to obtain from flat single-agent execution alone, including better success rates, exploiting parallelism where possible, generalization to harder problems, and solving tasks over horizons far beyond the model’s context window.

RAO 还提出了在此处研究的设置之外扩展递归代理的几个直接方向。对于可以通过委托分配计算的代理，评估不应仅局限于最终成功，而是衡量代理使用推理时间计算的效率。虽然 RAO 在递归树的所有节点上训练单个共享模型，但实际系统可能会受益于异构递归，其中更强的模型监督、验证或综合较小的专业子代理的工作，反之亦然。最后，因为我们的实验在每个域内分别训练递归，所以下一步重要的是训练跨域传输委托策略的通用递归代理。这也提出了关于单个递归部署中任务异构性的相关问题：我们的实验主要集中在子任务类似于父任务的较小实例的设置，但许多现实世界的任务需要委派给性质不同的子问题，例如检索、验证、实现、调试或综合。了解哪些环境最能教授分解、协调和长期规划对于构建具有广泛能力的递归代理至关重要，并且需要对超长范围、可并行任务结构、自适应计算分配和多代理协调进行压力测试的基准。RAO also raises several immediate directions for scaling recursive agents beyond the settings studied here. With agents that can allocate computation through delegation, evaluation should move beyond final success alone and measure how efficiently agents use inferencetime compute. While RAO trains a single shared model across all nodes of the recursive tree, practical systems may benefit from heterogeneous recursion, where stronger models supervise, verify, or synthesize the work of smaller specialist sub-agents, or vice-versa. Finally, because our experiments train recursion separately within each domain, an important next step is to train generalist recursive agents that transfer delegation strategies across domains. This also raises a related question about task heterogeneity within a single recursive rollout: our experiments primarily focus on settings where sub-tasks resemble smaller instances of the parent task, but many real-world tasks require delegation to qualitatively different subproblems, such as retrieval, verification, implementation, debugging, or synthesis. Understanding which environments best teach decomposition, coordination, and long-horizon planning will be crucial for building broadly capable recursive agents, and will require benchmarks that stress-test ultra-long horizons, parallelizable task structure, adaptive compute allocation, and multi-agent coordination.

更广泛地说，我们的结果指出了一个简单的原则：More broadly, our results point to a simple principle:推理时间支架不应仅仅围绕模型进行设计；应该训练模型来使用它们。inference-time scaffolds should not merely be designed around models; models should be trained to use them.递归是这一原理的一个实例，但也是一个特别强大的实例：它为代理提供了新的上下文窗口、分而治之的结构、测试时计算的自适应分配以及并行执行的机会。从这个意义上说，递归提供了一条通向自组织代理的道路。与此同时，随着递归方法和更通用的多智能体系统的不断扩展，我们需要解决一个实际的训练问题：当完全递归或多智能体的部署成本太高而无法在 RL 循环内完成时，我们应该如何设计代理采样程序？回答这个问题将需要新的培训支架、适当的数据混合以及从这些替代物转移到具有挑战性的开放式任务的目标。设计此类代理程序是未来工作的一个重要方向，有可能提高性能，同时减少延迟。Recursion is one instance of this principle, but a particularly powerful one: it gives agents fresh context windows, divide-and-conquer structure, adaptive allocation of test-time compute, and opportunities for parallel execution. In this sense, recursion offers a path toward self-organizing agents. At the same time, as recursive methods and more general multi-agent systems continue to scale, we will need to address a practical training question: how should we design surrogate sampling procedures when full recursive or multi-agent rollouts are too costly to complete inside the RL loop? Answering this will require new training scaffolds, appropriate data mixtures, and objectives that transfer from these surrogates to challenging open-ended tasks. Designing such surrogate procedures is an important direction for future work, with the potential to improve performance while reducing latency.

A.1 RAO 什么时候效果最好？A.1 When does RAO work best?

The main experiments in this work are performed on tasks with non-trivial difficulty and/or length (TEXTCRAFT-SYNTH, OOLONG-REAL and DEEPDIVE). On such tasks, RAO helps significantly with many advantages over single agent inference and training, as we discuss in detail in Section 4.

But what about when tasks are both easy and short-horizon?为了在这种情况下测试 RAO，我们使用 ART-E（Corbitt，2025）数据集训练了一种更简单的深度研究变体，其中代理需要搜索用户的电子邮件来回答问题。特别是，与需要大量顺序相关搜索来查找和合成分散在互联网上的信息的 DEEPDIVE 任务不同，ART-E 任务要容易得多，只需要在用户收件箱中查找单个相关电子邮件即可回答问题。But what about when tasks are both easy and short-horizon? To test RAO in this setting, we train on an easier variant of deep research using the ART-E (Corbitt, 2025) dataset, where an agent needs to search over a user’s emails to answer a question. In particular, unlike DEEPDIVE tasks which require numerous sequentially dependent searches to find and synthesize information scattered across the internet, ART-E tasks are much easier, requiring finding only a single relevant email in a user’s inbox to answer the question.

在这种情况下，我们发现 RAO 仍然可以帮助模型在训练的初始步骤中更快地学习，但随后单一代理和递归代理之间的性能达到平衡（图 9）。我们还在表 1b 中的 TEXTCRAFT-SYNTH 中观察到了这一点，其中仅在中等和更高难度的任务中出现显着的性能差距，而不是在简单的任务中。这是直观的：In this setting, we find that RAO still helps the model learn more rapidly in the initial steps of training, but then later the performance equalizes between the single and recursive agents (Fig. 9). This is intuitive:当任务要么足够困难，可以从分而治之中受益，要么足够长，需要扩展上下文窗口时，RAO 的帮助最大。RAO helps the most when tasks are either difficult enough to benefit from divide-and-conquer and/or long-horizon enough to require extended context windows.

A.5 代币使用比较A.5 Token Usage Comparison

在下表中，我们比较了跨不同域对递归代理和单一代理进行基准测试时的令牌使用情况。基于完美缓存读取的假设，缓存读取估计是理想化的。在 OOLONG-REAL 和 DEEPDIVE 等领域，单个代理仅学习简单且短期的策略来解决任务，而递归代理的令牌消耗要高得多，因为递归代理学习更努力的长期策略，以解决更困难的问题。相比之下，在 TEXTCRAFT-SYNTH 上，单个代理和递归代理都学习有效的长期策略来解决任务，与单个代理相比，递归代理实际上最终使用的标记要少得多（特别是当我们增加难度时）。这是因为随着任务范围的增加，单个代理令牌的使用量与轨迹中的步骤数呈二次方缩放，因为每个步骤都需要重新编码以前的历史令牌（尽管其中大部分可以通过 KV 缓存来缓解）；另一方面，递归代理将轨迹分成许多较短的子轨迹，这些子轨迹不需要为执行的每个新代理步骤重新编码较长的历史记录。In the tables below, we compare token usage when benchmarking the recursive and single agents across the different domains. Cache read estimates are idealized, based on an assumption of perfect cache reads. On domains like OOLONG-REAL and DEEPDIVE where the single agent learns only simple and short-horizon strategies for solving the tasks, token consumption is much higher for the recursive agent which learns more effortful and longhorizon strategies that scale to harder problems. In contrast, on TEXTCRAFT-SYNTH where both the single agent and the recursive agent learn effective long-horizon strategies for solving tasks, the recursive agent actually ends up using much fewer tokens compared to the single agent (especially as we increase difficulty). This is because as task horizons increase, single agent token usage scales quadratically with the number of steps in the trajectory, since each step needs to re-encode previous history tokens (although much of this can be alleviated with KV-Caching); on the other hand, the recursive agent splits the trajectory into many shorter sub-trajectories which do not need to re-encode a long history for each new agent step performed.
