ProofCouncil：解决开放数学问题的法学硕士代理ProofCouncil: An LLM Agent for Solving Open Mathematical Problems

Johannes Schmitt1, Tim Gehrunger1, Jasper Dekoninck1, Gergely Bérczi2, Uri Kreitner1, Liam Price3, David Holmes4 1ETH Zurich, 2Aarhus University, 3Independent Researcher, 4Leiden University Correspondence: johannes.schmitt@math.ethz.ch
摘要Abstract

大型语言模型 (LLM) 在解决数学中的开放问题方面显示出越来越大的前景。然而，它们的性能可以通过针对现实世界数学实践量身定制的代理工作流程进一步提高。为此，我们引入了 ProofCouncil，这是一种数学代理，旨在使用作者-评论家架构来解决开放问题。 ProofCouncil 是第二批 FirstProof 的提交作品，这是一项由智能体必须自主解决的 10 个现实世界数学问题组成的挑战。其提交的10道题中，有6道被裁判判定为正确，最多有小修改，显示了参赛队伍中最好的表现。我们还根据数学研究人员收集的 30 个开放问题对 ProofCouncil 进行了评估。在收到人类反馈的 21 个解决方案中，有 5 个被判断为完全正确，另外 2 个被判断为有希望等待最终验证，另外 8 个包含有用的部分进展。在这篇简短的论文中，我们描述了 ProofCouncil 的开发以及用于创建它的代理构建库，我们将其作为开源发布给社区。Large language models (LLMs) have shown increasing promise in solving open problems in mathematics. However, their performance can be further improved through agentic workflows tailored to real-world mathematical practice. To this end, we introduce ProofCouncil, a mathematical agent that is designed to tackle open problems using an author-critic architecture. ProofCouncil served as a submission to the second batch of FirstProof, a challenge consisting of 10 real-world mathematical problems that agents must solve autonomously. Its submissions for 6 of the 10 problems were judged by the referees to be correct up to at most minor revisions, showing the best performance among participating teams. We also evaluate ProofCouncil on 30 open problems collected from mathematical researchers. Among the 21 solutions that received human feedback, 5 were judged completely correct, 2 more were judged promising pending final verification, and a further 8 contained useful partial progress. In this short paper, we describe the development of ProofCouncil and the agent-building library used to create it, which we release as open source to the community.

2.2 作为 DAG 的代理Agents as DAGs

为了创建 ProofCouncil，我们开发了一个开源库，用于将代理系统构建为条件有向无环图 (DAG)。我们在这里简要描述它的主要特点。To create ProofCouncil, we developed an open-source library for constructing agentic systems as conditional directed acyclic graphs (DAGs). We briefly describe its main features here.

有向无环图表示DAG representation

在我们的库中，代理表示为 DAG，其节点可以是 LLM 调用、自定义 Python 块、基于 CLI 的计算代理、确定性门（例如编译检查）或控制流块，边对它们之间的依赖关系进行编码。节点本身可以​​是代理，从而实现模型和工作流的分层组合。例如，LLM 节点由提示模板、模型名称和一组输出等参数定义。提示是在运行时使用上游节点的输出呈现的，并且节点产生的输出又可以用作下游节点的输入。这种抽象支持复杂的信息流，同时保持系统结构的明确。In our library, an agent is represented as a DAG whose nodes can be LLM calls, custom Python blocks, CLI-based compute agents, deterministic gates (such as compilation checks), or control-flow blocks, with edges encoding the dependencies between them. Nodes may themselves be agents, enabling hierarchical compositions of models and workflows. An LLM node, for instance, is defined by parameters such as a prompt template, a model name, and a set of outputs. The prompt is rendered at runtime using the outputs of upstream nodes, and the outputs produced by a node can in turn serve as inputs to downstream nodes. This abstraction supports complex information flow while keeping the structure of the system explicit.

有条件执行Conditional execution

对于许多代理工作流程来说，普通 DAG 的表达能力不够，因为执行的调用集可能取决于中间输出。例如，在 ProofCouncil 中，仅当作者发出相应的标签时才会调用 LLM 委员会。为了支持这种行为，边缘可以配备条件来确定下游节点是否应根据其父节点的输出执行。Plain DAGs are not expressive enough for many agentic workflows because the set of calls to execute may depend on intermediate outputs. For instance, in ProofCouncil, the LLM council is called only when the author emits a corresponding tag. To support this behavior, edges can be equipped with conditions that determine whether a downstream node should execute based on the outputs of its parents.

虽然工作流程在Although the workflow inFig. 1包含从评论家到作者的反馈循环，它可以通过将循环展开固定轮数来表示为条件 DAG。为了提高可读性，该库支持表示循环的有界重复块，从而生成更易于读取和编辑的结构，同时仍作为有限条件 DAG 执行。contains a feedback loop from the critic to the author, it can be represented as a conditional DAG by unrolling the loop for a fixed number of rounds. For readability, the library supports bounded repeat blocks that represent loops, producing a structure that is easier to read and edit while still executing as a finite conditional DAG.

代理执行Agent execution

为了执行代理，库计算 DAG 中节点的拓扑顺序。一旦节点的所有依赖关系完成并且其边缘条件得到满足，节点就会运行。这使得独立节点能够并行执行，从而提高具有多个辅助调用或独立分支的工作流程的效率。To execute an agent, the library computes a topological order of the nodes in the DAG. A node is run as soon as all of its dependencies have completed and its edge conditions are satisfied. This enables independent nodes to execute in parallel, improving efficiency in workflows with multiple auxiliary calls or independent branches.

人机交互工作流程Human-in-the-loop workflows

该库还支持人机交互工作流程：人可以充当 DAG 中的节点，可与任何模型节点互换。当到达这样的节点时，运行暂停，任务显示在用户界面中，并使用提交的答案恢复执行。这使得数学家等能够在运行中审查中间证明或回答作者的问题。The library also supports human-in-the-loop workflows: a human can act as a node in the DAG, interchangeable with any model node. When such a node is reached, the run pauses, the task is presented in the user interface, and execution resumes with the submitted answer. 4 局限性和未来的工作Limitations and Future Work

我们简要讨论了我们工作的一些局限性和未来工作的方向。We briefly discuss several limitations of our work and directions for future work.

成本Cost

运行 ProofCouncil 的成本很高，记录的每个尝试问题的成本超过 200 美元。这一成本主要是由于重复使用前沿模型来进行证明生成和验证，以及调用 LLM 理事会和计算节点等辅助代理。降低这一成本是未来工作的一个重要方向。可能的方法包括改进停止标准或将更简单的子任务路由到更便宜的模型。Running ProofCouncil is expensive, with recorded costs exceeding $200 per attempted problem. This cost is primarily driven by the repeated use of frontier models for both proof generation and verification, as well as by calls to auxiliary agents such as the LLM council and compute node. Reducing this cost is an important direction for future work. Possible approaches include improving stopping criteria or routing simpler subtasks to cheaper models.

人类可读性Human readability

ProofCouncil 的优化主要是为了找到正确的解决方案，而不是为了生成完善的数学证明。几位数学家指出，由此产生的证明非常密集，需要进行扩展才能被相关子领域的非专家阅读。因此，提高可读性是未来工作的另一个重要方向。这可能涉及添加专用的阐述代理，以扩展论点，提供缺失的背景，标准化符号，并将最终解决方案重写为更接近研究论文的形式。ProofCouncil was optimized primarily for finding correct solutions rather than for producing polished mathematical proofs. Improving readability is therefore another important direction for future work. This could involve adding dedicated exposition agents that expand arguments, supply missing background, standardize notation, and rewrite final solutions into a form closer to a research paper.

5 结论Conclusion

在这项工作中，我们引入了 ProofCouncil，一个用于解决开放数学问题的代理系统。 ProofCouncil 在第二批 FirstProof 挑战赛中解决了 10 个问题中的 6 个问题，最多只进行了较小的修改，显示了参赛团队中最好的表现。针对从数学研究人员那里收集的一组单独的开放问题，ProofCouncil 提出了五个完整的解决方案，并在许多其他情况下取得了有意义的部分进展。为了支持进一步的工作，我们发布了 ProofCouncil 和底层开源库，用于将代理系统构建为条件 DAG。In this work, we introduced ProofCouncil, an agentic system for solving open mathematical problems. ProofCouncil solved 6 of the 10 problems in the second batch of the FirstProof challenge up to at most minor revisions, showing the best performance among participating teams. On a separate set of open problems collected from mathematical researchers, ProofCouncil produced five complete solutions and meaningful partial progress in many other cases. To support further work, we release both ProofCouncil and the underlying open-source library for constructing agentic systems as conditional DAGs.
