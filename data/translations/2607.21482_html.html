摘要Abstract

大型语言模型 (LLM) 和代理现在是代码开发中广泛使用的工具，数据通常发送到第三方基于云的模型。它们在使用个人数据的研究中的采用受到治理要求的限制，这些治理要求通常禁止将数据传输到外部服务。本地可部署的开放权重模型提供了一种替代方案，因为敏感数据永远不会离开本地环境。我们引入了一个开源框架，用于评估由开放权重法学硕士支持的人工智能代理在纵向人口研究中最持久的瓶颈之一：数据准备方面的功效。该框架包括：精心策划的地面实况数据集（准备来自英国队列研究的六次数据扫描的清理脚本）、包含类别协调和多波合并等任务的任务定义，以及用于评估法学硕士生成的 R 代码和输出数据的自动化例程。我们对（消费者级）部署范围内的法学硕士进行基准测试，以评估其在 20 个数据准备任务（创建 102 个变量）中的功效。当前最先进的 31-35B 参数模型几乎饱和了我们的基准（“平均任务完成率”高达 87.9%）。在消费级硬件上运行的开放权重法学硕士的性能表明，在受治理限制的研究环境中，有望为人工智能辅助数据准备提供一条可行的途径。我们的框架可在以下位置公开获取：Large language models (LLMs) and agents are now widely used tools in code development, with data typically sent to third-party cloud-based models. Their adoption in research using personal data is constrained by governance requirements that typically prohibit data transmission to external services. Locally deployable open-weight models offer an alternative since sensitive data never leave the local environment. We introduce an open-source framework for evaluating the efficacy of AI agents powered by open-weight LLMs on one of the most persistent bottlenecks in research on longitudinal population studies: data preparation. The framework comprises: a curated ground-truth dataset (cleaning scripts preparing six sweeps of data from a British cohort study), task definitions encompassing tasks such as category harmonization and multi-wave merging, and automated routines for evaluating the LLMproduced R code and outputted data. We benchmark LLMs across the (consumer grade) deployment spectrum to assess their efficacy in 20 data preparation tasks (creation of 102 variables). Current state-of-the-art, 31-35B parameter models almost saturated our benchmark (‗average task completion‘ up to 87.9%). The performance of open-weight LLMs running on consumer-grade hardware shows promise of a viable path toward AI-assisted data preparation in governance-restricted research settings. Our framework is publicly available at:https://github.com/UCL-ARC/RRBench。https://github.com/UCL-ARC/RRBench.

简介Introduction

在定量健康和社会科学中，大量时间花费在重复的数据准备上。查找相关变量、重新编码调查响应、构建综合指数、处理缺失和合并数据集等任务是必要的，但也是劳动密集型的。假设一项研究需要三个月的数据准备，在 1,000 个项目中重复这一过程相当于大约 250 人年的大量重复工作。In quantitative health and social sciences, considerable time is spent on repetitive data preparation. Tasks such as finding relevant variables, recoding survey responses, constructing composite indices, handling missingness, and merging datasets are essential but laborintensive. Assuming a single study requires three months of data preparation, repeating this process across 1,000 projects equates to roughly 250 person-years of largely duplicated effort.1这种累积的负担造成了持续的瓶颈，减缓了将数据转化为科学见解的速度。此外，研究人员经常犯编码错误，导致结果不准确；最近对主要经济学和政治学期刊的一项研究发现，四分之一的评估论文存在编码错误。This cumulative burden creates a persistent bottleneck, slowing the pace at which data can be translated into scientific insight. Moreover, researchers frequently make coding mistakes, leading to inaccurate results; a recent study of major economics and political science journals identified coding errors in a quarter of papers assessed.2

生成人工智能的最新进展为缓解这些挑战提供了一种有希望的方法。大型语言模型 (LLM) 越来越能够解释数据字典、转换原始数据集以及从简单语言指令生成分析代码。Recent advances in generative artificial intelligence offer a promising way to mitigate these challenges. Large language models (LLMs) are increasingly capable of interpreting data dictionaries, transforming raw datasets, and generating analysis code from plain-language instructions.3当嵌入到代理框架中时，这些模型还可以执行并迭代地完善此类代码（有关术语表，请参阅表 1）。然而，法学硕士在调查和行政数据准备中的采用受到严格的数据治理要求的限制。可信研究环境 (TRE) 现在是访问敏感数据（例如电子健康记录）的默认环境，仅允许在安全环境中进行数据管理和分析，并且对互联网的访问受到严格限制。但即使限制较少的数据访问协议，允许数据存储在自己的机器上，通常仍然禁止将个人级别的数据传输到外部云服务，例如前沿法学硕士。When embedded within agentic frameworks, these models can also execute and iteratively refine such code (see Table 1 for a glossary of terms). Yet, the adoption of LLMs in survey and administrative data preparation is constrained by stringent data-governance requirements. Trusted research environments (TREs)—now the default for accessing sensitive data, such as electronic health records—allow data curation and analysis only within a secure environment, with access to the internet heavily restricted. But even less restrictive data-access agreements, allowing data to be stored on one‘s own machine often still prohibit transmitting individual-level data to external cloud services, such as frontier LLMs.4

有多种方法可以将 LLM 与个人级别的数据结合使用，包括： 在本地部署开放权重模型（即数据永远不会离开它们所在的设备）；鼓励法学硕士托管在公共云中，但仅公开元数据或数据集的合成版本；或促使法学硕士托管在经批准的安全云环境或机构服务器中。在这里，我们专注于部署在消费级硬件上的开放权重模型，允许对敏感数据进行人工智能辅助工作流程。然而，虽然此类 LLM 在一般软件工程基准（例如 HumanEval、MBPP、APPS 和 SWE-bench）上表现良好，There are several ways of using LLMs with individual-level data, including: deploying openweight models locally (i.e., data never leave the device they reside on); prompting LLMs hosted in public clouds but only exposing metadata or synthetic versions of datasets; or prompting LLMs hosted in approved secure cloud environments or institutional servers. Here, we focus on open-weight models deployed on consumer-grade hardware, permitting AI-assisted workflows on sensitive data. However, while such LLMs perform well on general software-engineering benchmarks (e.g., HumanEval, MBPP, APPS, and SWE-bench),5–8这些基准为定量（调查）数据准备所需的特定领域能力提供了有限的证据，其中任务包括理解（不完美）标记的元数据、正确构建派生测量（例如，体重指数 [BMI]，单位为 kg/m）these benchmarks provide limited evidence on the domain-specific capabilities required for quantitative (survey) data preparation, where tasks include understanding (imperfectly) labelled metadata, correctly constructing derived measures (e.g., body mass index [BMI] in kg/m2或使用可接受的量表对心理健康进行汇总测量），并协调异构编码系统（例如，协调多次扫描中的就业状况测量）。or summary measures of mental health using accepted scales), and reconciling heterogeneous coding systems (e.g., harmonizing measures of employment status across multiple sweeps).

方法Methods

我们开发了一个开源框架，可在 https://github.com/UCL-ARC/RRBench 上获取，用于系统地评估法学硕士的调查数据准备任务。该框架包括（1）精心策划的地面实况数据集，（2）包含明确数据要求和更一般（“精简”）数据要求的任务定义，以及（3）用于生成、评估和比较法学硕士输出的自动化例程。此设置旨在促进以数据为中心的任务分析中 LLM 功能的基准测试和比较。请参阅图 1 了解视觉概览。We developed an open-source framework, available at https://github.com/UCL-ARC/RRBench, to systematically evaluate LLMs on survey data preparation tasks. The framework comprises (1) a curated ground-truth dataset, (2) task definitions containing explicit data requirements and more general (‗lite‘) data requirements, and (3) automated routines for generating, evaluating, and comparing LLM outputs. This setup is intended to facilitate benchmarking and comparison of LLM capabilities in data-centric task analysis. See Figure 1 for a visual overview.

任务Tasks

基本事实被分为 20 个不同的“任务”，每个任务都包含代理可用的输入和评估性能的预期输出。输入是 (1) 详细说明要创建的变量和一般设计决策的提示（例如变量命名约定），(2) 一组输入数据文件，以及 (3) 原始变量和数据集的元数据（JSON 格式）（例如变量名称和标签以及值标签）。输出是法学硕士编写的 R 脚本以及法学硕士在执行脚本时生成的数据集。此外，每个相应任务的相同输出均由人类研究人员生成（即将原始 Next Steps 数据集转换为 Next Steps Core 数据集和相应数据集的 R 脚本）；这些不适用于法学硕士，但用于基准测试。The ground truth was divided into 20 distinct ‗tasks‘, each of which comprised inputs available to the agent and expected outputs to evaluate performance. The inputs were (1) a prompt detailing the variable(s) to be made and general design decisions (e.g., variable naming conventions), (2) a set of input data files, and (3) metadata (in JSON format) for the raw variables and datasets (e.g., variable names and labels, and value labels). The outputs were an LLM-written R script and a dataset generated by the LLM upon executing the script. In addition, the same outputs for each corresponding task were produced by a human researcher (i.e., R scripts transforming raw Next Steps datasets into the Next Steps Core dataset and the corresponding dataset); these were not available to the LLM but used for benchmarking.

每项任务都包括准备纵向数据分析中常用领域的变量，例如人口、教育、健康和社会经济变量。有些任务需要从多次扫描的信息中推导出单个变量（例如，多次扫描中缺失率最小的性别变量）；其他人则需要创建多个特定年龄的变量（例如，自己和父母的收入、体重指数、心理健康状况）。每项任务都需要了解源元数据（变量名称、标签和值标签）Each task consisted of preparing variables across commonly used domains in longitudinal data analysis such as demographic, education, health, and socioeconomic variables. Some tasks required the derivation of a single variable from information across several sweeps (e.g., a sex variable with minimal missingness across multiple sweeps); others required the creation of multiple age-specific variables (e.g., own and parental income, BMI, mental health). 代理工作流程Agentic Workflow

每项任务均由人工智能代理自主执行。 AI 代理由底层 LLM 提供支持，该 LLM 配置了与任务相关的上下文和一组已定义的可用工具。许多代理框架采用不同的 LLM 交互、输出解析、上下文内存和工具调用编排。Each task was executed autonomously by an AI agent. The AI agent was powered by an underlying LLM that was configured with task-relevant context and a defined set of available tools. Many agentic frameworks employ varying orchestrations of LLM interactions, output parsing, context memory, and tool calling.15我们选择了 Hugging Face 的 SmolAgentsWe opted for Hugging Face's SmolAgents16因为它是轻量级的，并且不需要具有本机工具调用功能的法学硕士。这使得可以使用可以在消费级硬件上运行的较小的开放重量模型。每个任务总共运行 3 次，温度为 0.8。尽管这与编码任务的较低温度的常见建议不同，as it is lightweight and does not require an LLM with native tool-calling capabilities. This enabled the use of smaller open-weight models that could run on consumer-grade hardware. Each task was run a total of three times with a temperature of 0.8. Though this differs from the common recommendation of a lower temperature for coding tasks,17我们观察到，在较低温度下，代理通常会陷入解决其生成的 R 代码中的初始错误的困境。we observed that at lower temperatures, the agent would often remain stuck solving initial bugs in the R code it had produced.

模型评估Model Evaluation

与真实数据集的变量级别比较Variable-level Comparisons with Ground-truth Datasets

为了量化每个模型的表现，我们将给定任务的输出数据集与人类研究人员生成的数据集进行了比较。对于每项任务，我们计算了三个性能指标，然后对各个任务进行平均，以获得模型性能的平衡评估。完整性指标衡量给定任务的 LLM 处理输出中存在的预期变量的比例。正确性度量测量了当逐个单元与相应的真实变量进行比较时，满足预先指定的一致性阈值的恢复变量的比例。如果恢复的变量（真实数据和 LLM 生成的数据集中的变量）的预定部分与真实数据完全匹配，则该变量被认为是正确的；对于分类变量，该分数设置为 95%，以允许变量分类中存在微小差异，例如，缺失值编码或类别分类法在不同扫描中不同，并且必须选择单一统一方案。对于连续变量，标准是标准化均方根误差低于 10 ⁻To quantify how well each model performed, we compared the output dataset from a given task with that produced by a human researcher. For each task, we calculated three measures of performance and then averaged these across tasks to get a balanced evaluation of a model‘s performance. The completeness metric measured the proportion of expected variables that were present in the LLM-processed output for a given task. The correctness metric measured the proportion of the recovered variables that met the prespecified agreement threshold when compared cell by cell with the corresponding ground-truth variable. A recovered variable (a variable in both ground-truth and LLM-generated datasets) was considered correct if a prespecified fraction of its cells exactly matched the ground truth; this fraction was set to 95% for categorical variables to allow for minor differences in variable categorization, e.g., where missing-value coding or category taxonomies differ across sweeps and a single harmonized scheme must be chosen. For continuous variables, the criterion was a normalized root mean squared error below 10 ⁻4（有效地要求精确再现，具有较小的容忍度(effectively requiring exact reproduction, with a small tolerance to

讨论Discussion

我们根据英国纵向队列研究中的 20 项数据准备任务，对完全部署在本地基础设施上的 8 名开放权重法学硕士进行了评估。表现最好的模型 (Gemma 4 31B) 准确地完成了 75% 的任务，正确导出了 102 个变量中的 85.9%。 LLM 的表现通常随着模型参数数量的增加而提高，并因任务类型而异：大多数模型都能可靠地再现训练语料库中具有近乎通用定义的变量（例如，性别、种族、BMI），而需要理解调查特定元数据并结合逻辑上复杂的推导（例如，住房保有权、家庭收入）的任务被证明更加困难，即使在提示中（以自然语言）阐明了推导逻辑。主要的区别在于正确性而不是完整性：“较弱”的模型能够可靠地识别要生成的变量，但容易产生看似合理但不正确的预处理步骤，例如与元数据不一致的重新编码逻辑。在下游回归分析中，表现最好的模型产生的数据集产生与真实情况相同的系数，而较弱的模型产生“无声”错误：看似合理的变量包含数据质量问题，实质上改变了回归估计的幅度。We evaluated eight open-weight LLMs, deployed entirely on local infrastructure, on 20 datapreparation tasks drawn from a British longitudinal cohort study. The best-performing model (Gemma 4 31B) accurately completed 75% of the tasks, with 85.9% of 102 variables being correctly derived. LLM performance generally rose with the number of model parameters and varied by task type: variables with near-universal definitions well represented in training corpora (e.g., sex, ethnicity, BMI) were reliably reproduced by most models, whereas tasks requiring understanding of survey-specific metadata, combined with logically complex derivation (e.g., housing tenure, household income) proved more difficult, even with derivation logic spelled out (in natural language) in the prompt. The principal differentiator was correctness rather than completeness: ‗weaker‘ models reliably identified the variables to produce but were prone to hallucinating plausible yet incorrect preprocessing steps, such as recoding logic that did not align with the metadata. In downstream regression analyses, datasets produced by the bestperforming model yielded coefficients identical to the ground truth, while a weaker model produced ‗silent‘ errors: plausible-looking variables containing data quality issues that materially shifted the magnitude of regression estimates.

我们的结果中的几种模式表明了潜在的局限性，需要进一步调查。在任何一次运行中，任何评估模型都没有完全完成住房保有权，并且涉及复杂的调查特定元数据（例如家庭收入、经济活动）的任务始终被证明是困难的。这些失败有一个共同的特征：它们要求模型不仅要编写语法正确的代码，还要解释复杂的调查元数据，将其与相关的特定领域信息相结合，并将该理解转化为逻辑上复杂的推导序列。虽然 BMI 等变量在训练语料库中具有近乎通用的定义，但住房保有权类别是特定于调查的构造，模型必须完全从提示中提供的元数据中学习。与此一致的是，提示长度与任务成功呈现最强的负相关。提示长度在很大程度上是提示中嵌入的元数据的函数，充当数据复杂性的代理，尽管较差的性能也可能受到长文本降级的影响。Several patterns in our results point to potential limitations that warrant further investigation. Housing tenure was not fully completed by any of the evaluated models in any run, and tasks involving complex survey-specific metadata (e.g., household income, economic activity) proved consistently difficult. These failures share a common feature: they require the model not only to write syntactically correct code but to interpret intricate survey metadata, to combine that with relevant domain-specific information and translate that comprehension into logically complex derivation sequences. While a variable such as BMI has a near-universal definition wellrepresented in training corpora, housing tenure categories are survey-specific constructs that the model must learn entirely from the metadata provided in the prompt. Consistent with this, the prompt length showed the strongest negative association with task success. The prompt length was largely a function of the metadata embedded in the prompt, acting as a proxy for data complexity, although poorer performance may also be influenced by long-text degradation.23,24

最后，法学硕士的表现对即时设计很敏感，我们承认这给研究人员带来了很大的自由度。当我们提供较少的显式推导指令时，性能下降就证明了这一点。虽然我们试图优化提示以最大限度地提高性能，但可行的提示替代方案空间很大，而且我们无法切实测试所有变体。围绕措辞、结构、顺序和提供的明确指导水平的选择都可能会影响模型的性能，并且不同的选择可能会改变结果。进一步复杂化的是促进最佳实践的不断发展的性质，而这又可能因模型而异。因此，我们的研究结果应该被解释为通过合理的激励策略可以实现什么目标的指示，而不是作为一个明确的结果。Finally, LLM performance is sensitive to prompt design, and we acknowledge the substantial researcher degrees of freedom this introduces. This is demonstrated in the drop in performance when we provided fewer explicit derivation instructions. While we sought to optimize our prompts to maximize performance, the space of plausible prompt alternatives is vast, and we could not feasibly test all variants. Choices around phrasing, structure, ordering, and the level of explicit guidance provided can all plausibly affect the model performance, and different choices could have altered the results. Adding further complication is the evolving nature of prompting best practice, which may, in turn, differ by model. 结论Conclusion

完全部署在本地基础设施上的开放式法学硕士可以以有意义的保真度重现人工策划的数据准备脚本，用于纵向人口研究；与人类开发人员或基于云的模型生成的代码一样，仍然建议进行人工代码审查。鉴于其已经很高的性能，优化元数据以帮助 LLM 理解可能会比单独的模型端改进提供更大的性能提升。性能最高的模型仍然仅限于可部署在高端消费级硬件上的模型。这凸显了对计算基础设施的投资需求，以提高这些模型的可访问性。至关重要的是，这种基础设施投资与订阅基于云的 LLM 服务有本质上的不同。在机构硬件上运行的开放权重模型不涉及将敏感数据传输到外部服务，不存在持续的每次查询成本，也不依赖于商业提供商的数据处理策略。对于管理敏感数据的数据持有者或托管这些数据的基础设施（例如 TRE），这些模型可以部署在安全范围内，从而使在最严格的治理框架下工作的研究人员可以使用人工智能辅助的数据准备。Open-weight LLMs deployed entirely on local infrastructure can reproduce human-curated data preparation scripts for longitudinal population studies with meaningful fidelity; as with code generated by human developers or cloud-based models, human code review is still recommended. Given their already high performance, optimizing metadata to aid LLM understanding may offer larger performance gains than model-side improvements alone. The most performant models are still restricted to those deployable on high-end consumer-grade hardware. This highlights a need for investment in computing infrastructure that can improve accessibility to these models. Crucially, this infrastructure investment is qualitatively different from subscribing to cloud-based LLM services; open-weight models running on institutional hardware involve no transmission of sensitive data to external services, no ongoing per-query costs, and no dependency on commercial providers' data handling policies. For data holders managing sensitive data, or infrastructure that hosts them (e.g., TREs), these models could be deployed within secure perimeters, making AI-assisted data preparation available to researchers working under the most restrictive governance frameworks.
