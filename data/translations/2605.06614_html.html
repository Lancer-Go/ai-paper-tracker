附录DAppendix D局限性Limitations

检索机制。Retrieval Mechanism.

我们当前的实现依赖于相对简单的基于关键字的检索机制，例如 BM25，从技能存储库中检索相关技能。这种设计选择使我们能够区分出这项工作的主要焦点：研究如何通过经验驱动的学习来策划、更新和组织技能。然而，更先进的检索方法，例如密集检索、混合检索或学习检索器，可能会进一步提高检索技能的相关性，从而带来更强的下游性能。我们将技能管理和技能检索的联合优化留给未来的工作。Our current implementation relies on a relatively simple keyword-based retrieval mechanism, such as BM25, to retrieve relevant skills from the skill repository. This design choice allows us to isolate the main focus of this work: studying how skills can be curated, updated, and organized through experience-driven learning. However, more advanced retrieval methods, such as dense retrieval, hybrid retrieval, or learned retrievers, may further improve the relevance of retrieved skills and thus lead to stronger downstream performance. We leave the joint optimization of skill curation and skill retrieval to future work.

简化的技能表示。Simplified Skill Representation.

遵循 Anthropic 的技能范式Following Anthropic’s skill paradigm[anthropic_skills_2025]，我们将每个技能实例化为单个 Markdown 文件，该文件结合了 YAML frontmatter 和 Markdown body。这种简化使策展人的操作空间易于处理，但它放弃了原始 SKILL.md 格式的两个可供性：（i）支持脚本和外部资源文件，允许技能封装可执行过程而不是纯粹的声明性知识，以及（ii）分层组织，其中顶级技能可以引用或组合较低级别的子技能。因此，最自然地表达为可运行代码或细粒度原语组合的行为目前必须扁平化为散文。延伸, we instantiate each skill as a single Markdown file that combines a YAML frontmatter and Markdown body. This simplification keeps the curator’s action space tractable, but it discards two affordances of the original SKILL.md format: (i) supporting scripts and external resource files that allow skills to encapsulate executable procedures rather than purely declarative knowledge, and (ii) hierarchical organization in which a top-level skill can reference or compose lower-level sub-skills. As a result, behaviors that are most naturally expressed as runnable code or as compositions of finer-grained primitives must currently be flattened into prose. Extending技能操作系统SkillOS多文件、分层和部分可执行的技能是自然的下一步。to multi-file, hierarchical, and partially executable skills is a natural next step.
