1 简介Introduction

大型语言模型 (LLM) 代理越来越多地读取攻击者可写的内容、综合计划、调用外部工具、委派工作并创建比模型调用更持久的效果。间接提示注入表明，从网页、电子邮件、文档或工具响应检索的数据可以影响代理执行攻击者选择的操作Large language model (LLM) agents increasingly read attacker-writable content, synthesize plans, call external tools, delegate work, and create effects that outlive the model invocation. Indirect prompt injection demonstrates that data retrieved from a web page, email, document, or tool response can influence an agent toward attacker-chosen actions[1, 2, 3]。因此，系统级防御将不受信任的数据与控制分开，限制工具权限，跟踪因果支持或在执行时干预策略. System-level defenses therefore separate untrusted data from control, constrain tool privileges, track causal support, or interpose policy at execution[4, 5, 6, 7, 8].

已部署的代理很少只使用一种控件。典型的路径包含入口验证器、来源服务、内存层、策略网关、协议适配器、工具服务器和最终效果接收器。每个组件可能是局部合理的，而端到端路径是不安全的。考虑一个电子邮件操作，其目标源自不受信任的发票。来源层标记目的地，策略网关需要经过验证的版本。适配器稍后序列化该操作，但删除源绑定、重写逻辑别名或将许可绑定到不同的表示。最终接收器看到有效签名和允许的工具名称，但无法确定具体目的地是否是网关批准的目的地。失败不一定是提示分类或任一端点；它在构图中。A deployed agent rarely uses only one control. A typical path contains an ingress authenticator, provenance service, memory layer, policy gateway, protocol adapter, tool server, and final effect sink. Each component may be locally reasonable while the end-to-end path is insecure. Consider an email action whose destination was derived from an untrusted invoice. A provenance layer labels the destination and a policy gateway requires a validated release. An adapter later serializes the action but drops the source binding, rewrites a logical alias, or binds the permit to a different representation. A final sink sees a valid signature and an allowed tool name, yet cannot determine whether the concrete destination is the one the gateway approved. The failure is not necessarily in prompt classification or in either endpoint; it is in the composition.

Discontinuity has several forms. Cryptographic signatures alone do not prevent these failures. A signature authenticates who emitted an object, not whether the emitter was authorized for that stage or whether its transformation preserved the upstream security contract.

2 背景和动机Background and Motivation

2.1 从迅速妥协到外部后果From prompt compromise to external consequence

当模型输出连接到有效的接口时，立即注入是危险的。 InjecAgent 和 AgentDojo 等基准衡量攻击者控制的观察是否可以重定向使用工具的代理Prompt injection is dangerous when model output is connected to an effectful interface. A model-level compromise and a system-level security failure are related but not identical. The model may propose a forbidden action while a deterministic execution boundary rejects it; conversely, the model may propose an apparently benign action whose parameters are later changed or misinterpreted by an adapter.

因此，我们将三个事件分开：We therefore separate three events:

  1. 1.

    提案proposal：规划者发出一个候选行动；: the planner emits an action candidate;

  2. 2.

    入场admission：安全控制授权规范操作；: a security control authorizes a canonical action;

  3. 3.

    效果effect：接收器在外部世界中进行状态转换。: a sink commits a state transition in the outside world.

我们的主要衡量标准是有害影响的实现，而不是规划者是否生成了提案。假设规划者在每种攻击场景中都受到了损害。Our primary metric is harmful effect realization, not whether the planner generated the proposal. The planner is assumed compromised in every attack scenario.

连续性保证经过身份验证的安全事实和授权决策的连续性，而不是这些事实的真实性。受信任的出处、发布或转换验证器本身可能会产生不正确的结构化结论。在这种情况下，连续性可以忠实地保留并强制执行错误的结论。因此，可信验证器的语义正确性仍然是可信计算基础的一部分，并且与端到端结果完整性正交。CONTINUITY guarantees continuity of authenticated security facts and authorization decisions, not the truth of those facts. A trusted provenance, release, or transformation validator may itself produce an incorrect structured conclusion. In that case, CONTINUITY can faithfully preserve and enforce an incorrect conclusion. Semantic correctness of trusted validators therefore remains part of the trusted computing base and is orthogonal to end-to-end consequence integrity.

上下文清单的完整性。Context-manifest completeness.

验证者重新计算并验证上下文清单摘要。周围的代理运行时必须确保此清单涵盖向规划器显示的所有字节和工具输出。该原型不会检测生产模型运行时或证明其上下文捕获的完整性。默默地公开其他攻击者控制的内容的运行时违反了这一假设。The verifier recomputes and authenticates the context-manifest digest. The surrounding agent runtime must ensure that this manifest covers all bytes and tool outputs shown to the planner. The prototype does not instrument a production model runtime or prove completeness of its context capture. A runtime that silently exposes additional attacker-controlled content violates the assumption.

受限制的转换语言。Restricted transformation language.

该实现评估一个安全相关关系、别名解析和一个小型确定性谓词注册表。实际部署需要更丰富的版本化语义来进行货币转换、模式映射、标识符解析、聚合和解密。通用关系语言带来了自己的健全性、可判定性和政策审查挑战。The implementation evaluates one security-relevant relation, alias resolution, and a small deterministic predicate registry. Real deployments need richer, versioned semantics for currency conversion, schema mapping, identifier resolution, aggregation, and declassification. General-purpose relation languages create their own soundness, decidability, and policy-review challenges.

没有经过验证的实施。No verified implementation.

证明适用于抽象模型和条件。 Python 工件经过了广泛的回归测试，但没有经过机械验证、恒定时间、强化或正式显示以改进模型。其确定性 JSON 编码器受到有意限制，应在可互操作部署中由符合标准的规范化器取代。The proofs apply to the abstract model and conditions. The Python artifact is extensively regression-tested but not mechanically verified, constant-time, hardened, or formally shown to refine the model. Its deterministic JSON encoder is intentionally restricted and should be replaced by a standards-conformant canonicalizer in interoperable deployments.

综合一致性基准。Synthetic conformance benchmark.

该套件包含 32 个设计的故障模板、四个域和确定性参数变化。它对于伪造缺失的不变量和验证工件很有用，但它既不详尽，也不是从真实的攻击群体中采样的。 0/2,560 结果不得被解释为估计的通用故障概率。它也不比较模型质量，因为没有调用 LLM。The suite contains 32 designed fault templates, four domains, and deterministic parameter variations. It is useful for falsifying missing invariants and validating the artifact, but it is neither exhaustive nor sampled from a real attack population. The 0/2,560 result must not be interpreted as an estimated universal failure probability. It also does not compare model quality because no LLM is invoked.

简化的提供者语义。Simplified provider semantics.

最终性世界、随机数账本和幂等性存储都是内存中的和原子的。真正的提供者表现出并发性、重试、最终一致性、非幂等副作用和部分失败。生产需要特定于提供商的交易协议和持久证据。The finality world, nonce ledger, and idempotency store are in-memory and atomic. Real providers exhibit concurrency, retries, eventual consistency, non-idempotent side effects, and partial failures. Provider-specific transaction protocols and durable evidence are required for production.

信息流覆盖不完整。Incomplete information-flow coverage.

系统检查声明的受保护区域和效果。它不会消除隐蔽通道，推断每个语义上等效的效果路径，或通过允许的文本输出、计时、聚合查询、资源名称或恶意下游提供者行为来防止泄漏。完整的调解是一项工程和治理义务。The system checks declared protected fields and effects. It does not eliminate covert channels, infer every semantically equivalent effect path, or prevent leakage through allowed textual output, timing, aggregate queries, resource names, or malicious downstream provider behavior. Complete mediation is an engineering and governance obligation.

人为和语义错误。Human and semantic error.

有效的用户授权可能会授权不明智的操作。人类可以批准误导性的请求，而可信的工具可以返回错误的数据。A valid user grant may authorize an ill-advised action. A human can approve a misleading request, and a trusted tool can return false data.连续性Continuity保留授权上下文；它不保证授权的目标是明智的、合法的或语义上正确的。preserves authorization context; it does not guarantee that the authorized goal is wise, legal, or semantically correct.

神器整合。Artifact integration.

参考管道对内存、策略、适配器和最终边界进行建模，但不是生产 MCP、A2A、OWASP ACS、云 IAM 或区块链集成。这些绑定需要单独的协议配置文件和互操作性测试。The reference pipeline models memory, policy, adapter, and finality boundaries but is not a production MCP, A2A, OWASP ACS, cloud-IAM, or blockchain integration. Those bindings require separate protocol profiles and interoperability testing.

13 结论Conclusion

代理安全控制不会自动组合。出处标签、策略决策、功能或操作绑定许可可能是本地正确的，但当相邻组件放弃其假设、更改不同模式下的操作、接受未经授权的签名者或在陈旧状态下提交效果时，可能会失败。我们将这个问题形式化为安全上下文不连续性并定义了端到端结果完整性。Agent security controls do not compose automatically. A provenance label, policy decision, capability, or action-bound permit can be locally correct yet fail when a neighboring component drops its assumptions, changes the action under a different schema, accepts an unauthorized signer, or commits an effect under stale state. We formalized this problem as security-context discontinuity and defined end-to-end consequence integrity.

连续性Continuity演示具体响应：验证 root 授权；将每个阶段绑定到授权身份和合同；解决叶路径的来源； make 释放源绑定、值绑定、谓词绑定、任务绑定和到期绑定；要求独立检查的关系证人进行合法转换；并在最终确定时重新验证主题、操作、策略、撤销和重播状态。在确定性工件中，这些检查包含所有 128 个建模故障域类，同时保留良性执行和显式升级。demonstrates a concrete response: authenticate the root grant; bind each stage to an authorized identity and contract; resolve provenance at leaf paths; make releases source-, value-, predicate-, task-, and expiry-bound; require independently checked relation witnesses for legitimate transformations; and revalidate subject, action, policy, revocation, and replay state at finality. In the deterministic artifact, these checks contain all 128 modeled fault–domain classes while preserving benign execution and explicit escalation.

更广泛的教训是架构性的：规划可能仍然是概率性和对抗性的，但外部后果应该由一个小的、确定性的、带有证据的控制平面来调节，其保证从指令上下文到实现的效果保持连续。The broader lesson is architectural: planning may remain probabilistic and adversarial, but external consequence should be mediated by a small, deterministic, proof-carrying control plane whose guarantees remain continuous from instruction context to realized effect.
