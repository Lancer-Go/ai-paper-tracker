差异、任务顺序和规格不足Variance, Task Order, and Underspecification

摘要Abstract

基于记忆的自我改进代理——那些从在线任务流中学习并通过维护文本记忆库随着时间的推移而改进的代理——在最近的文献中显示出了巨大的前景。然而，这些方法的可靠性方面却被严重忽视。 在这项工作中，我们对两种基于记忆的方法进行了全面的重新评估，沿着两个轴拓宽了评估范围：（1）包括多次运行以量化Memory-based self-improving agents—those that learn from an online stream of tasks and improve over time by maintaining a textual memory bank—have shown great promise in recent literature. However, the reliability aspects of these methods have been critically overlooked. In this work, we conduct a comprehensive re-evaluation of two memory-based methods, broadening the scope of evaluation along two axes: (1) including multiple runs to quantify方差variance，以及（2）随机洗牌任务以研究效果, and (2) randomly shuffling the tasks to investigate the effect of任务顺序task order。通过这些实验，我们做了两个观察，暴露了当前方法的脆弱性： 首先，代理评估在复杂环境和多步骤任务中本质上是有噪声的，而在顶部堆叠自我改进循环可以进一步放大这种噪声。根据经验，当应用这些方法时，我们观察到 71% 的情况下运行的方差会增加，并且同一实验的最佳运行和最差运行之间的差距可达 10 个百分点。 其次，智能体的改进高度依赖于任务顺序。之前的作品经常采用默认的顺序，强加隐含的课程，作为成功的隐藏先决条件。相比之下，当在随机打乱的任务顺序下进行评估时，代理性能会下降 (-4.5%)，而不是表现出预期的改进 (+1.5%)。. Through these experiments, we make two observations that expose the fragility of current methods: First, agent evaluation is inherently noisy in complex environments and on multi-step tasks, and stacking a self-improving loop on top can further amplify this noise. Empirically, when these methods are applied, we observe the variance across runs increase in 71% of cases, and the gap between the best and worst runs of the same experiment can reach up to 10 percentage points. In contrast, when evaluated under a randomly shuffled task order, agent performance degrades (-4.5%) instead of exhibiting the expected improvement (+1.5%).

1 简介Introduction

自我完善剂的开发The development of self-improving agents[42, 56, 19]——旨在从过去的经验中学习并随着时间的推移自主改进其性能的系统——已成为一个非常有前途的研究方向。如果他们意识到这一潜力，他们不仅可以更好地自动化日常工作流程并产生重大的经济影响，而且还可以实现高度适应性的系统并促进开放式研究发现。虽然最近的工作表明在这个方向上取得了进展—systems designed to learn from past experiences and autonomously refine their performance over time—has emerged as a highly promising research direction. If they realize this potential, they could not only better automate routine workflows and create significant economic impact, but also enable highly adaptable systems and facilitate open-ended research discovery. While recent works show progress in this direction[66, 18, 64, 12, 35, 61]，很少有人关注对此类系统的可靠性进行压力测试, little focus has been placed on stress-testing the reliability of such systems[40]。 在实际设置中，例如企业部署，通常对错误的容忍度很小；最初的失败可能会失去用户的信任。 此外，从长远来看，最初的错误可能会悄无声息地蔓延，如果在高风险领域采用，会造成不可逆转或代价高昂的影响。 在我们能够自信地部署这些系统之前，我们必须严格评估它们在现实、充满挑战的条件下的可靠性。. In practical settings, such as enterprise deployments, there is often minimal tolerance for error; an initial failure risks losing user trust. Moreover, initial mistakes can cascade silently over the long term, causing irreversible or prohibitively costly impacts if adopted in high-stakes domains. Before we can confidently deploy these systems, we must critically evaluate their reliability under realistic, challenging conditions.

这项工作首先对两个具有代表性的基于记忆的自我改进系统进行全面的重新评估——Agent Workflow MemoryThis work begins with a comprehensive re-evaluation of two representative memory-based self-improving systems—Agent Workflow Memory[51]和推理银行and ReasoningBank[36]—跨越三个现实的网络浏览基准：WebArena—across three realistic web-browsing benchmarks: WebArena[63], 视觉网络竞技场, VisualWebArena[27]和水肺潜水, and SCUBA[8]。在本次评估中，我们通过升级底层语言模型和代理工具来建立更强大的基线。此外，我们沿着两个轴扩大了评估范围：对相同的实验设置进行多次运行以量化方差，并随机调整任务以研究任务顺序的影响。通过这次扩展的重新评估，我们发现了两个关键的可靠性问题。. In this evaluation, we establish a stronger baseline by upgrading both the underlying language model and the agent harness. Furthermore, we broaden the scope of evaluation along two axes: conducting multiple runs of the same experimental setting to quantify variance, and randomly shuffling the tasks to investigate the effect of task order. Through this extended re-evaluation, we identify two critical reliability issues.

首先，我们表明运行之间的方差可能相当大，这一观察结果很大程度上隐藏在先前的工作中，因为网络代理评估通常仅报告单次运行结果。 我们表明，无记忆基线代理在多次运行中已经表现出显着的差异，并且结合自我改进程序可以进一步放大这种差异。 例如，在 WebArena GitLab 子集（包含 180 个任务）上，最佳和最差基线运行之间的绝对性能差距为 4.4%，而应用 ReasoningBank 将这一差距扩大到 7.8%。这些观察结果使单次评估实践的可靠性受到质疑。First, we show that the variance across runs can be concerningly large, an observation largely hidden in prior works, as web agent evaluations typically report only single-run results. We show that the no-memory baseline agent already exhibits significant variance across multiple runs, and that incorporating a self-improving procedure can further amplify this variance. For example, on the WebArena GitLab subset (comprising 180 tasks), the absolute performance gap between the best and worst baseline runs is 4.4%, whereas applying ReasoningBank enlarges this gap to 7.8%. These observations call the reliability of single-run evaluation practices into question.

其次，我们证明智能体的改进对任务顺序高度敏感。 先前作品中的默认任务顺序强加了隐含的、由易到难的课程，这是这些自我改进方法成功的隐性先决条件。 在默认订单下，使用 ReasoningBank 的代理实现了 1.5% 的平均性能增益；然而，当在随机打乱的任务顺序下进行评估时，代理表现出 4.5% 的性能下降。 这种依赖性带来了一个紧迫的问题，因为现实世界的应用程序无法假设用户请求的有序流。Second, we demonstrate that agent improvement is highly sensitive to task order. The default task order in prior works imposes an implicit, easy-to-hard curriculum, which acts as a hidden prerequisite for these self-improving methods to succeed. Under the default order, the agent using ReasoningBank achieves an average performance gain of 1.5%; however, when evaluated under randomly shuffled task orders, the agent exhibits a performance degradation of 4.5%. This dependency introduces a pressing concern, as real-world applications cannot assume a neatly ordered stream of user requests.

为了更好地理解这种脆弱性，我们手动调查智能体写入的记忆，并识别记忆生成过程中环境和任务的不规范，作为大方差和性能下降的潜在驱动因素。 例如，当内存构建模型不知道环境是仅限浏览器且不支持代码执行时，它会生成使用 API 的建议，这是一种看似合理但无法执行的策略。 关于任务指定不足，我们表明，模糊的任务查询可能会引起误解、过度思考以及传播到后续任务的错误记忆的构建。To better understand this fragility, we manually investigate the memories written by the agents, and identify environment and task underspecification during memory generation as potential drivers for the large variance and degraded performance. For example, when the memory construction model is unaware that the environment is browser-only and does not support code execution, it generates suggestions to use APIs—a strategy that is plausible but unexecutable. Regarding task underspecification, we show that ambiguous task queries can give rise to misunderstanding, overthinking, and the construction of erroneous memories that propagate to subsequent tasks.

为了缓解这些问题，我们考虑将额外的上下文（例如环境反馈和任务规则）合并到内存构建步骤中，并使用更清晰的环境规范进一步修改提示。这些干预措施消除了在打乱的任务顺序设置中观察到的 31% 的性能下降。虽然这证明了此类附加信息的实用性，但剩余的性能差距表明其他未表征的因素导致了这种脆弱性，凸显了未来工作的必要性，以确保自我改进代理的可靠性。To mitigate these issues, we consider incorporating additional context—such as environment feedback and task rubrics—into the memory construction step, and we further revise the prompt with clearer environment specifications. These interventions close 31% of the performance degradation observed in the shuffled task order settings. While this demonstrates the utility of such additional information, the remaining performance gap suggests that other uncharacterized factors contribute to this fragility, highlighting the need for future work to ensure the reliability of self-improving agents.

除了这些实证结果之外，我们的工作还需要研究自我改进人工智能系统的严格评估方法，并且我们在这个方向上提供了实用的建议。此外，我们对规范不足的分析促进了有效的人为干预界面的开发，可以及时识别和纠正这些代理学到的“错误教训”。Beyond these empirical results, our work calls for research into rigorous evaluation methodologies for self-improving AI systems, and we provide practical recommendations in this direction. Furthermore, our analysis of underspecification motivates the development of effective human intervention interfaces, where the “wrong lessons” learned by these agents can be identified and corrected timely.

6 结论Conclusion

在这项工作中，我们对两种已建立的基于记忆的智能体自我改进方法进行了全面的重新评估，沿着两个轴（多次运行和打乱任务顺序）扩大了评估范围，同时使用基础模型和智能体利用的更强组合作为基线（In this work, we conducted a comprehensive re-evaluation of two established memory-based methods for agent self-improvement, broadening the scope of evaluation along two axes (multiple runs and shuffled task orders) while using a stronger combination of base model and agent harness as the baseline (即i.e.，自我提升的起点）。 总的来说，我们的结果揭示了这些自我改进系统在更具挑战性的环境下的脆弱性：自我改进实验的结果可能表现出显着的差异，这意味着基于单次运行的评估可能会阻碍对进度的准确测量。 此外，在基线已经很强或任务以随机顺序到达的挑战性环境中，智能体不会自我改进，而是会退化。, the starting point for self-improvement). Overall, our results reveal the fragility of these self-improving systems under more challenging settings: the results of self-improving experiments can exhibit significant variance, meaning that evaluation based on a single run can hinder accurate measurement of progress. Furthermore, agents do not self-improve, but instead degrade, in challenging settings where the baseline is already strong or when tasks arrive in a random order.

鉴于这些令人惊讶的发现，我们进一步手动检查智能体的记忆，并将环境和任务指定不足视为现有方法的关键限制，并通过详细的案例研究和分析来支持这一点。我们通过合并额外的信息来解决这个限制，这些信息为内存生成模块提供了更好的规范。通过这样做，之前实验中观察到的性能下降减少了 31%，这证明了有希望的进展。然而，剩下的 69% 的性能差距表明，为了完全克服这种脆弱性，仍然有一些根本问题有待发现和解决。Given these surprising findings, we further manually examine the agents’ memory and identify environment and task underspecification as a key limitation in existing approaches, supporting this with detailed case studies and analyses. We address this limitation by incorporating additional information that provides better specification to the memory generation module. By doing so, the performance degradation observed in prior experiments is reduced by 31%, demonstrating promising progress. However, the remaining 69% performance gap suggests that there are still fundamental issues to be uncovered and resolved to fully overcome this fragility.

除了这些实证观察之外，我们的研究结果还为使用自我改进代理系统的研究人员和从业者提供了实用的建议。Beyond these empirical observations, our findings offer practical recommendations for researchers and practitioners working with self-improving agentic systems.

评估建议。Recommendations for Evaluation.我们的工作主张采用更严格的评估方案来解释本研究中讨论的稳定性问题。具体来说，应谨慎解释单次运行的结果；相反，应该高度鼓励报告多次运行和随机任务顺序的结果。此外，我们建议首先在具有明确指定任务的基准上试用新方法，然后对未指定的任务进行压力测试，以在部署之前估计最坏情况的性能。Our work advocates for more rigorous evaluation protocols that account for the stability issues discussed in this study. Specifically, results from a single run should be interpreted with caution; instead, reporting outcomes across multiple runs and randomized task orders should be highly encouraged. Furthermore, we recommend first piloting new methods on benchmarks with well-specified tasks, followed by stress-testing them on underspecified tasks to estimate worst-case performance prior to deployment.

系统开发建议。Recommendations for System Development.我们的分析表明，如果没有适当的验证机制，代理记忆只是未经验证的假设，而不是真正的经验教训。它们可能是错误的，更重要的是，随着时间的推移，它们会对后续任务产生负面影响。未来的工作应该研究记忆验证机制，过滤掉有问题的记忆，以确保长期的稳健性。 此外，如§所示Our analysis reveals that without proper validation mechanisms, agent memories are merely unverified hypotheses rather than true lessons learned. They can be erroneous and, more importantly, cascade negatively into subsequent tasks over time. Future work should investigate memory validation mechanisms that filter out problematic memories to ensure long-term robustness. Additionally, as demonstrated in §4.1、任务和环境规范是一个微妙的挑战。由于规格不足无法完全预见，并且现实世界的部署是作为单一、不可逆的运行展开的，因此通过迭代过程完善规格代表了一条可行的前进道路。因此，我们的研究结果推动了界面的开发，在代理无意失败之前实现有效的人类监督和及时干预。, task and environment specification is a nuanced challenge. Because underspecification cannot be fully foreseen, and real-world deployments unfold as a single, irreversible run, refining specifications through an iterative process represents one viable path forward. Consequently, our findings motivate the development of interfaces that enable effective human oversight and timely intervention before agents fail unintentionally.
