摘要Abstract

This decomposition scales to traces of arbitrary length and produces span-level rationales for each verdict. 1 简介Introduction

人工智能代理越来越多地部署在生产中，为客户助理、开发人员工具和代表用户采取实际行动的自动化工作流程提供支持。随着自主权的增强，失败的后果也会随之增加：错误的输出、浪费的工具预算、有害的副作用以及用户信任的削弱。因此，可靠的评估至关重要，既可以在部署之前捕获故障，也可以诊断代理出错的位置和原因，以便进行改进。代理执行是通过跟踪基础设施捕获的，例如开放式遥测AI agents are increasingly deployed in production, powering customer assistants, developer tools, and automated workflows that take real actions on behalf of users. As autonomy grows, so do the consequences of failure: incorrect outputs, wasted tool budgets, harmful side-effects, and eroded user trust. Reliable evaluation is therefore essential, both for catching failures before deployment and for diagnosing where and why an agent went wrong so it can be improved. Top-down evaluation assesses agent-level metrics such as planning quality and tool coverage by analyzing an agent’s descendants; bottom-up evaluation inspects individual spans (e.g. LLM calls, tool invocations) to localize failures and categorize their causes. Trace-level assessments complement these by capturing behavioral patterns such as redundant calls, plan deviation, and incomplete coverage, which emerge only across spans.

3 整体代理评估Holistic Agent Evaluation

通过将基础设施跟踪为分层结构来捕获代理执行情况Agent execution is captured by tracing infrastructure as a hierarchical痕迹trace of 跨度spans，其中跨度结构取决于仪器而不仅仅是代理本身。在这种结构中，代理系统表现出多个级别的故障：各个跨度可以独立发生故障，而紧急故障可能无法归因于任何单个组件。我们的方法论结合了, where span structure depends on the instrumentation rather than only on the agent itself. Within this structure, agentic systems exhibit failures at multiple levels: individual spans can fail independently, while emergent failures may not be attributable to any single component. Our methodology combines自下而上的评估bottom-up evaluation，它计算叶跨度的度量并向上传播判决，其中, which computes metrics at leaf spans and propagates verdicts upward, with自上而下的评估top-down evaluation，它评估后代的代理级别模式。单独使用这两种方法都不够：自下而上的评估精确定位组件级故障，但忽略了整体低效率，而自上而下的评估捕获了系统范围的模式，但为根本原因定位提供了有限的粒度。, which assesses agent-level patterns across descendants. Neither approach alone suffices: bottom-up evaluation pinpoints component-level failures but misses holistic inefficiencies, while top-down evaluation captures system-wide patterns but offers limited granularity for root cause localization.
