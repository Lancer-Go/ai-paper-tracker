2.3 协议Protocol

探索在任何地方都是一样的。代理在一台 B300 的存储库内工作了四个小时， 免费阅读、编辑它、启动自己的训练运行以及查阅快速代理指标，而无需 限制。当四个小时结束时，它会停止，留下的代码就是提交。什么都没有 else 向前交叉：没有训练的权重，没有缓存的状态，没有自身的注释——只有源。Exploration is the same everywhere. For four hours the agent works inside the repository on one B300, free to read it, edit it, launch training runs of its own, and consult the fast proxy metric without limit. When the four hours are up it stops, and the code it leaves behind is the submission. Nothing else crosses forward: no weights it trained, no cached state, no notes to itself — only the source.

接下来发生的事情取决于任务。对于训练的八个任务，提交的源是从执行的 初始化直至终止或十二小时过去（以先到者为准）；最近的三个 然后对检查点进行评分，单元在任务的指导下选择最好的检查点。对于 两个不训练的代码，只需执行一次即可生成其模型 - 一个 平均模型，修剪模型——直接评分；在那里，十二个小时只是一个上限 在验证阶段，没有花费培训预算。What happens next depends on the task. For the two that do not train, the submitted code is simply executed once to produce its model — an averaged model, a pruned model — which is scored directly; there the twelve hours are only a ceiling on the verification stage, not a training budget being spent.

2.4 基线Baselines

将更改称为改进需要将其与某些东西进行比较，而这种比较 纸质报告故意是最严格的可用报告：存储库自己的算法，给定 正是代理人所给予的。对于训练任务，基线是存储库的提交 在相同的程序和相同的 12 小时预算下执行的代码，并通过相同的测量 同一资产的固定评估者。对于不训练的两个任务，这是存储库的配方 按原样执行，以同样的方式得分。在这两种情况下，基线和基线之间的唯一区别 提交的是源代码本身——相同的硬件、相同的预算、相同的评估者、相同的资产—— 这就是使胜利归因于代理所做的改变而不是其资源的原因 被给予。Calling a change an improvement requires something to compare it against, and the comparison this paper reports is deliberately the strictest one available: the repository’s own algorithm, given exactly what the agent was given. For a task that trains, the baseline is the repository’s committed code executed under the identical procedure and the same twelve-hour budget, and measured by the same fixed evaluator on the same asset. For the two tasks that do not train, it is the repository’s recipe executed as it stands, scored the same way. In both cases the only difference between the baseline and a submission is the source code itself — same hardware, same budget, same evaluator, same asset — which is what makes a win attributable to the change the agent made rather than to the resources it was given.

这是一个比看起来更难的标准，并且与相邻基准测试使用的标准不同。它 不是已发布的数字，因此不可能根据与我们不同的评估进行调整；它不是 官方指令调整版本，因此击败它并不是组装比 作者有；而且这不是人类专家的尝试，因此它没有声称人类的表现在哪里 谎言。这只是一个问题的答案：代理的代码是否能生成比代理代码更好的模型？ 已经存在的代码，在相同的条件下运行吗？This is a harder bar than it may look, and a different one from what neighbouring benchmarks use. It is not a published number, so it cannot have been tuned on a different evaluation than ours; it is not an official instruction-tuned release, so beating it is not a matter of assembling more data than the authors had; and it is not a human expert attempt, so it makes no claim about where human performance lies. It is the answer to one question only: does the agent’s code produce a better model than the code that was already there, run under identical conditions?

每项任务都会冻结一个研究存储库并要求同一件事：改进培训 存储库应用于其自己的模型的算法。它们之间的区别在于算法 给代理的资产，以及评估边界两侧的一对指标——一个便宜的 它可以在四小时内任意查询，并且决定其结果， 随后由它从未见过的评估者计算。两者在不同方面有不同的联系 任务，并且在阅读专栏时关系很重要：在某些情况下，代理是最终结果的子样本 协议，对于其他协议，它是完全不同的基准。Each task freezes one research repository and asks for the same thing: improve the training algorithm that repository applies to its own model.
