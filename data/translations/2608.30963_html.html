用于跨模型 KV 共享的通用上下文重用层A Universal Context-Reuse Layer for Cross-Model KV Sharing

Yi Li    Dongming Jiang    Yi Zhao    Bingzhe Li Affiliation: University of Texas at Dallas
摘要Abstract

现代大语言模型 (LLM) 服务系统越来越多地在重复或共享上下文上运行，但每个模型通常都会执行自己的预填充计算，即使另一个模型已经处理了相同的输入。现有的 KV 缓存重用机制大大减少了单个模型内的冗余计算，但通常假设缓存的生产者和消费者是相同的。我们学习Modern large language model (LLM) serving systems increasingly operate over repeated or shared context, yet each model typically performs its own prefill computation even when another model has already processed the same input. Existing KV-cache reuse mechanisms substantially reduce redundant computation within a single model, but generally assume that the producer and consumer of a cache are identical. We study跨模型KV共享cross-model KV sharing，它将源模型生成的 KV 状态转换为可由不同目标模型使用的表示，包括规模、架构、注意力配置、分词器和模型系列不同的模型。我们在家庭内部和跨家庭环境中评估该方法。适用于Qwen2.5-7B, which translates the KV state produced by a source model into a representation that can be consumed by a different target model, including models that differ in scale, architecture, attention configuration, tokenizer, and model family. We evaluate the approach in both within-family and cross-family settings. 1 简介Introduction

大语言模型（LLM）Large language model (LLM)[1, 2, 3]推理日益成为一个系统问题，涉及的不是一个模型，而是同一应用程序中协作的一组模型。现代人工智能服务越来越多地在单个应用程序中包含多个法学硕士。例如，模型路由和级联系统在具有不同功能成本配置文件的模型之间动态选择，通常将更容易的请求发送到较小的模型，并将更困难的请求升级到更强的模型inference is increasingly becoming a systems problem involving not one model, but a collection of models that cooperate within the same application. Modern AI services increasingly compose multiple LLMs within a single application. For example, model-routing and cascading systems dynamically select among models with different capability–cost profiles, often sending easier requests to smaller models and escalating more difficult requests to stronger models[4, 5]。其他系统结合了不同任务的专用模型或协调多个基于 LLM 的代理，这些代理通过共享任务状态、对话历史记录或检索的信息进行通信和操作. Other systems combine specialized models for different tasks or coordinate multiple LLM-based agents that communicate and operate over shared task state, conversation history, or retrieved information[6, 7]。这种异构性很有吸引力，因为可用的模型在准确性、延迟、推理成本、任务专业化和部署约束方面表现出不同的权衡。. Such heterogeneity is attractive because available models exhibit different tradeoffs in accuracy, latency, inference cost, task specialization, and deployment constraints.

然而，当前的推理基础设施并没有有效地利用这些异构模型通常在相同的底层上下文上运行的事实。当调用新模型时，它通常会独立处理输入标记，即使另一个模型已经处理了完全相同的对话历史记录、文档集合或用户提示。因此，相同的语义内容可能会被重复地转换为特定于模型的内部表示。However, current inference infrastructure does not efficiently exploit the fact that these heterogeneous models often operate over the same underlying context. When a new model is invoked, it normally processes the input tokens independently, even if another model has already processed exactly the same conversation history, document collection, or user prompt. As a result, the same semantic content may be repeatedly transformed into model-specific internal representations.

这种冗余在This redundancy is particularly important during the预填充prefillLLM推理阶段。在预填充期间，模型通过其转换器层处理所有输入标记，并构建注意力机制所需的键值 (KV) 状态。对于长提示，此过程可能涉及大量 GPU 计算、内存流量以及生成第一个输出令牌之前的延迟。一旦计算出 KV 状态，后续解码就可以有效地重用它们。stage of LLM inference. During prefill, the model processes all input tokens through its transformer layers and constructs the key-value (KV) states required by the attention mechanism. For a long prompt, this process can involve substantial GPU computation, memory traffic, and latency before the first output token is generated. Once the KV states have been computed, subsequent decoding can reuse them efficiently.

现有的 KV 缓存和前缀缓存系统已经在单个模型中利用了这一观察结果。如果同一模型遇到已经处理过的前缀，系统可以检索其现有的 KV 缓存，而不是重新计算前缀。这种优化已成为现代法学硕士服务基础设施的重要组成部分。Existing KV caching and prefix-caching systems already exploit this observation within a single model. If the same model encounters a prefix that has already been processed, the system can retrieve its existing KV cache rather than recomputing the prefix. This optimization has become an important component of modern LLM serving infrastructure.

局限性在于 KV 状态通常被视为特定于模型的对象。一个模型生成的 KV 缓存通常无法被另一模型使用，因为这些模型可能具有不同的隐藏表示、注意力配置、层数、分词器和架构参数。The limitation is that KV states are conventionally treated as model-specific objects. A KV cache generated by one model is generally unusable by another model because the models may have different hidden representations, attention configurations, numbers of layers, tokenizers, and architectural parameters.

本文研究了更广泛的重用形式：This paper investigates a broader form of reuse:跨模型KV共享cross-model KV sharing。中心思想是将一个模型生成的 KV 表示转换为可以被另一个模型使用的表示。源模型和目标模型可以是同一系列内不同大小的变体，或者更一般地，属于完全不同的体系结构系列的模型。. The central idea is to translate the KV representation generated by one model into a representation that can be consumed by another model. The source and target models may be different-sized variants within the same family or, more generally, models belonging to entirely different architectural families.

中央系统的原理是：The central systems principle is:

如果多个模型在同一上下文上运行，则用于理解该上下文的计算工作不必由每个模型独立重复。If multiple models operate over the same context, the computational work used to understand that context should not necessarily be repeated independently by every model.

因此，跨模型 KV 共享旨在使上下文计算能够跨模型边界部分移植。系统尝试重用早期模型生成的有用内部状态，而不是将每个模型调用视为从原始令牌开始的独立计算。Cross-model KV sharing therefore seeks to make contextual computation partially portable across model boundaries. Rather than treating each model invocation as an isolated computation beginning from raw tokens, the system attempts to reuse useful internal state produced by earlier models.

这种功能与新兴的异构和代理人工智能系统尤其相关，在这些系统中，模型转换越来越普遍，并且共享上下文可以长期存在。提供了说明跨模型 KV 共享实践的短视频演示This capability is especially relevant to emerging heterogeneous and agentic AI systems, where model transitions are increasingly common and shared context can be long-lived. 2 背景及相关工作Background and Related Work

2.1 KV缓存和上下文重用KV Caching and Context Reuse

基于 Transformer 的 LLM 依靠自注意力来根据序列中前面的标记来调节每个标记。在每个转换器层，模型计算查询、键和值表示。在自回归生成期间，与先前处理的令牌相关联的键和值表示可以保留在键值（KV）缓存中，并在后续解码步骤中重用。Transformer-based LLMs rely on self-attention to condition each token on preceding tokens in the sequence. At each transformer layer, the model computes query, key, and value representations. During autoregressive generation, the key and value representations associated with previously processed tokens can be retained in a key-value (KV) cache and reused during subsequent decoding steps.

Once these states have been constructed, subsequent decoding can reuse them rather than recomputing the representations of all preceding tokens. KV caching therefore converts the computation performed during prefill into reusable runtime state.

对于长上下文工作负载，构建此状态可能意味着大量的计算成本。处理数千或数万个输入令牌需要大量的矩阵计算、注意力处理、内存移动，以及在分布式部署中，在解码开始之前进行设备间通信。因此，KV 缓存管理已成为现代 LLM 服务系统的重要组成部分。For long-context workloads, constructing this state can represent a substantial computational cost. Processing thousands or tens of thousands of input tokens requires significant matrix computation, attention processing, memory movement, and, in distributed deployments, inter-device communication before decoding begins. Consequently, KV-cache management has become an important component of modern LLM-serving systems.

2.2 相关工作Related Work

一系列广泛的服务优化都利用了这个机会。当多个请求共享公共前缀时，前缀缓存会重用 KV 状态；分页KV管理提高了内存利用率和分配灵活性；缓存卸载和分布式 KV 存储将有效缓存容量扩展到本地加速器内存之外；缓存感知调度尝试将请求与可重用状态并置。这些技术的不同之处在于 KV 状态的存储、放置、传输和调度方式，但它们主要优化状态的重用，这些状态在语义和结构上与最初生成它们的模型保持关联。A broad class of serving optimizations exploits this opportunity. Prefix caching reuses KV states when multiple requests share a common prefix; paged KV management improves memory utilization and allocation flexibility; cache offloading and distributed KV storage extend effective cache capacity beyond local accelerator memory; and cache-aware scheduling attempts to colocate requests with reusable state. These techniques differ in how KV states are stored, placed, transferred, and scheduled, but they primarily optimize reuse of states that remain semantically and structurally associated with the model that originally generated them.

先前关于 KV 缓存重用的工作跨越了几个互补的方向Prior work on KV-cache reuse spans several complementary directions[8, 9, 10, 11, 12, 13]。当相同或结构兼容的上下文再次出现在同一模型中时，传统的前缀缓存和模块化提示重用系统避免了冗余预填充。代表性系统包括提示缓存和面向 RAG 的缓存管理器，它们将可重用的提示段或检索的文档视为可缓存的计算单元。. Conventional prefix caching and modular prompt-reuse systems avoid redundant prefill when identical or structurally compatible context reappears within the same model. Representative systems include prompt caching and RAG-oriented cache managers, which treat reusable prompt segments or retrieved documents as cacheable computational units.

缓存混合CacheBlend[8]通过允许在新上下文下组合独立缓存的文本块，将 KV 重用扩展到精确前缀匹配之外。由于独立缓存的块可能不会对新组合的提示所需的跨块注意依赖关系进行编码，因此 CacheBlend 有选择地重新计算令牌状态的子集，同时重用剩余的 KV 缓存。这一系列工作表明，即使周围上下文发生变化，先前计算的 KV 状态也仍然有用，只要适当纠正所产生的上下文不匹配即可。extends KV reuse beyond exact-prefix matching by allowing independently cached text chunks to be combined under a new context. This line of work demonstrates that previously computed KV states can remain useful even when the surrounding context changes, provided that the resulting contextual mismatch is appropriately corrected.

3 冗余上下文计算问题The Redundant Context Computation Problem

考虑一个人工智能工作流程，其中多个模型在公共上下文中运行Consider an AI workflow in which several models operate over a common contextCC。例如：. For example:

C→M1→M2→M3.C\rightarrow M_{1}\rightarrow M_{2}\rightarrow M_{3}.

上下文可以包括系统提示、用户请求、对话历史、检索到的文档、工具输出或中间代理状态。The context may include a system prompt, user request, conversation history, retrieved documents, tool outputs, or intermediate agent state.

在传统推理下，每个模型独立执行自己的预填充计算：Under conventional inference, each model independently performs its own prefill computation:

K​VM1​(C)=Prefill⁡(M1,C),KV_{M_{1}}(C)=\mathrm{Prefill}(M_{1},C),
K​VM2​(C)=Prefill⁡(M2,C),KV_{M_{2}}(C)=\mathrm{Prefill}(M_{2},C),
K​VM3​(C)=Prefill⁡(M3,C).KV_{M_{3}}(C)=\mathrm{Prefill}(M_{3},C).

预填充总成本约为The aggregate prefill cost is approximately

Cnative=∑i=1NCprefill​(Mi,C).C_{\mathrm{native}}=\sum_{i=1}^{N}C_{\mathrm{prefill}}(M_{i},C).

从每个单独模型的角度来看，这种计算是必要的，因为模型需要自己的内部表示。然而，从整个应用程序的角度来看，系统重复处理基本上相同的信息。From the perspective of each individual model, this computation is necessary because the model requires its own internal representation. From the perspective of the overall application, however, the system is repeatedly processing substantially the same information.

随着上下文长度或参与模型数量的增加，效率低下变得更加严重。简短的 100 个令牌请求可能会使冗余的预填充相对不重要。相比之下，由多个大型模型重复处理的 32K 令牌对话历史可能代表大量的重复计算。The inefficiency becomes more severe as either the context length or the number of participating models increases. A short 100-token request may make redundant prefill relatively unimportant. In contrast, a 32K-token conversation history repeatedly processed by several large models can represent significant duplicated computation.

同样的问题也出现在多个新兴工作负载中。在The same problem appears across multiple emerging workloads. In模型升级model escalation，一个小模型最初可能会处理一个请求，然后将其升级为一个更大的模型，然后该模型必须重新计算整个上下文。在, a small model may initially handle a request before escalating it to a larger model, which must then recompute the entire context. In多智能体系统multi-agent systems，使用不同模型的多个代理可能会使用相同的用户历史记录并检索证据。在, several agents using different models may consume the same user history and retrieved evidence. In模型路由model routing，请求可以根据任务难度、成本、延迟或专业化在模型之间动态移动。同样，在, requests may move dynamically among models based on task difficulty, cost, latency, or specialization. Similarly, in验证管道verification pipelines，一个模型可以生成答案，而另一个模型可以独立处理相同的输入以验证或批评它。在所有这些情况下，逻辑信息是共享的，但底层的计算表示不是共享的。跨模型 KV 共享旨在弥合这一差距。, one model may generate an answer while another independently processes the same input to verify or critique it. Across all these cases, the logical information is shared, but the underlying computational representations are not. Cross-model KV sharing seeks to bridge this gap.

4 跨模型KV共享Cross-Model KV Sharing

跨模型 KV 共享使一种语言模型能够重用先前由另一种模型执行的上下文计算。在传统推理中，每个模型独立处理相同的输入上下文并构建自己的 KV 缓存，即使另一个模型已经处理了该上下文。对于共享上下文Cross-model KV sharing enables one language model to reuse contextual computation that was previously performed by another model. In conventional inference, each model independently processes the same input context and constructs its own KV cache, even when another model has already processed that context. For a shared contextCC，这意味着不同的模型分别计算自己的表示：, this means that different models separately compute their own representations:K​VA​(C)KV_{A}(C)和andK​VB​(C)KV_{B}(C)。 在涉及多个模型在共享提示、对话历史、检索的文档或其他持久上下文上运行的系统中，这种重复的预填充计算变得越来越低效。. This repeated prefill computation becomes increasingly inefficient in systems that involve multiple models operating over shared prompts, conversation histories, retrieved documents, or other persistent context.

关键思想是不仅将 KV 缓存视为模型本地运行时工件，而且将其视为潜在的可重用计算表示。跨模型 KV 共享引入了一种转换机制，将源模型的 KV 表示转换为目标兼容的表示，而不是要求目标模型根据原始标记独立重建整个上下文：The key idea is to treat the KV cache not only as a model-local runtime artifact, but as a potentially reusable computational representation. Rather than requiring a target model to independently reconstruct the entire context from the original tokens, cross-model KV sharing introduces a translation mechanism that converts the source model’s KV representation into a target-compatible representation:

K​V^B​(C)=TA→B​(K​VA​(C)),\widehat{KV}_{B}(C)=T_{A\rightarrow B}\bigl(KV_{A}(C)\bigr),

哪里whereTA→BT_{A\rightarrow B}表示从源模型的表示空间到目标模型的表示空间的变换。然后，生成的转换状态可用于支持目标模型中的后续推理。denotes the transformation from the source model’s representation space to that of the target model. The resulting translated state can then be used to support subsequent inference in the target model.

这种转换不仅仅是张量格式转换或维度重塑。源 KV 缓存反映了源模型如何编码跨其注意力层的上下文关系，而目标模型可能使用不同的学习表示空间、注意力结构、层组织、隐藏维度或标记器。因此，成功的翻译必须保留对后续推理有用的上下文信息，同时使其适应目标模型预期的计算结构。This translation is more than a tensor-format conversion or dimensional reshaping. The source KV cache reflects how the source model encodes contextual relationships across its attention layers, while the target model may use a different learned representation space, attention structure, layer organization, hidden dimension, or tokenizer. A successful translation must therefore preserve the contextual information that is useful for subsequent inference while adapting it to the computational structure expected by the target model.

重要的是，翻译后的表示不一定需要准确地重现目标模型的本机 KV 缓存。一般来说，Importantly, the translated representation does not necessarily need to reproduce the target model’s native KV cache exactly. In general,

K​V^B​(C)≠K​VB​(C)\widehat{KV}_{B}(C)\neq KV_{B}(C)

可能还是可以接受的。实际目标是构建一种表示，为目标模型提供足够的上下文信息，以继续以可接受的输出质量进行推理，同时避免目标端预填充计算的有意义部分。这创建了一个设计空间，其中不同的翻译机制可以平衡重构保真度、翻译开销、运行时效率、泛化和跨异构模型的兼容性。may still be acceptable. The practical objective is to construct a representation that provides sufficient contextual information for the target model to continue inference with acceptable output quality while avoiding a meaningful portion of target-side prefill computation. This creates a design space in which different translation mechanisms can balance reconstruction fidelity, translation overhead, runtime efficiency, generalization, and compatibility across heterogeneous models.

因此，跨模型 KV 共享概括了传统的 KV 缓存重用，超出了缓存的生产者和消费者必须是同一模型的假设。源模型和目标模型可能在模型大小、配置、架构、分词器或模型系列方面有所不同。随着这些差异的增加，翻译问题变得更具挑战性，因为底层表示不太直接对齐。尽管如此，基本目标仍然是相同的：尽可能多地保留在处理上下文中已经投入的计算值，并跨模型边界携带该值。Cross-model KV sharing therefore generalizes conventional KV-cache reuse beyond the assumption that the producer and consumer of a cache must be the same model. The source and target models may differ in model size, configuration, architecture, tokenizer, or model family. As these differences increase, the translation problem becomes more challenging because the underlying representations are less directly aligned. Nevertheless, the fundamental objective remains the same: preserve as much as possible of the computational value already invested in processing the context and carry that value across model boundaries.

从系统角度来看，跨模型共享改变了异构AI应用的执行模型。运行时可以首先确定相关的上下文计算是否已经存在以及适当的转换路径是否可用，而不是要求每个新调用的模型从原始标记重新启动。当重用有益时，目标模型可以从转换的 KV 状态开始，而不是重复完整的预填充过程。当翻译后的表示不满足所需的质量或效率标准时，系统可以回退到传统的本地预填充。From a systems perspective, cross-model sharing changes the execution model of heterogeneous AI applications. Instead of requiring every newly invoked model to restart from raw tokens, the runtime can first determine whether relevant contextual computation already exists and whether an appropriate translation path is available. When reuse is beneficial, the target model can begin from a translated KV state rather than repeating the full prefill process. When the translated representation does not meet the required quality or efficiency criteria, the system can fall back to conventional native prefill.

通过将翻译成本与本机预填充成本进行比较，可以在较高层面上表达效率优势。跨模型重用在以下情况下是有利的：The efficiency benefit can be expressed at a high level by comparing the cost of translation with the cost of native prefill. Cross-model reuse is advantageous when

Ctrans+Coverhead<Cprefill,C_{\mathrm{trans}}+C_{\mathrm{overhead}}<C_{\mathrm{prefill}},

前提是翻译后的状态也满足应用程序的质量要求。因此，随着提示变得更长、目标模型的计算成本变得更高以及应用程序涉及模型之间更频繁的转换，潜在的好处也会增加。provided that the translated state also satisfies the application’s quality requirements. The potential benefit therefore increases as prompts become longer, target models become more computationally expensive, and applications involve more frequent transitions among models.

更广泛地说，跨模型 KV 共享引入了一种不同的方式来查看 LLM 系统中的上下文计算。 KV 状态不必仅仅被视为与各个推理调用相关的临时的、特定于模型的工件。相反，它们可以被视为可重用的计算资产，可以在不同的模型之间存储、传输、翻译和使用。这一观点为更广泛的概念奠定了基础More broadly, cross-model KV sharing introduces a different way to view contextual computation in LLM systems. KV states need not be treated solely as temporary, model-specific artifacts associated with individual inference calls. Instead, they can be viewed as reusable computational assets that may be stored, transferred, translated, and consumed across different models. This perspective provides the foundation for a broader notion of上下文移动性context mobility，其中当人工智能工作负载跨异构模型、代理和执行环境移动时，先前处理的信息的计算价值可以持续存在。, in which the computational value of previously processed information can persist as an AI workload moves across heterogeneous models, agents, and execution environments.

5 了解翻译层Understanding the Translation Layer

翻译层是实现跨模型重用的核心组件。The translation layer is the central component that enables cross-model reuse.

在较高级别上，系统观察源 KV 状态At a high level, the system observes source KV states

K​VA​(C)KV_{A}(C)

并学习或构造一个函数，生成适合目标模型的表示。and learns or constructs a function that produces a representation suitable for a target model.

总体目标可以写为The general objective can be written as

K​V^B​(C)=Tθ​(K​VA​(C)),\widehat{KV}_{B}(C)=T_{\theta}\left(KV_{A}(C)\right),

哪里whereθ\theta表示翻译机制的参数。represents the parameters of the translation mechanism.

一种可能的学习目标是最小化翻译状态与本机预填充生成的目标状态之间的差异：One possible learning objective is to minimize the difference between the translated state and a target state generated by native prefill:

ℒK​V=D⁡(Tθ​(K​VA​(C)),K​VB​(C)),\mathcal{L}_{KV}=D\left(T_{\theta}(KV_{A}(C)),KV_{B}(C)\right),

哪里whereD⁡(⋅,⋅)D(\cdot,\cdot)是一个适当的表示距离函数。is an appropriate representation-distance function.

然而，最小化原始 KV 距离可能不是唯一的，甚至不是最重要的目标。两个 KV 状态可能在数值上有所不同，但仍会导致相似的模型行为。因此，更加以任务为导向的目标可能会优化下游输出、注意力行为、逻辑或任务准确性。However, minimizing raw KV distance may not be the only or even the most important objective. Two KV states can differ numerically while still leading to similar model behavior. A more task-oriented objective may therefore optimize downstream outputs, attention behavior, logits, or task accuracy.

这个观点很重要，因为跨模型共享并不旨在重现目标模型将生成的精确内部计算；相反，它寻求构建一个兼容的状态，使目标模型能够继续有效地进行推理。这种转换可以跨单个层、层组、单个 KV 头、共享中间表示、压缩 KV 表示或低维潜在适配器进行操作。因此，翻译机制可以设计为平衡翻译保真度、运行时开销、内存占用以及支持其他模型的便利性。This perspective is important because cross-model sharing does not aim to reproduce the exact internal computation that the target model would have generated; rather, it seeks to construct a compatible state that enables the target model to continue inference effectively. Such translation can operate across individual layers, groups of layers, individual KV heads, shared intermediate representations, compressed KV representations, or low-dimensional latent adapters. The translation mechanism can therefore be designed to balance translation fidelity, runtime overhead, memory footprint, and the ease of supporting additional models.

6 Experimental Evaluation

我们在逐渐异构的源-目标对下评估跨模型 KV 共享。我们的实验提出了两个问题：（1）KV 状态是否可以在同一系列的不同大小的模型之间转移，以及（2）当模型的架构、分词器和规模不同时，有用的状态是否仍然可以转移。We evaluate cross-model KV sharing under progressively more heterogeneous source–target pairs. Our experiments ask two questions: (1) whether KV states can be transferred between differently sized models from the same family, and (2) whether useful state can still be transferred when the models differ in architecture, tokenizer, and scale.

7 结论Conclusion

这项工作研究了跨模型 KV 共享作为跨异构语言模型重用先前计算的上下文状态的机制。通过将 KV 缓存重用扩展到传统的同模型设置之外，所提出的方法使源模型的上下文表示能够转换为可以支持不同目标模型中的推理的形式。我们的实验结果提供了初步证据，表明这种形式的状态转移在模型系列内和不同模型系列之间都是可行的，包括模型规模、架构和内部表示存在重大差异的设置。在评估的配置中，转换后的 KV 状态保留了有意义的下游效用，同时减少了对冗余目标端预填充计算的需求。这些发现表明，KV 缓存不仅可以被视为模型本地执行工件，而且还可以被视为可转移的计算状态。更广泛地说，结果激发了以下概念：This work investigates cross-model KV sharing as a mechanism for reusing previously computed contextual state across heterogeneous language models. By extending KV-cache reuse beyond the conventional same-model setting, the proposed approach enables a source model’s contextual representation to be translated into a form that can support inference in a different target model. Our experimental results provide initial evidence that this form of state transfer is feasible both within a model family and across distinct model families, including settings with substantial differences in model scale, architecture, and internal representation. Across the evaluated configurations, translated KV states preserve meaningful downstream utility while reducing the need for redundant target-side prefill computation. These findings suggest that KV caches can be viewed not only as model-local execution artifacts, but also as transferable computational state. More broadly, the results motivate the notion of上下文移动性context mobility，其中先前计算的上下文可以在执行跨模型和推理阶段时保留价值。虽然需要进一步评估来描述其他架构、工作负载、上下文长度和部署环境的泛化特征，但当前的结果为跨模型 KV 重用作为高效异构 LLM 和多代理推理的系统抽象奠定了良好的基础。, in which previously computed context can retain value as execution moves across models and inference stages. While further evaluation is needed to characterize generalization across additional architectures, workloads, context lengths, and deployment environments, the current results establish a promising foundation for cross-model KV reuse as a systems abstraction for efficient heterogeneous LLM and multi-agent inference.
