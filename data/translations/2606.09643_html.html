2.1 基础模型2.1 Foundation Models

人工智能的最新进展已将模型开发从特定于任务的架构转向通用基础模型。早期的方法通常为分类、对象检测和分割等任务训练专门的模型[24、56、58、72、79]。相比之下，基础模型 (FM) 是通用的预训练模型Recent advances in AI have shifted model development from task-specific architectures toward general-purpose foundation models. Earlier approaches typically trained specialized models for tasks such as classification, object detection, and segmentation [24, 56, 58, 72, 79]. In contrast, foundation models (FMs) are general-purpose pretrained骨干模型backbone models使用自我监督对大型异构数据集进行训练，并且可以适应广泛的trained on large, heterogeneous datasets using self-supervision and can be adapted to a wide range of下游downstream任务 [6, 7]，在有限或没有特定任务适应的情况下实现出色的性能。 FM 涵盖多种输入方式，包括时间序列、视觉、语言及其组合。例子包括时间序列基础模型（TSFM）[3,17,19]，视觉基础模型（VFM）[15,49,54]，LLM[8,23,41,73]和VLM[34,42,75,80]。其他 FM 针对特定应用领域，包括能源 [29, 38]、金融 [55, 66, 83] 和健康 [14, 18, 27, 52]。在这些设置中，单个 FM 通常支持多个下游任务，我们将这种能力称为tasks [6, 7], achieving strong performance with limited or no task-specific adaptation. FMs cover multiple input modalities, including time series, vision, language, and combinations of these. Examples include timeseries foundation models (TSFMs) [3, 17, 19], vision foundation models (VFMs) [15, 49, 54], LLMs [8, 23, 41, 73], and VLMs [34, 42, 75, 80]. Other FMs target specific application domains, including energy [29, 38], finance [55, 66, 83], and health [14, 18, 27, 52]. Across these settings, a single FM often supports several downstream tasks, an ability we refer to as任务共享task sharing，这意味着即使每个任务都部署为单独的模型实例，模型也可以适应不同的任务。例如，MOMENT [19]，一种时间序列 FM，可以从单个骨干网执行分类、预测和异常检测。, meaning that the model can be adapted to different tasks even if each task is deployed as a separate model instance. For example, MOMENT [19], a time-series FM, can perform classification, forecasting, and anomaly detection from a single backbone.

R1 主干共享作为一流的原语。Backbone sharing as a first-class primitive.FM 主干是重量级系统对象，通常需要 GB 的 GPU 内存以及大量的加载和预热时间，而特定于任务的状态（例如解码器权重、PEFT 适配器、队列状态和会计元数据）相对轻量级。服务系统必须支持每个 FM 实例的多个任务，将主干网视为共享基础而不是每个任务的资源。FM backbones are heavyweight system objects, often requiring gigabytes of GPU memory and substantial loading and warmup time, whereas task-specific state (e.g., decoder weights, PEFT adapters, queue state, and accounting metadata) is comparatively lightweight. R2 将骨干网与任务生命周期解耦。Decoupling backbone from task lifecycle.因此，服务系统必须将主干实例生命周期与任务生命周期解耦，允许任务独立于当前为其服务的特定主干实例来维护独立的队列、定制状态和记账身份。这种解耦通过轻量级任务状态移动和跨现有 FM 实例的重新绑定实现运行时自适应，而不需要昂贵的 FM 重新加载或完整模型重新部署。The serving system must therefore decouple the backbone-instance lifecycle from the task lifecycle, allowing tasks to maintain independent queues, customization state, and accounting identities independent of the specific backbone instance currently serving them. R3 任务级隔离。Task-level isolation.任务具有异构的请求率和到达模式。服务系统必须提供每个任务的隔离边界、一个命名的、可寻址的上下文，具有自己的请求队列和记帐状态，在该边界上强制执行调度、公平性和准入决策。 R4Tasks have heterogeneous request rates and arrival patterns.
