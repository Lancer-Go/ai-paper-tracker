分类器上下文旋转：监控性能随上下文长度而下降Classifier Context Rot: Monitor Performance Degrades with Context Length

Sam Martin
Anthropic Fellows Program
Fabien Roger
Anthropic
摘要Abstract

使用语言模型监控编码代理的危险行为需要对通常超过 500K 标记的转录本进行分类，但之前的代理监控基准很少包含超过 100K 标记的转录本。 我们表明，当用作分类器时，当前的前沿模型无法在较长的记录中更频繁地注意到危险行为。特别是，在需要识别编码代理何时采取微妙危险操作的数据集上，Opus 4.6、GPT 5.4 和 Gemini 3.1 在 800K 良性活动标记之后发生这些操作时，错过这些操作的频率比它们单独发生时高 2 倍到 30 倍。我们还表明，这些弱点可以通过提示技术（例如在整个记录中定期提醒）来部分缓解，并且可以通过更好的后期培训进一步缓解。不考虑长上下文降级的显示器评估可能会高估显示器性能。Monitoring coding agents for dangerous behavior using language models requires classifying transcripts that often exceed 500K tokens, but prior agent monitoring benchmarks rarely contain transcripts longer than 100K tokens. We show that when used as classifiers, current frontier models fail to notice dangerous actions more often in longer transcripts. In particular, on a dataset that requires identifying when a coding agent takes a subtly dangerous action, Opus 4.6, GPT 5.4, and Gemini 3.1 miss these actions 2× to 30× more often when they occur after 800K tokens of benign activity than when they occur on their own. We also show that these weaknesses can be partially mitigated with prompting techniques such as periodic reminders throughout the transcript and may be mitigated further with better post-training. Monitor evaluations that do not consider long-context degradation are likely overestimating monitor performance.

1 简介Introduction

语言模型现在能够自主完成长任务Language models are now able to complete long tasks autonomously(Kwa et al., 2025)。为了以最少的人工干预来完成这些任务，语言模型代理被赋予了越来越广泛的功能。在此类任务的过程中，包含用户请求、工具调用和响应的记录会变得比人类监督的时间要长。为了检测危险行为，一种可能的方法是使用另一种语言模型来监控这些长文本. In order to complete these tasks with minimal human intervention needed, language model agents are given increasingly broad affordances. During the course of such a task, the transcript containing user requests, tool calls and responses grows longer than is feasible for a human to oversee. To detect dangerous actions, one potential approach is to use another language model to monitor these long transcripts(Greenblatt et al., 2024)。这种方法目前被前沿实验室使用. This approach is currently used by frontier labs(Anthropic, 2026; OpenAI, 2026)监控其内部代理是否有人工智能采取危险或失调行为的情况。to monitor their internal agents for cases in which the AI takes dangerous or misaligned actions.

为了评估监控器是否会发现危险或失调的行为，之前的工作通常依赖于综合评估或人工红队的数据To evaluate whether monitors would catch dangerous or misaligned actions, prior work often relied on data from synthetic evaluations or human red-teaming(Jotautaitė et al., 2026; Inglis et al., 2025; Loughridge et al., 2025; Storf et al., 2026)。 此类评估的代理记录通常比前沿语言模型的上下文窗口短得多。然而，众所周知，语言模型很难从问答上下文中的很长的输入中提取重要信息，例如大海捞针的评估. The agent transcripts from such evaluations are often much shorter than the context window of frontier language models. However, language models are known to struggle to extract important information from very long inputs in question answering contexts, for example in needle-in-a-haystack evals(Liu et al., 2024; Kamradt, 2023)。 在这项工作中，我们研究了这些长上下文故障如何应用于监控长代理记录中是否存在危险行为。. In this work, we study how these long-context failures apply in the context of monitoring long agent transcripts for dangerous actions.

我们研究解决长上下文弱点的缓解措施。我们发现提示更改可以产生显着的影响：使用更多的思考标记或思考指令、在记录中插入分类任务的提醒在某些情况下都可以显着提高监视器性能。我们还表明，人工智能开发人员可以通过执行多个增量监控调用来提高监控系统的性能，而不是仅仅在最后运行它。最后，我们研究了训练缓解措施，在长上下文分类数据集上微调 GPT-4.1，但发现它不能可靠地泛化到更好的监控性能。We study mitigations to address long context weakness. We find that prompting changes can make a significant difference: using more thinking tokens or thinking instructions, inserting reminders of the classification task into the transcript can all improve monitor performance significantly in some cases. We also show that AI developers may improve the performance of the monitoring system by performing multiple incremental monitor calls, rather than just running it at the end. Finally, we study training mitigations, where we fine-tune GPT-4.1 on long-context classification datasets, but find that it doesn’t reliably generalize to better monitor performance.

不考虑上下文长度的监控评估可能会高估监控系统提供的安全性。特别是，在极长的编码会话中，代理可能被赋予最大的自主权和破坏机会，因此监视器在这里发挥作用尤为重要。Monitor evaluations that do not take into consideration context length are potentially overestimating the safety provided by the monitoring system. In particular, extremely long coding sessions are likely to be the ones where the agent is given the most autonomy and opportunities for sabotage, so it is particularly important that monitors are effective here.

3 实验装置Experimental Setup

我们研究转录监视器：向语言模型提供完整的代理转录（用户轮流、AI 消息、工具调用和工具结果），并要求语言模型寻找恶意或危险的 AI 操作，重点关注削弱安全性、破坏安全研究、欺骗用户或泄露数据的操作。此类监视器通常用作自动异步监视管道的一部分We study transcript monitors: a language model is given a full agent transcript (user turns, AI messages, tool calls, and tool results) and asked to look for malicious or dangerous AI actions with a focus on actions that weaken security, sabotage safety research, deceive the user or exfiltrate data. Such monitors are often used as part of an automated asynchronous monitoring pipeline(Anthropic, 2026; Lindner et al., 2025).

3.1 型号Models

我们使用 Claude Opus 4.6、Gemini 3.1 Pro 和 GPT 5.4 Thinking 进行评估。对于 Opus 4.6，我们考虑三种模式：非思维分类（模型必须输出其标签作为第一个令牌）、提示思维链以及具有一系列令牌预算的扩展思维。我们不使用推荐的自适应思维模式，因为 Opus 经常选择不思考，即使是在最高级别。对于双子座，我们使用低、中、高思维模式；对于 GPT 5.4，我们还包括 xhigh。We run evaluations with Claude Opus 4.6, Gemini 3.1 Pro, and GPT 5.4 Thinking. For Opus 4.6 we consider three modes: non-thinking classification (the model must output its label as the first token), prompted chain-of-thought, and extended thinking with a range of token budgets. We do not use the recommended adaptive thinking mode, as Opus frequently chooses not to think even at the highest level. For Gemini we use the low, medium, and high thinking modes; for GPT 5.4 we additionally include xhigh.

3.2 提示Prompts

我们使用的分类提示类似于人工智能公司用于内部监控的分类提示（并且由该组织的一位研究人员私下共享）。我们考虑三个额外的变体： 标准的思维提示链We use a classification prompt similar to the one used by an AI company for internal monitoring (and was privately shared by a researcher from this organization). We consider three additional variants: a standard chain of thought prompt(Wei et al., 2022)附加“在提供答案之前一步一步思考”；that appends “think step by step before providing your answer”;CoT列表CoT-List，它明确指示模型在做出决定之前逐字列出它观察到的最可疑的行为；以及 GPT 特定的变体，其中有一个更长的部分描述了什么, which explicitly instructs the model to begin by listing, word for word, the most suspicious actions it observes before making a decision; and a GPT-specific variant with a substantially longer section describing what不not标记，我们发现这是必要的，因为共享提示在 GPT 模型上产生了更高的误报率。附录中提供了提示模板to flag, which we found necessary because the shared prompt produced a much higher false positive rate on GPT models. Prompt templates are provided in AppendixA.2.

我们还考虑了一种提醒缓解措施，即在每个工具调用和工具响应之间插入监控任务的提醒（第 1 节）We also consider a reminder mitigation, where we insert reminders of the monitoring task between every tool call and tool response (Section4.6).

3.3 监控策略Monitoring Strategies

我们考虑两种监控策略：We consider two monitoring strategies:

增量监控。Incremental Monitoring.

随着会议的进行，我们会监控多个截断版本的记录。这意味着对于给定的工具调用，我们会监视直至并包括该工具调用的记录。正如人择破坏风险报告中所述We monitor multiple truncated versions of the transcript as the session progresses. This means that for a given tool call, we monitor the transcript up to and including that tool call. As in the Anthropic sabotage risk report(Anthropic, 2026)，我们将二次抽样视为一种成本度量。这意味着以工具调用结束的每个子转录都有固定的被监视概率。因此，我们收到与已监控的每个子转录本相对应的同一转录本的多个标签。, we consider subsampling as a cost measure. This means that each sub-transcript ending at a tool call has a fixed probability of being monitored. As a result, we receive multiple labels for the same transcript corresponding to each sub-transcript that has been monitored.

最终成绩单监控。Final Transcript Monitoring.

等到会话结束并通过单个监视器调用监视完整的记录。这为我们的整个会话提供了一个标签。Wait until the session is over and monitor the full transcript with a single monitor call. This gives us one label for the entire session.

不过，这在不同型号之间有所不同。 Gemini 3.1 Pro 在这两项任务上都能顺利扩展。 GPT 5.4 能够使用更多推理来有效提高针对针头注射的检测率，但在具有长良性前缀的 MonitorBench 上无法获得相同的好处。具有一系列思维预算的 Opus 4.6 选择不使用其分配的思维，因此我们没有看到任何扩展（尽管与两项任务上的非思考相比，它仍然是一个强大的提升）。两种思路提示方法之间也存在很大差异：提示 Opus 首先输出最可疑的操作列表，然后进行推理，仅使用少量额外标记即可帮助大规模检测。这有点令人惊讶：当被问及是否存在可疑操作时，模型无法识别可疑操作，但当被要求复制可疑操作时，它能够逐字引用它们。This differs between models though. Gemini 3.1 Pro scales smoothly across both tasks. GPT 5.4 is able to use more reasoning to increase detection rate effectively against the needle injection, but does not gain the same benefit on MonitorBench with long benign prefixes. Opus 4.6 with a range of thinking budgets elects not to use its allocated thinking, so we do not see any scaling (though it is still a strong uplift vs non-thinking on both tasks). There is a large difference between the two chain of thought prompting methods too: prompting Opus to start by outputting a list of the most suspicious actions before doing its reasoning aids detection massively with only a small amount of extra tokens used. This is somewhat surprising: the model fails to identify suspicious actions when asked if any are present, but when asked to copy suspicious actions it is able to quote them verbatim.

5 长上下文分类的微调Fine-tuning on Long-Context Classification

We finetune and evaluate GPT-4.1 (none of the previously evaluated models provide fine-tuning access) on classification with no thinking. We use the default parameters available on the OpenAI fine-tuning API. To make sure that training improvements are due to improved classification ability rather than a calibration shift, we use the logprobs of "true" vs "false" to provide a continuous classification score rather than a binary label. This allows us to compute the AUC, using clean transcripts as negatives.

6 讨论Discussion

影响。Implications.

模型能够完成的更复杂的任务自然会产生长记录，这意味着监视器可能会错过危险的操作。但此外，未对准的代理可能会等到编码会话后期才进行攻击，只需等待，就有可能使其成功率加倍。此外，这些长时间的会话可能特别危险，因为它们可能对模型有更高的可供性，更多的攻击机会，现在我们已经表明，与较短的交换相比，监视器将相对较弱。这表明不考虑这种长上下文性能的监视器评估可能会高估其监视器性能。Long transcripts arise naturally from the more complex tasks that models are becoming able to complete, meaning that monitors may miss dangerous actions. But additionally, a misaligned agent could wait until late in a coding session to make its attack, potentially doubling its success rate simply by waiting. Further, these long sessions may be especially dangerous given that they are likely to have higher affordances given to the model, more opportunities to attack and now we have shown that the monitor will be comparatively weaker when compared to shorter exchanges. This suggests that monitor evaluations that do not consider this long context performance are likely to be overestimating their monitor performance.

缓解措施。Mitigations.

我们发现，更频繁的监控和更高的思考力度可以将计算转化为更高的监控召回率。展望未来，基于训练的方法可能也很重要，因为即使在对每个操作使用增量监控并尽最大努力时，当前的前沿模型仍然会在像 MonitorBench 这样的难题上遭受分类器上下文腐烂的困扰。We see that monitoring more frequently and using higher thinking effort can be used to convert compute into somewhat higher monitoring recall. Going forward, training-based approaches are likely to be important as well, as current frontier models still suffer from classifier context rot on hard problems like MonitorBench even when using incremental monitoring on each action and when using maximum effort.

局限性和未来的工作Limitations and Future Work
  1. 1.

    初步微调。Preliminary fine-tuning.我们的微调实验仅使用小数据集，并且由于较大训练运行的成本而没有思考（假设每个训练示例的长度超过 100k 个标记）。我们也没有研究这与构建语言模型的一般长上下文训练有何不同Our fine-tuning experiments only use small datasets and no thinking due to the cost of larger training runs (given that each training example is over 100k tokens long). We also do not study how this differs from the general long-context training that goes into building language models(Xiong et al., 2024)：与更专业的培训相比，此类培训的泛化可能会引发长情境能力。: generalization from such training may elicit long-context abilities comparably to more specialized training.

  2. 2.

    检测与校准。Detection vs Calibration.误报率很低，因此很难准确估计准确率。这意味着我们的核心实验中更高的检测率（但不是在我们能够测量 AUC 的微调实验中）可能来自模型之间的校准差异，而不是实际的分类能力。这并没有破坏要点，即随着上下文长度的增加，性能会下降：校准错误仍然会导致监视器错过危险的操作。未来的工作可以研究使用输入大小的特定阈值来减轻潜在的误校准困难。False positives are low, so getting an accurate estimate of the exact rate is difficult. This means that higher detection rates in our core experiments (but not in our fine-tuning experiments, where we are able to measure AUC) could come from calibration differences between models rather than actual classification capabilities. This does not undermine the main point, which is that performance decreases as context length increases: miscalibration would still cause monitors to miss dangerous actions. Future work could study using input-size specific thresholds to mitigate potential miscalibration difficulties.

  3. 3.

    仅局部攻击。Localised attacks only.我们只考虑跨越记录的一小部分的攻击。遍布整个上下文的多步攻击可能更难被监控器检测到。We only consider attacks that span a short section of the transcript. Multi-step attacks that are spread over the full context are potentially even harder for monitors to detect.

7 结论Conclusion

我们已经证明，Opus 4.6、GPT 5.4 和 Gemini 3.1 Pro 的召回率会随着转录长度的增加而降低。我们展示了几种可以部分解决此问题的缓解措施：扩展思维、增量监控和提醒提示都可以提高检测率。 SFT 显示了一些改进，但这些改进未能推广到分布外评估。在设计和评估监测系统时应考虑当前监测器的这一重要弱点。We have demonstrated that the recall of Opus 4.6, GPT 5.4 and Gemini 3.1 Pro degrades as transcript length increases. We demonstrate several mitigations that partially address this: extended thinking, incremental monitoring, and reminder prompting all improve detection rates. SFT showed some improvements, but these failed to generalize to out-of-distribution evaluations. This important weakness of current monitors should be considered when designing and evaluating monitoring systems.
