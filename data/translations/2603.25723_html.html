1 简介Introduction

现代代理人的成功或失败越来越多地取决于周围的环境Modern agents increasingly succeed or fail because of the surrounding马具harness：控制堆栈，用于构建多步骤推理、工具使用、内存、委托以及超出任何单个模型调用的停止。 大量研究表明，外部化控制模式可以发挥决定性作用，包括理性-行动循环: the control stack that structures multi-step reasoning, tool use, memory, delegation, and stopping beyond any single model call. A large body of research shows that externalized control patterns can be decisive, including reason–act loops(Yao et al., 2023)，检索增强生成, retrieval-augmented generation(Lewis et al., 2021)，以及明确的自我反馈, and explicit self-feedback(Shinn et al., 2023)。 最近的工作将这一空间扩展到外显记忆和自我进化. Recent work has expanded this space toward explicit memory and self-evolution(Zhang et al., 2026)、工作流程生成, workflow generation(Li et al., 2024; Zheng et al., 2025)、多智能体编排, multi-agent orchestration(Fourney et al., 2024; Wang et al., 2025b; Ke et al., 2026; Costa, 2026; Xia et al., 2026)，以及接口级测试时间缩放和本机工具执行, and interface-level test-time scaling and native tool execution(Muennighoff et al., 2025; Wang et al., 2024b; HKUDS, 2026)。 同时，长上下文和长视野设置表明，即使基本模型已修复，控制堆栈（包括状态管理、上下文管理和上下文折叠）也可能成为性能瓶颈. In parallel, long-context and long-horizon settings have exposed that the control stack—including state management, context curation, and context folding—can bottleneck performance even when the base model is fixed(Liu et al., 2024; Chroma Research, 2025; Tang et al., 2025, 2026a, 2026b; Sun et al., 2025; Su et al., 2026)。 同样的压力也出现在支架感知评估和日益苛刻的推理环境中，即使在固定基础模型下，支架和线束的差异也可能主导结果. The same pressure appears in scaffold-aware evaluation and increasingly demanding reasoning settings, where differences in scaffolds and harnesses can dominate outcomes even under fixed base models(Ding et al., 2026; An et al., 2025; Zhan et al., 2026b, a).

这种转变将“即时工程”重新定义为更广泛的实践This shift reframes “prompt engineering” into the broader practice of情境工程context engineering：决定长期运行的每一步应该提供哪些指令、证据、中间工件和状态。 从业者的说法强调，由于任务跨越许多上下文窗口，稳健的进展较少依赖于一次性措辞，而更多地依赖于持久的状态表面、验证门和明确的责任边界: deciding what instructions, evidence, intermediate artifacts, and state should be made available at each step of a long run. Practitioner accounts emphasize that as tasks span many context windows, robust progress depends less on one-shot phrasing and more on durable state surfaces, validation gates, and clear responsibility boundaries(Anthropic, 2024, 2025a, 2025b; Bui, 2026)。 本着同样的精神，最近的讨论. In the same spirit, recent discussions of线束工程harness engineering将线束视为一流的系统对象，而不是模型的薄包装treat the harness as a first-class systems object, not a thin wrapper around a model(OpenAI, 2026a; LangChain, 2026b, a, 2025).

问题。Problem.

尽管线束设计越来越重要，但线束逻辑很少作为连贯的、可移植的工件公开。 在大多数代理系统中，有效的利用分散在控制器代码、隐藏框架默认值、工具适配器、验证器脚本和特定于运行时的假设中Despite the growing importance of harness design, harness logic is rarely exposed as a coherent, portable artifact. In most agent systems, the effective harness is scattered across controller code, hidden framework defaults, tool adapters, verifier scripts, and runtime-specific assumptions(Lou et al., 2026; Shi et al., 2025; Chivukula et al., 2025; Wang et al., 2025a; Zhang et al., 2025)。 因此，工具很难跨运行时传输，难以公平比较，也难以彻底消除：名义上因一种设计选择而不同的两个系统通常在提示、工具中介、工件约定、验证门和状态语义方面同时不同. As a result, harnesses are difficult to transfer across runtimes, hard to compare fairly, and hard to ablate cleanly: two systems that nominally differ by one design choice often differ simultaneously in prompts, tool mediation, artifact conventions, verification gates, and state semantics(Liang et al., 2025; Cheng et al., 2025)。 这将评估分解为控制器包比较而不是模块级证据。. This collapses evaluation into controller-bundle comparisons rather than module-level evidence.

自然语言工件，例如Natural-language artifacts such as代理.mdAGENTS.md和技能包表明，实用的系统可以将存储库本地约定和可重用的过程打包为可移植文本and skill bundles show that practical systems can package repository-local conventions and reusable procedures in portable text(AGENTS.md, 2026; AgentSkills, 2026)。 最近的工作通过经验驱动的技能创建、情境工程技能进化、可重用的程序记忆和跨任务技能评估，进一步将这些工件视为可学习和可基准化的对象. Recent work further treats these artifacts as learnable and benchmarkable objects through experience-driven skill creation, context-engineering skill evolution, reusable procedural memory, and cross-task skill evaluation(Hao et al., 2026; Ye et al., 2026; Mi et al., 2026; Zhang et al., 2026; Li et al., 2026b)。 然而，他们建立的是可重用控制知识级别的可行性，而不是明确的可执行线束表示。 它们通常附加本地指令或可重用例程，但它们不会使线束范围的契约、角色边界、状态语义、故障处理和面向运行时的适配器成为一流的并且在共享运行时下联合可执行。 这种差距激发了我们的设置，而不是消除它：我们将自然语言从可重用过程的载体提升为显式的、可执行的工具对象。. What they establish, however, is feasibility at the level of reusable control knowledge, not an explicit executable harness representation. They typically attach local instructions or reusable routines, but they do not make harness-wide contracts, role boundaries, state semantics, failure handling, and runtime-facing adapters first-class and jointly executable under a shared runtime. This gap motivates our setting rather than closing it: we lift natural language from a carrier of reusable procedures to an explicit, executable harness object.

5 讨论Discussion

代码与自然语言。Code versus natural language.

我们并不认为自然语言应该取代代码。 相反，自然语言承载可编辑的高级控制逻辑，而代码仍然负责确定性操作、工具接口和沙箱执行。 科学主张是关于比较单元的：将线束模式逻辑外部化为共享运行时语义下的可读、可执行对象。We do not argue that natural language should replace code. Instead, natural language carries editable high-level harness logic, while code remains responsible for deterministic operations, tool interfaces, and sandbox enforcement. The scientific claim is about the unit of comparison: externalizing harness pattern logic as a readable, executable object under shared runtime semantics.

为什么自然语言仍然很重要。Why natural language still matters.

一个自然的担忧是更强大的基础模型是否会降低自然语言控制的价值。 根据经验，在某些情况下，复杂提示工程的收益可能会减少或变得脆弱A natural concern is whether stronger foundation models reduce the value of natural-language control. Empirically, gains from complex prompt engineering can diminish or become brittle in some settings(Wang et al., 2024a; Cao et al., 2024)。 然而，我们的结果支持对代理系统的不同解释：自然语言在用于指定时仍然很重要. However, our results support a different interpretation for agent systems: natural language remains important when used to specify线束级控制harness-level control——角色、契约、验证门、持久状态语义和委托边界——而不仅仅是一次性的提示措辞。 该框架与强调上下文工程和长期运行的线束设计的从业者的说法是一致的—roles, contracts, verification gates, durable state semantics, and delegation boundaries—rather than only one-shot prompt phrasing. This framing is consistent with practitioner accounts that emphasize context engineering and long-running harness design(Anthropic, 2025a, b; OpenAI, 2026a; LangChain, 2026b)。 它还与新兴的脚手架感知评估和线束综合研究兼容，这些研究将周围的控制堆栈视为评估系统的一部分. It is also compatible with emerging scaffold-aware evaluation and harness-synthesis research that treat the surrounding control stack as part of the system under evaluation(Ding et al., 2026; Lou et al., 2026; Chen et al., 2026b).

Longer term, this suggests automated search and optimization over harness representations rather than opaque bundle engineering, enabling harness engineering to become a more controlled scientific object.

7 结论Conclusion

我们研究线束设计模式层是否可以外部化为可执行的、可比较的和可消融的对象。 我们提出自然语言代理线束和智能线束运行时，直接在共享运行时语义下解释线束逻辑。 在当前的编码和计算机使用基准中，我们提供了受控证据，证明该堆栈在操作上可行，支持模块级组合和消融，并支持有意义的代码到文本利用迁移研究。 这些结果表明了一条通向线束表示科学的道路，其中线束模块成为一流的研究工件，而不是模型周围的偶然粘合剂。We study whether the harness design-pattern layer can be externalized as an executable, comparable, and ablatable object. We propose Natural-Language Agent Harnesses and an Intelligent Harness Runtime that interprets harness logic directly under shared runtime semantics. Across the current coding and computer-use benchmarks, we provide controlled evidence that this stack is operationally viable, enables module-level composition and ablation, and supports meaningful code-to-text harness migration studies. These results suggest a path toward harness representation science, where harness modules become first-class research artifacts rather than incidental glue around models.

局限性Limitations

自然语言不如代码精确，并且某些利用机制无法从文本中忠实恢复，特别是当它们依赖于隐藏的服务端状态、专有调度程序或无法从已发布的工件中观察到的训练引起的行为时。 运行时污染仍然是一个真正的风险：强大的共享运行时章程可能会吸收部分行为，否则这些行为可能归因于工具文本。 模块级消融并不是严格的因果识别；文本表示可能会带来混淆，例如指令的显着性和提示的长度。Natural language is less precise than code, and some harness mechanisms cannot be recovered faithfully from text, especially when they rely on hidden service-side state, proprietary schedulers, or training-induced behaviors not observable from released artifacts. Runtime contamination remains a real risk: a strong shared runtime charter may absorb part of the behavior that one might otherwise attribute to harness text. Module-level ablation is not strict causal identification; textual representations can introduce confounds such as instruction salience and prompt length.

更广泛的影响和风险Broader impact and risks

外部化线束模块可以降低开发成本，提高可比性，并鼓励重用强大的工作流程。 然而，可移植的线束逻辑和脚本也可以降低传播危险工作流程的障碍。 由于利用工具介导工具使用、工件处理和委托，因此它们可以引入新的攻击面，以实现快速注入、恶意工具移植或供应链污染。 部署应结合来源跟踪、审查、权限控制和沙箱隔离。Externalizing harness modules can reduce development cost, improve comparability, and encourage reuse of robust workflows. However, portable harness logic and scripts may also lower the barrier to spreading risky workflows. Because harnesses mediate tool use, artifact handling, and delegation, they can introduce new attack surfaces for prompt injection, malicious tool grafting, or supply-chain contamination. Deployments should combine provenance tracking, review, permission control, and sandbox isolation.
