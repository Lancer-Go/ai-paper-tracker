摘要Abstract

人工智能代理越来越多地执行知识工作（即，生成和修改持久性数字工件，例如代码存储库、文档、电子表格、幻灯片、报告），但他们搜索的解析视图、他们编辑的本机文件、他们审查的更改以及他们提交的工件可以引用同一工作产品的不同版本。我们将其表述为工作空间状态契约：每个视图都应该明确地与不断变化的工作空间状态的版本相关联。编码代理通过搜索、差异和测试的存储库合同部分满足了这一需求，而类似的合同对于 PDF、电子表格、幻灯片、笔记本和混合格式项目文件夹则不太明确。我们建议AI agents increasingly perform knowledge work (i.e., produce and modify persistent digital artifacts such as code repositories, documents, spreadsheets, slides, reports), yet the parsed views they search, the native files they edit, the changes they review, and the artifacts they submit can refer to different versions of the same work product. We formulate this as a workspace-state contract: every view should be explicitly tied to a version of the evolving workspace state. Coding agents partly address this need through repository contracts for search, diffs, and tests, whereas an analogous contract is less explicit for PDFs, spreadsheets, slides, notebooks, and mixed-format project folders. We propose暂存工作空间StagedWorkspace，知识工作代理的版本化工作区。工作区将解析的记录和审查差异绑定到本机文件更改时的内容哈希。在固定线束消融中, a versioned workspace for knowledge-work agents. The workspace binds parsed records and review diffs to content hashes of the native files as they change. In fixed-harness ablations onOfficeQA专业版OfficeQA Pro和andAPEX-代理APEX-Agents，双解析/本机访问对每个测试模型都有最高点估计；相对于限制性更强的单一视图，它将 OfficeQA Pass@1 提高了 8.3-12.1 分，APEX 平均评分提高了 4.7-9.2 分。, dual parsed/native access has the highest point estimate for every tested model; relative to the more limiting single view, it improves OfficeQA Pass@1 by 8.3–12.1 points and APEX mean rubric score by 4.7–9.2 points.SW代理SW-AgentGemini 3.1 Pro 在 OfficeQA 上的得分为 63.9%，GPT-5.4 Nano 在 APEX 上的得分为 42.1，而已发布的同型号得分分别为 29.3% 和 25.5。当差异可见时，对 57 个文件编辑任务的配对审查轴消融进一步发现了更高的观察到的分数。这些结果将工作空间状态识别为知识工作代理中的实验变量，并激发了对证据进行评分、分阶段编辑和提交工件作为显式状态转换的基准。scores 63.9% with Gemini 3.1 Pro on OfficeQA and 42.1 with GPT-5.4 Nano on APEX, compared with published same-model scores of 29.3% and 25.5, respectively. 1 简介Introduction

最近的大型语言模型（LLM）代理研究已经从孤立的纯文本任务转向基于数字工件的工作：编码代理修复存储库Recent large language model (LLM) agent research has moved from isolated text-only tasks toward work grounded in digital artifacts: coding agents repair repositories[12, 35]、文档和办公代理回答问题或编辑文件, document and office agents answer questions or edit files[28, 32]，以及网络、计算机使用和工作场所代理跨浏览器、桌面和企业工具进行操作, and web, computer-use, and workplace agents operate across browsers, desktops, and enterprise tools[33, 34]。这些设置有所不同，但它们有一个共同的目标：知识工作。经典的说法将知识工作定义为通过解释、判断和修正来产生或转换信息. These settings differ, but they share a target: knowledge work. Classic accounts define knowledge work as producing or transforming information through interpretation, judgment, and revision[6, 3]。正在关注. Following11，我们将编码、文档、办公室、网络和工作场所代理视为这一更广泛类别的分支，其中代理最终是根据其留下的工作产品来判断的。, we treat coding, document, office, web, and workplace agents as branches of this broader class, in which an agent is ultimately judged by the work product it leaves behind.

工作产品评估根据评分者或审阅者应用的标准来判断持久输出，例如答案、编辑或可交付成果Work-product evaluations judge persistent outputs such as answers, edits, or deliverables against criteria applied by a grader or reviewer[11, 22, 30]。代理还可以从一个工作簿版本中检索列定义，在其沙箱中编辑另一个版本，并提交与其使用的证据不一致的可交付成果。这激发了工作空间状态契约：解析的搜索、本机操作、审查和提交都必须识别它们公开或修改的工作空间版本。编码代理通过存储库签出部分实例化此类合同，使搜索、编辑和测试保持共享状态. An agent can otherwise retrieve a column definition from one workbook version, edit another version in its sandbox, and submit a deliverable inconsistent with the evidence it used. This motivates a workspace-state contract: parsed search, native operations, review, and submission must each identify the workspace version they expose or modify. Coding agents partly instantiate such a contract through a repository checkout that keeps search, edits, and tests in a shared state[12, 35]。非编码工作区接口并不总是公开等效的 合同，尽管他们的任务仍然需要源代码阅读、混合格式的项目工作和具体化的可交付成果. Non-coding workspace interfaces do not always expose an equivalent contract, even though their tasks still require source reading, mixed-format project work, and materialized deliverables[22, 30, 29]。如果没有该合同，解析的搜索、本机编辑和提交的文件可能会漂移到同一工作产品的不同版本。. Without that contract, parsed search, native edits, and the submitted file can drift to different versions of the same work product.

对这样一个合约的需求源于三个反复出现的接口权衡。首先，仅包含工件的系统保留了完整的本机工件，但使搜索变得困难，迫使代理翻阅大型文件并携带不相关的上下文。其次，仅解析的系统支持搜索，但可能会丢失布局层次结构、公式和视觉证据。第三，无版本控制的可变工作空间允许代理覆盖、移动或删除文件，而无需模型或人工审核的持久差异。这些权衡共同激发了两个可分离的接口需求：与显式文件版本相关的互补的解析视图和本机视图，以及对提交状态更改的可审查记录。The need for such a contract arises from three recurring interface trade-offs. First, artifact-only systems preserve complete native artifacts but make search difficult, forcing agents to page through large files and carry irrelevant context. Second, parsed-only systems support search but can lose layout hierarchy, formulas, and visual evidence. Third, an unversioned mutable workspace lets an agent overwrite, move, or delete files without a durable diff for model or human review. Together, these trade-offs motivate two separable interface requirements: complementary parsed and native views tied to explicit file versions, and a reviewable record of changes to the submitted state.
