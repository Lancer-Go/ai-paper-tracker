ANX：用于 AI 代理交互的协议优先设计以及支持的 3EX 解耦架构ANX: Protocol-First Design for AI Agent Interaction with a Supporting 3EX Decoupled Architecture

Xu Mingze
Hangzhou Ziyou Data Technology Co., Ltd., Hangzhou 310000, China
mountcoding@gmail.com
（2026 年 4 月 4 日）(April 4th, 2026)
摘要Abstract

人工智能代理，自主数字参与者，需要代理本机协议；现有的方法包括GUI自动化和基于MCP的技术，由于缺乏统一的顶层框架和关键组件，各个独立模块存在缺陷，因此存在代币消耗高、交互碎片化、安全性不足的缺陷。针对这些问题，我们提出了ANX，一个开放的、可扩展的、可验证的代理原生协议和集成CLI、Skill、MCP的顶级框架，通过协议创新、架构优化和工具补充来解决痛点。其四大核心创新点：1）Agent原生设计（ANX Config、Markup、CLI），信息密度高、灵活性强、适应性强，减少代币、消除不一致； 2) 人机交互结合了 Skill 的双重渲染灵活性，作为代理可执行指令和人类可读的 UI； 3）MCP支持的轻量级应用点播，无需预注册； 4) 支持 ANX 标记的机器可执行 SOP，消除了可靠的长期任务和多代理协作的歧义。作为系列的第一篇，我们重点介绍 ANX 的设计，展示其与 ANXHub 的 3EX 解耦架构以及初步的可行性分析和实验验证。 ANX 确保本机安全：绕过 LLM 的 UI 到核心通信使敏感数据脱离代理上下文；仅由人工确认可防止自动误用。使用 Qwen3.5-plus/GPT-4o 进行的表单填写实验表明，与基于 MCP 的技能相比，ANX 减少了 47.3% (Qwen3.5-plus) 和 55.6% (GPT-4o) 的令牌，与 GUI 自动化相比减少了 57.1% (Qwen3.5-plus) 和 66.3% (GPT-4o)，并将执行时间缩短了 58.1% 和 57.7%基于 MCP 的技能。AI agents, autonomous digital actors, need agent-native protocols; existing methods include GUI automation and MCP-based skills, with defects of high token consumption, fragmented interaction, inadequate security, due to lacking a unified top-level framework and key components, each independent module flawed. To address these issues, we present ANX, an open, extensible, verifiable agent-native protocol and top-level framework integrating CLI, Skill, MCP, resolving pain points via protocol innovation, architectural optimization and tool supplementation. Its four core innovations: 1) Agent-native design (ANX Config, Markup, CLI) with high information density, flexibility and strong adaptability to reduce tokens and eliminate inconsistencies; 2) Human-agent interaction combining Skill’s flexibility for dual rendering as agent-executable instructions and human-readable UI; 3) MCP-supported on-demand lightweight apps without pre-registration; 4) ANX Markup-enabled machine-executable SOPs eliminating ambiguity for reliable long-horizon tasks and multi-agent collaboration. As the first in a series, we focus on ANX’s design, present its 3EX decoupled architecture with ANXHub and preliminary feasibility analysis and experimental validation. ANX ensures native security: LLM-bypassed UI-to-Core communication keeps sensitive data out of agent context; human-only confirmation prevents automated misuse. Form-filling experiments with Qwen3.5-plus/GPT-4o show ANX reduces tokens by 47.3% (Qwen3.5-plus) and 55.6% (GPT-4o) vs MCP-based skills, 57.1% (Qwen3.5-plus) and 66.3% (GPT-4o) vs GUI automation, and shortens execution time by 58.1% and 57.7% vs MCP-based skills.

1 简介Introduction

1.1 背景和问题陈述Background and Problem Statement

人工智能代理正日益成为自主的、目标驱动的实体，能够代表人类执行复杂的数字任务，将它们定位为下一代核心互联网用户。这种范式转变需要代理与本机交互框架，而不是传统的以人为中心的范式。然而，现有的方法仍然是支离破碎的，没有一个统一的顶层架构来将它们编排成一个连贯的生态系统——ANX（AI Native eX）协议解决了一个关键的研究空白：一个整体的代理原生框架，旨在在单一系统范式下管理、统一和提升 GUI 自动化、MCP、技能系统和 CLI 执行。AI agents are increasingly emerging as autonomous, goal-driven entities capable of performing complex digital tasks on behalf of humans, positioning them as the next generation of core internet users. This paradigm shift demands agent-native interaction frameworks rather than the traditional human-centric paradigms. However, existing approaches remain fragmented without a unified top-level architecture to orchestrate them into a coherent ecosystem—a critical research gap addressed by the ANX (AI Native eX) protocol: a holistic agent-native framework designed to govern, unify, and elevate GUI automation, MCP, skill systems, and CLI execution under a single systematic paradigm.

图形用户界面（GUI）本质上是人工设计的，当代理自动化时，会产生高昂的代币成本、较差的可扩展性以及固有的安全缺陷。 MCP 和基于技能的 CLI 提供了渐进式改进，但存在核心限制：预安装要求、没有即用即用功能、分离的人机交互渠道、过度依赖有限的 Markdown、缺乏统一的结构化格式和敏感数据控制机制。最近基于 CLI 的探索，例如 OpenCLI（Kasibatla 等人，2025）和 SkillWeaver（Zheng 等人，2025）仍然以浏览器为中心，受到 DOM 脆弱性、页面加密解析障碍、更新引起的延迟以及不方便的设备绑定敏感数据输入的困扰，从而损害了可用性和安全性。Graphical user interfaces (GUIs), human-designed by nature, incur exorbitant token costs, poor scalability, and inherent security flaws when automated for agents. MCP and skill-based CLIs offer incremental improvements but suffer from core limitations: pre-installation requirements, no use-and-go capability, separated human-agent interaction channels, overreliance on limited Markdown, and the lack of unified structured formats and sensitive data control mechanisms. Recent CLI-based explorations such as OpenCLI (Kasibatla et al., 2025) and SkillWeaver (Zheng et al., 2025) still remain browser-centric, plagued by DOM fragility, parsing barriers from page encryption, update-induced latency, and inconvenient device-bound sensitive data entry, compromising both usability and security.

自然语言的歧义进一步破坏了复杂标准操作程序（SOP）中基于LLM的执行的稳定性。思想链（Wei et al., 2022）未能解决这种歧义，而验证链（Dhuliawala et al., 2024）只能以额外的代币开销为代价来减少幻觉，而没有消除对非结构化自然语言的依赖。尽管人工智能代理在日常任务执行方面优于人类（Wang et al., 2025），但其纯粹的编程方法缺乏质量，并且无法支持长期、多步骤的 SOP 调度和多代理协作——实际部署的关键能力。Natural language ambiguity further undermines the stability of LLM-based execution in complex standard operating procedures (SOPs). Chain-of-Thought (Wei et al., 2022) fails to resolve this ambiguity, while Chain-of-Verification (Dhuliawala et al., 2024) reduces hallucinations only at the cost of additional token overhead, without eliminating reliance on unstructured natural language. Although AI agents outperform humans in routine task execution (Wang et al., 2025), their purely programmatic approaches lack quality and fail to support long-horizon, multi-step SOP scheduling and multi-agent collaboration—key capabilities for practical deployment.

最关键的是，在现有范例中，安全性并未被视为首要问题。正如 Rosenberg 等人所证明的那样，敏感数据（例如密码、财务信息）必须遍历代理的上下文，从而产生固有的隐私风险和泄漏漏洞。 （2025）银行代理人幻觉事件。虽然语义工具发现（Mudunuri 等人，2026）和基于 CLI 的界面（Gao 等人，2026）等最近的优化提高了效率，但它们仍然是零碎的解决方案，无法同时解决代理交互的效率、安全性和语义精度的核心挑战。Most critically, security is not treated as a first-class concern in existing paradigms. Sensitive data (e.g., passwords, financial information) must traverse the agent’s context, creating inherent privacy risks and leakage vulnerabilities, as demonstrated by Rosenberg et al. (2025) in banking agent hallucination incidents. While recent optimizations like semantic tool discovery (Mudunuri et al., 2026) and CLI-based interfaces (Gao et al., 2026) boost efficiency, they remain piecemeal solutions that cannot simultaneously address the core challenges of efficiency, security, and semantic precision for agent interaction.

ANX 作为一种集成、协调和超越这些孤立工具的高阶架构范例填补了这一空白。 ANX将GUI、MCP、CLI和技能系统视为功能执行单元，作为统一的治理框架，解决其各自的局限性，实现系统、安全、高效的大规模代理交互。ANX fills this void as a higher-order architectural paradigm that integrates, coordinates, and transcends these isolated tools. Treating GUI, MCP, CLI, and skill systems as functional execution units, ANX acts as a unifying governance framework that resolves their individual limitations, enabling systematic, secure, and efficient large-scale agent interaction.

3.3 安全机制Security Mechanisms

ANX 通过嵌入其 3EX 架构和状态机中的两个核心、非重叠机制确保安全代理交互：敏感数据隔离和关键操作的人工验证。未来的扩展将通过加密的核心存储和 CLI 请求支持低敏感度自动化，而高敏感度数据和关键确认仍然是人类独有的。ANX ensures secure agent interaction through two core, non‑overlapping mechanisms embedded in its 3EX architecture and state machine: sensitive data isolation and human validation of critical operations. Future extensions will support low‑sensitivity automation via encrypted Core storage and CLI requests, while high‑sensitivity data and critical confirmations remain human‑exclusive.

3.3.1 UI 到核心敏感数据隔离UI‑to‑Core Sensitive Data Isolation

ANX通过架构设计实现了严格的敏感数据隔离：当ANX Markup将字段标记为敏感时，ANX UI会生成专用表单，通过加密通信将敏感信息传输到ANX Core，有效避免中间数据被LLM劫持的风险。此外，当 LLM 请求从 ANX Core 查看 ANX 标记时，Core 会自动屏蔽标记中的所有敏感信息，确保 LLM 仅访问非敏感内容。代理仅接收非敏感参考令牌，加密传输进一步增强了数据机密性。ANX achieves strict sensitive data isolation by architectural design: when ANX Markup marks fields as sensitive, ANX UI generates dedicated forms that transmit sensitive information to ANX Core via encrypted communication, effectively avoiding the risk of intermediate data being hijacked by the LLM. Additionally, when the LLM requests to view ANX Markup from ANX Core, the Core automatically shields all sensitive information in the markup, ensuring the LLM only accesses non‑sensitive content. The agent receives only a non‑sensitive reference token, with encrypted transmission further enhancing data confidentiality.

3.3.2 仅限人类确认Human‑Only Confirmation

在敏感数据隔离机制的基础上，ANX通过支持指定人为专属完成，进一步保证敏感操作的安全。为了防止LLM模拟人为操作和未经授权的执行，ANX构建了一个可信对话框，直接连接到ANXHub以获取用户令牌——该用户令牌由ANX UI独家管理，并且对LLM完全不可见。当针对敏感操作发起人工验证请求时，必须携带有效的用户令牌；只有ANX Handler验证用户Token的合法性后，才会执行敏感操作。该机制集成到协议的确认状态（无程序退出）中，确保不存在代理可访问的旁路，并且用户保留对高风险操作的绝对控制。Building on the sensitive data isolation mechanism, ANX further ensures the security of sensitive operations by supporting the designation of human‑exclusive completion. To prevent the LLM from simulating human operations and unauthorised execution, ANX constructs a trusted dialog box that connects directly to ANXHub to obtain a User Token – this User Token is exclusively managed by ANX UI and remains completely invisible to the LLM. When a Human‑Validated Request is initiated for sensitive operations, it must carry the valid User Token; only after ANX Handler verifies the legitimacy of the User Token will the sensitive operation be executed. This mechanism is integrated into the protocol’s CONFIRMING state (with no programmatic exit), ensuring no agent‑accessible bypass exists and users retain absolute control over high‑risk actions.

5.2 讨论Discussion

表 10 和表 11 中的结果表明，在职位登记表填写任务方面，ANX 相对于基于 MCP 的技能和 GUI 自动化具有明显的效率优势。The results in Tables 10 and 11 demonstrate clear efficiency advantages of ANX over both the MCP‑based Skill and GUI automation for the job account registration form‑filling task.

代币消耗。Token consumption.与基于 MCP 的技能相比，ANX 将任务增量令牌消耗减少了 47.3% (Qwen3.5-plus) 和 55.6% (GPT-4o)，与 GUI 相比减少了 57.1% 和 66.3%。主要原因是 ANX 将表单渲染和动态选项解析委托给 ANX Core 和 CLI 层，而不是强制 LLM 处理这些细节。在 GUI 基线中，LLM 必须处理整个 DOM 树并生成低级浏览器操作（单击、按键），从而导致高令牌使用率。基于 MCP 的技能通过使用声明性工具模式改进了 GUI，但它仍然需要 LLM 主动加载和传递动态选项集（例如，来自远程数据集的行业下拉列表）作为工具调用有效负载的一部分。 ANX 通过在 ANX 标记中仅指定 URL 来避免这种情况； ANX Core 在执行时自动获取选项，消除动态数据加载的令牌开销。这一优势在两种法学硕士模式中都是一致的。ANX reduces task‑incremental token consumption by 47.3% (Qwen3.5‑plus) and 55.6% (GPT‑4o) compared to the MCP‑based Skill, and by 57.1% and 66.3% compared to GUI. The primary reason is that ANX delegates form rendering and dynamic option resolution to ANX Core and the CLI layer, rather than forcing the LLM to handle these details. In the GUI baseline, the LLM must process the entire DOM tree and generate low‑level browser actions (clicks, key presses), leading to high token usage. The MCP‑based Skill improves over GUI by using a declarative tool schema, but it still requires the LLM to actively load and pass dynamic option sets (e.g., the industry dropdown from a remote dataset) as part of the tool call payload. ANX avoids this by specifying only a URL in the ANX Markup; ANX Core automatically fetches the options at execution time, eliminating token overhead for dynamic data loading. This advantage is consistent across both LLM models.

执行时间。Execution time.ANX 还实现了最低的端到端执行时间：12.9 s (Qwen) 和 16.5 s (GPT-4o)，而基于 MCP 的技能为 30.8 s 和 39.0 s，GUI 为 33.2 s 和 48.2 s。 GUI 基线受到缓慢的 DOM 解析、顺序元素交互和页面加载等待的影响。基于 MCP 的技能通过绕过视觉渲染来减少时间，但仍然会因序列化和传输完整的 JSON 负载（包括动态加载的选项）而产生开销。 ANX 的 CLI 执行和直接 ANX 节点调用最大限度地减少了序列化开销，并消除了动态选项获取的往返，因为核心在本地处理解​​析。ANX also achieves the lowest end‑to‑end execution time: 12.9 s (Qwen) and 16.5 s (GPT‑4o), compared to 30.8 s and 39.0 s for the MCP‑based Skill, and 33.2 s and 48.2 s for GUI. The GUI baseline suffers from slow DOM parsing, sequential element interaction, and page load waits. The MCP‑based Skill reduces time by bypassing visual rendering, but still incurs overhead from serializing and transmitting the full JSON payload, including dynamically loaded options. ANX’s CLI execution and direct ANX Node invocation minimize serialization overhead and eliminate round‑trips for dynamic option fetching, as the Core handles resolution locally.

跨模型的通用性。Generality across models.Qwen3.5-plus 和 GPT-4o 的相对效率增益相似，表明 ANX 的架构（而不是特定于模型的优化）是驱动因素。The relative efficiency gains are similar for Qwen3.5‑plus and GPT‑4o, indicating that ANX’s architecture—not model‑specific optimization—is the driving factor.

准确性考虑。Accuracy considerations.虽然我们在此评估中重点关注效率指标，但 ANX 的结构化语义也有助于提高任务完成的准确性。清晰的机器可执行 ANX 标记消除了自然语言歧义，降低了执行错误的可能性。这对于具有多个步骤或条件逻辑的复杂任务尤其重要。While we focused on efficiency metrics in this evaluation, ANX’s structured semantics also contribute to improved task completion accuracy. The clear, machine‑executable ANX Markup eliminates natural language ambiguity, reducing the likelihood of execution errors. This is particularly important for complex tasks with multiple steps or conditional logic.

实际意义。Practical implications.令牌效率的提高直接转化为成本节省，特别是对于 GPT‑4o 等模型，其中令牌的使用是一个重要的成本因素。此外，执行时间的缩短通过提供更快的任务完成来改善用户体验，这对于交互式应用程序至关重要。The token efficiency gains translate directly to cost savings, especially for models like GPT‑4o where token usage is a significant cost factor. Additionally, the reduced execution time improves user experience by providing faster task completion, which is crucial for interactive applications.

总之，对于具有动态选项的评估表单填写场景，ANX 结合了结构化标记 (ANX Markup)、解耦执行 (3EX) 和基于 CLI 的命令生成，在令牌效率和运行时方面提供了显着改进。其优势在于将动态数据解析从 LLM 上下文转移到执行层，这种设计避免了基于 MCP 的技能所需的预加载和主动选项处理。In summary, for the evaluated form‑filling scenario with dynamic options, ANX’s combination of structured markup (ANX Markup), decoupled execution (3EX), and CLI‑based command generation delivers substantial improvements in both token efficiency and runtime. The advantage is rooted in shifting dynamic data resolution from the LLM’s context to the execution layer, a design that avoids the pre‑loading and active option handling required by the MCP‑based Skill.

本文是ANX（AI Native eX）系列的第一篇，重点介绍核心协议设计和3EX解耦架构。作为本系列的首部作品，它通过提出一个全面的框架来解决人工智能代理系统中效率、安全性和协作的关键挑战，为代理与本机交互奠定了基础。This paper represents the first in the ANX (AI Native eX) series, focusing on introducing the core protocol design and 3EX decoupled architecture. As the inaugural work in this series, it lays the foundation for agent-native interaction by presenting a comprehensive framework that addresses the key challenges of efficiency, security, and collaboration in AI agent systems.

ANX (AI Native eX) 是一个三层协议架构，引入了 3EX (Expression-Exchange-Execution) 解耦框架，将任务规范、工具发现和执行分离到独立的层中。该架构基础实现了三项核心创新：ANX (AI Native eX) is a three-layer protocol architecture that introduces the 3EX (Expression-Exchange-Execution) decoupled framework—separating task specification, tool discovery, and execution into independent layers. ANX 为人机协作场景中的 AI 代理部署提供了可扩展、安全、经济高效的基础。现阶段，实验验证仅限于数据集受限的特定任务场景，仍需要进一步大规模评估来验证协议在复杂的跨平台环境中的稳定性和效率。ANX provides a scalable, secure, cost-effective foundation for AI agent deployment in human-machine collaboration scenarios. At this stage, experimental validation is limited to specific task scenarios with a constrained dataset, and further large-scale evaluations are still needed to verify the protocol’s stability and efficiency in complex, cross-platform environments.

6.2 未来的工作Future Work

我们提出并初步论证了 ANX 框架的可行性，我们很高兴与社区分享。然而，我们承认需要更多的工作和更严格的实验来充分验证其功能。展望未来，我们将重点关注以下七个关键方向来解决这些限制并进一步推进 ANX 协议：We have proposed and initially demonstrated the feasibility of the ANX framework, and we are excited to share it with the community. However, we acknowledge that more work and more rigorous experiments are needed to fully validate its capabilities. Moving forward, we will focus on the following seven key directions to address these limitations and further advance the ANX protocol:

• 多代理协调Multi-Agent Coordination– 扩展到混合协议（Dochkina，2026）并结合动态代理消除（Wang 等人，2025）以优化令牌效率和任务性能。我们当前的 ANXHub 实现了任务路由原语；与多个代理的全面评估留待将来的工作。– Extend to hybrid protocols (Dochkina, 2026) and incorporate dynamic agent elimination (Wang et al., 2025) to optimize token efficiency and task performance. Our current ANXHub implements task routing primitives; full evaluation with multiple agents is left for future work.

• 敏感数据和敏感运筹学Sensitive Data and Sensitive Operation Research– 通过系统实验（例如对抗性攻击、信息泄漏测试）进一步研究 ANX 的 UI 到核心隔离和仅限人类的确认机制。通过解决 UI 欺骗、不受信任的 Core/Hub 和 LLM 引发的社会工程等剩余漏洞来增强安全性。探索安全性和可用性之间的权衡：评估人工确认和敏感字段编辑的开销，并设计自适应策略，减少用户摩擦，同时保持对高风险操作的强有力保证。– Further investigate ANX’s UI-to-Core isolation and human-only confirmation mechanisms through systematic experiments (e.g., adversarial attacks, information leakage tests). Strengthen security by addressing remaining vulnerabilities such as UI spoofing, untrusted Core/Hub, and LLM-induced social engineering. Explore the trade-off between security and usability: evaluate the overhead of human confirmations and sensitive field redaction, and design adaptive policies that reduce user friction while maintaining strong guarantees for high-risk operations.

• ANXHub 与 SkillHub 发现和下载ANXHub vs. SkillHub Discovery and Download– 在四个关键维度上对 ANXHub（动态市场、即用即用、无需安装）和传统 SkillHub / MCP 式工具索引（预注册、本地二进制文件）进行系统比较：及时性（冷启动延迟、更新传播）、安全性（供应链攻击、病毒风险、依赖漏洞）、便利性（零安装与预下载、动态与静态发现）以及代币消耗（ANXHub 中的渐进披露与预加载） SkillHub 中的架构）。在实际网络条件、不同技能库大小和并发请求场景下进行评估，以量化 ANX 交换层的实际优势。– Conduct a systematic comparison between ANXHub (dynamic marketplace, use-and-go, no installation) and traditional SkillHub / MCP-style tool indices (pre-registration, local binaries) across four key dimensions: timeliness (cold-start latency, update propagation), security (supply chain attacks, virus risks, dependency vulnerabilities), convenience (zero-install vs. pre-download, dynamic vs. static discovery), and token consumption (progressive disclosure in ANXHub vs. pre-loaded schemas in SkillHub). Evaluate under realistic network conditions, varying skill library sizes, and concurrent request scenarios to quantify the practical advantages of ANX’s Exchange layer.

• 企业AI载体&弱去中心化ANXHubEnterprise AI Carrier & Weakly-Decentralized ANXHub– 研究基于AI运营商的企业架构，使组织能够通过联合信任模型、多Hub信任策略和语义发现优化来部署自己的ANXHub实例，实现弱中心化，同时减少对单个官方Hub的依赖。– Investigate AI Carrier-based enterprise architecture, enabling organizations to deploy their own ANXHub instances with federated trust models, multi-Hub trust policies, and semantic discovery optimization, achieving weak centralization while reducing dependency on a single official Hub.

• 复杂且计算密集的场景Complex and Compute-Intensive Scenarios– 扩展ANX以处理更复杂的任务图（例如，具有嵌套分支的50+步骤）和计算密集型场景（例如，实时数据处理、大规模模拟），评估3EX架构在高负载下的可扩展性和资源效率。– Extend ANX to handle more complex task graphs (e.g., 50+ steps with nested branches) and compute-intensive scenarios (e.g., real-time data processing, large-scale simulations), evaluating the scalability and resource efficiency of the 3EX architecture under high load.

• 技能成长Skill Growing– 与技能增长范式集成（Chen 等人，2026），以实现自适应技能学习和动态模式演化。– Integrate with skill-growing paradigms (Chen et al., 2026) to enable adaptive skill learning and dynamic schema evolution.

• 可追溯性Traceability– 开发更丰富的可追溯机制（Peng，2026）来跟踪交互生命周期并实现监管合规性的可审计性。– Develop richer traceability mechanisms (Peng, 2026) to track interaction lifecycles and enable auditability for regulatory compliance.

• ANX 协议的轻量级专用模型Lightweight Specialized Models for ANX Protocol– 随着 API 调用微调模型的成功（Gorilla、Patil 等人，2024 年），我们计划训练专门用于 ANX 协议任务的较小模型（例如，ANX 标记到 CLI 编译），从而实现更低成本的部署和更快的推理。– Following the success of fine-tuned models for API calling (Gorilla, Patil et al., 2024), we plan to train smaller models specialized for ANX protocol tasks (e.g., ANX Markup to CLI compilation), enabling lower-cost deployment and faster inference.
