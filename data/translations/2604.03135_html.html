人工智能辅助单元测试编写和测试驱动代码重构：案例研究AI-Assisted Unit Test Writing and Test-Driven Code Refactoring: A Case Study

Ema Smolić1, Mario Brčić12, Luka Hobor2, Mihael Kovač2 mario.brcic@fer.hr
摘要Abstract

许多软件系统最初都是原型或最小可行产品（MVP），开发时重点关注交付速度和对不断变化的需求的响应能力，而不是长期代码可维护性。虽然这种方法对于快速交付有效，但可能会导致代码库难以修改，从而在人工智能辅助甚至人工智能主导的编程时代带来巨大的机会成本。在本文中，我们提出了一个使用编码模型进行自动单元测试生成和随后的安全重构的案例研究，并通过通过测试验证了建议的代码更改。该研究探讨了迭代生成测试以捕获现有系统行为的最佳实践，然后在开发人员的监督下进行模型辅助重构。我们描述了这个工作流程如何限制重构变化、在两个阶段观察到的错误和限制、在需要手动干预时实现的效率增益，以及我们如何解决在模型中观察到的弱值错位。使用这种方法，我们在数小时而不是数周内生成了近 16,000 行可靠的单元测试，在关键模块中实现了高达 78% 的分支覆盖率，并显着降低了大规模重构期间的回归风险。这些结果说明了软件工程向实证科学的转变，强调支持快速、安全迭代的数据收集和约束机制。Many software systems originate as prototypes or minimum viable products (MVPs), developed with an emphasis on delivery speed and responsiveness to changing requirements rather than long-term code maintainability. While effective for rapid delivery, this approach can result in codebases that are difficult to modify, presenting a significant opportunity cost in the era of AI-assisted or even AI-led programming. In this paper, we present a case study of using coding models for automated unit test generation and subsequent safe refactoring, with proposed code changes validated by passing tests. The study examines best practices for iteratively generating tests to capture existing system behavior, followed by model-assisted refactoring under developer supervision. We describe how this workflow constrained refactoring changes, the errors and limitations observed in both phases, the efficiency gains achieved, when manual intervention was necessary, and how we addressed the weak value misalignment we observed in models. Using this approach, we generated nearly 16,000 lines of reliable unit tests in hours rather than weeks, achieved up to 78% branch coverage in critical modules, and significantly reduced regression risk during large-scale refactoring. These results illustrate software engineering’s shift toward an empirical science, emphasizing data collection and constraining mechanisms that support fast, safe iteration.

I 简介Introduction

许多软件系统都是从原型或最小可行产品 (MVP) 开始的，它们针对速度而不是长期可维护性进行了优化。不断变化的需求和快速的功能集成通常会导致代码库在结构和最佳实践编码方面不太理想。随着这些代码库的成熟，技术债务可能会将微小的变化变成复杂的问题，阻碍进一步的开发。在人工智能辅助（甚至人工智能主导）编程的时代，这个问题变得更加明显。由于编码模型在可预测的、先前见过的环境中表现最佳，因此组织不良的代码会限制其有效性。这带来了机会成本Many software systems begin as prototypes or minimum viable products (MVPs), which are optimized for speed rather than long-term maintainability. Shifting requirements and rapid feature integration often result in codebases that are less than optimal in terms of structure and best-practice coding. As these codebases mature, technical debt may turn small changes into complex problems, hindering further development. This issue becomes even more pronounced in the age of AI-assisted (or even AI-led) programming. Since coding models perform best in predictable, previously seen environments, poorly organized code limits their effectiveness. That presents an opportunity cost[20]必须通过重构来缓解。如果重构是实现可维护性的最快途径，那么测试就是使其变得可行的安全机制，尤其是当代码更改自动化时。which must be mitigated through refactoring. If refactoring is the fastest path to maintainability, then tests are the safety mechanism that makes it feasible, especially when code changes are automated.

测试作为可执行的规范和护栏，限制代码重构期间的性能回归和错误引入Tests serve as executable specifications and guardrails, limiting performance regressions and bug introductions during code refactoring[9]。研究表明法学硕士可以比其他自动化测试生成解决方案更有效地编写测试. Research shows that LLMs can write tests more effectively than other automated test generation solutions[19]。虽然研究概述了覆盖上限和脆弱性等一些问题，但他们也通过相对简单的技术（例如更好的提示策略）提出了解决方案. While studies outline some issues such as coverage ceilings and brittleness, they also propose solutions through relatively simple techniques such as better prompting strategies[14, 18, 6, 13].

同样，法学硕士可以有效地重构代码，从而带来可衡量的改进。它们已被证明可以降低复杂性和行数Likewise, LLMs can refactor code effectively, leading to measurable improvements. They have been shown to reduce complexity and line count[21, 22]。然而，LLM也容易产生幻觉，这可能会导致错误引入。为了解决这个问题，研究人员提出了人机交互工作流程. However, LLMs are also prone to hallucinations, which may result in error introduction. To address this issue, researchers propose human-in-the-loop workflows[7, 12]。在这项工作中，我们探索自动化测试是否可以达到这个目的。. In this work, we explore whether automated tests can serve this purpose instead.

该实验的动机是一个最初作为 MVP 的生产现实世界系统。为了促进基于人工智能的开发，需要进行重构。该系统缺乏全面的测试套件，使得此类重构存在风险。由于人类开发人员的重构成本太高，我们选择使用法学硕士。我们希望探索单一集成工作流程的可行性，其中法学硕士 (1) 构建全面的行为捕获测试套件，然后 (2) 使用该套件在成熟的商业代码库中约束和验证模型辅助重构。This experiment is motivated by a production, real-world system that originated as an MVP. To facilitate AI-based development, it needed a refactor. The system lacked a comprehensive test suite, making such refactors risky. Since refactoring by human developers would be too costly, we chose to use LLMs. We wanted to explore the feasibility of a single integrated workflow where LLMs (1) build a comprehensive, behavior-capturing test suite, and then (2) use that suite to constrain and validate model-assisted refactoring in a mature commercial codebase.

在本文中，我们提出了一个案例研究，评估人工智能辅助单元测试生成是否能够有效地捕获现有行为，以实现安全、大规模的重构（同样由模型主导）。我们发现确实可行。我们详细描述了工作流程，以帮助在其他系统中复制并为类似方法提供最佳实践。记录了两个阶段的常见故障模式，并在定性分析的同时对结果进行了量化。In this paper, we present a case study evaluating whether AI-assisted unit test generation can efficiently capture existing behavior well enough to enable safe, large-scale refactoring, also led by a model. We find that it is indeed feasible. We describe the workflow in detail to aid replication in other systems and to inform best practices for similar approaches. Common failure modes in both phases are documented, and outcomes are quantified alongside qualitative analysis.

软件开发中的测试不仅被认为是确保代码按预期运行的一种手段，而且也是变革的推动者。它们充当代码修改的护栏，通过表明系统仍然符合规范。类似地，测试被描述为Tests in software development are considered not only a means of assurance that code behaves as expected, but also an enabler of change. They serve as guardrails for code modification, with passing indicating the system remains aligned with the specifications. Similarly, tests have been described as可执行规范executable specifications，桥接静态文档/规范和动态、实时代码状态反馈的概念。由于这些好处，它们被广泛用于代码重构，以确保修改不会破坏当前行为, bridging the concepts of static documentation/specification and dynamic, real-time feedback on code status. Due to these benefits, they are widely used in code refactoring to ensure that modifications do not break current behavior[9].

重构过程中常见的问题包括引入错误和导致回归。研究表明，超过一半的引发错误的提交还包含重构更改Common concerns during the refactoring process include introducing bugs and causing regressions. Ⅲ-BIII-B 模型和工具Models and Tooling

该工作流程采用分层、多代理方法来平衡推理深度和执行速度。 “规划器”模型是 Gemini 2.5 Pro，可通过 Gemini CLI 访问。选择该模型是因为其大型上下文窗口，这使得它能够立即处理整个前端代码库，以识别跨模块依赖关系并计划重构步骤。 “执行者”模型负责重复测试实施和本地化重构，由Cursor在自动模式下的集成模型组合而成。The workflow employed a hierarchical, multi-agent approach to balance reasoning depth with execution speed. The "planner" model was Gemini 2.5 Pro, accessed via the Gemini CLI. This model was selected for its large context window, which allowed it to process the entire frontend codebase at once to identify cross-module dependencies and plan refactoring steps. The "executor" models, responsible for repetitive test implementation and localized refactoring, consisted of a combination of Cursor’s integrated models in Auto mode.

This approach ensured that even when an executor model operated on a narrow, file-specific scope, it remained constrained by global architectural rules and naming conventions. The core architectural constraints and generative guidelines were captured in persistent, version-controlled rule and planning files, whose structure is described below.

内部效度Internal validity

内部有效性的主要威胁是我们尚未识别的残值失调。该方法对持久配置文件的依赖（The main threat to internal validity is residual value misalignment that we have not yet identified. The methodology’s reliance on persistent configuration files (GEMINI.md, .cursorrules）和版本化的 Markdown 计划确保核心生成约束被记录下来。该测试套件通过现有源代码进行验证，并克服模型工具中的选择压力，使工作与软件工程的最佳实践保持一致。然而，在我们没有在工具或目标中指定或衡量的一些重要方面，代码库质量很可能没有提高甚至下降。在整个过程中，我们相对于起点迭代地扩展了我们考虑的标准和指标。) and versioned Markdown plans ensures that the core generative constraints are documented. The test suite was validated by passing against existing source code and by surviving selection pressure in the model harness, aligning the work with software engineering’s best practices. However, it is quite possible that codebase quality did not improve or even degraded on some important aspects that we did not specify or measure in the harness or objectives. We iteratively extended our criteria and metrics considered relative to the starting point throughout the procedure.

Replication across diverse settings — particularly traditional object-oriented backends and legacy systems — is needed to establish broader applicability.

Test quality was assessed through branch and line coverage, following constraint satisfaction on test effectiveness.

七VII结论和进一步研究Conclusion and Further Research

总而言之，实验的第一步通过大型、结构化、基础设施支持的单元测试套件丰富了未经测试的代码库。它引入了跨核心架构领域的数百个测试用例。生成的测试套件遵循最佳实践，特别是通过支持重用和稳定性的大量共享基础设施。To sum up, the first step of the experiment enriched an undertested codebase with a large, structured, infrastructure-backed unit test suite. It introduced hundreds of test cases across core architectural areas. The generated test suite followed best practices, especially through substantial shared infrastructure that supports reuse and stability.

另一方面，重构步骤将组织不良的 MVP 转变为模块化程度更高的分层架构。虽然总体源代码大小适度增长，但主要影响是将逻辑从路由文件重新分配到专用功能层和共享层。重构涉及大量文件重定位和选择性重写，但它保留了外部可观察的行为。基于 AST 的分析证实，所得结构减少了耦合（路由层中的导入减少了 57.5%），降低了平均圈复杂度（2.24 至 2.13），并为进一步开发提供了更可维护的基础。未来的工作应该在不同的技术堆栈中复制该方法。 此外，它应该创建最佳实践目录以及不同的重要质量指标及其阈值。这应该有助于缓解价值错位On the other hand, the refactor step transformed a poorly-organized MVP into a layered architecture with improved modularity. While the overall source code size grew moderately, the dominant effect was a redistribution of logic from routing files into dedicated feature and shared layers. The refactor involved extensive file relocation and selective rewriting, yet it preserved externally observable behavior. AST-based analysis confirms that the resulting structure reduces coupling (57.5% fewer imports in the routing layer), lowers average cyclomatic complexity (2.24 to 2.13), and provides a more maintainable foundation for further development. Future work should replicate the approach across different technology stacks. Furthermore, it should create a catalog of best practices as well as different important quality metrics and their thresholds. That should help alleviate value misalignment[4]这发生在目标规范或规范执行中。在本文中，我们确定了这两个问题。我们通过测试生成期间的反馈和迭代来解决这些问题（其中可以通过需要使用突变测试来修剪的无效测试来提高覆盖率）和后来的代码重构（其中质量仅在明确规定的目标上得到提高）。拥有独立于法学硕士的确定性代码来评估重要的质量特征非常重要，无论是作为模型利用的一部分还是在事后解决方案分析中，因为我们注意到法学硕士不愿意报告低于标准的指标，除非明确强调这个问题，同时将积极的指标和方面推到最前沿。这种模型行为与最近的研究是一致的that occurs either in goal specification or specification enforcement. In this paper, we identified both issues. We addressed them through feedback and iteration during test generation (where coverage can be improved by ineffective tests that need to be pruned using mutation testing) and later code refactoring (where quality gets improved only on explicitly stated objectives). It is important to have LLM-independent, deterministic code for evaluating important quality characteristics, both as part of the model harness and in post-hoc solution analysis, as we have noticed that LLMs hesitate to report subpar metrics unless explicitly pressed on the issue, while pushing positive metrics and aspects to the forefront. Such model behavior is consistent with the recent research[23].

总之，这两个阶段表明，只要在规则文件中设置初始指导、模型工具就位，并且在最关键时刻存在人在环，人工智能辅助工作流程就可以有效地应用于成熟的生产系统。通过将自动测试生成与自动重构相结合，该方法建立在人工智能辅助编码的当前进展之上。In conclusion, these two phases demonstrate that AI-assisted workflows can be effectively applied to mature, production systems, provided that initial guidance is set in rule files, model harness is in place, and a human-in-the-loop is present at most critical moments. By combining automated test generation with automated refactoring, the approach builds on current advances in AI-assisted coding.
