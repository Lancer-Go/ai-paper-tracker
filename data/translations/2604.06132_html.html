摘要Abstract

大型语言模型越来越多地部署为在现实软件环境中执行多步骤工作流程的自主代理。然而，现有的代理基准受到三个关键限制：（1）仅检查最终输出的轨迹不透明分级，（2）未指定的安全性和鲁棒性评估，以及（3）狭窄的模态覆盖范围和交互范例。我们介绍Large language models are increasingly deployed as autonomous agents executing multi-step workflows in real-world software environments. However, existing agent benchmarks suffer from three critical limitations: (1) trajectory-opaque grading that checks only final outputs, (2) underspecified safety and robustness evaluation, and (3) narrow modality coverage and interaction paradigms. We introduce爪评估Claw-Eval，一个解决所有三个差距的端到端评估套件。它包含 300 项经过人工验证的任务，涵盖 9 个类别、三个组（一般服务编排、多模式感知和生成以及多轮专业对话）。每个代理操作都通过三个独立的证据通道（执行跟踪、审核日志和环境快照）进行记录，从而能够对 2,159 个细粒度项目进行轨迹感知分级。评分协议评估完成度、安全性和稳健性，报告平均分、通过@, an end-to-end evaluation suite addressing all three gaps. It comprises 300 human-verified tasks spanning 9 categories across three groups (general service orchestration, multimodal perception and generation, and multi-turn professional dialogue). 1 简介Introduction

大型语言模型Large language models[23, 3, 7]从会话助理迅速发展而来have rapidly evolved from conversational assistants[25, 49]成为自主代理into autonomous agents[44, 28]能够执行复杂的多步骤工作流程capable of executing complex, multi-step workflows[29, 26, 26]在现实世界的软件环境中in real-world software environments[9, 34]。 现代特工安全带，例如 Claude Code. Modern agent harnesses, such as Claude Code[2]和张开爪and OpenClaw[24]，让法学硕士能够调用工具、导航文件系统、查询数据库以及跨多个应用程序协调操作，将中心评估问题从模型是否拥有知识转变为是否可以通过情境操作可靠地实现目标。 这种转变要求评估方法超越静态问答基准，而是在实时交互式环境中评估智能体，其中成功不仅取决于智能体生产什么，还取决于它如何生产。, equip LLMs with the ability to call tools, navigate file systems, query databases, and orchestrate actions across multiple applications, transforming the central evaluation question from whether a model possesses knowledge to whether it can reliably accomplish a goal through situated action. This shift demands evaluation methodologies that go beyond static question-answering benchmarks and instead assess agents in live, interactive environments where success depends not only on what the agent produces, but on how it produces it.

最近的基准测试在沙盒工具使用环境中评估代理，朝着这一目标迈出了重要的一步Recent benchmarks have made important strides toward this goal, evaluating agents across sandboxed tool-use environments[12, 18]、GUI驱动的桌面工作流程, GUI-driven desktop workflows[34, 35]，以及现实世界的编码代理管道, and real-world coding-agent pipelines[10, 8]。 然而，仍然存在三个关键差距，限制了当前评估实践的诊断能力。. Yet three critical gaps remain that limit the diagnostic power of current evaluation practices.(G1) 轨迹不透明分级。(G1) Trajectory-opaque grading.许多现有的基准测试仅验证代理是否生成正确的最终工件（创建的文件、通过的测试或匹配的答案），但没有系统地审核生成它的中间操作序列。这使得忠实的执行与捏造或幻觉的步骤无法区分。更重要的是，最近的证据表明，前沿模型积极利用仅输出的评估信号，发现满足最终工件检查的捷径，而无需忠实执行预期的工作流程Many existing benchmarks verify only whether the agent produces a correct final artifact (a file created, a test passed, or an answer matched) but do not systematically audit the intermediate action sequence that produced it. This renders faithful execution indistinguishable from fabricated or hallucinated steps. More critically, recent evidence shows that frontier models actively exploit output-only evaluation signals, discovering shortcuts that satisfy final-artifact checks without faithfully executing the intended workflow[31, 17]，这种现象被广泛地称为奖励黑客。因此，轨迹不透明的分级不仅不精确，而且还不够精确。它创建了一个评估表面，成熟的代理可以系统地进行博弈。, a phenomenon broadly termed reward hacking. Trajectory-opaque grading is thus not merely imprecise; it creates an evaluation surface that sophisticated agents can systematically game.(G2) 安全性和稳健性未明确。(G2) Underspecified safety and robustness.在实际部署中，安全性和稳健性与正常任务执行同时出现：代理必须在完成通信任务的压力下抵制发送未经授权的电子邮件，并且必须从工作流程中的 API 超时中恢复。目前的基准在这两方面都存在不足。为了安全起见，他们要么将其隔离到独立的红队套件中，脱离真正的任务压力，要么执行沙盒以防止伤害，而不对代理是否尝试不安全的行为进行评分；在这两种情况下，安全性都不是在现实的目标导向压力下进行评估的。为了鲁棒性，现有的基准测试没有在现实扰动（例如瞬时服务故障或速率限制）下系统地对代理进行压力测试。In real deployments, safety and robustness arise alongside normal task execution: an agent must resist sending an unauthorized email while under pressure to complete a communication task, and must recover from API timeouts mid-workflow. Current benchmarks fall short on both fronts. For safety, they either isolate it into standalone red-teaming suites divorced from genuine task pressure, or sandbox execution to prevent harm without scoring whether the agent attempted unsafe actions; in neither case is safety evaluated under realistic goal-directed pressure. For robustness, no existing benchmark systematically stress-tests agents under realistic perturbations such as transient service failures or rate limiting.(G3) 模态狭窄的任务覆盖范围。(G3) Modally narrow task coverage.现实世界的代理在截然不同的场景中运行，从编排多服务工作流程和处理视觉媒体到参与扩展的专业对话，通常在同一部署中。然而，现有的基准测试均针对单一模式或交互范例，例如基于文本的工具调用Real-world agents operate across radically diverse scenarios, from orchestrating multi-service workflows and processing visual media to engaging in extended professional dialogues, often within the same deployment. Yet existing benchmarks each target a single modality or interaction paradigm, such as text-based tool calls[12]、命令行执行, command-line execution[18]，或 GUI 导航, or GUI navigation[34]，并且没有一个框架能够在一致的分级方法和执行管道下联合评估这些异构功能。, and no single framework jointly evaluates these heterogeneous capabilities under a consistent grading methodology and execution pipeline.

6 结论Conclusions
