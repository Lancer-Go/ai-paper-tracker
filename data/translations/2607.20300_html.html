不要相信标签：人工智能供应链中的许可洗钱Don’t Trust the Label: License Laundering in AI Supply Chains

James Jewitt Queen’s University    Hao Li Queen’s University    Gopi Krishnan Rajbahadur Queen’s University    Bram Adams Queen’s University    Ahmed E. Hassan Queen’s University

摘要Abstract

AI 工件在多平台供应链中移动，涵盖 Hugging Face 上的数据集和模型以及 GitHub 上的应用程序。虽然每个工件都带有一个许可证，其义务应通过重新分配来传播，但尚未有研究衡量这些义务是否在链条中继续存在，或者随着工件向下游移动而被剥离和替换。我们追踪 232,270 个数据集AI artifacts move through a multi-platform supply chain, spanning datasets and models on Hugging Face and applications on GitHub. While each artifact carries a license whose obligations should propagate through redistribution, no study has yet measured whether those obligations survive the chain or are stripped and replaced as artifacts move downstream. We trace 232,270 dataset→\rightarrow模型model→\rightarrow应用程序链并量化两种形式application chains and quantify two forms of洗牌license laundering：当没有声明许可证的工件在下游获得明确的标签时，以及当一个声明的许可证类别在重新分发期间替换另一个时。我们发现，62.3% 的链通过至少一个没有声明许可证的工件（集中在一小部分基础数据集中），并且每个义务承担许可证类别的端到端生存率都低于 7%，而许可类别则达到 95.1%。基于这些发现，我们为从业者、模型出版商、权利持有者和平台所有者提供可行的建议。: when artifacts with no declared license acquire definitive labels downstream, and when one declared license category replaces another during redistribution. We find that 62.3% of chains pass through at least one artifact with no declared license (concentrated in a small set of foundational datasets), and that every obligation-bearing license category falls below 7% end-to-end survival while the Permissive category reaches 95.1%. Based on these findings, we provide actionable recommendations for practitioners, model publishers, rights holders, and platform owners.

Sentence-transformers/all-MiniLM-L6-v2，在 Hugging Face 上标记为 Apache-2.0，已被 GitHub 上的 1,656 个应用程序集成。虽然阅读该许可证标签的从业者可能会认为该模型是可自由重复使用的，但在其 21 个声明的训练数据集中，(1) 9 个没有声明许可证，这将所有权利保留给数据集的创建者，(2) 3 个带有共享条款，要求任何衍生品保留相同的义务。 Apache-2.0 许可证标签不反映这些上游权利，即，这是一个示例Sentence-transformers/all-MiniLM-L6-v2, labeled Apache-2.0 on Hugging Face, is integrated by 1,656 applications on GitHub. While a practitioner reading that license label likely assumes the model is freely reusable, of its 21 declared training datasets, (1) nine carry no declared license, which leaves all rights reserved to the dataset’s creators, and (2) three carry Sharealike terms that require any derivative to preserve the same obligations. 现有工具无法自动审核人工智能供应链上的许可证是否存在洗钱行为。软件行业已经创建了 FOSSology 和 Black Duck 等软件组合分析 (SCA) 工具，它们通过包管理器依赖关系图跟踪声明的软件许可证、标记不兼容的组合，并生成用于合规性审计的软件物料清单 (BOM)No existing tool is able to automatically audit the licenses along an AI supply chain for laundering occurrences. The software industry has created software composition analysis (SCA) tools such as FOSSology and Black Duck that trace declared software licenses through package-manager dependency graphs, flag incompatible combinations, and generate Software Bills of Material (BOMs) for compliance audits[5]。然而，这些工具不能轻易地在人工智能供应链上使用，因为后者打破了现有软件许可证审核工具所依赖的假设。模型的训练数据依赖项不是在锁定文件中声明的，而是在 Hugging Face 上的元数据标签中声明的，并且应用程序的模型依赖项只能通过 GitHub 上的代码搜索来恢复。通常根本没有声明任何许可证：Hugging Face 上 65.0% 的模型和 74.7% 的数据集没有可识别的许可证标签. However, these tools cannot be readily used on AI supply chains, as the latter break the assumptions existing software license auditing tools rely on. A model’s training-data dependencies are declared not in lockfiles but in metadata tags on Hugging Face, and an application’s model dependencies can only be recovered through code search across GitHub. Often no license is declared at all: 65.0% of models and 74.7% of datasets on Hugging Face carry no recognizable license tag[6]。 AI 链还跨平台：Hugging Face 数据集训练 Hugging Face 模型，然后将其集成到 GitHub 应用程序中，这是一条没有 SCA 工具端到端遵循的路径。因此，SCA 工具通常会针对软件发出警告，例如 Copyleft 依赖项要求集成项目在相同条款下共享其源代码，或者依赖关系图中的两个许可证发生冲突，这些警告永远不会针对 AI 工件生成。换句话说，二十年来的开源软件（OSS）合规基础设施还没有与人工智能相当的基础设施。. AI chains also cross platforms: a Hugging Face dataset trains a Hugging Face model that a GitHub application then integrates, a path no SCA tool follows end-to-end. As a result, the warnings that SCA tools routinely raise for software, e.g., that a copyleft dependency requires the integrating project to share its source under the same terms, or that two licenses in a dependency graph conflict, are never produced for AI artifacts. In other words, two decades of open-source software (OSS) compliance infrastructure has no AI equivalent.

构建该工具首先需要了解洗钱发生的频率。之前的审计量化了 Hugging Face 的许可标签有多差（超过 96% 的许可标签工件缺乏其声明的许可所需的完整许可文本）Building that tooling first requires knowing how often laundering happens. Prior audits quantify how poor Hugging Face’s license labels are (over 96% of permissively-labeled artifacts lack the full license text their declared licenses require[7]），但糟糕的标签并不等同于失去义务。之前的工作没有测量过义务承担许可类别（那些限制工件如何使用或重用的许可类别）是否能够在完整的数据集到模型到应用程序链中幸存下来。如果没有这种衡量标准，我们就无法判断洗钱行为是罕见的、孤立的还是常规的、系统性的，它是否集中在一些基础文物上，还是在整个生态系统中传播，或者不同类别的洗钱率是否不同。), but poor labels are not the same as lost obligations. What no prior work has measured is whether the obligation-bearing license categories (those that constrain how an artifact may be used or reused) survive the full dataset-to-model-to-application chain. Without that measurement, we cannot tell whether laundering is rare and isolated or routine and systemic, whether it concentrates in a few foundational artifacts or spreads across the ecosystem, or whether different categories are laundered at different rates.

供应链建设Supply Chain Construction

遵循与我们之前的工作类似的方法Following a methodology similar to our prior work[7]，我们将 Hugging Face 数据集和模型链接到使用它们的 GitHub 应用程序，然后提取每个工件声明的许可证。我们通过 Hugging Face 的数据集依赖元数据将数据集链接到模型，通过代码搜索和抽象语法树 (AST) 识别调用这些模型的 GitHub 应用程序，并使用 ScanCode 提取每个存储库中声明的许可证标签。该初始集合包含 3,198 个数据集、6,218 个模型和 26,302 个应用程序，形成 294,012 个候选数据集, we link Hugging Face datasets and models to the GitHub applications that use them, then extract each artifact’s declared license. We link datasets to models through Hugging Face’s dataset dependency metadata, identify GitHub applications that invoke those models via code search and abstract syntax tree (AST), and use ScanCode to extract the license label declared in each repository. This initial collection contains 3,198 datasets, 6,218 models, and 26,302 applications, forming 294,012 candidate dataset→\rightarrow模型model→\rightarrow应用链。application chains.

然后我们在候选链上应用两个过滤器。第一个过滤器删除仅用作基础模型、没有应用程序直接调用它们的模型，确保每个链恰好经过两次转换，从而留下 264,431 个链。第二个过滤器排除工件携带未映射到我们的分类（如下所述）的许可证字符串的任何链，从而进一步删除 32,161 个链。经过两个过滤器后，我们剩下 232,270 条链，涵盖 3,120 个数据集、5,556 个模型和 24,076 个应用程序。其中，144,631 个 (62.3%) 通过了至少一个具有未知许可证的工件，87,639 个 (37.7%) 在所有三个工件上都具有已知类别。We then apply two filters on the candidate chains. The first filter removes models that serve only as base models with no application directly invoking them, ensuring that every chain passes through exactly two transitions, which leaves 264,431 chains. The second filter excludes any chain in which an artifact carries a license string that does not map to our classification (described next), removing a further 32,161 chains. After both filters, we are left with 232,270 chains spanning 3,120 datasets, 5,556 models, and 24,076 applications. Of these, 144,631 (62.3%) pass through at least one artifact with an Unknown license, and 87,639 (37.7%) carry a Known category at all three artifacts.

有效性的威胁Threats to Validity

内部有效性。Internal Validity.我们跟踪许可证标签，而不是许可证的完整法律文本。对于数据集和模型，这些标签来自 Hugging Face 上自我报告的元数据。对于应用程序，我们使用 GitHub 存储库中 ScanCode 识别的许可证标签。在所有情况下，如果标签没有反映出版商的意图，我们的分析会捕获从业者遇到的标签，而不是潜在的法律地位。具有模糊或不明确元数据（例如“其他”）的许可证字符串与不存在的许可证一起被分类为“未知”。如果其中一些字符串代表我们无法解决的故意许可选择，则未知计数可能会被夸大。斯塔纳克等人。We track license labels, not the full legal text of the licenses. For datasets and models, these labels come from self-reported metadata on Hugging Face. For applications, we use the license label identified by ScanCode from GitHub repositories. In all cases, if the label does not reflect the publisher’s intent, our analysis captures the label as practitioners encounter it, not the underlying legal status. License strings with vague or ambiguous metadata (e.g., “other”) are classified as Unknown alongside absent licenses. If some of these strings represent intentional license choices that we cannot resolve, the Unknown count may be overstated. Stalnaker et al.[6]以同样的方式处理此类字符串，将 Hugging Face 的“其他”和“未知”标签视为无法解析的类别，而不是将它们映射到特定许可证，因为检索和评估这些许可证条款既困难又耗时。handle such strings the same way, treating Hugging Face’s “other” and “unknown” labels as unresolvable categories rather than mapping them to specific licenses, since retrieving and evaluating these license terms is difficult and time-consuming.

外部有效性。External Validity.我们收集的数据仅包括通过元数据声明训练数据的模型，占 Hugging Face 模型的 7.1%Our collected data includes only the models that declare their training data via metadata, which amount to 7.1% of Hugging Face models[7]。不公开训练数据的模型和未出现在 GitHub 代码搜索中的应用程序不在我们的范围之内。之前对 Hugging Face 供应链的审计也面临着相同的边界：Stalnaker 等人。. Models that do not disclose training data and applications that do not appear in GitHub code search are outside our scope. Prior audits of the Hugging Face supply chain face the same boundary: Stalnaker et al.[6]仅根据声明的元数据构建供应链图，并注意它必须捕获整个链的子集。这种选择偏差的影响尚不清楚：公开训练数据的模型可能比不公开训练数据的模型遵循更好或更差的许可合规实践。build their supply-chain graph from declared metadata alone and note that it necessarily captures a subset of the full chain. The impact of this selection bias is unclear: models that disclose their training data may follow better or worse license-compliance practices than those that do not.

我们的样本取自最流行的模型和数据集，因此它捕获了下游范围最广的工件，包括高扇出基础数据集，例如 ImageNet-1K、The Pile 和 BookCorpus。因此，我们的研究结果描述了供应链中流行的、公开的部分，而不是其长尾部分。我们还排除包含未映射到我们的分类框架的许可证字符串的链（765 个唯一字符串中的 495 个，主要是自定义字符串或不明确字符串）。被排除的链仅占预过滤器链的 12.2%。每个标准义务承担许可证（Copyleft、Sharealike、ML 许可证、CC-Restrictive）都属于我们识别的 270 个字符串之内，因此排除的字符串不会影响我们衡量其生存的类别。Our sample is drawn from the most popular models and datasets, so it captures the artifacts with the widest downstream reach, including high-fan-out foundational datasets such as ImageNet-1K, The Pile, and BookCorpus. Our findings therefore characterize the popular, disclosed portion of the supply chain rather than its long tail. We also exclude chains containing license strings that do not map to our classification framework (495 of 765 unique strings, predominantly custom or ambiguous). The excluded chains represent only 12.2% of the pre-filter chains. Every standard obligation-bearing license (Copyleft, Sharealike, ML License, CC-Restrictive) falls within the 270 strings we recognize, so the excluded strings do not affect the categories whose survival we measure.

Concretely: Hugging Face and GitHub should auto-surface upstream license categories alongside downstream labels and warn when categories conflict; researchers should build tools that auto-generate AI BOMs from existing metadata, connecting the existing standards to the supply chains they are designed to describe.
