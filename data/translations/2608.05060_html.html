修复器RepairFormer：使用变压器自动修复结构化输入: Automated Repair of Structured Inputs Using Transformers

Ovi Paul opaul@uh.edu University of HoustonHoustonTexasUSA , Tom J King tjking2@uh.edu University of HoustonHoustonTexasUSA and Ali Shokri ashokri@uh.edu University of HoustonHoustonTexasUSA
(2018)
摘要。Abstract.

JSON、DOT、OBJ、INI、S-表达式和 TinyC 等结构化输入文件广泛用于软件系统中，但小的损坏可能会导致解析器拒绝其他有用的数据。修复此类输入非常重要，因为即使大多数原始内容保持不变，格式错误的配置、程序和数据文件也可能会中断测试、分析、部署和下游自动化。现有的修复技术可以产生结构上有效的输入，但它们通常依赖于删除或重复搜索，这可能会丢失原始内容并导致语义错误。本文介绍了Structured input files such as JSON, DOT, OBJ, INI, S-expression, and TinyC are widely used in software systems, but small corruptions can cause parsers to reject otherwise useful data. Repairing such inputs is important because malformed configuration, program, and data files can interrupt testing, analysis, deployment, and downstream automation even when most of the original content remains intact. Existing repair techniques can produce structurally valid inputs, but they often rely on deletion or repeated search, which may lose original content and result in semantic incorrectness. This paper presents修复器RepairFormer，一个基于变压器的结构化输入修复框架。该方法将修复制定为监督序列生成任务，并使用格式标签、预言机验证和边界局部修复来生成有效的输出，同时保留内容。边界工作流程将生成重点放在检测到的故障区域上，减少输入大小并支持较长文件的修复。在评价中，, a transformer-based framework for structured input repair. The approach formulates repair as a supervised sequence generation task and uses format tags, oracle validation, and boundary-localized repair to generate valid outputs while preserving content. The boundary workflow focuses generation on the detected fault region, reducing the input size, and supporting repair of longer files. In evaluation,修复器RepairFormer修复率达到 88%，恢复率达到 94%，修复成功后内容保存效果最强。我们的基准测试的其他实验显示achieves a 88% in repair and 94% in recovery, showing strongest content preservation when repairs are successful. Additional experiments on our benchmark shows修复器RepairFormer与现有技术相比，修复率提高了 97.57%，恢复率提高了 94.29%，运行时间快了 5 倍。repairs 97.57% and recovers 94.29% with 5x faster runtime compared to state of the art.

1. 简介Introduction

现代软件系统依赖于结构化输入格式（例如 JSON、XML、DOT、OBJ、INI、S-表达式和 TinyC）来表示配置数据、程序结构和领域特定信息Modern software systems rely on structured input formats such as JSON, XML, DOT, OBJ, INI, S-expression, and TinyC to represent configuration data, program structures, and domain specific information(Kirschner et al., 2020; Luo et al., 2025)。这些文件通常是手动编辑或由外部工具生成的，这使得它们容易受到损坏。即使是很小的语法错误，例如缺少分隔符、错误放置的标记或不完整的结构，也可能导致解析器拒绝整个文件. These files are often manually edited or generated by external tools, which makes them vulnerable to corruption. Even small syntax errors, such as missing delimiters, misplaced tokens, or incomplete structures, can cause a parser to reject the entire file(Korn et al., 2013)。 此类无效输入在现实世界的存储库（例如 GitHub）中很常见. Such invalid inputs are common in real-world repositories (e.g., GitHub)(Kirschner et al., 2020)，即使文件的大部分内容保持正确，也会导致有用的信息无法访问。手动修复此类文件可能会很慢并且容易出错，尤其是对于大文件或错误位置不清楚时。, causing useful information to become inaccessible even when most of the file remains correct. Repairing such files manually can be slow and error-prone, especially for large files or when the error location is unclear.

先前的输入修复技术通过解析器引导搜索来解决这个问题。例如，ddmaxPrior input repair techniques address this problem through parser guided search. For example, ddmax(Kirschner et al., 2020)通过删除片段来修复输入，直到解析器接受剩余的文件。最近，repairs inputs by removing fragments until the remaining file is accepted by the parser. More recently,ϵ\epsilon修复REPAIR(Luo et al., 2025)通过考虑插入、删除和替换来扩展基于搜索的修复。但这些方法依赖于许多重复的预言执行和迭代搜索步骤来探索候选修复。extends search-based repair by considering insertions, deletions, and replacements. But these approaches rely on many repeated oracle executions and iterative search steps to explore candidate repairs.

这项工作研究了不同的方向。我们使用基于变压器的模型将结构化输入修复制定为序列生成任务This work investigates a different direction. We formulate structured input repair as a sequence generation task using transformer-based model(Vaswani et al., 2017; Chen et al., 2021)。该模型不是仅搜索编辑操作，而是从损坏的和有效的输入对中学习修复模式。目标不仅是生成解析器有效的文件，而且还保留尽可能多的原始信息。为了提高长输入的可扩展性，我们还设置了边界局部化工作流程，在生成之前引导模型走向可疑的故障区域。 RepairFormer 可以支持错误配置的恢复和 下游处理之前的其他结构化输入文件. Instead of only searching over edit operations, the model learns repair patterns from corrupted and valid input pairs. The goal is not only to produce a parser valid file, but also to preserve as much of the original information as possible. To improve scalability for long inputs, we also put a boundary localized workflow that guides the model toward the suspected faulty region before generation. RepairFormer can support the recovery of malformed configuration and other structured input files before downstream processing(Liu et al., 2024; Korn et al., 2013; Kirschner et al., 2020)。 本文做出以下贡献：. 2. 激励例子Motivating Example

考虑以下损坏的 JSON 输入：Consider the following corrupted JSON input:

{“id”：17，“状态”“活动”}{"id": 17, "status" "active"}

输入无效，因为后面的冒号The input is invalid because the colon after“状态”"status"失踪了。基于删除的修复方法可以通过删除损坏的字段来生成有效的文件：is missing. A deletion-based repair method may produce a valid file by removing the corrupted field:

{“id”：17}{"id": 17}

此输出在语法上是有效的，但它丢失了状态信息。虽然最先进的工具要么生成上述输出，要么随机生成字符来修复文件，但生成修复模型可以通过插入丢失的冒号来保留字段：This output is syntactically valid, but it loses the status information. While the state of the art tools either produce the above output or randomly generate characters to repair the file, a generative repair model can instead preserve the field by inserting the missing colon:

{“id”：17，“状态”：“活跃”}{"id": 17, "status": "active"}

此示例显示了通过输入修复工具保留有用内容同时满足结构化输入的语法正确性的重要性。This example shows the importance of preserving the useful content by an input repair tool while also satisfying the syntax correctness of a structured input.

The trained model then generates a repair candidate for that local window. Model inference refers to the generation of this repair candidate, rather than the localization or extraction of the local window. The generated candidate is reconstructed into the original file and validated again using the oracle. A repair is accepted when the reconstructed file becomes valid. Invalid candidates are rejected unless they advance the error boundary. The process repeats until the file is repaired or the maximum number of iterations is reached.

5. 相关工作Related Work

已经提出了几种用于调试和修复无效程序输入的技术。这些方法可以大致分为基于解析器的恢复方法和自动输入修复技术。Several techniques have been proposed for debugging and repairing invalid program inputs. These approaches can be broadly categorized as parser-based recovery methods and automated input repair techniques.

解析器生成器，例如 ANTLRParser generators such as ANTLR(Parr and Fisher, 2011)为格式错误的输入提供内置错误恢复provide built-in error recovery for malformed inputs(Luo et al., 2025)。然而，它们需要正式的语法规范，并且通常仅限于局部语法错误，这使得它们不太适合复杂的结构损坏或没有现成语法的格式。. However, they require a formal grammar specification and are typically limited to local syntax errors, making them less suitable for complex structural corruptions or formats without readily available grammars.

最大DD值DDMax(Kirschner et al., 2020)通过识别输入的最大解析器接受子集来修复损坏的结构化输入。虽然它与语法无关并且支持多种格式，但它主要通过删除来修复输入，这会减少内容保留。它对重复解析器执行的依赖也会增加运行时间。repairs corrupted structured inputs by identifying the largest parser-accepted subset of the input. While it is grammar-independent and supports multiple formats, it primarily repairs inputs through deletion, which can reduce content preservation. Its reliance on repeated parser executions can also increase runtime.

ϵ\epsilon修复REPAIR(Luo et al., 2025)是一种与格式无关的修复技术，它使用解析器反馈来搜索将无效输入转换为有效输入的编辑。它支持插入、删除和替换，不需要语法规范，但仍然依赖于迭代搜索和重复的预言机执行。相比之下，is a format-independent repair technique that uses parser feedback to search for edits that transform invalid inputs into valid ones. It supports insertions, deletions, and replacements without requiring a grammar specification, but still relies on iterative search and repeated oracle executions. In contrast,修复器RepairFormer使用局部错误上下文和学习的修复模型直接生成修复。uses localized error context and a learned repair model to generate repairs directly.

6. 局限性Limitations

同时While修复器RepairFormer可以有效修复无效的输入文件，但它有几个限制。首先，模型受到最大令牌长度的限制。因此，较长的文件可能需要更精确的边界定位或更大的模型。其次，修复结果取决于基于预言机的验证，这意味着不同的解析器可能会接受对相同输入的不同修复。第三，如果在提取的局部上下文窗口的边缘附近发生错误，则模型可能无法生成正确的修复。最后，当生成有效修复需要来自输入的远程部分的信息时，本地修复可能是不够的。can effectively repair invalid input files, it has several limitations. First, the model is constrained by a maximum token length. Therefore, longer files may require more precise boundary localization or larger models. Second, repair outcomes depend on oracle-based validation, meaning that different parsers may accept different repairs for the same input. Third, if an error occurs near the edge of the extracted local context window, the model may fail to generate a correct repair. Finally, local repairs may be insufficient when producing a valid fix requires information from distant parts of the input.

7. 结论Conclusion

本文提出This paper presented修复器RepairFormer，一个基于变压器的框架，用于修复损坏的结构化输入。该方法将输入修复制定为序列生成任务，并使用格式标签、预言机验证和边界局部修复来生成有效的输出，同时保留原始内容。与基于删除的修复方法相比，所提出的方法侧重于重建丢失或损坏的语法，而不是删除大的输入片段。, a transformer-based framework for repairing corrupted structured inputs. The approach formulates input repair as a sequence generation task and uses format tags, oracle validation, and boundary-localized repair to generate valid outputs while preserving original content. Compared with deletion-based repair methods, the proposed method focuses on reconstructing missing or corrupted syntax instead of removing large input fragments.

评估表明，我们的方法实现了 88% 的修复和 94% 的恢复，表明内容保存能力很强。它在 C、DOT、INI、JSON 和 OBJ 上表现良好，而 S 表达仍然更具挑战性。在我们的基准测试中，The evaluation shows that our approach achieves 88% repair and 94% recovery, indicating strong content preservation. It performs well on C, DOT, INI, JSON, and OBJ, while S expression remains more challenging. 总的来说，结果表明基于变压器的输入修复是跨多种结构化格式进行内容保留修复的一个有前途的方向。Overall, the results suggest that transformer-based input repair is a promising direction for producing content-preserving repairs across multiple structured formats.
