摘要Abstract

长期对话代理需要能够捕获事件之间关系（而不仅仅是孤立事实）的记忆系统，以支持时间推理和多跳问答。当前的方法面临着一个根本性的权衡：平面内存虽然高效，但无法对关系结构进行建模，而基于图的内存可以实现结构化推理，但代价是昂贵且脆弱的构造。为了解决这些问题，我们建议Long-term conversational agents need memory systems that capture relationships between events, not merely isolated facts, to support temporal reasoning and multi-hop question answering. Current approaches face a fundamental trade-off: flat memory is efficient but fails to model relational structure, while graph-based memory enables structured reasoning at the cost of expensive and fragile construction. To address these issues, we propose结构内存StructMem，一个结构丰富的分层内存框架，可保留事件级绑定并诱导跨事件连接。通过临时锚定双重视角并执行定期语义整合，StructMem 改进了临时推理和多跳性能, a structure-enriched hierarchical memory framework that preserves event-level bindings and induces cross-event connections. By temporally anchoring dual perspectives and performing periodic semantic consolidation, StructMem improves temporal reasoning and multi-hop performance on洛科莫LoCoMo，同时与之前的内存系统相比大幅减少了令牌使用、API 调用和运行时间, while substantially reducing token usage, API calls, and runtime compared to prior memory systems111https://github.com/zjunlp/LightMem.

5 结论Conclusion

我们提出了 StructMem，它通过分层设计实现结构丰富的组织：保留事件级绑定并启用跨事件合并，StructMem 保留时间和关系结构，而无需连续图维护的计算开销。实验We propose StructMem, which achieves structure-enriched organization through hierarchical design: preserving event-level bindings and enabling cross-event consolidation, StructMem preserves temporal and relational structures without the computational overhead of continuous graph maintenance. Experiments on洛科莫LoCoMo证明 StructMem 实现了更好的性能，在多跳和时间推理方面取得了出色的成果，同时与以前的内存系统相比，大大减少了令牌消耗、API 调用和运行时间。demonstrate that StructMem achieves better performance with strong results in multi-hop and temporal reasoning, while substantially reducing token consumption, API calls, and runtime compared to prior memory systems.

局限性Limitations

尽管 StructMem 性能强大，但它也有一些局限性。双视角提取的质量高度依赖于指令提示，次优设计可能会导致关系信息捕获不完整或不准确。未来的研究可以调查自动提示优化，以提高各种对话环境的稳健性。此外，该框架主要解决内存扩展和合成问题，但目前缺乏冲突解决和内存更新的明确机制。由于用户事实或偏好可能会长期演变，缺乏修订过程可能会导致历史摘要与新信息之间的不一致。未来的迭代应该结合记忆衰退或更新策略，以确保分层组织准确地反映交互的最新状态。Despite its strong performance, StructMem has several limitations. The quality of dual-perspective extraction is highly dependent on instruction prompts, where suboptimal design may result in incomplete or inaccurate relational information capture. Future research could investigate automated prompt optimization to improve robustness across various dialogue contexts. Additionally, the framework primarily addresses memory expansion and synthesis but currently lacks an explicit mechanism for conflict resolution and memory updating. As user facts or preferences may evolve over long horizons, the absence of a revision process could lead to inconsistencies between historical summaries and new information. Future iterations should incorporate memory decay or updating strategies to ensure the hierarchical organization accurately reflects the most current state of the interaction.

A.8 案例研究Case Study

表Table8提出了一个案例研究，比较不同的记忆范式如何处理联合参与的时间推理。该查询询问两个发言者何时一起参加一个活动，需要对个人对话轮次中未明确说明的共同参与关系进行推断。presents a case study comparing how different memory paradigms handle temporal reasoning over joint participation. The query asks when two speakers attended an event together, requiring inference over co-participation relationships that are not explicitly stated in individual conversational turns.

平面内存Flat Memory独立检索事实条目：卡罗琳“去年”参加了骄傲节（暂时固定为 2023 年 8 月 17 日，指的是 2022 年），而梅兰妮在骄傲节上“与整个团伙”享受了时光。由于没有任何机制将这些孤立的事实联系起来，系统得出的结论是“它们没有走到一起”，无法识别隐含的共同参与。retrieves factual entries independently: Caroline attended Pride fest "last year" (temporally anchored to August 17, 2023, referring to 2022), while Melanie enjoyed time "with the whole gang" at Pride fest. Without any mechanism to connect these isolated facts, the system concludes "they haven’t gone together," failing to recognize the implicit joint participation.

图形存储器Graph Memory在相同的事实条目之上构造实体关系三元组。虽然该图捕获了个人出席情况，但这些仍然是孤立的节点，没有明确的共同参与边缘。事后图结构无法推断出同一对话中不同说话者提及同一事件表明共同出席。因此，它会产生错误的时间推断：“上个月，2023 年 6 月”。constructs entity-relation triples on top of the same factual entries. While the graph captures individual attendance, these remain isolated nodes without explicit co-participation edges. The post-hoc graph structure cannot infer that mentions of the same event by different speakers within the same conversation indicate joint attendance. Consequently, it produces an incorrect temporal inference: "Last month, June 2023."

结构内存StructMem通过两种机制解决这个限制。首先，关系条目捕捉了提取过程中的人际动态：“梅兰妮对卡罗琳的骄傲游行经历表现出兴趣”提供了关于他们共同讨论的重要背景。其次，综合巩固了时间上位于同一位置的条目。当卡罗琳的骄傲节提及在按时间顺序排序的上下文中出现在梅兰妮的旁边时，关系条目的所有格代词“他们的”表示共同参与。然后，综合使这种隐式联系变得明确：“他们去年在骄傲节上度过的愉快时光”，使系统能够正确回答“去年，2022 年 8 月”。addresses this limitation through two mechanisms. First, relational entries capture interpersonal dynamics during extraction: "Melanie showed interest in Caroline’s pride parade experience" provides crucial context about their shared discussion. Second, synthesis consolidates temporally co-located entries. When Caroline’s Pride fest mention appears adjacent to Melanie’s in the chronologically sorted context, the relational entry’s possessive pronoun "their" signals joint participation. The synthesis then makes this implicit connection explicit: "their enjoyable time at Pride fest last year," enabling the system to correctly answer "Last year, August 2022."

此案例说明了为什么提取时间结构捕获在时间推理方面优于事后图构造。通过在记忆形成过程中分层组织信息而不是随后叠加结构，StructMem 保留了推断对话轮次中隐含关系所需的时间和关系上下文。This case demonstrates why extraction-time structural capture outperforms post-hoc graph construction for temporal reasoning. By organizing information hierarchically during memory formation rather than overlaying structure afterward, StructMem preserves the temporal and relational context necessary for inferring implicit relationships across conversational turns.
