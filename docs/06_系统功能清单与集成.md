# AI 学术热度追踪平台 - 系统功能清单与外围集成

> 系统的骨架定义，指明系统划分了多少个端、多少个子模块，以及要和哪些外部系统打交道。

## 1. 系统模块划分架构图 / 清单
- **[端 A - 终端用户展示页面 (React / Vite)]**
  - [UI 模块 - 榜单展示]：展示最新热度排名的列表，包含论文卡片、标题、摘要和作者等。
  - [UI 模块 - 过滤与筛选]（演进中）：支持用户按时间追溯、按分类（大模型/多模态/视觉等）进行特定筛选。
- **[端 B - 自动化后端 (Python)]**
  - [爬虫与抓取模块]：负责和 arXiv / OpenAlex 等数据源通信，保障数据可靠获取。
  - [清洗去重模块]：负责保证论文库中不出现脏数据或重复处理的 arXiv ID。
  - [打分处理器]：核心算法落地区域，执行权重计算。
  - [导出调度器]：操作 SQLite，并将结果打包输出给前端的 `data` 目录。

## 2. 上下游集成系统 (Dependencies)
列出本系统强依赖的外部基础设施或中台服务：

| 外部系统名称 | 集成方式 (API/MQ/SDK) | 依赖内容说明 | 负责方 |
|------------|----------------------|------------|-----------|
| **arXiv API** | HTTP API 查询 | 提供全球最全的 AI 预印本论文源数据（标题、时间、作者、摘要） | Cornell University |
| **OpenAlex API** | HTTP API 查询 | 提供高质量的开源论文引用数据池，由于放弃 Semantic Scholar，此接口为热度测算依赖的唯一引用量数据源 | OpenAlex |
| **GitHub Actions** | CI/CD 引擎 | 系统的“心脏”，每天按时拨动整个后端逻辑运转并打包项目 | GitHub |
| **GitHub Pages** | 静态站点托管服务 | 零成本、高可用的展示站点 | GitHub |
