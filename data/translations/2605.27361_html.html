3.1 观察 1：工作负载内的查询级差异Observation 1: Query-Level Variance Within a Workload

工作负载是对公共语料库的一组查询。语料库是固定的；查询不是。工作负载中的查询在结构上有所不同：事实查找、多跳比较和消歧查询可以同时出现，最佳服务配置取决于查询的结构。迭代检索对于事实查找来说是大材小用；仅 LLM 调用会使多跳比较服务不足。修复整个工作负载的一种配置（§A workload is a set of queries over a common corpus. The corpus is fixed; the queries are not. Queries within a workload differ in structure: factual lookups, multi-hop comparisons, and disambiguation queries can co-occur, and the best-serving configuration depends on the query’s structure. 6 局限性和更广泛的影响Limitations and Broader Impact

局限性。Limitations.BRANE 为每种配置训练一个轻量级预测器，以实现稳定的工作负载。然而，在工作负载分布发生变化（例如新查询类型、新域或用户意图漂移）的情况下，配置准确性将会下降，直到重新训练预测器。对于大规模工作负载，每日重新训练所产生的开销相对于推理成本可以忽略不计。我们根据三个知识密集型基准评估 BRANE，这些基准可以扩展到更多样化的基准集。BRANE trains one lightweight predictor per configuration for stable workloads. However, under a shift in workload distribution (such as new query types, new domains, or drifts in user intent), configuration accuracy will degrade until the predictors are retrained. For large-scale workloads, daily retraining incurs negligible overhead relative to inference cost. We evaluate BRANE on three knowledge-intensive benchmarks, which can be potentially extended to more diverse benchmark set.

更广泛的影响。Broader impact.随着基于法学硕士的系统的构建和部署规模不断扩大，确定何时更便宜的配置就足够了，可以节省计算和能源以供其他用途。我们将 BRANE 视为迈向更高效人工智能系统的一步。As LLM-based systems are built and deployed at increasing scale, identifying when a cheaper configuration suffices saves compute and energy for other uses. We view BRANE as a step towards more efficient AI systems.

7 结论Conclusion

我们制定了 Query2Conf：给定自然语言查询和准确性目标，从预定义的管道配置空间中选择满足准确性目标的配置，同时最小化推理时间的成本。 Query2Conf 之所以困难有以下三个原因。首先，LLM、检索器旋钮和合成策略的联合性能在组合大的配置空间上非单调变化。其次，原始自然语言查询没有直接映射到系统配置空间。第三，在工作负载规模上，对该领域进行详尽的分析非常昂贵且耗时。我们提出了BRANE，它用两个想法解决了Query2Conf。 LLM 从每个查询中提取特定于工作负载的二进制特征，充当查询语义和管道空间之间的转换层。 在此表示之上，一个轻量级的按配置预测器估计管道正确回答查询的概率，通过分析正确性标签而不是显式建模隐式捕获组合旋钮效果。这两个简单而有效的想法共同使 BRANE 的性能优于直接在 Query2Conf 上训练的经过微调的端到端 BERT 和 Qwen3-4B。在 MuSiQue、BrowseComp-Plus 和 FinanceBench 中，BRANE 能够以高达 89% 的降低成本与最佳固定管道的准确性相媲美，并推动成本质量帕累托前沿。We formulate Query2Conf: given a natural-language query and an accuracy target, select from a predefined pipeline configuration space the configuration that satisfies the accuracy target while minimizing cost at inference time. Query2Conf is hard for three reasons. First, the joint performance across the LLM, retriever knobs, and synthesis strategy varies non-monotonically over a combinatorially large configuration space. Second, raw natural-language queries have no direct mapping to the system configuration space. Third, exhaustive profiling across this space is prohibitively expensive and time-consuming at workload scale. We propose BRANE, which solves Query2Conf with two ideas. An LLM extracts workload-specific binary characteristics from each query, serving as a translation layer between query semantics and the pipeline space. On top of this representation, one lightweight per-configuration predictor estimates the probability that the pipeline answers the query correctly, implicitly capturing combinatorial knob effects through profiled correctness labels rather than explicit modeling. Together, these two simple yet effective ideas enable BRANE to outperform fine-tuned end-to-end BERT and Qwen3-4B trained directly on Query2Conf. Across MuSiQue, BrowseComp-Plus, and FinanceBench, BRANE matches the accuracy of the best fixed pipeline at up to 89% lower cost and pushes the cost-quality Pareto frontier.
