摘要Abstract

安全更新创造了一个短暂但重要的窗口，在这个窗口中，防御者和 攻击者可以比较易受攻击的软件和已修补的软件。然而在许多运营中 设置中，最容易访问的工件是二进制包而不是源代码 补丁或咨询文本。本文询问语言模型代理是否 仅限于本地二进制派生证据，可以重建安全性 Linux 发行版更新的含义。 Patch2Vuln 是一个本地的、可恢复的 提取旧/新 ELF 对的管道，将它们与 Ghidra 和 Ghidriff 进行比较， 对更改的职能进行排名，建立候选档案，并要求离线代理 制定初步审核、有限验证计划和最终审核。Security updates create a short but important window in which defenders and attackers can compare vulnerable and patched software. Yet in many operational settings, the most accessible artifacts are binary packages rather than source patches or advisory text. This paper asks whether a language-model agent, restricted to local binary-derived evidence, can reconstruct the security meaning of Linux distribution updates. Patch2Vuln is a local, resumable pipeline that extracts old/new ELF pairs, diffs them with Ghidra and Ghidriff, ranks changed functions, builds candidate dossiers, and asks an offline agent to produce a preliminary audit, bounded validation plan, and final audit.

The agent localizes a verified security-relevant patch function in 10 of 20 security pairs and assigns an accepted final root-cause class in 11 of 20. 2 问题定义Problem Definition

Patch2Vuln 研究安全更新作为一对可见的时刻 二进制工件，但分析人员尚未了解其含义。一个包是 旧的，另一个修好了；该补丁仅在代码布局、控件中可见 流、常量、调用、字符串和行为。任务是恢复 漏洞故事编码在这种差异中：与安全相关的地方 发生了变化，它可能消除了哪些不安全行为，哪些输入表面 达到代码，以及哪些有限的本地证据可以支持该假设。Patch2Vuln studies the moment when a security update is visible as a pair of binary artifacts but its meaning is not yet given to the analyst. One package is old and the other repaired; the patch is visible only in code layout, control flow, constants, calls, strings, and behavior. The task is to recover the vulnerability story encoded in that difference: where the security-relevant change occurred, what unsafe behavior it likely removed, what input surface reaches the code, and what bounded local evidence would support the hypothesis.

A.1 什么才算识别漏洞？What Counts as Identifying a Vulnerability?

对某些内存安全补丁最客观的验证是差异化 在旧二进制文件上失败并在新二进制文件上被拒绝或安全处理的输入 二进制。当有限验证发现此类证据时，我们会报告此类证据。然而， 需要崩溃或类似漏洞的输入作为唯一的成功指标 低估了有意义的重建：它奖励浅层可触发性， 惩罚高阈值整数和分配保护，并模糊论文的内容 漏洞利用生成的目标。因此，我们的主要指标是手动的 判定最终审核是否本地化了真正的安全相关补丁 家庭并解释其根本原因类别和输入媒介。The most objective validation for some memory-safety patches is a differential input that fails on the old binary and is rejected or handled safely on the new binary. We report such evidence when bounded validation finds it. However, requiring a crashing or exploit-like input as the only success metric would undercount meaningful reconstruction: it rewards shallow triggerability, penalizes high-threshold integer and allocation guards, and blurs the paper’s goal with exploit generation. Our primary metric is therefore manual adjudication of whether the final audit localizes a true security-relevant patch family and explains its root-cause class and input medium.

Across the full benchmark, 10 of 20 security-update pairs are localized by the agent, 11 of 20 receive an accepted evaluation root-cause label, and all five negative controls are rejected as未知unknown.

这很有用，因为原始二进制差异对于许多人来说不能直接操作 防守者。排名功能列表并不能解释更改是否可能是 边界检查、整数溢出防护、解析器状态修复或包装器重构。一个 结构化代理审计可以总结可能的输入媒介、受影响的代码 区域、验证策略、置信度和不确定性。This is useful because raw binary diffs are not directly actionable for many defenders. A ranked function list does not explain whether a change is likely a bounds check, integer overflow guard, parser-state fix, or wrapper refactor. A structured agent audit can summarize the likely input medium, affected code region, validation strategy, confidence, and uncertainty.

A.2 为什么诊断验证仍然困难Why Diagnostic Validation Remains Hard

Patch2Vuln 不会搜索崩溃漏洞。其验证阶段运行 从安全模式中选择的有界本地旧/新差异测试。这些测试 当它们揭示改变的诊断或拒绝行为时很有用，但是 阴性测试并不能反驳静态重建。外籍整数守卫 可能需要极限长度或 API 状态，而有界测试无法命中； libarchive 格式解析器需要精确的存档结构才能深入 元数据分支； tcpdump 数据包打印机路径可能需要特定的链接类型， 端口、选项或捕获长度组合。Patch2Vuln does not search for crashing exploits. Its validation stage runs bounded local old/new differential tests chosen from a safe schema. These tests are useful when they reveal changed diagnostics or rejection behavior, but a negative test does not disprove the static reconstruction. Expat integer guards may require extreme lengths or API states that bounded tests do not hit; libarchive format parsers require precise archive structures to reach deep metadata branches; tcpdump packet-printer paths may require specific linktypes, ports, options, or capture-length combinations.

轻量级可达性检查将加强此阶段：动态库 函数跟踪、候选地址上的调试器断点、QEMU/rr 样式 指令覆盖率，或二进制仪器。验证执行者应该 不仅报告旧/新输出，还报告可疑的候选函数或 到达了附近的基本街区。Lightweight reachability checks would strengthen this stage: dynamic library function tracing, debugger breakpoints on candidate addresses, QEMU/rr-style instruction coverage, or binary instrumentation. A validation executor should report not only old/new output, but whether the suspected candidate function or nearby basic blocks were reached.

A.3 补丁簇和微差异Patch Clusters and Micro-Diffs

Ubuntu 安全更新通常会同时修复多个 CVE。这是现实且 很重要，但它使精确评分变得复杂。 tcpdump 仿生对包括 大型上游解析器更新加上后来的 Ubuntu 向后移植更改。代理发现 真正的 OpenFlow 行为发生了变化，并且还本地化了过滤器文件路径，但是 这些是补丁簇的不同成员。因此评分应 区分越来越精确的级别：包和二进制、输入介质、 根本原因类、解析器或函数系列以及确切的源/CVE 匹配。Ubuntu security updates often fix multiple CVEs at once. This is realistic and important, but it complicates exact scoring. The tcpdump bionic pair includes a large upstream parser update plus later Ubuntu backport changes. The agent found real OpenFlow behavior changes and also localized the filter-file path, but these are different members of the patch cluster. Scoring should therefore distinguish increasingly precise levels: package and binary, input medium, root-cause class, parser or function family, and exact source/CVE match.

从仅二进制证据中准确命名 CVE 是最难的一层，而不是唯一的一层 成功标准。Exact CVE naming from binary-only evidence is the hardest tier, not the only success criterion.

该基准测试涵盖 25 个目标，并具有私有功能级预言机评分 所有 20 个安全更新对和所有五个控件，但它仍然是 UbuntuThe benchmark covers 25 targets with private function-level oracle scoring for all 20 security-update pairs and all five controls, but it is still an Ubuntu.debRPM 生态系统的实例化而不是证据，滚动 发行版或特定于供应商的二进制更新格式。评价也是 现实而不是完全盲目：包名称、路径、字符串、诊断、 代理仍可以看到已发送的符号。元数据盲和 符号抑制的变体需要单独测量。instantiation rather than evidence for RPM ecosystems, rolling distributions, or vendor-specific binary update formats. The evaluation is also realistic rather than fully blinded: package names, paths, strings, diagnostics, and shipped symbols remain visible to the agent. Metadata-blind and symbol-suppressed variants require separate measurement.

目标集包含真实的补丁簇。这提高了生态有效性 因为发行版安全更新通常会同时修复多个 CVE，但它 使得单个 CVE 归因不如实验室补丁对清晰。手册 因此，oracle 对选定的源函数族和二进制函数族进行评分 ELF 并记录 ELF 之外的 CVE，而不是强制执行精确的 CVE 比赛。这项任务需要手动注释，但更大规模的研究应该 使用多个注释者和注释者间协议。The target set contains real patch clusters. This improves ecological validity because distribution security updates often fix several CVEs at once, but it makes single-CVE attribution less clean than laboratory patch pairs. The manual oracle therefore scores source and binary function families inside the selected ELF and records CVEs that fall outside that ELF rather than forcing an exact CVE match. Manual annotations are necessary for this task, but larger studies should use multiple annotators and inter-annotator agreement.

最大的经验瓶颈是二进制差异和上下文导出堆栈： 六个安全对是排序或差异未命中，另外一对是 上下文导出未命中。这些被算作管道故障，而不是隐藏模型 成功。我们也不端到端运行 BinXray；本文比较原始 Ghidriff 排序、Patch2Vuln 排序器和代理重建 将完整的 BinXray 执行视为单独的补丁状态匹配基线。The largest empirical bottleneck is the binary-diff and context-export stack: six security pairs are ranker-or-diff misses, and one additional pair is a context-export miss. These are counted as pipeline failures, not hidden model successes. We also do not run BinXray end-to-end; this paper compares raw Ghidriff ordering, the Patch2Vuln ranker, and agent reconstruction while treating full BinXray execution as a separate patch-status matching baseline.

验证是有限的。两个 tcpdump 案例产生了最小化的旧/新行为 差异，但没有运行产生崩溃、超时、消毒剂发现或 内存损坏证明，并且系统并非设计用于合成漏洞利用 有效负载。这些差异表明生成的本地输入发生了变化 解析器行为，而不是说旧的二进制文件可以在 记忆损坏感；没有可达性跟踪，否定验证运行 也不能证明候选函数已经达到。Validation is bounded. Two tcpdump cases produced minimized behavioral old/new differentials, but no run produced a crash, timeout, sanitizer finding, or memory-corruption proof, and the system is not designed to synthesize exploit payloads. These differentials show that a generated local input reaches changed parser behavior, not that the old binary is exploitable in the memory-corruption sense; without reachability tracing, a negative validation run also cannot prove that the candidate function was reached.

这项工作本质上是双重用途的，因为攻击者也会检查公共补丁。 Patch2Vuln 的范围是理解和审计：代理没有任何建议或建议 重建期间的网络访问，验证是旧/新二进制文件的本地 Docker，报告的工件是漏洞解释和 诊断差异而不是利用有效负载。The work is inherently dual-use because attackers inspect public patches too. Patch2Vuln is scoped to understanding and audit: the agent has no advisory or web access during reconstruction, validation is local to old/new binaries in Docker, and the reported artifacts are vulnerability explanations and diagnostic differentials rather than exploit payloads.
