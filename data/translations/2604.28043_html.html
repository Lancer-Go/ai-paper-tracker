协作智能体推理工程 (CARE)：一种由主题专家、开发人员和辅助智能体系统地设计人工智能智能体的三方设计方法Collaborative Agent Reasoning Engineering (CARE): A Three-Party Design Methodology for Systematically Engineering AI Agents with Subject Matter Experts, Developers, and Helper Agents

Rahul Ramachandran    Nidhi Jha    Muthukumaran Ramasubramanian
摘要Abstract

大型语言模型（LLM）越来越多地用于科学和技术知识工作，但它们的性能在不同的任务体系中仍然参差不齐，并且结果在很大程度上取决于用户的专业知识和验证规则。 本文提出了 CARE（协作代理推理工程），这是一种用于工程 LLM 代理的规范的、分阶段的方法，其中主题专家 (SME)、开发人员和所需的基于 LLM 的帮助代理协作将隐性领域意图转化为明确的、可审查的工件，指定交互策略、基础、工具编排和验证。 CARE 将辅助代理构建为促进基础设施（受加速知识发现的影响），通过提出阶段性问题、以简洁的 Markdown 起草和规范化工件，以及在阶段关口提出具体修订供人工批准来提高规范吞吐量。 我们在 NASA 地球科学数据发现案例研究中评估了 CARE，其中使用工具的代理通过 NASA CMR API 检索数据集。 使用双门评估（用于快速迭代的综合基准，然后是 SME 创建的用于更高置信度验证的黄金基准）和 Recall@K 作为指标，CARE 设计的代理在相同模型和工具访问下优于基线，在合成门上实现更高的 Recall@1（n=621；71.7% vs 69.1%），在黄金门上实现更高的 Recall@5（n=43；27.2% vs 20.2%）。总体而言，CARE 通过使设计意图明确、可审查和随着时间的推移可验证，为构建可维护的 LLM 代理提供了实用、可重复的流程。Large Language Models (LLMs) are increasingly used in scientific and technical knowledge work, but their performance remains uneven across task regimes, and outcomes depend strongly on user expertise and verification discipline. This paper proposes CARE (Collaborative Agent Reasoning Engineering), a disciplined, stage-gated methodology for engineering LLM agents in which subject-matter experts (SMEs), developers, and required LLM-based helper agents collaboratively translate tacit domain intent into explicit, reviewable artifacts specifying interaction policy, grounding, tool orchestration, and verification. CARE frames helper agents as facilitation infrastructure (influenced by accelerated knowledge discovery) that increases specification throughput by asking phase-aligned questions, drafting and normalizing artifacts in concise Markdown, and proposing concrete revisions for human approval at stage gates. We evaluate CARE in a NASA Earth Science data discovery case study where a tool-using agent retrieves datasets via the NASA CMR API. Using a two-gate evaluation (synthetic benchmark for rapid iteration followed by an SME-created gold benchmark for higher-confidence validation) and Recall@K as the metric, the CARE-designed agent outperforms a baseline under identical model and tool access, achieving higher Recall@1 on the synthetic gate (n=621; 71.7% vs 69.1%) and higher Recall@5 on the gold gate (n=43; 27.2% vs 20.2%). Overall, CARE provides a practical, repeatable process for building maintainable LLM agents by making design intent explicit, reviewable, and verifiable over time.

I 简介Introduction

法学硕士现在可以在许多任务中生成高质量的文本和代码，从而创造了加速科学和技术工作流程的机会，分析师可以在其中解释需求、检索信息并将证据综合到决策中。 然而，法学硕士在不同的任务和环境中的表现仍然参差不齐，通常被描述为“锯齿状的技术前沿”，其中输出在某些制度内非常有用，但在其之外则不可靠，并且用户技能决定生产力是提高还是降低LLMs now produce high-quality text and code across many tasks, creating an opportunity to accelerate scientific and technical workflows where analysts interpret requirements, retrieve information, and synthesize evidence into decisions. However, LLM performance remains uneven across tasks and contexts, often described as a “jagged technological frontier”, where outputs can be highly useful within certain regimes but unreliable outside them, and where user skill determines whether productivity increases or decreases[1]。 这种不均匀性在新手和专家分析师之间造成了实际差距：专家更一致地应用领域约束、验证中间输出并构建多步骤工作流程，而新手更有可能接受流畅但不正确的结果或未明确说明意图和约束。. This unevenness creates a practical gap between novice and expert analysts: experts more consistently apply domain constraints, verify intermediate outputs, and structure multi-step workflows, while novices are more likely to accept fluent but incorrect results or to under-specify intent and constraints.

定制的LLM代理可以通过将专家分析实践嵌入到可重用的系统行为中来缩小这一差距，包括规范的分解、验证习惯、领域基础和（相关时）工具使用工作流程，使检索和计算具有权威性而不是推测性。 然而，构建可靠的代理并非易事，因为行为是从提示、基础内容、工具、编排逻辑和评估标准之间的交互中产生的；试错提示迭代可能会导致系统默默地失败、在小变化后回归或过度适应狭窄的测试用例。 传统的软件流程支持迭代，但它们不能直接解决代理工程问题，例如指定预期的推理行为、将 SME 知识转化为稳定的基础工件，以及构建随时间检测回归的验证基准。Custom LLM agents can reduce this gap by embedding expert analytic practices into reusable system behavior, including disciplined decomposition, verification habits, domain grounding, and (when relevant) tool-using workflows that make retrieval and computation authoritative rather than speculative. Yet building reliable agents is non-trivial because behavior emerges from interactions among prompts, grounding content, tools, orchestration logic, and evaluation criteria; trial-and-error prompt iteration can yield systems that fail silently, regress after small changes, or overfit to narrow test cases. Traditional software processes support iteration, but they do not directly solve agent-engineering problems such as specifying intended reasoning behavior, translating SME knowledge into stable grounding artifacts, and constructing verification benchmarks that detect regressions over time.

本文提出了协作代理推理工程（CARE），这是一种通过中小企业、开发人员和企业之间的三元协作来设计 LLM 代理的分阶段方法。This paper proposes Collaborative Agent Reasoning Engineering (CARE), a stage-gated methodology for engineering LLM agents via triadic collaboration among SMEs, developers, and必填required基于法学硕士的帮助代理。 辅助代理概念受到加速知识发现 (AKD) 的影响LLM-based helper agents. The helper-agent concept is influenced by accelerated knowledge discovery (AKD)[4]，它将人工智能定义为增强科学家认知能力和加速发现的工具；我们通过使用辅助代理来增强规范、工件起草和验证设计，将这一想法扩展到代理设计过程本身。 最近基于法学硕士的科学代理系统和调查进一步激发了多步骤工作流程的系统工程方法, which frames AI as a tool to augment scientists’ cognitive capabilities and speed discovery; we extend this idea to the agent design process itself by using helper agents to augment specification, artifact drafting, and verification design. Recent LLM-based scientific agent systems and surveys further motivate systematic engineering approaches for multi-step workflows[2, 3, 7, 5].

贡献。Contributions.我们做出三项贡献： (1) 我们引入 CARE 作为一种阶段控制的、工件驱动的方法，通过中小企业、开发人员和帮助代理之间的三方协作来工程 LLM 代理； （2）我们将LLM代理解构为交互策略、领域基础、工具编排和评估/验证，并将这些目标映射到CARE工件和门； (3) 我们提出了 NASA 地球科学数据发现案例研究，证明 CARE 使用双门评估在相同模型和工具访问下相对于最小基线提高了检索性能。We make three contributions: (1) we introduce CARE as a stage-gated, artifact-driven methodology for engineering LLM agents via three-party collaboration among SMEs, developers, and helper agents; (2) we deconstruct LLM agents into interaction policy, domain grounding, tool orchestration, and evaluation/verification, and map these targets to CARE artifacts and gates; and (3) we present a NASA Earth Science data discovery case study demonstrating that CARE improves retrieval performance relative to a minimal baseline under identical model and tool access using a two-gate evaluation.

II LLM代理的设计目标Design Targets for LLM Agents

LLM“代理”最好理解为一个系统，它反复将输入目标转换为中间决策和行动，而不是产生单个响应的单个提示。 在 CARE 中，我们将代理质量视为取决于四个相互作用的设计目标：An LLM “agent” is best understood as a system that repeatedly transforms an input goal into intermediate decisions and actions rather than a single prompt producing a single response. In CARE, we treat agent quality as dependent on four interacting design targets:

交互策略和推理策略Interaction policy and reasoning strategy指定代理如何解释意图、分解任务、管理不确定性、决定何时提出澄清问题以及执行批评/验证行为。specifies how the agent interprets intent, decomposes tasks, manages uncertainty, decides when to ask clarifying questions, and performs critique/verification behaviors.

域接地Domain grounding指定代理应将哪些领域知识和上下文视为权威（术语、假设、模式、决策标准），以及如何限制解释以减少看似合理但错误的输出。specifies what domain knowledge and context the agent should treat as authoritative (terminology, assumptions, schemas, decision criteria) and how it constrains interpretation to reduce plausible-but-wrong outputs.

工具编排Tool orchestration指定代理可以使用哪些工具、每个工具的用途、如何表示输入/输出、如何选择工具以及如何处理错误、歧义、重试和出处。specifies what tools the agent may use, what each tool is for, how inputs/outputs are represented, how tool choice is made, and how errors, ambiguity, retries, and provenance are handled.

评估与验证Evaluation and verification指定成功的含义、如何衡量实际任务（包括复杂或模糊查询）的性能，以及如何随着提示、工具或模型的发展检测回归。specifies what success means, how performance is measured on realistic tasks (including complex or ambiguous queries), and how regressions are detected as prompts, tools, or models evolve.

由于故障经常出现在这些目标之间的边界处，因此临时的即时调整很少会产生稳健的行为。 CARE 将这些目标作为带有审查门的明确工件来操作，因此意图是可测试和可维护的。这种分解如图 1 所示。Because failures often arise at the boundaries between these targets, ad hoc prompt tweaking rarely yields robust behavior. CARE operationalizes these targets as explicit artifacts with review gates so intent is testable and maintainable. This decomposition is illustrated in Fig.1.

三、III关怀方法论CARE Methodology

CARE 是一种用于工程 LLM 代理的协作方法，其中 SME、开发人员和基于 LLM 的帮助代理共同将领域专业知识和工作流程需求转化为明确的、可审查的工件，而不是依赖于难以重现和验证的迭代提示修补。 CARE 通过阶段门组织成多个阶段，每个阶段都会生成指定交互策略、领域基础、工具编排和评估/验证的工件，以便随着工具、提示和模型的发展，可以测试和维护代理行为。图 1 概述了完整的方法及其工件流程。CARE is a collaborative methodology for engineering LLM agents in which SMEs, developers, and LLM-based helper agents jointly translate domain expertise and workflow requirements into explicit, reviewable artifacts rather than relying on iterative prompt tinkering that is difficult to reproduce and verify. CARE is organized into phases with stage gates, where each phase produces artifacts specifying interaction policy, domain grounding, tool orchestration, and evaluation/verification so agent behavior can be tested and maintained as tools, prompts, and models evolve. The complete methodology and its artifact flow are outlined in Fig.2.

第 1 阶段：确定代理范围并分解代理。Phase 1: Scope and decompose the agent.团队定义目标工作流程、预期用户和约束，并使用代理解构来定义在实施开始之前必须指定的内容。 辅助代理起草初始范围工件集（约束、分解目标、预期用户）以进行 SME 和开发人员审查。The team defines the target workflow, intended users, and constraints, and uses the agent deconstruction to define what must be specified before implementation begins. Helper agents draft an initial scoped artifact set (constraints, decomposition targets, intended users) to seed SME and developer review.

第 2 阶段：关键信息获取（工具、上下文、输出格式）。Phase 2: Key information elicitation (Tools, Context, Output format).辅助代理通过生成有针对性的、阶段一致的问题并以一致的 Markdown 格式起草工具/上下文/输出工件以供人工验证来运行结构化启发。 此阶段在详细的行为设计之前明确操作环境和预期的可交付成果。Helper agents run structured elicitation by generating targeted, phase-aligned questions and drafting the Tools/Context/Output artifacts in consistent Markdown for human validation. This phase makes the operational environment and expected deliverables explicit before detailed behavior design.

第三阶段：推理政策和护栏。Phase 3: Reasoning policy and guardrails.辅助代理起草候选推理策略和护栏行为，以解决不确定性、证据缺失、工具错误和不明确的查询，并根据 SME 和开发人员的反馈对其进行迭代修改。 第三阶段强制要求安全边界和预期的思维逻辑决定提示必须实现的内容。Helper agents draft candidate reasoning policies and guardrail behaviors to address uncertainty, missing evidence, tool errors, and ambiguous queries, and iteratively revise them based on SME and developer feedback. Phase 3 enforces that safety boundaries and the intended thinking logic determine what the prompt must implement.

第 4 阶段：快速架构和工具编排实施。Phase 4: Prompt architecture and tool-orchestration implementation.此阶段将批准的工件转换为使用提示目录中的模式设计的可实现的代理提示This phase translates the approved artifacts into an implementable agent prompt designed using patterns from a prompt catalog[6]，包括接地注入策略、工具模式、路由逻辑和重试策略。 辅助代理生成与输入工件一致的提示；实施被视为将工件结构化转换为工作提示，而不是临时迭代。, including grounding injection strategy, tool schemas, routing logic, and retry policies. A helper agent generates a prompt aligned with the input artifacts; implementation is treated as structured translation of artifacts into a working prompt rather than ad hoc iteration.

第五阶段：基准测试和验证。Phase 5: Benchmarking and verification.此阶段定义构建实际查询基准的要求，定义评分标准和通过/失败阈值，并将评估集成到迭代中。 帮助代理引发中小企业的响应，以识别支持自动化或半自动化基准构建的来源、查询类型和目标答案格式；然后，单独的辅助代理工作流程可以生成基于这些来源的候选基准项目，然后进行 SME 验证。This phase defines requirements for constructing a benchmark of realistic queries, defines scoring rubrics and pass/fail thresholds, and integrates evaluation into iteration. Helper agents elicit responses from SMEs to identify sources, query types, and target answer formats that support automated or semi-automated benchmark construction; a separate auxiliary agent workflow can then generate candidate benchmark items grounded in those sources, followed by SME validation.

舞台大门。Stage gates.CARE 的阶段关卡是通过开发人员和中小企业对阶段工件的审查和批准来定义的，确保预期的行为、约束和验证标准与领域要求和实施可行性保持一致。CARE’s stage gates are defined by review and approval by both developers and SMEs of phase artifacts, ensuring intended behavior, constraints, and verification criteria remain aligned with domain requirements and implementation feasibility.

V 讨论和限制Discussion and Limitations

案例研究表明，当工作流程需要细致入微的领域解释和受限检索时，CARE 最为有价值，因为 CARE 的分阶段工件将隐性 SME 实践转化为明确的推理策略、上下文/基础要求、工具使用约束和验证标准，否则这些标准很难在迭代中保持一致。The case study suggests CARE is most valuable when workflows require nuanced domain interpretation and constrained retrieval, because CARE’s staged artifacts translate tacit SME practice into explicit reasoning policies, context/grounding requirements, tool-use constraints, and verification criteria that are otherwise difficult to keep consistent across iterations.

对有效性的威胁包括基准敏感性和基准泄漏或过度拟合，这些可能通过多种途径发生，包括工件的迭代细化和基准分布的提示、隐式“教导测试”的辅助代理启发，以及可能编码不代表真实用户查询的潜在规律的辅助基准生成工作流程。 如果辅助代理启发未能涵盖重要维度（例如，边缘情况查询类型、工具约束），或者如果阶段控制审查变得肤浅，那么这种风险就会变得更加复杂，因为团队可能会优化基准可见行为，同时留下未指定的实际故障模式，因此未经测试。Threats to validity include benchmark sensitivity and benchmark leakage or overfitting that can occur through multiple pathways, including iterative refinement of artifacts and prompts to the benchmark distribution, helper-agent elicitation that implicitly “teaches to the test,” and auxiliary benchmark-generation workflows that may encode latent regularities not representative of real user queries. This risk is compounded if helper-agent elicitation fails to cover important dimensions (e.g., edge-case query types, tool constraints) or if stage-gate reviews become superficial, because teams may optimize benchmark-visible behaviors while leaving real-world failure modes unspecified and therefore untested.

CARE 还取决于CARE also depends on the帮手的素质quality of helper agents（特别是他们是否在相关维度上提出了正确的问题并忠实地起草了工件）以及(especially whether they ask the right questions across relevant dimensions and faithfully draft artifacts) and on the中小企业和开发商的专业水平expertise levels of SMEs and developers（中小企业必须明确细致入微的限制；开发人员必须确保工具的现实性和可行性）。 最后，模型/提供商的偏差可能会影响已部署的代理和辅助代理促进层，从而通过 CARE 的阶段门以及工件和辅助代理提示模块的受控版本控制来激励定期重新验证。(SMEs must surface nuanced constraints; developers must ensure tool realism and feasibility). Finally, model/provider drift can affect both the deployed agent and the helper-agent facilitation layer, motivating periodic re-verification through CARE’s stage gates and controlled versioning of artifacts and helper-agent prompt modules.

VI 结论Conclusion

本文介绍了 CARE（协作代理推理工程），这是一种用于工程 LLM 代理的规范的、分阶段的方法，它将领域专业知识和工作流程需求转化为可重用的工件，指定交互策略、基础、工具编排和验证，而不是依赖于试错提示迭代。 CARE 被明确定义为中小企业、开发人员和所需帮助代理之间的三方工作流程，帮助代理提供便利基础设施，提高规范吞吐量，同时人类保留审查关口的权力。 在使用 NASA CMR API 的 NASA 地球科学数据发现案例研究中，CARE 设计的代理在双门评估中的相同模型和工具访问下优于基线，在合成基准和基于 SME 的基准上展示了一致的检索增益。 未来的工作应优先考虑多域复制和进一步详细的评估，以测试 CARE 的收益是否能够跨域、查询分布和工具生态系统持续存在。This paper introduced CARE (Collaborative Agent Reasoning Engineering), a disciplined, stage-gated methodology for engineering LLM agents that translates domain expertise and workflow requirements into reusable artifacts specifying interaction policy, grounding, tool orchestration, and verification rather than relying on trial-and-error prompt iteration. CARE is explicitly defined as a three-party workflow among SMEs, developers, and required helper agents, with helper agents providing facilitation infrastructure that increases specification throughput while humans retain authority at review gates. In a NASA Earth Science data discovery case study using the NASA CMR API, a CARE-designed agent outperformed a baseline under identical model and tool access in a two-gate evaluation, demonstrating consistent retrieval gains on both synthetic and SME-grounded benchmarks. Future work should prioritize multi-domain replication and further detailed evaluation to test whether CARE’s gains persist across domains, query distributions, and tool ecosystems.
