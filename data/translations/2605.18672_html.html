摘要Abstract

本立场文件认为，在单个抽象层中强制实施 LLM 代理安全不仅不是最理想的，而且对于已部署的 LLM 代理来说绝对是不够的——这是代理执行工作方式的结构性结果，而不是当前系统的偶然限制。共同构成安全操作的三个维度——语义意图和政策合规性、环境有效性和动态可行性——每个维度都依赖于在不同执行阶段可用的严格不同的信息集。没有任何一个护栏可以同时证明这三者。 我们认为，社区必须采用基于合约的架构来应对，其中每个安全维度都由独立认证层强制执行，其概率保证满足下一个安全维度的假设。我们勾画出这样的架构，并通过概率链式法则导出它所允许的组合系统级安全边界。三个悬而未决的问题存在于这个和可部署的之间 标准：非独立同分布的边界估计跟踪、部署漂移下合约的优雅降级，以及 扩展到多代理设置——最重要的 LLM代理运行时保证中未完成的事情。This position paper argues that enforcing LLM agent safety within a single abstraction layer is not merely suboptimal but categorically insufficient for deployed LLM agents—a structural consequence of how agent execution works, not a contingent limitation of current systems. The three dimensions that jointly constitute safe operation—semantic intent and policy compliance, environmental validity, and dynamical feasibility—each depend on a strictly distinct information set that becomes available at a different stage of execution. No single guardrail can certify all three. We argue the community must respond with a contract-based architecture in which each safety dimension is enforced by an independently certified layer whose probabilistic guarantee satisfies the assumption of the next. We sketch such an architecture and derive the compositional system-level safety bounds it admits via the chain rule of probability. Three open problems stand between this and a deployable standard: bound estimation from non-i.i.d. traces, graceful degradation of contracts under deployment drift, and extension to multi-agent settings—the most important unfinished business in LLM agent runtime assurance.

在安全关键环境中部署 LLM 代理会带来 运行时间保证面临着质的新挑战。 LLM 代理使用语言模型作为其推理引擎 实现面向任务的功能：它接收指令 来自人类用户，进行多步骤推理和规划，以及 通过工具调用或物理与环境交互 执行。 与传统软件不同，传统软件的行为是形式化的 指定的，与静态语言模型不同，静态语言模型的输出 不对世界采取行动，LLM代理结合了非确定性 通过闭环执行进行推理，其中生成计划 影响世界和未来的观察。The deployment of LLM agents in safety-critical settings poses a qualitatively new challenge for runtime assurance. An LLM agent uses a language model as its reasoning engine to implement task-oriented functionality: it receives instructions from human users, conducts multi-step reasoning and planning, and interacts with the environment through tool invocation or physical execution. Unlike conventional software, whose behaviour is formally specified, and unlike static language models, whose outputs do not act on the world, LLM agents combine non-deterministic reasoning with closed-loop execution in which generated plans influence the world and future observations.
