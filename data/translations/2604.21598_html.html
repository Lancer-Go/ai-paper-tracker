DryRUN：论公共测试在 LLM 驱动的代码生成中的作用DryRUN: On the Role of Public Tests in LLM-Driven Code Generation

Kaushitha Silva WSO2Santa ClaraCAUSA kaushitha@wso2.com 0009-0005-0098-7815 and Srinath Perera WSO2Santa ClaraCAUSA srinath@wso2.com 0000-0002-4457-903X
摘要。Abstract.

多代理框架广泛应用于自主代码生成，并在复杂算法问题解决中得到应用。最近的工作通过结合模拟驱动的规划和调试来解决生成功能正确的代码的挑战，其中语言模型跟踪执行步骤以验证逻辑。然而，这些方法依赖于人类提供的公共测试用例来支撑调试和模拟循环。手动编写全面的输入输出示例是软件开发生命周期中的劳动密集型瓶颈。由于在现实世界的软件工程中实现之前很少有真实的输入输出示例，因此这种依赖性将方法限制为策划的竞争性编程基准。此外，我们发现对这些公开测试的依赖会导致“过度自信差距”，导致框架过度拟合简单的示例并在隐藏评估上失败。相反，我们观察到外部样本输入对于代码生成来说并不是严格必要的。我们证明大型语言模型可以自主生成有效输入并模拟执行跟踪以进行自我纠正。因此，我们开发了 DryRUN，这是一个框架，通过允许法学硕士迭代计划、自主生成自己的输入并模拟执行，从而消除对真实样本的需求，从而减轻算法的过度自信。对 LiveCodeBench v6 数据集（2025 年 3 月后）的评估表明，DryRUN 的性能与 CodeSIM（一种最先进且依赖于公共测试的框架）相匹配，同时完全无需公共测试用例或外部执行反馈即可运行，同时减少了输出令牌消耗。Multi-agent frameworks are widely used in autonomous code generation and have applications in complex algorithmic problem-solving. Recent work has addressed the challenge of generating functionally correct code by incorporating simulation-driven planning and debugging, where language models trace execution steps to verify logic. However, these approaches depend on human-provided public test cases to ground the debugging and simulation loop. Manually authoring comprehensive input-output examples is a labor-intensive bottleneck in the software development lifecycle. Because ground-truth input-output examples are rarely available prior to implementation in real-world software engineering, this dependency restricts methods to curated competitive programming benchmarks. Furthermore, we identify that reliance on these public tests induces an “overconfidence gap,” causing frameworks to overfit to simplistic examples and fail on hidden evaluations. In contrast, we observe that external sample inputs are not strictly necessary for code generation. We demonstrate that large language models can autonomously generate valid inputs and simulate execution traces to self-correct. Consequently, we develop DryRUN, a framework that eliminates the need for ground-truth samples by allowing the LLM to iteratively plan, autonomously generate its own inputs and simulate execution, mitigating algorithmic overconfidence. Evaluations on the LiveCodeBench v6 dataset (post-March 2025) demonstrate that DryRUN matches performance against CodeSIM, a state-of-the-art and public-test-dependent framework, while operating entirely without public test cases or external execution feedback while reducing output token consumption.

3.3. DryRUN 与 CodeSIMDryRUN vs CodeSIM

尽管 DryRUN 和 CodeSIM 都遵循相似的模拟阶段，但这两种方法之间存在关键的根本区别。Although both DryRUN and CodeSIM follow a similar simulation phase, there are key fundamental differences that separates the two approaches.

  • •

    自主计划细化：Autonomous Plan Refinement:DryRUN 包括一个没有外部反馈的计划细化阶段。通过提示法学硕士改进逻辑、添加更多细节步骤并考虑更多边缘情况来完善该计划。DryRUN consists of a plan refinement phase with no external feedback. The plan is refined by prompting the LLM to improve the logic, add more details steps and consider more edge cases.

  • •

    免执行细化：Execution-Free Refinement:DryRUN 严格省略外部代码执行，生成的代码永远不会针对任何输入执行。DryRUN strictly omits external code execution, the generated code is never executed against any input.

  • •

    自生成输入：Self-generated Inputs:DryRUN 对 LLM 自己提出的重要输入进行心理模拟，而在 CodeSIM 中，输入是从失败的公共测试用例中选择的。DryRUN does the mental simulation of a non-trivial input that the LLM comes up with its own, whereas in CodeSIM, the input is chosen from the failed public test cases.

  • •

    模拟之前是计划细化：Simulation is preceded by plan refinement:DryRUN 总是完善计划，然后生成代码。相比之下，CodeSIM 会提示法学硕士修复代码或计划。DryRUN always refines the plan and then generates the code. In comparison CodeSIM prompts the LLM to either repair the code or the plan.

  • •

    最终代码细化：Final Code Refinement:DryRUN最终对精炼后的代码进行打磨，这是为了弥补精炼阶段可能引入的语法或逻辑错误而造成的执行不足。DryRUN finally polishes the refined code, this is to compensate for the lack of execution where there may have been syntax or logic errors introduced in the refining stage.

First, adapting mental trace-driven refinement for Small Language Models (SLMs) remains an open challenge. Initial experiments indicate that current SLMs struggle with the multi-step reasoning required for mental simulation, and inability to follow complex commands (e.g: writing code when simulating, writing plans when prompted to refine the code), and frequently introducing syntax errors when generating the code. 6. 结论Conclusion

当前的代码生成框架严重依赖于人类提供的公共测试，与现实世界的软件工程脱节，在现实世界中，通常无法获得全面的输入输出示例。我们认为，频繁依赖这些简单化的测试可能会导致模型对无法覆盖复杂边缘情况的有缺陷的解决方案过于自信。为了解决这个问题，DryRUN 在严格的零示例约束下运行，通过迭代规划、自主合成有效输入和心理模拟执行跟踪，消除了对外部沙箱的需求。基于 LCB 与最先进的解决方案和基线进行的实证评估表明，公共测试用例在驱动正确性方面的作用远小于社区通过在不使用公共测试用例的情况下匹配 SOTA 性能所认为的作用。虽然像 CodeSIM 这样的标准方法由于依赖于琐碎的测试预言而表现出夸大的过度自信差距，但 DryRUN 在保持可比性能的同时保持了低得多的差距，证明了免执行自我纠正的有效性。最终，这些发现挑战了标准评估实践，并提出了一个关键问题：是否应该将公共测试用例完全从编码基准中删除，以防止该领域的模型出现偏见和过度自信。Current code generation frameworks heavily depend on human-provided public tests, creating a disconnect from real-world software engineering where comprehensive input-output examples are often unavailable. We argued that relying on these simplistic tests frequently can cause the model to become overconfident in flawed solutions that fail to cover complex edge cases. To address this, DryRUN operates under strictly zero-example constraints by iteratively planning, autonomously synthesizing valid inputs and mentally simulating execution traces, eliminating the need for external sandboxes. Empirical evaluations based on LCB against state-of-the-art solutions and baselines demonstrate that the role of public test cases in driving correctness is much smaller than the community believes by matching the SOTA performance without using public test cases. While standard methods like CodeSIM exhibit an inflated overconfidence gap due to their reliance on trivial testing oracles, DryRUN maintains a much lower gap while maintaining comparable performance, proving the efficacy of execution-free self-correction. Ultimately, these findings challenge standard evaluation practices and raise the critical question of whether public test cases should be removed from coding benchmarks entirely to prevent biased, overconfident models in the field.
