1 简介Introduction

考试时提示学习Test-time prompt learning提供了一种轻量级机制，用于在部署后调整基础模型。 先前的工作表明，提示可以作为有效的适应界面，而无需更新模型权重offers a lightweight mechanism for adapting foundation models after deployment. Prior work shows that prompts can serve as an effective adaptation interface without updating model weights[10]，黑盒优化器可以根据模型反馈修改指令, and black-box optimizers can revise instructions from model feedback[21, 32]。 测试时提示学习更新提示新输入、分布变化和故障模式，而不是依赖固定的离线提示。 这使得它适合自我改进的代理，通过与环境的交互来完善行为，就像在反射代理和不断发展的上下文系统中一样. Rather than relying on a fixed offline prompt, test-time prompt learning updates prompts for new inputs, distribution shifts, and failure modes. This makes it suitable for self-improving agents, where behavior is refined through interaction with the environment, as in reflective agents and evolving-context systems[26, 35].

However, they mostly adapt within a single dataset or benchmark. In real-world deployment, incoming queries often come from heterogeneous domains, task formats, and capability mixtures. 我们建议We propose伊布Eevee，一个测试时即时学习框架，通过以下方式增强即时学习：, a test-time prompt learning framework that augments prompt learning with a路由器router。 路由器不会强制所有输入通过一条适应路径，而是将流划分为任务集群，并将每个集群分配给合适的提示配置。 这保留了基于提示的适应，同时减少了跨域的破坏性干扰。. Instead of forcing all inputs through one adaptation path, the router partitions the stream into task clusters and assigns each cluster to a suitable prompt configuration. This preserves prompt-based adaptation while reducing destructive interference across domains.

然而，设计路由器本身就很困难。 僵化的路由器无法捕获多样化的任务结构，而不稳定的路由器会破坏即时优化。 提示学习器和路由器也是耦合的：路由确定每个提示学习哪些示例，提示行为确定哪个路由策略有用。 因此我们引入一个Designing the router, however, is itself difficult. A rigid router fails to capture diverse task structure, while an unstable router disrupts prompt optimization. The prompt learner and router are also coupled: routing determines which examples each prompt learns from, and prompt behavior determines which routing policy is useful. To make this co-evolution practical, we further design a three-stage training process that initializes useful prompt slots, explores coupled updates efficiently, and then converges under a stable router.

5 结论Conclusion

我们介绍了We introduced伊布Eevee，一个多数据集测试时提示学习框架，适用于面对异构任务流而不是单一基准分布的 LLM 代理。为了减少交叉数据集干扰，, a multi-dataset test-time prompt learning framework for LLM agents facing heterogeneous task streams rather than a single benchmark distribution. To reduce cross-dataset interference,伊布Eevee维护路由器条件提示集，因此可以将不同的输入分配给专门用于兼容任务行为的提示。因为路由器和提示相互依赖，maintains a router-conditioned prompt set, so different inputs can be assigned to prompts specialized for compatible task behavior. Because the router and prompts depend on each other,伊布Eevee使用三阶段路由器提示协同进化过程，初始化有用的提示，探索耦合更新，然后在稳定的路由器下细化提示。这使得该框架能够更好地适应异构的现实世界代理工作负载。uses a three-stage router-prompt co-evolution procedure that initializes useful prompts, explores coupled updates, and then refines prompts under a stable router. This makes the framework better aligned with heterogeneous real-world agent workloads.

实验表明，在混合数据集设置中，与即时学习基线相比，取得了巨大的进步，并且随着更多任务的引入以及合理的保留和跨模型迁移，收益也会增加。案例研究进一步表明，当反馈可以转化为可重用的程序、输出合同或任务解决策略时，即时学习是最有用的。总体而言，Experiments show strong gains over prompt-learning baselines in mixed-dataset settings, with benefits increasing as more tasks are introduced and with reasonable held-out and cross-model transfer. Case studies further suggest that prompt learning is most useful when feedback can be converted into reusable procedures, output contracts, or task-solving strategies. Overall,伊布Eevee为现实世界的考试即时学习提供了实用的自我改进方法和经验视角。offers both a practical self-improving method and an empirical lens for real-world test-time prompt learning.

6 局限性和社会影响Limitations and Social Impact

虽然Although伊布Eevee改进了多数据集即时学习，但局限性仍然存在。与其他基于 LLM 的进化过程一样，它不能保证运行过程中精确的性能再现，因为随机搜索可以产生不同的路由器和提示集。它的反馈循环仍然依赖于事实或基于规则的标签来积累任务知识，因此它还不是一个完全仅反射的学习器，并且仍然需要准备好的适应集而不是完全在线的流。一个实际的风险是分布不匹配：如果适应数据有噪声或与实际应用程序不一致，则学习到的提示可能泛化能力较弱，甚至会降低性能。部署应在更新前检查数据质量和分布相似性。improves multi-dataset prompt learning, limitations remain.
