摘要Abstract

文本到代码的一个基本限制是无法保证生成代码的正确性。因此，为了确保其正确性，生成的代码仍然需要开发人员进行审查、测试和维护。然而，解析 LLM 生成的代码可能既乏味又耗时，可能会抵消人工智能编码工具所承诺的生产力提升。为了应对这一挑战，我们提出A fundamental limitation of Text-to-Code is that no guarantee can be obtained about the correctness of the generated code. Therefore, to ensure its correctness, the generated code still has to be reviewed, tested, and maintained by developers. However, parsing through LLM-generated code can be tedious and time-consuming, potentially negating the productivity gains promised by AI-coding tools. To address this challenge, we present维维拉Viverra，一个自动产生的系统, a system that automatically produces正式验证的注释formally verified annotations与生成的代码一起帮助用户理解生成的程序。给定自然语言任务描述，alongside generated code to aid user’s understanding of the generated program. Given a natural-language task description,维维拉Viverra提示法学硕士综合一个 C 程序以及表达安全性和正确性属性的候选断言。然后，它通过有界模型检查器组合以组合和尽力的方式验证这些断言。对 18 种不同编程任务的评估表明prompts an LLM to synthesize a C program together with candidate assertions expressing safety and correctness properties. 1 简介Introduction

基于大型语言模型 (LLM) 的文本到代码可以显着提高软件开发效率。然而，LLM 生成的代码是不透明的：细微的错误、不正确的逻辑和违反的假设都可能被忽视。在实践中，开发人员必须手动审查或重写 LLM 生成的程序，然后才能信任它们，这种开销可能会抵消人工智能编码工具所承诺的生产力提升。 由于文本到代码从根本上不能保证生成的代码在任何细节级别上正确实现自然语言规范，因此人类的参与仍然是不可避免的。因此，我们认为文本到代码的一个关键瓶颈是开发人员缺乏有效的方法来检查生成的代码。在本文中，我们提出以下问题：Text-to-Code based on Large Language Models (LLMs) can significantly improve software development productivity. However, LLM-generated code is opaque: subtle bugs, incorrect logic, and violated assumptions can all slip through unnoticed. In practice, developers must manually review or rewrite LLM-produced programs before they can trust them, an overhead that risks negating the productivity gains promised by AI coding tools. Since Text-to-Code fundamentally cannot guarantee that the generated code correctly implements the natural language specification at any level of detail, human involvement is still unavoidable. We therefore argue that a key bottleneck in Text-to-Code is that developers lack efficient ways to check the generated code. In this paper, we ask the following question:我们如何帮助开发人员理解和分析人工智能生成的代码？How can we help the developer to understand and analyze AI-generated code?

这个问题的标准答案是彻底执行A standard answer to this question is to perform thorough测试testing。然而，生成的代码可能很大，逻辑可能很重要，并且仅测试有限数量输入的见证正确性；它们无法可靠地表征各种执行跟踪中的一般程序行为。另一方面，完整的形式验证，例如通过 Lean 或 Rocq 等证明助手，有可能为用户提供有关程序行为的绝对保证。然而，要求每个生成的程序都有完整的形式证明是不切实际的：即使有法学硕士的帮助，证明助手中的程序验证仍然非常耗时且具有挑战性. However, generated code can be large, the logic can be non-trivial, and tests only witness correctness on a finite number of inputs; they cannot reliably characterize general program behavior across a wide range of execution traces. On the other hand, full formal verification, e.g., through proof assistants such as Lean or Rocq, has the potential to provide the user with absolute guarantees about the behavior of the program. However, requiring a complete formal proof for every generated program is impractical: even with the aid of LLMs, program verification in proof assistants can still be time-consuming and challenging(First et al., 2023; Jiang et al., 2022)。因此，在这两个极端之间存在实用方法的空间，即提供比测试更强的保证而不需要完整的形式验证的方法。 为了探索这一差距，我们建议. Therefore, there is room for practical methods between these two extremes, that is, approaches that provide stronger guarantees than testing without requiring full formal verification. To explore this gap, we propose维维拉Viverra，一个新颖的文本到代码框架。目标是, a novel Text-to-Code framework. The goal of维维拉Viverra是为开发人员提供有关程序行为的经过验证的声明，同时保持获取该信息的成本实用。is to provide developers with proven statements about program behavior while keeping the cost of obtaining that information practical.

的设计The design of维维拉Viverra为了实现这一目标做出了一些重要的妥协。首先，它提出了这样的想法makes several important compromises to achieve this goal. First, it puts forward the idea of部分共同规范partial co-specification：以断言的形式共同生成代码以及代码的属性。这些属性从程序功能的自然语言描述中捕获需求。通常，它们表达代码的安全性和正确性属性。这些断言同时充当部分规范和形式验证的目标。: co-generating code together with properties of the code in the form of assertions. These properties capture requirements from the natural language description of the program functionality. Usually, they express safety and correctness properties of the code. These assertions serve simultaneously as partial specifications and as targets for formal verification.

其次，我们精心设计了Second, we carefully design a尽力验证best-effort verification程序。我们建议使用有界程序验证来以尽力而为的方式检查这些断言：我们不需要完全验证每个断言，这使得我们的验证在设计上不完整。关键的见解是，即使不完整的验证也是有价值的：确认在有限深度内保留所有执行的断言是开发人员可以依赖的正式事实，帮助他们理解代码的属性并缩小必须手动审查的范围。procedure. We propose using bounded program verification to check these assertions in a best-effort manner: we do not require every assertion to be fully verified, making our verification incomplete by design. The key insight is that even incomplete verification is valuable: an assertion confirmed to hold on all executions within a bounded depth is a formally grounded fact that the developer can rely on, helping them understand the properties of the code and narrowing what must be reviewed manually.

一个基本限制A fundamental limitation of维维拉Viverra是它只提供一定深度的保证。这是一种深思熟虑的权衡，可以使复杂程序的验证变得可行。将来，考虑调用人工智能驱动的证明助手以尽最大努力全面验证属性可能会很有趣。 虽然有界模型检查器的可扩展性在过去二十年中得到了显着提高，is that it only provides guarantees up to a certain depth. In the future, it might be interesting to consider invoking AI-driven proof assistants to fully verify properties in a best-effort manner. While the scalability of bounded model checkers has improved significantly in the past two decades,维维拉Viverra仍然可能受到底层验证者的瓶颈，并且只能与验证者支持的程序一起工作。接下来的步骤很自然，就是将该方法扩展到更丰富的语言（例如 Python 或 Rust）以及堆属性和量化不变量。最后，经过验证的注释的质量取决于法学硕士生成有意义的断言。将来，考虑替代属性启发策略或设计指标来评估生成的断言的质量将会很有趣。由于预算限制，人体研究是由众包人员进行的，规模相对较小。虽然我们观察到的模式是清晰且一致的，但在离线环境中与专业开发人员就更多问题进行扩展用户研究将进一步确定can still be bottlenecked by the underlying verifiers and can only work with programs supported by the verifiers. In the future, it would be interesting to consider alternative property elicitation strategies or design metrics to evaluate the quality of the generated assertions. Due to budget constraints, the human study was conducted with crowdworkers and at a relatively small scale.
