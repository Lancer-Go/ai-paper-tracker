2 概念背景Conceptual Background

技术债务隐喻起源于软件工程，用于描述捷径如何加速近期交付，同时增加未来的维护成本The technical-debt metaphor originated in software engineering to describe how shortcuts can accelerate near-term delivery while increasing future maintenance cost(Cunningham, 1992)。后来的实证研究表明，技术债务可以通过具体负债来衡量，并与修复成本、运营中断和系统寿命联系起来. Later empirical work showed that technical debt can be measured through concrete liabilities and linked to remediation cost, operational disruption, and system longevity(Ramasubbu et al., 2015)。机器学习系统将债务比喻扩展到代码之外，包括数据依赖性、隐藏的反馈循环、管道纠缠和未声明的消费者. Machine-learning systems expanded the debt metaphor beyond code to include data dependencies, hidden feedback loops, pipeline entanglement, and undeclared consumers(Sculley et al., 2015)。基础模型和代理系统再次扩展了问题，因为概率输出不再局限于预测。它们可以指导工具调用、检索或写入内存、触发外部操作以及跨多步骤工作流程修改计划. Foundation models and agentic systems extend the problem again because probabilistic outputs are no longer confined to prediction. They can guide tool calls, retrieve or write memory, trigger external actions, and revise plans across multi-step workflows(Bommasani et al., 2021; Yao et al., 2022).

传统的软件系统通常是确定性的：修复缺陷可能成本高昂，但通常是可重现的。预测机器学习系统引入了概率输出，但模型通常作为单个推理组件嵌入到更大的确定性工作流程中。代理人工智能系统作为控制循环运行。它们计划、调用工具、以检索到的上下文为条件、写入或读取内存以及在外部系统中执行操作。这就产生了一个独特的管理问题：组织必须管理概率行为，而不仅仅是代码质量或模型准确性。Traditional software systems are often deterministic: a defect may be expensive to fix, but it is usually reproducible. Predictive ML systems introduce probabilistic outputs, but the model is often embedded as a single inference component in a larger deterministic workflow. Agentic AI systems operate as control loops. They plan, call tools, condition on retrieved context, write or read memory, and act in external systems. This creates a distinctive managerial problem: the organization must govern probabilistic action, not only code quality or model accuracy.

3.1 代理技术债务Agentic Technical Debt

定义。Definition. 代理技术债务Agentic Technical Debt是通过权宜之计组装、修改或管理代理系统时产生的累积责任，这些选择使未来的变更、验证、解释或控制的成本高于必要的成本。is the accumulated liability created when an agentic system is assembled, modified, or governed through expedient choices that make future change, validation, explanation, or control more costly than necessary.

责任单位不仅仅是代码或数据。在代理系统中，债务还存在于指令、上下文、状态、工具契约、操作权限以及使未来变化安全的治理例程中。The unit of liability is not only code or data. In agentic systems, debt also resides in instructions, context, state, tool contracts, action authority, and the governance routines that make future changes safe.

  • •

3.2 随机税Stochastic Tax

定义。Definition. 随机税Stochastic Tax是在业务工作流程中将随机代理行为保持在可接受范围内的经常性操作负担。这种税收源于代理人工智能系统固有的概率性质，而不仅仅是源于工程缺陷，而且即使所有技术债务都得到偿还，它也可能持续存在。因此，相关的管理问题不是税收是否可以消失，而是哪一部分是操作随机行为不可避免的成本，哪一部分因可补救的债务而放大。is the recurring operating burden of keeping stochastic agentic behavior within acceptable bounds in a business workflow. The tax arises from the inherently probabilistic nature of agentic AI systems, not only from engineering shortcomings, and it can persist even if all technical debt were paid down. The relevant managerial question is therefore not whether the tax can be made to vanish, but which portion is an unavoidable cost of operating stochastic action and which portion is amplified by remediable debt.

该税与企业系统的一般运营负担不同。 ERP 系统会造成审核延迟、审批队列和覆盖工作流程，但这些成本在很大程度上是确定性和可预测的。This tax is distinct from the general operating burden of enterprise systems. ERP systems impose review delays, approval queues, and override workflows, but those costs are largely deterministic and predictable.随机税Stochastic Tax具体来说，是由非确定性引入的可变负担，即由于相同的语义输入不需要产生相同的执行路径而存在的成本。is specifically the variable burden introduced by non-determinism, namely the cost that exists because the same semantic input need not produce the same execution path.
