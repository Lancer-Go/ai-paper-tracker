摘要Abstract

如果没有刀，机器人可以用盘子切蛋糕吗？工具的使用极大地扩展了机器人的能力，但要创造性地使用超出其预期功能的工具，机器人面临着以下挑战：Can the robot use a plate to cut a cake if no knife is available? Tool use greatly expands robot capabilities, but to use tools creatively beyond their intended functions, the robot faces the challenge of开放世界可供性基础open-world affordance grounding：选择一个开放类别的对象作为工具并定位其特定的作用区域。为此，我们引入GROW: select an open-category object to act as a tool and localize its specific region of action. To this end, we introduce GROW2（GRounding Which andWhere），它利用对象部分作为自然抽象，将基础过程分层划分为语义和几何级别，从而绕过对数据密集型端到端训练的需求。从语义上讲，成长(GROunding Which and Where), which leverages object parts as a natural abstraction to split the grounding process hierarchically into semantic and geometric levels, thus bypassing the need for data-heavy, end-to-end training. Semantically, GROW2利用视觉语言模型（VLM）的常识推理来解析自然语言任务指令，选择合适的对象作为工具，并识别工具和目标对象上与任务相关的部分。从几何角度来看，视觉基础模型随后将选定的部件从单个 RGB-D 图像中磨成精确的 3D 区域。对既定基准的实验表明，GROWharnesses the commonsense reasoning of Vision-Language Models (VLMs) to parse a natural-language task instruction, select a suitable object as the tool, and identify task-relevant parts on the tool and the target object. Geometrically, vision foundation models then ground the selected parts into precise 3D regions from a single RGB-D image. Experiments on established benchmarks show that GROW2优于可供性预测基准的最新基线。此外，它实现了对开放类别对象的零样本泛化，并且在模拟和现实世界的机器人工具使用实验中都优于基线。outperforms state-of-the-art baselines on affordance prediction benchmarks. Further, it achieves zero-shot generalization over open-category objects and outperforms baselines in both simulated and real-world robot tool use experiments.

1 简介Introduction

人类拥有以即兴方式使用工具的非凡能力：从杂乱的日常物品场景中，我们可以识别哪个物品可以作为所需的工具，并通过正确的交互来应用它Humans possess a remarkable capacity to use tools in improvised ways: from a cluttered scene of everyday objects, we can identify which object can serve as the needed tool and apply it through the right interaction[1, 2, 3]（图。(Fig.1）。例如，当没有刀时，我们可以用盘子的边缘切蛋糕。我们的目标是将这种能力带给机器人，扩展其可行的操纵策略，并提高家庭和仓库等非结构化环境中的鲁棒性。). For example, when a knife is unavailable, we may cut a cake with the edge of a plate. We aim to bring this capability to robots, expanding their feasible manipulation strategies and improving robustness in unstructured environments such as homes and warehouses.

为了即兴使用工具，机器人必须对环境进行推理，并找出哪个物体可以用作工具以及相关交互区域在该物体上的位置，以便执行所需的动作。与之前关于机器人工具使用的工作不同，我们不假设工具对象已经指定To improvise tool use, the robot has to reason about the environment and figure out which object can serve as the tool and where the relevant interaction regions are on that object in order to perform the desired action. Unlike previous works on robot tool use, we do not assume that the tool object is already specified[4, 5, 6]，或者我们有一组固定的工具，具有预定义的工具功能映射, or that we have a fixed set of tools with predefined tool-function mappings[7, 8, 9]。相反，这项工作解决了开放世界可供性基础的问题：从场景中的一组开放类别对象中选择一个工具并预测其可供性区域。. Instead, this work addresses the problem of open-world affordance grounding: selecting a tool from a set of open-category objects in the scene and predicting its affordance regions.

开放世界可供性基础存在两个主要挑战。 (i) 系统需要在语义上理解开放类别对象的可供性。例如，要切蛋糕，机器人应该识别具有锋利边缘的物体，同时更喜欢盘子而不是簸箕，尽管它们的局部几何形状相似。 (ii) 可供性必须基于精确的几何区域以进行下游操作。这种基础应该以任务和环境为条件，并且应该推广到开放类别的对象。传统上，人们构建一个大规模数据集，将任务映射到可供性区域并训练端到端神经网络There are two main challenges in open-world affordance grounding. (i) The system needs to semantically understand affordances of open-category objects. C.3 真实世界的实验Real-World Experiments

工具和零件的选择以及可供性检测与模拟实验中使用的相同。在这里，我们描述了如何在现实实验中通过单视图 RGB-D 观察来执行运动规划。在可供性接地期间，我们以 3D 形式重建并注册工具和目标对象，这使我们能够将它们的网格加载到规划场景中。原则上，我们可以重建场景中的每个对象，但由于重复调用 SAM3D，这样做会非常耗时。相反，对于背景和其他对象，我们仅加载它们的部分点云作为碰撞几何体，并忽略它们的运动学和动力学。我们发现这种方法在效率和正确性之间提供了良好的权衡。Tool and part selection, as well as affordance detection, are identical to those used in the simulation experiments. Here, we describe how we perform motion planning from a single-view RGB-D observation in the real-world experiments. During affordance grounding, we reconstruct and register the tool and target object in 3D, which allows us to load their meshes into the planning scene. In principle, we could reconstruct every object in the scene, but doing so would be time-consuming due to repeated calls to SAM3D. Instead, for the background and other objects, we load only their partial point clouds as collision geometry and ignore their kinematics and dynamics. We found this approach provides a good trade-off between efficiency and correctness.
