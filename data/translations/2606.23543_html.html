1 简介Introduction

大型语言模型中以推理为中心的进展，例如 DeepSeek-R1 等基于 RL 的系统Reasoning-centric progress in large language models, exemplified by RL-based systems like DeepSeek-R1[2]，使得数据质量和奖励质量成为一阶训练瓶颈。对于视觉推理来说，这个问题更为尖锐，模型必须在图表中确定变量，从图表中读取值，将符号与视觉结构对齐，并执行多步骤数学推理。现有基准, has made data quality and reward quality first-order training bottlenecks. The issue is sharper for visual reasoning, where a model must ground variables in diagrams, read values from charts, align symbols with visual structures, and execute multi-step mathematical inference. Existing benchmarks[4, 5, 6, 7, 11]表明当前的多模态大语言模型（MLLM）在这些组合技能方面仍然存在不足。show that current multimodal large language models (MLLMs) still fall short on these compositional skills.

扩大这种培训制度不仅仅是收集更多提示的问题。许多多模态问答对都是基于图像的，但难度较低，强调识别或局部提取而不是多步推理；通用合成管道可以增加语料库大小，同时产生的问题只是更长、视觉效果较弱或可以从文本先验中回答。在 RL 阶段，瓶颈变得更加严重：随着推出和训练样本数量的增长，任何未经验证的标签都会反复转换为奖励信号，因此标签噪声不再是静态注释错误，而是可以系统地强化错误策略的训练目标。Scaling this training regime is not only a matter of collecting more prompts. Many multimodal question-answer pairs are image-grounded but of low difficulty, emphasizing recognition or local extraction over multi-step reasoning; generic synthetic pipelines can increase corpus size while producing questions that are merely longer, weakly visual, or answerable from text priors. The bottleneck becomes more severe at the RL stage: as the number of rollouts and training samples grows, any unverified label is repeatedly converted into reward signal, so label noise is no longer a static annotation error but a training objective that can systematically reinforce incorrect policies.

We chose this discretization for three reasons. First, a 12-topic vocabulary is small enough that each topic’s evolution prompt can be authored and audited by hand, and each gate’s failure modes can be enumerated; the full cross product would be impractical to maintain at this scale. Second, fixing the operator bundle per topic eliminates a class of compositional errors that arise when independently sampled operators produce internally inconsistent prompts (e.g., a multiple-choice answer-type operator attached to a problem whose answer is a continuous quantity). Third, adopting one prompt per topic makes the rejection reasons of the question-level gate easier to attribute back to the topic, which in turn supports per-topic threshold tuning. The trade-off is reduced expressivity: prompts that legitimately need to mix two routes (e.g., a document page combining a formula with a chart) are currently authored as part of the most fitting single topic rather than composed from independent route operators. Closing this gap with a verifier-aware operator-composition mechanism is left to future work.
