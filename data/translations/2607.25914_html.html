走向自治网络中标准化跨供应商代理工具信任管理Toward Standardized Cross-Vendor Agent Tool Trust Management in Autonomous Networks

Ravi Kant Sharma, Ashutosh Uttam, Ajay Kumar
摘要Abstract

自治网络级别 4-5 要求人工智能代理在没有人工监督的情况下跨供应商边界调用工具，但现有的管理标准缺乏跨供应商信任可见性的标准化机制。当供应商 B 的工具受到威胁时，供应商 A 的代理会继续调用该工具（不知道信任度下降），从而导致级联服务影响。我们呈现Autonomous Network Levels 4–5 require AI agents to invoke tools across vendor boundaries without human oversight, yet existing management standards lack a standardized mechanism for cross-vendor trust visibility. When a tool from Vendor B is compromised, agents from Vendor A continue invoking it—unaware of the trust degradation—causing cascading service impact. We present代理工具MOAgentToolMO，一个提议的用于代理工具信任管理的 3GPP NRM 信息模型。该模型包括：具有可证明的分级执行的正式定义的信任状态机、具有有限收敛的阻尼级联传播、通过现有管理服务 (MnS) 接口进行的跨供应商信任通知，以及通过 NRM 依赖图遍历进行追溯影响评估。跨多供应商拓扑的基于仿真的评估表明，标准化的跨供应商通知将爆炸半径从小时级未检测到的传播减少到以 MnS 通知交付为界的近实时遏制，并在有界迭代和跨供应商域的亚线性通知扩展中保证级联收敛。该框架在现有 3GPP 管理基础设施内运行，利用现有协议，并为值得信赖的多供应商自主网络管理提供标准化途径。, a proposed 3GPP NRM information model for agent tool trust management. The model comprises: a formally defined trust state machine with provable graduated enforcement, damped cascade propagation with bounded convergence, cross-vendor trust notifications via existing Management Services (MnS) interfaces, and retroactive impact assessment through NRM dependency graph traversal. Simulation-based evaluation across multi-vendor topologies shows that standardized cross-vendor notifications reduce blast radius from hours-scale undetected propagation to near-real-time containment bounded by MnS notification delivery, with cascade convergence guaranteed in bounded iterations and sub-linear notification scaling across vendor domains. The framework operates within existing 3GPP management infrastructure, leverages existing protocols, and provides a standardization pathway for trustworthy multi-vendor autonomous network management.

I 简介Introduction

自主 5G/6G 网络管理越来越依赖于跨供应商边界调用专用工具的 AI 代理Autonomous 5G/6G network management increasingly relies on AI agents that invoke specialized tools across vendor boundaries[1, 2]。在典型的多供应商部署中，一个供应商的无线电优化代理可能会使用由另一供应商管理的配置分析工具. In a typical multi-vendor deployment, a radio optimization agent from one vendor may consume a configuration analytics tool managed by another[3]。这些跨供应商工具依赖性创建了当前管理框架未明确解决的信任边界。. These cross-vendor tool dependencies create trust boundaries that are not explicitly addressed by current management frameworks.

核心挑战是The core challenge is跨供应商边界的信任可见性trust visibility across vendor boundaries。工具的行为可能会降低——其配置建议可能会超出运营商批准的基线，它可能会访问其声明范围之外的托管元素，其操作可能会导致通过 3GPP 性能管理检测到的 KPI 回归，或者可能会由于模型漂移而产生不一致的输出. A tool’s behavior may degrade—its configuration recommendations may drift beyond operator-approved baselines, it may access managed elements outside its declared scope, its actions may cause KPI regression detected through 3GPP performance management, or it may produce inconsistent outputs due to model drift[4, 5]。在单个供应商域内，这种降级会在内部检测到并包含在内。然而，在多供应商环境中，这种遏制会失败：当供应商 B 限制降级工具时，供应商 A 的代理（使用该工具的输出）没有机制来了解该限制。我们称此为. Within a single vendor domain, such degradation is detected and contained internally. In multi-vendor environments, however, this containment fails: when Vendor B restricts a degraded tool, Vendor A’s agents - which consume that tool’s outputs - have no mechanism to learn of the restriction. We term this沉默的信任退化silent trust degradation。其结果是，不可靠的输出继续推动跨域边界的自主决策，爆炸半径不断扩大而未被发现，直到服务影响变得可见. The consequence is that unreliable outputs continue to drive autonomous decisions across domain boundaries, with blast radius expanding undetected until service impact becomes visible[6].

现有方法无法弥补这一差距。基于沙箱的信任Existing approaches fail to close this gap. Sandbox-based trust[7]限制不受信任的功能，但不会暴露跨供应商的信任结果。每个供应商的框架confines untrusted functions but does not expose trust outcomes cross-vendor. Per-vendor frameworks[1]将信任视为专有的内部状态。零信任架构treat trust as proprietary internal state. Zero-trust architectures[8]验证身份和授权（二进制访问决策），但不通过分级执行来评估持续行为的可信度。verify identity and authorization - binary access decisions - but do not assess ongoing behavioral trustworthiness with graduated enforcement.

However, no IOC exists for agent tool trust state, no MnS notification type covers trust transitions[11]，并且在 3GPP 环境中尚未解决正式的安全属性（不存在不安全状态跳跃、有界级联收敛）。先前的信任传播工作, and no formal safety properties (absence of unsafe state jumps, bounded cascade convergence) have been addressed within the 3GPP context. II 相关工作Related Work

自治网络系统的信任管理借鉴了几个不同的研究团体。我们将相关文献分为五类，找出激发我们在每一类中做出贡献的具体差距。The management of trust in autonomous network systems draws upon several distinct research communities. We organize the related literature into five categories, identifying the specific gap that motivates our contribution in each.

Ⅱ-AII-A 多代理系统中的信任管理Trust Management in Multi-Agent Systems

计算信任模型已被广泛研究。马什Computational trust models have been studied extensively. Marsh[14]将信任正式化为源自过去经验的持续价值。约桑formalized trust as a continuous value derived from past experiences. Jøsang[15]引入了在不确定性下推理信任的主观逻辑。拉姆彻恩等人。introduced subjective logic for reasoning about trust under uncertainty. Ramchurn et al.[16]调查了信任机制，包括个人层面的学习、制度机制和社会认知模型。最近的工作探索了混合方法surveyed trust mechanisms including individual-level learning, institutional mechanisms, and socio-cognitive models. More recent work has explored hybrid approaches[17], 博弈论信任, game-theoretic trust[18]，以及基于区块链的去中心化信任, and blockchain-based decentralized trust[19].

尽管它们很成熟，但这些模型假设信任信息可以在内部访问的同质平台。无地址Despite their maturity, these models assume homogeneous platforms where trust information is internally accessible. None address标准化信息模型standardized information models允许通过明确定义的管理界面跨供应商边界查询信任——这是多供应商电信管理的先决条件。enabling trust to be queried across vendor boundaries through well-defined management interfaces - a prerequisite for multi-vendor telecom management.

Ⅱ-BII-B 3GPP管理框架和信息模型3GPP Management Framework and Information Models

3GPP NRM (TS 28.541The 3GPP NRM (TS 28.541[20]）为通过通用管理服务访问的托管实体定义信息对象类 (IOC) (TS 28.532) defines Information Object Classes (IOCs) for managed entities accessed through Generic Management Services (TS 28.532[11]）。 SA5 已将其扩展到自主操作：管理数据分析 (MDAS)). SA5 has extended this for autonomous operations: Management Data Analytics (MDAS)[21]、意图驱动管理, intent-driven management[22]，以及 AI/ML 管理 (TS 28.105, and AI/ML management (TS 28.105[2]）介绍) introducingML训练功能MLTrainingFunction和andML实体MLEntity国际奥委会。IOCs.

至关重要的是，3GPP NRM 中没有现有的 IOC 代表代理工具的信任状态。虽然该框架为我们的解决方案提供了架构模式 - IOC 定义、属性规范、通知机制和 MnS 查询接口 - 但代理工具信任的语义内容尚未指定。Critically, no existing IOC in the 3GPP NRM represents the trust state of an agent’s tool. While the framework provides the architectural patterns for our solution - IOC definition, attribute specification, notification mechanisms, and MnS query interfaces - the semantic content for agent tool trust has not been specified.

Ⅱ-CII-C AI/ML Trust and Safety in Telecom Networks

一些行业举措解决了电信中人工智能功能的信任和安全问题，但没有一个举措提供跨供应商标准化信息模型。Several industry initiatives address trust and safety for AI functions in telecommunications, though none provide a cross-vendor standardized information model.

Ⅱ-CII-C1 欧洲电信标准协会ETSI ENI

欧洲电信标准协会 (ETSI) 体验式网络智能 (ENI) 行业规范组The European Telecommunications Standards Institute (ETSI) Experiential Networked Intelligence (ENI) Industry Specification Group[23]定义了人工智能辅助网络管理的参考架构，其中包括适用于信任评估的治理概念。然而，重点是单个运营商的领域而不是跨供应商的可见性。has defined a reference architecture for AI-assisted network management that includes governance concepts applicable to trust assessment. However, the focus is on a single operator’s domain rather than cross-vendor visibility.

Ⅱ-CII-C2 欧洲电信标准协会ZSMETSI ZSM

ETSI 零接触网络和服务管理 (ZSM) 框架The ETSI Zero-touch network and Service Management (ZSM) framework[24]定义了使用跨管理域的闭环自动化进行全自动网络管理的参考架构。 While ZSM addresses cross-domain coordination through domain integration fabrics and data services, it does not define trust management for the AI-driven decision agents within those domains.所提出的框架通过提供信任治理层来补充 ZSM，该信任治理层可在 ZSM 管理的域内实现安全代理操作。defines a reference architecture for fully automated network management using closed-loop automation across management domains. While ZSM addresses cross-domain coordination through domain integration fabrics and data services, it does not define trust management for the AI-driven decision agents within those domains. The proposed framework complements ZSM by providing the trust governance layer that enables safe agent operation within ZSM-managed domains.

Ⅱ-CII-C3 O-RAN联盟O-RAN Alliance

Open RAN 联盟指定了 ML 模型生命周期管理The Open RAN Alliance has specified ML model lifecycle management[25]包括模型训练、验证、部署和监控阶段。 O-RAN 架构支持模型性能跟踪，但在没有标准化暴露于外部管理系统的情况下，信任评估仍然是近 RT RIC 或非 RT RIC 中的本地问题。including model training, validation, deployment, and monitoring phases. The O-RAN architecture supports model performance tracking, but trust assessment remains a local concern within the near-RT RIC or non-RT RIC without standardized exposure to external management systems.

Ⅱ-CII-C4 认知功能沙箱Cognitive Function Sandboxing

A sandboxing orchestration framework [7]引入了认知功能的分级信任级别，其中不受信任的功能在沙箱环境中执行，并逐步获得在特定条件（时间、拓扑或范围限制）下在实时网络上执行操作的许可。这证明了具有行为证据的分级信任的价值，但在单个供应商的管理实体内运作，没有跨供应商的可见性。introduces graduated trust levels for cognitive functions, where untrusted functions execute in sandbox environments and progressively earn permission to act on the live network under specific conditions (temporal, topological, or scope restrictions). This demonstrates the value of graduated trust with behavioral evidence but operates within a single vendor’s management entity without cross-vendor visibility.

Ⅱ-CII-C5 Exploration Management for Safe RL Agents

勘探管理框架An exploration management framework[26]通过根据操作员定义的安全标准和网络部分关键性计算差异化的探索策略来协调多个强化学习代理。该框架提供遗憾保证，但将安全模型保留在勘探管理功能内部 - 不作为可查询的信息模型公开。coordinates multiple reinforcement learning agents by computing differentiated exploration policies based on operator-defined safety criteria and network part criticality. The framework provides regret guarantees but keeps safety models internal to the exploration management function - not exposed as a queryable information model.

Ⅱ-CII-C6 网络控制功能Network Control Function

A Network Control Function (NCF) [27]在网络应用之前使用自适应接受标准评估认知功能建议（与提议的变化幅度成反比，与预期改进成正比）。当函数展示出可靠的预测时，信任就会建立。然而，NCF 作为单一供应商监管实体运作。evaluates cognitive function recommendations before network application using adaptive acceptance criteria (inversely proportional to proposed change magnitude, directly proportional to expected improvement). Trust builds as the function demonstrates reliable predictions. However, the NCF operates as a single-vendor supervisory entity.

Ⅱ-CII-C7 3GPP SA5 Closed Control Loop Trust

用于通信服务保证的 3GPP 管理服务 (TS 28.535)The 3GPP management services for communication service assurance (TS 28.535)[28]包括带有信任开发条款的闭环控制概念，其中循环协商共享资源的优先级。然而，信任仍然隐含在协调优先级中，而不是显式的、可查询的状态机。includes closed control loop concepts with trust development provisions where loops negotiate precedence on shared resources. However, trust remains implicit in coordination priority rather than an explicit, queryable state machine.

Ⅱ-DII-D 网络管理的零信任架构Zero-Trust Architectures for Network Management

Whether an agent invokes a tool via RESTful MnS, gRPC, or proprietary interfaces, the trust state is maintained at the NRM level and accessible through standard management queries. Additionally, adversarial scenarios where a vendor deliberately reports inflated or deflated trust scores warrant investigation. Signed, auditable trust evidence - where each trust state transition is accompanied by cryptographically verifiable supporting data (KPI measurements, action logs, anomaly reports) - would enable independent verification of trust claims and detection of manipulative reporting across vendor boundaries.

八VIII结论Conclusion

我们提出了一个用于自治网络中跨供应商代理工具信任管理的标准化信息模型。该模型将 AgentToolMO 作为 3GPP NRM 中的一流托管对象引入，具有正式定义的信任状态、通过可证明安全的状态机进行分级执行、具有保证收敛的阻尼级联传播以及通过 NRM 依赖图遍历进行追溯影响评估。We have presented a standardized information model for cross-vendor agent tool trust management in autonomous networks. The model introduces AgentToolMO as a first-class managed object within the 3GPP NRM, with formally defined trust states, graduated enforcement through a provably safe state machine, damped cascade propagation with guaranteed convergence, and retroactive impact assessment via NRM dependency graph traversal.

我们的正式分析表明：（1）状态机不允许不安全的转换，确保工具无法绕过中间信任状态的分级执行； (2)无论网络拓扑如何，级联传播都会以有界步收敛； (3) 所有信任状态变化都会向订阅管理系统生成通知，从而消除无声的信任退化。Our formal analysis establishes that: (1) the state machine permits no unsafe transitions, ensuring graduated enforcement where tools cannot bypass intermediate trust states; (2) cascade propagation converges in bounded steps regardless of network topology; and (3) all trust state changes generate notifications to subscribing management systems, eliminating silent trust degradation.

仿真结果表明，与不信任基准和每个供应商基准相比，标准化模型大大降低了信任失败爆炸半径，跨供应商检测延迟受 MnS 通知传递时间而不是小时级服务影响表现的限制。通知开销随着参与供应商的数量呈次线性扩展，并且所有级联都会在配置的深度范围内终止。Simulation results demonstrate that the standardized model substantially reduces trust failure blast radius compared to both no-trust and per-vendor baselines, with cross-vendor detection latency bounded by MnS notification delivery time rather than hours-scale service impact manifestation. Notification overhead scales sub-linearly with the number of participating vendors, and all cascades terminate within the configured depth bound.

拟议的框架为值得信赖的多供应商自主网络管理提供了标准化基础，使运营商能够跨供应商边界部署代理，并提供正式的安全保证和完整的信任可见性。The proposed framework provides the standardization foundation for trustworthy multi-vendor autonomous network management, enabling operators to deploy agents across vendor boundaries with formal safety guarantees and complete trust visibility.
