1 简介Introduction

现代人工智能代理越来越多地部署在复杂的、开放式的环境中，从软件工程来看Modern AI agents are increasingly deployed in complex, open-ended environments, from software engineering(Jimenez et al., 2024; Yang et al., 2024; Merrill et al., 2026)和工具的使用and tool-use(Bandi et al., 2026; Patil et al., 2025)控制真实的网络浏览器和桌面to controlling real web browsers and desktops(Zhou et al., 2024; Xue et al., 2025; Xie et al., 2024)。 为了在这些环境中有效运行，最先进的代理很少是纯粹的语言或视觉语言模型；相反，它们被包裹在日益复杂的环境中. 随着智能体面临日益复杂的环境，端到端训练它们已成为一个中心目标，而强化学习（RL）则成为主要工具。 几个开源强化学习框架，例如 veRLAs agents take on increasingly complex environments, training them end-to-end has become a central goal, with reinforcement learning (RL) emerging as the primary tool. Several open-source RL frameworks, such as veRL(Sheng et al., 2024), 史莱姆, Slime(Zhu et al., 2025)，以及更多, and more(Hu et al., 2024; Cao et al., 2025; Fu et al., 2026)，支持高级算法（例如PPO和GRPO）和异步分布式训练。 然而，他们假设相对简单的推出：单轮生成，或多轮与轻量级工具调用（例如沙盒代码执行）交互。 这些假设对于复杂的推理工具来说是不成立的，复杂的推理工具在内部管理多轮交互、工具使用和上下文，其部署需要具有专用 CPU 和内存的容器化环境，而这些环境无法大规模共存于训练节点上。 因此，在这些复杂环境中训练代理的初始尝试需要大量修改训练循环以适应具体任务的具体情况, support advanced algorithms (e.g., PPO and GRPO) and asynchronous distributed training. 异步推出和超时。Asynchronous rollout and timeouts.

由于每次部署都是远程运行且超出了培训师的控制范围，因此单个无响应的部署将阻止整个训练批次的收集，并随后导致训练停滞。 限制每次推出的轮数Because each rollout runs remotely and outside the trainer’s control, a single unresponsive rollout will block the collection of an entire training batch and subsequently stall training. Capping the number of turns per rollout(Jin et al., 2025; Yu et al., 2025b)，一种常见的保护措施，在这种情况下是不可靠的：一些线束（例如，Codex）不公开转弯限制，并且跨线束的“转弯”定义不一致。 相反，我们对每个部署作业施加（慷慨的）挂钟超时。当作业超过超时时间时，我们会终止它并向代理和轨迹重建模块返回错误信号，因此训练会继续从剩余的部署中收集数据，而不是被终止的部署阻塞。, a common safeguard, is unreliable in this setting: some harnesses (e.g., Codex) do not expose a turn limit, and a “turn” is defined inconsistently across harnesses. We instead impose a (generous) wall-clock timeout on each rollout job. When a job exceeds its timeout, we terminate it and return an error signal to the proxy and the trajectory-reconstruction module, so training continues collecting from the remaining rollouts rather than blocking by the terminated one.

错误处理。Error handling.

在这些复杂环境中推出可能会因与策略模型无关的原因而失败，例如网络问题、线束崩溃或超时。关注 DAPORollouts in these complex environments can fail for reasons unrelated to the policy model, such as network issues, harness crashes, or timeouts. Designing better credit assignment for these partial rollouts is a promising direction in this setting, which we leave to future work.
