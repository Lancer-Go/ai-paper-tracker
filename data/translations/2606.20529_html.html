摘要Abstract

客户服务域中遵守策略的工具调用代理必须维护 任务状态在调用工具和遵守域策略时交替进行。任务 状态由相关事实、标识符、约束和条件组成 通过用户交互和工具调用来观察。 在标准代理中，任务状态不会单独表示。 观察结果、工具返回和策略说明都放在提示中， 让智能体每次根据提示重建相关状态 决定下一步做什么。 这种设计使状态管理变得隐式，从而创建了两种常见的故障模式。 代理可能会检索到正确的事实，但随后其决定就会变得陈旧， 信息缺失或不正确；并且语法上有效的工具调用可能仍然 违反取决于当前任务状态的域策略。 我们介绍Policy-adherent tool-calling agents in customer-service domains must maintain task states across turns while calling tools and obeying domain policies. Task states consist of relevant facts, identifiers, constraints, and conditions observed through user interaction and tool calls. In standard agents, task states are not represented separately. Observations, tool returns, and policy instructions are placed in the prompt, leaving agents to reconstruct the relevant states from the prompt each time they decide what to do next. This design makes state management implicit, creating two common failure modes. An agent may retrieve the right facts but later ground its decision in stale, missing, or incorrect information; and a syntactically valid tool call may still violate a domain policy that depends on the current task state. 语言代理越来越多地在需要持续的环境中进行评估 交互而不是孤立的工具调用Language agents are increasingly evaluated in settings that require sustained interaction rather than isolated tool calls(Li et al., 2023; Liu et al., 2025; Zhou et al., 2024a; Lu et al., 2025; Trivedi et al., 2024)。 他们必须与用户交谈，从外部系统检索记录， 并在多个回合中遵循特定于域的规则。 客户服务领域. They must converse with users, retrieve records from external systems, and follow domain-specific rules across multiple turns. Customer-service domains(Yao et al., 2024; Barres et al., 2025)使这一要求具体化： 代理人可以检查预订、检查订单、更改服务计划、发出 退款或更新帐户。因此，成功不仅仅取决于选择 正确的工具。代理必须保持相关的交互状态并采取行动 仅当域策略允许该操作时。make this requirement concrete: an agent may inspect a reservation, check an order, change a service plan, issue a refund, or update an account. Tool outputs are appended to the prompt. Prior actions remain interleaved with user messages and model generations. The policy document is supplied as natural-language instructions. At each turn, the model must identify which prior facts matter, decide whether more information is needed, choose the next response or tool call, and judge whether the intended action is allowed. 第二个失败出现在策略边界处。域策略指定何时 动作是被允许的。例如，他们可以定义哪些订单可以退货或 哪种付款方式必须收到退款。通常会提供这些规则 在代理检索到确定哪些规则的记录之前 申请A second failure appears at the policy boundary. Domain policies specify when actions are allowed. A tool call can therefore be syntactically valid while still violating the domain policy.

3 方法Method

账本代理LedgerAgent是标准的推理时间方法 遵守策略的工具调用代理。它添加了两个确定性组件： 存储从成功的工具返回中观察到的状态的分类帐，以及 策略门在执行前检查环境更改调用。 环境改变调用修改外部状态，例如发放退款， 更新订单、更改预订或更改帐户；只读调用是 没有门控。is an inference-time method for a standard policy-adherent tool-calling agent.
