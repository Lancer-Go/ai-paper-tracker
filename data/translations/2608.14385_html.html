1 简介Introduction

专家混合 (MoE) 模型已成为扩展大型语言模型 (LLM) 的核心方法，它可以增加模型容量，同时保持每个令牌计算的可管理性。 因此，MoE 架构已在最先进的法学硕士和大规模工业部署中得到广泛采用Mixture-of-Experts (MoE) models have become a central approach for scaling large language models (LLMs) by increasing model capacity while keeping per-token computation manageable. Consequently, MoE architectures have been widely adopted in state-of-the-art LLMs and large-scale industrial deployments(5; 24; 11; 17).

人们已经见证了 MoE 模型越来越多地部署在实时和交互式应用中，例如代码完成、语音助手和多模态音视频系统，这些应用中严格的延迟要求使得解码效率成为首要问题。在这些场景中，从业者通常倾向于小批量解码来平衡解码延迟和吞吐量之间的权衡，因为较大的批量大小可以提高吞吐量，但会带来不可接受的延迟。然而，在小批量解码下，MoE 推理会受到内存限制，并受到专家权重加载的严重瓶颈。在自回归解码过程中，每步仅处理几个令牌，而每个令牌激活多个专家，从而导致专家访问分散，权重重用最小。因此，解码延迟主要由重复加载专家参数而不是计算决定。It has been witnessing that MoE models are increasingly deployed in real-time and interactive applications such as code completion, voice assistants, and multi-modal audio-video systems, where strict latency requirements make decoding efficiency a primary concern. In these scenarios, practitioners typically favor small-batch decoding to balance the trade-off between decoding latency and throughput, as larger batch sizes improve throughput but introduce unacceptable delays. However, under small-batch decoding, MoE inference becomes memory-bound and is severely bottlenecked by expert weight loading. During autoregressive decoding, only a few tokens are processed per step while multiple experts are activated per token, leading to scattered expert access with minimal weight reuse. As a result, decoding latency is dominated by repeatedly loading expert parameters rather than computation.

2.2 小批量解码中的专家加载问题Expert Loading Issue in Small-batch Decoding

MoE 模型已广泛部署在实时和交互式应用中，这些应用中严格的响应能力要求对解码延迟提出了很高的要求。代表性场景包括实时代码补全和交互式编程助手、具有流式ASR（自动语音识别）和TTS（文本转语音）功能的语音助手，以及实时音视频交互系统，例如用于视频会议的多模态代理、实时翻译和嵌入式人工智能。在这些设置中，用户通常期望令牌级响应延迟约为数十毫秒，这使得解码延迟成为主要优化目标。MoE models have been widely deployed in real-time and interactive applications, where strict responsiveness requirements impose highly demanding constraints on decoding latency. Representative scenarios include real-time code completion and interactive programming assistants, voice assistants with streaming ASR(Automatic Speech Recognition) and TTS(Text-to-Speech), and real-time audio-video interaction systems such as multimodal agents for video conferencing, live translation, and embodied AI. In these settings, users typically expect token-level response latencies on the order of tens of milliseconds, making decoding latency a primary optimization target.

然而，MoE 推理在批量大小、解码延迟和解码吞吐量之间表现出众所周知的权衡However, MoE inference exhibits a well-known trade-off among batch size, decoding latency, and decoding throughput(3)。一方面，大批量通过分摊计算和内存访问成本显着提高吞吐量，但它们也会引入违反实时约束的令人望而却步的延迟。另一方面，减少批量大小可以显着降低延迟，但由于计算资源未得到充分利用而严重降低了吞吐量。因此，对于延迟关键的场景，先前的工作和工业部署通常采用小批量解码机制，通常在每步 4-128 个令牌的范围内，这在超低延迟和可接受的吞吐量之间取得了实际的平衡. On the one hand, large batch sizes significantly improve throughput by amortizing computation and memory access costs, but they also introduce prohibitive latency that violates real-time constraints. On the other hand, reducing the batch size leads to much lower latency but severely degrades throughput due to underutilized compute resources. Consequently, for latency-critical scenarios, both prior work and industrial deployments commonly adopt small-batch decoding regimes, typically in the range of 4–128 tokens per step, which strike a practical balance between ultra-low latency and acceptable throughput(10).

不幸的是，小批量 MoE 推理在自回归解码过程中造成了严重的专家加载瓶颈，其中大部分解码时间都由加载专家参数而不是计算主导。这是因为在每个解码步骤中，仅处理少量令牌，而路由器通常为每个令牌激活多个专家。激活的专家分散在许多不同的专家指数中，在同一步骤中跨代币的专家权重的重复使用非常有限。在这种情况下，MoE 解码不再受矩阵乘法的计算限制，而是受内存限制，因为必须从内存中重复获取专家参数，从而导致高有效内存流量和增加的延迟Unfortunately, small-batch MoE inference poses a severe expert loading bottleneck during autoregressive decoding, where the majority of decoding time is dominated by loading expert parameters rather than computation. This is because during each decoding step, only a small number of tokens are processed, while the router often activates multiple experts per token. The activated experts are scattered across many distinct expert indices, with very limited reuse of expert weights across tokens within the same step. In this regime, MoE decoding is no longer compute-bound by matrix multiplications, but instead becomes memory-bound, as expert parameters must be repeatedly fetched from memory, leading to high effective memory traffic and increased latency(5; 32; 3).

这个问题在大型 MoE 模型中尤为明显。例如，DeepSeek-V3中的每个专家由三个形状矩阵组成This issue is particularly evident in large-scale MoE models. For example, each expert in DeepSeek-V3 consists of three matrices of shape[7168,2048][7168,2048]，总计约 44 MB 的 FP8 权重，已经接近 H100 GPU 二级缓存容量的上限, amounting to approximately 44 MB of FP8 weights, which is already close to the upper limit of the H100 GPU’s L2 cache capacity(5)。随着现代教育部模型不断扩大专家的数量和规模以提高能力和专业化，小批量专家加载问题变得更加明显。最近的模型如 Kimi-K2、Longcat-Omni 和 Qwen3-Next 分别采用 384、512 和 512 个路由专家. As modern MoE models continue to scale in both the number and size of experts to improve capacity and specialization, the small-batch expert loading problem becomes even more pronounced. Recent models such as Kimi-K2, Longcat-Omni, and Qwen3-Next adopt 384, 512, and 512 routed experts, respectively(11; 17; 23)。由于有数百名专家可用，小批量内的不同令牌选择同一专家的可能性进一步降低，从而加剧了参数加载冗余并增加了每个解码步骤的内存带宽压力。. With hundreds of experts available, the likelihood that different tokens within a small batch select the same expert further diminishes, exacerbating parameter loading redundancy and increasing memory bandwidth pressure per decoding step.
