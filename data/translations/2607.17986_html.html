对自托管人工智能代理的自状态攻击：操作系统防御能走多远？Self-State Attacks on Self-Hosted AI Agents: How Far Can OS Defenses Go?

摘要。Abstract.

自托管人工智能代理读取和写入自己的内存和配置文件以发挥作用。代理可能会因自身状态的损坏而受到损害——这是通过合法的操作系统系统调用调用实现的损害。我们将此类威胁称为自我状态攻击。在本文中，我们研究了操作系统对此类攻击的恢复能力。形式上，我们描述了四轴攻击空间（目标、机制、粒度、时间）；研究预防、检测和恢复的结构性限制；并引入了可检测性的工作负载条件视图。为了实例化该框架，我们从跨不同工作负载配置文件运行的代表性自托管代理收集实时活动跟踪，并将攻击空间实现为 23 单元矩阵、对真实自状态文件的 43 个具体操作，并注入到这些跟踪中。然后我们评估规范和工作负载条件的防御策略。实证结果表明，分层防御堆栈（指令和配置层上的访问控制预防、内存层上的工作负载条件检测以及定期备份恢复）对大多数攻击单元都是有效的，而小的残留攻击面在操作系统级别上在结构上仍然无法区分。Self-hosted AI agents read and write their own memory and configuration files to function. An agent may get compromised via corruption of its own state—a compromise realized via legitimate OS system call invocation. We refer to this class of threats as self-state attacks. In this paper, we investigate the OS resilience to this class of attacks. Formally, we characterize a four-axis attack space (Target, Mechanism, Granularity, Temporal); investigate the structural limits of prevention, detection, and recovery; and introduce a workload-conditioned view of detectability. To instantiate the framework, we collect live activity traces from a representative self-hosted agent running across distinct workload profiles, and realize the attack space as a 23-cell matrix, 43 concrete operations on real self-state files, and injected into those traces. We then evaluate both canonical and workload-conditioned defense strategies. The empirical results show that a layered defense stack (access-control prevention on the instruction and configuration layers, workload-conditioned detection on the memory layer, and periodic backup for recovery) is effective on most attack cells while a small residual attack surface remains structurally indistinguishable at the OS level.

1. 简介Introduction

基于大型语言模型 (LLM) 构建的人工智能代理正在从被动助手发展成为可以在现实环境中规划和行动的自主系统。与传统的聊天界面不同，这些代理执行任务、调用工具并在交互过程中维护持久状态。这种范例正在代码助手和自主工作流程等系统中迅速得到采用AI agents built on large language models (LLMs) are evolving from passive assistants into autonomous systems that can plan and act in real-world environments. Unlike traditional chat interfaces, these agents execute tasks, invoke tools, and maintain persistent state across interactions. This paradigm is rapidly gaining adoption in systems such as code assistants and autonomous workflows(Anthropic, 2025; Team, 2024; Gauthier, 2024; Labs, 2024).

基于法学硕士的人工智能代理正在从云托管的聊天界面转向直接在用户机器上运行的自主系统。这种转变是由云沙箱在结构上无法满足的需求驱动的：开发人员需要在私有代码库内运行且具有完整 shell 和文件系统访问权限的代理。企业需要能够在不泄露机密文件的情况下对机密文件进行推理的助手。个人希望个人人工智能能够处理电子邮件、健康记录和本地工作流程。这些现在是代理计算的主导轨迹，已经在广泛部署的系统（例如 Claude Code）中实现LLM-based AI agents are shifting from cloud-hosted chat interfaces to autonomous systems that run directly on users’ machines. This shift is driven by demand that cloud sandboxes structurally cannot serve: developers need agents that operate inside private codebases with full shell and filesystem access. Enterprises need assistants that can reason over confidential documents without exfiltrating them. Individuals want personal AI that handles email, health records, and local workflows. These are now the dominant trajectory of agentic computing, already realized in widely-deployed systems such as Claude Code(Anthropic, 2025)和张开爪and OpenClaw(OpenClaw Community, 2025)，以及快速扩展的生态系统, alongside a rapidly expanding ecosystem(Anomaly, 2025; Qwibit, 2026; Nous Research, 2025).

自托管代理的特点是其持久状态，采用本地文件的形式：跨会话积累知识的内存文件、定义其角色和目标的身份文档以及管理其行为的配置。与普通数据不同，代理将这些文件读回作为影响其未来决策的上下文，并且它必须不断读取和重写它们以记住先前的上下文，从经验中学习并适应不断变化的偏好。这不是实施细节，而是产品要求。由于代理本身必须改变这些行为控制文件才能发挥作用，因此它们永久存在于自己的写入集中，而不是任何沙盒或只读区域中。Self-hosted agents are characterized by their persistent state, which takes the form of local files: memory files that accumulate knowledge across sessions, identity documents that define their persona and goals, and configuration that governs their behavior. Unlike ordinary data, the agent reads these files back as the context that shapes its future decisions, and it must continuously read and rewrite them to remember prior context, learn from experience, and adapt to changing preferences. This is not an implementation detail but a product requirement. Because the agent itself must mutate these behavior-governing files to function, they live permanently inside its own write set, rather than in any sandboxed or read-only region.

这种必要的自我可变性产生了一类独特的威胁。一旦代理的决策过程在语义上受到损害，例如通过间接提示注入This necessary self-mutability creates a distinctive class of threats. Once the agent’s decision process is semantically compromised, for example, through an indirect prompt injection(Greshake et al., 2023)，通常更新内存、身份和配置的合法写入路径成为攻击者破坏代理自身持久状态的通道。我们称这个类为, the legitimate write paths that normally update memory, identity, and configuration become a channel for the attacker to corrupt the agent’s own persistent state. We call this class自状态攻击self-state attacks (§2）。这个设置类似于经典的困惑代理问题). This setting resembles the classical confused deputy problem(Hardy, 1988; RoyChowdhury et al., 2024)，其中特权组件被欺骗滥用其权限。然而，在基于 LLM 的代理中，自然语言的灵活性和代理随时间持续变化的能力会放大这个问题。现实世界的事件和最近的研究进一步凸显了这些风险的严重性, where a privileged component is tricked into misusing its authority. In LLM-based agents, however, this issue is amplified by the flexibility of natural language and the agent’s ability to persist in changes over time. Real-world incidents and recent studies further highlight the severity of these risks(Brodt et al., 2026; Ying et al., 2026; Habler and Chang, 2026).

最近的代理安全研究集中在语义层，使用 LLM 作为法官Recent agent-security research concentrates on the semantic layer, using LLM-as-judge(Zheng et al., 2023; Yuan et al., 2024)或警卫人员or guard agents(Xiang et al., 2024)在执行之前拒绝恶意行为。语义防御作为第一道防线是不可或缺的，但它们在结构上是概率性的。它们在攻击者使用的同一开放式自然语言空间中运行，其中恶意意图可以间接表达或通过无休止的释义和上下文重构来表达。自适应攻击始终利用这一差距to reject malicious actions before execution. Semantic defenses are indispensable as a first line, but they are structurally probabilistic. They operate in the same open-ended natural-language space the attacker uses, where malicious intent can be expressed indirectly or through endless paraphrase and contextual reframing. Adaptive attacks consistently exploit this gap(Zhan et al., 2025).

因此，操作系统 (OS) 是一个自然的补充：它是任何自状态损坏提交到磁盘之前的最后一个确定性执行点，因为每个此类损坏最终都必须发出 OS 可以观察到的具体系统调用，例如写入、重命名、取消链接或模式更改。然而，自托管代理的操作系统防御尚未得到系统研究：尚不清楚操作系统层可以自行关闭哪些自状态攻击，这取决于代理的部署方式，以及哪些必然会逃避任何操作系统层机制。The operating system (OS) is therefore a natural complement: it is the last deterministic enforcement point before any self-state corruption commits to disk, since every such corruption must eventually issue a concrete syscall, e.g., a write, rename, unlink, or mode change, that the OS can observe. Yet, OS defenses of self-hosted agents have not been systematically studied: it remains unclear which self-state attacks the OS layer can close on its own, which depend on how the agent is deployed, and which necessarily escape any OS-layer mechanism.

本文提供了这种系统的研究。我们首先提出了一个自状态攻击框架，该框架沿四个轴（目标、机制、粒度、时间）构建攻击面，以便每个攻击实例对应于明确定义的自状态组件上的 Target × Mechanism 矩阵的一个单元。然后，我们从预防、检测和恢复三个维度分析操作系统防御，并表明每种防御都满足针对自状态攻击的独特结构限制：预防无法区分同一文件上的攻击写入和合法写入，检测无法推断出有害意图，恢复继承检测作为前提条件，并支付与备份间隔成比例的数据丢失成本。This paper provides that systematic study. We first propose a framework for self-state attacks that structures the attack surface along four axes (Target, Mechanism, Granularity, Temporal), so that every attack instance corresponds to a cell of a Target × Mechanism matrix over well-defined self-state components. We then analyze OS defenses along three dimensions, prevention, detection, and recovery, and show that each meets a distinct structural limit against self-state attacks: prevention cannot discriminate attack writes from legitimate writes on the same file, detection cannot infer harmful intent, and recovery inherits detection as a precondition and pays a data-loss cost proportional to the backup interval.

3.3. 复苏差距The Recovery Gap

自状态恢复差距是由恢复点模糊和选择性恢复模糊引起的。因为中毒可能是渐进的、语义上的和潜在的，所以观察到有害行为的时间不一定能确定自我状态第一次被破坏的时间。最近的快照可能已经包含了病毒，而较旧的快照可能是干净的，但操作上已经过时了。The self-state recovery gap arises from both recovery-point ambiguity and selective-recovery ambiguity. Because poisoning may be gradual, semantic, and latent, the time at which harmful behavior is observed does not necessarily identify when the self-state first became corrupted. A recent snapshot may already contain the poison, while an older snapshot may be clean but operationally stale.

The difficulty is amplified by cross-layer entanglement: a poisoned memory may later be distilled into an instruction state, an instruction change may alter configuration, and configuration may shape which future memories are collected. Recovery may therefore require restoring a consistent cut across memory, instruction, and configuration, not only reverting the file that was first modified.

7. 结论Conclusion

本文将自状态攻击定义为自托管人工智能代理的特定安全问题，该类代理通过操作系统权限破坏其自身的持久状态。它首次系统地描述了此类的操作系统层防御能力。我们贡献了一个具有两层的框架：一个正式的威胁模型和一个四轴维度分类法，为自状态攻击提供了一个适合操作系统层分析的结构，以及一个 23 单元规范攻击矩阵，该矩阵将该分类法实例化为具体的评估单元。我们将框架与对四种不同工作负载配置文件的评估配对，锚定在真实的代理会话中。利用这些，我们实现了三种检测变体，这些变体利用了已建立的异常检测方法，并表明工作负载调节将操作系统层检测扩展到了基线可实现的覆盖范围之外。与预防和恢复的发现一起，这表明建议的三个维度组成了一个可用的防御堆栈。除了直接的发现之外，这还支持语义层检测器的未来研究。This paper formulates self-state attacks as a specific security problem for self-hosted AI agents, a class in which the agent corrupts its own persistent state through the OS permissions. It provides the first systematic characterization of OS-layer defensibility for this class. We contribute a framework with two layers: a formal threat model and a four-axis dimensional taxonomy that gives self-state attacks a structure amenable to OS-layer analysis, and a 23-cell canonical attack matrix that instantiates this taxonomy as a concrete evaluation unit. We pair the framework with an evaluation over four different workload profiles, anchored in real agent sessions. Using these, we implemented three detection variants that draw on established anomaly-detection methods and showed that workload-conditioning extends OS-layer detection beyond the coverage achievable by baselines. Together with the findings for prevention and recovery, this shows that the three proposed dimensions compose into a usable defense stack. Beyond the immediate findings, this supports future research on semantic-layer detectors.
