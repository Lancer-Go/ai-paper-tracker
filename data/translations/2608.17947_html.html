摘要Abstract

大型语言模型可以生成可执行程序，这使得直接通过程序内容生成器而不是单个级别进行搜索成为可能。我们在《推箱子》、《塞尔达传说》、《危险戴夫》和《淘金者》中研究了这种方法。每次运行都会通过语言模型突变和交叉演化出完整的 Python 生成器。我们引入了持续抽象发现（CAD），它将可重用的原语从高适应性程序中提取到特定于运行的帮助程序模块中。一个Large language models can generate executable programs, which makes it possible to search directly over procedural content generators rather than individual levels. We study this approach in Sokoban, Zelda, Dangerous Dave, and Lode Runner. Each run evolves complete Python generators through language-model mutation and crossover. We introduce Continual Abstraction Discovery, or CAD, which extracts reusable primitives from high-fitness programs into a run-specific helper module. These results support that discovering reusable primitives improves evolutionary program search for content generators.

I 简介Introduction

以程序生成内容为特色的游戏通常依赖于根据特定游戏的机制、约束和设计目标定制的自定义生成器。创建这些发电机需要大量的工程设计和反复评估。程序内容生成器生成旨在通过搜索生成器本身而不是直接搜索单个工件来自动化此过程Games that feature procedurally generated content usually rely on custom generators tailored to the mechanics, constraints, and design goals of a particular game. Creating these generators requires substantial engineering and repeated evaluation. Procedural content generator generation seeks to automate this process by searching for the generator itself rather than directly searching for individual artifacts[5]。这个过程也可以称为程序内容. This process can also be called procedural content元代metageneration.

现有方法通过进化计算、机器学习或强化学习来学习生成器Existing approaches learn generators through evolutionary computation, machine learning, or reinforcement learning[5, 8, 20, 6, 11]。许多产生神经或其他不透明的表示。这样的生成器可能很有效，但它们难以检查和编辑。可执行源代码提供了不同的表示形式。程序可以由设计者编译、测试、修改，并在搜索系统之外重用。. Many produce neural or otherwise opaque representations. Such generators can be effective, but they are difficult to inspect and edit. Executable source code offers a different representation. A program can be compiled, tested, modified by a designer, and reused outside the search system.

大型语言模型编写和修改代码的能力越来越强。这使得将代码生成模型放置在进化循环中成为可能。候选生成器被执行，其级别被评估，产生的反馈指导后续的突变和交叉调用。相关系统已使用语言模型作为可执行程序搜索的变体运算符Large language models are increasingly capable of writing and revising code. This makes it possible to place a code-generating model inside an evolutionary loop. A candidate generator is executed, its levels are evaluated, and the resulting feedback guides later mutation and crossover calls. Related systems have used language models as variation operators for executable program search[14, 1, 17]。程序内容元生成提出了这个问题的一个要求很高的实例，因为生成器的质量只能通过重复执行和行为评估来判断。. Procedural content metageneration presents a demanding instance of this problem since the quality of a generator can only be judged through repeated execution and behavioral evaluation.

对原始代码的搜索修复了可用于变化的词汇表。随着程序的发展，可达性、实体标准化、修复和结构构造等有用的例程可以在许多候选者中独立地重新创建。手写的帮助器 API 可以公开可重用的操作，尽管其词汇在搜索开始之前保持固定。我们介绍Search over raw code fixes the vocabulary available to variation. As programs grow, useful routines for reachability, entity normalization, repair, and structural construction may be independently recreated in many candidates. A hand-written helper API can expose reusable operations, although its vocabulary remains fixed before search begins. We introduce持续抽象发现Continual Abstraction Discovery或 CAD，作为在运行期间增加可执行基元集的一种方法。 CAD 将可重用实用程序从高适应度程序中提取到特定于运行的帮助程序模块中，验证该模块，并在可以安全完成时重构程序以使用学习到的实用程序。, or CAD, as a way to let the set of executable primitives increase during a run. CAD extracts reusable utilities from high-fitness programs into a run-specific helper module, validates the module, and refactors programs to use the learned utilities when this can be done safely.

我们根据 PCG 基准在四个领域评估系统We evaluate the system on four domains from the PCG Benchmark[7]。主要研究涉及固定域帮助器 API 与 CAD。这种设计将对可重用词汇表的访问与搜索过程中词汇表的发现分开。. The main study crosses a fixed domain helper API with CAD. This design separates access to a reusable vocabulary from the discovery of a vocabulary during search.

II 相关工作Related Work

多种计算方法已被应用于生成游戏内容，特别是游戏关卡。这些范围从进化计算A wide variety of computational methods have been applied to generating game content, in particular, game levels. These range from evolutionary computation[23]和约束满足and constraint satisfaction[18]监督学习to supervised learning[20]和强化学习and reinforcement learning[6]。已发布的游戏通常依赖于建设性生成器. Published games typically rely on constructive generators[16]专门针对特定游戏，这限制了可重用性。specialized for the particular game, which limits reusability.

最近，研究人员应用法学硕士来生成游戏关卡Recently, researchers have applied LLMs to generating game levels[22, 19, 3, 2, 21, 12, 13, 4]。结果好坏参半。为了以法学硕士可以理解的方式表示游戏关卡，需要以某种方式将其转换为字符串。通常，这意味着将级别表示为行序列，其中每个字符代表一个图块。初步结果表明，对特定游戏的关卡进行微调可以提高生成能力，并且更现代和最新的法学硕士在关卡生成方面优于旧的和较小的法学硕士（就像在大多数其他事情上一样）. The results are mixed. In order to represent a game level in a way that an LLM can understand, it needs to be converted to a string somehow. Typically, this means representing the level as a sequence of rows, where each character represents a tile. Initial results showed that fine-tuning generators on levels from particular games improved generation capacity, and that more modern and recent LLMs outperform older and smaller ones on level generation (as on most other things)[22].

然而，当前的法学硕士在生成游戏内容时存在局限性，特别是诸如关卡之类的空间内容。例如，法学硕士往往会遇到问题，无法确保从 A 点到 B 点存在畅通的路径，并且存在正确数量的物品和各种类型的角色（例如恰好有一个玩家角色，以及与钥匙数量相同的门）。 LLM 生成的游戏关卡的其他病症似乎源于弱空间推理However, current LLMs have limitations when generating game content, particularly spatial content such as levels. For example, LLMs tend to have problems ensuring that clear paths exist from point A to point B, and that the right number of items and characters of various types exist (such as exactly one player character, and the same number of doors as keys). Other pathologies of LLM-generated game levels seem to originate in weak spatial reasoning[22, 2, 12].

法学硕士的主要用例之一是代码生成。目前，软件工程正在因法学硕士的出现而发生转变，法学硕士可以根据非正式规范生成工作代码。然而，在许多情况下，您知道自己想要什么，但不知道如何实现目标。在这些情况下，您可以创建一个适应度函数来衡量您想要的结果，然后将代码生成 LLM 嵌入到进化循环中。这种方法由 AlphaEvolve 推广One of the major use cases of LLMs is code generation. Software engineering is currently being transformed by the emergence of LLMs that can produce working code from an informal specification. However, in many cases, you know what you want but not exactly how to get there. In those cases, you can create a fitness function measuring what you want, and then embed the code-generating LLM inside an evolutionary loop. This approach was popularized by AlphaEvolve[14]，其中发现了一种改进的矩阵乘法算法，类似的方法也被应用于创建科学数据分析解决方案和金融交易政策, which, among other things, discovered an improved matrix multiplication algorithm, and similar methods have also been applied to creating scientific data analysis solutions and financial trading policies[1, 17].

使用 LLM 在进化循环内生成代码可以被视为遗传编程的一种形式，这是进化计算在程序合成中的应用Using LLMs to generate code inside an evolutionary loop can be seen as a form of genetic programming, which is the application of evolutionary computation to program synthesis[15, 9]。从这个角度来看，法学硕士正在执行遗传编程中的突变和/或交叉操作。遗传编程中的一个重要概念是自动定义函数，其中一组可调用函数与主程序一起演化，构成一种演化抽象形式. From this perspective, the LLM is carrying out the mutation and/or crossover operations in genetic programming. An important concept in genetic programming is Automatically Defined Functions, where a set of callable functions is evolved in tandem with the main program, constituting a form of evolved abstraction[10].

持续抽象发现 (CAD) 还与代理技能库的最新工作相关，其中存储可重用的代码或行为以供以后使用，例如 Voyager 的 Minecraft 代理技能库Continual abstraction discovery (CAD) is also related to recent work on agent skill libraries, where reusable code or behaviors are stored for later use, such as Voyager’s skill library for Minecraft agents[24]。我们设置的主要区别在于，该库不是已解决任务或手动公开技能的记录，而是在持续进化搜索过程中从高性能生成器程序中提取的一组不断更新的辅助函数。因此，CAD 充当搜索时表示机制。它更改了可用于以后变异、交叉和重构调用的程序原语，同时种群仍在优化。. The key difference in our setting is that the library is not a record of solved tasks or manually exposed skills, but a continually updated set of helper functions extracted from high-performing generator programs during an ongoing evolutionary search. CAD, therefore, functions as a search-time representation mechanism. It changes the program primitives available to later mutation, crossover, and refactoring calls while the population is still being optimized.

回归PCG研究，通过机器学习研究PCGReturning to PCG research, work on PCG through machine learning[20]，包括强化学习, including reinforcement learning[6]，通常学习生成器，然后使用生成器生成游戏内容。然而，他们主要学习神经网络或其他类型的黑盒表示，这些表示不允许简单的人类解释和编辑。但也有例外，即使用进化或类似的方法来学习以符号表示形式表达的生成器, generally learns generators, which are then used to generate game content. However, they mostly learn neural networks or other types of black box representations, which do not allow for easy human interpretation and editing. There are exceptions to this, where evolution or similar methods are used to learn generators expressed in a symbolic representation[5, 8]。本文提出的方法可以被视为程序性内容生成器生成，或程序性内容元生成，在生成器空间中使用基于搜索的方法，并通过 LLM 代码编写增强。超越工具和领域组合的一项关键发明是持续抽象发现机制，它类似于自动定义函数，但使用 LLM 驱动的演化。. The approach presented in this paper can be seen as procedural procedural content generator generation, or procedural content metageneration, using a search-based approach in generator space enhanced by LLM code writing. A key invention beyond the combination of tool and domain is the Continual Abstraction Discovery mechanism, which is similar to Automatically Defined Functions but using LLM-driven evolution.

VI 讨论Discussion

六一AVI-A 跨域证据Cross-Domain Evidence

结果表明，一种进化程序搜索框架可以在具有不同网格大小和基准评估器的四种游戏中运行。 CAD 提高了每个领域的平均适应度。当专家 API 可用时，最大的效果出现在 Lode Runner 中。在这种情况下，搜索已经具有特定于领域的可调用例程，但特定于运行的学习词汇仍然可以提高最佳适应度。其他三个 API 单元也支持 CAD，尽管它们的测试未达到The results show that one evolutionary program-search framework can operate across four games with different grid sizes and benchmark evaluators. CAD improves the mean fitness in every domain. The largest effect appears in Lode Runner when the expert API is available. Search already has domain-specific callable routines in this condition, yet the run-specific learned vocabulary still improves the best fitness. The three other API cells also favor CAD, although their tests do not reachp<0.05p<0.05.

六-BVI-B CAD 作为表示适应CAD as Representation Adaptation

CAD 更改了搜索过程中以后变体调用可用的操作。可执行的底层仍然是 Python，而有效的词汇量随着帮助程序的提取而增长。机制测量表明，生成的函数被后续程序采用并重复调用。通常重复出现的辅助函数处理实体规范化、玩家放置、可达性、连接性和结构构造等模式。这些是基于图块的生成器设计的核心操作。较大的特定于运行的尾部还表明 CAD 不会收敛到一个固定库。它将循环核心与由域和搜索历史形成的实用程序结合在一起。CAD changes the operations available to later variation calls during search. The executable substrate remains Python, while the effective vocabulary grows as helpers are extracted. The mechanism measurements show that the resulting functions are adopted by later programs and called repeatedly. Commonly recurring helper functions address patterns such as entity normalization, player placement, reachability, connectivity, and structural construction. These are central operations in tile-based generator design. The large run-specific tail also indicates that CAD does not converge to one fixed library. It combines a recurring core with utilities shaped by the domain and search history.

程序规模分析支持相关解释。 CAD 缩短了最好的基础程序，而固定的 API 已经产生了紧凑的源库。这并不能证明较短的项目本质上就更好。它表明可重用的可调用词汇表可以将逻辑从主生成器中卸载出来，这可能使以后的编辑更容易表达和保存。The program-size analysis supports a related interpretation. CAD shortens the best Base programs, while the fixed API already yields compact source libraries. This does not establish that shorter programs are intrinsically better. It shows that reusable callable vocabularies can offload logic out of the main generator, which may make later edits easier to express and preserve.

六-CVI-C 实际意义和局限性Practical Implications and Limitations

可解决性、基准质量和多样性并不能完全捕捉视觉风格、节奏、新颖性或设计师意图。当所需的生成器具有基准中缺少的美学或体验目标时，人工审查仍然很重要。Solvability, benchmark quality, and diversity do not fully capture visual style, pacing, novelty, or designer intent. Human review remains important when the desired generator has aesthetic or experiential goals that are absent from the benchmark.

计算成本是巨大的。典型的 50 代运行需要使用数百万个近前沿级模型的代币和几个小时的挂钟时间。 CAD 引入了额外的提取、校正和重构调用。未来的工作应该根据代币使用和挂钟成本来评估健身收益。The compute cost is substantial. A typical 50-generation run uses millions of tokens of a near-frontier-class model and several hours of wall-clock time. CAD introduces additional extraction, correction, and refactoring calls. Future work should evaluate fitness gains against token use and wall-clock cost.

CAD 作为一个完整的管道进行评估。辅助提取、模块校正和源代码重构不会分成单独的消融。机制痕迹显示了增长、采用和程序规模的变化，尽管它们没有隔离每个组件的因果贡献。额外的工作应该测试更长的预算、其他语言模型、非图块内容、交叉运行库传输以及发现的助手的设计器编辑。CAD is evaluated as a complete pipeline. Helper extraction, module correction, and source refactoring are not separated into individual ablations. The mechanism traces show growth, adoption, and program-size changes, although they do not isolate the causal contribution of each component. Additional work should test longer budgets, other language models, non-tile content, cross-run library transfer, and designer editing of discovered helpers.

七VII结论Conclusion

我们提出了一个进化程序搜索系统，它使用法学硕士来生成可执行的程序内容生成器。评测涵盖《推箱子》、《塞尔达》、《危险戴夫》和《淘金者》，每款游戏运行 10 次。无论您从空的帮助程序库还是专家帮助程序函数开始，持续抽象发现都会提高平均最终最佳适应度。We presented an evolutionary program-search system that uses an LLM to generate executable procedural content generators. The evaluation covers Sokoban, Zelda, Dangerous Dave, and Lode Runner, where each one is run 10 times. Continual Abstraction Discovery raises the mean final best fitness regardless you start with an empty helper library or expert helper functions.

在 CAD 运行过程中，学习库不断增长，被后来的程序采用，并反复恢复验证、可达性和结构实用程序。结果支持 CAD 作为在程序内容元生成期间调整可搜索程序词汇的实用机制。Across the CAD runs, learned libraries grow, are adopted by later programs, and repeatedly recover validation, reachability, and structural utilities. The results support CAD as a practical mechanism for adapting the searchable program vocabulary during procedural content metageneration.
