I 简介Introduction

图像到代码生成已成为人工智能辅助编码的核心范例。 来自重写为 HTML 的 UI 模型Image-to-code generation has become a central paradigm in AI-assisted coding. From UI mockups rewritten as HTML[6, 41, 7, 49, 40, 34]，将科学绘图逆向工程化为可重现的 Python 脚本, to scientific plots reverse-engineered into reproducible Python scripts[38, 48, 25]多模式大语言模型 (MLLM) 正在将软件创建的前端从纯粹的文本规范转向更丰富的视觉工件。 在每个任务中，视觉输入都可以被视为, multimodal large language models (MLLMs) are shifting the front-end of software creation from purely textual specifications toward richer visual artifacts. In each of these tasks, the visual input can be viewed as a视觉领域特定语言（视觉DSL）visual domain-specific language (visual DSL)：UI 模型指定布局和交互语义，图表编码数据和渲染逻辑，并且每一个都必须忠实地转换为可执行代码。 最近，这种范例已扩展到硬件：MLLM 用于翻译: a UI mockup specifies layout and interaction semantics, a chart encodes data and rendering logic, and each must be faithfully translated into executable code. Recently, this paradigm has been extended to hardware: MLLMs are used to translate电路图circuit diagrams转换为可综合的寄存器传输级（RTL）代码，我们称之为任务into synthesizable register-transfer-level (RTL) code, a task we call电路到 Verilog 代码生成circuit-to-Verilog code generation [37, 47]。 电路图可以说是要求严格的视觉 DSL，因为它对时序、拓扑和位级语义进行编码，这些语义对于临时检查来说是不可见的，但一旦在硅中制造出来，就安全至关重要。. A circuit diagram is arguably the demanding visual DSL, because it encodes timing, topology, and bit-level semantics that are invisible to casual inspection yet safety-critical once fabricated in silicon.

虽然不可靠的视觉到代码转换是所有视觉 DSL 普遍关注的问题，但硬件领域的后果尤其严重While unreliable vision-to-code translation is a general concern across all visual DSLs, the consequences in the hardware domain are uniquely severe[44, 26]。 RTL 位于硅设计流程的最开始，并向下游提供综合、布局布线和制造；单个误读原理图可以在整个工具链中悄无声息地传播，并表现为硅级缺陷，其成本比渲染或绘图错误高出几个数量级。 更广泛地说，如果人工智能代码生成器看似“理解”视觉规范，但实际上却绕过了它，那么生成的代码就会带来传统测试可能无法发现的隐蔽正确性风险。 这直接威胁到 MLLM 的. RTL sits at the very beginning of the silicon design flow and feeds downstream into synthesis, place-and-route, and fabrication; a single misread schematic can propagate silently through the entire toolchain and materialize as a silicon-level defect whose cost is orders of magnitude higher than a rendering or plotting error. More broadly, if an AI code generator appears to “understand” a visual specification while actually bypassing it, the resulting code carries a covert correctness risk that conventional testing may not catch. This directly threatens MLLMs’可信度trustworthiness，软件工程界的核心关注点。 因此，电路到 Verilog 的生成充当了严格的试验场：这里暴露的任何可靠性缺陷都可能以较温和但同样阴险的形式出现在其他视觉到代码管道中。, a core concern of the software engineering community. Circuit-to-Verilog generation therefore serves as a rigorous proving ground: any reliability flaw exposed here is likely to manifest, in milder but equally insidious forms, in other vision-to-code pipelines.

尽管最近的研究已经证明了使用 MLLM 读取电路图和生成 Verilog 代码的可行性，但一个基本问题在很大程度上仍未得到探索：Although recent studies have demonstrated the feasibility of using MLLMs to read circuit diagrams and generate Verilog code, a fundamental question remains largely unexplored:现有的 MLLM 是否真正能够读取电路图，或者仅仅利用文本快捷方式？do existing MLLMs truly read circuit diagrams, or merely exploit textual shortcuts?
