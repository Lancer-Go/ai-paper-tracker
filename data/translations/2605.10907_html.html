摘要Abstract

人工智能代理的主导范例是“即时”循环，其中代理综合计划并在几秒或几分钟内执行操作以响应用户提示。我们认为，这种范式短路了严格的软件工程（SE）流程——迭代设计、严格测试、对抗性评估、分阶段部署等等——这些流程提供了我们今天使用的（相对）可靠和安全的系统。通过专注于快速、实时的综合，人工智能代理是否可以有效地为用户提供临时原型，而不是适合用户可能无意中应用它们的高风险场景的系统？The dominant paradigm for AI agents is an “on-the-fly” loop in which agents synthesize plans and execute actions within seconds or minutes in response to user prompts. We argue that this paradigm short-circuits disciplined software engineering (SE) processes—iterative design, rigorous testing, adversarial evaluation, staged deployment, and more—that have delivered the (relatively) reliable and secure systems we use today. By focusing on rapid, real-time synthesis, are AI agents effectively delivering users improvised prototypes rather than systems fit for high-stakes scenarios in which users may unwittingly apply them?

退后一步，我们给出了我们的观点，即为什么要克服这种紧张局势需要超越即时执行而转向工程化工作流程。考虑一下当我们从传统软件转向代理系统时会发生什么：这本质上重新协商了开发人员控制、功能灵活性和鲁棒性之间的界限。 增加应用程序的“代理性”——开发人员可以卸载更多的负载 人工智能应用程序开发——提高了灵活性，但减少了开发人员的工作量 控制，在开发人员意图和应用程序规范之间造成差距。 虽然法学硕士擅长通用推理，但他们唯一真正的规范是 将输入标记转换为输出标记；到目前为止，我们还不能保证 即使经过仔细提示，他们也会正确地认识到开发人员的意图。Stepping back, we give our perspective on why navigating this tension requires moving beyond on-the-fly execution toward engineered workflows. Consider what happens as we move from traditional software to agentic systems: this essentially renegotiates the boundaries between developer control, functional flexibility, and robustness. Increasing application “agenticness”—where the developer offloads more application development to AI—expands flexibility but reduces developer control, creating a gap between developer intent and application specification. While LLMs excel at general-purpose reasoning, their only true specification is to transform input tokens into output tokens; as of yet, we have no guarantee they will correctly realize developer intent, even when carefully prompted.

We argue that robustness in agentic systems can be similarly achieved by integrating SE processes—design, testing, adversarial evaluation, and iteration—into the agentic loop. The AI Workflow Store operationalizes this shift by replacing per-request improvisation with hardened, reusable workflows and amortizing the engineering effort across users and requests.
