摘要Abstract

根本原因分析（RCA）对法学硕士代理能力进行全面测试，例如长上下文理解、多步骤推理和工具使用。 然而，现有的数据集存在一个根本性的差距：它们仅标记根本原因，而不标记将其连接到观察到的症状的传播路径，这在很大程度上简化了朴素模式匹配的任务。 为了支持严格的评估，我们引入了 PAVE，这是一种逐步标记协议，它利用故障注入的已知干预措施来重建因果传播路径。 其机制是Root cause analysis (RCA) poses a holistic test of LLM agentic capabilities, such as long-context understanding, multi-step reasoning, and tool use. However, existing datasets suffer from a fundamental gap: they label only the root cause, not the propagation path connecting it to the observed symptom, which largely simplifies the task to naive pattern matching. To support rigorous evaluation, we introduce PAVE, a step-wise labeling protocol that leverages known interventions from fault injection to reconstruct causal propagation paths. The mechanism is前向验证forward verification：从原因到结果进行推理，而不是从症状向后推断。 应用 PAVE 产生 OpenRCA 2.0（500 个实例），这是第一个跨系统 RCA 基准，为 LLM 代理提供逐步因果注释。 在 11 个前沿法学硕士中，平均只有 20.7% 的案例能够成功恢复确切的根本原因。 为了找到这个困难所在，我们放宽标准并找到我们所说的: reasoning from cause to effect rather than inferring backward from symptoms. Applying PAVE yields OpenRCA 2.0 (500 instances), the first cross-system RCA benchmark with step-wise causal annotations for LLM agents. Across 11 frontier LLMs, recovering the exact root-cause set succeeds in only 20.7% of cases on average. To locate where this difficulty lies, we relax the criterion and find what we call the无根据的诊断ungrounded diagnosis：代理在 76.0% 的情况下至少识别出一种正确的根本原因服务，但只有 61.5% 的情况下将该服务置于经过验证的因果传播路径中以观察到的症状。 仅结果评估隐藏了这种失败模式；对于基于 LLM 的值得信赖的 RCA 代理来说，逐步的因果基础事实是缺失的部分。: agents identify at least one correct root-cause service in 76.0% of cases but ground that service in a verified causal propagation path to the observed symptom in only 61.5%. Outcome-only evaluation hides this failure mode; step-wise causal ground truth is the missing piece for trustworthy LLM-based RCA agents.

1 简介Introduction

根本原因分析Root cause analysis(RCA)，精确定位大型软件系统中的哪个组件导致了故障，已成为 LLM 代理的严格测试平台(RCA), pinpointing which component caused a failure in a large software system, has emerged as a demanding testbed for LLM agents[16, 2, 1, 23]。 根源故障很少出现在症状首次出现的地方：现代云应用程序被分成数十个通过网络进行通信的小组件. The originating fault is rarely where symptoms first appear: modern cloud applications are split into dozens of small components communicating over the network[25]，因此本地故障可以在任何人注意到之前通过调用者级联并到达系统的远程部分。 从这个级联中，代理接收异构遥测数据：显示每个请求如何传播的请求跟踪、时间序列指标和自由格式日志。 它必须从该遥测数据向后推理到原始故障。, so a local fault can cascade through callers and reach distant parts of the system before any human notices. From this cascade, the agent receives heterogeneous telemetry: request traces showing how each request propagated, time-series metrics, and free-form logs. It must reason backward from this telemetry to the originating fault.

对推导进行评分，而不仅仅是对结果进行评分，揭示了我们所说的Scoring the derivation rather than just the outcome reveals what we call the无根据的诊断ungrounded diagnosis：代理识别出正确的根本原因服务，但没有经过验证的因果传播路径将其链接到观察到的故障。 大规模检测它需要逐步的因果基础事实，但构建它会遇到代理的问题：仅从遥测数据来看，注释者仍然必须从级联效应向后推理到原始故障，因为许多故障可以产生类似的遥测数据。 但是错误注入记录向注释者提供了代理永远看不到的东西：启动级联的干预: the agent identifies a correct root-cause service without a verified causal propagation path linking it to the observed failure. Detecting it at scale requires step-wise causal ground truth, but building it runs into the agent’s problem: from telemetry alone, an annotator would still have to reason backward from cascading effects to the originating fault, since many faults can produce similar telemetry. But fault-injection records hand the annotator one thing the agent never sees: the intervention that started the cascade[12]。 这种信息不对称. This information asymmetry[10]将注释者的任务从推理转变为turns the annotator’s task from inference into前向验证forward verification：根据给定的原因，检查实际遵循的下游影响。: with the cause given, check which downstream effects actually followed.

我们将这一见解转化为 PAVE（通过验证效果的路径注释），这是一种注释协议，可从故障注入记录中重建经过验证的因果传播路径。 没有一个单一的信号是足够的：结构上合理的链可能实际上并未带来故障，统计上的共现可能是巧合，并且单独的时间对齐并不意味着因果关系。 因此，PAVE 仅当同时满足所有三个条件时才承认候选路径：符合已知的传播机制（结构性）、与预注入基线的统计显着偏差（统计性）以及上游到下游时序对齐（时间）。 因此，承认的路径携带一致的结构、统计和时间证据（第We turn this insight into PAVE (Path Annotation via Verified Effects), an annotation protocol that reconstructs verified causal propagation paths from fault-injection recordings. No single signal is sufficient: a structurally plausible chain may not actually have carried the failure, a statistical co-occurrence may be coincidental, and aligned timing alone does not imply a causal link. PAVE therefore admits a candidate path only when it satisfies all three conditions jointly: conformance to known propagation mechanisms (structural), statistically significant deviation from a pre-injection baseline (statistical), and upstream-to-downstream timing alignment (temporal). Admitted paths thus carry consistent structural, statistical, and temporal evidence (Section2.3).

将 PAVE 应用于 3 个架构不同的微服务系统（TrainTicket、OpenTelemetry Demo 和 DeathStarBench Hotel Reservation）和 27 种故障类型，产生 OpenRCA 2.0，这是第一个具有逐步因果注释的跨系统 RCA 基准：500 个可评估实例，平均带有 7.5 个经过验证的因果边缘。Applying PAVE across 3 architecturally distinct microservice systems (TrainTicket, the OpenTelemetry Demo, and DeathStarBench Hotel Reservation) and 27 fault types yields OpenRCA 2.0, the first cross-system RCA benchmark with step-wise causal annotations: 500 evaluable instances carrying 7.5 verified causal edges on average.

在 OpenRCA 2.0 上，识别正确的服务和将其置于可验证的路径中之间的差距对于前沿法学硕士来说是巨大的。 对 11 个此类模型进行平均，代理仅在 20.7% 的案例中恢复了确切的根本原因集。 为了找出这个困难所在，我们放宽了标准：识别至少一个正确的根本原因服务的比例上升到 76.0%，但将该服务扎根于已验证的因果传播路径中观察到的症状的满足率只有 61.5%，大约五分之一的正确识别没有扎根。 仅结果评估隐藏了这种失败模式；对于基于 LLM 的值得信赖的 RCA 代理来说，逐步的因果基础事实是缺失的部分。On OpenRCA 2.0, the gap between identifying a correct service and grounding it in a verifiable path is substantial across frontier LLMs. Averaged across 11 such models, agents recover the exact root-cause set in only 20.7% of cases. Outcome-only evaluation hides this failure mode; step-wise causal ground truth is the missing piece for trustworthy LLM-based RCA agents.

过程级基本事实揭示了基于 LLM 的 RCA 代理中仅结果评估隐藏的推理差距：在 11 个前沿 LLM 中，正确的根本原因识别通常不基于任何经过验证的因果传播路径。Process-level ground truth reveals a reasoning gap in LLM-based RCA agents that outcome-only evaluation hides: across 11 frontier LLMs, correct root-cause identifications are routinely not grounded in any verified causal propagation path.

Three patterns recur across the sample, each describing how an agent commits to an incorrect or unsupported answer rather than continuing to verify, and together they account for the dominant share of ungrounded diagnoses.

(1) 勘探中过早承诺。(1) Premature commitment under under-exploration.在确定了一个可能的根本原因后，代理停止调查并发出答案，而不会检查同时发生的故障或替代归因。 这种形状在混合注入中最为明显，它将一个突出的错误与一个微妙的错误配对：每个评估的模型都集中在突出的一半上（通常在异构主干上发出几乎相同的措辞），并且一致错过微妙的一半，每当地面事实覆盖多个服务时，就会抑制召回率和 EM。After identifying one plausible root cause, the agent stops investigating and emits the answer, leaving co-occurring faults or alternative attributions unexamined. This shape is most visible on hybrid injections that pair one prominent fault with one subtle one: every evaluated model converges on the prominent half (often emitting nearly identical wording across heterogeneous backbones) and uniformly misses the subtle half, depressing Recall and EM whenever the ground truth covers more than one service.

(2) 可观察活动的存在偏差。(2) Presence bias on observable activity.代理根据他们所看到的情况来衡量证据，并将观察到的活动的缺失视为正常运行的证据，而不是认识到缺失本身可能是故障特征。 Killed-pod 注入使这种故障模式变得清晰：在事件窗口期间，受影响的服务完全停止生成跨度，并且许多代理将由此产生的沉默读取为“该服务没有错误，因此这里没有故障”，然后将事件归因于上游调用者，这些调用者恰恰因为被调用者消失而出现错误。 模式（3）的双重特征：对强积极信号的注意力偏向和对无声信号的注意力偏向共同解释了定位缺陷的大部分。Agents weight evidence by what they see and treat absence of observed activity as evidence of normal operation, rather than recognizing that the absence itself can be the fault signature. 4.1 从基于分类的排名到生成推理From Classification-Based Ranking to Generative Reasoning

根本原因分析 (RCA) 的制定方式发生了根本性转变。 传统上，RCA 被选为The formulation of Root Cause Analysis (RCA) has undergone a fundamental shift. F.4.4 Key Design Choices

  • •

    Investigation/synthesis separation. The investigation prompt withholds the JSON schema so the model spends tokens on collecting evidence rather than packing partial answers.   • •

    Controlled fault-kind vocabulary.   • •

    No topology leakage. The agent is not given the service dependency graph; service relations must be inferred from trace data, testing investigative ability rather than pattern matching over a known graph.

  • •

    Paired normal/abnormal telemetry. Both pre- and post-injection parquets ship in the case directory, so the agent can run differential queries (error rates, latency tails, log volumes) on identical schemas.

G.2.1 Primary Metrics (Service-Level)

All primary metrics operate on service-level representations. Service names are normalized (lowercased, ts- prefix stripped, hyphens removed) before comparison.

Edge F1. Let ℰ^\hat{\mathcal{E}} and ℰ∗\mathcal{E}^{*} be the service-level edge sets of the predicted and ground-truth causal graphs, respectively:

Edge Precision =|ℰ^∩ℰ∗||ℰ^|,Edge Recall=|ℰ^∩ℰ∗||ℰ∗|\displaystyle=\frac{|\hat{\mathcal{E}}\cap\mathcal{E}^{*}|}{|\hat{\mathcal{E}}|},\quad\text{Edge Recall}=\frac{|\hat{\mathcal{E}}\cap\mathcal{E}^{*}|}{|\mathcal{E}^{*}|} (7)

Edge F1 is the harmonic mean.

Node F1. Let 𝒱^\hat{\mathcal{V}} and 𝒱∗\mathcal{V}^{*} be the service-level node sets:

Node Precision =|𝒱^∩𝒱∗||𝒱^|,Node Recall=|𝒱^∩𝒱∗||𝒱∗|\displaystyle=\frac{|\hat{\mathcal{V}}\cap\mathcal{V}^{*}|}{|\hat{\mathcal{V}}|},\quad\text{Node Recall}=\frac{|\hat{\mathcal{V}}\cap\mathcal{V}^{*}|}{|\mathcal{V}^{*}|} (8)

Node F1 measures whether the agent correctly identified the set of affected services.

Boundary case. When both the predicted and ground-truth sets are empty for a metric (e.g., both graphs have zero edges), we assign a perfect score of 1.0, since the agent correctly predicted the absence of that element.

G.2.2 SQL Exec

The agent answer schema (Section F.3) ties every claim to at least one piece of SQL evidence. Every evidence.sql in the agent answer is re-executed on a fresh in-memory DuckDB connection with each *.parquet of the case directory mounted as a same-named view. The result is one of three statuses: OK (executed, ≥1\geq 1 row), EMPTY (executed, 0 rows), or SQL_ERROR (parse or runtime failure). Per case,

SQL Exec=|{e∈ℰev,q:status​(e)=OK}||ℰev,q|\text{SQL Exec}=\frac{|\{e\in\mathcal{E}_{\text{ev},q}:\text{status}(e)=\texttt{OK}\}|}{|\mathcal{E}_{\text{ev},q}|} (9)

where ℰev,q\mathcal{E}_{\text{ev},q} is the union of all evidence items in qq’s root_causes and propagation edges. This axis is mechanical; whether the rows actually back the claim is not scored here.

G.2.3 Diagnostic Reasoning Axes

Path Reachability (PR). Path reachability measures the fraction of all instances where the agent both names a correct root-cause service and constructs at least one valid directed path from that service to a ground-truth alarm node in its predicted graph:

PR=1|𝒬|∑q∈𝒬𝟙[AnySvcq=1∧∃path r^q↝s^q in 𝒢^q∣r^q∈Rq∗,s^q∈Aq∗]\text{PR}=\frac{1}{|\mathcal{Q}|}\sum_{q\in\mathcal{Q}}\mathbb{1}\left[\text{AnySvc}_{q}=1\;\wedge\;\exists\,\text{path }\hat{r}_{q}\leadsto\hat{s}_{q}\text{ in }\hat{\mathcal{G}}_{q}\mid\hat{r}_{q}\in R^{*}_{q},\,\hat{s}_{q}\in A^{*}_{q}\right] (10)

where Rq∗R^{*}_{q} and Aq∗A^{*}_{q} are the ground-truth root cause and alarm-node sets for instance qq, and AnySvcq=1\text{AnySvc}_{q}=1 when at least one of the agent’s predicted root-cause services lies in Rq∗R^{*}_{q} (kind-agnostic). Anchoring on AnySvc rather than on a kind-correct hit lets PR vary independently from the fault-kind-tagged Recall: PR isolates whether the agent constructed a faithful chain, while Recall captures whether it also labelled the fault kind correctly. Cases where the agent named no correct service receive PR=0{}=0 by definition, since no service-correct anchor exists for the path. PR is therefore strictly upper-bounded by AnySvc, and the share of AnySvc cases failing PR quantifies how often a correctly localized service lacks even a single actionable propagation path.

HIT-anchored variant.

For backward comparison we also report a HIT-anchored variant of PR (Appendix Table 9), which restricts the anchor to root-cause claims that match both service and fault kind. The HIT-anchored variant is strictly upper-bounded by Recall and is what the SDK stores by default; the AnySvc-anchored variant in the main table is computed locally from the same trajectories.
