可靠的空间分析是 GIS 科学中的一项具有挑战性的任务。分析必须保留坐标参考语义、空间谓词、拓扑、测量单位、空间支持和地理合理性。目前的差距是，基于LLM的GIS系统越来越多地生成流畅的脚本和工具工作流程，但它们很少使这些地理规则明确化或在真实的本地GIS数据上大规模验证它们。我们推出了 GeoContra，这是一个基于地理的验证和修复框架，适用于 LLM 驱动的 Python GIS 工作流程。 GeoContra 将每个任务表示为基于自然语言空间问题、数据集模式、CRS 元数据、预期输出、空间关系语义、拓扑和度量约束、所需 GIS 操作和禁止的快捷方式的可执行地理空间契约。生成的程序通过静态地理规则检查、运行时工件验证和任务级语义验证器进行检查；违规行为会在有界修复循环中返回到模型。我们评估的是Reliable spatial analysis is a challenging task in GIScience. An analysis must preserve coordinate-reference semantics, spatial predicates, topology, measurement units, spatial support, and geographic plausibility. The current gap is that LLM-based GIS systems increasingly generate fluent scripts and tool workflows, but they rarely make these geographic rules explicit or verify them at scale on real local GIS data. We present GeoContra, a geography-grounded verification and repair framework for LLM-driven Python GIS workflows. GeoContra represents each task as an executable geospatial contract over a natural-language spatial question, dataset schemas, CRS metadata, expected outputs, spatial relation semantics, topology and metric constraints, required GIS operations, and forbidden shortcuts. Generated programs are checked by static geographic-rule inspection, runtime artifact validation, and task-level semantic verifiers; violations are returned to the model in a bounded repair loop. 1 简介Introduction

自动化 GIS 的核心挑战不仅在于系统是否可以编写代码，还在于它是否可以保留分析的地理意义。传统的 GIS 脚本编写已经很容易出错，因为分析人员必须将空间问题转换为一系列操作，其有效性取决于坐标参考系统、测量单位、空间支持、几何有效性、拓扑、空间谓词方向、栅格分辨率、图形连通性和输出解释。脚本在以度为单位进行缓冲、聚合错误的面积单位、删除零计数源对象、将欧几里得距离视为网络可访问性或返回负行程时间时，在语法上可能是正确的。此类失败会破坏可重复性和空间决策支持，因为它们改变了正在回答的地理问题。The central challenge of automated GIS is not merely whether a system can write code, but whether it can preserve the geographic meaning of an analysis. Traditional GIS scripting is already error-prone because analysts must translate a spatial question into a chain of operations whose validity depends on coordinate reference systems, measurement units, spatial support, geometry validity, topology, spatial predicate direction, raster resolution, graph connectivity, and output interpretation. A script may be syntactically correct while buffering in degrees, aggregating over the wrong areal unit, dropping zero-count source objects, treating a Euclidean distance as network accessibility, or returning a negative travel time. Such failures undermine reproducibility and spatial decision support because they change the geographic question being answered.

大型语言模型加剧了这一长期存在的 GIS 问题。最近关于 GeoFM 的研究认为，基础模型可能会重塑空间数据科学和 GeoAI，但也提出了围绕地理对齐、多模态和空间明确评估的挑战Large language models intensify this long-standing GIS problem. Recent study on GeoFM argues that foundation models may reshape spatial data science and GeoAI, but also raises challenges around geo-alignment, multimodality, and spatially explicit evaluation[1]。 Nature Machine Intelligence 同样强调，地理空间基础模型应该负责任地开发，而不仅仅是为了性能而缩放. Nature Machine Intelligence has similarly emphasized that geospatial foundation models should be developed responsibly rather than only scaled for performance[2]，以及最近的地球观测基础模型显示了地理空间人工智能变得更加通用和多模式的速度, and recent Earth-observation foundation models show the speed at which geospatial AI is becoming more general and multimodal[3]。与此同时，最近的 GIS 和地球科学法学硕士工作已将模型适应领域知识、GIS 工具、拓扑推理和地理空间代码生成. In parallel, recent GIS and geoscience LLM work has adapted models to domain knowledge, GIS tools, topological reasoning, and geospatial code generation[8, 9, 4, 5, 6, 7];其他基准测试评估地理空间代码生成和 Google Earth Engine 程序; other benchmarks evaluate geospatial code generation and Google Earth Engine programs[14, 17, 18]。这些努力证明了基于 LLM 的 GIS 自动化的前景，但它们也揭示了一个差距：大多数系统仍然以工具调用、代码流畅性、基础模型功能或特定于平台的执行为中心，而 GIS 科学问题. These efforts demonstrate the promise of LLM-based GIS automation, but they also reveal a gap: most systems remain centered on tool invocation, code fluency, foundation-model capability, or platform-specific execution, while the GIScience question of地理规则保存geographic rule preservation仅部分检查。特别是，现有的评估很少将真实的本地矢量、栅格、网络和拓扑数据与可以大规模测试 CRS 正确性、空间关系语义、拓扑一致性、度量合理性和行级再现性的可执行合约相结合。缩小这一差距很重要，因为可执行但地理位置错误的 LLM-GIS 工作流程可能会默默地扭曲可达性、暴露度、环境正义和规划结论。is only partially checked. In particular, existing evaluations rarely combine real local vector, raster, network, and topology data with executable contracts that can test CRS correctness, spatial-relation semantics, topology consistency, metric plausibility, and row-level reproducibility at scale. Closing this gap matters because an LLM-GIS workflow that is executable but geographically wrong can silently distort accessibility, exposure, environmental justice, and planning conclusions.

本文采取了地理驱动的立场：LLM驱动的GIS应该根据明确的空间契约来评估和修复，而不仅仅是根据生成的代码是否运行。我们引入了 GeoContra，一个框架，它将 LLM 与机器可检查的地理空间合同和验证者引导的修复循环包装在一起。该模型仍然生成 Python GIS 工作流程，但 GeoContra 在生成之前指定了空间问题、数据表示、预期输出、所需的地理操作、禁止的快捷方式和地理有效性规则。生成后，系统检查工作流程是否保留大地测量、拓扑、关系、度量和表格语义，并将具体的地理违规返回到模型进行修复。This paper takes a geography-driven position: LLM-driven GIS should be evaluated and repaired according to explicit spatial contracts, not only by whether generated code runs. We introduce GeoContra, a framework that wraps an LLM with machine-checkable geospatial contracts and a verifier-guided repair loop. The model still produces Python GIS workflows, but GeoContra specifies the spatial question, data representations, expected output, required geographic operations, forbidden shortcuts, and geographic validity rules before generation. After generation, the system checks whether the workflow preserves geodetic, topological, relational, metric, and tabular semantics, and it returns concrete geographic violations to the model for repair.

经验设置故意广泛。该基准包含从 15 个大波士顿地区的本地地理空间图层生成的 7,079 个真实任务，涵盖缓冲区计数、空间连接、最近邻距离、网络可访问性、覆盖区域、栅格采样、区域统计、拓扑质量任务和多步骤工作流程。我们在完整基准上对 DeepSeek-V4 和 Kimi-K2.5 运行配对的仅 LLM 和 GeoContra 评估，每个模型系列生成 14,158 行。我们进一步评估 11 个开放模型，每个模型在两种设置下执行 300 个选定任务，每个模型运行 600 次。The empirical setting is deliberately broad. The benchmark contains 7,079 real tasks generated from local geospatial layers for 15 Greater Boston areas, covering buffer counting, spatial joins, nearest-neighbor distances, network accessibility, overlay areas, raster sampling, zonal statistics, topology-quality tasks, and multi-step workflows. We run paired LLM-only and GeoContra evaluations for DeepSeek-V4 and Kimi-K2.5 on the full benchmark, yielding 14,158 rows per model family. We further evaluate 11 open models, each on 300 selected tasks under two settings, yielding 600 runs per model.

该基准测试令人信服，因为它不是孤立提示的合成玩具套件。它是根据真实的本地地理空间资产构建的，混合矢量、栅格、网络和拓扑操作，跨越具有异构特征分布的城市，并将每个任务编码为具有模式、CRS、方法、拓扑、度量和输出要求的可执行合同。在实践中，行业 GIS 数据通常是私有的、分散的，并且不与可参考的任务合同一起发布，这使得 LLM GIS 评估没有共享的、可重复的压力测试。据我们所知，The benchmark is convincing because it is not a synthetic toy suite of isolated prompts. It is built from real local geospatial assets, mixes vector, raster, network, and topology operations, spans municipalities with heterogeneous feature distributions, and encodes each task as an executable contract with schema, CRS, method, topology, metric, and output requirements. In practice, industry GIS data are often private, fragmented, and not released with referenceable task contracts, which leaves LLM GIS evaluation without a shared, reproducible stress test. To the best of our knowledge,GeoContra-Real是第一个这种规模的基准，使可执行的地理空间合同成为评估和修复法学硕士驱动的 GIS 工作流程的核心。is the first benchmark at this scale to make executable geospatial contracts central to evaluating and repairing LLM-driven GIS workflows.

6 讨论Discussion

结果表明，LLM 地理空间可靠性较少依赖于模型规模，而更多地依赖于模型周围的结构。在仅限法学硕士的环境中经常失败的小型开放模型仍然可以从明确的合同和验证者反馈中受益匪浅。相反，当唯一目标是合理的代码时，强封闭模型仍然会犯系统性 GIS 错误。最大的改进发生在无需完整预言机即可检查错误的任务中：行保存、CRS 处理、空间谓词、网络方法使用和输出模式有效性。The results suggest that LLM geospatial reliability depends less on model scale alone than on the structure surrounding the model. Smaller open models that fail frequently in the LLM-only setting can still benefit substantially from explicit contracts and verifier feedback. Conversely, strong closed models still make systematic GIS mistakes when the only target is plausible code. The largest improvements occur in tasks where errors are checkable without a full oracle: row preservation, CRS handling, spatial predicates, network-method use, and output schema validity.

从 GIS 科学的角度来看，关键的含义是值得信赖的 GeoAI 应该将自动化工作流程的地理假设公开为一流的计算对象。合同指定正在分析哪些空间支持、预期哪种空间关系、哪种 CRS 和单位系统使测量有意义、必须遵守哪些拓扑规则以及哪些输出可以被解释为地理上合理的。这使得基于 LLM 的 GIS 从代码辅助转向From a GIScience perspective, the key implication is that trustworthy GeoAI should expose the geographic assumptions of an automated workflow as first-class computational objects. A contract specifies which spatial support is being analyzed, which spatial relation is intended, which CRS and unit system make measurements meaningful, which topology rules must hold, and which outputs can be interpreted as geographically plausible. This shifts LLM-based GIS from code assistance toward可验证的空间分析verifiable spatial analysis：模型不仅仅因为生成可执行脚本而获得奖励，还因为在整个分析链中保留空间问题而获得奖励。: a model is not rewarded merely for generating an executable script, but for preserving the spatial question through the entire analysis chain.

当前的验证器故意是轻量级的。它尚未将每个输出与参考解决方案进行比较，并且一些拓扑质量任务仍然很困难。这是一种设计权衡：该框架旨在扩展到数千个任务，同时保持检查的可解释性。未来的工作应该添加更强大的特定于任务的参考求解器、更丰富的拓扑验证器、决定何时值得进行额外轮次的不确定性修复策略，以及区分可接受的分析替代方案和违反任务意义的特定领域的地理本体。The current verifier is deliberately lightweight. It does not yet compare every output against a reference solution, and some topology-quality tasks remain difficult. This is a design trade-off: the framework aims to scale to thousands of tasks while keeping checks interpretable. Future work should add stronger task-specific reference solvers, richer topology validators, uncertainty-aware repair policies that decide when additional rounds are worthwhile, and domain-specific geographic ontologies that distinguish acceptable analytical alternatives from violations of the task meaning.

一个相关的限制是当前语义验证器的范围。本文中，语义层主要检查生成的工作流是否包含合约所需的GIS操作，例如缓冲区构建、空间连接、图最短路径、叠加或栅格采样。这捕获了许多可执行但错误的程序，但距离完整的空间语义理解还很远。它尚未验证跨多个层的复杂空间关系一致性、结果的空间分布合理性、空间自相关模式、邻域效应或输出地图在地理上是否“看起来”合理。这些更丰富的语义验证形式对于未来值得信赖的 GeoAI 非常重要。他们可能需要针对选定任务类的参考求解器、分布感知的空间诊断、拓扑感知的几何比较以及对结果地图和空间模式的学习或基于规则的检查。A related limitation is the scope of the current semantic verifier. In this paper, the semantic layer mainly checks whether the generated workflow contains the GIS operation required by the contract, such as buffer construction, spatial joins, graph shortest paths, overlays, or raster sampling. This catches many executable-but-wrong programs, but it is still far from full spatial semantic understanding. It does not yet verify complex spatial-relation consistency across multiple layers, the spatial distributional plausibility of results, spatial autocorrelation patterns, neighborhood effects, or whether an output map “looks” geographically reasonable. These richer forms of semantic validation are important for future trustworthy GeoAI. They will likely require reference solvers for selected task classes, distribution-aware spatial diagnostics, topology-aware geometry comparison, and learned or rule-based checks over result maps and spatial patterns.

有些错误对于 GeoContra 来说也很难修复。首先，如果任务未明确说明，或者合同没有对相关地理区别进行编码，验证者可能无法判断两种合理的解释是否等效。其次，噪声或不完整的源数据，例如丢失的 OSM 标签或不明确的设施类别，无法仅通过程序修复来修复。第三，重复的低级编码失败、不受支持的库调用、包不兼容或超时可能会在模型达到有意义的 GIS 工作流程之前耗尽有限的修复预算。第四，保留所需操作但产生令人难以置信的空间分布的错误可能会通过当前的轻量级语义检查。这些案例澄清了贡献的边界：GeoContra 是一个基于合同的修复框架，而不是一个完整的地理预言机。Some errors are also difficult for GeoContra to repair. First, if a task is under-specified or if the contract does not encode the relevant geographic distinction, the verifier may be unable to tell whether two plausible interpretations are equivalent or not. Second, noisy or incomplete source data, such as missing OSM tags or ambiguous facility categories, cannot be fixed by program repair alone. Third, repeated low-level coding failures, unsupported library calls, package incompatibilities, or timeouts can exhaust the bounded repair budget before the model reaches a meaningful GIS workflow. Fourth, errors that preserve the required operation but produce an implausible spatial distribution may pass the current lightweight semantic checks. These cases clarify the boundary of the contribution: GeoContra is a contract-grounded repair framework, not a complete geographic oracle.

7 结论Conclusion

我们推出了 GeoContra，这是一个基于地理的验证和修复框架，适用于法学硕士驱动的 GIS 工作流程。在 7,079 个真实任务和 11 个额外的开放模型上，该方法持续提高了可执行性和空间正确性，同时减少了最终违规。案例研究说明了原因：GeoContra 将模糊的故障转换为可操作的地理空间反馈，允许模型围绕 CRS、模式、网络、谓词、拓扑和输出契约错误修复程序。更广泛地说，GeoContra 主张 GeoAI 走一条以 GIS 科学为中心的道路：判断自动化 GIS 的标准应该是它是否保留了地理意义，而不仅仅是它是否生成流畅的代码。We introduced GeoContra, a geography-grounded verification and repair framework for LLM-driven GIS workflows. On 7,079 real tasks and 11 additional open models, the method consistently improves executability and spatial correctness while reducing final violations. The case studies show why: GeoContra converts vague failure into actionable geospatial feedback, allowing the model to repair programs around CRS, schema, network, predicate, topology, and output-contract errors. More broadly, GeoContra argues for a GIScience-centered path for GeoAI: automated GIS should be judged by whether it preserves geographic meaning, not only by whether it produces fluent code.
