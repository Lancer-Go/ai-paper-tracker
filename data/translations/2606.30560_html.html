TraceLab：表征 LLM 服务的编码代理工作负载TraceLab: Characterizing Coding Agent Workloads for LLM Serving

摘要Abstract

编码代理正在迅速成为代理法学硕士的主要应用，但有效地为它们提供服务仍然具有挑战性。应对这一挑战的进展需要了解真实的工作负载模式，但此类分析所需的数据基本上不存在。现有的公共跟踪和基准测试无法捕获跨多个代理和模型系列的真实日常编码代理使用情况以进行服务系统分析。为了帮助填补这一空白，我们收集并发布了大约 4,300 个编码代理会话的跟踪记录，其中包含来自我们日常使用 Claude Code 和 Codex 的大约 350,000 个 LLM 步骤和 430,000 个工具调用。我们的分析表明，编码代理工作负载具有长自主循环、短输出的长上下文、多样化且重尾的工具调用以及高但不完美的前缀缓存命中率。这些发现指出了优化服务的具体机会，包括较低开销的工具调用、附加长度感知预填充、语义感知工具延迟预测以及围绕人为进度差距改进的 KV 缓存管理。我们在以下位置发布了数据集、跟踪收集管道和分析代码：Coding agents are rapidly becoming a major application of agentic LLMs, but serving them efficiently remains challenging. Progress on this challenge requires understanding real workload patterns, yet the data needed for such analysis is largely absent. Existing public traces and benchmarks do not capture real, day-to-day coding-agent usage across multiple agents and model families for serving-system analysis. To help fill this gap, we collect and release a trace of roughly 4,300 coding-agent sessions, containing about 350,000 LLM steps and 430,000 tool calls from our own day-to-day use of Claude Code and Codex. Our analysis shows that coding-agent workloads feature long autonomous loops, long contexts with short outputs, diverse and heavily-tailed tool calls, and high but imperfect prefix cache hit rates. These findings point to concrete opportunities for optimizing serving, including lower-overhead tool calling, append-length-aware prefill, semantic-aware tool-latency prediction, and improved KV-cache management around human-paced gaps. In this paper, we share initial insights from what is, to our knowledge, the first large-scale cross-provider trace of real coding-agent usage: about 4,300 sessions comprising roughly 350,000 LLM steps and 430,000 tool calls, collected from 43 developers over roughly eight months and spanning both Claude Code and Codex across more than 20 model versions. 鉴于这些见解，我们重点关注以下关于优化编码代理的 LLM 服务的研究方向：Given these insights, we highlight the following research directions on optimizing LLM serving for coding agents:

  1. 1.

    频繁的工具-LLM 切换的开销激发了更密集或融合的工具调用和更低开销的工具调用批准/运行时路径。The overhead of frequent tool-LLM switch motivates denser or fused tool invocations and lower-overhead tool call approval/runtime paths.

  2. 2.

    短附加长度和长附加长度的混合激发了附加长度感知的预填充路由，以及内核的自适应选择和服务引擎并行性。The mixture of short and long append lengths motivates append-length-aware prefill routing, along with adaptive selection of kernels and serving-engine parallelism.

  3. 3.

    每种工具类型的较大延迟变化表明，KV 缓存逐出策略的工具延迟预测应考虑所请求操作的语义和最近的延迟历史记录，而不仅仅是工具名称。The large latency variation for each tool type suggests that tool-latency prediction for KV cache eviction policy should consider the semantics of the requested operation and recent latency history, not just the tool name.

  4. 4.

    长前缀激发稀疏注意力以降低解码成本。The long prefix motivates sparse attention for reducing the decoding cost.

  5. 5.

    频繁的空闲间隙需要更便宜的 KV 缓存存储、更好的压缩算法以及明智的 KV 缓存驱逐或围绕这些间隙的预取策略。The frequent idle gaps necessitate cheaper KV cache storage, a better compression algorithm, and wise KV-cache eviction, or prefetching policies around those gaps.

总体而言，我们的工作首次对编码代理的实际工作负载特征进行了大规模、跨提供商的研究。我们发布了数据集、跟踪收集和分析管道，我们很高兴看到社区如何使用这些资源来进一步了解和优化这一新兴工作负载。Overall, our work provides the first large-scale, cross-provider look into the real-world workload characteristics of coding agents. We release our datasets, trace collection and analysis pipeline, and we are excited to see how the community can use these resources to further understand and optimize for this emerging workload.

2.1 代理法学硕士和编码代理Agentic LLMs and Coding Agents

与传统的LLM相比，Agentic LLM旨在与外部工具和环境交互，执行多步骤推理，因此更适合复杂的任务。编码代理作为一种特定类型的代理法学硕士，旨在协助完成编程任务，例如代码生成、调试和测试。 在短短几年内，它们已成为代理法学硕士最广泛采用的应用之一。 2025 年 Stack Overflow 开发者调查报告称，84% 的开发者现在在工作流程中使用或计划使用 AI 工具Agentic LLMs, compared to traditional LLMs, are designed to interact with external tools and environments, perform multi-step reasoning, and thus are more suitable for complex tasks. 2.2 现有数据集和基准Existing Datasets and Benchmarks

尽管编码代理很复杂且很受欢迎，但仍缺乏捕获其实际使用情况并适合指导系统优化的公共数据集。Despite the complexity and popularity of coding agents, there is a lack of public datasets that capture their real-world usage and suitable for guiding system optimization.

The output-cached policy requires transferring the KV entries produced during decode back to the shared KV-storage backend. Decode instances are read-only with respect to shared KV state: they fetch the prefix KV needed for generation, but discard the KV entries for newly generated output tokens.

9 局限性和未来的工作Limitations and Future Work

我们的研究有一些局限性，也指出了未来的工作。首先，我们的踪迹是从我们自己日常使用编码代理中得出的。尽管它跨越多个开发人员、代理和模型版本，但结果可能无法完全推广到其他组织、开发工作流程或代理域。其次，我们的分析仅限于外部可见的日志，包括提示、模型响应、工具调用、时间戳和令牌元数据。如果没有服务提供商的内部遥测，我们可以识别工作负载模式，但只能推断其背后的机制，例如调度策略、缓存行为或后端路由。第三，代理的工作负载正在从编码扩展到更广泛的计算机使用和自动化任务。未来的跟踪研究应该将此方法扩展到其他代理领域，并比较它们的上下文增长、工具使用、延迟和缓存行为与编码代理工作负载的差异。Our study has several limitations that also point to future work. First, our trace is drawn from our own day-to-day use of coding agents. Although it spans multiple developers, agents, and model versions, the results may not fully generalize to other organizations, development workflows, or agent domains. Second, our analysis is limited to externally visible logs, including prompts, model responses, tool calls, timestamps, and token metadata. Without internal telemetry from service providers, we can identify workload patterns but can only infer the mechanisms behind them, such as scheduling policies, cache behavior, or backend routing. Third, agent workloads are expanding beyond coding to broader computer-use and automation tasks. Future trace studies should extend this methodology to other agent domains and compare how their context growth, tool use, latency, and cache behavior differ from coding-agent workloads.

10 结论Conclusion

在本文中，我们提出了基于跟踪的编码代理工作负载分析。值得注意的是，我们发现这些工作负载具有长自主循环、长上下文与短输出、强长尾工具调用以及高但不完美的前缀缓存命中率。总而言之，这些观察结果表明了服务机会，包括更密集或更低开销的工具调用、特定于附加长度的预填充优化，以及更好的 KV 缓存驱逐或围绕人为节奏的差距进行预取。我们希望这项工作为未来关于编码代理以及更广泛的基于 LLM 的代理的系统研究提供有用的参考，并且我们期待社区努力将这种基于跟踪的分析方法扩展到更大规模和更多样化的代理工作负载。In this paper, we present a trace-based analysis of coding-agent workloads. Notably, we find that these workloads feature long autonomous loops, long contexts paired with short outputs, strongly long-tailed tool calls, and high yet imperfect prefix-cache hit rates. Taken together, these observations point to serving opportunities, including denser or lower-overhead tool calling, append-length-specific prefill optimization, and better KV-cache eviction or prefetching around human-paced gaps. We hope this work provides a useful reference for future system research on coding agents and, more broadly, on LLM-based agents, and we look forward to community efforts that extend this trace-based analysis methodology to larger-scale and more diverse agent workloads.
