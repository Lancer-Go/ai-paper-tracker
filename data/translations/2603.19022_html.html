LLM 端点稳定性和身份的行为指纹Behavioral Fingerprints for LLM Endpoint Stability and Identity

Jonah Leshin , Manish Shah , Ian Timmis Project VAILSan FranciscoUSA jonah@projectvail.org and Daniel Kang University of Illinois Urbana-ChampaignDepartment of Computer ScienceUrbanaIllinoisUSA
摘要。Abstract.

AI原生应用程序的一致性取决于The consistency of AI-native applications depends on the行为的 一致性behavioral consistency为它们提供动力的模型端点。传统的可靠性 正常运行时间、延迟和吞吐量等指标未捕获 行为改变，并且终点可以保留 “健康”，而其有效模型身份发生变化 由于权重、分词器、量化的更新， 推理引擎、内核、缓存、路由或 硬件。我们介绍of the model endpoints that power them. Traditional reliability metrics such as uptime, latency and throughput do not capture behavioral change, and an endpoint can remain “healthy” while its effective model identity changes due to updates to weights, tokenizers, quantization, inference engines, kernels, caching, routing, or hardware. We introduce稳定性监测器Stability Monitor, 一个 黑匣子稳定性监测系统，定期 通过对固定的输出进行采样来对端点进行指纹识别 提示设置并比较结果输出 随时间的分布。指纹比较使用 能量距离统计总和 提示，用排列检验 p 值作为分布变化的证据 按顺序聚合以检测 更改事件并定义稳定期。在受控的 验证，稳定性监视器检测到更改 模型系列、版本、推理堆栈、量化和行为参数。在 对同一模型的真实世界监控 多个提供商，我们观察到大量 提供商之间以及提供商内部的稳定性 差异。, a black-box stability monitoring system that periodically fingerprints an endpoint by sampling outputs from a fixed prompt set and comparing the resulting output distributions over time. Fingerprints are compared using a summed energy distance statistic across prompts, with permutation-test p-values as evidence of distribution shift aggregated sequentially to detect change events and define stability periods. In controlled validation, Stability Monitor detects changes to model family, version, inference stack, quantization, and behavioral parameters. In real-world monitoring of the same model hosted by multiple providers, we observe substantial provider-to-provider and within-provider stability differences.

1. 简介Introduction

1.1. 可靠性不等于稳定性Reliability is not stability

软件部署直觉“如果它正常运行并且 快，很好”对于 AI 原生系统来说还不够： 端点可以通过标准健康检查，而其输出 漂移、改变格式、语气或工具行为 破坏下游解析器和护栏的方法。 稳定性故障在多步代理中特别有影响 工作流程，早期步骤中的微小差异可以 复合成大的工作流程差异。这个 激励The software deployment intuition “if it’s up and fast, it’s fine” is insufficient for AI-native systems: an endpoint can pass standard health checks while its outputs drift, shifting formatting, tone, or tool behavior in ways that break downstream parsers and guardrails. Stability failures are particularly impactful in multi-step agentic workflows, where small variance in early steps can compound into large workflow variance. This motivates稳定性stability作为一个独特的运营 指标：模型端点的行为一致性 根据固定的接口合同。as a distinct operational metric: behavioral consistency of a model endpoint under a fixed interface contract.

即使用户修复了可见的设置（例如温度）， 由于系统级别的不确定性“在 表面”：推理引擎、内核、缓存、批量大小和硬件的差异——提供商可能会 跨异构环境路由请求。这些因素的值 在运行时可能是整个系统负载的函数，用户无法控制， 从而使端点与用户的不确定性 观点Even if users fix visible settings (e.g., temperature), endpoint behavior can vary due to system level nondeterminism “beneath the surface”: variance in inference engines, kernels, caching, batch sizes, and hardware—and providers may route requests across heterogeneous environments. The values of these factors at run time may be a function of overall system load, which the user cannot control, thus making the endpoint nondeterministic from the user’s perspective(He and Thinking Machines Lab, 2025).

这些系统级因素可能会导致 即使在温度为 0 时也必须考虑不确定性行为 离散的、有意的更新，例如模型版本 变化，破坏了生产的可重复性 和评估环境。评估不稳定和提供者影响 现在被认为是差异的主要来源 基准测试结果These system-level factors, which can result in nondeterministic behavior even at temperature 0, must be considered on top of discrete, deliberate updates such as a model version change, undermining reproducibility in both production and evaluation environments. Evaluation instability and provider effects are now recognized as a major source of variance in benchmarking results(Brand and Denain, 2025).

关于黑盒变更检测的最新工作包括 B3ITMore recent work on black-box change detection includes B3IT(Chauvin et al., 2026)，它使用每个端点的“边界 输入”——多个令牌几乎并列为顶部的提示 低温预测。就像我们的方法一样， B3IT 将问题描述为对输出分布的假设检验 并制定持续监测目标。一个关键的区别是 B3IT 的 探针在初始化阶段针对每个端点进行定制 并且可能需要在更改事件后重新发现，因为 模型的决策边界可能已经发生了变化。我们的系统使用 一个固定的、与模型无关的提示集，在更改事件中持续存在 和端点，避免每个端点初始化。, which uses per-endpoint “border inputs”—prompts where multiple tokens are nearly tied as the top prediction at low temperature. 我们使用能量距离统计作为核心指标 比较响应嵌入的样本。该指标是一个 分布之间的非参数距离 和 是 当且仅当分布在温和条件下匹配时为零（如 随机向量分布的度量）We use an energy distance statistic as the core metric comparing samples of response embeddings. 我们使用基于顺序证据积累 e 值（期望有界测试统计量） 启用连续监控并可选择停止 行为，适合流检测设置We use sequential evidence accumulation based on e-values (expectation-bounded test statistics) to enable continuous monitoring with optional stopping behavior, suited for streaming detection settings(Wang, 2023; Ramdas and Wang, 2025).

我们衡量行为变化的统计方法是 与随着时间的推移运行特定领域评估的项目相补充Our statistical approach to measuring behavioral change is complementary to projects that run domain-specific evaluations over time(Margin Research, 2025; Phillips, 2025)。 随着时间的推移，这些努力提供了有关特定能力的信号， 但通常运行成本昂贵，限制了覆盖的可行性 跨越一系列模型和提供商。. 7. 调查结果：跨提供商比较 相同型号Findings: cross-provider comparisons for the same model

VAIL的指纹支持不同端点的比较 以两种模式提供相同的标称模型： (a) 共享时间窗口上的成对比较，以及 (b) 单个端点相对于一组端点的分歧。VAIL’s fingerprints support comparisons of different endpoints serving the same nominal model in two modes: (a) pairwise comparisons over shared time windows, and (b) individual endpoint divergence relative to a group of endpoints.

7.1. 成对提供商相似度（热图）Pairwise provider similarity (heatmap)

在 (a) 的情况下，我们考虑多个提供者服务于相同的名义模型 在同一时间段内。在这段时间里，我们进行成对指纹 使用能量距离形成每对提供者之间的比较 距离矩阵。 一个应用程序是提供者识别：给定一个为模型提供服务的端点 已知在一组候选提供商中，我们可以确定哪个提供商 通过对端点进行指纹识别并与候选者进行比较来提供服务。 图中In the case of (a), we consider multiple providers serving the same nominal model over the same time period. During this time period, we perform pairwise fingerprint comparisons between each pair of providers using energy distance to form a distance matrix. One application is provider identification: given an endpoint serving a model known to be among a set of candidate providers, we can determine which provider is serving it by fingerprinting the endpoint and comparing against the candidates. 7.2. 个别端点分歧Individual endpoint divergence

对于(b)的情况，我们提出“提供商与群体”的方案 我们将一个提供商的指纹与偏差分数进行比较 所有其他提供商的集中分配 在匹配的时间窗口内同一模型的指纹。对于每个提供商来说， 我们计算该提供商与所有其他提供商指纹的聚合分布之间的距离。 然后，我们将这些距离相对于所有提供商之间的中值距离归一化到聚合分布 产生发散比。例如，分歧比为 2 的提供商的差异是其两倍 来自中位数提供者的总分布。For the case of (b), we propose a “provider vs the pack” deviation score in which we compare one provider’s fingerprints to the pooled distribution of all other providers’ fingerprints for the same model over matched time windows. For each provider, we compute the distance between that provider and an aggregate distribution of all other providers’ fingerprints. We then normalize these distances relative to the median distance across all providers to the aggregate distribution to produce a divergence ratio. For example, a provider with a divergence ratio of 2 is twice as different from the aggregate distribution as the median provider is.

在稳定竞技场“提供商比较”选项卡中，我们计算此 每日差异率并将其值绘制在 时间，使我们能够识别哪些提供商偏离共识并 当。由于该指标是按中位数标准化的，因此它对 个别异常值而不是统一的变化；滚动模型更新 跨提供商的传播不均匀将显示为一系列异常峰值。In the Stability Arena ”Provider Comparisons” tab we compute this divergence ratio daily and plot its values over time, enabling us to identify which providers diverge from the consensus and when. Because the metric is normalized by the median, it is sensitive to individual outliers rather than uniform shifts; a rolling model update that propagates unevenly across providers would appear as a sequence of outlier spikes.

8. 调查结果：现实世界的部署稳定性示例Findings: real-world deployment stability examples

Kimi-K2-0905-Instruct 的生产监控 跨提供商的模型，稳定性监视器观察到 2025 年 11 月，有一个提供商（DeepInfra）最不稳定——几乎所有提供商 指纹生成导致输出分布 触发了一个变更事件。另一方面，由 模型的创建者（Moonshot）表现出 100% 的稳定性。In production monitoring of the Kimi-K2-0905-Instruct model across providers, Stability Monitor observed that in November 2025, one provider (DeepInfra) was least stable—nearly every fingerprint generation resulted in an output distribution that triggered a change event. On the other hand, the endpoint hosted by the model’s creator (Moonshot) showed 100% stability.

2025 年 12 月，稳定性监视器标记了模型更改事件 Parasail，Parasail 团队证实了 由于物理节点而导致硬件提供商切换 失败。In December 2025, when Stability Monitor flagged a model change event for Parasail, the Parasail team confirmed a hardware-provider switch due to a physical node failure.

9. 注意事项和限制Caveats and limitations

即使对于固定模型，推理执行规范 （引擎、内核、缓存、推测解码、 硬件）可以影响下一个令牌概率和令牌 选择；提供商可以跨路由/批量请求 异构环境，引发持续的随机性 这使归因变得复杂并且可能模糊界限 在“改变事件”和“总是有点”之间 不稳定。”Even for a fixed model, inference execution specifications (engine, kernels, caching, speculative decoding, hardware) can affect next-token probabilities and token selection; providers may route/batch requests across heterogeneous environments, inducing ongoing randomness that complicates attribution and can blur the line between “change event” and “always somewhat unstable.”

这种持续的、基础设施驱动的随机性的存在与系统工作一致，认为 端点不确定性通常由以下因素驱动 负载引起的批量大小变化相互作用 非批次不变内核This presence of ongoing, infrastructure-driven randomness is consistent with systems work arguing that endpoint nondeterminism is often driven by load-induced batch-size variation interacting with non-batch-invariant kernels(He and Thinking Machines Lab, 2025)。稳定性监视器是 旨在检测端点级别的变化，以及 端点水平方差可以是这些的乘积 执行层面因素。. Stability Monitor is designed to detect endpoint-level changes, and endpoint-level variance can be a product of these execution-level factors.

10. 结论Conclusion

行为不稳定提高安全性和合规性 担忧：如果模型悄无声息地发生变化，安全性就会受到影响 验证和护栏可能不再适用。稳定性监测提供 行为改变时间的审计跟踪。Behavioral instability raises security and compliance concerns: if a model changes silently, prior safety validation and guardrails may no longer apply. Stability monitoring provides an audit trail of when behavior changed.

在操作上，稳定竞技场还表明 由不同提供商提供的“同一模型”可以 表现出不同的行为特征 提供商基础设施选择；这对于 选择制作提供商和口译 取决于提供商的基准或评估结果 访问路径。Operationally, Stability Arena also surfaces that “the same model” served by different providers can exhibit different behavioral characteristics due to provider infrastructure choices; this matters for selecting production providers and for interpreting benchmark or eval results that depend on provider access paths.
