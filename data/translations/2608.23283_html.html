1 简介Introduction

通用语言模型在知识、推理、数学和编码方面进步很快。然而，即使模型可以给出正确的答案，许多有价值的任务仍然很困难，因为这项工作是在很长的时间内展开的。该模型必须查找和解释证据，操作异构文件，执行和调试代码，维护和修改多个步骤的连贯计划，从失败的操作中恢复而不丢弃有效的进度，并提供其他人可以检查或继续使用的工件。先前关于推理与行动、学习工具使用和交互式代理评估的工作暴露了答案质量和可靠行动之间的差距General-purpose language models have improved rapidly in knowledge, reasoning, mathematics, and coding. Yet many valuable tasks remain difficult even when the model can state the right answer, because the work unfolds over a long horizon. The model must find and interpret evidence, operate on heterogeneous files, execute and debug code, maintain and revise a coherent plan over many steps, recover from failed actions without discarding valid progress, and deliver artifacts that another person can inspect or continue using. Prior work on reasoning-and-acting, learned tool use, and interactive agent evaluation has exposed this gap between answer quality and reliable action(67; 48; 31; 63)。因此，限制能力不是孤立的推理，而是在不断变化的环境中将推理转化为持续工作的能力。. The limiting capability is therefore not reasoning in isolation, but the ability to turn reasoning into sustained work inside a changing environment.

Apodex 1.1 是一个通用模型和执行系统，可扩展复杂工作的代理智能。我们将这一目标具体化为Apodex 1.1 is a general-purpose model and execution system that scales agentic intelligence for complex work. We operationalize this objective as工作能力working capability：通过理解目标、通过工具和状态环境采取行动、在观察结果改变问题时修改计划、从失败中恢复以及满足交付合同，从而在长期范围内取得有用进展的能力。此功能的单位是已完成的工作，而不是孤立的响应。它适用于长期的专业工作流程、以工件为中心的文件和代码任务、开放式科学和财务调查以及其解决方案必须保持可验证的硬推理问题。工作能力是我们长期目标的模型级基础：: the ability to make useful progress over long horizons by understanding an objective, acting through tools and stateful environments, revising plans when observations change the problem, recovering from failure, and satisfying a delivery contract. The unit of this capability is completed work rather than an isolated response. It applies across long-horizon professional workflows, artifact-centric file and code tasks, open-ended scientific and financial investigations, and hard reasoning problems whose solutions must remain verifiable. Working capability is the model-level foundation of our longer-term objective: a重型求解器Heavy-Duty Solver能够承担起日益雄心勃勃、长期运行且可验证的工作的责任。that can take responsibility for increasingly ambitious, long-running, and verifiable work.

我们沿着两个互补的尺度维度开发工作能力。第一个是We develop working capability along two complementary scaling dimensions. The first is环境缩放Environment Scaling：扩展模型学习和操作的文件、搜索和代码世界的多样性、保真度和可验证性。这些环境指定状态、工具、转换、交互预算、失败条件和完成检查。他们将操作、观察、文件更改、代码输出、恢复决策和工件转化为学习分布的一部分，而不是将工具视为附加到其他静态示例的文本描述。: expanding the diversity, fidelity, and verifiability of the file, search, and code worlds in which the model learns and acts. These environments specify state, tools, transitions, interaction budgets, failure conditions, and completion checks. They turn actions, observations, file changes, code outputs, recovery decisions, and artifacts into part of the learning distribution rather than treating tools as textual descriptions attached to otherwise static examples.

第二个是The second is主体协调尺度Agentic Coordination Scaling：扩展跨代理、任务分支和时间的工作组织方式。 Apodex 1.1 学习分解目标、委派工作、合并异步结果、修改共享计划以及重组未完成的分支。特工团队通过跨证据收集、文件分析、实施、验证和反分析的自适应并行工作来实现这些行为。现有系统展示了对话协调、角色专业化和多代理假设生成的收益: expanding how work is organized across agents, task branches, and time. Apodex 1.1 learns to decompose objectives, delegate work, incorporate asynchronous results, revise shared plans, and reorganize unfinished branches. Agent Team realizes these behaviors through adaptive parallel effort across evidence gathering, file analysis, implementation, verification, and counteranalysis. Existing systems demonstrate gains from conversational coordination, role specialization, and multi-agent hypothesis generation(61; 24; 13; 22)。因此，相关的缩放变量不仅仅是代理或样本的数量，而是随着目标的发展可以协调的有用工作量。. The relevant scaling variable is therefore not simply the number of agents or samples, but the amount of useful work that can be coordinated as an objective evolves.

这两个维度都依赖于共同的执行工具。该工具将模型绑定到文件、搜索和代码环境；维护工作空间、工件、出处和分支状态；定义观测和完成合同；并提供重放和验证挂钩。 AgentOS 在此工具下提供持久的运行时，跨工具、代理、上下文压力、干预和部分故障保留权威状态。相同的执行合约支持训练期间的轨迹收集和运行时的持续任务执行，从而在公共模型和系统堆栈中保持环境交互和代理协调。Both dimensions depend on a common execution harness. The harness binds the model to File, Search, and Code environments; maintains workspace, artifact, provenance, and branch state; defines observations and completion contracts; and supplies replay and verification hooks. AgentOS provides the persistent runtime beneath this harness, preserving authoritative state across tools, agents, context pressure, intervention, and partial failure. The same execution contract supports trajectory collection during training and sustained task execution at runtime, keeping environment interaction and agent coordination within a common model-and-system stack.

2.3 主体协调是一个缩放表面Agentic Coordination Is a Scaling Surface

长期工作会产生协调问题和计算问题。一个有能力的模型必须决定如何分解目标，哪些分支可以独立进行，何时部分结果应该改变共享计划，以及何时应该停止过时的工作。这些是可以在训练轨迹中表示的策略行为，而不仅仅是推理时间包装器的属性。多代理框架探索了基于角色的对话、软件开发组织、辩论和动态科学假设生成Long-horizon work creates a coordination problem as well as a computation problem. Multi-agent frameworks have explored role-based conversation, software-development organizations, debate, and dynamic scientific hypothesis generation(61; 24; 45; 18; 22).

A slow or failed branch does not erase completed work elsewhere, and the user can change priorities or stop a path while other branches continue.

It is to expose a common policy to increasingly diverse state transitions, information-acquisition problems, failure modes, and verifiable delivery requirements while preserving the causal structure of real work.

Construction separates reusable infrastructure from task-specific state: shared base images provide interpreters, toolchains, tests, and common dependencies, while each task contributes its repository state and requirements. Long-tail environments are built once and cached, making most new worlds an exercise in state assembly rather than repeated infrastructure construction.

Synthesized tasks expand from verified seeds through composition, abstraction shifts, request variation, and adversarial input changes. As these transformations can invalidate an existing grader, verifier hardening precedes task perturbation; otherwise the result is a corrupted task rather than a new executable world.

代码验证基于沙盒执行。对于收获的世界，失败通过测试必须在基本状态上失败并在参考更改后通过，而通过测试必须在两种状态下都成功。合成世界没有外部预言机，因此仅通过参考解决方案是不够的。我们还测试了求解者是否可以在没有实际完成任务的情况下获得奖励，并且只有在沙箱中成功的攻击才会被视为验证者失败。评分与求解器隔离，因此求解器无法修改验证器本身。失败的执行还用于诊断构造错误：在修复点之前通过的测试指向不正确的测试选择，而在修复点之后失败的测试则指向容器、依赖项或运行命令中的问题。这使得验证既是针对奖励黑客的防御，也是修复环境的可执行反馈的来源。Code verification is grounded in sandboxed execution. For harvested worlds, fail-to-pass tests must fail on the base state and pass after the reference change, while pass-to-pass tests must succeed in both states. Synthesized worlds have no external oracle, so passing the reference solution alone is not enough. We additionally test whether a solver can obtain reward without actually completing the task, and only attacks that succeed in the sandbox are treated as verifier failures. Scoring is isolated from the solver so that the solver cannot modify the verifier itself. Failed executions are also used to diagnose construction errors: tests passing before the fix point to incorrect test selection, while tests failing after the fix point to problems in the container, dependencies, or run command. This makes verification both a defense against reward hacking and a source of executable feedback for repairing the environment.

3.1.3 验证、隔离和重放Verification, Isolation, and Replay

仅当其反馈在交互下保持可信时，可扩展的任务分配才有用。当生成的任务、其测试和参考解决方案三者可能共享相同的错误时，这三者之间的一致性是不够的。可执行检查、独立推导、出处约束或有界语义审查必须在用于生成候选结果的路径之外建立验证器。盲目求解器探测会暴露假阴性，忠实的解决方案和评分者之间的分歧会被退回到任务构建，而不是默默地重新标记为模型失败。A scalable task distribution is useful only when its feedback remains trustworthy under interaction. Agreement among a generated task, its tests, and a reference solution is insufficient when all three may share the same error. Executable checks, independent derivations, provenance constraints, or bounded semantic review must establish the verifier outside the path used to produce the candidate result. Blind solver probes expose false negatives, and disagreements between a faithful solution and the grader are routed back to task construction rather than silently relabeled as model failures.

每次推出都会收到一个不可变的世界清单和一个新的可变沙箱。该工具实现了初始状态，在整个会话中保留它，并在关闭或空闲超时时回收沙箱。粘性路由将会话保留在一名工作人员上。学习服务构建对话和奖励，而安全带则拥有物理执行力；求解器观察、隐藏验证器状态和事后标签保持分离。Each rollout receives an immutable world manifest and a fresh mutable sandbox. The harness materializes the initial state, preserves it throughout the session, and reclaims the sandbox on close or idle timeout. Sticky routing keeps a session on one worker. The learning service constructs dialogue and reward, while the harness owns physical execution; solver observations, hidden verifier state, and post-hoc labels remain separated.

仅当轨迹的初始状态可以重建、工具执行被隔离并且验证器可以重放时，轨迹才会被保留。重播记录包括世界种子和生成器版本、工具版本、操作/观察序列、文件增量、验证器版本和终止原因。在轨迹提供训练信号之前，重放会检查将基础设施故障与策略故障分开。A trajectory is retained only when its initial state can be reconstructed, tool execution is isolated, and the verifier can be replayed. 由此产生的构建原则是“正向便宜，反向昂贵”。生成器使用潜在状态或参考程序来廉价地构建和解决一个世界；代理只能看到渲染的工作空间，并且必须在约束下恢复相关路径。这种不对称性让规模和验证共存，而无需假装每个有机任务都具有机器证明的语义。The resulting construction principle is “forward cheap, inverse expensive.” A generator uses latent state or a reference program to construct and solve a world cheaply; the agent sees only the rendered workspace and must recover the relevant path under constraints. This asymmetry lets scale and verification coexist without pretending that every organic task has machine-proved semantics.

3.2.1 从潜在分解到显式任务板From Latent Decomposition to an Explicit Task Board

在 Apodex 1.0 中，分解主要是内部协调决策：主代理对问题进行推理并派遣专家子代理。 Apodex 1.1 使该决策成为任务状态的明确部分。在委派之前，主代理将其分解写入任务板，任务板的条目记录有界目标、依赖性、解决状态、分配的代理以及返回的证据或工件。董事会不仅仅是私人推理的可视化。它是模型、运行时和用户之间的共享协调记录：子代理从中接收其范围，将完成的工作附加回其中，并且计划修订表示为对其进行的工具介导的编辑。In Apodex 1.0, decomposition was primarily an internal coordination decision: the main agent reasoned about the question and dispatched expert subagents. Apodex 1.1 makes that decision an explicit part of the task state. Before delegation, the main agent writes its decomposition to a task board whose entries record a bounded objective, dependencies, resolution state, assigned agents, and returned evidence or artifacts. The board is not merely a visualization of private reasoning. It is the shared coordination record between the model, runtime, and user: subagents receive their scope from it, completed work is attached back to it, and plan revisions are expressed as tool-mediated edits to it.

计划的外部化改变了协调的语义。一个结果可以立即解锁一个依赖任务；失败或被取代的前提只能使其后代无效；缓慢的分支不再阻碍独立工作的进展。更重要的是，主代理必须不断协调其内部策略与可检查的任务状态。这将一次性前导码的分解转变为长期工作的持久控制面。Externalizing the plan changes the semantics of coordination. A result can unlock a dependent task immediately; a failed or superseded premise can invalidate only its descendants; and a slow branch no longer prevents independent work from progressing. More importantly, the main agent must continuously reconcile its internal strategy with an inspectable task state. This turns decomposition from a one-shot preamble into a persistent control surface for long-horizon work.

3.2.3 非对称验证Asymmetric Verification

Apodex 1.0 在与主代理分离的环境中引入了冲突审查员、事实检查员和草稿审查员Apodex 1.0 introduced conflict reviewers, fact checkers, and draft reviewers in contexts separated from the main agent(10)。上下文分离至关重要，因为继承生成器完整轨迹的验证者很容易被相同的假设所锚定。然而，仅有独立是不够的。如果要求具有相当能力的验证代理再次解决整个问题，它的响应可能会引入第二个同样不受约束的错误链。然后，验证者就成为上下文污染的另一个来源，而不是纠正信号的来源。. Context separation is essential because a verifier that inherits the generator’s full trajectory is easily anchored by the same assumptions. Independence alone, however, is insufficient. If a verification agent of comparable capability is asked to solve the entire problem again, its response can introduce a second, equally unconstrained chain of errors. The verifier then becomes another source of context pollution rather than a source of corrective signal.

Apodex 1.1 构建体Apodex 1.1 constructs验证不对称verification asymmetry：验证故意比生成更窄。验证者不会定期复制整个解决方案，而是会收到特定的声明、其支持证据以及适用的交付约束。它的任务是通过搜索反例、与真正独立的源类进行三角测量、检查原子细节（例如名称、日期、数字和公式）或测试是否符合格式和规范要求来攻击该主张。众所周知，有针对性的验证问题可以减少生成和检查之间的耦合: verification is deliberately narrower than generation. Instead of routinely reproducing the whole solution, a verifier receives a specific claim, its supporting evidence, and the applicable delivery constraint. Its task is to attack that claim by searching for counterexamples, triangulating with a genuinely independent source class, checking atomic details such as names, dates, numbers, and formulas, or testing compliance with format and specification requirements. Targeted verification questions are already known to reduce coupling between generation and checking(15);在这里，相同的原则也适用于现场代理团队。; here the same principle is applied inside a live agent team.

不对称在于任务，不一定在于模型大小。与从头开始生成报告相比，伪造已声明的声明、查找缺失的引文或检测合同违规行为需要更少的开放式综合。它还产生一个更具可操作性的信号：反馈列出了有争议的索赔、否定证据或失败的检查以及所需的维修。因此，主要代理人可以重新打开一个董事会项目，派遣有针对性的后续行动，并整合纠正措施，而不会允许自由形式的验证者叙述覆盖其他地方更有力的证据。The asymmetry is in the task, not necessarily in model size. Falsifying a stated claim, locating a missing citation, or detecting a contract violation demands less open-ended synthesis than generating the report from scratch. It also produces a more actionable signal: the feedback names the contested claim, the disconfirming evidence or failed check, and the required repair. The main agent can therefore reopen one board item, dispatch a focused follow-up, and integrate the correction without allowing a free-form verifier narrative to overwrite stronger evidence elsewhere.

3.2.4 自适应最大团队努力Adaptive Max Team Effort

测试时间缩放可以通过投入更多的推理计算来改善困难或模糊的结论，但统一缩放会浪费预算在已经解决的子问题上。自适应最大团队努力在团队层面应用了这一原则：主要代理人仅针对薄弱的、有争议的或承重的索赔分配额外的、独立范围的调查。该策略沿着真正不同的假设、方法、源类或查询框架展开；将后面的wave分配给未解决或未确认的分支；并需要重点验证后才能得出承重结论。由于每次返回后都会修改分配，因此缩放变量是有用的协调工作，而不是固定数量的代理或样本。这些行为在训练轨迹中表示，并在推理时通过代理团队执行合约激活。Test-time scaling can improve difficult or ambiguous conclusions by investing more inference compute, but uniform scaling wastes budget on subproblems that are already settled. Adaptive Max Team Effort applies this principle at the team level: the main agent assigns additional, independently scoped investigations only to weak, contested, or load-bearing claims. The policy fans out along genuinely different hypotheses, methods, source classes, or query framings; allocates later waves to unresolved or disconfirmed branches; and requires focused verification before a load-bearing conclusion is finalized. Because allocation is revised after each return, the scaling variable is useful coordinated work rather than a fixed number of agents or samples. These behaviors are represented in training trajectories and activated at inference time through the Agent Team execution contract.

3.2.5 循证综合Evidence-Grounded Synthesis

长期团队执行和最终综合提出了不同的要求。首席特工必须计划、调度、整合部分发现并对新证据做出反应，而最终的交付成果必须保留决定性的细节、出处、分歧和在许多轨迹中积累的未解决的不确定性。直接从首席特工的最终背景中压缩所有这些内容可能会丢失早期证据或将暂定的分支结果变成没有支持的结论。因此，Apodex 1.1 在团队执行和验证之后添加了专用的综合阶段。该阶段使用终端任务板、子代理报告、检索的证据、生成的工件和验证者的结果；它不会将主导代理的最后一条消息视为报告状态。Long-horizon team execution and final synthesis impose different demands. The lead agent must plan, dispatch, integrate partial findings, and react to new evidence, while the final deliverable must preserve decisive details, provenance, disagreement, and unresolved uncertainty accumulated across many trajectories. Apodex 1.1 therefore adds a dedicated synthesis stage after team execution and verification. 4.5 重型求解器Heavy-Duty Solver(HDS6)分析Analysis

结果分数确定任务是否完成；它们没有表明基础工作是否连贯、有根据或可恢复。因此，我们以以下方式结束评估Outcome scores establish whether a task was completed; they do not show whether the underlying work was coherent, grounded, or recoverable. We therefore close the evaluation withHDS6，一个与第节中介绍的工作能力目标一致的过程验证框架, a process-verification framework aligned with the working-capability objective introduced in Section1。 HDS6 评估六种流程能力：长期状态一致性、证据保真度、假设管理、边界和故障推理、工具使用和执行状态管理以及验证下的自我纠正。每个功能包含四个评分细则项目，总共产生 24 个项目，并在记录的轨迹上应用单独的完整性门。因此，该框架测试是否有可防御的执行过程支持成功交付，而不仅仅是看似合理的最终工件。. HDS6 evaluates six process capabilities: long-horizon state coherence, evidence fidelity, hypothesis management, boundary and failure reasoning, tool use and execution-state management, and self-correction under verification. Each capability contains four scored rubric items, producing 24 items in total, with a separate integrity gate applied to the recorded trajectory. The framework therefore tests whether a successful delivery is supported by a defensible execution process rather than only a plausible final artifact.

过程级判断协议。Process-level judging protocol.

跨多个同时活跃的智能体跨越数百步的轨迹太长，而且结构太不规则，单个前向传球无法针对所有 24 个评分项目可靠地评分。因此我们适应A trajectory spanning hundreds of steps across several concurrently active agents is too long, and too structurally irregular, for a single forward pass to score reliably against all 24 scored items. We therefore adaptHDS6为异步多智能体轨迹进行代理、流程级判断：工具调用、子代理调度和中间观察被拼接到单个有序日志中，然后通过角色专用映射、判断、审查和仲裁阶段进行处理。每个评分细则项都会收到一个 0/​​1/2 等级（失败、满足或超出合规性），并由可见执行日志的引用支持。评分是不考虑结果的，并且排除私人推理；每一个被引用的事件在支持判决之前都会根据记录的轨迹重新建立基础。 一个单一的完整性门位于标题之上：捏造的工具结果或从未发生过的叙述动作将整个轨迹彻底归零，绕过加权分数。into an agentic, process-level judge for asynchronous multi-agent trajectories: tool calls, subagent dispatches, and intermediate observations are stitched into a single ordered log, then processed by role-specialized mapping, judging, review, and arbitration stages. Each rubric item receives a 0/1/2 band (fails, meets, or exceeds compliance) supported by citations to the visible execution log. Grading is outcome-blind and excludes private reasoning; every cited event is re-grounded against the recorded trajectory before it can support a verdict. A single integrity gate sits above the rubric: a fabricated tool result or a narrated action that never occurred zeroes the entire trajectory outright, bypassing the weighted score.

5 相关工作Related Work

通用代理模型。General-purpose agentic models.

最近发布的前沿模型越来越多地将代理工作视为通用智能的核心表达，而不是特定于应用程序的层。 Kimi K3、GPT-5.6、Claude Fable 5、GLM-5.2 和 DeepSeek V4 将通用模型扩展到长上下文推理、编码、工具使用、信息搜索和持续任务执行的不同组合Recent frontier model releases increasingly treat agentic work as a core expression of general intelligence rather than an application-specific layer. Kimi K3, GPT-5.6, Claude Fable 5, GLM-5.2, and DeepSeek V4 extend general-purpose models toward different combinations of long-context reasoning, coding, tool use, information seeking, and sustained task execution(52; 39; 3; 71; 14)。尽管它们的架构、训练方法和运行时系统有所不同，但它们反映了从优化孤立响应到可以通过工具和环境在更长期范围内运行的模型的共同转变。 Apodex 1.1 遵循这个通用方向，但围绕两个明确的扩展表面组织其开发：环境扩展扩展了学习工作能力的可执行世界，而代理协调扩展扩展了跨代理、任务分支和时间组织该功能的方式。. Although their architectures, training recipes, and runtime systems differ, they reflect a shared transition from optimizing isolated responses toward models that can operate through tools and environments over longer horizons. Apodex 1.1 follows this general-purpose direction, but organizes its development around two explicit scaling surfaces: Environment Scaling expands the executable worlds in which working capability is learned, while Agentic Coordination Scaling expands how that capability is organized across agents, task branches, and time.

可执行的环境和实际工作。Executable environments and real work.

ReAct 建立了环境交互的推理-行动-观察循环ReAct establishes the reasoning–action–observation loop for environmental interaction(67)，而 Toolformer 研究模型如何学习何时以及如何调用外部 API, while Toolformer studies how models can learn when and how to invoke external APIs(48)。 WebArena 为长期网络代理提供可复制的网站和功能任务检查. WebArena provides reproducible websites and functional task checks for long-horizon web agents(75); WorkArena 和 BrowserGym 将基于环境的评估扩展到企业知识工作; WorkArena and BrowserGym extend environment-based evaluation to enterprise knowledge work(17); OSWorld 使用基于执行的评分器评估真实操作系统中的跨应用程序任务; and OSWorld evaluates cross-application tasks in real operating systems with execution-based graders(63)。在软件工程中，SWE-bench 根据存储库测试衡量问题解决情况. In software engineering, SWE-bench measures issue resolution against repository tests(25)，并且 SWE-agent 表明代理-计算机接口对存储库级别的性能有重大影响, and SWE-agent shows that the agent–computer interface materially affects repository-level performance(65)。 Terminal-Bench 将这个方向扩展到实际的命令行任务. Apodex’s File, Search, and Code environments follow the same execution-grounded principle but are used jointly for task synthesis, training, replay, and evaluation.

深度研究系统将推理与行动扩展到开放式信息搜索、证据协调和报告综合。产品体系包括OpenAI Deep Research、Claude Research、Kimi-Researcher、Grok DeepSearchDeep-research systems extend reasoning-and-acting to open-ended information seeking, evidence reconciliation, and report synthesis. Apodex combines three verification levels: environment checks over executable outcomes, artifact and provenance checks over the completed workspace, and Statement Review over consequential claims with an independent role and context.

6 结论Conclusion

Apodex 1.1 提出了复杂工作的代理智能的模型级视图：能力应该通过模型是否能够通过不断变化的任务维持进展、有效使用工具和证据、从失败中恢复并提供可验证的结果来衡量。我们沿着两个互补的扩展维度开发这种能力。环境扩展扩展了模型学习和操作的可执行文件、搜索和代码世界，而代理协调扩展扩展了跨代理和时间分解、委托、集成和重组工作的方式。通用的harness和AgentOS提供了两个维度所需的持久执行状态，统一的训练将环境和协调轨迹转换为更强大的工作策略。Apodex 1.1 advances a model-level view of agentic intelligence for complex work: capability should be measured by whether a model can sustain progress through a changing task, use tools and evidence effectively, recover from failure, and deliver a verifiable result. We develop this capability along two complementary scaling dimensions. Environment Scaling broadens the executable file, search, and code worlds in which the model learns and acts, while Agentic Coordination Scaling broadens how work is decomposed, delegated, integrated, and reorganized across agents and time. A common harness and AgentOS provide the persistent execution state required by both dimensions, and unified training converts environment and coordination trajectories into a stronger working policy.

评估是围绕同一目标设计的。科学研究、专业工作、数学、搜索、编码和内部长期评估的结果测试了底层模型的广度，而 ReAct 和 Agent Team 之间的比较则估计了在额外有组织的计算下经过训练的协调的系统级提升。 HDS6 分析和端到端案例进一步检查成功的输出是否得到连贯的工具使用、证据、修复、替代方案和可审查工件的支持。总而言之，这些评估将 Apodex 1.1 定位为一个通用模型和执行堆栈，而不是特定任务代理的集合，其功能涵盖不同形式的工作。The evaluation is designed around the same objective. Results across scientific research, professional work, mathematics, search, coding, and internal long-horizon evaluations test the breadth of the underlying model, while the comparison between ReAct and Agent Team estimates the system-level lift of trained coordination under additional organized computation. The HDS6 analysis and end-to-end cases further examine whether successful outputs are supported by coherent tool use, evidence, repair, alternatives, and reviewable artifacts. Taken together, these evaluations position Apodex 1.1 not as a collection of task-specific agents, but as a common model and execution stack whose capabilities compose across different forms of work.

This shows that the two scaling dimensions improve not only peak system performance, but also the capability obtained at a compact model scale.

我们的长期目标是Our longer-term goal is a重型求解器Heavy-Duty Solver：一个能够承担越来越雄心勃勃、长期运行和可验证工作的系统。实现这一目标的进展将来自于扩大可执行环境的覆盖范围和保真度，加强长期的学习协调，改进分层跟踪的培训和信用分配，以及关闭实际失败、任务构建、培训和评估之间的循环。 Apodex 1.1 建立了这条开发路径，并展示了如何围绕已完成的工作而不是孤立的响应来扩展代理智能。: a system capable of taking responsibility for increasingly ambitious, long-running, and verifiable work. 案例1Case 1为蛋白质模拟构建可运行的起点。对每个原子进行建模太慢了，因此标准举措是粗粒度——将原子组捆绑成单个珠子，这里有 3785 个珠子——这样可以以一小部分成本保持整体形状。从该模型中，运行必须生成告诉模拟引擎珠子如何相互作用的文件，一个在盐水中保存三个蛋白质副本的盒子，以及缓解尴尬接触的第一个计算：十八个互锁文件，如果一个盒子尺寸或颗粒计数与其他文件不一致，引擎将拒绝所有这些文件。builds a runnable starting point for a protein simulation. Modelling every atom is too slow, so the standard move is to coarse-grain—bundle groups of atoms into single beads, 3785 of them here—which keeps the overall shape at a fraction of the cost. From that model the run has to produce the files that tell a simulation engine how the beads interact, a box holding three copies of the protein in salt water, and a first calculation that relaxes the awkward contacts: eighteen interlocking files, and the engine rejects all of them if one box dimension or particle count disagrees with the rest.

In each of six microscope photographs, blue marks every nucleus and green marks the dying cells, so the greener an image is relative to its blue, the more death it shows.
