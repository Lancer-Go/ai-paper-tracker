摘要Abstract

大型语言模型 (LLM) 代理依靠可重用的技能来解决复杂的任务。然而，现有的技能创建方法将技能视为孤立的静态工件，限制了其可重用性、可靠性和长期改进。我们建议Large language model (LLM) agents rely on reusable skills to solve complex tasks. However, existing skill creation approaches treat skills as isolated and static artifacts, limiting their reusability, reliability, and long-term improvement. We proposeMUSE-Autoskill代理MUSE-Autoskill Agent (M埃默里-emory-U铺瓷砖tilizingS杀killEvolution），一个以技能为中心的代理框架，允许代理通过在统一的生命周期（创建、记忆、管理、评估和细化）下创建、重用和细化技能来不断提高其任务解决能力。我们的框架使代理能够按需创建技能，跨任务存储和重用它们，有效地组织和选择它们，并通过单元测试和运行时反馈来评估它们以进行持续改进。我们进一步引入了技能级别记忆，可以跨任务积累每种技能的经验，从而随着时间的推移实现更有效的重用和适应。 SkillsBench 上的实验提供了初步证据，表明生命周期管理的技能可以提高任务成功率、效率、重用和跨代理转移，强调将技能视为长期、体验感知和可测试资产的重要性。volution), a skill-centric agent framework that lets agents continuously improve their task-solving capability by creating, reusing, and refining skills under a unified lifecycle (creation, memory, management, evaluation, and refinement). Our framework enables agents to create skills on demand, store and reuse them across tasks, organize and select them efficiently, and evaluate them through unit tests and runtime feedback for continuous refinement. We further introduce skill-level memory that accumulates experience for each skill across tasks, enabling more effective reuse and adaptation over time. Experiments on SkillsBench provide initial evidence that lifecycle-managed skills can improve task success, efficiency, reuse, and cross-agent transfer, highlighting the importance of treating skills as long-lived, experience-aware, and testable assets.

随着任务变得越来越长，累积的短期上下文可能会超出模型的代币预算。现有补救措施涵盖令牌级提示压缩As tasks grow longer, the accumulated short-term context can exceed the model’s token budget. Existing remedies span token-level prompt compression[7]，基于注意力接收器的 KV 保留，用于流式推理, attention-sink-based KV retention for streaming inference[30]，以及针对一般LLM代理的操作系统风格的虚拟上下文管理, and OS-style virtual context management for general LLM agents[18];位置研究进一步记录了当相关内容被埋在长上下文中时的显着退化; positional studies further document significant degradation when relevant content is buried in the middle of a long context[12]，这促使我们在下面采用明确的第一个/最后一个固定。为了在代理级别处理此问题，MUSE 应用了两个级别的自适应上下文压缩。, which motivates the explicit first/last pinning we adopt below. To handle this at the agent level, MUSE applies adaptive context compression with two levels.1级Level-1（单节点压缩）扫描活动链中代币占用超过每个节点阈值（通常是大型工具输出或详细观察）的单个节点，并用紧凑摘要替换该节点的内容，同时将其保留在链中。如果在 Level-1 后总上下文仍然超出预算，(single-node compression) scans the active chain for individual nodes whose token footprint exceeds a per-node threshold (typically a large tool output or a verbose observation) and replaces that node’s content with a compact summary while keeping it in the chain. If the total context is still over budget after Level-1,2级Level-2（链压缩）将连续范围的中间节点合并为单个综合摘要节点，然后该节点取代活动链中的这些节点。我们总是首先尝试 Level-1，因为它是严格意义上破坏性较小的操作：仅重写有问题的节点的有效负载，而每回合边界和链的完整计划/操作/观察结构都被保留，因此下游回合仍然可以通过其原始位置引用较早的回合。 Level-2 将多个回合折叠为一个合成节点，并丢失每回合结构，因此仅当单节点摘要无法使链低于预算时，我们才调用它。在这两个级别中，原始节点都保留在完整历史记录中，因此活动链始终是可恢复的。相比之下，长期记忆和技能库是分开存储的，并且不受压缩，允许代理在多个会话中积累经验而不会丢失。(chain compression) merges a contiguous range of intermediate nodes into a single synthetic summary node, which then takes the place of those nodes in the active chain. We always try Level-1 first because it is the strictly less destructive operation: only the offending node’s payload is rewritten, while the per-turn boundaries and the full plan/action/observation structure of the chain are preserved, so downstream turns can still reference earlier turns by their original positions. Level-2 collapses several turns into one synthetic node and loses that per-turn structure, so we invoke it only when single-node summaries alone cannot bring the chain under budget. In both levels the original nodes remain in the full history, so the active chain is always recoverable. Long-term memory and the skill bank, by contrast, are stored separately and are not subject to compression, allowing the agent to accumulate experience across sessions without loss.

此外，代理的完整状态，包括对话历史记录、技能使用记录和执行元数据，都会在每次会话后作为快照保存。这允许任务从中间状态恢复，而无需从头开始，这对于可能跨越多个会话的复杂、长期工作流程至关重要。In addition, the agent’s full state, including conversation history, skill usage records, and execution metadata, is persisted as a snapshot after each session. This allows tasks to be resumed from an intermediate state without restarting from scratch, which is essential for complex, long-horizon workflows that may span multiple sessions.

技能质量审核Skill Quality Audit

我们手动检查 35 个生成的技能是否存在潜在的基准泄漏。这些技能都没有硬编码预期的验证器输出、任务标识符分支或从真实文件中读取。技能的子集包含特定于基准测试的假设，例如固定文件名、目录路径或从源运行派生的数字范围。这些并不构成作弊，但可能会限制对分布外输入的概括。清除此类假设是未来工作的明确方向，特别是在部署超出源基准的生成技能时。We manually inspect the 35 generated skills for potential benchmark leakage. None of the skills hardcode expected verifier outputs, branch on task identifiers, or read from ground-truth files. A subset of skills contain benchmark-specific assumptions such as fixed file names, directory paths, or numerical ranges derived from the source run. These do not constitute cheating but may limit generalization to out-of-distribution inputs. Cleaning such assumptions is a clear direction for future work, especially when deploying generated skills beyond the source benchmark.

By representing all functionality as structured skills, the agent reduces redundant reasoning and improves efficiency over time.
