ViHoRec：质量控制的越南酒店推荐数据集和冷启动基准ViHoRec: A Quality-Controlled Vietnamese Hotel Recommendation Dataset and Cold-Start Benchmark

Minh Hoang Nguyen
Faculty of Information Technology, University of Science, Ho Chi Minh City, Vietnam
Vietnam National University, Ho Chi Minh City, Vietnam
24C15049@student.hcmus.edu.vn
摘要Abstract

由于缺乏公共的、有据可查的酒店互动资源，越南人的推荐系统研究仍然受到限制。构建这样的资源具有挑战性，原因有以下三个：在交互具有可比性之前必须协调跨平台酒店名称；必须使用可重复的指标来审核质量，而不是临时清洁；公开发布必须保护隐私，同时在现实的冷启动条件下保持基准。我们介绍Recommender-system research for Vietnamese remains limited by the absence of a public, well-documented hotel interaction resource. Building such a resource is challenging for three reasons: cross-platform hotel names must be reconciled before interactions are comparable; quality must be audited with reproducible metrics rather than ad hoc cleaning; and public release must preserve privacy while remaining benchmarkable under realistic cold-start conditions. We introduce维霍记录ViHoRec是一个经过质量控制的越南酒店推荐数据集，包含 6,832 位用户和 560 家酒店之间的 18,267 次互动，爬取自 Booking.com、Traveloka 和 Ivivu。我们的贡献是：（i）具有跨平台实体解析和定量质量控制的可重复构建管道； (ii) 以 HMAC 假名发布的隐私保护版本； (iii) 公共冷启动基准，具有时间留后一分割、以数据为中心的消融和无依赖性基线。在公共分裂中，学习模型对于历史较短的用户急剧退化（BPR-MF Recall@10：0.065 vs. 0.120），而 UserKNN 总体上仍然最强，将 ViHoRec 建立为稀疏、冷启动主导的低资源推荐测试平台。所有数据均可公开获取, a quality-controlled Vietnamese hotel recommendation dataset of 18,267 interactions between 6,832 users and 560 hotels, crawled from Booking.com, Traveloka, and Ivivu. Our contributions are: (i) a reproducible construction pipeline with cross-platform entity resolution and quantitative quality control; (ii) a privacy-preserving release with HMAC pseudonyms; and (iii) a public cold-start benchmark with temporal leave-last-one-out split, data-centric ablations, and dependency-free baselines. On the public split, learned models degrade sharply for users with short histories (BPR-MF Recall@10: 0.065 vs. 0.120), while UserKNN remains strongest overall, establishing ViHoRec as a sparse, cold-start-dominated testbed for low-resource recommendation. All data are publicly available athttps://github.com/MinhNguyenDS/ViHoRec.

4 数据收集与构建Data Collection and Construction

4.1 数据收集Data collection

我们从越南三个信誉良好、高流量的预订平台收集数据。对于公开评论列表API的网站，我们调用该API以获取JSON数据；对于没有 API 的网站，我们发送标准 HTTP 请求并使用 BeautifulSoup 库从 HTML 中提取字段。酒店内容元数据（没有 API）是根据交互数据中出现的酒店列表半手动收集的。根据声誉和用户群规模选择平台。原始交互数据包含以下字段：客户名称、位置、酒店名称、评级和时间戳。We collect data from three reputable, high-traffic booking platforms in Vietnam. For sites that expose a review-listing API, we call the API to obtain data in JSON; for sites without an API, we send standard HTTP requests and extract fields from HTML using the BeautifulSoup library. Hotel content metadata (which has no API) is collected semi-manually based on the list of hotels appearing in the interaction data. Platforms were selected based on reputation and user-base size. The raw interaction data contains the fields: customer name, location, hotel name, rating, and timestamp.

4.2 规范化和酒店实体解析Normalization and hotel entity resolution

酒店可能会在各个网站上以不同的名称拼写出现（不同的变音符号、存在/不存在前缀，例如“Khách sạn”/“Hotel”/“Khu nghỉ dưỡng”、不同的词序、不同的标点符号）。朴素的精确字符串匹配会将此类变体视为不同的酒店并分割交互图。因此我们应用A hotel may appear under different name spellings across websites (differing diacritics, presence/absence of prefixes such as “Khách sạn”/“Hotel”/“Khu nghỉ dưỡng”, differing word order, differing punctuation). Naïve exact-string matching would treat such variants as distinct hotels and fragment the interaction graph. We therefore apply an实体解析entity-resolution步骤：每个名称都映射到一个规范键，该键无重音、小写、无标点符号，删除了特定于域的停用词（“khách sạn”、“hotel”、“resort”...），并且标记按词序独立排序。共享规范密钥的名称被合并为一个step: each name is mapped to a canonical key that is accent-free, lower-cased, punctuation-free, with domain-specific stopwords removed (“khách sạn”, “hotel”, “resort”…), and with tokens sorted to be word-order independent. Names sharing a canonical key are merged into a single酒店_idhotel_id。这个过程（节. This process (Section5）合并了 21 个名称变体，并识别了出现在多个平台上的 78 家酒店。) merges 21 name variants and identifies 78 hotels appearing on more than one platform.

4.3 基线模型的预处理Preprocessing for the baseline models

从清理后的交互表中，我们得出三个表：用户信息、酒店信息和评级历史。对于基于内容的推荐，对于至少有一条评论的每个用户，我们聚合他们所评论的酒店的四个属性组（设施、周边、邻近地区、价格）；文本被标准化（删除逗号、小写、标记化）并使用 Word2Vec 映射到向量空间，为用户和酒店生成四个特征向量。From the cleaned interaction table we derive three tables: user information, hotel information, and rating history. For content-based recommendation, for each user with at least one review we aggregate the four attribute groups (Facilities, Around, Vicinity, Price) of the hotels they have reviewed; the text is normalized (removing commas, lower-casing, tokenization) and mapped to a vector space with Word2Vec, yielding four feature vectors for the user and for the hotel.

8 使用说明、限制和结论Usage Notes, Limitations, and Conclusion

8.1 使用说明Usage notes

ViHoRec 适用于协同过滤、基于内容和混合推荐器的研究；冷启动研究；以及针对越南市场的稀疏数据、低资源语言环境下的推荐任务。用户应采用随附的公共分割进行公平比较，并可以利用内容元数据（设施、周围、附近、价格）进行特征利用模型；见附录ViHoRec is suitable for research on collaborative-filtering, content-based, and hybrid recommenders; cold-start research; and recommendation tasks under sparse-data, low-resource-language settings for the Vietnamese market. Users should adopt the accompanying public split for fair comparison, and can leverage the content metadata (Facilities, Around, Vicinity, Price) for feature-exploiting models; see AppendixB对于文件模式。for file schemas.

8.2 局限性Limitations

我们明确说明了透明度的限制。首先，与 MovieLens-100K 或 Amazon 相比，规模仍然很小（18,267 次交互），并且数据集相当稀疏（基准分割为 97.53%）。其次，由于爬行时的用户标识符是从值空间较小的名称字符串派生的（并且估算了一些缺失的名称），因此不同用户的数量和每个用户的交互只是近似的；共享缩写名称的不同个体可能会被合并（由于这个原因，手动验证的交互中有 13.0% 被标记）。第三，内容元数据覆盖了309家酒店（占基准项目集的52.9%），限制了基于内容的评估。第四，评分是综合评分，而不是多重标准。We state the limitations explicitly for transparency. First, the scale is still small (18,267 interactions) compared to MovieLens-100K or Amazon, and the dataset is fairly sparse (97.53% on the benchmark split). Second, because the user identifier at crawl time was derived from a name string with a small value space (and some missing names were imputed), the number of distinct users and the interactions per user are only approximate; distinct individuals sharing an abbreviated name may be merged (13.0% of manually validated interactions were flagged for this reason). Third, content metadata covers 309 hotels (52.9% of the benchmark item set), limiting content-based evaluation. Fourth, the ratings are aggregate scores, not multi-criteria.

8.3 未来的工作Future work

未来，数据集可以通过以下方式扩展：收集更多数据以增加规模并减少稀疏性；将内容元数据扩展到当前 309 家酒店之外；添加新属性（情感、完整评论文本、房间类型、图像）；加强用户层面的实体解析（不仅针对酒店）。In the future, the dataset can be extended by: collecting more data to increase scale and reduce sparsity; expanding content metadata beyond the current 309 hotels; adding new attributes (sentiment, full review text, room types, images); and strengthening entity resolution at the user level (not only for hotels).

8.4 结论Conclusion

我们引入 ViHoRec，一个质量控制的越南酒店推荐数据集，其主要贡献是We introduce ViHoRec, a quality-controlled Vietnamese hotel recommendation dataset whose central contribution is资源及其可复制的构建管道the resource together with its reproducible construction pipeline：跨平台实体解析、定量质量控制、隐私保护匿名化和公共冷启动基准。我们的分层评估表明，学习模型对于历史最短的用户来说失败最多，而邻域方法仍然最强——这种模式在饱和的英语语料库中很少出现。通过发布所有数据、代码和文档，ViHoRec 为酒店推荐提供了第一个可复制的越南资源，并为稀疏数据、低资源方法提供了真实的压力测试。: cross-platform entity resolution, quantitative quality control, privacy-preserving anonymization, and a public cold-start benchmark. Our stratified evaluation shows that learned models fail most on users with the shortest histories, while neighborhood methods remain strongest—a pattern that saturated English corpora rarely surface. By releasing all data, code, and documentation, ViHoRec provides the first reproducible Vietnamese resource for hotel recommendation and a realistic stress test for sparse-data, low-resource methods.
