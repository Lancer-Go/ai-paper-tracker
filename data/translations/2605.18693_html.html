3 技能生成基准SkillGenBench

SkillGenBench 评估法学硕士从复杂的源材料中提取可部署、可重复使用的技能并将其应用于下游任务的能力。与评估智能体端到端任务解决能力的基准不同SkillGenBench evaluates how well LLMs can distill deployable, reusable skills from complex source materials and apply them to downstream tasks. Unlike benchmarks that assess the end-to-end task solving of agents(Liu et al., 2024; Zhou et al., 2024; Jimenez et al., 2023; Merrill et al., 2026)，SkillGenBench将技能生成本身作为评估的首要对象。 Agent首先分析源材料并生成技能；然后，一个单独的执行器调用该技能来完成下游任务。通过将技能生成与执行分离，SkillGenBench 提供了更直接的衡量方法, SkillGenBench treats skill generation itself as the primary object of evaluation. The agent first analyzes the source materials and generates a skill; a separate executor then invokes that skill to complete downstream tasks. By decoupling skill generation from execution, SkillGenBench provides a more direct measure of程序到技能的蒸馏procedure-to-skill distillation，而不是将其与下游代理能力（例如任务解释、规划和工具使用）混为一谈。, rather than conflating it with downstream agentic capabilities such as task interpretation, planning, and tool use.

在实例层面，每个基准测试项都被打包为一个容器化环境，由五个组件组成：源材料、任务规范、技能接口、执行器和评估协议。At the instance level, each benchmark item is packaged as a containerized environment comprising five components: source materials, task specification, skill interface, executor, and evaluation protocol.

The two differ in how procedures are presented in the source materials and, accordingly, in what the model must extract.

基于存储库的实例。Repository-grounded instances.

源材料由代码存储库快照组成，包括目录结构、自述文件、配置文件、依赖脚本和环境约定。程序性知识很少被明确表述；相反，它隐含在代码组织、调用关系、入口脚本和运行时约束中。该模型必须从存储库中恢复这些潜在的工作流程，并将它们提炼成可重用的技能。The source materials consist of a code repository snapshot, including directory structures, README files, configuration files, dependency scripts, and environment conventions. Procedural knowledge is rarely stated explicitly; instead, it is implicit in code organization, call relations, entry scripts, and runtime constraints. The model must recover these latent workflows from the repository and distill them into a reusable skill.

基于文档的实例。Document-grounded instances.

源材料由密集的长文本组成，例如系统手册、API 规范和技术报告。与基于存储库的实例相比，程序知识是明确表达的，但分布在各个段落中，采用条件分支、参数规则、先决条件和有序步骤等形式。该模型必须将这些分散的约束集成到可以在下游任务中调用的单个技能中。The source materials consist of dense, long-form texts such as system manuals, API specifications, and technical reports. In contrast to repository-grounded instances, procedural knowledge is expressed explicitly but distributed across passages, taking forms such as conditional branches, parameter rules, prerequisites, and ordered steps. The model must integrate these scattered constraints into a single skill that can be invoked on downstream tasks.

3.4 评估协议Evaluation Protocol

SkillGenBench 通过下游行为评估生成的技能。执行者加载技能并尝试执行任务。如表所示SkillGenBench evaluates a generated skill by its downstream behavior. An executor loads the skill and attempts the task. As summarized in Table1，实例分为两种评估模式，, instances fall into two evaluation modes,基于执行的execution-based和and基于工件的artifact-based.

在技能生成过程中，模型可以访问源材料，并在任务条件设置中访问任务规范。测试用例、验证器内部结构、参考输出和保留任务永远不会暴露给模型。在执行过程中，所有生成的技能都在同一执行器下的容器化环境中运行。During skill generation, the model has access to the source materials and, in the task-conditioned setting, the task specification. Test cases, verifier internals, reference outputs, and held-out tasks are never exposed to the model. During execution, all generated skills are run in containerized environments under the same executor.

基于执行的评估。Execution-based evaluation.

提交的代码针对具有确定性预期输出的隐藏测试用例运行，类似于程序判断基准。当所需结果是可调用过程或可重用实现时，使用此模式。The submitted code is run against hidden test cases with deterministic expected outputs, analogous to program-judging benchmarks. This mode is used when the desired result is a callable procedure or reusable implementation.

基于工件的评估。Artifact-based evaluation.

首先执行提交的代码以生成工件，然后将其与参考输出进行比较。比较方法取决于输出模态，包括精确匹配、像素级相似性、语义相似性或当单个确定性指标无法捕获多个有效输出时的 LLM 判断。启发式预检查（例如，分辨率、持续时间、架构或文件格式）在比较之前过滤掉无效输出。此模式不假设唯一的真实实现，因为许多任务允许多个有效程序产生等效的输出。The submitted code is first executed to produce an artifact, which is then compared against a reference output. Comparison methods depend on the output modality, including exact matching, pixel-level similarity, semantic similarity, or an LLM judge when multiple valid outputs cannot be captured by a single deterministic metric. A heuristic pre-check (for example, resolution, duration, schema, or file format) filters out invalid outputs before comparison. This mode does not assume a unique ground-truth implementation, since many tasks admit multiple valid programs producing equivalent outputs.

这种分类法阐明了动态和静态结果为何存在差异的原因。代码回购失败很大程度上是由执行环境、资产和界面问题造成的，因此仅改进文本基础并不能保证成功。代码文档失败主要取决于模式和格式精度，其中显式接口契约和验证线索至关重要。相反，领域知识文档失败需要精确的数字、状态和规则编码，而粗略的程序覆盖只能微弱地捕获这些编码。This taxonomy clarifies why dynamic and static results diverge. Code Repo failures are largely driven by execution environment, asset, and interface issues, so improved textual grounding alone does not guarantee success. Code Doc failures mostly reduce to schema and format precision, where explicit interface contracts and verification cues are critical. Domain Knowledge Doc failures instead require precise numeric, state, and rule encoding, which is only weakly captured by coarse procedural coverage.

总的来说，结果支持四个结论。首先，技能生成应被评估为生成器-骨干-执行器管道，而不是孤立的提示配方。其次，主要困难在于源特定：存储库任务需要操作恢复，代码文档任务需要精确的接口合规性，领域文档需要精确的规则执行。第三，与任务无关的技能可以有所帮助，但前提是它们保留可转移的程序而不放弃特定于任务的约束。第四，工件诊断对于解释是必要的，但基于执行的 pass@3 仍然是衡量生成的技能是否真正有用的决定性衡量标准。Overall, the results support four conclusions. First, skill generation should be evaluated as a generator–backbone–executor pipeline rather than as an isolated prompting recipe. Second, the main difficulty is source-specific: repository tasks require operational recovery, code documentation tasks require exact interface compliance, and domain documents require precise rule execution. Third, task-agnostic skills can help, but only when they preserve transferable procedures without discarding task-specific constraints. Fourth, artifact diagnostics are necessary for explanation, but execution-based pass@3 remains the decisive measure of whether a generated skill is actually useful.

5 结论Conclusion

我们引入了 SkillGenBench，这是一个评估技能生成作为 LLM 代理系统中的一流问题的基准。通过将上游技能生成与下游执行分离，SkillGenBench 可以跨存储库和文档源对过程到技能蒸馏管道进行受控比较。We introduced SkillGenBench, a benchmark for evaluating skill generation as a first-class problem in LLM agent systems. By decoupling upstream skill generation from downstream execution, SkillGenBench enables controlled comparison of procedure-to-skill distillation pipelines across repository and document sources.

我们的实验表明，技能生成从根本上来说是一个管道级问题：性能不仅取决于生成方法，还取决于主干模型和源材料的性质。特别是，基于存储库的任务仍然比基于文档的任务更具挑战性，这凸显了从分布式代码工件中恢复隐式执行结构的难度。 更重要的是，我们发现规范和执行之间存在持续的差距。生成的技能通常捕获正确的结构组件，但无法将它们转化为满足严格验证约束的可执行程序。这种差距在需要精确接口对齐、状态处理和规则保真度的设置中尤其明显。Our experiments show that skill generation is fundamentally a pipeline-level problem: performance depends not only on the generation method, but also on the backbone model and the nature of the source material. In particular, repository-grounded tasks remain significantly more challenging than document-based ones, highlighting the difficulty of recovering implicit execution structure from distributed code artifacts. More importantly, we identify a persistent gap between specification and execution. Generated skills often capture the right structural components, yet fail to translate them into executable procedures that satisfy strict verification constraints. This gap is especially pronounced in settings that require precise interface alignment, state handling, and rule fidelity.

这些发现表明，提高技能生成需要超越表面层结构并解决执行层的正确性。因此，静态诊断和基于执行的评估起着互补的作用：前者解释技能包含的内容，而后者确定技能是否真正有效。These findings suggest that improving skill generation requires going beyond surface-level structure and addressing execution-level correctness. Static diagnostics and execution-based evaluation therefore play complementary roles: the former explains what a skill contains, while the latter determines whether it actually works.

SkillGenBench 为研究这一差距提供了基准和分析框架。我们希望它将鼓励未来的工作不仅关注生成技能，还要确保它们可执行、可靠并符合现实世界的程序限制。SkillGenBench provides both a benchmark and an analysis framework for studying this gap. We hope it will encourage future work to focus not only on generating skills, but on ensuring that they are executable, reliable, and aligned with real-world procedural constraints.

附录EAppendix E局限性Limitations

SkillGenBench 旨在作为技能生成管道的受控基准，但它并不涵盖客服人员技能的所有部署设置。首先，当前的动态执行结果涵盖六代主干，未来的版本应该为每个摘要行提供完全独立的原始运行目录。SkillGenBench is intended as a controlled benchmark for skill-generation pipelines, but it does not cover every deployment setting for agent skills. First, the current dynamic execution results cover six generation backbones, and future releases should ship fully self-contained raw run directories for every summary row.

其次，完全失败的分类法是诊断性的，而不是替代人类的判断。它结合了执行跟踪、生成的代码和任务元数据，以在共享机制下对已完成的验证者失败进行分类；这使得大规模分析成为可能，但单个故障可能涉及多个重叠的原因。Second, the completed-failure taxonomy is diagnostic rather than a substitute for human adjudication. It combines execution traces, generated code, and task metadata to classify completed verifier failures under shared mechanisms; this makes large-scale analysis possible, but individual failures can involve multiple overlapping causes.

第三，该基准测试侧重于确定性任务验证器和固定下游执行。这对于隔离技能生成很有用，但它不足以代表下游代理可以与用户协商、交互调用外部服务或在部署后修改技能的设置。第四，存储库和文档来源足够广泛，可以揭示不同的故障模式，但它们并不详尽。额外的域、更大的存储库、多存储库工作流程和更长的与任务无关的技能库设置将进一步测试生成的技能是否可以跨相关任务转移。最后，静态分数是基于规则的代理。它们对于解释观察到的故障很有用，但它们应该被解释为诊断而不是技能质量的内在衡量标准。Third, the benchmark focuses on deterministic task verifiers and fixed downstream execution. This is useful for isolating skill generation, but it under-represents settings where downstream agents can negotiate with users, call external services interactively, or revise skills after deployment. Fourth, the repository and document sources are broad enough to expose distinct failure modes, but they are not exhaustive. Additional domains, larger repositories, multi-repository workflows, and longer task-agnostic skill-library settings would further test whether generated skills transfer across related tasks. Finally, the static scores are rule-based proxies. They are useful for explaining observed failures, but they should be interpreted as diagnostics rather than intrinsic measures of skill quality.

更广泛的影响。Broader Impact.

这项工作引入了评估大型语言模型中技能生成的基准，这可以提高代理系统的可靠性。同时，增强的自动化功能可能会带来风险，例如误用生成的工作流程或降低执行复杂任务的障碍。仔细评估和监控对于减轻这些风险非常重要。This work introduces a benchmark for evaluating skill generation in large language models, which may improve the reliability of agent systems. At the same time, enhanced automation capabilities may introduce risks such as misuse of generated workflows or lowering the barrier to executing complex tasks. Careful evaluation and monitoring are important to mitigate these risks.
