摘要Abstract

计算机使用代理在 OSWorld 和 AndroidWorld 等基准方面取得了进步，但仍然主要通过 GUI 进行操作，通常会产生低效的轨迹。现实世界的计算机工作是混合的，将视觉状态检查与精确、高吞吐量的命令行操作相结合，因此有能力的代理必须在共享应用程序状态上协调这两种模式。然而，可扩展的混合环境仍然稀缺，因为在实际应用程序上同时支持 GUI 和 CLI 通常需要为每个应用程序进行大量的手动工程。现有的代理也很难互补地使用这两个界面：CLI 本机代理缺乏对涉及界面状态或布局的任务的视觉感知，而 GUI 本机代理对于通过命令更好地执行的操作效率低下。Computer-use agents have advanced on benchmarks like OSWorld and AndroidWorld, but still act mostly through the GUI, often producing inefficient trajectories. Real-world computer work is hybrid, combining visual-state inspection with precise, high-throughput command-line operations, so capable agents must coordinate both modalities over shared application state. Yet scalable hybrid environments remain scarce because supporting both GUI and CLI over real applications typically requires substantial manual engineering for each application. Existing agents also struggle to use the two interfaces complementarily: CLI-native agents lack visual perception for tasks involving interface state or layout, while GUI-native agents are inefficient for operations better executed through commands.

1 简介Introduction

计算机使用代理 (CUA) 发展迅速，在 OSWorld 和 AndroidWorld 等基准测试中完成了广泛的真实桌面和移动任务Computer-use agents (CUAs) have advanced rapidly, completing a broad range of real desktop and mobile tasks on benchmarks such as OSWorld and AndroidWorld(Xie et al. 2024; Rawles et al. 2025)。然而，领先的代理仍然主要通过图形用户界面 (GUI) 进行交互，导致轨迹通常过长. Yet leading agents still interact predominantly through the graphical user interface (GUI), resulting in trajectories that are often unnecessarily long(Abhyankar et al. 2025)并且在扩展工作流程上变得越来越脆弱and increasingly brittle on extended workflows(Yuan et al. 2026)。然而，真正的计算机使用本质上是多模式的：用户依靠 GUI 进行基于视觉的交互，同时使用命令行工具、脚本或 API 进行精确和高吞吐量的操作。因此，有能力的 CUA 应该在. Real computer use, however, is inherently multi-modal: users rely on the GUI for visually grounded interaction, while using command-line tools, scripts, or APIs for precise and high-throughput operations. Capable CUAs should therefore operate inGUI+CLI 混合环境hybrid GUI+CLI environments，动态选择最适合每个子任务的接口，同时维护跨模式的共享应用程序状态, dynamically choosing the interface best suited to each subtask while maintaining a shared application state across modalities(Song et al. 2025; Yang et al. 2025; Jia et al. 2025).

实现这种混合计算机使用代理面临两个耦合瓶颈：Realizing such hybrid computer-use agents faces two coupled bottlenecks:可扩展的现实环境scalable real-world environments和and跨模态编排cross-modality orchestration。在环境方面，以 GUI 为中心的环境构建成本高昂，并且通常需要大量的手动工程，而以 CLI 为中心的环境更容易自动化，但缺乏对可视布局和界面状态的访问。因此，构建在同一应用程序状态下支持两种模式的混合环境仍然昂贵且难以跨应用程序扩展。在代理方面，现有代理通常针对一种模式进行优化，并且很难互补地使用这两个接口。 CLI 本机代理通常缺乏视觉感知，因此诉诸于脆弱的脚本来执行依赖于界面状态或视觉布局的任务，而 GUI 本机代理对于单个命令可以完成的批量操作可能效率低下。因此，更深层次的挑战是. On the environment side, GUI-centric environments are costly to build and often require substantial manual engineering, while CLI-centric environments are easier to automate but lack access to visual layout and interface state. Building hybrid environments that support both modalities over the same application state therefore remains expensive and difficult to scale across applications. On the agent side, existing agents are typically optimized for one modality and struggle to use the two interfaces complementarily. CLI-native agents often lack visual perception and therefore resort to brittle scripts for tasks that depend on interface state or visual layout, while GUI-native agents can be inefficient for batch operations that a single command could complete. 5 结论Conclusion

我们提出 CUA-Universe 作为扩展计算机使用代理的不同方式的一步：扩展代理学习的环境和交互空间，而不是仅依赖于更大的模型或更多仅 GUI 的轨迹。通过将真实的桌面软件转变为共享状态的 GUI+CLI 环境，CUA-Universe 提供了可扩展的混合任务和轨迹源，不仅教会代理如何行动，还教会代理如何有效地编排互补接口。由此产生的 9B 模型表明，这种能力是可学习和可转移的，在 CUA-Verse 和 OSWorld 上取得了巨大的进步，并进一步推广到 OSWorld-MCP 看不见的工具接口。更广泛地说，我们的结果表明，混合环境构建可以成为训练计算机使用代理的新轴，其中每个附加应用程序都扩展了可用于学习的任务、工具和交互策略的空间。我们希望这能够将 CUA 的开发从收集越来越多的单一模态行为转向构建可扩展的环境，不断为更有能力、更高效和更通用的计算机使用代理生成更丰富的监督。We presented CUA-Universe as a step toward a different way of scaling computer-use agents: scaling the environments and interaction spaces from which agents learn, rather than relying only on larger models or more GUI-only trajectories. By turning real desktop software into shared-state GUI+CLI environments, CUA-Universe provides a scalable source of hybrid tasks and trajectories that teach agents not only how to act, but how to orchestrate complementary interfaces efficiently. The resulting 9B model shows that this capability is learnable and transferable, with strong gains on CUA-Verse and OSWorld and further generalization to the unseen tool interface of OSWorld-MCP. More broadly, our results suggest that hybrid environment construction can become a new axis for training computer-use agents, where each additional application expands the space of tasks, tools, and interaction strategies available for learning. We hope this shifts CUA development from collecting increasingly large amounts of single-modality behavior toward building scalable environments that continuously generate richer supervision for more capable, efficient, and general computer-use agents.

我们的研究留下了几个方向。首先，CUA-Universe 综合了单应用程序任务：每个任务都基于一个应用程序的共享 GUI+CLI 状态，这使我们能够构建可验证的环境并大规模引导高效的混合路径。跨应用程序工作流程（其中状态跨多个应用程序进行）是同一管道的自然扩展，而不是不同的设计，我们将它们留给未来的工作。其次，我们仅使用收获的轨迹进行监督微调，因此学习的策略受到其数据生成主干的限制；因为管道已经生成了每个任务的验证器，所以使用它们作为强化学习的奖励是超越老师的直接下一步。第三，任务成功与否由 VLM 判断进行评分，而不是按任务进行编程检查，这可能会引入标签噪声；附录中的法官-人类验证Our study leaves several directions open. First, CUA-Universe synthesizes single-application tasks: each task is grounded in one application’s shared GUI+CLI state, which is what lets us build verifiable environments and steer efficient hybrid paths at scale. Cross-application workflows, where state is carried across several applications, are a natural extension of the same pipeline rather than a different design, and we leave them to future work. Second, we use the harvested trajectories for supervised fine-tuning only, so the learned policy is bounded by its data-generation backbone; because the pipeline already produces per-task verifiers, using them as rewards for reinforcement learning is a direct next step toward surpassing the teacher. Third, task success is scored by a VLM judge rather than per-task programmatic checks, which may introduce label noise; the judge–human validation in AppendixF限制这个（bounds this (99.0%99.0\%接受精度，科恩acceptance precision, Cohen’sκ=0.94\kappa=0.94），并且我们通过保守的接受阈值以及让法官以 CLI 和出口文物证据为基础来进一步缓解它，但我们并没有消除它。最后，应用程序适应假设软件是开源的或可编写脚本的，足以公开命令行界面，并且我们的环境以桌面 Linux 为目标；编码代理驱动的构建原则上与这些选择无关，但扩展到闭源或非桌面平台仍然是开放的。), and we further mitigate it with a conservative acceptance threshold and by grounding the judge in CLI and exported-artifact evidence, but we do not eliminate it. Finally, application adaptation assumes software that is open-source or scriptable enough to expose a command-line surface, and our environments target desktop Linux; the coding-agent-driven construction is not tied to these choices in principle, but broadening to closed-source or non-desktop platforms remains open.
