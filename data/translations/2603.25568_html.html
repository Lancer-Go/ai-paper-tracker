LLM 对数据库来说是杀伤力大吗？：关于 SQL 有限性的研究Are LLMs Overkill for Databases?: A Study on the Finiteness of SQL

Yue Li, David Mimno, Unso Eun Seo Jo
Cornell University
{yl3865, mimno, unsojo}@cornell.edu Corresponding author.
摘要Abstract

借助代码生成法学硕士，将自然语言转换为 SQL 以进行数据检索变得更加容易。但是生成 SQL 代码有多难呢？虽然数据库的复杂性可能变得无限，但查询的复杂性却受到现实生活实用性和人类需求的限制。通过 376 个数据库的样本，我们表明 SQL 查询作为自然语言问题的翻译是有限的Translating natural language to SQL for data retrieval has become more accessible thanks to code generation LLMs. But how hard is it to generate SQL code? While databases can become unbounded in complexity, the complexity of queries is bounded by real life utility and human needs. With a sample of 376 databases, we show that SQL queries, as translations of natural language questions are finite in实用的practical复杂性。数据库表数量的增加和 SQL 查询复杂性的增加之间不存在明显的单调关系。在模板形式中，SQL 查询遵循类似幂律的频率分布，其中 70% 的测试查询可以用所有模板类型的 13% 覆盖，这表明绝大多数 SQL 查询是可预测的。这表明，虽然用于代码生成的法学硕士可能很有用，但在数据库访问领域，它们可能在一个狭窄的、高度公式化的空间中运行，其中模板可能更安全、更便宜且可审计。complexity. There is no clear monotonic relationship between increases in database table count and increases in complexity of SQL queries. In their template forms, SQL queries follow a Power Law-like distribution of frequency where 70% of our tested queries can be covered with just 13% of all template types, indicating that the high majority of SQL queries are predictable. This suggests that while LLMs for code generation can be useful, in the domain of database access, they may be operating in a narrow, highly formulaic space where templates could be safer, cheaper, and auditable.

(2025)。 例如，在首要的 BIRD 文本到 SQL 基准测试中，公共网站上几乎所有排名靠前的方法都是基于代理的. For instance, on the premier BIRD text-to-SQL benchmark, almost all of the top ranking methods on the public site are either agent-basedPourreza and Rafiei (2024)或基于法学硕士or LLM-basedLongShine AI Research (2025)。 虽然这些方法很有效，但它们可能会变得昂贵，每次查询的令牌计数会花费数美元，并且可能不可靠，而企业数据库查询对效率和安全性高度敏感。 该代码在多大程度上是样板、可预测或可模板化的？ 在这项工作中，我们探讨了 SQL 应用程序是否真的需要完整的代码生成。. While these approaches are effective, they can get expensive, costing several dollars in token-count per query, and potentially unreliable, whereas enterprise database queries are highly sensitive to efficiency and security. To what extent is this code boilerplate, predictable, or templatizable? In this work, we probe whether full code generation is really necessary for SQL applications.

Using counts of proxies for complexity such as JOIN clause count, subclause count, and length of query, we show that there is no monotonic relationship between increase in table count of databases and increase in proxy count. We observe there is a “ceiling” of proxy-based complexity in SQL queries regardless of the complexity and size of the database schema design.

We find that the top 13% of templates account for 90% of all queries: only 7 templates cover 10%, and about 40 cover 30%. High-frequency templates tend to be less complex (e.g., fewer JOINs), suggesting that relatively simple structures suffice to cover most user questions. Overall, a few hundred templates are sufficient to capture the vast majority of database queries.

2 相关工作Related Work

长期以来，文本到 SQL 一直被研究为使用深度学习模型的语义解析任务Text-to-SQL has long been studied as a semantic parsing task using deep learning modelsZhong et al. (2017); Xu et al. Recent advances in LLMs have shifted this paradigm, with state-of-the-art systems adopting LLM-driven pipelines with iterative reasoning, self-correction, and agent-based workflowsPourreza and Rafiei (2023).

虽然基于 LLM 的 SQL 生成显着提高了准确性，但对实证研究的工作有限While LLM-based SQL generation has significantly improved accuracy, limited work has examined the empirical科学science的数据库查询。据我们所知，这是第一个探索 SQL 查询边界的工作，得益于最近出现的大规模、高质量 AI 生成的 SQL 数据，这些数据允许对查询模式和用户意图进行系统分析。of database queries. To our knowledge, this is the first work to explore the boundaries of SQL queries, enabled by the recent availability of large-scale, high-quality AI-generated SQL data that allows systematic analysis of query patterns and user intents.

类型 1：硬模板。Type 1: Hard Templates.

我们通过抽象数据集特定来构建硬 SQL 模板 来自 SQL 查询的标识符和文字，同时保留其结构和逻辑形式。此过程将查询规范化为代表底层 SQL 模式的规范模板。硬模板具有更严格、更详细的提取规则，可将 SQL 查询转换为 SQL 模板。我们将表、列和别名等实体类型保留为占位符。附录We construct hard SQL templates by abstracting dataset-specific identifiers and literals from SQL queries while preserving their structural and logical forms. This process normalizes queries into canonical templates that represent the underlying SQL pattern. Hard templates have stricter and more detailed extraction rules to transform SQL queries into SQL templates. We keep entity types such as table, column, and alias names as placeholders. 5 结论Conclusion

关系数据库和其他数据库是人类理解和计算效率之间的数据存储和组织的中间基础。 SQL 于 20 世纪 70 年代提出，作为弥合人类自然语言和计算机执行之间差距的一种方法。法学硕士以其看似神奇的代码生成功能成为了这一层的附加层。但我们的实验表明，SQL 领域的 LLM 代码生成可能并不那么令人印象深刻，因为它们在复杂性的上限下运行，其中仅几百个模板就涵盖了绝大多数查询案例。Relational and other databases are the middle ground of data storage and organization between human understanding and computational efficiency. SQL was proposed in the 1970s as a way to bridge the gap between human natural language and computer execution. LLMs have emerged as the additional layer over this with its seemingly magical code generation capabilities. But our experiments show LLMs code generation in the SQL domain may not be as impressive as they operate under a ceiling of complexity where just a few hundred templates cover the vast majority of query cases.

局限性Limitations

基于模板的分析的局限性之一是 SQL 查询没有规范形式，并且许多不同的查询可以是同构的。换句话说，可以生成看起来完全不同的代码，因此具有不同的模板，但检索相同的“答案”或表格结果。我们尝试了使生成的查询的整体风格同质化的方法，以测试最大化模板频率的不同级别，但最终决定以最纯粹的、已发现的形式测试查询（以及生成的模板）。One limitation of template-based analysis is that SQL queries do not have canonical forms and many different queries can be isomorphic. In other words, it is possible to generate code that looks completely different, and therefore have different templates, but retrieve the same “answer” or table result. We experimented with ways of homogenizing the overall style of generated queries to test different levels of maximizing template frequency, but ultimately decided that we wanted to test the queries (and resulting templates) in the most unadulterated, as-found forms.
