2.2
表提取评估指标
根据真实情况评估提取的表需要共同的指标
评估结构保真度和内容正确性。有向邻接关系
(DAR) [7]，在 ICDAR 2013 表竞赛中作为第一个指标引入
专为表结构评估而设计，捕获本地单元邻居
引擎盖但不能代表全局表结构，激发树级
以及随后的网格级方法。
树编辑基于距离的相似性 (TEDS)。 TEDS [46]，介绍
与 PubTabNet 一起，已成为表格识别的事实上的标准
评价。预测表和真实表均以 HTML 形式表示
叶节点 () 带有 colspan、rowspan 和字符级 tok- 的树
en化的内容。树编辑距离是用结构的单位成本计算的
细胞内容的自然不匹配和归一化 Levenshtein 距离，产生
TEDS = 1 −d / max(|Tpred|, |Tgt|)，其中 d 是编辑距离，|T|的
每棵树中的节点数。由于结构和内容都进行了比较
在字符级别，分数对标记选择敏感（例如， 与
或 与 ）和表面级字符串差异。

方法论
我们的基准测试方法基于两个关键的设计决策：(1) 使用真实的
从 arXiv 中提取的表格以确保现实的多样性，以及 (2) 嵌入它们
转化为综合生成的 PDF 以获得准确的地面事实，无需手动操作
注释。本节描述了由此产生的基准构建和
将解析器输出与地面真值表对齐的匹配管道。

4.1
基于规则的指标的局限性
由于 TEDS、GriTS 和 SCORE 比较结构和内容纯粹是同步的
从战术上讲，他们无法区分改变语义的差异
表格的内容和那些仅仅具有代表性的内容。图2说明
这是一个构建的示例，突出了我们经常使用的差异模式
在解析器输出中观察到。几种差异类型在语义上无关紧要
但会产生较大的编辑距离：
– 结构重组：解析器扁平化多层标题或解析行-
跨度——通常是因为输出格式缺乏对跨度单元格的支持（例如，
Markdown 与 HTML 不同，没有 colspan/rowspan 机制），导致
解决方法，例如重复值或插入空填充单元格。
– 符号编码：公式显示为 Unicode 符号而不是 LaTeX
命令（例如，用 α 代替 $\alpha$）。
– 等效值：“85.0%”与“85%”或“—”与“N/A”。
– 标记工件：视觉属性被编码为原始命令（例如，
\textbf{})。
相比之下，唯一的语义关键差异、内容错误，例如
丢失的小数点 (1.12 →112) 和翻转的符号 (+2.8 →−2.8)，只需更改
每个字符一个字符，对编辑距离的贡献最小。基于字符串
因此，由无害的代表性变量驱动的指标分配低分
化，而从根本上改变表格含义的几个字符错误
几乎没有反映出来。

能够或者几乎无法使用。性能最好的系统是 Gemini 3 型号，

这表明广泛的视觉语言能力可以很好地转移到表格提取中

专有 API 服务与应用程序自托管管道之间的差距
