1 简介Introduction

工具的使用正在成为大型语言模型（LLM）代理的定义能力。 强大的系统必须决定何时需要外部工具，在工具模式中进行地面调用，从冗长且嘈杂的上下文中提取参数，将多个工具组合到工作流程中，并在信息不完整时进行恢复。 这些行为现在在函数调用、API 编排、交互式代理基准测试和新兴模型上下文协议 (MCP) 生态系统中都很重要Tool use is becoming a defining capability of large language model (LLM) agents. Strong systems must decide when external tools are needed, ground calls in tool schema, extract arguments from long and noisy context, compose multiple tools into workflows, and recover when information is incomplete. These behaviors now matter across function calling, API orchestration, interactive agent benchmarks, and emerging Model Context Protocol (MCP) ecosystems(21; 13; 17; 14).

然而，工具使用方面的最新进展来自后期培训。 针对策划跟踪的监督微调 (SFT) 和强化学习 (RL) 显着改善了函数调用和代理行为Most recent progress on tool use, however, has come from post-training. Supervised fine-tuning (SFT) and reinforcement learning (RL) on curated traces have substantially improved function calling and agent behavior(23; 12; 19; 33)，但也给后期培训带来了沉重的负担。 该模型必须同时从相对狭窄的监督中获得一组原子代理能力，包括工具识别、基于模式的论证构建、缺失信息下的澄清以及多步骤执行。 更根本的是，成功使用工具的知识不仅仅存在于明确的轨迹中。 它分布在开发人员文档、手册、PDF、代码存储库、API 规范和结构化工具定义中，其中大多数从未以干净代理演示的形式出现, but they also place a heavy burden on post-training. The model must simultaneously acquire a set of atomic agentic capabilities, including tool recognition, schema-grounded argument construction, clarification under missing information, and multi-step execution, from comparatively narrow supervision. More fundamentally, the knowledge that underlies successful tool use does not live only in explicit trajectories. It is distributed across developer documentation, manuals, PDFs, code repositories, API specifications, and structured tool definitions, most of which never appear as clean agent demonstrations(20; 13; 33).

这就提出了一个自然的问题：This raises a natural question:是否可以通过专门的中期培训来更早地塑造一般工具使用能力，而不是几乎完全留给培训后？can general tool-use ability be shaped earlier through dedicated mid-training, rather than being left almost entirely to post-training?训练中期是多阶段预训练的一个独特阶段，弥合了一般预训练和训练后之间的差距 阶段Mid-training is a distinct stage of multi-stage pre-training, bridging the gap between general pre-training and post-training stages(27)。 最近的研究表明，有针对性的中期训练可以显着提高推理密集型能力. Recent work has shown that targeted mid-training can materially improve reasoning-intensive capabilities(28; 25)，新兴的努力已经开始探索用于深度研究的代理中期训练, and emerging efforts have begun to explore agentic mid-training for deep research(24; 26), 编码, coding(37; 36; 32)和软件工程（SWE）, and software engineering (SWE)(34; 38)。 然而，作为中期培训目标，一般工具的使用仍未得到充分探索。 与数学或 SWE 任务相比，工具使用数据需要覆盖更广泛、更异构的能力面，包括自然语言文档、可执行代码模式、结构化模式、多工具工作流程以及因信息缺失而导致的失败案例。. Yet general tool use remains underexplored as a mid-training target. Compared with math or SWE tasks, tool use data requires covering a broader and more heterogeneous capability surface, including natural-language documentation, executable code patterns, structured schemas, multi-tool workflows, and failure cases caused by missing information.

2 中间工具MidTool：用于代理中间训练数据合成的可扩展管道: Scalable Pipeline for Agentic Mid-training Data Synthesizing

在本节中，我们将介绍构建大规模中期训练语料库的流程，包括数据源收集、数据预处理和代理轨迹合成阶段。In this section, we present our pipeline to construct the large-scale mid-training corpus, including data source collection, data preprocessing and agentic trajectory synthesis stages.

2.1 第一阶段：数据源收集Stage 1: Data Source Collection

如图所示As illustrated in Figure2，我们的数据收集阶段旨在涵盖代理工具使用所需的补充信号。有效的工具使用行为不仅取决于明确的轨迹，还取决于广泛的技术知识、面向工具的文档、可执行代码模式和基础工具模式。因此，我们收集了四个源系列：Web 文档、PDF、代码存储库和结构化工具工件。, our data collection stage is designed to cover the complementary signals required for agentic tool use. Effective tool-use behavior depends not only on explicit trajectories, but also on broad technical knowledge, tool-facing documentation, executable code patterns, and grounded tool schemas. We therefore collect four source families: web documents, PDFs, code repositories, and structured tool artifacts.

网络数据。Web data.我们使用来自 FineWeb 的已处理 Common Crawl 转储We use processed Common Crawl dumps from FineWeb(18)作为主要的大型网络资源。我们对 2020 年至 2025 年的多个转储进行了采样，以捕获最新的技术内容，包括 API 参考、开发人员文档、故障排除页面、教程和 CLI 风格的说明。相对于后来的轨迹合成，网络语料库大规模地提供了与工具相关的概念、术语和工作流程描述的广泛覆盖。as the primary large-scale web source. We sample multiple dumps spanning 2020 to 2025 to capture recent technical content, including API references, developer documentation, troubleshooting pages, tutorials, and CLI-style instructions. Relative to later trajectory synthesis, the web corpus provides broad coverage of tool-related concepts, terminology, and workflow descriptions at scale.

PDF 数据。PDF data.许多高价值的工具使用资源，例如手册、产品手册和平台文档，都以 PDF 形式分发，而不是以干净的 HTML 页面形式分发。因此我们使用 FinePDFMany high-value tool-use resources, such as manuals, product handbooks, and platform documentation, are distributed as PDFs rather than clean HTML pages. We therefore use FinePDFs(8)作为补充抓取源并仅保留英语子集。与网页相比，PDF 提供了标准 Web 快照中通常缺少的较长形式的程序内容和文档，但它们也需要更严格的下游过滤，因为提取噪声要高得多。as a complementary crawl source and keep only the English subset. Compared with web pages, PDFs contribute longer-form procedural content and documentation that is often absent from standard web snapshots, but they also require stricter downstream filtering because extraction noise is substantially higher.

代码数据。Code data.工具的使用与软件工件紧密耦合，因此我们从两个互补的 GitHub 片段收集存储库数据。我们从 Snowflake GH Archive 事件数据初始化存储库发现Tool use is tightly coupled with software artifacts, so we collect repository data from two complementary GitHub slices. We initialize repository discovery from Snowflake GH Archive event data(4)，然后应用特定于任务的过滤。第一个切片的目标是从 GitHub 事件数据获取的与代理相关和 MCP 相关的存储库，并过滤新近度、活动和选择性许可。该切片捕获了具体的工具接口、编排模式和新兴代理工程实践。第二部分针对具有强大社区信号和主要编程生态系统（例如 Python、Java、JavaScript、TypeScript、Go、Rust、C/C++、C#、SQL、Shell 和 Dockerfile）中近期活动的高质量公共存储库。我们进一步保留可能包含有用的库、SDK、框架、示例或教育技术内容的存储库，同时删除会增加噪音或泄漏风险的个人项目、分叉以及基准或数据集存储库。特别是，我们在数据收集期间通过主动维护的黑名单明确从 GitHub 代码片中排除已知的基准测试和评估存储库；附录中提供了更多详细信息, then apply task-specific filtering. The first slice targets agent-related and MCP-related repositories obtained from GitHub event data, with filtering for recency, activity, and selective licensing. This slice captures concrete tool interfaces, orchestration patterns, and emerging agent engineering practice. The second slice targets high-quality public repositories with strong community signals and recent activity in major programming ecosystems such as Python, Java, JavaScript, TypeScript, Go, Rust, C/C++, C#, SQL, Shell, and Dockerfile. We further retain repositories that are likely to contain useful libraries, SDKs, frameworks, examples, or educational technical content, while removing personal projects, forks, and benchmark or dataset repositories that would add noise or leakage risk. In particular, we explicitly exclude known benchmark and evaluation repositories from the GitHub code slice through an actively maintained blacklist during data collection; more details are provided in AppendixA.1.

刀具数据。Tool data.最后，我们单独收集结构化工具工件，包括 REST API 和 MCP 技能，以支持本机代理轨迹合成。与 Web、PDF 和代码源不同，这些工件直接公开可执行模式、参数结构和工具边界。因此，它们为构建基础工具调用、多工具计划和后期综合阶段的恢复行为提供了最可靠的基础。Finally, we separately collect structured tool artifacts, including REST APIs and MCP skills, to support native agentic trajectory synthesis. Unlike web, PDF, and code sources, these artifacts expose executable schemas, parameter structures, and tool boundaries directly. They therefore provide the most faithful substrate for constructing grounded tool calls, multi-tool plans, and recovery behaviors in the later synthesis stage.

总的来说，这四个源家族有意在广度和结构之间进行权衡。 Web 和 PDF 数据提供广泛的技术背景，代码存储库提供可执行模式和开发人员工作流程，工具工件提供显式模式和可调用接口。随后的预处理和合成阶段将这种异构原始语料库转换为统一的训练混合物，用于代理中期训练。Taken together, these four source families intentionally trade off breadth and structure. Web and PDF data provide broad technical context, code repositories contribute executable patterns and developer workflows, and tool artifacts supply explicit schemas and callable interfaces. The subsequent preprocessing and synthesis stages convert this heterogeneous raw corpus into a unified training mixture for agentic mid-training.

2.2 第二阶段：数据预处理Stage 2: Data Preprocessing

代码。Code.正在关注Following9和and30，我们应用多阶段过滤来构建高值子集以进行有效训练。我们采用基于扩展名的过滤列表来排除二进制数据、模型权重和日志等文件。然后我们采用 StarCoder 的启发法, we apply multi-phase filtering to construct a high-value subset for effective training. We adapt the extension-based filtering list to exclude files such as binary data, model weights, and logs. We then adapt the heuristics from StarCoder(9)用于基于内容的过滤，包括行数、平均行长度、最大行长度和 Alpha 比率。我们还将 Jupyter Notebook 文件转换为 Python 文本文件。对于重复数据删除，我们通过对规范化文本进行 SHA-256 哈希来删除精确的重复项，并使用 MinHash LSH 删除近似重复项。对于公认的高质量存储库，我们应用一个过滤器，仅匹配类似文档的目录，例如文档、示例、教程、指南、示例和说明书。for content-based filtering, including line count, average line length, maximum line length, and alpha ratio. We also convert Jupyter Notebook files to Python text files. For deduplication, we remove exact duplicates by SHA-256 hashing over normalized text, and we remove near-duplicates with MinHash LSH. For accepted high-quality repositories, we apply a filter that matches only documentation-like directories such as docs, examples, tutorials, guides, samples, and cookbook.

Web 和 PDF 数据。Web and PDF data.对于 Web 和 PDF 中间训练源，我们使用四阶段管道：高召回率关键字/URL 预筛选、轻量级 fastTextFor web and PDF midtraining sources, we use a four-phase pipeline: high-recall keyword/URL prescreening, a lightweight fastText(7)分类器经过 LLM 标记的种子数据、文档级质量过滤和 MinHash LSH 重复数据删除的训练。该管道旨在保留面向开发人员的文档和技术参考材料，同时抑制通用网络噪声和 PDF 提取伪影，并对 PDF 具有更严格的阈值。完整的详细信息在附录中提供classifier trained on LLM-labeled seed data, document-level quality filtering, and MinHash LSH deduplication. The pipeline is designed to retain developer-oriented documentation and technical reference material while suppressing generic web noise and PDF extraction artifacts, with stricter thresholds for PDFs. 共同设计培训中和培训后。Co-designing mid-training and post-training.

我们的实验故意固定下游配方，以便可以隔离训练中期语料库的影响，并且我们的计算预算不允许我们也扫描研究训练后轴。因此，这两个阶段之间的关系在很大程度上尚未被探索，我们相信这是最有希望的下一步：SFT 语料库的组成如何与训练中期的混合物相互作用，更强或更大的训练后监督是否替代或与工具使用先验的复合，以及 RL 环境和奖励设计的选择如何改变先验的价值。每一个都值得单独消融，我们将它们视为中期培训研究的核心问题，而不是本研究的细节。Our experiments deliberately hold the downstream recipe fixed so that the effect of the mid-training corpus can be isolated, and our compute budget did not allow us to also sweep study the post-training axis. The relationship between the two stages is therefore largely unexplored, and we believe it is the most promising next step: how the composition of the SFT corpus interacts with the mid-training mixture, whether stronger or larger post-training supervision substitutes for or compounds with a tool-use prior, and how the choice of RL environments and reward design shifts what the prior is worth. Each of these deserves its own ablation, and we regard them as core questions for mid-training research rather than as details of the present study.

The last of these is a substantial undertaking on its own, since it requires executable tool environments, interaction generation, and validation at the scale of tens of billions of tokens, and we see it as an interesting systems-and-data challenge in its own right.

减少对优秀教师的依赖。Reducing dependence on strong teachers.

As open-weight agentic models continue to improve, the same pipeline can be instantiated with progressively smaller or self-generated teachers, and the point at which a model can usefully synthesize its own tool-use mid-training data becomes an informative measure of agentic maturity. We expect this question to be most meaningful at larger student scales, where self-generation is diverse and reliable enough to sustain the pipeline’s validation requirements.

超越一般工具的使用。Beyond general tool use.

最后，我们的结果找到了一个边界而不是上限：一般工具使用先验广泛地跨越不熟悉的模式和 MCP 领域，而大量搜索和其他探索行为似乎需要它们自己的监督。将中期训练视图扩展到深度搜索、软件工程和垂直代理工作流程，并了解它们之间共享哪些先验，是我们希望这项工作能够帮助开启的更广泛的议程。Finally, our results locate a boundary rather than a ceiling: a general tool-use prior transfers broadly across unfamiliar schemas and MCP domains, while search-heavy and other exploratory behaviors appear to require their own supervision. Extending the mid-training view to deep search, software engineering, and vertical agentic workflows, and understanding which priors are shared across them, is the broader agenda we hope this work helps open.
