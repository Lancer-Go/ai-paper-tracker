基于 LLM 的恶意软件分类的多视图反编译Multi-View Decompilation for LLM-Based Malware Classification

Bercan Efe Independent Researcher befeturkmen@gmail.com Vyas Raina SPARK vyas@sparkairesearch.com github.com/B3f3/Compiled-C-Malware
摘要Abstract

当源代码不可用时，恶意软件分析人员经常通过反编译的伪 C 检查编译的二进制文件。最近的研究表明，大型语言模型 (LLM) 可以通过将反编译代码分类为良性或恶意来协助此过程，但现有管道通常依赖于单个反编译器视图。我们认为这种假设是脆弱的：反编译器是有损启发式工具，不同的反编译器可以暴露同一二进制文件的不同产物。我们策划了涵盖一系列威胁行为的良性实用程序和恶意程序的基准。每个样本都使用 Ghidra 和 RetDec 进行编译和反编译，产生匹配的伪 C 视图。在来自主要模型系列的一系列法学硕士中，我们发现提供两种反编译器视图可以提高恶意类Malware analysts often inspect compiled binaries through decompiled pseudo-C, when source code is unavailable. Recent work suggests that large language models (LLMs) can assist this process by classifying decompiled code as benign or malicious, but existing pipelines typically rely on a single decompiler view. We argue that this assumption is fragile: decompilers are lossy heuristic tools, and different decompilers can expose different artefacts of the same binary. We curate a benchmark of benign utilities and malicious programs spanning a range of threat behaviors. Each sample is compiled and decompiled with both Ghidra and RetDec, yielding matched pseudo-C views. Across a range of LLMs from major model families, we find that providing both decompiler views improves malicious-classF1F_{1}，主要是通过增加对恶意样本的召回率。一致性分析进一步表明，Ghidra 和 RetDec 犯了部分不同的错误，支持反编译器输出提供补充证据的观点。我们的结果表明，多反编译器提示是一种简单、无需培训的方法，可以在实际环境中改进基于 LLM 的恶意软件分类。, mainly by increasing recall on malicious samples. Agreement analyses further show that Ghidra and RetDec make partially different errors, supporting the view that decompiler outputs provide complementary evidence. Our results suggest that multi-decompiler prompting is a simple, training-free way to improve LLM-based malware triage in practical settings.

1 简介Introduction

软件通常作为编译的二进制文件而不是源代码分发 代码。这在商业软件、游戏、安全工具中很常见， 和企业应用程序，其中保留源代码以保护 知识产权或简化部署。然而，二进制文件也是 更难审计：程序可能看起来提供良性功能 同时还包含凭证盗窃等恶意行为， 进程注入、文件加密或命令和控制通信。 按照恶意软件分类团队所面临的规模，手动检查每个 可疑的二进制文件是不可行的。Software is often distributed as compiled binaries rather than source code. This is common across commercial software, games, security tools, and enterprise applications, where source code is withheld to protect intellectual property or simplify deployment. However, binaries are also harder to audit: a program may appear to provide benign functionality while also containing malicious behavior such as credential theft, process injection, file encryption, or command-and-control communication. At the scale faced by malware triage teams, manually inspecting every suspicious binary is infeasible.

Reverse engineers then inspect this decompiled pseudo-code to reason about the program’s behavior and decide whether it is benign or malicious. Although this workflow is standard, the inspection stage remains a costly human bottleneck: it requires specialist expertise, is time-consuming, and does not scale easily. 大语言模型 (LLM) 的代码理解能力使得 他们是自动化部分检查过程的自然候选者The code-understanding capabilities of large language models (LLMs) make them a natural candidate for automating part of this inspection process(Zhang et al., 2025; Xu et al., 2024)。 最近的工作表明法学硕士可以解释反编译的代码和推理 关于程序行为. Recent work suggests that LLMs can interpret decompiled code and reason about program behavior(Pordanesh and Tan, 2024; Fang et al., 2024; Manuel et al., 2024)。一个 因此，简单的管道是反编译二进制文件，传递 向 LLM 发送伪代码，并要求模型将样本分类为良性 或恶意的。这样的系统可以支持首次分类，减少 分析人员的工作量，并显示可疑样本以供人工审查。. A straightforward pipeline is therefore to decompile a binary, pass the pseudo-code to an LLM, and ask the model to classify the sample as benign or malicious. Such a system could support first-pass triage, reduce analyst workload, and surface suspicious samples for human review.

然而，大多数基于 LLM 的反编译管道依赖于单个 反编译器，通常将其输出视为规范表示 该计划However, most LLM-based decompilation pipelines rely on a single decompiler, often treating its output as the canonical representation of the program(Chawla and Prasad, 2026; Manuel et al., 2024)。这个 假设是脆弱的。反编译是一个有损且启发式的过程： 不同的工具对控制流恢复做出不同的选择， 变量命名、类型推断和表达式简化. Decompilation is a lossy and heuristic process: different tools make different choices about control-flow recovery, variable naming, type inference, and expression simplification(Dramko et al., 2024; Lee et al., 2011; Schwartz et al., 2013)。作为一个 结果，每个反编译器都会暴露不同的. A behavior obscured in one decompiler’s output may be more visible in another, while a noisy representation may also mislead the model.

这引发了一个简单的假设：不同的反编译器可以提供 LLM 的补充证据。如果由一引起的错误 反编译器的表示与那些并不完全相关 由另一个引起，然后组合多个反编译视图可能会改善 分类。这在实践中很有吸引力，因为它可以建立在 现有开源反编译器和现成的 LLM 的顶部，无需 需要模型训练或访问源代码。This motivates a simple hypothesis: different decompilers can provide complementary evidence to an LLM. If the errors induced by one decompiler’s representation are not perfectly correlated with those induced by another, then combining multiple decompiled views may improve classification. This is attractive in practice because it can be built on top of existing open-source decompilers and off-the-shelf LLMs, without requiring model training or access to source code.

We construct a balanced benchmark of benign and malicious C programs, compile each program into a binary, and decompile every binary with two widely used free and open-source decompilers: Ghidra and RetDec(National Security Agency, 2019; Avast Software, 2024; Cao et al., 2022)。 良性样本的策划旨在反映 常见的实用行为，包括解析、加密、监控、 和网络。恶意样本涵盖了一系列恶意软件 行为，包括僵尸网络、蠕虫、特洛伊木马、rootkit、后门和 键盘记录。这个设置让我们可以评估现成的法学硕士的表现如何 对反编译的二进制文件进行分类以及是否有多个反编译器视图 提供有用的补充信息。. The benign samples are curated to reflect common utility behaviors, including parsing, cryptography, monitoring, and networking. The malicious samples cover a range of malware behaviors, including botnets, worms, trojans, rootkits, backdoors, and keylogging. This setup lets us evaluate both how well off-the-shelf LLMs classify decompiled binaries and whether multiple decompiler views provide useful complementary information.

在法学硕士小组中，我们发现反编译器的选择很大程度上 影响分类行为，以及结合反编译器视图 提高了模型系列中大多数设置的性能。收获 对于较小的模型尤其重要，其中多视图输入 提高记忆力。我们还发现反编译器观点之间存在分歧 信息丰富：当单视图预测不同时，额外的 来自多个视图的上下文通常有助于模型恢复正确的 决定。我们的主要贡献是：Across a panel of LLMs, we find that decompiler choice substantially affects classification behavior, and that combining decompiler views improves performance in most settings across model families. The gains are particularly important for smaller models, where multi-view inputs improve recall. We also find that disagreements between decompiler views are informative: when single-view predictions differ, the additional context from multiple views often helps the model recover the correct decision. 6 结论和未来的工作Conclusions and Future Work

我们研究了反编译二进制文件中基于 LLM 的恶意软件分类，结果表明反编译器的选择会对性能产生重大影响。单一反编译器视图通常会导致模型变得保守，当相关行为被模糊或渲染不清楚时会丢失恶意样本。提供多个反编译器视图为模型提供了额外的证据，提高了召回率，从而提高了恶意级别We studied LLM-based malware classification from decompiled binaries and showed that decompiler choice materially affects performance. Single decompiler views often lead models to be conservative, missing malicious samples when the relevant behavior is obscured or rendered unclearly. Providing multiple decompiler views gives the model additional evidence, improving recall and therefore malicious-classF1F_{1}在大多数情况下；这对于恶意软件分类尤其有价值，因为错过的恶意样本比误报的成本更高。我们的结果表明，反编译器多样性是一种简单实用的方法，可以在无需模型训练的情况下改进现成的 LLM 分析。未来的工作应该通过更难的良性程序、更广泛的恶意软件行为以及新兴的人工智能时代攻击面（例如生成代码中的恶意或幻觉依赖性）来扩展基准。它还应该探索更丰富的组合策略，包括学习视图选择、证据聚合和成本感知管道，这些管道决定何时值得查询其他反编译器视图。in most settings; this is especially valuable for malware triage, where missed malicious samples are more costly than false positives. Our results suggest that decompiler diversity is a simple and practical way to improve off-the-shelf LLM analysis without model training. Future work should extend the benchmark with harder benign programs, broader malware behaviors, and emerging AI-era attack surfaces such as malicious or hallucinated dependencies in generated code. It should also explore richer combination strategies, including learned view selection, evidence aggregation, and cost-aware pipelines that decide when additional decompiler views are worth querying.

7 局限性Limitations

目标文件，而不是整个程序。Object files, not whole programs.

我们对可重定位目标文件进行分类（We classify relocatable object files (.o），没有的代码片段), code fragments without a主要main入口点或完整链接。这反映了单个恶意软件模块经常出现的方式，但部署的分析师通常会检查完整的可执行文件及其周围的上下文，因此我们的发现可能不会直接转移到整个二进制分类。entry point or full linkage. This mirrors how individual malware modules often appear, but a deployed analyst usually inspects a complete executable with surrounding context, so our findings may not transfer directly to whole-binary triage.

无混淆或反反编译。No obfuscation or anti-decompilation.

我们假设二进制文件可以干净地反编译。在实践中，作者有时会故意混淆或打包代码以抵抗反编译，例如阻止逆向工程或代码盗窃，而我们的样本既没有打包也没有进行对抗性强化（我们保留了部分符号表，而不是打乱或完全模糊程序结构）。严重混淆或反反编译强化的二进制文件位于我们研究的环境之外，并且可能会降低我们评估的每种方法的性能。We assume binaries decompile cleanly. In practice, authors sometimes deliberately obfuscate or pack code to resist decompilation, for instance to deter reverse engineering or code theft, and our samples are neither packed nor adversarially hardened (we retain part of the symbol table rather than scrambling or fully obscuring program structure). Heavily obfuscated or anti-decompilation-hardened binaries lie outside the setting we study and would likely degrade every approach we evaluate.

反编译器的数量。Number of decompilers.

我们研究了两个反编译器：Ghidra 和 RetDec。尽管这两个工具被广泛使用，但它们并不涵盖其他专有工具（例如 IDA Pro、Binary Ninja），并且我们的互补性发现可能会因其他工具或两种以上视图的组合而改变。We study two decompilers, Ghidra and RetDec. Although these two are widely used, they do not cover other proprietary tools (e.g. IDA Pro, Binary Ninja), and our complementarity findings may change with other tools, or with more than two views combined.

8 道德和影响声明Ethics and Impact Statement

预期用途和影响。Intended use and impact.

我们研究二进制文件的自动分类为恶意或良性， 这是一项防御任务。我们的目标是帮助分析师、研究人员、 安全系统可以更可靠地对软件进行分类，尤其是在 源代码不可用，只能检查反编译的输出。我们的目标是检测而不是生成攻击：我们不开发新颖的恶意软件、攻击技术或规避方法。We study the automated classification of binaries as malicious or benign, which is a defensive task. Our aim is to help analysts, researchers, and security systems triage software more reliably, especially when the source code is unavailable and only decompiled output can be inspected. Our goal is detection rather than generating attacks: we do not develop novel malware, attack techniques, or evasion methods.

恶意样本。Malicious samples.

除了一个恶意样本外，所有恶意样本都是真实世界的样本 从已建立的公共存储库获得有据可查的家庭All but one of our malicious samples are real-world specimens of well-documented families obtained from an established public repository(ytisf and contributors, 2014);上面提到的合成键盘记录器是个例外， 它重新实现了公开描述的技术并且没有添加新的 能力。我们没有引入新的恶意软件系列、功能或规避措施 方法。基准测试中的每个程序，无论是良性的还是恶意的，都是 从源代码编译，然后在隔离的内部静态反编译， 禁用网络的容器；恶意二进制文件永远不会被执行。; the exception is the synthetic keylogger noted above, which reimplements a publicly described technique and adds no new capability. We introduce no new malware families, capabilities, or evasion methods. Every program in the benchmark, benign and malicious alike, is compiled from source and then statically decompiled inside an isolated, network-disabled container; the malicious binaries are never executed.

释放和双重用途的考虑。Release and dual-use considerations.

为了支持可重复性，我们共享反编译的工件和 用于研究目的的评估代码是我们结果的基础。因为 恶意样本要么是已经公开的样本，要么是微不足道的样本 重新实现一项长期记录的技术，释放他们的 反编译表示不提供超出的功能 社区已经可以获得，我们判断可重复性的好处 超过了这个边际风险。尽管如此，我们承认双重用途 恶意软件研究的性质：坚定的对手可能会尝试制作 逃避基于 LLM 的分类器（例如我们的分类器）的样本。我们发布的 材料涉及检测而不是逃避，并且不包含新的 进攻性功能。我们遵循来源的使用条款 存储库并建议任何重复使用这些文物的人只这样做 在受控的非生产环境中进行防御性研究。To support reproducibility, we share the decompiled artefacts and evaluation code underlying our results for research purposes. Because the malicious samples are either already-public specimens or a trivial reimplementation of a long-documented technique, releasing their decompiled representations does not provide capabilities beyond what the community can already obtain, and we judge the reproducibility benefit to outweigh this marginal risk. We nonetheless acknowledge the dual-use nature of malware research: a determined adversary could attempt to craft samples that evade an LLM-based classifier such as ours. Our released material concerns detection rather than evasion and contains no new offensive functionality. We follow the usage terms of the source repositories and recommend that anyone reusing these artefacts do so only in controlled, non-production environments for defensive research.

附录EAppendix E提示模板Prompt Templates

我们在主要实验中使用仅定义提示。它定义了 恶意和良性行为，但未列出具体恶意软件 指标，以避免将模型转向特定的攻击系列 或表面图案。在单反编译器设置中，用户消息 包含一个反编译的伪 C 视图。在多视图设置中， 使用相同的定义，但用户消息包含 Ghidra 和 RetDec 输出并声明它们是相同观点的互补观点 二进制；已发布的代码库中提供了确切的提示包装器。在 所有设置，模型都需要在之前提供一个简短的理由 返回结构化二元决策。We use a definition-only prompt for the main experiments. It defines malicious and benign behavior without listing concrete malware indicators, to avoid steering the model toward particular attack families or surface patterns. In the single-decompiler setting, the user message contains one decompiled pseudo-C view. In the multi-view setting, the same definition is used, but the user message contains both Ghidra and RetDec outputs and states that they are complementary views of the same binary; the exact prompt wrapper is provided in the released codebase. In all settings, the model is asked to provide a brief rationale before returning a structured binary decision.

引导提示应被解释为乐观的上限，而不是 作为主要的可部署设置。其指标列表为模型提供了 优先于可疑行为，这可以提高性能 已知的恶意软件模式，但可能会降低对新行为的鲁棒性或 具有表面相似 API 的良性程序。因此，我们报告了这一情况 仅作为消融。The guided prompt should be interpreted as an optimistic upper bound, not as the main deployable setting.
