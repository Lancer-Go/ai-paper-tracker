并发子代理执行和迭代重新规划。Concurrent Sub-Agent Execution and Iterative Replanning.收到广播子任务后，每个子代理通过语义搜索独立地从 RSPL 注册表检索相关提示和工具资源，执行工具调用以与环境交互，并将中间结果和推理跟踪作为持久的、可查询的状态写入共享内存。子代理并发操作：总线将任务调度与任务完成解耦，因此多个子代理可以并行执行，而无需同步开销。一旦当前轮中的所有子代理完成，Orchestrator 就会通过总线收集它们的输出，汇总聚合结果，并使用当前执行状态更新 plan.md。基于这个全局视图，Orchestrator 决定任务是否完成或者是否需要进行进一步的子任务分解和广播。这种收集和重新计划循环会重复，直到满足终止条件为止，使系统能够处理任意深度和分支复杂性的任务。作为互补模式，Upon receiving a broadcast subtask, each subagent independently retrieves the relevant prompt and tool resources from the RSPL registry via semantic search, executes tool calls to interact with the environment, and writes intermediate results and reasoning traces to shared memory as persistent, queryable state. This collect-and-replan loop repeats until the termination condition is satisfied, enabling the system to handle tasks of arbitrary depth and branching complexity.
