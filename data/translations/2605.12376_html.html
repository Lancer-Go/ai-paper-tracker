ProfiliTable：通过代理工作流程进行分析驱动的表格数据处理ProfiliTable: Profiling-Driven Tabular Data Processing via Agentic Workflows

Wei Liu Peking UniversityChina , Yang Gu Peking UniversityChina , Xi Yan Institute of Computing Technology, Chinese Academy of SciencesChina , Zihan Nan Peking UniversityChina , Beicheng Xu Peking UniversityChina , Keyao Ding Peking UniversityChina , Bin Cui Peking UniversityChina and Wentao Zhang Peking UniversityChina
摘要。Abstract.

表处理（包括清理、转换、扩充和匹配）是现实世界数据管道中的基础但容易出错的阶段。虽然最近基于法学硕士的方法显示出自动化此类任务的希望，但由于指令不明确、任务结构复杂以及缺乏结构化反馈，它们在实践中经常遇到困难，导致语法正确但语义有缺陷的代码。为了应对这些挑战，我们提出了ProfilTable，这是一个以动态分析为中心的自主多智能体框架，它通过交互式探索、知识增强综合和反馈驱动的细化来构建和迭代细化统一的执行上下文。 ProfiliTable 集成了 (i) 执行 ReAct 式数据探索以构建语义理解的探查器，(ii) 检索精选运算符以合成任务感知代码的生成器，以及 (iii) 注入执行分数和诊断见解以实现闭环细化的评估器-总结器循环。对涵盖 18 种表格任务类型的多样化基准进行的广泛实验表明，ProfilTable 始终优于强大的基准，特别是在复杂的多步骤场景中。这些结果凸显了动态分析在将模糊的用户意图可靠地转换为稳健且符合治理的表转换方面的关键作用。Table processing—including cleaning, transformation, augmentation, and matching—is a foundational yet error-prone stage in real-world data pipelines. While recent LLM-based approaches show promise for automating such tasks, they often struggle in practice due to ambiguous instructions, complex task structures, and the lack of structured feedback, resulting in syntactically correct but semantically flawed code. To address these challenges, we propose ProfiliTable, an autonomous multi-agent framework centered on dynamic profiling, which constructs and iteratively refines a unified execution context through interactive exploration, knowledge-augmented synthesis, and feedback-driven refinement. ProfiliTable integrates (i) a Profiler that performs ReAct-style data exploration to build semantic understanding, (ii) a Generator that retrieves curated operators to synthesize task-aware code, and (iii) an Evaluator–Summarizer loop that injects execution scores and diagnostic insights to enable closed-loop refinement. Extensive experiments on a diverse benchmark covering 18 tabular task types demonstrate that ProfiliTable consistently outperforms strong baselines, particularly in complex multi-step scenarios. These results highlight the critical role of dynamic profiling in reliably translating ambiguous user intents into robust and governance-compliant table transformations.

1. 简介Introduction

表格数据构成了现代数据驱动决策的支柱，并支撑着广泛的机器学习应用，特别是在金融等高风险领域Tabular data constitutes the backbone of modern data-driven decision making and underpins a wide range of machine learning applications, especially in high-stakes domains such as finance(Shwartz-Ziv and Armon, 2021), 医疗保健, healthcare(Park et al., 2021)和政府, and government(Pi, 2021)。然而，现实世界的表格数据很少可供分析：它通常有噪音、不完整且语义不一致，需要进行大量处理才能开始可靠的建模. However, real-world tabular data is rarely analysis-ready: it is often noisy, incomplete, and semantically inconsistent, requiring extensive processing before reliable modeling can begin(Maharana et al., 2022)。此外，表结构和领域语义的多样性排除了可以处理所有数据争用场景的单一固定算法的存在. Moreover, the diversity of table structures and domain semantics precludes the existence of a single, fixed algorithm that can handle all data wrangling scenarios(Ni et al., 2025)。因此，基于规则的表处理工具（例如 OpenRefine）. As a result, rule-based table processing tools such as OpenRefine(Miller and Vielfaure, 2022)需要大量的手动配置和专家干预，使得表格数据处理成为数据科学管道中劳动力最密集且最容易出错的阶段之一demand substantial manual configuration and expert intervention, making tabular data processing one of the most labor-intensive and error-prone stages in the data science pipeline(Polyzotis et al., 2017; Sambasivan et al., 2021; Ridzuan and Zainon, 2019).

这些限制激发了人们对更灵活和自动化解决方案的兴趣日益浓厚，这些解决方案可以以最少的手动干预来适应不同的表格结构和任务要求。大型语言模型 (LLM) 的出现为自动化以数据为中心的任务开辟了新途径These limitations have motivated growing interest in more flexible and automated solutions that can adapt to diverse tabular structures and task requirements with minimal manual intervention. The advent of large language models (LLMs) has opened new avenues for automating data-centric tasks(Narayan et al., 2022)。最近的工作证明了法学硕士能够从自然语言生成用于表操作的可执行代码，从而使数据科学代理能够生成 pandas 或 SQL 脚本. Recent works have demonstrated LLMs’ ability to generate executable code for table manipulation from natural language, enabling Data Science Agents that produce pandas or SQL scripts(Trirat et al., 2025; Liu et al., 2025a; Zhang et al., 2024)。然而，由于以下三个关键原因，现有方法无法提供强大的通用表管理：首先，许多方法范围狭窄，侧重于孤立的操作，例如插补. However, existing approaches fall short in delivering robust, general-purpose table curation for three key reasons: First, many methods are narrowly scoped, focusing on isolated operations such as imputation(Srinivasan and Manikonda, 2025; Ding et al., 2024; He et al., 2025), 纠错, error correction(Bendinelli et al., 2025; Ni et al., 2024; Biester et al., 2024)，或模式匹配, or schema matching(Fu et al., 2025)，因此无法处理复合工作流程, and thus cannot handle composite workflows(Li et al., 2025b)。其次，更广泛的框架通常会优先考虑其他数据科学任务，例如自动化机器学习（AutoML）. Second, broader frameworks often prioritize other data science tasks—such as automated machine learning (AutoML)(Zhang et al., 2023; Wang et al., 2025)或基于表格的问答or table-based question answering(Xing et al., 2025; Sui et al., 2024)— 涵盖整个表格处理范围。第三，即使那些明确针对表处理的系统也依赖于通用的多代理支架，而这些支架缺乏对特定于表的数据的理解—over the full spectrum of table processing. Third, even those systems explicitly targeting table processing either rely on generic multi-agent scaffolds, which lack table-specific data understanding(Hong et al., 2024b; Qian et al., 2024)，或采用不强调自适应、反馈驱动的分析的手工制作管道, or employ hand-crafted pipelines that do not emphasize adaptive, feedback-driven profiling(Liu et al., 2025b; Qi et al., 2025).

这种限制在当前的工具中很明显。例如，CleanAgent 执行列类型注释，但在代码生成期间不会主动采样或检查实际单元格值This limitation is evident in current tools. For example, CleanAgent performs column-type annotation but does not actively sample or inspect the actual cell values during code generation(Qi et al., 2025)。因此，当给出诸如“标准化货币列”之类的模糊指令时，它不知道该列中存在的具体值，因此无法确定如何构建适当的标准化映射表。. As a result, when given an ambiguous instruction such as “standardize the currency column,” it has no knowledge of the concrete values present in the column and therefore cannot determine how to construct an appropriate mapping table for standardization.

相比之下，像 DataGovAgent 这样基于规则的系统通常只对每列的几行进行采样来估计基本属性In contrast, a rule-based system like DataGovAgent typically samples only a few rows per column to estimate basic properties(Liu et al., 2025b)。然而，这种有限的检查通常无法捕获解释不明确指令所需的全部值，尤其是当不检查其实际内容就无法识别相关列时。为了可靠地处理此类情况，需要计算完整值统计信息，例如该列的唯一值。但由于目标列事先未知，唯一安全的选择是计算所有列的唯一值。这会导致显着的冗余，尤其是在宽表中，并用不相关的信息淹没提示。根本问题是静态的、规则驱动的分析无法根据指令自适应地决定要探索哪一列，因此必须过度配置以避免失败。. However, this limited inspection often fails to capture the full range of values needed to interpret ambiguous instructions—especially when the relevant column cannot be identified without examining its actual content. To handle such cases reliably, it would need to compute full value statistics such as unique values for that column. But since the target column is unknown in advance, the only safe option is to compute unique values for all columns. This leads to significant redundancy, especially in wide tables, and floods the prompt with irrelevant information. The root issue is that static, rule-driven profiling cannot decide adaptively which column to explore based on the instruction, and therefore must over-provision to avoid failure.

这些缺点凸显了为什么表处理需要灵活的、假设驱动的分析机制，该机制仅探索必要的内容并在正确的时间执行此操作。因此，我们建议These shortcomings highlight why table processing demands a flexible and hypothesis-driven profiling mechanism that explores only what is necessary and does so at the right time. Therefore, we propose剖面表ProfiliTable，其核心见解是健壮的表处理取决于, whose core insight is that robust table processing depends on an主动、迭代的分析概念active, iterative notion of profiling——不是被动的元数据消费，而是通过交互、反馈和知识整合而演变的语义构建的动态过程。我们的分析框架通过三种协同机制运行：(1)—not as passive metadata consumption, but as a dynamic process of semantic construction that evolves through interaction, feedback, and knowledge integration. The resulting insight is fed to the Profiler and Generator, guiding more accurate profiling and code generation.
