摘要Abstract

多模态大型语言模型（MLLM）对文本、图像和视频进行了先进的统一推理，但它们的推理受到键值（KV）缓存的快速增长的阻碍。 每个视觉输入都会扩展为数千个标记，导致缓存随上下文长度线性扩展，并在整个解码过程中保留在 GPU 内存中，这会导致内存开销和延迟过高，即使在高端 GPU 上也是如此。 常见的解决方案是在不同粒度的固定分配预算下压缩缓存：令牌级统一丢弃不太重要的令牌，层级跨层改变保留，头级在头之间重新分配预算。然而，这些方法停留在分配上，并忽略了需要不同压缩策略的注意力头的异构行为。 我们建议Multimodal Large Language Models (MLLMs) have advanced unified reasoning over text, images, and videos, but their inference is hindered by the rapid growth of key–value (KV) caches. Each visual input expands into thousands of tokens, causing caches to scale linearly with context length and remain resident in GPU memory throughout decoding, which leads to prohibitive memory overhead and latency even on high-end GPUs. A common solution is to compress caches under a fixed allocated budget at different granularities: token-level uniformly discards less important tokens, layer-level varies retention across layers, and head-level redistributes budgets across heads. Yet these approaches stop at allocation and overlook the heterogeneous behaviors of attention heads that require distinct compression strategies. We propose混合KVHybridKV，一种混合 KV 缓存压缩框架，集成了三个阶段的互补策略：首先使用以文本为中心的注意力将头部分为静态或动态类型；然后采用自上而下的预算分配方案，分层分配KV预算；最后，静态头通过文本优先修剪进行压缩，动态头通过块方式检索进行压缩。 在 11 个多模式基准上进行的实验, a hybrid KV cache compression framework that integrates complementary strategies in three stages: heads are first classified into static or dynamic types using text-centric attention; then a top-down budget allocation scheme hierarchically assigns KV budgets; finally, static heads are compressed by text-prior pruning and dynamic heads by chunk-wise retrieval. Experiments on 11 multimodal benchmarks withQwen2.5-VL-7B表明show that混合KVHybridKV减少 KV 缓存内存高达reduces KV cache memory by up to7.9×7.9\times并实现and achieves1.52×1.52\times解码速度更快，几乎没有性能下降，甚至比全缓存 MLLM 更高。faster decoding, with almost no performance drop or even higher relative to the full-cache MLLM.

Specifically, the token sequence is divided into fixed-size chunks (e.g., 8 tokens each), and each chunk is represented by metadata computed as the average of its key vectors. As illustrated inFig.˜6，在预填充阶段，我们从元数据构建块级索引，将动态头 KV 缓存卸载到 CPU 内存，并仅保留 GPU 上的索引。在每个解码步骤中，我们通过计算查询向量和块元数据之间的内积来识别相关块，从 CPU 加载选定的块，并相应地更新 GPU KV 缓冲区。加载的块的数量由每个头的预算和块的大小决定。然后将最终的注意力输出与静态 KV 缓存一起计算。该策略自适应地检索基本上下文，同时通过逐块数据传输实现效率。, during the prefill stage we build a chunk-level index from the metadata, offload dynamic-head KV caches to CPU memory, and retain only the index on GPU. At each decoding step, we identify relevant chunks by computing the inner product between the query vector and chunk metadata, load the selected chunks from CPU, and update the GPU KV buffer accordingly. The number of loaded chunks is determined by the per-head budget and chunk size. The final attention output is then computed together with the static KV cache. This strategy adaptively retrieves essential contexts while achieving efficiency through chunk-wise data transfer.
