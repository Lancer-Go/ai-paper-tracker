PalmClaw：移动电话的本机设备上代理框架PalmClaw: A Native On-Device Agent Framework for Mobile Phones

Hongru Cai1  Yongqi Li1\advisor Ran Wei2  Wenjie Li1
1 The Hong Kong Polytechnic University  2 Hangzhou Diagens Biotechnology Co., Ltd.
{henry.hongrucai, liyongqi0}@gmail.com
摘要Abstract

大型语言模型 (LLM) 代理已经不再只是生成响应，而是通过调用工具、观察结果并迭代地决定下一步操作来执行多步骤任务。大多数代理系统运行在桌面或服务器上，支持工具使用和任务自动化。移动设备也是重要的代理环境，因为它们可以广泛访问并且包含用户的数据、传感器和日常使用的应用程序。现有的移动代理主要通过点击、滑动和打字等图形用户界面（GUI）操作来操作智能手机，这些操作通常形成长的、依赖于界面的序列，无法直接访问设备功能，并且使得执行边界难以定义。我们呈现Large Language Model (LLM) agents have moved beyond generating responses to executing multi-step tasks by calling tools, observing the results, and iteratively deciding the next action. Most agent systems run on desktops or servers, which support tool use and task automation. Mobile devices are also important agent environments because they are widely accessible and contain users’ data, sensors, and daily-use applications. Existing mobile agents mainly operate smartphones through graphical user interface (GUI) actions such as tapping, swiping, and typing, which often form long, interface-dependent sequences, cannot directly access device capabilities, and make execution boundaries difficult to define. We present掌爪PalmClaw，一个开源代理框架，在移动电话上本地运行，并直接在设备上管理会话、内存、技能、工具和代理循环。 PalmClaw 将设备功能公开为具有显式参数、结构化结果和明确定义的执行边界的设备工具。这种设计使代理能够直接使用移动​​功能，同时保持每个操作的明确和受控。实验表明，与最强基线相比，任务成功率相对提​​高了 11.5%，完成时间缩短了 94.9%，设置负担更低，并且跟踪说明了如何应用执行边界。, an open-source agent framework that runs natively on mobile phones and manages the sessions, memory, skills, tools, and agent loop directly on the device. PalmClaw exposes device capabilities as device tools with explicit arguments, structured results, and clearly defined execution boundaries. This design enables agents to use mobile capabilities directly while keeping each action explicit and controlled. Experiments show an 11.5% relative improvement in task success and a 94.9% reduction in completion time over the strongest baseline, with lower setup burden and traces illustrating how execution boundaries are applied.

1 简介Introduction

最近的大型语言模型（LLM）代理已经超越了生成响应以在外部环境中执行任务的范围Recent Large Language Model (LLM) agents have moved beyond generating responses to executing tasks in external environments[yao2023react, schick2023toolformer, li2026clawsbench]。给定复杂的用户指令，代理可以将任务分解为多个步骤，调用工具，观察结果，并迭代地决定下一步做什么，直到任务完成. Given a complex user instruction, the agent can decompose the task into multiple steps, call tools, observe the results, and iteratively decide what to do next until the task is completed[openclawGettingStarted, gao2025agentscope10developercentricframework]。这种迭代交互使代理不仅能够提供建议，更重要的是能够自主执行信息查找等任务. This iterative interaction enables agents not only to offer advice, but more importantly, to autonomously execute tasks such as information seeking[zhu2026gisa]、档案管理, file management[xie2024osworld, li2026clawsbench]和工作流程自动化, and workflow automation[xu2025theagentcompany].

代理本质上是一个基于 LLM 基础的框架，通过指令、持久内存、可重用技能、可执行工具、会话管理和迭代代理循环的结合。这些组件共同允许代理检索相关的内存和会话历史记录、加载特定于任务的指令和技能、调用 LLM、执行工具并将结果观察结果反馈到后续回合中。代表性代理框架，例如 AutoGenAn agent is essentially a framework upon a foundational LLM through the incorporation of instructions, persistent memory, reusable skills, executable tools, session management, and an iterative agent loop. Together, these components allow the agent to retrieve relevant memory and session history, load task-specific instructions and skills, invoke the LLM, execute tools, and feed the resulting observations into subsequent turns. Representative agent frameworks, such as AutoGen[wu2023autogen], 代理范围, AgentScope[gao2025agentscope10developercentricframework]和张开爪, and OpenClaw[openclawGettingStarted]将这些组件托管在桌面计算机或云服务器上。host these components on a desktop computer or cloud server.

虽然桌面和服务器平台为代理提供了丰富且实用的环境，但我们认为在移动设备上本地支持代理也很重要。首先，移动电话是最广泛使用的个人计算设备之一，全球五分之四的 10 岁或以上的人拥有一部While desktop and server platforms provide a rich and practical environment for agents, we argue that supporting agents natively on mobile devices is also important. First, mobile phones are among the most widely available personal computing devices, with four out of five people aged 10 or older worldwide owning one[itu2024mobileownership]。这种广泛的可用性使移动原生代理能够接触到可能无法持续访问个人计算机的用户。其次，智能手机存储高度个人化的数据，提供摄像头、麦克风和位置等传感器，并托管日常生活中使用的许多应用程序. This broad availability allows mobile-native agents to reach users who may not have continuous access to a personal computer. Second, smartphones store highly personal data, provide sensors such as cameras, microphones, and location, and host many of the applications used in everyday life[wang2024mobileagentbenchefficientuserfriendlybenchmark]。因此，直接在智能手机上运行代理可以使它们更接近用户、他们的设备资源以及日常任务所需的功能。. Running agents directly on smartphones can therefore place them closer to the users, their device resources, and the capabilities required for daily tasks.

尽管有这种潜力，现有的移动代理主要通过 GUI 操作（例如点击、滑动和打字）来操作智能手机（见图Despite this potential, existing mobile agents primarily operate smartphones through GUI actions such as tapping, swiping, and typing (see Figure1(一))(a))[wang2024mobileagentbenchefficientuserfriendlybenchmark, zhang-etal-2025-agentcpm, ye2025mobileagentv3fundamentalagentsgui]。虽然与现有应用程序广泛兼容，但这种方法具有三个局限性：1）高级任务变成对布局变化和复杂界面敏感的长动作序列； 2）无法直接访问设备资源和能力，如本地文件、传感器数据等； 3) GUI 控制授予对可到达接口的广泛访问，没有明确的特定于任务的访问限制或执行边界。因此，GUI 交互对于一般屏幕操作很有用，但不足以作为移动代理的唯一操作空间。最近兴起的终端原生代理（例如 Codex CLI）. Although broadly compatible with existing applications, this approach has three limitations: 1) high-level tasks become long action sequences that are sensitive to layout changes and complex interfaces; 2) it cannot directly access device resources and capabilities, such as local files and sensor data; and 3) GUI control grants broad access to reachable interfaces, without clear task-specific access limits or execution boundaries. GUI interaction is therefore useful for general screen operations, but insufficient as the sole action space for mobile agents. The recent rise of terminal-native agents such as Codex CLI[openaiCodexCLI], 克劳德·代码, Claude Code[anthropicClaudeCode]和 Gemini CLI, and Gemini CLI[googleGeminiCLI]反映了向明确且可执行的基于工具的交互的更广泛转变，激发了移动代理的类似本机设备上设计。reflects a broader shift toward explicit and executable tool-based interaction, motivating a similar native on-device design for mobile agents.

3 框架Framework

本节介绍 PalmClaw 中的代理组件以及它们在设备上执行期间如何协同工作。This section describes the agent components in PalmClaw and how they work together during on-device execution.

3.1 概述Overview

PalmClaw 直接在移动设备上运行多步骤代理执行所需的组件。如图PalmClaw runs the components needed for multi-step agent execution directly on the mobile device. As shown in Figure2，会话组织用户交互，内存保存可重用信息，技能提供特定于任务的指令，工具公开设备资源和功能。代理循环通过重复的模型和工具交互来组合这些组件。 LLM 推理是通过远程 LLM API 提供的，而上下文管理、工具执行和会话状态保留在移动设备上。 PalmClaw将这些组件集成到移动应用程序中，代表性界面如图所示, sessions organize user interactions, memory preserves reusable information, skills provide task-specific instructions, and tools expose device resources and capabilities. The agent loop combines these components through repeated model and tool interactions. LLM inference is provided through a remote LLM API, while context management, tool execution, and session state remain on the mobile device. PalmClaw integrates these components into a mobile application, with representative interfaces shown in Figure6.

3.2 代理组件Agent Components

PalmClaw 直接在移动设备上维护会话、内存、技能和设备工具。PalmClaw maintains sessions, memory, skills, and device tools directly on the mobile device.

会议。Sessions.

会话组织来自三个输入源的持久代理交互：本地聊天消息、来自连接的远程通道的消息以及由计划唤醒生成的自动消息。每个会话都存储其对话历史记录、工具跟踪、附件以及用于文档、临时文件和生成工件的专用工作区。 PalmClaw 将每个输入路由到现有或新会话，允许任务在多个轮次中继续，同时保持并发任务独立。Sessions organize persistent agent interactions from three input sources: local chat messages, messages from connected remote channels, and automated messages generated by scheduled wakeups. Each session stores its conversation history, tool traces, attachments, and a dedicated workspace for documents, temporary files, and generated artifacts. PalmClaw routes each input to an existing or new session, allowing tasks to continue across multiple turns while keeping concurrent tasks separate.

记忆。Memory.

PalmClaw 维护两个持久内存层：1）共享长期内存，存储跨会话可用的信息，并包含在每个代理的轮次中；2）每个会话摘要，保存任务进度和结论的紧凑记录。当未合并的消息到达可配置窗口时，单独的 LLM 调用会汇总旧消息并更新两层。内存工具允许代理读取或更新长期内存以及读取或搜索所选会话的历史记录。PalmClaw maintains two persistent memory layers: 1) shared long-term memory, which stores information available across sessions and is included in each agent’s turn, and 2) per-session summaries, which keep compact records of task progress and conclusions. When unconsolidated messages reach a configurable window, a separate LLM call summarizes older messages and updates both layers. Memory tools allow the agent to read or update long-term memory and to read or search the history of a selected session.

技能。Skills.

技能是用于应用工具和完成常见例程的可重复使用的任务指令，存储在Skills are reusable task instructions for applying tools and completing common routines, stored in技能.mdSKILL.md文件。 PalmClaw 提供内置和用户安装的技能。对于每个回合，它都会向上下文添加可用技能的摘要，加载标记为始终处于活动状态的技能的完整说明，并通过将最近的用户消息与其名称、描述和关键字进行匹配来选择其他相关技能。仅完整加载始终处于活动状态和选定的技能，提供特定于任务的指导，而无需将每个技能加载到上下文中。图files. PalmClaw provides built-in and user-installed skills. For each turn, it adds a summary of available skills to the context, loads the full instructions of skills marked as always active, and selects other relevant skills by matching recent user messages against their names, descriptions, and keywords. Only always-active and selected skills are loaded in full, providing task-specific guidance without loading every skill into the context. Figure3总结了内置技能和工具组。summarizes the built-in skills and tool groups.

工具。Tools.

设备工具将模型生成的工具调用连接到手机上可用的资源和功能。每个工具都链接一个面向模型的规范（包含其名称、描述和 JSON 参数架构）以及一个面向设备的函数，该函数调用移动服务或应用程序管理的操作。 PalmClaw 将规范发送给 LLM，在调用时执行相关函数，并返回结构化结果或错误。内置设备工具涵盖设备状态和权限、媒体、蓝牙、日历和联系人、工作区文件；其他工具组支持网络访问、内存、通信和计划自动化。Device tools connect model-generated tool calls to resources and capabilities available on the phone. Each tool links a model-facing specification containing its name, description, and JSON argument schema and a device-facing function that invokes a mobile service or app-managed operation. PalmClaw sends the specification to the LLM, executes the associated function when called, and returns a structured result or error. Built-in device tools cover device status and permissions, media, Bluetooth, calendar, and contacts, and workspace files; other tool groups support web access, memory, communication, and scheduled automation.

3.3 代理执行Agent Execution

这些组件通过上下文组装、代理循环和设备工具执行来协同工作。These components work together through context assembly, the agent loop, and device tool execution.

上下文组装。Context assembly.

将输入分配给会话后，PalmClaw 从六个来源组装代理上下文：1）来自After an input is assigned to a session, PalmClaw assembles the agent context from six sources: 1) system instructions from代理.mdAGENT.md, 灵魂.mdSOUL.md, 和, and用户名.mdUSER.md; 2) 运行时上下文，包括当前时间、时区、会话 ID 和工作空间路径； 3）共享长期记忆； 4）主动技能说明和可用技能总结； 5）最近的对话历史、附件和工具痕迹； 6) 可用的工具规范，包括其名称、描述和参数模式。前五个来源形成模型消息，而工具规范与它们一起提供给远程 LLM API。图; 2) runtime context, including the current time, timezone, session ID, and workspace paths; 3) shared long-term memory; 4) active skill instructions and a summary of available skills; 5) recent conversation history, attachments, and tool traces; and 6) available tool specifications, including their names, descriptions, and argument schemas. The first five sources form the model messages, while the tool specifications are provided alongside them to the remote LLM API. Figure5显示了此上下文的示例。shows an example of this context.

代理循环。Agent loop.

PalmClaw 将每个代理回合作为有界多轮循环运行，将远程 LLM 推理与设备上的工具执行连接起来PalmClaw runs each agent turn as a bounded multi-round loop that connects remote LLM reasoning with on-device tool execution[yao2023react, schick2023toolformer]。在每一轮中，PalmClaw 从当前会话状态重建上下文，将模型消息和可用工具规范发送到远程 LLM API，并将返回的辅助消息存储在会话中。如果响应包含工具调用，PalmClaw 会执行它们，将其结果附加到会话中，并使用更新的上下文开始下一轮。如果响应不包含任何工具调用，则它成为最终回复。当工具发出任务完成信号或达到轮次限制时，循环也会结束。. In each round, PalmClaw rebuilds the context from the current session state, sends the model messages and available tool specifications to the remote LLM API, and stores the returned assistant message in the session. If the response contains tool calls, PalmClaw executes them, appends their results to the session, and starts the next round with the updated context. If the response contains no tool calls, it becomes the final reply. The loop also ends when a tool signals task completion or the round limit is reached.

工具执行。Tool execution.

来自代理循环的工具调用进入设备工具执行路径如图所示Tool calls from the agent loop enter the device tool execution path shown in Figure2。 PalmClaw 首先匹配对工具注册表的每次调用。在执行相应的操作之前，调用会通过三项检查：1). PalmClaw first matches each call to the tool registry. Before the corresponding operation is executed, the call passes three checks: 1)模式Schema验证所需的参数、类型和允许的范围。 2）validates required arguments, types, and allowed ranges. 2)权限Permissions包括设备授权和用户确认。缺少权限会调用系统权限或设置流程，而需要用户直接参与的操作仅在用户确认或完成后才会继续。 3）includes device authorization and user confirmation. Missing permissions invoke the system permission or settings flow, while actions requiring direct user involvement proceed only after the user confirms or completes them. 3)工作空间Workspace解析当前会话工作区或批准的共享存储中的文件路径，拒绝其他会话工作区和未批准的全局路径，并在外部写入之前需要确认。通过这些检查的调用将针对相应的设备资源或功能执行。其结构化结果返回给会话进行下一轮；如果检查失败或用户拒绝，PalmClaw 将返回结构化错误。resolves file paths within the current session workspace or approved shared storage, rejects other session workspaces and unapproved global paths, and requires confirmation before external writes. A call that passes these checks is executed against the corresponding device resource or capability. Its structured result is returned to the session for the next round; if a check fails or the user declines, PalmClaw returns a structured error.

5 结论Conclusion

本文研究了如何为移动环境设计代理框架，而不仅仅是操作电话界面。我们提出了 PalmClaw，这是一个开源设备上代理框架，它直接在手机上运行，​​并通过具有显式参数、结构化结果和特定于工具的执行边界的设备工具公开设备功能。在 MobileTask 上，PalmClaw 的任务成功率相对提​​高了 11.5%，完成时间缩短了 94.9%，同时降低了设置负担。基于跟踪的案例进一步说明了其执行边界是如何应用的。总之，这些结果表明，移动电话可以作为代理框架的环境，将移动代理研究扩展到屏幕操作之外，直接和受控地使用设备功能。This paper examined how agent frameworks can be designed for the mobile environment beyond operating phone interfaces. We presented PalmClaw, an open-source on-device agent framework that runs directly on the phone and exposes device capabilities through device tools with explicit arguments, structured results, and tool-specific execution boundaries. On MobileTask, PalmClaw achieves an 11.5% relative improvement in task success and a 94.9% reduction in completion time, while lowering setup burden. Trace-based cases further illustrate how its execution boundaries are applied. Together, these results show that mobile phones can serve as environments for agent frameworks, extending mobile-agent research beyond screen operation toward direct and controlled use of device capabilities.

道德声明Ethics Statement

PalmClaw 旨在保持移动操作明确且有界：工具已注册、参数已验证、敏感操作依赖于 Android 权限或用户确认、文件操作遵循工作区边界。部署仍应使提供商端的数据流对用户而言清晰可见，尤其是当远程 LLM 提供商收到提示、工具结果或任务上下文时。本文的实验使用公共或构建的评估任务，不需要收集私人用户数据。PalmClaw is designed to keep mobile actions explicit and bounded: tools are registered, arguments are validated, sensitive actions rely on Android permissions or user confirmation, and file operations follow workspace boundaries. Deployments should still make provider-side data flow clear to users, especially when remote LLM providers receive prompts, tool results, or task context. The experiments in this paper use public or constructed evaluation tasks and do not require collecting private user data.
