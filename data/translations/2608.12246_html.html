VICBench：代码漏洞检测的多语言基准VICBench: A Multi-Language Benchmark for Code Vulnerability Detection

Jin Lu    Xuening Han    Yang Zhong Affiliation: University of Pittsburgh    Lin Tan Affiliation: Purdue University[-0.5em] jinlu2@asu.eduxuenihan@amazon.comyaz118@pitt.edulintan@purdue.edu    Kevin Luo    Andrew Gacek    Neha Rungta    [-0.2em] Amazon Web Services
摘要Abstract

评估安全漏洞检测工具需要具有漏洞诱导提交 (VIC) 的基准数据集，即首先将漏洞引入代码库的提交。 VIC 对于确定所有易受攻击的软件版本至关重要。 现有的漏洞数据集受到编程语言覆盖范围有限、补丁复杂性有限以及项目范围狭窄的困扰。 通过人类专家的双重注释和代理工作流程，我们创建了一个基准——Evaluating security vulnerability detection tools requires benchmark datasets with vulnerability-inducing commits (VICs)—the commits that first introduce vulnerabilities into codebases. VICs are essential for determining the full range of vulnerable software versions. Existing vulnerability datasets suffer from limited programming language coverage, restricted patch complexity, and narrow project scope. Through our dual annotation by human experts and an agentic workflow, we create a benchmark—VIC基准VICBench—Python、Java 和 C++ 中 88 个项目的 100 个 CVE 的 100 个经过验证的 VIC，涵盖 48 种 CWE 类型。 VICBench 具有复杂的实际漏洞修复功能，平均为 38.6 行，相应的 VIC 为 252.5 行，比之前的工作大得多。 我们的评估表明，最先进的算法 V-SZZ 和 LLM4SZZ 仅实现 33.3%–40.1% F1，这证实使用现有方法仍然需要大量的手动工作。 VICBench 能够对漏洞检测方法进行稳健的评估。—of 100 verified VICs for 100 CVEs across 88 projects in Python, Java, and C++, covering 48 CWE types. VICBench features complex real-world vulnerability fixes averaging 38.6 lines and corresponding VICs of 252.5 lines—significantly larger than prior work. Our evaluation shows that state-of-the-art algorithms V-SZZ and LLM4SZZ achieve only 33.3%–40.1% F1, confirming that using existing approaches still entails significant manual effort. VICBench enables robust evaluation of vulnerability detection approaches.

A.3 Cohen 的 Kappa 计算详细信息Cohen’s Kappa Calculation Details

Cohen 的 kappa 定义为：Cohen’s kappa is defined as:

κ=Po−Pe1−Pe\kappa=\frac{P_{o}-P_{e}}{1-P_{e}} (1)

哪里wherePoP_{o}是观察到的一致性比例，is the observed agreement proportion andPeP_{e}是偶然的预期协议。is the expected agreement by chance.

协议标准：Agreement Criteria:

当且仅当两个注释都标识了完全相同的提交时，才认为两个注释是一致的。这个严格的定义避免了关于基本事实的循环推理。Two annotations were considered in agreement if and only if both identified the exact same commit. This strict definition avoids circular reasoning about ground truth.

对于 VIC 注释，随机一致的概率取决于注释者可以选择的提交池大小。对于每个 CVE，我们确定了两个注释之间最早的 VIC，并使用 git 历史记录计算从该最早的 VIC（包括）到修复提交（不包括）的提交。池大小范围为 2 到 212,671 次提交，中位数为 1,690 次提交。预期一致性计算如下：For VIC annotation, the probability of random agreement depends on the commit pool size from which annotators could select. For each CVE, we identified the earliest VIC between the two annotations and counted commits from this earliest VIC (inclusive) to the fix commit (exclusive) using git history. Pool sizes ranged from 2 to 212,671 commits with a median of 1,690 commits. Expected agreement was computed as:
