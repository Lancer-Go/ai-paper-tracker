当 LLM 反编译器重新编译更多并保留更少时When LLM Decompilers Recompile More and Preserve Less

Chang Liu    Edward Raff    Kristopher Micinski
摘要Abstract

反编译从编译的机器代码中恢复高级源代码并 作为漏洞检测和恶意软件分析等安全任务的基础。像 Ghidra 和 Hex-Rays 这样的传统反编译器会将它们无法解析的任何内容公开为可见占位符，并且经常会发出无法编译或执行的伪代码；基于 LLM 的反编译器生成干净、惯用的 C，现在几乎完全通过可重编译性和可重执行性来判断：输出是否构建并通过其附带的输入/输出测试。我们表明，这些指标可能会奖励错误的路径：一个函数可能会重新编译并通过每个已发布的测试，但在其他合法输入上会出现分歧，并且公开的漏洞可能会从重新编译的代码中消失，而没有明显的崩溃痕迹。现有套件不会捕获这两种故障。Decompilation recovers high-level source from compiled machine code and serves as a foundation for security tasks such as vulnerability detection and malware analysis. Traditional decompilers like Ghidra and Hex-Rays expose whatever they cannot resolve as visible placeholders and often emit pseudocode that will not compile or execute; LLM-based decompilers produce clean, idiomatic C and are now judged almost entirely by recompilability and re-executability: whether the output builds and passes its shipped input/output tests. We show that these metrics can reward the wrong path: a function may recompile and pass every shipped test yet diverge on other legitimate inputs, and a disclosed vulnerability may disappear from the recompiled code with no visible trace of the crash. Neither failure is caught by existing suites.

为了解决这一差距，我们提出了 Decompile-Diverge，这是一种不依赖于固定或手工测试的行为比较预言机：它为每个函数合成一个驱动程序，从参考中生成一个模糊语料库，并在相同的输入上重新运行反编译代码以检测函数行为的变化。在已建立的 LLM 反编译语料库上的 9 个配置的 8 个系统中，通过每次发布测试的候选者仍然与我们输入语料库中的原始版本存在差异：总体为 4.9%，单个系统高达 13%。在 300 个真实的 GitHub 库函数和 287 个基于 CVE 的函数上，可重编译性和行为一致性可能会分崩离析：最强的细化 LLM 将 Ghidra 的构建率从 75% 提升到 90%，而其匹配率从 74% 下降到 62%；对于已披露的漏洞，多达十分之一在其输出中显示崩溃缺失。源代码级分析将这种差异追溯到引入的字段、类型、被调用者和守卫，这些字段、类型、被调用者和守卫取代了传统工具留下的可见未知数。To address this gap, we propose Decompile-Diverge, a behavioral comparison oracle not relying on fixed or hand-crafted tests: for each function it synthesizes a driver, grows a fuzzing corpus from the reference, and reruns the decompiled code on the same inputs to detect changes in the function’s behavior. Across eight systems in nine configurations on established LLM decompilation corpora, candidates that pass every shipped test still diverge from the original on our input corpus: 4.9% overall, and as many as 13% for a single system. On 300 real GitHub library functions and 287 CVE-grounded functions, recompilability and behavioral agreement can come apart: the strongest refinement LLM lifts Ghidra’s build rate from 75% to 90%, while its Matched rate falls from 74% to 62%; on disclosed vulnerabilities, up to one tenth exhibit Crash Absence in its output. Source-level analysis traces this divergence to introduced fields, types, callees, and guards that replace the visible unknowns traditional tools leave behind.

1 简介Introduction

反编译是安全和软件工程的基础，可促进安全审计、漏洞分类、遗留软件维护和恶意软件分析等关键任务。随着反编译代码被集成到活动代码库中并进行模糊测试，与原始代码的行为一致性与可读性一样重要。传统反编译器，如 GhidraDecompilation serves as a foundation in both security and software engineering, facilitating critical tasks such as security auditing, vulnerability triage, legacy software maintenance, and malware analysis. As decompiled code is being integrated in active codebases and subjected to fuzzing, behavioral agreement with the original is as critical as readability. 受这种测量差距的启发，我们提出了反编译发散。该框架通过合成驱动程序、从参考函数生成模糊输入语料库、并将反编译代码的有界可观察后状态的摘要与原始代码的相应摘要进行比较来自动进行评估。基于 LLM 的反编译器和原始前端基线都通过该管道通过两个不同的轨道进行评估：行为协议的通用轨道和用于漏洞保存的通用漏洞和暴露 (CVE) 轨道。我们的分析揭示了失败模式的重大转变：传统工具会产生可见的未知数，而法学硕士往往会发明部分代码，这些代码要么会破坏编译，要么会导致行为分歧。Motivated by this measurement gap, we propose Decompile-Diverge. This framework automates evaluation by synthesizing a driver, generating a corpus of fuzzed inputs from the reference function, and comparing a digest of the decompiled code’s bounded observable post-state with the corresponding digest from the original. Both LLM-based decompilers and raw front-end baselines are evaluated through this pipeline via two distinct tracks: a general track for behavioral agreement, and a Common Vulnerabilities and Exposures (CVE) track for vulnerability preservation. Our analysis reveals a major shift in failure modes: whereas traditional tools yield visible unknowns, LLMs tend to invent part of the code that either breaks compilation or results in behavioral divergence.

6 结论Conclusion

Decompile-Diverge 根据源自参考函数的模糊器生成的输入以及精确的拼接程序构建了一个行为比较预言机，将行为一致性的评估扩展到无需发布测试的函数。在真实和易受攻击的代码中，结果表明可重编译性和可重执行性无法捕获行为差异，并且源代码分析将这种差异与从可见的前端未知数到引入令牌的转变联系起来。Decompile-Diverge builds a behavioral comparison oracle from fuzzer-generated inputs derived from the reference function, together with a precise splicing procedure, extending evaluation of behavioral agreement to functions without released tests. Across real and vulnerable code, the results show that recompilability and re-executability fail to capture behavioral divergence, and source analysis connects that divergence to a shift from visible front-end unknowns to introduced tokens.
