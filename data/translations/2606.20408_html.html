3. NRT-长凳NRT-Bench

3.1. 设计要求Design Requirements

NRT-Bench 围绕四个设计要求构建。NRT-Bench is built around four design requirements.

R1：多圈自适应。R1: Multi-turn adaptivity.

基准测试必须允许对手观察早期消息的部分后果，并以此为基础调整后来的消息。这对于模拟权限欺骗、紧急操纵、逐步升级以及在会话中而不是在单个提示中展开的其他攻击是必要的。The benchmark must allow an adversary to observe partial consequences of earlier messages and condition later messages on them. This is necessary to model authority spoofing, urgency manipulation, gradual escalation, and other attacks that unfold over a session rather than in a single prompt.

R2：多智能体角色结构。R2: Multi-agent role structure.

基准测试必须评估一个团队而不是一个孤立的模型。安全关键操作取决于分工、指挥权、独立审查和交叉检查。将这种结构分解为一个辅助响应的基准无法衡量团队级别的不安全轨迹。The benchmark must evaluate a team rather than an isolated model. Safety-critical operation depends on division of labour, command authority, independent review, and cross-checking. A benchmark that collapses this structure into one assistant response cannot measure team-level unsafe trajectories.

R3：客观伤害信号。R3: Objective harm signal.

主要指标必须来自环境状态，而不是法学硕士法官对文本的解释。法学硕士法官对于诊断仍然有用，但他们不应该确定主要的身体伤害指标。The primary metric must be derived from the environment state, not from an LLM judge’s interpretation of text. LLM judges remain useful for diagnostics, but they should not determine the headline physical-harm metric.

R4：可重玩性和归因。R4: Replayability and attribution.

在固定单元配置下，相同的攻击工作负载必须能够针对不同的防御者进行重玩。成功的攻击应该归因于特定的回合，并且可以通过跟踪日志进行分解。The same attack workload must be replayable against different defenders under fixed cell configurations. Successful attacks should be attributable to a specific turn and decomposable through trace logs.

本节的其余部分描述 NRT-Bench 如何满足这些要求。The remainder of this section describes how NRT-Bench satisfies these requirements.

3.2. 环境Environment

NRT-Bench 是一个封闭的模拟，我们将其视为基准环境。在环境内部，由 LLM 支持的操作团队联合操作有状态工厂，而外部攻击者通过受限的 HTTP 接口注入消息。该堆栈在一个容器内运行，没有互联网出口，因此该场所可以安全地暴露于任意攻击代码。NRT-Bench is a closed simulation that we treat as the benchmark environment. Inside the environment, an LLM-backed operator team jointly operates a stateful plant while an external attacker injects messages through a constrained HTTP interface. The stack runs inside one container with no internet egress, so the venue is safe to expose to arbitrary attack code.

6. 讨论和限制Discussion and Limitations

护栏不能独立于其包装的型号而获得认证。Guardrails cannot be certified independently of the model they wrap.

相同的护栏堆栈可以减少一个操作员系列的 ASR，并增加另一个操作员系列的 ASR。这并不意味着护栏总体上是有害的。这意味着护栏是接口：它们取决于操作员模型发出的内容、它如何构造操作、它是否引用过程以及它如何解释权限。 “防御堆栈”形式的安全声明The same guardrail stack can reduce ASR for one operator family and increase it for another. This does not imply that guardrails are harmful in general. It implies that guardrails are interfaces: they depend on what the operator model emits, how it structures actions, whether it cites procedures, and how it interprets authority. 聚合 ASR 不足以用于部署选择。Aggregate ASR is insufficient for deployment selection.

A scalar leaderboard hides the information most relevant to deployment: whether a candidate model is weak against the attack types most plausible in the target environment. NRT-Bench therefore reports sub-goal and strategy-level metrics by design. We argue that agent-safety benchmarks should treat vulnerability as a vector over operational failure modes, not a single number.

多样性可能与个体的稳健性一样重要。Diversity may matter as much as individual robustness.

配对结果显示四个操作员的故障集基本上不相交。这表明，当与保守的否决规则相结合时，模型多样性可以提供广度防御。然而，我们的小组结果只是第 § 中讨论的一致否决阅读下的神谕式上限。The paired results show largely disjoint failure sets across four operators. A practical panel must handle latency, cost, disagreement arbitration, correlated prompts, transfer attacks, and the possibility that an adaptive attacker can identify and target the weakest panel member.

局限性。Limitations.

三个警告约束了这些主张。首先，NRT-Bench 是一个抽象的文本模拟器，而不是高保真工厂模型，因此结果说明的是对抗性多智能体协调，而不是反应堆物理。其次，攻击工作负载是固定的，并且部分是针对种子防御者生成的，因此它是重放基准，而不是最坏情况的自适应攻击者基准；配对结果仅部分缓解了这一问题，每个防守者的自适应再生仍然是未来的工作。第三，每个操作员在托管端点下的​​单个种子上进行评估，并且轮级诊断使用固定的LLM判断，因此最大的单细胞幅度（特别是（S0，G10，A1）符号翻转）应该通过重复的种子进行确认；相反，主要的跨运营商调查结果依赖于无法官的 CSF 信号和干净的计数，例如 50 中的 0 次全部四次违规结果。Three caveats bound these claims. First, NRT-Bench is an abstract textual simulator, not a high-fidelity plant model, so results speak to adversarial multi-agent coordination rather than reactor physics. Second, the attack workload is fixed and partly generated against a seed defender, so it is a replay benchmark rather than a worst-case adaptive-attacker benchmark; the paired results mitigate this only partially, and adaptive regeneration per defender remains future work. Third, each operator is evaluated at a single seed under hosted endpoints, and turn-level diagnostics use a fixed LLM judge, so the largest single-cell magnitudes (notably the (S0, G10, A1) sign-flips) should be confirmed with repeated seeds; the headline cross-operator findings instead rest on the judge-free CSF signal and clean counts such as the 0-of-50 all-four-breach result.
