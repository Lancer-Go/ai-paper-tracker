当代理协调时：When Agents Coordinate:
测量多智能体人工智能编码中的协调性Measuring Coordination in Multi-Agent AI Coding

Giuseppe Destefanis Thanks: Corresponding author: g.destefanis@ucl.ac.uk    Tomaso Aste Affiliation: Department of Computer Science, University College London, UK
摘要Abstract

我们研究人工智能编码代理团队在解决编程任务时如何协调。目前的评估通常会报告代理是否完成任务以及运行成本是多少，而团队内部的协调很大程度上无法衡量。我们引入了一种工具来直接测量这种协调。每次运行都表示为一个临时网络，其中代理和文件是节点，消息、文件写入和文件读取是带时间戳的有向边以及相关成本。我们将此工具应用于 1,902 次运行，每次运行都使用固定的测试套件进行评估，跨配置改变团队规模、团队结构和文件策略。We study how teams of AI coding agents coordinate while solving programming tasks. Current evaluations usually report whether the agents complete the task and how much the run costs, leaving the coordination inside the team largely unmeasured. We introduce an instrument to measure this coordination directly. Each run is represented as a temporal network in which agents and files are nodes, and messages, file writes, and file reads are timestamped directed edges with an associated cost. We apply this instrument to 1,902 runs, each evaluated with a fixed test suite, across configurations that vary the team size, the team structure, and the file policy.

由此产生的网络显示了协调如何随着团队的成长和工作的变化而变化。直接消息传递最初随着座席数量的增加接近二次方，其中大部分增长来自早期一轮的介绍。随着团队的进一步发展，这种增长在我们研究的最大团队中趋于平稳，其中代理越来越多地通过广播消息进行通信。编程任务还塑造了出现的网络。围绕共享规范构建的工作会产生密集、高度互联的团队，而管道任务会产生围绕本地接口组织的稀疏网络。共享文件可以取代重复的一对一通信，在八个代理处理大量消息的工作时将输出令牌减少约 42%，同时当文件已经进行协调时会增加开销。将一名代理指定为协调员不会创建任何通信中心，也不会提供可靠的成功改进。The resulting networks show how coordination changes as teams grow and as the work changes. Direct messaging initially increases close to quadratically with the number of agents, with much of this growth coming from an early round of introductions. As the teams grow further, this increase levels off in the largest teams we study, where agents increasingly communicate through broadcast messages. The programming task also shapes the network that emerges. Work built around a shared specification produces dense, highly connected teams, while pipeline tasks produce sparse networks organised around local interfaces. Shared files can replace repeated one-to-one communication, cutting output tokens by about 42% at eight agents on message-heavy work, while adding overhead when files already carry the coordination. Naming one agent as coordinator creates no communication hub and provides no reliable improvement in success.

我们还观察到代理人倾向于寻找隐藏的分级材料。我们在密封环境中重复关键实验条件，用标记的占位符文件替换隐藏材料。在额外的 244 次运行中，代理仍然在五分之四的运行中达到了目标，而协调器和文件通道的发现则重现了。We also observe an unprompted tendency for agents to seek out hidden grading material. We repeat the key experimental conditions in a sealed environment, replacing the hidden material with marked placeholder files. Across 244 additional runs, agents still reach for it in four fifths of runs, while the coordinator and file-channel findings reproduce.

重复运行还表明，在相同的配置和固定模型下，协调测量可能会有很大差异，特别是当任务让代理在如何组织方面有更大的自由度时。因此，单次运行仅给出配置协调行为的一个样本。这些结果表明，人工智能编码代理之间的协调可以直接测量，揭示任务成功和总令牌计数隐藏的结构、行为和成本。Repeated runs also show that coordination measurements can vary substantially under the same configuration and pinned model, especially when the task leaves agents more freedom in how to organise. A single run therefore gives only one sample of the coordination behaviour of a configuration. These results show that coordination among AI coding agents can be measured directly, exposing structures, behaviours, and costs that task success and aggregate token counts leave hidden.

1 简介Introduction

多智能体人工智能编码系统将编程任务分配给在共享工作空间中并行工作的多个智能体。团队是否成功以及运行成本取决于代理如何协调：他们如何划分工作、彼此告诉对方什么、共享哪些文件以及如何解决其贡献之间的接口。这些几乎都没有保留到最终代码中。一次运行可以通过每个测试，而不会留下其需要多少协调的痕迹，并且通过相同测试的两次运行在消息、文件活动和令牌方面可能有数倍的不同。Multi-agent AI coding systems assign a programming task to several agents that work in parallel in a shared workspace. Whether the team succeeds, and what the run costs, depends on how the agents coordinate: how they divide the work, what they tell each other, which files they share, and how they resolve the interfaces between their contributions. Almost none of this survives into the final code. A run can pass every test while leaving no trace of how much coordination it required, and two runs that pass the same tests can differ severalfold in messages, file activity, and tokens.

配置此类系统的开发人员必须决定团队规模、是否指定一名代理协调员以及团队是否应通过直接消息传递或通过共享文件进行协调。这些选择的影响仍然知之甚少。评估通常报告任务成功和最终代码或补丁，计算成本越来越多地被视为额外的评估维度A developer configuring such a system must decide the team size, whether to name one agent coordinator, and whether the team should coordinate through direct messaging or through shared files. The effects of these choices are still poorly understood. Evaluations typically report task success and the final code or patch, with computational cost increasingly considered as an additional evaluation dimension[19, 32, 1]，或规定哪些代理可以与哪些代理进行通信, or prescribe which agents may communicate with which[29, 16, 39]。这些措施并没有显示跑步过程中出现的协调结构。. These measures do not show the coordination structure that emerges during a run.

我们使该结构可测量。每次运行都表示为一个时间网络，其中代理和文件是节点。直接消息是代理到代理的边缘，文件写入是代理到文件的边缘，文件读取是文件到代理的边缘；每条边都带有时间戳、字节大小和令牌成本。将文件视为节点是仪器的核心。文件写入后仍然存在；一次写入可以被多个代理以任意顺序读取；其内容保留在跨代理进程的共享工作区中，并且比写入它们的会话寿命更长。因此，文件提供持久的共享状态以及一对多的通信通道。将它们表示为节点允许在同一时间线上测量文件介导的协调和直接消息传递。每条边都对应一个记录的事件，因此时间网络记录运行期间发生的协调。We make that structure measurable. Each run is represented as a temporal network in which agents and files are nodes. A direct message is an agent-to-agent edge, a file write is an agent-to-file edge, and a file read is a file-to-agent edge; every edge carries a timestamp, a byte size, and a token cost. Treating files as nodes is central to the instrument. A file persists after it is written; one write can be read by many agents in any order; and its contents remain in the shared workspace across agent processes and outlive the session that wrote them. Files therefore provide persistent shared state as well as a one-to-many communication channel. Representing them as nodes allows file-mediated coordination and direct messaging to be measured on the same timeline. Every edge corresponds to a logged event, so the temporal network records the coordination that occurred during the run.

12 结论Conclusion

多智能体人工智能编码系统通过其输出进行评估，但其成功或失败取决于其协调，而协调在输出中是不可见的。本文的贡献是使其成为一个可测量的对象：一个时间网络，其中代理和文件都是节点，并且运行时工具记录的每条消息、写入和读取都是带有时间戳、成本的边缘。该图表是该工具介导的活动的直接记录，从现有日志中收集起来成本低廉，并且可以在团队规模、配置和框架之间进行比较。Multi-agent AI coding systems are evaluated by their outputs, but they succeed or fail by their coordination, and the coordination is invisible in the output. This paper’s contribution is to make it a measured object: a temporal network in which agents and files are both nodes and every message, write, and read logged by the runtime’s tools is a timestamped, costed edge. The graph is a direct record of that tool-mediated activity, cheap to collect from existing logs, and comparable across team sizes, configurations, and frameworks.

通过这种方式衡量，开发人员面临的三种配置选择与输出级别评估建议的结果不同。沟通的二次成本是真实但肤浅的：它是一次公开握手，进行一次，之后每个代理维持几个频道，没有中心形式，并且最大的团队越来越多地转向广播和消息传递增长水平在八到十六个代理之间。文件通常被视为输出，是团队的一对多渠道，要求使用它们可以使 8 个代理执行大量消息工作时的输出令牌减少约 42%，同时增加文件已进行协调的链式工作的成本。通过提示分配的领导权只是名义上的：它没有创建任何结构，也买不到可靠的成功，八个代理冲突小组的密封复制在每个文件政策下都留下了扁平和协调员团队的水平。共同点是提示声明的内容和交互结构构建的内容可能不同，而测量的结果遵循第二个。Measured this way, the three configuration choices a developer faces come out differently from what output-level evaluation suggests. The quadratic cost of communication is real but shallow: it is an opening handshake, made once, after which each agent sustains a few channels, no hub forms, and the largest teams switch increasingly to broadcast and messaging growth levels off between eight and sixteen agents. Files, usually treated as outputs, are the team’s one-to-many channel, and requiring their use cuts output tokens by about 42% at eight agents on message-heavy work, while adding cost on chain-shaped work whose files already carry the coordination. And leadership assigned by prompt is nominal only: it creates no structure and buys no reliable success, and a sealed replication of the eight-agent conflict cells leaves flat and coordinator teams level under every file policy. The common thread is that what the prompt declares and what the interaction structure builds can differ, and the measured outcomes follow the second.

在这些选择之下，协调网络的形状是由任务决定的。如果让团队自行组织，团队不会集中在单一的协调范围内。分布式任务中，每个人都协调一个共享规范，构建一个密集的、紧密集群的图，该图沿着所有线路进行；在链式任务中，每个智能体只同意与其邻居交互，相对于 16 个智能体中 15 个智能体的小集团，其平均程度下降到 0.28，几乎没有形成任何命名消息网络。两者都没有枢纽。在我们的实验中，团队构建的结构是其所承担工作的一个属性，可以直接从图表中读取。Beneath those choices, the shape of the coordination network is set by the task. Left to organise themselves, the teams do not converge on a single coordination span. The distributed task, where everyone reconciles one shared specification, builds a dense, tightly clustered graph that rides the all-to-all line; the chained task, where each agent agrees interfaces only with its neighbours, stays sparse, down to a mean degree of 0.28 against a clique of fifteen at sixteen agents, where scarcely any named-message network forms at all. Neither has a hub. In our experiments, the structure a team builds is a property of the work it is given, read directly off the graph.

Under one pinned model, the chained task’s measurements replicate across sessions to two decimal places while the distributed task’s exponent moves from 1.76 to 2.44, so a configuration is a distribution of runs, and single-run evaluations of multi-agent systems stand on a sample of size one. The cost of that judgement is that the affected cell-level graph estimates remain less precise than the rule intended. A few hypotheses do read specific flagged cells, among them H1, H5, and H6, and their intervals should be read with that reduced precision in mind. The strict alternative of topping up every flagged cell was considered and set aside, and we record the departure here. First, the forbidden policy is a prompt clause; re-running the worst-affected cell with the workspace locked at the filesystem level produced the same workspaces and the same outcomes, so the prompt form is sound. Second, the pilot’s dominant failure traced to an ambiguous return-type clause in one specification; the clause was tightened and the worst cell re-validated (three of three passes) before the full schedules ran, leaving a cleaner outcome variable.
