摘要Abstract

自动漏洞修复旨在减少根据漏洞分类报告修补安全缺陷所需的时间和精力。最近的代理人工智能方法在自动程序修复方面显示出了有希望的结果。然而，漏洞修复需要比一般错误修复更丰富的程序上下文——安全工程师在实践中例行组装的上下文，但现有的代理方法无法设计。我们确定了三个关键差距：捕获跨文件数据流和内存操作模式的代码结构上下文、揭示崩溃语义和内存起源的运行时执行上下文、以及恢复如何引入脆弱代码模式的提交历史记录上下文。 我们呈现Automated vulnerability repair aims to reduce the time and effort required to patch security flaws from a vulnerability triage report. Recent agentic AI approaches have shown promising results in automated program repair. However, vulnerability repair demands richer program context than general bug repair — context that security engineers routinely assemble in practice but that existing agentic approaches do not engineer. We identify three critical gaps: code-structure context capturing cross-file data flows and memory operation patterns, runtime-execution context revealing crash semantics and memory origins, and commit-history context recovering how fragile code patterns were introduced. I 简介Introduction

软件漏洞是现代软件系统中最持久和最危险的威胁之一，经常导致严重的安全事件，并产生广泛的现实世界影响。与普通的软件错误不同，安全漏洞通常源于微妙的低级交互、跨文件数据流和脆弱的历史代码模式，这些模式很难正确诊断和修复。因此，修补这些缺陷仍然是一项非常耗时且需要专业知识的任务。特别是，之前的一项研究报告称，从漏洞披露到补丁部署的中位时间通常超过 70 天Software vulnerabilities represent one of the most persistent and dangerous threats in modern software systems, frequently resulting in severe security incidents with widespread real-world impact. Unlike ordinary software bugs, security vulnerabilities often originate from subtle low-level interactions, cross-file data flows, and fragile historical code patterns that are exceptionally difficult to diagnose and repair correctly. As a result, patching these flaws remains a highly time-consuming and expertise-intensive task. In particular, a prior study reports that the median time from vulnerability disclosure to patch deployment often exceeds 70 daysRoumani (2021).

Ⅱ-AII-A 基于学习的漏洞修复Learning-Based Vulnerability Repair

早期基于学习的自动漏洞修复方法将任务定义为序列到序列学习，将易受攻击的函数作为输入并生成相应的修复补丁作为输出。 VRepair 等基础工作Early learning-based automatic vulnerability repair approaches framed the task as sequence-to-sequence learning, taking a vulnerable function as input and generating the corresponding repair patch as output. Foundational works such as VRepairChen et al. (2022)和漏洞修复and VulRepairFu et al. (2022)微调的小型变压器模型（例如 CodeT5）。后来的扩展，包括 VQMfine-tuned small transformer models (e.g., CodeT5). 尽管有这些改进，所有基于学习的方法都存在严重的局限性：它们在严格的输入长度窗口下运行，将代码视为结构意识有限的平面文本序列，并且主要关注单一功能范围。因此，它们无法处理需要跨模块、标头和目录交互的跨文件或存储库级漏洞。Despite the improvements, all learning-based approaches share critical limitations: they operate under strict input-length windows, treat code as flat text sequences with limited structural awareness, and focus primarily on single-function scope. Consequently, they cannot handle cross-file or repository-level vulnerabilities that require interactions across modules, headers, and directories.
