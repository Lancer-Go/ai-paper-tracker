契约技能：企业人工智能代理的GovernSpec设计框架Contractual Skills: A GovernSpec Design Framework for Enterprise AI Agents

Ting Liu
SymbolicLight Research
Foshan, Guangdong, China
research@symboliclight.com
（2026 年 5 月）(May 2026)
摘要Abstract

技能已成为座席指令、工作流程、脚本和参考资料的实用包装机制。然而，在企业环境中，通常期望技能不仅仅能够触发相关上下文。它还必须表达输入边界、权限、人工审批点、证据要求、输出合同、质量标准、验证步骤和移交规则。当这些控件被编写为非正式的散文时，它们很难审查、重用、测试或连接到运行时护栏。本文提出Skills have become a practical packaging mechanism for agent instructions, workflows, scripts, and reference materials. In enterprise settings, however, a skill is often expected to do more than trigger relevant context. It must also express input boundaries, permissions, human approval points, evidence requirements, output contracts, quality criteria, verification steps, and handoff rules. When these controls are written as informal prose, they are difficult to review, reuse, test, or connect to runtime guardrails. This paper proposes合同技能contractual skills，一个组织的设计框架, a design framework that organizes技能.mdSKILL.md具有 GovernSpec 风格的任务合同字段的文件，同时保留技能的轻量级发现和渐进式加载属性。该框架将技能定位为可读的任务契约，而不是自由格式的提示片段。它还澄清了合同技能、GovernSpec YAML 合同、模型上下文协议 (MCP) 表面、工具适配器、运行时护栏、跟踪和评估系统之间的界限。files with GovernSpec-style task contract fields while preserving the lightweight discovery and progressive-loading properties of skills. The framework positions a skill as a readable task contract rather than as a free-form prompt fragment. It also clarifies the boundary between contractual skills, GovernSpec YAML contracts, Model Context Protocol (MCP) surfaces, tool adapters, runtime guardrails, tracing, and evaluation systems.

我们通过两个离线实验评估该框架。文本生成实验涵盖了3个企业技能、15个综合任务、4个指令条件和8个生成模型，产生了960个输出和1680个交叉评判评分记录。在所有八个模型中，合同技能的平均模型评判分数都高于无技能和最低技能基线。与包含类似信息但缺少契约字段的普通扩展技能相比，契约技能在六个模型上略高，在两个模型上略低，差异较小。工具调用挑战实验涵盖了 8 个模型和 192 条模拟工具调用记录。技能通常会减少高风险工具的尝试，但效果因模型而异；合同技能并不能取代工具级护栏。结果表明，合同技能作为治理层最有用，可以明确任务意图、边界和验收标准，而不是作为独立的安全机制。We evaluate the framework with two offline experiments. The text-generation experiment covers three enterprise skills, fifteen synthetic tasks, four instruction conditions, and eight generation models, producing 960 outputs and 1680 cross-judge score records. Contractual skills receive higher mean model-judge scores than the no-skill and minimal-skill baselines on all eight models. Compared with a plain expanded skill that contains similar information but lacks contract fields, contractual skills are slightly higher on six models and slightly lower on two models, with small differences. The tool-calling challenge experiment covers eight models and 192 simulated tool-call records. Skills usually reduce high-risk tool attempts, but the effect varies by model; contractual skills do not replace tool-level guardrails. The results suggest that contractual skills are most useful as a governance layer for making task intent, boundaries, and acceptance criteria explicit, rather than as a standalone safety mechanism.

1 简介Introduction

大型语言模型应用程序正在从单轮问答转向读取文件、调用工具、检索知识、生成工件和协调多步骤工作流程的代理系统。在企业环境中，代理商越来越多地参与销售跟进、售前解决方案起草、合同审查、交付管理、客户成功、知识运营、财务检查和代码审查。这些工作流程结合了业务环境、组织规则、面向客户的承诺、隐私约束、外部系统和人工审批。因此，他们需要的不仅仅是流畅的文本生成。Large language model applications are moving from single-turn question answering toward agent systems that read files, call tools, retrieve knowledge, generate artifacts, and coordinate multi-step workflows. In enterprise settings, agents increasingly participate in sales follow-up, pre-sales solution drafting, contract review, delivery management, customer success, knowledge operations, finance checks, and code review. These workflows combine business context, organizational rules, customer-facing commitments, privacy constraints, external systems, and human approval. They therefore require more than fluent text generation.

技能是封装可重用代理能力的常用方式。技能通常由一个目录组成Skills are a common way to package reusable agent capabilities. A skill usually consists of a directory with a技能.mdSKILL.md文件。它的 frontmatter 提供了发现元数据，例如file. Its frontmatter provides discovery metadata such as姓名name和and描述description;正文提供任务指导、工作流程、参考，有时还提供脚本。 Anthropic 的代理技能文档将技能描述为模型在相关时可以使用的指令、可执行代码和资源的模块化包; the body provides task guidance, workflows, references, and sometimes scripts. Anthropic’s Agent Skills documentation describes skills as modular packages of instructions, executable code, and resources that the model can use when relevant[1]。这种设计很有吸引力，因为它是本地的、可检查的，并且与渐进加载兼容。. This design is attractive because it is local, inspectable, and compatible with progressive loading.

然而，企业技能通常需要表达的不仅仅是任务建议。销售增长技能不应该仅仅告诉代理如何分析客户帐户；还应该告诉代理如何分析客户帐户。它还应防止代理商承诺价格、交货日期、最终折扣条款或保证结果。财务合同技能应该将事实与假设分开，确定批准点，并明确草案何时不是具有约束力的承诺。代码审查技能应该优先考虑行为风险，避免不相关的编辑，并说明测试差距。换句话说，企业技能必须编码任务目标、行为边界和接受标准。Yet enterprise skills often need to express more than task advice. A sales-growth skill should not merely tell an agent how to analyze a customer account; it should also prevent the agent from promising prices, delivery dates, final discount terms, or guaranteed outcomes. A finance-contract skill should separate facts from assumptions, identify approval points, and make clear when a draft is not a binding commitment. A code-review skill should prioritize behavioral risks, avoid unrelated edits, and state test gaps. In other words, enterprise skills must encode task goals, behavioral boundaries, and acceptance criteria.

本文提出This paper proposes合同技能contractual skills。合同技能仍然是. A contractual skill is still a技能.mdSKILL.md文件，但其主体被组织为任务契约。推荐的部分包括目标、受众、输入、上下文、工作流程、权限、人门、约束、证据、输出、质量栏、验证和移交。该术语的起源是GovernSpec，这是一个用于人工智能任务治理的本地优先合约编译器。在之前的工作中，file, but its body is organized as a task contract. The recommended sections include goal, audience, inputs, context, workflow, permissions, human gates, constraints, evidence, output, quality bar, verification, and handoff. The term is motivated by GovernSpec, a local-first contract compiler for AI task governance. In prior work,Liu [6]引入了 GovernSpec 作为独立于运行时的工作流程，用于验证单个任务治理契约，将其编译为多个代理工件，导入现有工件，并使用离线断言检查输出。本文重点关注技能层：如何将相同的面向契约的规则引入到代理实际加载为功能的 Markdown 文件中。introduced GovernSpec as a runtime-independent workflow that validates a single task-governance contract, compiles it into multiple agent artifacts, imports existing artifacts, and checks outputs with offline assertions. This paper focuses on the skill layer: how to bring the same contract-oriented discipline into the Markdown files that agents actually load as capabilities.

核心主张是温和的。契约技能并不能使模型本质上安全，也不能取代运行时权限检查。它们的价值在于使任务契约变得明确且可审查。它们帮助模型、维护者和评估者在决定需要哪些输入、允许哪些操作、哪些证据是充分的、预期的输出形状以及何时必须移交或暂停工作以供人工审查时参考相同的字段。The central claim is modest. Contractual skills do not make a model inherently safe, nor do they replace runtime permission checks. Their value is to make the task contract explicit and reviewable. They help the model, the maintainer, and the evaluator refer to the same fields when deciding what inputs are required, which actions are allowed, what evidence is sufficient, what output shape is expected, and when work must be handed off or paused for human review.

  2. 2.

  3. 3.

    它澄清了合同技能、GovernSpec YAML、MCP、工具适配器、运行时护栏、跟踪和评估之间的界限。It clarifies the boundary between contractual skills, GovernSpec YAML, MCP, tool adapters, runtime guardrails, tracing, and evaluation.

  4. 4.

    它报告了一个多模型文本生成实验，有 960 个输出和 1680 个交叉评判记录。It reports a multi-model text-generation experiment with 960 outputs and 1680 cross-judge records.

  5. 5.

2 背景及相关工作Background and Related Work

2.1 代理技能和渐进加载Agent skills and progressive loading

代理技能将指令、脚本和资源打包到可重用的单元中。 frontmatter 帮助代理决定何时加载技能，而 body 和辅助文件则提供特定于任务的指导。这对于文档工作流程、特定领域的分析、编码约定和企业程序非常有用。核心好处是上下文经济：代理不需要执行主提示中的每条指令。Agent skills package instructions, scripts, and resources into reusable units. The frontmatter helps the agent decide when to load the skill, while the body and auxiliary files provide task-specific guidance. This is useful for document workflows, domain-specific analysis, coding conventions, and enterprise procedures. The core benefit is context economy: the agent does not need to carry every instruction in the main prompt.

然而，轻量级的技能格式也可能隐藏重要的治理信息。有关客户承诺、隐私、人工批准、源质量和输出接受的规则可能分散在散文段落中。当技能库在销售、财务、交付、风险、客户成功和工程方面不断增长时，维护人员需要一种方法来审核每种技能是否包含相关边界。However, a lightweight skill format can also hide important governance information. Rules about customer commitments, privacy, human approval, source quality, and output acceptance may be scattered across prose paragraphs. When a skill library grows across sales, finance, delivery, risk, customer success, and engineering, maintainers need a way to audit whether each skill contains the relevant boundaries.

最近的实证和安全研究使这一治理问题更加具体。Recent empirical and security studies make this governance problem more concrete.Ling et al. [5]分析 40,285 种公开列出的 Claude 技能，并报告生态系统冗余、软件工程工作流程的集中度以及重要的安全风险，包括状态更改或系统级操作。analyze 40,285 publicly listed Claude skills and report ecosystem redundancy, concentration in software engineering workflows, and non-trivial safety risks including state-changing or system-level actions.Li et al. [3]研究代理技能生命周期并识别结构性风险，例如薄弱的数据指令分离和持久的信任假设。study the Agent Skills lifecycle and identify structural risks such as weak data-instruction separation and persistent trust assumptions.Duan et al. [2]表明即使是看似良性的技能也可能在对抗性提示下暴露可利用的漏洞。这些研究激发了对技能水平结构、可审查性和运行时分离的需求，这是合同技能的核心问题。show that even apparently benign skills can expose exploitable vulnerabilities under adversarial prompting. These studies motivate the need for skill-level structure, reviewability, and runtime separation, which are central concerns of contractual skills.

2.2 GovernSpec 和工件级治理GovernSpec and artifact-level governance

GovernSpec 将 AI 任务描述为显式 YAML 合约。合约可以指定任务目标、权限、约束、确认门、输出要求和确定性验收测试。 Liu 的 SSRN 论文将 GovernSpec 定义为独立于运行时的工件级治理：团队可以维护一个治理合约并将其编译为下游工件，而无需修改每个代理运行时GovernSpec describes AI tasks as explicit YAML contracts. A contract can specify a task goal, permissions, constraints, confirmation gates, output requirements, and deterministic acceptance tests. Liu’s SSRN paper frames GovernSpec as runtime-independent artifact-level governance: teams can maintain one governance contract and compile it into downstream artifacts without modifying each agent runtime[6].

契约技能重用了这个想法，但针对的是不同的工件。 GovernSpec YAML 是可以验证和编译的结构化事实来源。契约技能是代理可以直接加载的人类可读的指令工件。两者可以独立使用，但最强大的工作流程是让高风险技能源自 GovernSpec 合同或与 GovernSpec 合同保持一致。Contractual skills reuse this idea but target a different artifact. GovernSpec YAML is a structured source of truth that can be validated and compiled. A contractual skill is a human-readable instruction artifact that an agent can load directly. The two can be used independently, but the strongest workflow is to let high-risk skills derive from or remain aligned with a GovernSpec contract.

2.3 工具调用、护栏和追踪Tool calling, guardrails, and tracing

工具调用允许模型通过结构化调用与外部系统交互。 OpenAI 将函数调用描述为模型与外部系统交互并访问模型本身外部数据的一种方式Tool calling allows a model to interact with external systems through structured calls. OpenAI describes function calling as a way for models to interface with external systems and access data outside the model itself[8]。在代理系统中，工具调用可以与切换、状态、护栏和跟踪相结合。 Guardrails 可以检查或阻止输入、输出或工具调用. In agent systems, tool calls may be combined with handoffs, state, guardrails, and traces. Guardrails can check or block inputs, outputs, or tool calls[9]。跟踪记录模型生成、工具调用、切换、护栏和自定义事件. Tracing records model generations, tool calls, handoffs, guardrails, and custom events[10].

契约技能并不能取代这些运行时机制。技能可以规定未经人工确认不得执行折扣批准，但工具适配器仍必须强制执行该策略。该技能告诉模型和维护者应该发生什么；适配器和护栏决定了会发生什么。Contractual skills do not replace these runtime mechanisms. A skill can state that a discount approval must not be executed without human confirmation, but the tool adapter must still enforce that policy. The skill tells the model and maintainer what should happen; the adapter and guardrail determine what can happen.

2.4 MCP 和结构化能力暴露MCP and structured capability exposure

模型上下文协议 (MCP) 为服务器提供了一种向客户端公开提示、资源和工具的标准化方法The Model Context Protocol (MCP) provides a standardized way for servers to expose prompts, resources, and tools to clients[7]。 MCP 是面向运行时的协议表面。契约技能是指导和治理的表面。它们是互补的：合同技能可以描述何时使用 MCP 工具、需要哪些输入以及何时应阻止或升级呼叫。. MCP is a runtime-facing protocol surface. A contractual skill is an instruction and governance surface. They are complementary: a contractual skill can describe when to use MCP tools, what inputs are required, and when a call should be blocked or escalated.

2.5 推理、行动和评估Reasoning, acting, and evaluation

ReAct 表明，语言模型可以交织推理轨迹和特定于任务的操作，从而允许模型根据观察来更新计划ReAct showed that language models can interleave reasoning traces and task-specific actions, allowing the model to update plans based on observations[11]。企业代理需要类似的循环，但有组织限制。如果证据不足，代理人应当说明。如果某项操作具有高风险，则应暂停。如果任务跨越角色边界，则应进行移交。. Enterprise agents need a similar loop, but with organizational constraints. If evidence is insufficient, the agent should say so. If an action is high-risk, it should pause. If the task crosses a role boundary, it should hand off.

评价也需要是多维度的。 HELM 主张跨场景和指标进行广泛、透明的评估Evaluation also needs to be multidimensional. HELM argues for broad, transparent evaluation across scenarios and metrics[4]。对于企业代理来说，单一的准确度分数是不够的。因此，我们评估结构、风险控制、证据质量、输出可用性、切换清晰度、维护一致性、严重错误和工具调用行为。. For enterprise agents, a single accuracy score is insufficient. We therefore evaluate structure, risk control, evidence quality, output usability, handoff clarity, maintenance consistency, critical errors, and tool-call behavior.

3 问题定义Problem Definition

3.1 非正式技能的限制Limits of informal skills

非正式技能通常包含发现元数据和散文指导。这适用于低风险任务，但企业设置会暴露出五个重复出现的限制。An informal skill usually contains discovery metadata and prose guidance. This works for low-risk tasks, but enterprise settings expose five recurring limitations.

首先，输入边界不明确。一项技能可能会说“阅读客户上下文”，但没有定义必需的输入、可选的输入、丢失数据行为或隐私类别。代理可以从不完整的上下文中产生自信的推荐。First, input boundaries are unclear. A skill may say “read the customer context” without defining required inputs, optional inputs, missing-data behavior, or privacy class. The agent may produce confident recommendations from incomplete context.

其次，权限不明确。一项技能可能会提到代理商不应承诺价格或删除文件，但此类规则被埋藏在散文中。当工具包括电子邮件、CRM 更新、合同编辑、文件写入或部署操作时，分散的提醒是不够的。Second, permissions are not explicit. A skill may mention that the agent should not promise a price or delete files, but such rules are buried in prose. When tools include email, CRM updates, contract editing, file writes, or deployment actions, scattered reminders are not enough.

第三，人的认可点不稳定。价格承诺、折扣批准、生产变更、外部消息和破坏性操作通常需要人工确认。如果没有明确的人门部分，模型可能无法检测到暂停点。Third, human approval points are unstable. Price commitments, discount approval, production changes, external messages, and destructive operations often require human confirmation. Without an explicit human-gates section, the model may fail to detect the pause point.

第四，证据政策薄弱。研究、风险审查和客户分析需要区分事实、假设、推论和建议。如果没有专门的证据部分，就更有可能出现未经证实的确定性。Fourth, evidence policy is weak. Research, risk review, and customer analysis require a distinction between facts, assumptions, inferences, and recommendations. Without a dedicated evidence section, unsupported certainty becomes more likely.

第五，输出接受度取决于人类的默认期望。技能可能会要求提供客户资料、风险和后续步骤，但不会定义所需的部分、模式、字数限制或验证标准。然后输出会随着任务和模型的变化而变化。Fifth, output acceptance depends on tacit human expectations. A skill may ask for a customer profile, risks, and next steps, but not define required sections, schema, word limit, or verification criteria. Outputs then drift across tasks and models.

3.2 企业治理边界Enterprise governance boundaries

企业代理在组织工作流程内运行。他们的产出可以影响客户期望、合同范围、财务决策、交付计划和工程责任。因此，一项技能需要定义至少五个边界：Enterprise agents operate inside organizational workflows. Their outputs can influence customer expectations, contract scope, finance decisions, delivery planning, and engineering responsibility. A skill therefore needs to define at least five boundaries:

  • •

    客户承诺边界，例如价格、范围、交付时间和保证的结果；customer commitment boundaries, such as price, scope, delivery time, and guaranteed outcomes;

  • •

    隐私和数据边界，例如联系信息、财务数据、内部项目问题和敏感凭证；privacy and data boundaries, such as contact information, financial data, internal project issues, and sensitive credentials;

  • •

    证据边界，例如事实、假设、推论和未经支持的主张；evidence boundaries, such as facts, assumptions, inference, and unsupported claims;

  • •

    工具边界，例如只读工具、草稿生成工具、外部写入工具和破坏性工具；tool boundaries, such as read-only tools, draft-generating tools, external write tools, and destructive tools;

  • •

    角色边界，例如销售何时应移交给售前、财务、风险、交付或工程。role boundaries, such as when sales should hand off to pre-sales, finance, risk, delivery, or engineering.

3.3 从提示片段到组织资产From prompt fragments to organizational assets

当团队只有少量技能时，非正式的 Markdown 可能就足够了。当公司在多个业务领域保持技能时，技能就成为组织资产。资产必须是可检查、可审查、可重用和可测试的。契约技能将治理信息放在稳定的部分，以便维护人员可以快速检查技能是否有输入要求、权限边界、证据策略、输出期望和验证标准。When a team has only a few skills, informal Markdown may be enough. When a company maintains skills across many business lines, skills become organizational assets. Assets must be inspectable, reviewable, reusable, and testable. Contractual skills put governance information in stable sections so that maintainers can quickly check whether a skill has input requirements, permission boundaries, evidence policy, output expectations, and verification criteria.

4 合同技能框架The Contractual Skill Framework

4.1 设计原则Design principles

合同技能遵循六个原则。Contractual skills follow six principles.

  1. 1.

    保留技能的轻量级发现机制。前面的内容仍然很小并且以触发为导向。Preserve the lightweight discovery mechanism of skills. The frontmatter remains small and trigger-oriented.

  2. 2.

    使用字段来明确执行边界，而不是制造官僚主义。并不是每项技能都需要每一个领域。Use fields to clarify execution boundaries, not to create bureaucracy. Not every skill needs every field.

  3. 3.

    明确高风险规则。许可、人为大门、证据和交接不应该隐藏在长篇散文中。Make high-risk rules explicit. Permissions, human gates, evidence, and handoff should not be hidden in long prose.

  4. 4.

    将技能指令与运行时执行分开。技能表达意图；适配器、护栏和权限强制执行行为。Separate skill instructions from runtime enforcement. Skills express intent; adapters, guardrails, and permissions enforce behavior.

  5. 5.

    支持逐步采用。团队可以从重写现有技能开始，然后为高风险工作流程添加 GovernSpec YAML 和离线测试。Support gradual adoption. Teams can start by rewriting existing skills, then add GovernSpec YAML and offline tests for high-risk workflows.

  6. 6.

    支持评价。字段应映射到检查，例如必填部分、禁止的承诺、隐私泄露、不确定性标记和移交完整性。Support evaluation. Fields should map to checks such as required sections, forbidden commitments, privacy leakage, uncertainty marking, and handoff completeness.

4.3 模板变体Template variants

不同的技能不应该共享一个僵化的模板。业务流程技能，例如销售增长、客户成功、交付管理、财务合同审查、风险审查和质量验收，都受益于完整的模板。工具操作技能，例如浏览器自动化、文档处理、云CLI使用、Playwright或Sentry检查，应强调工具契约、危险操作、故障排除和验证。研究分析技能应强调来源政策、证据和不确定性处理。编码技能应强调存储库上下文、变更策略、测试、风险和验证。内容制作技巧应强调受众、声音、结构和审查清单。多代理技能应强调角色、交接、工具边界和评估。Different skills should not share a single rigid template. Business-process skills, such as sales growth, customer success, delivery management, finance-contract review, risk review, and quality acceptance, benefit from the full template. Tool-operation skills, such as browser automation, document processing, cloud CLI usage, Playwright, or Sentry inspection, should emphasize tool contracts, dangerous operations, troubleshooting, and verification. Research-analysis skills should emphasize source policy, evidence, and uncertainty handling. Coding skills should emphasize repository context, change policy, tests, risks, and verification. Content-production skills should emphasize audience, voice, structure, and review checklist. Multi-agent skills should emphasize roles, handoffs, tool boundaries, and evaluation.

4.4 与GovernSpec、MCP和运行时控制的边界Boundary with GovernSpec, MCP, and runtime controls

合同技能和 GovernSpec YAML 相关但不相同。 GovernSpec YAML 是一个结构化、可验证、可编译的源合约。契约技能是 Markdown 指令工件。团队可以使用技能优先的工作流程、GovernSpec 优先的工作流程或双轨工作流程，其中高风险技能得到双方的支持Contractual skills and GovernSpec YAML are related but not identical. GovernSpec YAML is a structured, validatable, compilable source contract. A contractual skill is a Markdown instruction artifact. A team may use a skill-first workflow, a GovernSpec-first workflow, or a dual-track workflow in which high-risk skills are backed by both治理.yamlgovern.yaml和and技能.mdSKILL.md.

合同技能也不同于 MCP 和运行时护栏。 MCP 公开提示、资源和工具。工具适配器强制执行架构、权限和错误处理。护栏阻止不安全或无效行为。追踪记录发生的事情。契约技能提供了这些系统可以与之保持一致的语义契约，但不应将其视为执行层。Contractual skills also differ from MCP and runtime guardrails. MCP exposes prompts, resources, and tools. Tool adapters enforce schemas, permissions, and error handling. Guardrails block unsafe or invalid behavior. Tracing records what happened. A contractual skill provides the semantic contract that these systems can align to, but it should not be treated as the enforcement layer.

5.1 研究问题Research questions

这些实验解决了四个研究问题。The experiments address four research questions.

RQ1

合同技能是否可以改善产出结构和可检查性？Do contractual skills improve output structure and checkability?

RQ2

合同技能是否可以减少未经批准的承诺、隐私泄露、薄弱证据或危险的工具尝试？Do contractual skills reduce unapproved commitments, privacy leakage, weak evidence, or risky tool attempts?

合同技能是否可以提高维护一致性和交接清晰度？Do contractual skills improve maintenance consistency and handoff clarity?

RQ4

文本生成和工具调用任务从契约结构中获益是否不同？Do text-generation and tool-calling tasks benefit differently from contractual structure?

7 讨论Discussion

7.1 为什么合同技能有帮助Why contractual skills help

合同技能有助于减少歧义。在非正式技能中，目标、约束、证据政策和输出要求在散文中争夺注意力。合同技能将它们分为可预测的部分。这使得模型更有可能在其响应中保留这些要求，并且审阅者或检查者更有可能检测到遗漏。Contractual skills help by reducing ambiguity. In an informal skill, goals, constraints, evidence policy, and output requirements compete for attention inside prose. A contractual skill separates them into predictable sections. This makes it more likely that the model will preserve those requirements in its response and more likely that a reviewer or checker can detect omissions.

该框架还将隐性组织知识转变为可见的工件。诸如“销售不得批准折扣”、“合同范围变更需要审查”、“未经确认不得承诺交货日期”以及“事实必须与推论分开”等规则通常为人们所熟知，但在模型可读的说明中却缺失。契约技能提供了一种轻量级的方式来公开这些规则，而无需立即构建完整的治理平台。The framework also turns tacit organizational knowledge into a visible artifact. Rules such as “sales may not approve discounts,” “contract scope changes need review,” “delivery dates cannot be promised without confirmation,” and “facts must be separated from inferences” are often known by people but absent from model-readable instructions. Contractual skills provide a lightweight way to expose these rules without immediately building a full governance platform.

7.2 企业资产管理Enterprise asset management

如果技能成为长期的企业资产，组织就需要管理发现、安全使用和评估。实用的分层是：If skills become long-lived enterprise assets, organizations need to manage discovery, safe use, and evaluation. A practical layering is:

  • •

    全球存储库或组织规则定义了广泛的安全和协作规范；global repository or organization rules define broad safety and collaboration norms;

  • •

    合同技能定义了能力级别的任务合同；contractual skills define capability-level task contracts;

  • •

    GovernSpec YAML 为高风险工作流程提供可验证、可编译的源合同；GovernSpec YAML provides validatable and compilable source contracts for high-risk workflows;

  • •

    MCP和工具适配器在结构化模式和权限下连接真实系统；MCP and tool adapters connect real systems under structured schemas and permissions;

  • •

    护栏和审批工作流程强制执行运行时边界；guardrails and approval workflows enforce runtime boundaries;

  • •

    跟踪和评估套件监控部署后的行为。traces and evaluation suites monitor behavior after deployment.

这种分层避免了两个极端。一种极端是将所有规则放在一个大型系统提示中，这会变得难以维护。另一种是仅依赖于运行时权限，这可能会阻止不安全的操作，但不会告诉代理何时暂停、移交或将证据标记为不足。This layering avoids two extremes. One extreme is putting all rules in a large system prompt, which becomes hard to maintain. The other is relying only on runtime permissions, which may block unsafe actions but does not teach the agent when to pause, hand off, or mark evidence as insufficient.

7.3 何时使用完整模板When to use the full template

完整的合同模板对于高风险、多次交接、格式敏感或验收驱动的工作流程最有用：销售跟进、售前解决方案起草、合同审查、风险审查、交付报告、质量验收、客户成功和知识库变更。研究分析任务也受益，因为它们需要证据和不确定性纪律。当存储库边界、测试和更改范围必须明确时，编码任务就会受益。The full contractual template is most useful for high-risk, multi-handoff, format-sensitive, or acceptance-driven workflows: sales follow-up, pre-sales solution drafting, contract review, risk review, delivery reporting, quality acceptance, customer success, and knowledge-base changes. Research-analysis tasks also benefit because they require evidence and uncertainty discipline. Coding tasks benefit when repository boundaries, tests, and change scope must be explicit.

并非所有技能都需要完整的模板。一次性、低风险、无工具、无固定输出的任务可能无法证明这种开销是合理的。命令参考、API 注释和简单的文档转换可以使用简化的模板。如果官方或缓存的插件技能破坏了更新机制，则不应直接重写。Not every skill needs the full template. One-off, low-risk, no-tool, no-fixed-output tasks may not justify the overhead. Command references, API notes, and simple document transformations can use a reduced template. Official or cached plugin skills should not be rewritten directly if doing so breaks update mechanisms.

8 有效性的威胁Threats to Validity

该研究有五个主要局限性。The study has five main limitations.

首先，任务范围小。它包括三个技能系列和十五个合成文本任务，以及一个小型工具调用挑战。结果不应推广到所有企业工作流程。First, the task set is small. It includes three skill families and fifteen synthetic text tasks, plus a small tool-calling challenge. The results should not be generalized to all enterprise workflows.

其次，评分采用模范评委。交叉评判减少了同模型的自我评价偏差，但它并不能取代专家的人工审查。未来的工作应包括人类评估者和评估者间的协议。Second, scoring uses model judges. Cross-judging reduces same-model self-evaluation bias, but it does not replace expert human review. Future work should include human raters and inter-rater agreement.

第三，工具调用实验是离线的、模拟的。真实的企业系统包括状态、权限、审核日志、并发、重试和部分失败。这些因素可能会改变行为。Third, the tool-calling experiment is offline and simulated. Real enterprise systems include state, permissions, audit logs, concurrency, retries, and partial failures. These factors may change behavior.

第四，型号版本变化。结果描述了测试模型在 2026 年 5 月 API 条件和提示下的行为。后续版本可能有所不同。Fourth, model versions change. The results describe the behavior of the tested models under the May 2026 API conditions and prompts. Later versions may differ.

第五，现场模型本身是临时的。不同的组织可能需要重命名、合并、拆分或扩展字段。Fifth, the field model itself is provisional. Different organizations may need to rename, merge, split, or extend fields.

9 结论Conclusion

本文介绍了契约技能，这是一种用于企业代理技能的 GovernSpec 风格的设计框架。该框架将技能视为任务合同，指定目标、输入、权限、人门、证据、输出、质量标准、验证和移交。它不会取代 GovernSpec YAML、MCP、工具适配器、护栏或跟踪。相反，它提供了一个可读的治理层，使模型、维护者和评估者围绕相同的任务语义保持一致。This paper introduced contractual skills, a GovernSpec-style design framework for enterprise agent skills. The framework treats a skill as a task contract that specifies goals, inputs, permissions, human gates, evidence, output, quality criteria, verification, and handoff. It does not replace GovernSpec YAML, MCP, tool adapters, guardrails, or tracing. Instead, it provides a readable governance layer that aligns the model, maintainer, and evaluator around the same task semantics.

实验提供了初步证据。在文本生成任务中，在八个模型中，契约技能比无技能和最低技能基线获得更高的平均模型判断分数，并提高结构一致性、证据表达和交接清晰度。与信息丰富的普通扩展技能相比，分数优势较小且不具有普遍性，这表明契约字段主要提高可检查性和可维护性。在工具调用任务中，技能通常会减少高风险的工具尝试，但运行时强制仍然是必要的。The experiments provide initial evidence. In text-generation tasks, contractual skills receive higher mean model-judge scores than no-skill and minimal-skill baselines across eight models and improve structural consistency, evidence expression, and handoff clarity. Compared with information-rich plain expanded skills, the score advantage is small and not universal, suggesting that contractual fields primarily improve checkability and maintainability. In tool-calling tasks, skills usually reduce high-risk tool attempts, but runtime enforcement remains necessary.

随着企业代理从原型转向操作工作流程，技能将成为组织资产而不是提示片段。合同技能提供了一条使这些资产可审查、可重用和可测试的轻量级途径。As enterprise agents move from prototypes to operational workflows, skills will become organizational assets rather than prompt snippets. Contractual skills offer a lightweight path toward making those assets reviewable, reusable, and testable.
