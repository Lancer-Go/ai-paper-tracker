摘要Abstract

空间推理、确定对象的位置、它们之间的关系以及它们如何在 3D 中移动的能力，仍然是视觉语言模型 (VLM) 的基本挑战。 工具增强代理试图通过用专业感知模块增强 VLM 来解决这个问题，但其有效性受到以下限制：Spatial reasoning, the ability to determine where objects are, how they relate, and how they move in 3D, remains a fundamental challenge for vision-language models (VLMs). Tool-augmented agents attempt to address this by augmenting VLMs with specialist perception modules, yet their effectiveness is bounded by the动作界面action interface通过它调用这些工具。 在这项工作中，我们研究了该界面的设计如何塑造代理的开放式空间推理能力。 现有的空间代理要么采用单遍代码执行，在观察任何中间结果之前致力于完整的分析策略，要么依赖结构化的工具调用接口，该接口通常为自由组合操作或针对每个任务定制分析提供较低的灵活性。这两种设计都为开放式、复杂的 3D/4D 空间推理提供了有限的灵活性。 因此我们建议through which those tools are invoked. In this work, we study how the design of this interface shapes the agent’s capacity for open-ended spatial reasoning. Existing spatial agents either employ single-pass code execution, which commits to a full analysis strategy before any intermediate result is observed, or rely on a structured tool-call interface that often offers less flexibility for freely composing operations or tailoring the analysis to each task. Both designs offer limited flexibility for open-ended, complex 3D/4D spatial reasoning. 2 空间推理代理的动作接口Action Interfaces for Spatial Reasoning Agents

我们通过工具增强空间代理来表征它们We characterize tool-augmented spatial agents by their动作界面action interface，即他们获取、检查和转换视觉证据的媒介。 当不使用接口时，VLM 通过直接在输入图像上生成自然语言的思维链基本原理来执行空间推理, that is, the medium through which they acquire, inspect, and transform visual evidence. When no interface is used, the VLM performs spatial reasoning by generating a chain-of-thought rationale in natural language directly over the input images(yang2024think; chen2025eagle2.5; qwen3.5; gemma4)，无需调用任何外部计算或获取中间证据。 除了这种无工具的情况之外，先前的空间代理主要依赖于两个操作接口之一：单遍代码执行，或通过结构化工具调用进行预定义的 API 调用。, without invoking any external computation or acquiring intermediate evidence. Beyond this tool-free case, prior spatial agents have primarily relied on one of two action interfaces: single-pass code execution, or predefined API calls through structured tool-calls.

单通代码。Single-pass code.

代理编写一个完整的Python程序，运行一次，并用它来调用感知模块并处理其输出The agent writes a complete Python program, runs it once, and uses it to call perception modules and process their outputs(luo2026pyspatial; marsili2025visual)。 该程序可以表达特定于任务的计算，但在观察任何中间掩模、深度图、绘图或运行时错误之前，它必须承诺完整的策略。 重试机制可以修复语法或运行时故障，但中间视觉证据不参与推理循环。. The program can express task-specific computations, but it must commit to a complete strategy before observing any intermediate mask, depth map, plot, or runtime error. Retry mechanisms may repair a syntax or runtime failure, but intermediate visual evidence does not participate in the reasoning loop.

结构化工具调用。Structured tool-calls.

代理按名称调用感知模块，通过预定义的结构化命令传递键入的输入并接收键入的输出The agent invokes perception modules by name, passing typed inputs and receiving typed outputs through predefined structured commands(chen2025geometrically; chen2025spacetools; ropero2026riemind)，例如 JSON 或 XML。 虽然这公开了用于调用感知的干净接口，但只能在测试时确定的组合（例如以特定于问题的方式将深度估计与分段掩码链接起来）很难在预定义的命令模式中表达。, e.g., JSON or XML. While this exposes a clean interface for invoking perception, compositions that can only be determined at test time, such as chaining a depth estimate with a segmentation mask in a way specific to the question, are difficult to express within the predefined command schema.

动机。Motivation.

这些考虑因素激发了以代码为中心的第三个界面，作为基于中间证据的灵活迭代组合的媒介。 SpatialClaw 建立在现代 LLM 代码生成功能快速进步的基础上，让代理每一步编写一个 Python 单元，并在持久内核中执行它，根据生成的文本、变量、错误和可视化来调节每个后续步骤；也就是说，我们将代码解释为操作界面。 代码生成提供了比任何一种方法更通用的适应任务的机制：例如通过以下方式查找最近的对象的计算These considerations motivate a third interface centered on code as a medium for flexible iterative composition based on intermediate evidence. 3 空间之爪SpatialClaw

SpatialClaw 通过持久的 Python 工作空间将此代码实现为操作接口，以进行空间推理。 它不是公开更大的空间工具菜单，而是让代理将视觉证据转化为可检查的空间分析，可以通过多个步骤进行组合和修改。 对于每个示例，SpatialClaw 都会创建一个预加载输入帧和一组跨越感知模块（例如深度估计、分割）和科学库（例如 NumPy）的基元的持久 Python 内核。SpatialClaw realizes this code as the action interface through a persistent Python workspace for spatial reasoning. H.1 局限性Limitations

SpatialClaw 剩下的主要瓶颈是骨干视觉语言模型及其组成的感知工具的感知质量。主论文中的故障模式分析将剩余错误的最大份额归因于感知而不是操作界面，这意味着在当前的评估规模下，进一步的界面设计的回报递减。我们预计未来改进的主轴是感知质量，无论是在主干视觉语言模型中还是在底层重建和分割模型中。The main remaining bottleneck of SpatialClaw is the perceptual quality of the backbone vision-language model and of the perception tools it composes. The failure-mode analysis in the main paper attributes the largest share of remaining errors to perception rather than to the action interface, which means that further interface design has diminishing returns at the current scale of evaluation. We expect the principal axis for future improvement to be perceptual quality, both in the backbone vision-language model and in the underlying reconstruction and segmentation models.

H.2 更广泛的影响Broader Impact

SpatialClaw 无需训练，也不向骨干视觉语言模型添加任何参数。因此，现有模型可以扩展为具有更强的空间推理能力，而无需额外的训练数据和微调，这在数据收集昂贵或不切实际的领域尤其有价值，包括机器人、具体应用程序和辅助系统。由于相同的配置无需修改即可跨主干网和基准进行传输，因此该框架增加了已部署的视觉语言模型的实用价值。SpatialClaw is training-free and adds no parameters to the backbone vision-language model. Existing models can therefore be extended with stronger spatial reasoning ability without additional training data and without fine-tuning, which is particularly valuable in domains where data collection is expensive or impractical, including robotics, embodied applications, and assistive systems. Because the same configuration transfers across backbones and benchmarks without modification, the framework increases the practical value of vision-language models that are already deployed.
