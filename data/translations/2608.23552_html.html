摘要Abstract

语言模型是顺序处理器，但长期代理需要模型权重和活动上下文之外的外部信息和计算。 Prime Agent 是一个用于长期评估和编码代理工作流程的开源工具。 持久性 IPython REPL 遵循用于编程上下文处理和测试时计算的递归语言模型抽象，而持续利用则保留跨轨迹的历史、记忆、技能、提示和子代理规范。 递归子代理通过直接代理到代理通信进行协调，代理视图允许人们检查和管理守护程序支持的会话。 Prime Agent 标准化执行、恢复、验证和资源核算，同时将策略构建留给模型。 这种低摩擦、富有表现力的薄膜可以防止线束故障变成模型故障，并将测量推向模型真正的最大基础能力。 Prime Agent 将 ARC-AGI-3 RHAE Best@1 从 30% 提高到 95.5%，并且在长上下文编码、GPU 内核生成、模拟器构建和自主 nanoGPT 速度运行方面匹配或超过了本地和流行的工具。 在异星工厂中，我们发现细化可以实现持续的技术进步，而专用的子代理可以实现并行工作。 代码可在Language models are sequential processors, but long-horizon agency requires external information and computation beyond model weights and active context. Prime Agent is an open-source harness for long-horizon evaluation and coding-agent workflows. A persistent IPython REPL follows the Recursive Language Model abstraction for programmatic context processing and test-time compute, while Continual Harness preserves histories, memories, skills, prompts, and subagent specifications across trajectories. Recursive subagents coordinate through direct agent-to-agent communication, and the Agents View lets humans inspect and manage daemon-backed sessions. Prime Agent standardizes execution, recovery, verification, and resource accounting while leaving strategy construction to the model. 2.1 架构概述2.1 Architecture overview

Prime Agent 将信息管理与计算管理分开。 信息管理确定什么状态进入模型调用以及什么状态在压缩或重新启动后仍然存在。Prime Agent separates information management from computation management. Information management determines what state enters a model invocation and what survives compaction or restart.

计算管理将模型选择的操作映射到代码、工具和递归子代理会话。 代理间的直接通信连接相关会话，而人工代理的直接交互则暴露各个节点以供检查和干预。Computation management maps model-selected actions to code, tools, and recursive subagent sessions. Direct agent-to-agent communication connects related sessions, and direct human-agent interaction exposes individual nodes for inspection and intervention.

模型用代码操纵中间值。 会话保留压缩、分离和重新启动的历史记录。 子代理继承根的执行和通信原语。 运行时记录模型调用、工具使用、消息、线束更改和资源使用。 该模型控制分解、计算分配、通信和停止。Models manipulate intermediate values with code. 保留的运行时状态包括仅附加事件历史记录、选定的内核快照、根会话树、上下文和压缩记录、持久消息队列以及版本化的持续框架状态。 分支或分叉创建新的逻辑延续，而不删除先前的事件序列。 恢复以相同的身份重建会话。 不可序列化的 Python 对象和外部进程是从保存的工件或外部服务重新创建的。The retained runtime state includes an append-only event history, selected kernel snapshots, the rooted session tree, context and compaction records, persistent message queues, and versioned Continual Harness state. 2.5 持续安全带2.5 Continual Harness

Entries support create, read, update, and delete operations; local entries belong to one session, and explicitly requested global entries remain available to later sessions.

5  结论5  Conclusion

Prime Agent 引入了一种新的代理工具设计范例，其中持久执行、递归会话、自主控制、记录历史和持续工具构成了长期工作的基础。交互式推理、长上下文任务、自主研究、系统构建和持久环境的结果表明，该基底支持标准化执行和会计下不同形式的测试时间计算。尽管其结果与替代工具相关，但模型在决定如何分配子代理、管理保留信息和细化可重用状态时仍然会遇到摩擦。许多线束功能仍未得到充分利用，因为当前模型没有接受过操作它们的培训。我们预计模型利用协同学习将成为实现新的长期能力的主要途径。直接使用 Prime Agent 进行训练可以教会模型更有效地使用集成线束，而对 RLM 和持续线束组件的有针对性的培训可以隔离它们的贡献。Prime Agent introduces a new paradigm for agent harness design in which persistent execution, recursive sessions, autonomous controls, recorded history, and Continual Harness form one substrate for long-horizon work. Results across interactive reasoning, long-context tasks, autonomous research, systems construction, and persistent environments show that this substrate supports different forms of test-time computation under standardized execution and accounting. Despite its results relative to alternative harnesses, models still experience friction when deciding how to allocate subagents, manage retained information, and refine reusable state. Many harness capabilities remain underused because current models were not trained to operate them. We expect model-harness co-learning to become the dominant route to new long-horizon capabilities. Training directly with Prime Agent could teach models to use the integrated harness more effectively, while targeted training on the RLM and Continual Harness components could isolate their contributions.
