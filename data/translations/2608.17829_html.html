摘要Abstract

法学硕士越来越依赖外部环境（例如预定义的系统提示或检索的文档）来提高生成质量。 然而，与用户查询一起处理这些上下文会产生攻击面：对抗性输入可能会导致模型披露它们。 先前的探测研究表明，与泄漏相关的信号出现在隐藏状态中，但提取这些状态的需要带来了额外的部署挑战。 在本文中，我们探讨了这种内部信号在解码之前是否留下了更容易理解的“信息”。 我们建议LLMs increasingly rely on external contexts, such as pre-defined system prompts or retrieved documents, to improve generation quality. However, processing these contexts alongside user queries creates an attack surface: adversarial inputs can induce models to disclose them. Prior probing studies suggest that leakage-related signals emerge in hidden states, yet the need to extract these states poses additional deployment challenges. In this paper, we explore whether this internal signal leaves a more accessible “tell” before decoding. We propose泄漏计LeakGauge，它通过附加一个衡量泄漏行为的后缀并将其预填充令牌概率映射到攻击风险分数来探测此响应。 虽然直接测量使用机密内容的初始标记，但我们发现用语言表达泄漏行为的内容无关的测量会产生更强大的信号。 跨越 11 个法学硕士，包括 GLM-5.2 (753B) 和 Kimi-K3 (2.8T)，, which probes this response by appending a suffix that gauges leakage behavior and mapping its prefill token probabilities to an attack-risk score. While a direct gauge uses the initial tokens of confidential content, we find that a content-agnostic one that verbalizes leakage behavior yields more robust signals. Across 11 LLMs, including GLM-5.2 (753B) and Kimi-K3 (2.8T),泄漏计LeakGauge对于看不见的攻击，AUROC 范围达到 0.944–0.996。 当内容改变语言或攻击从逐字公开转向语义公开时，信号保持稳定。 通过激活引导干预，我们进一步表明风险评分对内部泄漏相关方向敏感，将可观察信号与模型的内部表示联系起来。 此外，reaches an AUROC range of 0.944–0.996 on unseen attacks. 1 简介Introduction

现代大型语言模型（LLM）越来越依赖外部环境才能在实践中表现良好。 系统提示设定助理的行为规则Modern large language models (LLMs) increasingly depend on external contexts to perform well in practice. System prompts set the behavioral rules of an assistant(32; 13; 16)，检索增强生成 (RAG) 提供为模型答案提供基础的私人文档, and retrieval-augmented generation (RAG) supplies private documents that ground the model’s answers(22; 10; 9)。 尽管这些上下文通常对最终用户隐藏，但与用户输入一起处理它们会产生攻击面：对抗性输入可能会导致模型泄露受保护的内容. Although these contexts are normally hidden from end users, processing them alongside user inputs creates an attack surface: adversarial inputs can induce the model to disclose the protected content(45; 37; 15; 44).

为了减轻此类风险，之前的工作提出了基于文本的分类器，可以在用户查询到达模型之前对其进行筛选To mitigate such risks, prior work has proposed text-based classifiers that screen user queries before they reach the model(26; 23; 5)。 这些分类器将 LLM 视为黑匣子，仅依赖于输入文本。 因此，它们通常无法推广到未见过或重新制定的攻击. These classifiers treat the LLM as a black box, relying solely on input text. As a result, they often fail to generalize to unseen or reformulated attacks(27; 30).

最近的研究表明，泄漏攻击在模型的内部信号中留下了明显的痕迹，包括隐藏状态Recent studies indicate that leakage attacks leave distinct traces in the model’s internal signals, including hidden states(8)和注意力模式and attention patterns(14)，在生成之前。 然而，提取这些信号需要访问中间模型状态和特定于模型的配置，以了解要探测哪些层或注意力头，从而带来了额外的部署挑战。 此外，标准服务引擎（例如 vLLM）通常不会公开细粒度的注意力分数, prior to generation. Concatenated with user queries in the same context window, they are exposed to adversarial leakage attacks, a.k.a. stealing or extraction attacks(41; 13)。 我们考虑一个黑盒威胁模型：.
