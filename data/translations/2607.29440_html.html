1 简介Introduction

随着大型语言模型 (LLM) 代理在越来越长的范围内与用户交互，它们积累了广泛的多模式历史记录（包括对话、屏幕截图、图像、文档和上下文观察），这些历史记录很快超出了其主干模型的有限上下文窗口As Large Language Model (LLM) agents interact with users over increasingly long horizons, they accumulate extensive multimodal histories – including dialogues, screenshots, images, documents, and contextual observations – that quickly exceed the finite context windows of their backbone models(He et al., 2024; Koh et al., 2024; Xie et al., 2024; Wang et al., 2024)。多模式记忆系统，保留并组织此类历史以支持未来的推理. Multimodal memory systems, which retain and organize such histories to support future reasoning(Wang and Chen, 2025; Feng et al., 2026)因此，已变得至关重要并被广泛应用于个人协助等应用中, have therefore become essential and are widely adopted in applications such as personal assistance(Li et al., 2024; Feng et al., 2026), 体现互动, embodied interaction(Driess et al., 2023; Wang et al., 2023)和工具增强的工作流程, and tool-augmented workflows(Yao et al., 2022; Schick et al., 2023).

最近的多模式记忆系统探索了广泛的设计，包括文本抽象Recent multimodal memory systems have explored a broad range of designs, including textual abstraction(Feng et al., 2026)，专门的内存类型, specialized memory types(Nguyen et al., 2026), 混合商店, hybrid stores(Wang and Chen, 2025)和跨模态检索, and cross-modal retrieval(Lu et al., 2026)。 大多数现有系统遵循检索然后回答的范式，将法学硕士的条件限制在一组有界的相关记忆上，我们将其表示为检索记忆。此类系统能够有效地从长期交互历史中选择相关记忆。然而，长期的交互历史也会积累重复的观察结果，这些观察结果共同形成一个仅附加日志。针对此类历史的分析问题需要完整、范围正确的记录和操作，例如过滤、聚合、排名和时间选择。因此，检索记忆系统采用的基于相关性的方法会产生覆盖范围与上下文的权衡：较小的检索集可能会省略所需的观察结果，而较大的检索集会消耗有限的上下文预算并引入冗余或分散注意力的证据。例如如图所示. Most existing systems follows a retrieve-then-answer paradigm, conditioning an LLM on a bounded set of relevant memories, which we denote as retrieval memory. Such systems are effective at selecting relevant memories from long interaction histories. However, long interaction histories also accumulate recurring observations that collectively form an append-only log. Analytical questions over such histories require complete, correctly scoped records and operations such as filtering, aggregation, ranking, and temporal selection. Relevance-based approach adopted by retrieval memory systems therefore creates a coverage–context trade-off: a small retrieval set may omit required observations, whereas a larger retrieval set consumes the limited context budget and introduces redundant or distracting evidence. For example, as illustrated in Figure1，计算用户过去一个月的平均睡眠时间需要在聚合之前收集多个屏幕截图的所有相关测量值；因此，不完整的检索可能会产生有偏差的估计。 我们将基于相关性的检索和分析之间的这种差距称为, computing a user’s average sleep duration over the past month requires collecting all relevant measurements across multiple screenshots before aggregation; incomplete retrieval may therefore produce a biased estimate. 为了弥补这一差距，我们的主要见解是内存系统应该耦合两个互补的子系统：To bridge this gap, our key insight is that a memory system should couple two complementary subsystems:检索记忆retrieval memory，它识别并提供相关历史记录作为上下文，以及, which identifies and supplies relevant historical records as context, and分析记忆analytic memory，它主动将交互历史记录组织成可重用和可查询的结构，并自适应地对它们执行操作。它们共同支持灵活的语义回忆和结构化分析，而不是要求法学硕士从检索到的记录中重复重建所需的组织。然而，实现分析记忆面临两个关键挑战。首先，交互历史没有明确的组织模式，因此不清楚应保留哪些信息以及应如何构建它们以支持未来的查询。其次，用户查询很少指定内存访问策略，因此系统必须使每个查询所需的内容与不断发展的内存可以实现的内容相协调 目前支持。即使针对相同基础记录的问题也可能需要根本不同的操作（例如聚合、排序、过滤），这对自适应执行计划的设计提出了挑战。, which proactively organizes interaction histories into reusable and queryable structures and adaptively executes operations over them. Together, they support both flexible semantic recall and structured analysis, rather than requiring the LLM to repeatedly reconstruct the needed organization from retrieved records. Realizing analytic memory, however, presents two key challenges. First, interaction histories do not come with an explicit organizing schema, making it unclear what information should be preserved and how they should be structured to support future queries. Second, user queries rarely specify memory access strategies, the system therefore must reconcile what each query requires with what the evolving memory can currently support. Even questions over the same underlying records may require fundamentally different operations (e.g., aggregation, ordering, filtering), posing challenges to the design of adaptive execution plans.

3.4 检索内存构建Retrieval Memory Construction

除了结构化分析查询之外，许多用户请求还可以通过与过去的交互进行直接语义匹配来解决。检索内存是为此类查询而设计的，它保留开放式事件、关系和可能不会表现出重复模式的视觉细节。它通过实现灵活的语义检索和对交互历史的上下文感知推理来补充分析记忆。Beyond structured analytic queries, many user requests can be addressed through direct semantic matching against past interactions. 3.5 自适应查询处理Adaptive Query Processing

不同的查询对内存有不同的要求：有些需要对开放式事件进行语义检索，而另一些则需要对分析内存进行结构化计算。没有任何一个检索原语能够充分支持这种全方位的需求，需要一种自适应机制，根据查询意图和内存中可用的结构来选择和组合操作。Different queries place different demands on memory: some require semantic retrieval over open-ended events, whereas others require structured computation over analytic memory. 5 结论Conclusion

在这项工作中，我们发现了长期多模式代理记忆中检索与分析的不匹配，强调了除了检索之外积累的经验之外还需要可执行操作。 为了解决这个问题，我们引入了In this work, we identify a retrieval–analysis mismatch in long-term multimodal agent memory, highlighting the need for executable operations over accumulated experience beyond retrieval. To address this issue, we introduced阿达MMAdaMM，它将分层检索记忆与模式诱导的分析记忆结合起来，并通过特定于操作的工具展示它们的独特功能。 记忆感知规划器进一步将工具选择基于当前的记忆状态，并逐步组成检索和分析操作。 在 MemEye 和 MemGallery 上跨两个答案主干进行的实验表明，将灵活的召回与可执行分析相结合可以得到一致的改进。, which couples hierarchical retrieval memory with schema-induced analytic memory and exposes their distinct capabilities through operation-specific tools. A memory-aware planner further grounds tool selection in the current memory state and progressively composes retrieval and analytic operations. Experiments on MemEye and MemGallery across two answer backbones demonstrate consistent improvements from combining flexible recall with executable analysis.

局限性Limitations

First, analytic memory depends on record fragments extracted from multimodal interactions. Incorrect or missing fields may propagate to schema induction, table construction, and downstream computations. Future work could incorporate confidence-aware extraction and cross-round consistency checks to improve robustness. Second,阿达MMAdaMM使用一组预定义的访问工具，因此需要手动扩展看不见的、特定于域的操作。未来的工作可以 开发一个自我进化的工具框架，识别新出现的能力差距并安全地综合、验证和集成新工具。uses a predefined set of access tools and thus requires manual extension for unseen, domain-specific operations.
