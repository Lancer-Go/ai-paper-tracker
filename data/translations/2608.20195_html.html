1. 简介Introduction

软件文档研究传统上集中于单一受众： 人类开发者。文档质量框架、陈旧性指标和 可读性指南都以读者形成意图、获得 很困惑，向同事询问。这个预设不再总是成立。一个 开源代码更改中大量且不断增长的部分是由以下人员编写的 读取存储库、执行命令和打开拉取的自主编码代理 每个步骤都无需人工参与循环的请求。Software documentation research has traditionally focused on a single audience: the human developer. Documentation quality frameworks, staleness metrics, and readability guidelines all presuppose a reader who forms intentions, gets confused, and asks colleagues. That presupposition no longer always holds. A substantial and growing fraction of code changes in open source is authored by autonomous coding agents that read repositories, execute commands, and open pull requests without a human in the loop at each step.

如果代理现在是一类重要的文档消费者，那么文档 设计应该根据智能体的实际行为来进行设计。目前，此类证据 缺乏是因为他们的行为尚未被测量。新兴指导 “代理友好”文档——编写清晰的标题，提供可运行的 示例，发布If agents are now a significant class of documentation consumers, documentation design should be informed by what agents actually do. 8. 结论Conclusion

我们测量了编码代理如何与 557 个真实的技术文档交互 代理会话和 33,097 个代理拉取请求。主要发现是 主体的发展产生了一种文献研究所具有的流派 尚未研究：代理指令文件和代理工作笔记， 它们合计占观察到的文档交互的 60.5%，并且是 代理人写的次数几乎和阅读的次数一样多。文档类型 当前的工具和质量框架目标 - API 参考和 故障排除文档——占交互的 1.3% 和 0.4%， 分别。We measured how coding agents interact with technical documentation across 557 real agentic sessions and 33,097 agentic pull requests. The dominant finding is that agentic development has produced a genre that documentation research has not yet studied: agent instruction files and agent working notes, which together account for 60.5% of observed documentation interaction and are written by agents nearly as often as they are read. The documentation types that current tooling and quality frameworks target — API references and troubleshooting documentation — account for 1.3% and 0.4% of interactions, respectively.

数据并不一致支持三种假设的机制。之间的关联 咨询及后续代码编辑仍未解决：未调整 估计值没有显示升高，而阶段调整后的估计值却显示升高。文档 很少是第一个故障恢复 资源：这是 2,034 次失败事件中 5.4% 的首次恢复举措。 最后，没有观察到明确的基于文档的验证序列，这意味着 可验证性——通常被描述为面向代理的理想属性 文档 - 对应于我们的仪器没有记录的行为，并且 因此必须是设计的而不是假设的。Three assumed mechanisms are not consistently supported by the data. The association between consultation and subsequent code editing remains unresolved: unadjusted estimates show no elevation, whereas stage-adjusted estimates do. Documentation is rarely the first failure-recovery resource: it is the first recovery move in 5.4% of 2,034 failure episodes. Finally, no explicit documentation-based validation sequence was observed, which means verifiability — a property routinely described as desirable for agent-facing documentation — corresponds to no behaviour recorded by our instrument and must therefore be designed for rather than assumed.

实际意义是重新分配工作量：改进代理 指令文件有可能更频繁地到达代理商手中 API 参考散文的同等工作。研究意义在于 文档现在有两个行为明显不同的受众，并且 新读者写的几乎和读的一样多。The practical implication is a reallocation of effort: improving agent instruction files has the potential to reach agents far more often than equivalent work on API reference prose. The research implication is that documentation now has two audiences with measurably different behaviours, and the newer audience writes almost as much as it reads.
