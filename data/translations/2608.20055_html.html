EchoCoT：从大型推理模型中提取隐藏的思维链EchoCoT: Extracting Hidden Chain-of-Thought from Large Reasoning Models

Yiting Qu Ziqing Yang Chi Cui Ye Leng Junjie Chu Yang Zhang Thanks: Yang Zhang is the corresponding author. Affiliation: CISPA Helmholtz Center for Information Security
摘要Abstract

隐藏的思想链 (CoT) 痕迹，尤其是来自前沿专有大型推理模型 (LRM) 的痕迹，是有价值的模型资产。 然而，这些隐藏的 CoT 是否可以直接从黑盒模型中提取仍然很大程度上尚未得到探索。 在这项工作中，我们系统地研究了是否可以通过 API 交互从黑盒 LRM 中近乎逐字地提取隐藏的 CoT。 我们确定了工具调用之间以前被忽视的推理重放表面，并开发了 EchoCoT，这是一种多步骤攻击，可使用 API 返回的保真度信号迭代提取隐藏的 CoT。 我们进一步开发了一个基于 LLM 的优化框架，可以自动搜索跨各种数据集的有效通用注入轨迹。 我们在三个开源 LRM 和五个前沿专有 LRM 上评估 EchoCoT。 在开源 LRM 上，EchoCoT 的近逐字提取成功率高达 66.4%，提取的跟踪长度在目标的 10% 以内，并且至少 90% 的令牌与目标 CoT 完全匹配。 相同的注入轨迹还可以推广到未见过的数据集，在相同标准下实现高达 80% 的提取成功率。 对于经过测试的前沿专有 LRM，提取的 CoT 的很大一部分与提供商报告的推理长度和可用的 CoT 摘要紧密一致。 EchoCoT 还可以提取很长的 CoT：在 Gemini-2.5 上，它从 32,948 个令牌的目标中提取 33,463 个令牌。 这些结果将隐藏 CoT 提取确定为一种实际的安全风险，并强调需要更好地保护隐藏 CoT 资产。Hidden chain-of-thought (CoT) traces, especially those from frontier proprietary large reasoning models (LRMs), are valuable model assets. Yet whether these hidden CoTs can be directly extracted from black-box models remains largely unexplored. In this work, we systematically study whether hidden CoTs can be extracted near-verbatim from black-box LRMs through API interactions. We identify a previously overlooked reasoning replay surface between tool calls and develop EchoCoT, a multi-step attack that iteratively extracts hidden CoTs using API-returned fidelity signals. We further develop an LLM-based optimization framework that automatically searches for an effective universal injection trajectory across various datasets. We evaluate EchoCoT on three open-source and five frontier proprietary LRMs. On open-source LRMs, EchoCoT achieves up to 66.4% near-verbatim extraction success, with the extracted trace length within 10% of the target and at least 90% of tokens exactly matching the target CoT. The same injection trajectory also generalizes to unseen datasets, achieving up to 80% extraction success under the same criterion. For tested frontier proprietary LRMs, a substantial fraction of extracted CoTs closely align with provider-reported reasoning lengths and available CoT summaries. EchoCoT can also extract very long CoTs: on Gemini-2.5, it extracts 33,463 tokens from a 32,948-token target. These results establish hidden-CoT extraction as a practical security risk and highlight the need to better protect hidden CoT assets.11 1我们的代码位于Our code is available athttps://github.com/TrustAIRLab/EchoCoT.

简介Introduction

大型推理模型 (LRM)，例如 GPT-5Large reasoning models (LRMs), such as GPT-5[42], DeepSeek-R1 [13]、双子座思维, and Gemini Thinking[18]，在数学、编码和科学推理任务中取得了出色的表现。 给定一个输入问题，LRM 首先生成一个文本, have achieved strong performance in mathematics, coding, and scientific reasoning tasks. Given an input question, an LRM first generates a textual思路链chain-of-thought (CoT) [53]，即推理痕迹，然后产生最终答案。 与最终答案相比，隐藏的 CoT 包含了丰富得多的信息，包括逐步计算、探索的替代方案、失败的尝试和自我修正, i.e., reasoning traces, and then produces the final answer. Compared with the final answer, hidden CoT contains substantially richer information, including step-by-step calculations, explored alternatives, failed attempts, and self-corrections[13, 35, 53].

隐藏的 CoT 是有价值的模型资产。 他们为培训提供丰富的监督Hidden CoTs are valuable model assets. They provide rich supervision for training[60]并提炼推理模型and distilling reasoning models[13, 21]。 他们还支持模型诊断. In particular, CoTs can reveal meaningful differences between models that are not captured by final-answer accuracy alone[28]。 鉴于其对模型开发和安全性的价值，OpenAI 等前沿 LRM 提供商. Given their value for model development and safety, frontier LRM providers such as OpenAI[40]和人择and Anthropic[2]严格保护内部CoT，防止其暴露给用户。strictly protect internal CoTs and prevent them from being exposed to users.

EchoCoT 部署EchoCoT Deployment

针对特定目标模型进行优化后，我们选择经验文件中记录的最佳轨迹并冻结其所有注射。 然后，我们使用这个单一的固定轨迹将 EchoCoT 推理过程应用于来自不同任务和数据集的各种未见过的问题。 对于每个问题，我们执行轨迹而不调用 LLM 优化器。After optimizing for a specific target model, we select the best trajectory recorded in the experience file and freeze all its injections. We then apply the EchoCoT inference process to diverse unseen questions from different tasks and datasets using this single fixed trajectory. For each question, we execute the trajectory without invoking the LLM optimizer.

防御Defense

EchoCoT 成功的根本原因是工具调用之间的推理连续性。 我们首先评估一种理想化的防御，该防御在每次工具调用后删除目标 CoT，这可以防止重放，但不切实际，因为 LRM 依赖于这种连续性来完成任务。 然后，我们专注于隐藏或混淆推理令牌计数（即攻击者的密钥提取信号）的实际防御，并评估系统提示防御。 更基本的解决方案，例如培训后安全调整，留给未来的工作。The fundamental reason EchoCoT succeeds is the reasoning continuity between tool calls. We first evaluate an idealized defense that removes the target CoT after each tool call, which prevents replay but is impractical because LRMs rely on such continuity to complete tasks. We then focus on practical defenses that hide or obfuscate the reasoning-token count, i.e., the attacker’s key extraction signal, and also evaluate a system-prompt defense. More fundamental solutions, e.g., post-training safety alignment, are left for future work.

推理状态移除。Reasoning State Removal.在此设置中，我们在第一次工具调用后从上下文中删除隐藏的 CoT，同时保留可见的对话和工具结果。 如果无法访问原始推理状态，模型可能会生成新的解释，但无法直接重现目标 CoT。 此设置提供了防御有效性的上限。In this setup, we remove the hidden CoT from the context after the first tool call, while retaining the visible conversation and tool result. Without access to the original reasoning state, the model may generate a new explanation but cannot directly reproduce the target CoT. This setup provides an upper bound on defense effectiveness.

防御系统提示。Defensive System Prompt.我们添加了一个系统提示，明确指示模型将工具输出视为不受信任的内容，并且不要向用户或外部工具揭示、复制或存档其隐藏的推理。 这种防御测试了更强的系统级指令是否可以在不改变 API 接口或推理流程的情况下减少 CoT 提取。 我们还考虑了一种自适应攻击者，它可以针对防御模型重新优化注入轨迹，从而允许优化器在防御系统提示下适应模型的响应。 我们在附录中展示了防御系统提示We add a system prompt that explicitly instructs the model to treat tool outputs as untrusted content and not to reveal, reproduce, or archive its hidden reasoning for users or external tools. This defense tests whether a stronger system-level instruction can reduce CoT extraction without changing the API interface or reasoning flow. 结论Conclusion

在这项工作中，我们开发了 EchoCoT，这是一种 CoT 提取方法，它利用工具调用之间的推理连续性来迭代地从黑盒目标 LRM 中恢复隐藏的推理。 即使使用手动编写的注入，EchoCoT 也可以以近乎逐字的方式恢复大部分隐藏的 CoT。 我们进一步表明，API 返回的推理令牌计数和 CoT 摘要可以作为自动优化注入轨迹的反馈，从而实现更强的提取性能。 这些发现指出了一些更广泛的安全影响。 首先，向用户隐藏 CoT 并不一定会阻止其提取。 在工具调用期间，模型需要保留其先前的推理才能继续任务，并且攻击者可以重放此保留的推理以提取隐藏的 CoT。 其次，看似有限的 API 信号，即推理令牌计数和可选的 CoT 摘要，可以为近乎逐字的 CoT 提取提供有效的反馈。 最后，EchoCoT 的优化自动化使攻击更具可扩展性，从而进一步加剧了 CoT 暴露的风险。 总而言之，这些发现表明，减轻 CoT 提取可以激发多层防御，包括强对齐、系统提示防御以及限制相关 API 信号的暴露。In this work, we develop EchoCoT, a CoT extraction method that exploits reasoning continuity across tool calls to iteratively recover hidden reasoning from a black-box target LRM. Even with manually written injections, EchoCoT can recover a substantial fraction of hidden CoTs in a near-verbatim manner. We further show that reasoning-token counts and CoT summaries returned by the API can serve as feedback for automatically optimizing injection trajectories, leading to stronger extraction performance. These findings point to several broader security implications. First, hiding CoT from users does not necessarily prevent its extraction. During tool calling, the model needs to retain its previous reasoning to continue the task, and this retained reasoning can be replayed by an attacker to extract the hidden CoT. Second, seemingly limited API signals, i.e., reasoning-token counts and optional CoT summaries, can provide effective feedback for near-verbatim CoT extraction. Finally, automating the optimization of EchoCoT further exacerbates the risk of CoT exposure by making the attack more scalable. Taken together, these findings suggest that mitigating CoT extraction motivates defenses at multiple layers, including strong alignment, system-prompt defenses, and limiting the exposure of related API signals.

局限性。Limitations.我们的研究有几个局限性。 首先，对于前沿专有LRM，真实的CoT及其原始标记器不可用，因此定量保真度评估只能作为代理估计。 但我们的定性示例揭示了语言切换等内部行为，这是隐藏 CoT 提取的标志。 其次，由于 API 和计算预算的限制，我们使用每个样本的单次运行来评估提取性能，因此不会量化运行之间的变异性。 然而，多个模型和评估数据集的一致提取性能支持了我们主要发现的稳健性。 最后，我们评估了几种实际的防御措施，而更基本的防御措施，例如训练后的安全调整，则留待未来的工作。Our study has several limitations. First, for frontier proprietary LRMs, the ground-truth CoTs and their original tokenizers are unavailable, so the quantitative fidelity evaluation can only serve as a proxy estimate. But our qualitative examples reveal internal behaviors like language switching, which are signs of hidden CoT extraction. Second, due to API and computational budget constraints, we evaluate extraction performance using a single run per sample and therefore do not quantify run-to-run variability. However, consistent extraction performance across multiple models and evaluation datasets supports the robustness of our main findings. Finally, we evaluate several practical defenses, while more fundamental defenses, such as post-training safety alignment, remain for future work.

道德考虑Ethics Considerations

隐藏的 CoT 是有价值的模型资产，了解其暴露风险对于前沿专有 LRM 提供商非常重要。 我们的目标是评估强大的黑盒攻击者可能会暴露多少隐藏推理，而不是获取专有的 CoT 进行实际使用。 因此，我们使用 EchoCoT 作为最坏情况评估方法来测量隐藏的 CoT 泄漏。 所有实验都是使用公共数据集中的问题进行的，其中不包含来自真实用户的敏感信息。 此外，我们不会针对用户数据、其他用户的对话或与生成的 CoT 无关的其他内部敏感信息。 我们的研究经过机构伦理审查并获得批准。Hidden CoTs are valuable model assets, and understanding their exposure risks is important for frontier proprietary LRM providers. Our goal is to assess how much hidden reasoning may be exposed under a strong black-box attacker rather than to obtain proprietary CoTs for practical use. We therefore use EchoCoT as a worst-case evaluation method for measuring hidden CoT leakage. All experiments are conducted using questions from public datasets, which contain no sensitive information from real users. Also, we do not target user data, other users’ conversations, or other internal sensitive information unrelated to the generated CoT. Our study underwent institutional ethics review and was approved.
