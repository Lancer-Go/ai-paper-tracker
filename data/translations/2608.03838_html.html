摘要Abstract

基于推理的保护模型改进了 LLM 保障措施，但解码每次交互的明确理由使得部署成本高昂。尽管潜在推理方法通过将推理转移到连续状态来减少令牌生成，但它们对于安全调节的探索仍然不足，并且缺乏用于部署的检查界面。在本文中，我们提出了 LatentGuard，这是一种高效且可检查的防护框架，可为防护模型带来连续的潜在推理。 LatentGuard 使用分阶段课程逐步将与任务相关的文本原理压缩为紧凑的潜在状态，从而能够直接从连续表示中预测安全判决。为了保持可检查性，隔离的辅助解码器根据需要生成紧凑的审计工件，使基本原理生成远离标准推理路径。实验表明，与 GuardReasoner8B 相比，LatentGuard-8B 将平均加权 F1 从 83.95 提高到 84.91，同时将关键路径推理成本从 268.56 个生成的基本原理标记降低到 1.60 个潜在推理标记。其审计解码器的审计效用得分为 85.75，展示了实现可部署的 LLM 保障措施的有效且可检查的路径。Reasoning-based guard models improve LLM safeguards, but decoding explicit rationales for every interaction makes them costly to deploy. Although latent-reasoning methods reduce token generation by moving reasoning into continuous states, they remain underexplored for safety moderation and lack an inspection interface for deployment. In this paper, we propose LatentGuard, an efficient and inspectable safeguard framework that brings continuous latent reasoning to guard models. LatentGuard uses a staged curriculum to progressively compress task-aligned textual rationales into compact latent states, enabling safety verdicts to be predicted directly from continuous representations. To preserve inspectability, an isolated auxiliary decoder generates compact audit artifacts on demand, keeping rationale generation off the standard inference path. Experiments show that LatentGuard-8B improves mean weighted F1 from 83.95 to 84.91 over GuardReasoner8B, while reducing critical-path reasoning cost from 268.56 generated rationale tokens to 1.60 latent reasoning tokens. Its audit decoder achieves an audit utility score of 85.75, demonstrating an efficient and inspectable path toward deployable LLM safeguards.

降低这种成本的自然方法是将推理从令牌空间转移到连续的隐藏状态。最近的潜在推理方法表明，中间推理可以内化为紧凑表示，从而减少标记生成（Hao 等人，2025；Cheng 和 Durme，2024）。然而，这些方法主要是针对数学和逻辑推理任务进行研究的，其目标是答案的正确性而不是部署时间的调节。目前尚不清楚潜在推理是否可以适应 LLM 保障措施，其中审核决策取决于政策，通常不明确，并且在部署后必须保持可检查性。此外，潜在推理方法通常侧重于高效的任务解决，而不是提供用于检查单个决策的部署时界面。A natural way to reduce this cost is to move reasoning from token space into continuous hidden states. Recent latent-reasoning methods show that intermediate reasoning can be internalized as compact representations, reducing token generation (Hao et al., 2025; Cheng and Durme, 2024). Yet these methods have been studied primarily on mathematical and logical reasoning tasks, where the goal is answer correctness rather than deployment-time moderation. It remains unclear whether latent reasoning can be adapted to LLM safeguards, where moderation decisions are policydependent, often ambiguous, and must remain inspectable after deployment. Moreover, latentreasoning approaches typically focus on efficient task solving rather than providing a deploymenttime interface for inspecting individual decisions.

我们认为，防护模型应该将安全预测与基本原理生成脱钩。在标准推理过程中，警卫应在内部执行推理并以最小的延迟输出安全判决。当需要检查时，系统应该能够根据需要生成紧凑的、人类可读的审计工件，而不需要为每次交互生成理由。这种设计保留了潜在推理的效率优势，同时保留了用于记录、审查和下游审计的实用界面。We argue that guard models should decouple safety prediction from rationale generation. During standard inference, the guard should perform reasoning internally and output safety verdicts with minimal latency. When inspection is needed, the system should be able to produce compact, humanreadable audit artifacts on demand, without requiring rationale generation for every interaction. This design preserves the efficiency benefits of latent reasoning while retaining a practical interface for logging, review, and downstream auditing.

为此，我们提出了 LATENTGUARD，这是一种高效且可检查的防护框架，它将连续潜在推理引入 LLM 防护模型中。 LatentGuard 基于 GuardReasoner 的三标签安全调节公式构建，其中模型预测请求危害性、拒绝检测和响应危害性。为了提高效率，LatentGuard 使用分阶段的潜在推理课程来逐步将与任务相关的文本原理压缩为连续的潜在状态。该课程提供了从显式推理监督到潜在计算的稳定训练路径，使警卫能够在标准推理过程中从紧凑表示中预测结构化安全判决。为了可检查性，LatentGuard 进一步训练了一个隔离的辅助解码器，仅在请求审计模式时，该解码器才从守卫的潜在状态和源交互中生成紧凑的审计工件。解码器远离标准推理路径，并且不会改变警卫的潜在推理动态，从而保留潜在推理的效率优势，同时保留实用的检查接口。To this end, we propose LATENTGUARD, an efficient and inspectable safeguard framework that introduces continuous latent reasoning into LLM guard models. LatentGuard is built on the threelabel safety moderation formulation of GuardReasoner, where the model predicts request harmfulness, refusal detection, and response harmfulness. For efficiency, LatentGuard uses a staged latentreasoning curriculum to progressively compress task-aligned textual rationales into continuous latent states. This curriculum provides a stable training path from explicit reasoning supervision to latent computation, enabling the guard to predict structured safety verdicts from compact representations during standard inference. For inspectability, LatentGuard further trains an isolated auxiliary decoder that generates compact audit artifacts from the guard’s latent states and the source interaction only when audit mode is requested. The decoder is kept off the standard inference path and does not alter the guard’s latent reasoning dynamics, thereby preserving the efficiency benefit of latent reasoning while retaining a practical inspection interface.

我们在基于推理的安全审核设置下评估 LatentGuard，测量审核准确性、推理成本、延迟和审计效用。大量的实验验证了所需的效率与可检查性的权衡。 LatentGuard 持续改进了相应 GuardReasoner 检查点的三任务平均加权 F1，与 GuardReasoner-8B 相比，LatentGuard-8B 将平均加权 F1 从 83.95 提高到 84.91。同时，它将关键路径上的平均推理成本从 268.56 个显性推理标记降低到 1.60 个潜在推理标记。可选的审计解码器的审计效用得分为 85.75，这表明潜在推理可以支持有用的按需检查，而无需在每个审核调用中强制生成基本原理。这些结果表明 LatentGuard 提供了一条实现高效且可检查的 LLM 保障措施的实用途径。We evaluate LatentGuard under a reasoningbased safety moderation setting, measuring moderation accuracy, reasoning cost, latency, and audit utility. Extensive experiments verify the desired efficiency–inspectability trade-off. LatentGuard consistently improves the three-task mean weighted F1 over the corresponding GuardReasoner checkpoints, with LatentGuard-8B improving mean weighted F1 from 83.95 to 84.91 over GuardReasoner-8B. Meanwhile, it reduces average reasoning cost from 268.56 explicit rationale tokens to 1.60 latent reasoning tokens on the critical path. The optional audit decoder achieves an audit utility score of 85.75, indicating that latent reasoning can support useful on-demand inspection without forcing rationale generation into every moderation call. These results suggest that LatentGuard provides a practical path toward efficient and inspectable LLM safeguards.

5 结论5 Conclusion

我们提出了 LatentGuard，这是一个将常规安全预测与基本原理生成分离的安全框架。通过使用分阶段的潜在推理课程，LatentGuard 将与任务相关的基本原理内化为连续状态，并预测安全判决，而无需在标准推理过程中生成完整的自然语言推理轨迹。为了保持可检查性，它进一步引入了一个隔离的审计解码器，仅在请求检查时才生成紧凑的审计工件。实验表明，LatentGuard 改进了显式推理保护基线的有效性与效率权衡，将关键路径推理预算从数百个基本原理标记减少到几个潜在推理步骤，同时保持有用的审计效用。这些结果表明，潜在推理是可扩展和可检查的法学硕士保障措施的一个有前途的方向。We presented LatentGuard, a safeguard framework that decouples routine safety prediction from rationale generation. By using a staged latent-reasoning curriculum, LatentGuard internalizes task-aligned rationales into continuous states and predicts safety verdicts without generating full natural-language reasoning traces during standard inference. To retain inspectability, it further introduces an isolated audit decoder that produces compact audit artifacts only when inspection is requested. Experiments show that LatentGuard improves the effectiveness–efficiency trade-off over explicit-reasoning guard baselines, reducing the critical-path reasoning budget from hundreds of rationale tokens to a few latent reasoning steps while maintaining useful audit utility. These results suggest that latent reasoning is a promising direction for scalable and inspectable LLM safeguards.

8

局限性Limitations

尽管 LatentGuard 使基本原理生成远离标准推理路径，但在请求检查时，审核模式解码仍然会引入额外的计算。这使得当前的设计最适合抽样审查、事后审计或高优先级案例；当每个决策都需要审计工件时，可能需要进一步的系统级优化。此外，生成的审计工件是紧凑的证据摘要，而不是模型内部计算的忠实重建，应与源交互和预测标签一起解释。我们当前的评估重点是 GuardReasoner 公式下的纯文本安全审核。将 LatentGuard 扩展到多模式输入、更长的对话和不断发展的安全策略将留给未来的工作。Although LatentGuard keeps rationale generation off the standard inference path, audit-mode decoding still introduces additional computation when inspection is requested. This makes the current design most suitable for sampled review, post-hoc auditing, or high-priority cases; further systemslevel optimization may be needed when audit artifacts are required for every decision. In addition, the generated audit artifacts are compact evidence summaries rather than faithful reconstructions of the model’s internal computation, and should be interpreted together with the source interaction and predicted labels. Our current evaluation focuses on text-only safety moderation under the GuardReasoner formulation. Extending LatentGuard to multimodal inputs, longer conversations, and evolving safety policies is left for future work.

数据集和任务详细信息A Dataset and Task Details

数据建设。Data construction.我们使用 GuardReasonerTrain (Liu et al., 2025a) 作为训练语料库。我们保留 2.1K 个示例用于验证，并使用剩余的示例进行训练。每个示例都包含要判断的人机交互，包括任务指令、用户请求和助理响应。警卫模型经过训练来评估这种交互并输出三个安全决策：请求危害性、拒绝检测和响应危害性。目标输出包含明确的思想链基本原理，后面是这三个任务的最终结构化结论。We use GuardReasonerTrain (Liu et al., 2025a) as the training corpus. We reserve 2.1K examples for validation and use the remaining examples for training. Each example contains a human–AI interaction to be judged, consisting of a task instruction, a user request, and an assistant response. The guard model is trained to assess this interaction and output three safety decisions: request harmfulness, refusal detection, and response harmfulness. The target output contains an explicit chain-of-thought rationale followed by the final structured verdict for the three tasks.

与任务一致的理由提取。Task-aligned rationale extraction.GuardReasonerTrain 中的每个示例都包含完整的推理跟踪和三个安全任务的最终结构化结论。我们根据数据格式中已有的任务标记来解析推理轨迹。这给出了三个与任务一致的基本原理部分，分别对应于请求危害性、拒绝检测和响应危害性。Each example in GuardReasonerTrain contains a full reasoning trace and a final structured verdict for the three safety tasks. We parse the reasoning trace according to the task markers already present in the data format. This gives three task-aligned rationale segments corresponding to request harmfulness, refusal detection, and response harmfulness.

紧凑的审计目标。Compact audit targets.为了训练审计解码器，我们使用 Qwen3.5-27B（Qwen Team，2026）进一步压缩每个特定于任务的基本原理。压缩仅保留最少的决策相关证据并删除冗余的推理步骤。这些紧凑的基本原理被用作审计解码器目标，而原始的完整基本原理则用于潜在推理课程。To train the audit decoder, we further compress each task-specific rationale with Qwen3.5-27B (Qwen Team, 2026). The compression keeps only the minimal decisionrelevant evidence and removes redundant reasoning steps. These compact rationales are used as auditdecoder targets, while the original full rationales are used for the latent-reasoning curriculum.

D 审计评估详情D Audit Evaluation Details

本节描述用于审计实用程序的自动评估协议。对于每个审计工件，我们使用 Qwen3.5-27B（Qwen Team，2026）作为评估器。评估者接收原始的人机交互、特定于任务的审核指令以及审计解码器生成的紧凑基本原理。我们使用两个单独的评估器调用：一个用于标签验证，另一个用于基本原理质量评估。This section describes the automatic evaluation protocol used for audit utility. For each audit artifact, we use Qwen3.5-27B (Qwen Team, 2026) as the evaluator. The evaluator receives the original human–AI interaction, the task-specific moderation instruction, and the compact rationale generated by the audit decoder. We use two separate evaluator calls: one for label verification and one for rationale-quality assessment.

标签验证。Label verification.第一个评估器调用测量解码的审计工件是否保留了足够的决策相关信息来恢复任务标签。我们没有直接询问基本原理是否支持目标标签，而是要求评估者使用解码的基本原理作为主要基础来预测任务标签。提供源交互仅用于参考解析和事实一致性检查。我们将评估者预测的标签与目标标签进行比较，并将结果报告为验证 F1。The first evaluator call measures whether the decoded audit artifact preserves enough decision-relevant information to recover the task label. Instead of directly asking whether the rationale supports the target label, we ask the evaluator to predict the task label using the decoded rationale as the primary basis. The source interaction is provided only for reference resolution and factual-consistency checking. We compare the evaluator-predicted label with the target label and report the result as Verify F1.

基本原理-质量评估。Rationale-quality assessment.第二个评估器调用测量解码的工件是否可用作紧凑的审计工件。评估者将每个理由分类为可接受或偏离目标。如果基本原理与源交互大体一致并为审核判断提供足够的任务相关支持，则该基本原理被认为是可接受的。如果它实质上偏离了互动、关注了错误的证据、与案例相矛盾，或者过于模糊而无法支持有意义的内容，则被认为是off_targetThe second evaluator call measures whether the decoded artifact is usable as a compact audit artifact. The evaluator classifies each rationale as either acceptable or off_target. A rationale is considered acceptable if it is broadly consistent with the source interaction and provides enough task-relevant support for the moderation judgment. It is considered off_target if it materially deviates from the interaction, focuses on the wrong evidence, contradicts the case, or is too vague to support a meaningful
