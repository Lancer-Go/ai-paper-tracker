I 简介Introduction

自我进化代理通过将经验转化为可重复使用的指令来进行改进。当工具失败时，它会附加警告；当答案违反格式时，它会添加一个示例；当一个罕见的分支成功时，它会记录成功的过程。每次更新都是局部合理的。然而，积累的技能通常被编辑为仅附加的笔记本，而不是作为一个连贯的程序来维护。经过足够多的轮次后，“永远不会覆盖源文件”可能会出现在简介、三个工作流分支和一个示例中，而相同的验证-修复-验证序列会被重复复制，只有微小的差异。A self-evolving agent improves by turning experience into reusable instructions. When a tool fails, it appends a warning; when an answer violates a format, it adds an example; when a rare branch succeeds, it records the successful procedure. Each update is locally reasonable. The accumulated skill, however, is usually edited as an append-only notebook rather than maintained as a coherent program. After enough rounds, “never overwrite the source file” may appear in the introduction, three workflow branches, and an example, while the same validate–repair–verify sequence is copied repeatedly with only minor differences.

七VII结论Conclusion

自我进化的智能体需要一种忘记重复而不忘记程序的机制。Self-evolving agents need a mechanism for forgetting repetition without forgetting procedure.技能压缩包SkillZip将技能视为类型化合同，并使用一个简单的原则对其进行压缩：解释一次共享结构，在需要时引用它，并保持真正的差异明确。由此产生的最短忠实解释目标是免评估的，通过硬覆盖保护罕见的需求，并统一规则共享、范围放置、工作流重用和异常处理。一次性压缩需要一次结构化提取调用，然后进行确定性优化； Zip-on-Write 将相同的原理融入到持续的技能发展中。所提出的实验将结构正确性、保留行为、评估集过度拟合和成本分开，为自我进化代理提供了一种实用可靠的技能压缩方法。treats a skill as a typed contract and compresses it using a simple principle: explain shared structure once, reference it where needed, and keep genuine differences explicit. The resulting shortest-faithful-explanation objective is evaluation-free, protects rare requirements through hard coverage, and unifies rule sharing, scope placement, workflow reuse, and exception handling. One-shot compression requires one structured extraction call followed by deterministic optimization; Zip-on-Write integrates the same principle into continual skill evolution. The proposed experiments separate structural correctness, held-out behavior, evaluation-set overfitting, and cost, providing a practically reliable skill compression method tailored for self-evolving agents.

D-A 为什么目标不仅仅是语义重复数据删除Why the Objective Is More Than Semantic Deduplication

语义去重回答两个子句是否具有相似的含义。最短解释目标提出了一个不同的问题：在为共享定义、引用、范围符号和例外付费之后，共享表示实际上是否更短？当异常编码冗长时，它可以拒绝合理的合并，并且它可以接受在文档中出现的位置相距很远但共享相同的受保护操作模式的工作流抽象。它还比较了竞争相同源单元的替代抽象。Semantic deduplication answers whether two clauses have similar meanings. The shortest-explanation objective asks a different question: after paying for a shared definition, references, scope notation, and exceptions, is the shared representation actually shorter? It can reject a plausible merge when exception encoding is verbose, and it can accept a workflow abstraction whose occurrences are far apart in the document but share the same guarded action pattern. It also compares alternative abstractions that compete for the same source units.
