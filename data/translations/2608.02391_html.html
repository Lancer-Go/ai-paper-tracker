资源受限的代理法学硕士培训后的合作协同进化Cooperative Coevolution for Resource-Constrained Agentic LLM Post-Training

Zhiyuan Wang1, Shengcai Liu1\corresponding, Jiahao Wu1,2, Ning Lu1, 3, Hui Ouyang1,5,
Shaofeng Zhang1,4, Haoze Lv1,4, Ke Tang1\corresponding
摘要Abstract

使用工具的大型语言模型 (LLM) 代理会产生长的多回合轨迹，从而使基于梯度的训练后内存密集。进化策略 (ES) 无需反向传播即可实现内存高效的全参数后期训练，并且最终可以匹配基于梯度的强化学习 (RL) 的性能。然而，资源受限的设置通常只提供少量 GPU，因此 ES 对 GPU 小时的高要求会导致训练时间过长。为了解决这个问题，我们引入了协作参数子空间进化策略（CoPES），这是一种协作协同进化方法，它将完整参数空间分解为低维子空间并协同搜索它们以提高优化效率。我们对使用 Qwen3.5-4B 工具的代理进行数学任务的后训练，并在五个不同难度的基准上对其进行评估。在全参数 GRPO 最佳验证检查点的 GPU 小时预算下，CoPES 恢复了 GRPO 验证精度增益的 92%，而标准 ES 为 67%，而其理论 GPU 内存需求不到全参数 GRPO 的八分之一。它在所有评估的 pass@ 上始终优于标准 ES 和基于 LoRA 的 GRPOTool-using large language model (LLM) agents produce long, multi-turn trajectories, making gradient-based post-training memory-intensive. Evolution strategies (ES) enable memory-efficient full-parameter post-training without backpropagation and can eventually match the performance of gradient-based reinforcement learning (RL). However, resource-constrained settings typically offer only a few GPUs, so the high GPU-hour requirements of ES translate into prohibitively long training times. To address this, we introduce Cooperative Parameter-subspace Evolution Strategy (CoPES), a cooperative coevolutionary method that decomposes the full parameter space into lower-dimensional subspaces and searches over them cooperatively to improve optimization efficiency. We post-train a Qwen3.5-4B tool-using agent for the math task and evaluate it on five benchmarks of varying difficulty. Under the GPU-hour budget of full-parameter GRPO’s best validation checkpoint, CoPES recovers 92% of GRPO’s validation-accuracy gain, versus 67% for standard ES, while its theoretical GPU memory requirement is less than one-eighth that of full-parameter GRPO. It consistently outperforms standard ES and LoRA-based GRPO on all evaluated pass@kk五个基准的指标。额外的实验进一步证明了 CoPES 在问答任务上的优势。这些结果表明，在资源限制下，代理法学硕士后期培训的内存要求和培训时间之间的权衡得到了改善。该代码是开源的metrics across the five benchmarks. Additional experiments further show the advantage of CoPES on the question-answering task. These results demonstrate an improved trade-off between memory requirements and training time for agentic LLM post-training under resource constraints. The code is open-sourced inhttps://github.com/MetaronWang/CoPES

简介Introduction

使用工具的大型语言模型 (LLM) 代理通过将语言生成与外部操作和环境反馈交错来解决复杂的任务Tool-using large language model (LLM) agents solve complex tasks by interleaving language generation with external actions and environmental feedback(Yao et al. 2023; Jiang et al. 2025; Lv et al. 2026)。具有可验证奖励的训练后提供了一种可扩展的方法来改善此类行为，而无需带注释的轨迹. Post-training with verifiable rewards offers a scalable way to improve such behavior without requiring annotated trajectories(Lu et al. 2025)。因此，强化学习 (RL) 已成为代理后训练的主流范例，当前方法以基于梯度的方法为主. Reinforcement learning (RL) has consequently become a mainstream paradigm for agentic post-training, with current approaches dominated by gradient-based methods(Zhang et al. 2026; Wu et al. 2026)。然而，与解决传统单轮任务的模型不同，使用工具的代理通常会产生长的多轮轨迹。通过这些轨迹进行反向传播会给代理 LLM 后期训练带来巨大的 GPU 内存瓶颈。. However, unlike models solving conventional single-turn tasks, tool-using agents often produce long, multi-turn trajectories. Backpropagating through these trajectories creates a substantial GPU memory bottleneck for agentic LLM post-training.

基于梯度的后训练必须存储模型权重、梯度、优化器状态以及反向传播所需的中间激活。之前的工作提出了几种减少训练后 GPU 内存使用的方法。组相对策略优化 (GRPO) 消除了对博学批评家的需求Gradient-based post-training must store model weights, gradients, optimizer states, and the intermediate activations required for backpropagation. Prior work has proposed several approaches to reduce GPU memory usage during post-training. Group Relative Policy Optimization (GRPO) eliminates the need for a learned critic(Shao et al. 2024)，而低秩适应 (LoRA) 通过仅更新低秩适配器来减少梯度和优化器状态内存, while low-rank adaptation (LoRA) reduces gradient and optimizer-state memory by updating only low-rank adapters(Hu et al. 2022)。然而，两者都没有避免通过策略模型进行反向传播以及由此产生的存储中间激活的需要。由于激活记忆随着上下文长度的增加而增长，因此对于具有长、多回合轨迹的代理后训练来说，这种未解决的成本变得尤其严重. However, neither avoids backpropagation through the policy model and the resulting need to store intermediate activations. Because activation memory grows with context length, this unresolved cost becomes especially severe for agentic post-training with long, multi-turn trajectories(Korthikanti et al. 2023)。在实践中，高内存 GPU 成本高昂，而且大规模获得它们通常很困难。这些限制促使我们关注资源受限的设置，每个 GPU 内存有限，并且只有少量可用的 GPU，其中长轨迹的激活成本可能会使基于梯度的代理 LLM 后期训练难以部署。. In practice, high-memory GPUs are costly, and obtaining them at scale is often difficult. These constraints motivate our focus on resource-constrained settings with limited per-GPU memory and only a small number of available GPUs, where the activation cost of long trajectories can make gradient-based agentic LLM post-training difficult to deploy.

进化策略（ES）通过避免反向传播来缓解这种内存瓶颈。标准 ES 使用标量奖励评估随机扰动模型，并将结果聚合到参数更新中，仅需要前向生成和奖励评估Evolution strategies (ES) alleviate this memory bottleneck by avoiding backpropagation. Standard ES evaluates randomly perturbed models using scalar rewards and aggregates the results into a parameter update, requiring only forward generation and reward evaluation(Salimans et al. 2017)。因此，它可以优化所有模型参数，而无需存储参数梯度或反向传播激活，从而大幅减少 GPU 内存使用. It can therefore optimize all model parameters without storing parameter gradients or backpropagation activations, substantially reducing GPU memory usage(Sun et al. 2026)。最近的工作表明，ES 最终可以在 LLM 训练后达到与基于梯度的 RL 相当的性能. Recent work shows that ES can eventually achieve performance comparable to gradient-based RL in LLM post-training(Qiu et al. 2026)，但通常需要更多的 GPU 时间才能完成, but typically requires substantially more GPU-hours to do so(Sun et al. 2026)。此外，现有的研究主要集中在单轮推理任务上。在代理环境中，生成每条长的多转弯轨迹的高成本进一步放大了这种计算劣势。尽管 ES 评估具有高度可并行性，但资源受限的设置提供的 GPU 数量太少，无法通过并行性吸收额外的 GPU 时间，从而导致挂钟训练时间过长，不切实际。因此，核心挑战是在不牺牲内存优势的情况下提高 ES 的优化效率。. Moreover, existing studies focus primarily on single-turn reasoning tasks. In agentic settings, the high cost of generating each long, multi-turn trajectory further magnifies this computational disadvantage. Although ES evaluations are highly parallelizable, resource-constrained settings provide too few GPUs to absorb the additional GPU-hours through parallelism, resulting in impractically long wall-clock training times. The central challenge is therefore to improve the optimization efficiency of ES without sacrificing its memory advantage.

为了应对这一挑战，我们提出了一种合作共同进化方法To address this challenge, we propose a cooperative coevolutionary method(Potter and De Jong 1994)用于基于 ES 的 LLM 后期训练，称为协作参数子空间演化策略 (CoPES)。高维度通常会降低进化优化的有效性，从而激发协同进化将搜索空间划分为更小的子问题for ES-based LLM post-training, termed Cooperative Parameter-subspace Evolution Strategy (CoPES). High dimensionality often reduces the effectiveness of evolutionary optimization, motivating cooperative coevolution to divide the search space into smaller subproblems(Yang et al. 2008)。 CoPES 通过协作搜索低维参数子空间，将此原理应用于全参数 ES。通过将每个扰动限制在一个子空间，每个标量奖励反映了共享全模型上下文下的低维变化，而不是整个参数空间的同时变化，从而可以更有效地使用固定评估预算。 CoPES 按子空间维度缩放扰动，以匹配全空间扰动的预期平方范数，联合标准化跨子空间的奖励，并同步组成结果更新。这些设计共同改进了固定评估和 GPU 小时预算下的参数探索，同时保留了标准 ES 的仅前向、内存高效和全参数性质。. CoPES applies this principle to full-parameter ES by cooperatively searching lower-dimensional parameter subspaces. By confining each perturbation to one subspace, each scalar reward reflects a lower-dimensional change under a shared full-model context rather than simultaneous changes across the entire parameter space, allowing the fixed evaluation budget to be used more effectively. CoPES scales perturbations by subspace dimensionality to match the expected squared norm of a full-space perturbation, jointly standardizes rewards across subspaces, and synchronously composes the resulting updates. Together, these designs improve parameter exploration under fixed evaluation and GPU-hour budgets while retaining the forward-only, memory-efficient, and full-parameter nature of standard ES.

我们的贡献有三方面：Our contributions are threefold:

  • •

    我们引入了 CoPES，它结合了参数空间分解和联合奖励标准化，用于基于 ES 的 LLM 后期训练。据我们所知，CoPES 是第一个用于全参数代理 LLM 后期培训的合作协同进化方法。We introduce CoPES, which combines parameter-space decomposition and joint reward standardization for ES-based LLM post-training. To our knowledge, CoPES is the first cooperative coevolutionary method for full-parameter agentic LLM post-training.

  • •

    我们证明，CoPES 提高了固定预算优化效率，同时保留了 ES 的内存高效、全参数优势，在全参数 GRPO 最佳验证检查点的 GPU 小时预算内始终优于标准 ES 和基于 LoRA 的 GRPO。We show that CoPES improves fixed-budget optimization efficiency while preserving the memory-efficient, full-parameter advantages of ES, consistently outperforming standard ES and LoRA-based GRPO within the GPU-hour budget of full-parameter GRPO’s best validation checkpoint.

  • •

    对五个数学基准和三个问答基准的实验，加上硬件可行性测试和受控消融，跨任务和多个指标验证 CoPES，同时隔离其关键组件的影响。Experiments on five math and three question-answering benchmarks, together with hardware-feasibility tests and controlled ablations, validate CoPES across tasks and multiple metrics while isolating the effects of its key components.

相关工作Related Work

代理法学硕士培训后Agentic LLM Post-Training

最近的代理强化学习方法使用基于结果或可验证的奖励来优化多轮工具使用轨迹Recent agentic reinforcement learning methods optimize multi-turn tool-use trajectories using outcome-based or verifiable rewards(Zhang et al. 2026; Jiang et al. 2026)。例如，Search-R1 训练法学硕士在推理过程中发出多个搜索查询并合并检索到的证据. For example, Search-R1 trains LLMs to issue multiple search queries during reasoning and incorporate retrieved evidence(Jin et al. 2025)，而 ReTool 将监督冷启动与结果驱动的 RL 相结合，以了解何时以及如何调用代码解释器, while ReTool combines a supervised cold start with outcome-driven RL to learn when and how to invoke a code interpreter(Feng et al. 2025)。这些方法通常建立在基于梯度的策略优化之上。 GRPO 通过估计抽样响应组的优势来消除学习批评. These methods commonly build on gradient-based policy optimization. GRPO removes the learned critic by estimating advantages from groups of sampled responses(Shao et al. 2024)，LoRA 通过低秩适配器减少了可训练参数的数量, and LoRA reduces the number of trainable parameters through low-rank adapters(Hu et al. 2022)。这两种方法都无法消除策略模型反向传播。相反，CoPES 避免了策略模型反向传播，同时优化所有模型参数，解决了基于梯度的后期训练的更广泛的 GPU 内存开销，而无批评和参数高效的方法只能部分减少这种开销。. Neither approach eliminates policy-model backpropagation. CoPES instead avoids policy-model backpropagation while optimizing all model parameters, addressing the broader GPU memory overhead of gradient-based post-training that critic-free and parameter-efficient methods only partially reduce.

LLM 培训后的演变策略Evolution Strategies for LLM Post-Training

进化策略根据随机扰动模型的奖励来估计参数更新，因此不会通过采样轨迹进行反向传播Evolution strategies estimate parameter updates from the rewards of randomly perturbed models and therefore do not backpropagate through sampled trajectories(Wierstra et al. 2014; Salimans et al. 2017)。最近的工作表明，进化优化可以直接扩展到十亿参数的 LLM. Recent work has demonstrated that evolutionary optimization can scale directly to billion-parameter LLMs(Qiu et al. 2026; Liu et al. 2025)。 ESSAM 将 ES 与锐度感知最大化相结合，以提高数学推理的泛化能力，同时仅需要推理级 GPU 内存. ESSAM combines ES with sharpness-aware maximization to improve generalization on mathematical reasoning while requiring only inference-level GPU memory(Sun et al. 2026)。 EGGROLL 相反，代表具有低等级因素的个体扰动，以支持大群体规模的批量评估. EGGROLL instead represents individual perturbations with low-rank factors to support batched evaluation at large population sizes(Sarkar et al. 2026)。总的来说，这些研究将进化优化确立为法学硕士后期培训的可行的无反向传播替代方案。然而，标准 ES 是计算密集型的，通常需要大量的 GPU 时间. Collectively, these studies establish evolutionary optimization as a viable backpropagation-free alternative for LLM post-training. Nevertheless, standard ES is computationally intensive, often requiring substantial GPU-hours(Sun et al. 2026)。在资源受限的环境中，有限的并行性会将这种计算需求转化为较长的挂钟训练时间。 CoPES 通过协作参数子空间搜索来解决代理 LLM 后训练中的效率瓶颈，同时保留标准 ES 的仅前向、全参数性质。. In resource-constrained settings, limited parallelism translates this computational demand into long wall-clock training times. CoPES targets this efficiency bottleneck in agentic LLM post-training through cooperative parameter-subspace searches while retaining the forward-only, full-parameter nature of standard ES.

合作协同进化Cooperative Coevolution

引入合作共同进化来将复杂的解决方案进化为相互作用、共同适应的子组件Cooperative coevolution was introduced to evolve complex solutions as interacting, coadapted subcomponents(Potter and De Jong 1994, 2000)。对于连续优化，它将高维决策向量分解为子空间，优化相应的子问题，并在剩余子组件提供的上下文中评估每个部分解决方案。随后的研究开发了具有随机分组和自适应权重的大规模优化框架. For continuous optimization, it decomposes a high-dimensional decision vector into subspaces, optimizes the corresponding subproblems, and evaluates each partial solution within a context supplied by the remaining subcomponents. Subsequent studies developed a large-scale optimization framework with random grouping and adaptive weighting(Yang et al. 2008)并引入差异分组来识别相互作用的变量并构建更好地反映变量相互依赖性的子问题and introduced differential grouping to identify interacting variables and construct subproblems that better reflect variable interdependence(Omidvar et al. 2014)。最近的工作已将这种范式扩展到 170 万维神经策略搜索和可扩展的多目标优化. Recent work has extended this paradigm to 1.7-million-dimensional neural policy search and scalable many-objective optimization(Yang et al. 2022; Hu et al. 2024; Qian et al. 2025)。 CoPES 在此文献的基础上，将合作协同进化应用于基于全参数 ES 的 LLM 后期训练。. CoPES builds on this literature by adapting cooperative coevolution to full-parameter ES-based LLM post-training.

内存高效的实施和成本Memory-Efficient Implementation and Cost

种子重播、分块处理和权重备份。Seed Replay, Chunked Processing, and Weight Backup.

关注 OpenAI-ESFollowing OpenAI-ES(Salimans et al. 2017)，CoPES通过随机种子表示每个扰动，并在更新过程中重新生成其高斯方向，避免存储完整的扰动向量；模型参数按块进行处理。与之前通过减去重放扰动来恢复参数的工作不同，CoPES 在相对便宜的 CPU 内存中备份预扰动权重，并在每次扰动模型评估后恢复它们，避免浮点加法和减法的不可逆性带来的残余误差，并确保每个扰动都是从相同的预更新模型评估的。 CoPES 还存储分区种子并重播块到子空间的分配，从而避免参数级掩码。这些机制支持稳定、内存高效的执行，而不是构成单独的算法贡献。, CoPES represents each perturbation by a random seed and regenerates its Gaussian direction during the update, avoiding storage of full perturbation vectors; model parameters are processed in chunks. Unlike prior work that restores parameters by subtracting replayed perturbations, CoPES backs up the pre-perturbation weights in comparatively inexpensive CPU memory and restores them after each perturbed-model evaluation, avoiding residual errors from the non-reversibility of floating-point addition and subtraction and ensuring that every perturbation is evaluated from the same pre-update model. CoPES also stores a partition seed and replays the chunk-to-subspace assignments, avoiding a parameter-level mask. These mechanisms support stable, memory-efficient execution rather than constituting separate algorithmic contributions.

Like standard ES, CoPES requires only forward generation and reward evaluation, storing no parameter gradients, optimizer states, or backpropagation activations.

结论Conclusion

我们引入了协作参数子空间进化策略（CoPES），这是一种协作协同进化方法，通过参数子空间搜索和联合奖励标准化来提高基于 ES 的代理 LLM 后期训练的固定预算优化效率。数学和多跳 QA 实验表明，CoPES 比标准 ES 有了显着改进，同时接近全参数 GRPO，而无需牺牲 ES 的内存高效、全参数性质。这些发现使得基于 ES 的代理 LLM 后训练在有限的 GPU 资源下更加实用。目前的实验主要集中在Qwen3.5-4B和两个代理任务上；未来的工作将把 CoPES 扩展到更广泛的模型和代理环境，特别强调自适应参数空间分区。We introduced Cooperative Parameter-subspace Evolution Strategy (CoPES), a cooperative coevolutionary method that improves the fixed-budget optimization efficiency of ES-based agentic LLM post-training through parameter-subspace search and joint reward standardization. Experiments on math and multi-hop QA show that CoPES substantially improves over standard ES while approaching full-parameter GRPO, without sacrificing the memory-efficient, full-parameter nature of ES. These findings make ES-based agentic LLM post-training more practical under limited GPU resources. Current experiments focus on Qwen3.5-4B and two agentic tasks; future work will extend CoPES to a broader range of models and agent environments, with particular emphasis on adaptive parameter-space partitioning.

A.8 内存高效的 ES 实现Memory-Efficient ES Implementation

种子重播和分块。Seed Replay and Chunking.

关注 OpenAI-ESFollowing OpenAI-ES(Salimans et al. 2017)，每个扰动都由随机种子表示并在更新期间重新生成。 CoPES 重播参数块中的每个扰动，避免在 GPU 或 CPU 上存储完整的扰动向量。, each perturbation is represented by a random seed and regenerated during the update. CoPES replays each perturbation in parameter chunks, avoiding storage of full perturbation vectors on either GPU or CPU.

CPU 重量备份。CPU Weight Backup.

CoPES 不是通过减去重放的扰动来恢复未扰动的模型，而是在 CPU 内存中备份扰动前的权重，并在每次扰动模型评估后直接恢复它们。这种设计避免了浮点加法和减法的不可逆性引起的残余数值误差，并确保每个扰动都是从相同的预更新模型评估的。Rather than restoring the unperturbed model by subtracting a replayed perturbation, CoPES backs up the pre-perturbation weights in CPU memory and directly restores them after each perturbed-model evaluation. This design avoids residual numerical errors caused by the non-reversibility of floating-point addition and subtraction and ensures that every perturbation is evaluated from the same pre-update model.

分区重播。Partition Replay.

CoPES 还存储用于构建每个参数分区的随机种子。在更新期间，它会重播来自该种子的块到子空间的分配，而不是保留参数级分配掩码。种子重放、分块处理、CPU 权重备份和分区重放支持内存高效执行；它们不会改变主论文中描述的算法更新。CoPES also stores the random seed used to construct each parameter partition. During the update, it replays the chunk-to-subspace assignment from this seed instead of retaining a parameter-level assignment mask. Seed replay, chunked processing, CPU weight backup, and partition replay support memory-efficient execution; they do not alter the algorithmic update described in the main paper.
