超越成功率：进攻性和防御性安全代理的成本意识评估Beyond Success Rate: Cost-Aware Evaluation of Offensive and Defensive Security Agents

\NamePaul Kassianik    \NameBlaine Nelson    \NameYaron Singer
摘要Abstract

安全代理评估通常在慷慨的推理预算下衡量峰值攻击能力，强调漏洞发现、漏洞利用开发、渗透测试和 CTF 完成。 这样的测量很有用，但不完整：在操作安全中，每个推理步骤、工具调用、遥测查询和丰富请求都会消耗预算。 我们通过这种成本成功的视角来评估语言模型安全代理，以应对进攻性 Cybench 挑战和防御性 Splunk BOTS v1 调查挑战。 我们不只报告最佳案例的成功，而是比较固定成本水平的模型，并通过推理支出和工具支出来分解性能。 我们的结果显示了红队和蓝队任务的不同扩展机制。 通过额外的测试时间计算，进攻性 CTF 性能得到提高，并且扩展的开放权重模型可以接近前沿专有系统，同时保持成本竞争力。 防御性 SOC 调查的扩展方式不同：成功更多地依赖于严格的工具使用、遥测导航和选择性丰富，而不是仅仅依赖于原始推理预算。 我们认为，安全代理基准应该衡量经济效率和运营适合度以及任务成功程度。 具有成本意识的 SOC 原生评估可以更清晰地了解哪些模型在当今实际有用，以及防御代理在哪些方面仍需要改进。我们展示了一个带有我们结果的交互式网站Security-agent evaluations commonly measure peak offensive capability under generous inference budgets, emphasizing vulnerability discovery, exploit development, penetration testing, and CTF completion. Such measurements are useful but incomplete: in operational security, every reasoning step, tool call, telemetry query, and enrichment request consumes budget. We evaluate language-model security agents through this cost-success lens on offensive Cybench challenges and defensive Splunk BOTS v1 investigation challenges. Instead of reporting only best-case success, we compare models at fixed cost levels and decompose performance by inference spend and tool spend. Our results show distinct scaling regimes for red- and blue-team tasks. Offensive CTF performance improves with additional test-time compute, and scaled open-weight models can approach frontier proprietary systems while remaining cost-competitive. Defensive SOC investigation does not scale in the same way: success depends more heavily on disciplined tool use, telemetry navigation, and selective enrichment than on raw reasoning budget alone. We argue that security-agent benchmarks should measure economic efficiency and operational fit alongside task success. Cost-aware, SOC-native evaluations provide a clearer picture of which models are practically useful today and where defensive agents still need to improve. We present an interactive website with our resultshttps://evals.frontier.security.

1 简介Introduction

安全代理评估通常会问，当给予慷慨的推理预算和进攻性任务时，模型可以走多远：解决 CTF、查找漏洞、编写漏洞利用程序或自动化渗透测试步骤。 最近的 Claude Mythos 预览评估例证了这一制度，将 CTF 套件、多步骤网络范围、漏洞发现/利用开发评估与百万代币预算和攻击者引导的执行访问相结合Security-agent evaluations often ask how far a model can go when it is given a generous inference budget and an offensive task: solve a CTF, find a vulnerability, write an exploit, or automate a penetration-testing step. Recent Claude Mythos Preview evaluations exemplify this regime, combining CTF suites, multi-step cyber ranges, and vulnerability-discovery/exploit-development evaluations with million-token budgets and attacker-directed execution access(UK AI Security Institute, 2026a; Anthropic, 2026)。 这些测量非常有用，因为它们跟踪攻击者可以使用的功能。 它们是不完整的，因为操作安全不是峰值能力练习。 安全运营中心 (SOC) 需要能够导航遥测、选择搜索、决定何时值得付费进行丰富以及在预算范围内返回分析师级答案的代理。. Those measurements are useful because they track capabilities that attackers can use. They are incomplete because operational security is not a peak-capability exercise. A security operations center (SOC) needs agents that can navigate telemetry, choose searches, decide when enrichment is worth paying for, and return analyst-grade answers under a budget.

因此，我们将成本作为比较进攻性和防御性安全代理的共同轴。 固定预算将成功率变成了一个操作问题：每美元的推理和工具可以为模型购买多少功能？ 这种框架还将两种经常合并在一起的成本分开。 对于进攻性 CTF，大部分边际支出是测试时推理和命令执行。 对于 SOC 调查，该模型还花费了面向分析师的资源：Splunk 查询、事件检查、网络搜索、WHOIS 历史记录和其他丰富调用。We therefore make cost the common axis for comparing offensive and defensive security agents. A fixed budget turns success rate into an operational question: how much capability does a model buy per dollar of inference and tooling? This framing also separates two costs that are often collapsed together. For offensive CTFs, most marginal spend is test-time reasoning and command execution. For SOC investigation, the model also spends analyst-facing resources: Splunk queries, event inspection, web search, WHOIS history, and other enrichment calls.

Cybench provides sandboxed CTF-style tasks with shell and Python access. BOTS v1 provides public Splunk telemetry and official competition questions with point values and hint penalties. Rather than presenting a single leaderboard, we characterize operating points: model, task family, cost limit, tools, and scoring rule.

我们发现了不同的缩放机制。 在 Cybench 上，回顾性预算上限显示 Claude Opus 4.8 和 DeepSeek v4 Flash 有明显的空间，而 GPT-5.5 已经解决了低于上限的大多数成功挑战。 在 BOTS v1 上，额外预算的预测性较差：直接增加 DeepSeek v4 Flash 上限几乎不会产生什么收益，而且高工具量通常伴随着较低的分数。 因此，防御信号不仅仅是原始推理预算；它是严格的工具使用、遥测导航和选择性浓缩。We find distinct scaling regimes. On Cybench, retrospective budget caps show clear headroom for Claude Opus 4.8 and DeepSeek v4 Flash, while GPT-5.5 already solves most successful challenges below the lower cap. On BOTS v1, extra budget is less predictive: the direct DeepSeek v4 Flash cap increase produces little gain, and high tool volume often accompanies lower scores. The defensive signal is therefore not raw reasoning budget alone; it is disciplined tool use, telemetry navigation, and selective enrichment.

3 评估设计Evaluation Design

我们使用 Inspect 评估框架We use the Inspect evaluation framework(UK AI Security Institute, 2024)来组织实验。 我们使用具有自动压缩功能的 ReAct 风格代理to organize the experiments. We use a ReAct-style agent with auto-compaction(Yao et al., 2023)对于所有基准测试运行。 当代理上下文达到模型上下文窗口的 90% 时，我们会自动压缩。 自动压缩使用了 Inspect AI 的自动压缩策略，该策略尝试提供者本机压缩并回退到基于摘要的压缩for all benchmark runs. We auto-compacted when the agent context reached 90% of the model context window. Auto-compaction used Inspect AI’s automatic compaction strategy, which attempts provider-native compaction and falls back to summary-based compaction(UK AI Security Institute, 2026b)。 在进攻和防守任务之间，我们只改变可用的工具套件。 我们依靠 Inspect 来跟踪辅助指标，例如成本、代币消耗和工具调用统计信息。 我们将成本预算作为代理运行的主要资源控制。 代理不知道成本或代币预算，但知道某些昂贵的工具调用的限制。. Between offensive and defensive tasks, we only change the suite of available tools. We rely on Inspect to keep track of auxiliary metrics like cost, token consumption, and tool calling statistics. We set budgets on the cost as the main resource control on agent runs. The agents are unaware of cost or token budgets but are aware of limits on certain expensive tool calls.

这种设计使我们能够确定模型在各种成本和代币消耗上限下的成功率。 我们可以得出实用的指标，例如每个解决问题的成本。 通过在 0 和运行限制之间改变成本，我们可以跟踪成功率如何随着成本和代币预算的增加而变化。This design allows us to ascertain the model’s success rate at various cost and token consumption caps. We can derive practical metrics such as cost per solved question. By varying the cost between 0 and the run limit, we can track how success rate scales with the cost and token budget increases.

对于 OpenAI 和 Anthropic 提供的模型，我们使用它们各自的 API。 Inspect 还依赖于自动压缩、提示缓存和成本跟踪指标的前沿提供商。 对于其他模型，我们使用 OpenRouter 选择一个主要提供商和两个后备提供商。 我们使用三个提供商的平均定价来计算运行成本。 由于 OpenRouter 将即时缓存委托给提供者，因此拥有一个主要提供者可以实现最高效的缓存方案，而不会牺牲操作稳定性。 在操作上，大多数 OpenRouter 模型调用都会记录一些提示缓存读取，但缓存未命中率因运行而异。For models provided by OpenAI and Anthropic, we use their respective APIs. Inspect also relies on frontier providers for autocompaction, prompt caching, and cost tracking metrics. For other models, we use OpenRouter to select one primary provider and two fallback providers. We use average pricing across the three providers to calculate the cost of runs. Since OpenRouter delegates prompt caching to providers, having one primary provider enables a maximally efficient caching scheme without sacrificing operational stability. Operationally, most OpenRouter model calls record some prompt-cache reads, though cache-miss rates vary by run.

Defensive evaluation should therefore scale not only dollars or tokens but also evidence quality: whether the agent finds the right telemetry, validates its answer, and pays for enrichment only when it changes the investigation.

我们的实验是观察性的，而不是前瞻性随机运行矩阵。 我们分析了应用于已完成跟踪的前瞻性固定成本上限和回顾性上限。 因此，我们强调固定预算操作点而不是通用模型排名。 BOTS v1 行在任务级别更加统一，尽管提供程序默认值和推理设置仍然因模型而异。 BOTS v1 运行使用 250 条消息限制； 2.10 美元上限的 8/93 DeepSeek v4 Flash 样本周期、4.20 美元上限的 14/93 和 5/93 DeepSeek v4 Pro 样本周期都达到了此限制，因此截断可能会抑制大容量模型。 附录中的引导区间Our experiments are observational rather than a prospectively randomized run matrix. We analyze both prospectively fixed cost caps and retrospective caps applied to completed traces. We therefore emphasize fixed-budget operating points over universal model rankings. BOTS v1 rows are more uniform at the task level, though provider defaults and reasoning settings still vary across models. BOTS v1 runs used a 250-message limit; this limit was hit by 8/93 DeepSeek v4 Flash sample-epochs at the $2.10 cap, 14/93 at the $4.20 cap, and 5/93 DeepSeek v4 Pro sample-epochs, so truncation may depress high-volume models. The bootstrap intervals in AppendixB是描述性的稳健性检查，而不是正式的总体水平推论。are descriptive robustness checks, not formal population-level inferences.

在排除官方热身后，我们的防守分析仅涵盖 31 个得分的 BOTS v1 Po1s0n1vy/Cerber 问题，并使用公共 Splunk 数据集。 BOTS v2 和 v3 扩展了 v1：v2 涵盖了 51 个问题的 Frothly 企业入侵，具有更大的端点、网络、电子邮件和 Web 数据集，而 v3 使用了 58 个问题的云密集型 Frothly 场景，涵盖 AWS CloudTrail、osquery、Windows 和网络遥测。 这些后续版本的可比多模型结果尚不可用，因此将相同的成本感知分析扩展到 BOTS v2 和 v3 是未来的工作。 因此，我们将 SOC 结论作为评估设计结果而不是关于生产 SOC 准备情况的最终声明。Our defensive analysis covers only the 31 scored BOTS v1 Po1s0n1vy/Cerber questions, after excluding the official warm-up, and uses a public Splunk dataset. BOTS v2 and v3 extend v1: v2 covers a 51-question Frothly enterprise intrusion with a much larger endpoint, network, email, and web dataset, while v3 uses a 58-question cloud-heavy Frothly scenario spanning AWS CloudTrail, osquery, Windows, and network telemetry. Comparable multi-model results for these later versions are not yet available, so extending the same cost-aware analysis to BOTS v2 and v3 is future work. We therefore present the SOC conclusion as an evaluation-design result rather than a final claim about production SOC readiness.

8 人工制品和道德考虑Artifact and Ethical Considerations

我们使用公共网络安全基准和沙盒环境。 我们仅报告总体指标和方法。 我们不会发布秘密、API 密钥或操作漏洞指令。 任何公开发布都应仅包含经过消毒的材料。We use public cybersecurity benchmarks and sandboxed environments. We report aggregate metrics and methodology only. We do not publish secrets, API keys, or operational exploit instructions. Any public release should include only sanitized materials.

9 结论Conclusion

安全代理评估应该具有成本意识和特定于工作流程。 进攻性 CTF 和防御性 SOC 调查强调不同的行为并显示不同的扩展模式。 我们发现更多的测试时间计算可以提高某些前沿/共享模型的 CTF 成功率，特别是回顾上限下的 Claude Opus 4.8 和 DeepSeek v4 Flash；新的 GPT-5.6 和《神鬼寓言》运行也表明，政策拒绝可以主导进攻得分。 我们还发现 SOC 工作并不以同样的方式随原始预算扩展； GPT-5.6 Terra 和 Sol 接近领先的 Claude Opus 4.8 分数，而成功仍然取决于严格的工具使用、遥测导航和选择性丰富。 公共 SOC 基准仍然有价值，但我们的无工具 BOTS v1 控件表明，它们的绝对分数需要在用作功能声明之前进行净化检查。Security-agent evaluation should be cost-aware and workflow-specific. Offensive CTFs and defensive SOC investigations stress different behaviors and show different scaling patterns. We find that more test-time compute can improve CTF success for some frontier/shared models, especially Claude Opus 4.8 and DeepSeek v4 Flash under retrospective caps; the new GPT-5.6 and Fable runs also show that policy refusals can dominate offensive scores. We also find that SOC work does not scale with raw budget in the same way; GPT-5.6 Terra and Sol approach the leading Claude Opus 4.8 score, while success still depends on disciplined tool use, telemetry navigation, and selective enrichment. Public SOC benchmarks remain valuable, but our no-tools BOTS v1 controls show that their absolute scores require decontamination checks before they are used as capability claims.
