Ziang Wei    Minjun Yu    Zheyuan Lai    Mingjie Pang    Wei Li
摘要Abstract

防御性驾驶分数只有在保留两者之间的区别时才有用 观察周围行为者和不观察周围行为者的政策。重新模拟 基准可以使用参考条件宽恕，在该宽恕下，代理 当记录的人工参考未通过合规渠道时，将获得信用。当 代理和参考共享不稳定的 rollout 转换，该规则可以 将共享的参考失败传播到广泛的合规信用中。Defensive driving scores are useful only when they preserve distinctions between policies that observe surrounding actors and those that do not. Re-simulation benchmarks may use reference-conditioned forgiveness, under which an agent receives credit when the logged human reference fails a compliance channel. When agent and reference share an unstable rollout transformation, this rule can propagate shared reference failures into broad compliance credit.

我们在NAVSIM v2.2原始场景单阶段评分中审核了这一风险。下 审计数字后端上受影响的记录堆栈条件， 路由盲忽略所有探针和路由感知演员盲探针超越人类 重播和 PDM-在完整的 12,146 个代币 navtest 拆分中关闭。一个新鲜的 遵循公共规范的安装再现了推出差异 在固定的 32 个令牌诊断集上。同源依赖堆栈控制和 精确输入诊断隔离依赖敏感的数值行为 共享速度改装。在 450 个代币的控制池上，仅替换求解器 消除推出分歧并恢复盲后排序，同时保持 宽恕已启用。因此，数值不稳定是直接触发因素。 参考条件宽恕传播生成的共享参考 未能进入合规信用。我们贡献了一份审计协议，要求 分数基础和堆栈披露、盲探、覆盖报告，以及 在使用此类分数进行防御性驾驶声明之前先进行稳定性测试。We audit this risk in NAVSIM v2.2 original scene single-stage scoring. Under the affected documented-stack condition on the audited numerical backend, the route-blind Ignore-All probe and a route-aware actor-blind probe outrank human replay and PDM-Closed over the complete 12,146-token navtest split. A fresh installation following the public specification reproduces rollout divergence on a fixed 32-token diagnostic set. A same-source dependency stack control and an exact-input diagnostic isolate dependency-sensitive numerical behavior in the shared velocity refit. On a 450-token control pool, replacing only the solver eliminates rollout divergence and restores blind-last ordering while keeping forgiveness enabled. Thus, the numerical instability is the direct trigger. Reference-conditioned forgiveness propagates the resulting shared reference failures into compliance credit. We contribute an audit protocol requiring score basis and stack disclosure, blind probes, overwrite reporting, and rollout stability tests before using such scores for defensive driving claims.

2.2 防御性驾驶评估和行为者敏感行为Defensive driving evaluation and actor-sensitive behavior

防御性驾驶并不等于避免有记录的碰撞。它 需要预测潜在危险、保持安全裕度、在发生危险时屈服 另一个参与者可能会进入自我路径，并维持路线和地图约束 随着互动的发展。交互丰富的数据集使这些行为 可测量的Defensive driving is not equivalent to avoiding a recorded collision. It requires anticipating latent hazards, preserving safety margins, yielding when another actor may enter the ego path, and maintaining route and map constraints as interactions evolve. Interaction-rich datasets make these behaviors measurable[zhan2019interaction]。规划基准然后总结它们 通过安全、进度和合规条款. Planning benchmarks then summarize them through safety, progress, and compliance terms[caesar2021nuplan, dauner2024navsim]。这种聚合通常被解读为 危险敏感性的证据，而不仅仅是轨迹模仿。. Such aggregates are routinely read as evidence of hazard sensitivity rather than trajectory imitation alone.

用于支持参与者敏感声明的分数必须至少区分策略 从政策中观察周围的行为者，而政策却没有这样做。单独盲最后订购 不保证预期、舒适度或部署安全性。然而，一个盲人 胜利是一个重要的警告信号。在我们的审计中，它成为诊断性的，因为记分员仍然 观察参与者，核心故障被广泛覆盖，并且顺序颠倒 在独立稳定的分数基础下。A score used to support actor-sensitive claims must at least distinguish policies that observe surrounding actors from policies that do not. Blind-last ordering alone does not certify anticipation, comfort, or deployment safety. However, a blind win is an important warning sign. In our audit, it becomes diagnostic because the scorer still observes the actors, core failures are broadly overwritten, and the ordering reverses under independently stabilized score bases.

3 审计协议Audit Protocol

我们的可重复使用的审核从行为症状开始，然后测试其分数 基础。我们问盲目的政策能否获胜，记分员是否仍然观察 真实场景，参考宽恕是否覆盖行为相关 故障，以及删除共享故障是否恢复盲后排序。 这些检查一起将不透明的排名异常与分数基础分开 机制。Our reusable audit begins with a behavioral symptom and then tests its score basis. We ask whether a blind policy can win, whether the scorer still observes the true scene, whether reference forgiveness overwrites behavior-relevant failures, and whether removing the shared failure restores blind-last ordering. Together these checks separate an opaque ranking anomaly from a score basis mechanism.

3.1 审计测试什么What the audit tests

这四个问题是刻意安排的。首先，盲目的胜利意味着失败 演员盲健全性检查。二、可见性检查区分评分依据 因更简单的实现错误而失败，其中参与者从未传递给 得分手。第三，通道级掩码显示症状是否由某个原因引起 引用条件重写而不是普通的聚合权衡。 最后，对共同转换的干预测试是否重写 取决于共享推出失败。没有后三者的盲赢 签名需要不同的诊断。The four questions are deliberately ordered. First, a blind win signals failure of the actor-blind sanity check. Second, visibility checks distinguish a score basis failure from a simpler implementation error in which actors were never passed to the scorer. Third, channel-level masks show whether the symptom is caused by a reference-conditioned rewrite rather than an ordinary aggregation trade-off. Finally, interventions on the common transformation test whether that rewrite depends on shared rollout failure. A blind win without the latter three signatures requires a different diagnosis.

5 对防御性驾驶评估的影响Implications for Defensive Driving Evaluation

依赖性敏感的速度改装不稳定是直接触发因素 审核的配置。参考条件宽恕不会导致 不稳定；它将共享参考失败传播到代理信用中，并且 启用观察到的排名反转。保持宽恕启用 稳定求解器可消除发散并恢复盲后排序 450 个代币的控制池。 Blind-last 恢复只是一个必要的属性，因为无法区分参与者感知策略和忽略周围参与者的策略的分数无法支持更强的行为主张。The dependency-sensitive velocity refit instability is the direct trigger in the audited configuration. Reference-conditioned forgiveness does not cause that instability; it propagates shared reference failures into agent credit and enables the observed ranking inversion. Keeping forgiveness enabled while stabilizing the solver removes divergence and restores blind-last ordering on the 450-token control pool. Blind-last recovery is only a necessary property, since a score that cannot distinguish an actor-aware policy from one that ignores surrounding actors cannot support stronger behavioral claims.

崩溃需要对提案和参考应用共同的转换， 宽恕以参考失败和广泛共同失败为条件 行为相关渠道。稳定的推出消除了观察到的崩溃，但是 参考条件宽恕仍然需要稳定性检查，因为它 没有独立的机制来区分共享数值故障和 合法的引用异常。对称两侧干预测试 共同转变，不偏向任何一方，而后备则保留 股票路径直至出现严重背离。Collapse requires a common transformation applied to proposal and reference, forgiveness conditioned on reference failure, and broad shared failure in behavior-relevant channels. Stable rollouts remove the observed collapse, but reference-conditioned forgiveness still requires stability checks because it has no independent mechanism to distinguish shared numerical failure from a legitimate reference exception. The symmetric two-sided intervention tests the common transformation without favoring either side, while fallback retains the stock path until gross divergence.

宽恕仍然可以解决真正的误报问题，因为严格的不宽恕评分可以推动人工重播，并且在交互频繁的候选者上将 PDM 关闭为零。因此，我们建议在解释排名之前报告依赖项版本和数字后端、参考故障掩码和失败覆盖率、路由盲探和路由感知参与者盲探，以及安装状态和推出稳定性。 这些检查并不证明防御性驾驶。盲目的胜利反而暴露了失败 对行动者敏感的解释的必要条件。Forgiveness still addresses real false positives, as strict no-forgiveness scoring can drive human replay and PDM-Closed to zero on interaction-heavy candidates. We therefore recommend reporting dependency versions and numerical backend, reference failure masks and fail-to-pass overwrite rates, route-blind and route-aware actor-blind probes, and fitted-state and rollout stability before interpreting rankings. These checks do not certify defensive driving. A blind win instead exposes failure of a necessary condition for actor-sensitive interpretation.

7 结论Conclusion

我们在共享 NAVSIM 中发现了依赖性敏感的数值故障 推出和改装路径。参考条件宽恕不会导致这种情况 不稳定，但会将由此产生的参考失败传播到广泛的代理中 信用，从而实现观察到的排名倒转。求解器、堆栈和分数基础 控件消除折叠并恢复盲后排序。 这些发现仅适用于经过审核的配置。它们激发依赖性披露、覆盖报告、盲目探测和推出稳定性检查。We identify a dependency-sensitive numerical failure in the shared NAVSIM rollout and refit path. Reference-conditioned forgiveness does not cause this instability, but propagates the resulting reference failures into broad agent credit, enabling the observed ranking inversion. Solver, stack, and score basis controls remove the collapse and restore blind-last ordering. These findings apply only to the audited configuration. They motivate dependency disclosure, overwrite reporting, blind probes, and rollout stability checks.
