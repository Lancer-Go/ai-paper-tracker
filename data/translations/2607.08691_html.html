ProjAgent：存储库级代码生成的程序相似性检索ProjAgent: Procedural Similarity Retrieval for Repository-Level Code Generation

Qihong Chen chenqh@uci.edu 0009-0000-4844-4717 University of California, IrvineIrvineUSA , Aaron Imani 0000-0001-7183-5468 University of California, IrvineIrvineUSA aaron.imani@uci.edu and Iftekhar Ahmed 0000-0001-8221-5352 University of California, IrvineIrvineUSA iftekha@uci.edu
摘要。Abstract.

存储库级代码生成需要实现目标函数，同时考虑复杂的跨文件依赖性和特定于项目的约定。现有的检索方法主要依赖于词汇、结构或语义相似性，常常忽略尽管标识符或应用程序域不同但实现相似过程逻辑的存储库功能。我们提出了 ProjAgent，这是一个存储库级代码生成系统，它将程序相似性作为显式检索信号引入。 ProjAgent 将目标函数分解为中间推理步骤，并采用代理工作流程来检索在每个步骤中表现出类似过程行为的存储库函数。检索到的过程上下文与传统语义检索相集成，为代码生成构建更丰富的存储库上下文。 ProjAgent 进一步合并了保守的静态分析反馈循环，该循环使用编译器和静态分析反馈迭代修复生成的代码。在 REPOCOD 上进行评估，ProjAgent 达到了 41.14% Pass@1，优于现有的基于检索的基线。这些结果表明，程序相似性是存储库级代码生成的有效且先前未探索的检索维度。Repository-level code generation requires implementing target functions while accounting for complex cross-file dependencies and project-specific conventions. Existing retrieval methods predominantly rely on lexical, structural, or semantic similarity, often overlooking repository functions that implement similar procedural logic despite differing in identifiers or application domains. We propose ProjAgent, a repository-level code generation system that introduces procedural similarity as an explicit retrieval signal. ProjAgent decomposes the target function into intermediate reasoning steps and employs an agentic workflow to retrieve repository functions that exhibit similar procedural behavior at each step. The retrieved procedural context is integrated with conventional semantic retrieval to construct a richer repository context for code generation. ProjAgent further incorporates a conservative static-analysis feedback loop that iteratively repairs generated code using compiler and static-analysis feedback. Evaluated on REPOCOD, ProjAgent achieves 41.14% Pass@1, outperforming existing retrieval-based baselines. These results demonstrate that procedural similarity is an effective and previously unexplored retrieval dimension for repository-level code generation.

1. 简介Introduction

大型语言模型 (LLM) 在广泛的软件工程 (SE) 任务中表现出了强大的性能。从自动错误修复到测试用例生成，基于 LLM 的方法在 SWE-bench 等既定基准上取得了可喜的结果Large Language Models (LLMs) have demonstrated strong performance across a wide range of Software Engineering (SE) tasks. From automated bug fixing to test case generation, LLM-based approaches have achieved promising results on established benchmarks such as SWE-bench(Jimenez et al., 2024)和 BigCodeBenchand BigCodeBench(Zhuo et al., 2025)。这些进步加速了法学硕士在软件开发工作流程中的采用，支持包括代码编写、代码审查和软件维护在内的活动。在这些应用程序中，代码生成因其广泛的实用性和在实际开发中的日益采用而引起了特别关注. These advances have accelerated the adoption of LLMs in software development workflows, supporting activities including code writing, code review, and software maintenance. Among these applications, code generation has attracted particular attention due to its broad practical utility and increasing adoption in real-world development(Ziegler et al., 2022; Shah et al., 2025).

尽管取得了这些进步，存储库级代码生成仍然比独立代码生成更具挑战性Despite these advances, repository-level code generation remains substantially more challenging than standalone code generation(Chen et al., 2021; Austin et al., 2021; Wang et al., 2025)。与独立基准测试不同，现实世界的软件开发很少涉及实现孤立的功能。相反，开发人员在存储库中工作，其中的函数依赖于分布在多个文件中的实用程序、类型定义、API 和特定于项目的约定. Unlike standalone benchmarks, real-world software development rarely involves implementing isolated functions. Instead, developers work within repositories where functions depend on utilities, type definitions, APIs, and project-specific conventions distributed across multiple files(Li et al., 2024; Zhang et al., 2023)。当相关存储库上下文不可用时，LLM 经常会产生 API 幻觉、调用不存在的函数或生成违反项目约定的实现，从而导致错误或不可执行的代码. When relevant repository context is unavailable, LLMs frequently hallucinate APIs, invoke nonexistent functions, or generate implementations that violate project conventions, resulting in incorrect or non-executable code(Le-Anh et al., 2026)。先前的工作表明，删除存储库上下文会持续降低跨模型的代码生成性能. Prior work has shown that removing repository context consistently degrades code generation performance across models(Li et al., 2024)。因此，存储库级代码生成不仅取决于LLM的生成能力，还取决于其检索对解决目标编程任务有用的存储库上下文的能力。. Consequently, repository-level code generation depends not only on the generation capability of an LLM, but also on its ability to retrieve repository context that is useful for solving the target programming task.

现有的用于存储库级代码生成的上下文检索方法，例如 BM25 和密集嵌入搜索，主要依赖于词汇或语义相似性Existing context retrieval methods for repository-level code generation, such as BM25 and dense embedding search, rely primarily on lexical or semantic similarity(Zhang et al., 2023; Gu et al., 2025; Robertson and Zaragoza, 2009)。这些方法最初是为代码搜索而开发的，其中检索表面级别的相似示例通常就足够了. These methods were originally developed for code search, where retrieving surface-level similar examples is often sufficient(Le-Anh et al., 2026)。然而，在存储库级代码生成中，目标函数（即要生成的函数）的关键上下文可能来自它所依赖的辅助函数，即使这些函数在命名、数据类型或领域词汇方面存在很大差异。有用的上下文还可以来自实现类似逻辑过程而不共享直接依赖关系的函数。由于此类函数通常与目标函数在词汇或语义上几乎没有相似性，因此它们很可能被现有的检索方法所忽略。我们将其步骤与目标函数的步骤共享相同的底层推理模式的函数称为程序上相似的上下文。. In repository-level code generation, however, critical context for the target function (i.e., the function to be generated) may come from helper functions that it depends on, even when those functions differ substantially in naming, data types, or domain vocabulary. Useful context may also come from functions that implement similar logical procedures without sharing a direct dependency relationship. Because such functions often exhibit little lexical or semantic similarity to the target function, they are likely to be overlooked by existing retrieval methods. We refer to functions whose steps share the same underlying reasoning patterns as the target function’s steps as a procedurally similar context.

在本文中，我们介绍了In this paper, we introduced程序相似性procedural similarity作为存储库级代码生成的补充检索信号并提出as a complementary retrieval signal for repository-level code generation and presented项目代理ProjAgent，一个检索增强生成系统，它将程序、词汇和语义检索集成到代理工作流程中，以及静态分析反馈循环。与主要依赖于词汇、语义或结构相似性的现有检索方法不同，ProjAgent 识别实现类似计算过程的存储库函数，从而为法学硕士提供有助于解决目标编程任务的上下文。, a retrieval-augmented generation system that integrates procedural, lexical, and semantic retrieval within an agentic workflow, together with a static-analysis feedback loop. Unlike existing retrieval approaches that primarily rely on lexical, semantic, or structural similarity, ProjAgent identifies repository functions that implement similar computational procedures, thereby providing LLMs with context useful for solving the target programming task.

我们对 REPOCOD 的评估表明，ProjAgent 实现了最先进的存储库级代码生成性能，优于现有基准。我们进一步表明，推理子空间投影为识别程序相关函数提供了有效的表示，并且将程序检索与传统检索信号相结合一致地提高了生成性能。消融研究进一步证实，检索管道的每个组成部分都有助于系统的整体有效性。Our evaluation on REPOCOD demonstrates that ProjAgent achieves state-of-the-art repository-level code generation performance, outperforming existing baselines. We further show that reasoning-subspace projections provide an effective representation for identifying procedurally related functions and that combining procedural retrieval with conventional retrieval signals consistently improves generation performance. Ablation studies further confirm that each component of the retrieval pipeline contributes to the system’s overall effectiveness.

更广泛地说，我们的结果表明，检索质量不仅取决于识别词汇或语义相似的代码，还取决于检索遵循相似计算过程的代码。我们希望这项工作能够推动未来对软件工程任务的行为感知检索方法以及大型语言模型中程序知识的更丰富表示的研究。More broadly, our results suggest that retrieval quality depends not only on identifying code that is lexically or semantically similar, but also on retrieving code that follows similar computational procedures. We hope this work motivates future research on behavior-aware retrieval methods for software engineering tasks and on richer representations of procedural knowledge in large language models.
