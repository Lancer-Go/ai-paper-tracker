通过训练编译：转向自然语言Compile by Training: Turning Natural-Language
局部神经功能的规范Specifications into Local Neural Functions

Yuntian Deng Affiliation: University of Waterloo Email: yuntian@uwaterloo.ca    Pengyu Nie Affiliation: University of Waterloo Email: pynie@uwaterloo.ca    Stuart Shieber Affiliation: Harvard University Email: shieber@seas.harvard.edu
摘要Abstract

许多重复出现的文本函数很容易描述，但很难用规则来实现，而为每个输入调用大型远程模型会带来重复的成本、延迟和对提供者的依赖。我们呈现Many recurring text functions are easy to describe but difficult to implement with rules, while calling a large remote model for every input introduces repeated cost, latency, and dependency on a provider. We present通过训练编译compile by training，它将自然语言规范转化为可重用的神经函数。在编译时，教师模型会生成特定于任务的示例，用于训练紧凑解释器的小型适配器。生成的函数无需教师即可运行，并且可以像普通软件一样进行存储、版本控制和编写。在 FuzzyBench-Hard（Program-as-Weights 快速编译器未产生精确匹配的子集）上，通过训练进行编译达到了 83.6% 的语义准确度。这种更高的精度伴随着更高的编译时间成本：对于快速编译器来说大约是一分钟而不是几秒钟。我们将编译器部署在公共交互服务中，并在多站点网站助手、语言控制的 3D 化身和双向英语-克劳迪什翻译器中演示编译功能。, which turns a natural-language specification into a reusable neural function. At compile time, teacher models generate task-specific examples that are used to train a small adapter for a compact interpreter. The resulting function runs without the teachers and can be stored, versioned, and composed like ordinary software. On FuzzyBench-Hard, a subset on which the Program-as-Weights fast compiler produced no exact matches, compile by training reaches 83.6% semantic accuracy. This higher accuracy comes with a higher compile-time cost: roughly a minute rather than seconds for the fast compiler. We deploy the compiler in a public interactive service and demonstrate compiled functions in a multi-site website helper, a language-controlled 3D avatar, and a bidirectional English–Claudish translator.

1 简介Introduction

考虑一个电子邮件分类功能，将“EOD 所需的签名”映射到Consider an email-triage function that maps “Signature needed by EOD” to立即的immediate，但将新闻通讯映射到, but maps a newsletter to等待wait。预期的行为很容易描述，并且在数千条消息中很有用，但编码为规则却很乏味。通用远程 LLM 可以执行该任务，但为每条消息重复调用它会导致网络延迟、提供商成本以及对外部服务的依赖。许多重复出现的文本函数都介于这两个选项之间：它们对于传统代码来说过于模糊，但又过于狭窄和频繁，无法证明每次调用时都需要进行大型模型调用。. The intended behavior is easy to describe and useful across thousands of messages, yet tedious to encode as rules. A general-purpose remote LLM can perform the task, but calling it for every message repeatedly incurs network latency, provider cost, and dependence on an external service. Many recurring text functions fall between these two options: they are too fuzzy for conventional code, but too narrow and frequent to justify a large-model call at every invocation.

我们建议We propose通过训练编译compile by training：使用大型模型一次来构建更小的、可重复使用的神经函数。开发人员编写自然语言规范，教师模型生成所需行为的示例，梯度下降使用这些示例来专门化紧凑的解释器。编译大约需要一分钟，但生成的函数可以处理新的输入，而无需致电老师。从这个角度来看，适应成为软件构建步骤，大型语言模型充当工具构建者而不是运行时 依赖关系。: use large models once to build a smaller, reusable neural function. A developer writes a natural-language specification, teacher models generate examples of the desired behavior, and gradient descent uses those examples to specialize a compact interpreter. Compilation takes roughly a minute, but the resulting function can then process new inputs without calling the teachers. In this view, adaptation becomes a software build step, and large language models act as tool builders rather than run-time dependencies.

我们的系统建立在程序权重 (PAW) 的基础上Our system builds on Program-as-Weights (PAW)(Zhang et al., 2026)，在 这是一个专门共享本地解释器的神经程序。 PAW推出了摊销 在一次前向传递中预测此类程序的编译器。这使得 编译速度快，但在每个上花费相同的固定计算量 功能。通过训练编译保留相同的程序格式和运行时间 接口，以摊销预测为起点，然后投资 教师综合和特定规范中的额外计算 优化。生成的程序仍然可以使用普通软件进行版本控制、缓存和组合。, in which a neural program specializes a shared local interpreter. PAW introduced an amortized compiler that predicts such a program in a single forward pass. This makes compilation fast, but spends the same fixed amount of computation on every function. Compile by training retains the same program format and run-time interface, uses the amortized prediction as a starting point, and then invests additional computation in teacher synthesis and specification-specific optimization. The resulting programs can still be versioned, cached, and composed with ordinary software.

First, does the additional compile-time investment produce better functions than one-shot weight prediction? Second, can a minute-scale build remain usable in an interactive service? Third, can independently compiled neural functions serve as components in larger applications? We evaluate correctness on FuzzyBench-Hard, a subset of examples for which the PAW fast compiler produced no exact matches. We also measure latency and responsiveness in our deployed compiler and demonstrate composition in a multi-site website helper, a language-controlled 3D avatar, and a bidirectional English–Claudish translator. 3 通过训练编译Compile by Training

通过训练进行编译分两个阶段将自然语言规范转变为可重用的神经程序。首先，教师模型综合所需函数的示例。其次，这些示例专门用于共享解释器的轻量级适配器，然后将其打包以供将来执行。Compile by training turns a natural-language specification into a reusable neural program in two stages. First, teacher models synthesize examples of the desired function. Second, those examples specialize a lightweight adapter for a shared interpreter, which is then packaged for future execution.

4 交互式分钟级编译Interactive Minute-Scale Compilation

通过训练进行编译需要几十秒，而不是单个模型调用。为了使此构建步骤可交互使用，系统必须缩短关键路径并让用户在编译过程中继续工作。我们在三个层面上满足这些要求：与培训重叠综合、协调共享工作人员的工作以及将每个编译呈现为持久的后台工作。Compile by training takes tens of seconds rather than a single model call. To make this build step usable interactively, the system must both shorten the critical path and let users continue working while compilation proceeds. We address these requirements at three levels: overlapping synthesis with training, coordinating work across shared workers, and presenting each compile as a persistent background job.

4.1 重叠合成和训练Overlapping Synthesis and Training

在顺序管道中，编译器将在加载解释器并开始优化之前等待所有教师生成的示例。这使得 GPU 在等待最慢的教师响应时处于空闲状态。我们部署的In a sequential pipeline, the compiler would wait for all teacher-generated examples before loading the interpreter and beginning optimization. This leaves the GPU idle while waiting for the slowest teacher responses. Our deployed流式编译路径streaming compile path相反，同时启动教师请求、模型加载和训练。instead starts teacher requests, model loading, and training concurrently.

一旦第一批所需的示例可用，训练就会开始，并且只有在赶上综合时才会停止。由于教师的响应可能会在不同时间到达，因此调度程序首先将传入的示例分配给较早批次所需的空位，而不更改已接受的示例或其规定的训练顺序。这种重叠缩短了关键路径，因为教师综合比单独的训练步骤要慢得多且变化更大。Training begins as soon as the examples required for its first batch are available and blocks only if it catches up with synthesis. Because teacher responses may arrive at different times, the scheduler assigns incoming examples to open slots needed by earlier batches first, without changing the accepted examples or their prescribed training order. This overlap shortens the critical path because teacher synthesis is substantially slower and more variable than an individual training step.

4.2 协调作业和重用工作Coordinating Jobs and Reusing Work

该服务将工作协调与执行综合和培训的编译工作人员分开。 API 维护每个已提交作业的持久记录，同时共享队列将待处理作业分派给可用的 GPU 工作线程。在请求新示例之前，工作人员会检查缓存并重用匹配的教师输出。已完成的程序将写入共享工件存储并链接回持久作业记录。图The service separates job coordination from the compilation workers that perform synthesis and training. The API maintains a persistent record of each submitted job, while a shared queue dispatches pending jobs to available GPU workers. Before requesting new examples, workers check the cache and reuse matching teacher outputs. Completed programs are written to a shared artifact store and linked back to the persistent job record. Figure3总结了这个服务架构。summarizes this service architecture.

这种分离允许 API 在工作人员执行长时间运行的构建时保持响应，并保持编译作业提供的可用 GPU。This separation allows the API to remain responsive while workers execute long-running builds, and it keeps available GPUs supplied with compilation jobs.

4.3 交互设计Interaction Design

该界面将编译视为后台软件构建，而不是阻塞表单提交。提交规范后，用户可以继续浏览，同时界面报告作业的队列位置和训练进度。The interface treats compilation as a background software build rather than a blocking form submission. After submitting a specification, users can continue browsing while the interface reports the job’s queue position and training progress.

5.4 编译速度是否足够快以进行交互？Is compilation fast enough for interaction?

我们在 2026 年 5 月推出服务时测量了编译延迟。冷编译 （没有缓存的教师输出）相同的代表性规范 B300 上为 50.9 秒，H200 上为 68.2 秒，RTX GPU 上为 99.2 秒。在一次负载测试中，其中四个编译 作业同时提交，所有四个作业均已完成，平均队列等待时间为 1.01 s 甚至跨工人的利用率。因为老师综合 主导端到端延迟，直接与训练重叠合成 缩短了我们服务的关键路径。We measured compile latency at service launch in May 2026. A cold compile (with no cached teacher outputs) of the same representative specification took 50.9 s on a B300, 68.2 s on an H200, and 99.2 s on an RTX GPU. In a load test in which four compile jobs were submitted concurrently, all four completed with a mean queue wait of 1.01 s and even utilization across workers. Because teacher synthesis dominates end-to-end latency, overlapping synthesis with training directly shortens the critical path of our service.

8 结论Conclusion

我们引入通过训练编译，它从 用户提供的功能描述。它首先使用大型语言模型来 从描述中综合示例，然后微调 LoRA 适配器以 专门设计一个较小的解释器模型。这为 PAW 增添了另一点 速度与精度的权衡：快速编译器在单个文件中生成 LoRA 适配器 前向传播需要几秒钟，而通过训练编译大约花费一 分钟以获得更高的精度。在 FuzzyBench-Hard 上，一组任务 PAW 快速编译器没有产生精确匹配，通过训练进行编译达到 83.6% 语义准确度。我们将其添加到公共 PAW 演示中作为另一个选项 在相同的编译器接口中并使用生成的程序来构建 多站点网站助手、语言控制的 3D 头像和双向 英语-克劳迪什翻译。We introduce compile by training, which compiles a neural program from a user-provided function description. It first uses large language models to synthesize examples from the description, then finetunes a LoRA adapter to specialize a smaller interpreter model. This adds another point to PAW’s speed–accuracy tradeoff: the fast compiler generates a LoRA adapter in a single forward pass and takes seconds, while compile by training spends roughly a minute to obtain higher accuracy. On FuzzyBench-Hard, a set of tasks for which the PAW fast compiler produced no exact matches, compile by training reaches 83.6% semantic accuracy. We added it to the public PAW demo as another option in the same compiler interface and used the resulting programs to build a multi-site website helper, a language-controlled 3D avatar, and a bidirectional English–Claudish translator.

9 局限性Limitations

综合监督可能会继承教师的错误。需要的应用程序 保证正确性应该验证输出或保留确定性控制 路径。 我们的应用证据侧重于组合和结构化执行； 系统的用户研究是未来的工作。Synthetic supervision may inherit teacher errors. Applications that require guaranteed correctness should validate outputs or retain deterministic control paths. Our application evidence focuses on composition and structured execution; systematic user studies are future work.
