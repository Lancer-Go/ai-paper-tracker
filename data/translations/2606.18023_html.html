摘要Abstract

循环 Transformer 通过重复应用共享块来扩展潜在计算，但顺序循环会随着循环计数而增加延迟和 KV 缓存内存。并行循环 Transformer (PLT) 通过跨循环位置偏移 (CLP) 和共享 KV 门控滑动窗口注意力来减轻这种成本，使循环计数成为实用的设计选择。因此，我们通过增益-成本视图来研究 PLT 循环计数选择：额外的循环可以改进表示，但 CLP 也会在每个循环边界引入位置不匹配。我们通过在 18T 令牌上从头开始训练 LoopCoder-v2（一系列具有不同循环计数的 7B PLT 编码器）来实例化这项研究，然后进行匹配的指令调整和评估。根据经验，两循环变体在代码生成、代码推理、代理软件工程和工具使用基准方面比非循环基线提供了广泛的收益，将 SWE-bench Verified 从 43.0 点提高到 64.4 点，将 Multi-SWE 从 14.0 点提高到 31.0 点。相反，具有三个或更多循环的变体会回归，揭示出强烈的非单调循环计数效应。我们的诊断表明，循环 2 提供了主要的生产性改进，而后面的循环则产生递减的振荡更新并减少了表征多样性。由于随着细化增益的缩小，CLP 引起的不匹配仍然大致固定，因此抵消成本越来越占主导地位。这种增益-成本权衡解释了 PLT 在两个循环处的饱和，并为循环计数选择提供了诊断。Looped Transformers scale latent computation by repeatedly applying shared blocks, but sequential looping increases latency and KV-cache memory with the loop count. Parallel loop Transformers (PLT) alleviate this cost through cross-loop position offsets (CLP) and shared-KV gated sliding-window attention, making loop count a practical design choice. We therefore study PLT loop-count selection through a gain–cost view: an extra loop may refine representations, but CLP also introduces a positional mismatch at each loop boundary. We instantiate this study by training LoopCoder-v2, a family of 7B PLT coders with different loop counts, from scratch on 18T tokens, followed by matched instruction tuning and evaluation. Empirically, the two-loop variant delivers broad gains over the non-looped baseline across code generation, code reasoning, agentic software engineering, and tool-use benchmarks, improving SWE-bench Verified from 43.0 to 64.4 points and Multi-SWE from 14.0 to 31.0 points. In contrast, variants with three or more loops regress, revealing a strongly non-monotonic loop-count effect. Our diagnostics show that loop 2 provides the main productive refinement, while later loops yield diminishing, oscillatory updates and reduced representational diversity. Because the CLP-induced mismatch remains roughly fixed as refinement gains shrink, the offset cost increasingly dominates. This gain–cost trade-off explains PLT’s saturation at two loops and provides diagnostics for loop-count selection.

1 简介Introduction

循环大语言模型 (LLM)Looped large language models (LLM)[yang2025codesurvey, wu2025parallel]已经成为一种有前景的方法，可以在不按比例增加参数数量的情况下扩展语言模型的有效计算深度。循环大语言模型 (LLM) 不是堆叠许多不同的层，而是重复应用共享的 Transformer 块，允许相同的参数执行多轮潜在空间计算have emerged as a promising way to scale the effective computational depth of language models without proportionally increasing their parameter count. Instead of stacking many distinct layers, a looped large language model (LLM) repeatedly applies a shared Transformer block, allowing the same parameters to perform multiple rounds of latent-space computation[dehghani2018universal, giannou2023looped, yang2023looped]。这种设计对于测试时计算扩展特别有吸引力，可以在不生成辅助推理令牌的情况下实现额外的内部细化. This design is especially attractive for test-time compute scaling, enabling additional internal refinement without generating auxiliary reasoning tokens[geiping2025scaling]。最近的工作表明，这种循环深度 LLM 可以接近更深的非循环 Transformer，并随着使用更多推理时间计算而提高推理性能. Recent work has shown that such recurrent-depth LLMs can approach deeper non-looped Transformers and improve reasoning performance as more inference-time computation is used[geiping2025scaling, yang2026stabilizing, schwethelm2026how].

尽管有这样的承诺，标准顺序循环很难有效部署：每个额外的循环都需要再次通过共享块并引入特定于循环的 KV 缓存状态，导致延迟和内存随着循环计数而增长Despite this promise, standard sequential looping is difficult to deploy efficiently: each additional loop requires another pass through the shared block and introduces loop-specific KV-cache states, causing both latency and memory to grow with the loop count[vendrell2026memoryefficient]。并联环路变压器 (PLT). The Parallel Loop Transformer (PLT)[wu2025parallel]通过两种互补机制缓解了这一瓶颈：跨循环位置偏移 (CLP)，它打破顺序循环间依赖性并启用并行循环执行；以及共享 KV 门控滑动窗口注意 (G-SWA)，它使缓存占用空间在循环计数之间保持几乎恒定。然而，降低循环成本本身并不能确定最佳工作点。在 PLT 中，循环计数成为部署时的设计选择：太少的循环可能无法充分利用模型的细化能力，而太多的循环可能会引入冗余或有害的计算。详尽地训练和评估每个候选循环计数的成本很高，并且无法深入了解特定设置成功或失败的原因。这引发了一个更具诊断性的问题：mitigates this bottleneck with two complementary mechanisms: cross-loop position offsets (CLP), which break sequential inter-loop dependencies and enable parallel loop execution, and shared-KV gated sliding-window attention (G-SWA), which keeps the cache footprint nearly constant across loop counts. Yet reducing the cost of looping does not by itself determine the best operating point. In PLT, the loop count becomes a deployment-time design choice: too few loops may underuse the model’s refinement capacity, while too many loops may introduce redundant or harmful computation. Exhaustively training and evaluating every candidate loop count is expensive and offers little insight into why a particular setting succeeds or fails. This motivates a more diagnostic question:我们可以通过检查每个循环内部的贡献来确定 PLT 的饱和点吗？can we identify the saturation point of PLT by examining what each loop contributes internally?

本节形式化了本文研究的循环计数选择问题。我们首先回顾标准循环 Transformer，其中额外的循环增加了潜在的计算深度，但也会产生顺序推理成本。然后，我们引入并行循环 Transformer (PLT)，它通过并行循环执行和共享 KV 注意力来降低这种成本，同时改变循环迭代之间的信息流。最后，我们比较这两种设置，并将 PLT 循环计数选择制定为增益-成本权衡：每个附加循环都可以提供有用的表征细化，但在 PLT 中，它还引入了偏移引起的位置不匹配。This section formalizes the loop-count selection problem studied in this paper. We first review standard looped Transformers, where additional loops increase latent computational depth but also incur sequential inference cost. We then introduce the parallel loop Transformer (PLT), which reduces this cost through parallel loop execution and shared-KV attention, while changing the information flow across loop iterations. Finally, we compare the two settings and formulate PLT loop-count selection as a gain–cost trade-off: each additional loop may provide useful representational refinement, but in PLT it also introduces an offset-induced positional mismatch.

7 结论Conclusion

循环变压器提供了一种有吸引力的机制，可以在不增加参数数量的情况下扩展潜在计算，但它们在增加循环数量下的行为仍然知之甚少。在这项工作中，我们从增益-成本的角度研究 PLT 中的这个问题：每个额外的循环都可以提供有用的改进，但 CLP 偏移也会在每个循环边界引入结构位置不匹配。我们的受控循环分析表明，第二个循环是生产性细化的主要来源，在隐藏状态、注意力路由和输出分布方面产生有意义的变化，而后面的循环产生递减和越来越振荡的更新。由于当边际环路增益缩小时，CLP 引起的失配保持大致恒定，因此额外的环路最终变得无效，这解释了为什么 PLT 在小环路计数时饱和。这些发现为循环计数选择提供了基于可解释性的诊断，无需进行详尽的基准扫描，并提出了未来的方向，例如自适应偏移机制、动态循环分配以及对潜在循环如何与显式思想链推理相互作用的更深入理解。Looped Transformers provide an appealing mechanism for scaling latent computation without increasing parameter count, but their behavior under increasing loop count remains poorly understood. In this work, we study this problem in PLT through a gain–cost perspective: each additional loop may provide useful refinement, but the CLP offset also introduces a structural positional mismatch at every loop boundary. Our controlled loop-wise analysis shows that the second loop is the primary source of productive refinement, producing meaningful changes in hidden states, attention routing, and output distributions, while later loops yield diminishing and increasingly oscillatory updates. Because the CLP-induced mismatch remains approximately constant as marginal loop gains shrink, additional loops eventually become unproductive, explaining why PLT saturates at a small loop count. These findings provide interpretability-grounded diagnostics for loop-count selection without exhaustive benchmark sweeps, and suggest future directions such as adaptive offset mechanisms, dynamic loop allocation, and a deeper understanding of how latent recurrence interacts with explicit chain-of-thought reasoning.
