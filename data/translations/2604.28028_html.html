大型语言模型 (LLM) 彻底改变了文本到 SQL 的生成，使用户能够越来越轻松地使用自然语言查询结构化数据。然而，由于准确性不一致以及生成无效 SQL 的风险，实际部署仍然具有挑战性，尤其是在复杂或看不见的模式中。Large language models (LLMs) have revolutionised Text-to-SQL generation, allowing users to query structured data using natural language with growing ease. Yet, real-world deployment remains challenging, especially in complex or unseen schemas, due to inconsistent accuracy and the risk of generating invalid SQL.

我们引入了模板约束解码 (TeCoD)，该系统通过利用标记工作负载中查询模式的重现来解决这些限制。 TeCoD 将历史 NL-SQL 对转换为可重用模板，并引入了强大的模板选择模块，该模块使用经过微调的自然语言推理模型来有效匹配或拒绝查询。选择模板后，TeCoD 在 SQL 生成过程中通过语法约束解码强制执行该模板，并通过确保语法有效性和效率的新颖分区策略实现。这些组件的执行精度比上下文学习 (ICL) 高出 36%，并且匹配查询的延迟降低了 2.2 倍。We introduce Template Constrained Decoding (TeCoD), a system that addresses these limitations by harnessing the recurrence of query patterns in labeled workloads. TeCoD converts historical NL-SQL pairs into reusable templates and introduces a robust template selection module that uses a fine-tuned natural language inference model to match or reject queries efficiently. Once the template is selected, TeCoD enforces it during SQL generation through grammar-constrained decoding, implemented via a novel partitioned strategy that ensures both syntactic validity and efficiency. Together, these components yield up to 36% higher execution accuracy than in-context learning (ICL) and 2.2× lower latency on matched queries.

通过自然语言查询（NLQ）访问数据库一直是数据库社区的长期目标[16,20,25]。最近，法学硕士凭借其卓越的自然语言理解和代码生成能力，在文本到 SQL 生成的准确性方面取得了巨大进步，如公共基准测试所示 [19, 35]。基准测试数字是多个数据库模式的平均值，并且通常在未见过的模式上进行零样本评估。然而，数据库特定的准确性随着模式的变化而显示出显着的变化。在图 1 中，我们显示了 11 种模式的准确性。对于某些数据库来说，精度很低，在实际系统中几乎没有什么用处。这种经历对于企业来说很常见，因为企业的数据库是前沿法学硕士专用的。因此，企业可能愿意用专家提供的正确 SQL 来组织 NLQ 的工作量，并调整 LLM 将其文本到 SQL 的准确性提高到可接受的水平。Accessing databases via natural language queries (NLQs) has been a long-standing goal of the database community [16, 20, 25]. Recently, LLMs with their superior capability of natural language understanding and code generation, have achieved great strides in the accuracy of Text-to-SQL generation as seen via public benchmarks [19, 35]. The benchmark numbers are averaged over multiple database schemas, and typically evaluated zero-shot on unseen schema. However, databasespecific accuracy shows significant variation with changing schema. In Figure 1 we show accuracy on 11 schemas. For some databases, the accuracy is low enough to be of little use in practical systems. Such an experience is common for enterprises, whose databases are private to frontier LLMs. Consequently, the enterprise may be willing to organize workload of NLQs with expert provided correct SQL, and adapt the LLM to increase its Text-to-SQL accuracy to acceptable levels.

目前，适应有两种选择：微调和上下文学习。微调需要预先提供大量标记数据，对于小型企业来说是负担不起的，并且会导致忘记其他任务。这些限制引起了人们对基于非微调的适应的极大兴趣Currently, there are two options for adaptation: fine-tuning and in-context learning. Fine-tuning requires a lot of labeled data up-front, is unaffordable for small enterprises, and leads to forgetting of other tasks. 我们设计了一个系统 TeCoD，超越上下文学习，利用密切相关的查询来提高 SQL 生成的准确性。我们的核心思想是将以前看到的带标签的 Text-SQL 对转换为模板化的 Text-SQL 形式，以促进与未来查询的更好匹配。当未来的查询与存储的模板之一匹配时，TeCoD 通过专用模板约束解码生成 SQL。我们表明，通过我们的约束解码，匹配查询的准确性从 ICL 的大约 60% 跃升至近 90%。这意味着重复查询的执行可靠性比基线 ICL 方法高得多。此外，我们利用模板化形式实现了推理吞吐量几乎两倍的提高。We design a system TeCoD, to go beyond in-context learning to harness closely related queries to improve accuracy of SQL generation. Our core idea is to convert previously seen labeled Text-SQL pairs to templatized Text-SQL forms to foster greater match to future queries. When a future query matches one of the stored templates, TeCoD generates the SQL via a dedicated template constrained decoding. We show that accuracy of matched queries jumps from approximately 60% with ICL to almost 90% via our constrained decoding. This implies that recurring queries can be executed with significantly higher reliability than baseline ICL methods. In addition, we take advantage of the templatized form to achieve almost a factor of two improvements in inference throughput.

我们在实施 TeCoD 过程中遇到了两个主要挑战。第一个挑战是设计匹配器模块，以将查询准确地匹配到模板化文本-SQL 对的存储池。我们需要拒绝与池中任何模板都不匹配的查询，并从池中为其余查询选择正确的模板。由于错误匹配的模板肯定会提供带有约束解码的错误 SQL，因此此步骤的高精度至关重要。我们提出了三种策略来提高匹配器的准确性，超越句子嵌入的简单阈值余弦相似度：(1) 将模板匹配作为自然语言推理问题，(2) 屏蔽用户问题的部分内容，(3) 生成原始标记文本-SQL 对的多个合成释义，为共享模板提供多个文本注释。总之，这些策略使选择/拒绝准确率从基线的 73% 跃升至 91%。We encountered two primary challenges in the implementation of TeCoD. The first challenge was designing the matcher module for accurately matching queries to a stored pool of templatized Text-SQL pairs. We need to reject queries that do not match any template in the pool and choose the correct template from the pool for the rest. Since a wrongly matched template is guaranteed to provide the wrong SQL with constrained decoding, high accuracy in this step is crucial. We propose three strategies to boost the accuracy of the matcher beyond simple thresholded cosine similarity of sentence embeddings: (1) casting template match as a natural language inference problem, (2) masking parts of the user question, (3) generating multiple synthetic paraphrases of the original labeled Text-SQL pair to provide multiple text annotation to a shared template. Together, these strategies obtained a jump in selection/rejection accuracy from 73% to 91% beyond the baseline.

工作负载驱动的定制。Workload-driven Customization.一类方法建议针对 Text-SQL 任务对预训练的 LLM 进行微调。例子包括专注于跨模式泛化微调的 CodeS [18]。针对特定目标数据库微调模型的一项挑战是预先收集标记数据。一些方法建议通过合成示例进行增强 [1, 31]。然而，随着法学硕士的出现，焦点转移到无需模型微调的即时定制。 LLM 自然支持上下文学习 [5]，其中上下文中提供的文本-SQL 对的示例已被发现可以使 LLM 适应目标数据库的 SQL [18,33,38]。其他适应方法包括基于案例的推理，这些方法已被发现对于将 SQL 生成为关系代数树是有效的 [28]。One class of methods proposes to fine-tune pre-trained LLMs to the Text-SQL tasks. Examples include CodeS [18] that focused on fine-tuning for cross-schema generalization. One challenge with fine-tuning models for a specific target database is collecting labeled data up front. Some methods propose to augment with synthetic examples [1, 31]. However, with the advent of LLMs, the focus shifted to on-the-fly customization without model fine-tuning. LLMs naturally support In-Context Learning [5] where examples of Text-SQL pairs provided within the context have been found to adapt the LLM to SQLs of a target database [18, 33, 38]. Other methods of adaptation include case base reasoning, and these have been found to be effective for generating SQL as a relational algebra tree [28].

基于模板的生成Template-based generation在许多现有系统中，模板已被用来降低 SQL 生成的复杂性。 ZeroNL2SQL [7] 使用小型语言模型创建候选模板，然后使用较大的 LLM 通过软提示和迭代反馈生成最终 SQL。 CatSQL [8] 使用自定义深度学习模型来生成模板并填充模板中的槽位，然后对生成的 SQL 进行语义校正和后处理以修复错误。 AmbiQT [4] 利用模板来生成结构多样的 SQL。然而，我们不知道之前有任何工作建议利用现有的标记数据作为模板，以便为类似查询生成更准确的 SQL。Templates have been harnessed for reducing the complexity of SQL generation in many prior systems. ZeroNL2SQL [7] uses a small language model to create candidate templates, and then uses a larger LLM to generate the final SQL via soft prompting and iterative feedback. CatSQL [8] uses a custom deep learning model to generate templates and fill the slots in the template, followed by semantic correction and post-processing of the generated SQL to fix the errors. AmbiQT [4] harnesses templates for generating structurally diverse SQLs. However, we are not aware of any prior work that proposes to harness existing labeled data as templates for more accurate SQL generation for similar queries.

For SQL generation PICARD [27] pioneered this paradigm by integrating incremental parsing constraints during autoregressive decoding, dynamically rejecting tokens that violate SQL grammar rules and significantly improving execution validity. Recently, more general forms of constrained generation is supported by libraries such Transformer-CFG [10], DOMINO [3] and Outlines [32]. These differ in how they balance validity guarantees with computational efficiency through hybrid static/dynamic analysis of grammatical structures. Transformer-CFG [10] introduced explicit modeling of context-free grammar (CFG) states through finite state machine (FSM) representations. This approach parses the entire vocabulary against the current FSM state, masks invalid token IDs, and updates the state based on sampled tokens - ensuring syntactic correctness at the cost of substantial inference overhead due to real-time FSM transitions and vocabulary-wide validity checks. Recent advancements like DOMINO [3] address this efficiency challenge through offline precomputation of prefix trees (tries) for each FSM state. By encoding valid token sequences in trie structures during preprocessing, DOMINO improves the latency of validity checks during decoding using tries, reducing computational complexity while maintaining grammatical constraints. Outlines [32] is another open-source Python library. We are using Outlines as part of our system to generate SQL, but we innovate in how we efficiently invoke the library for template constraining.

In each case, there is a generic natural language instruction, followed by a description of the schema and metadata of the database queried, followed by the in-context examples, and then the current test question q. If we include complete schema in the prompt, it will exceed the model’s context length. We use the models developed by CodeS [18] to do schema subsetting. Essentially, at inference time, we input database schema and NLQ to get relevance scores and using those scores, we choose top-k tables and columns, which would become part of the schema prompt.

4.3 训练模板匹配器4.3 Training the Template Matcher

我们使用 BIRD 基准的训练分割对 NLI 任务的 distilbert-base-uncased [26] 模型进行了微调（有关非合成工作负载使用的嵌入和 NLI 模型的详细信息，请参阅 A.3）。我们使用 OpenAI o3-mini 从训练集中为每个问题生成 20 个备用 NLQ，作为正对。为了训练模型，我们需要硬负例，我们使用余弦相似度来挖掘硬负例，并添加相同数量的负例对（带有未屏蔽的 NLQ）。此外，我们还添加了相同数量的带有 masked NLQ 的正负对，以使模型更加稳健。请注意，模板匹配器模型与数据库无关，并且与模板索引不同，它是跨数据库共享的。训练期间从中采样查询的数据库与测试期间使用的数据库是脱节的。该模型能够泛化，因为任务要简单得多——建立用户 NLQ 和屏蔽 NLQ 之间的语义对应关系（来自 I）。 BIRD列车提供了大量的例子。在 BIRD 训练集上进行训练不会给 BIRD 开发集带来不公平的优势，因为这些分片中的数据库完全不同。We fine-tuned the distilbert-base-uncased [26] model for the NLI task using the training split of the BIRD benchmark (See A.3 for the details on the embedding and NLI models used with non-synthesized workload). We generated 20 alternate NLQs per question from the train set using OpenAI o3-mini to serve as positive pairs. To train the model, we needed hard negatives, which we mined using cosine similarity and added an equal number of negative pairs (with unmasked NLQ). Also, we added the same number of positive and negative pairs with masked NLQ to make the model more robust. Note, that the template matcher model database-agnostic and is shared across databases unlike the template index. The databases from which queries are sampled during training are disjoint from the databases used during testing. The model is able to generalize because the task is much simpler — establishing the semantic correspondence between user NLQ and masked-NLQs (from I). The BIRD train provides a large number of examples. Training on BIRD’s train set does not give an unfair advantage on BIRD dev set because the databases in these splits are entirely different.

对于每个数据库模式，我们创建不同的模板索引，因为我们的模板引用模式的表和列名称。我们的系统旨在利用特定企业数据库的先前查询，以提高频繁查询的 SQL 生成性能。For each database schema we create a different template index since our template refer to table and column names of a schema. Our system is designed for harnessing the previously seen queries of a specific enterprise database, to improve SQL generation performance of frequent queries.

A.3 嵌入和 NLI 模型A.3 Embedding and NLI model

正如论文中详细介绍的，我们的模板匹配模块最初使用 NV-Embed-v2 模型来创建嵌入，并使用微调的 distilbert-base-uncased 模型来进行自然语言推理 (NLI)。在评估非合成工作负载时，我们更新了这些组件以使用更新的、最先进的模型。具体来说，我们现在使用 Qwen/Qwen3-Embedding-4B [39] 来生成嵌入，并为 NLI 分类任务使用微调的 Qwen/Qwen3-Reranker-4B [39]。核心方法不变：直接使用嵌入模型对候选检索进行初始相似性搜索，然后对重排序器进行微调并用作 NLI 模型来验证和选择最终模板。然而，我们发现使用来自同一模板的替代品的 NLI 分数平均值更好，并使用相同的方法来选择模板。As detailed in the paper, our template matching module initially utilized the NV-Embed-v2 model for creating embeddings and a fine-tuned distilbert-base-uncased model for the Natural Language Inference (NLI). While evaluating for the non-synthetic workload, we have updated these components to use more recent, state-of-the-art models. Specifically, we now employ Qwen/Qwen3-Embedding-4B [39] to generate embeddings and a fine-tuned Qwen/Qwen3-Reranker-4B [39] for the NLI classification task. The core methodology is unchanged: the embedding model is used directly to perform an initial similarity search for candidate retrieval, and the reranker is subsequently fine-tuned and used as the NLI model to validate and select the final template.
