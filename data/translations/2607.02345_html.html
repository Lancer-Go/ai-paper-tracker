SkillFuzz：在开放技能市场中模糊化技能组合以发现隐式意图SkillFuzz: Fuzzing Skill Composition for Implicit Intents Discovery in Open Skill Marketplaces

Jinwei Hu1, Yi Dong1, Youcheng Sun2, Xiaowei Huang1
摘要Abstract

基于大型语言模型 (LLM) 的代理通过可重用的技能、指导规划和执行的自然语言说明文档，越来越多地实现软件工程任务的自动化。开放技能市场使用户能够通过共同激活社区贡献的技能来组建代理，但市场运营商通常会单独审核技能。因此，个体良性技能可能会相互作用，将智能体重定向到意想不到的目标，我们称之为Large Language Model (LLM)-based agents increasingly automate software engineering tasks through reusable skills, natural-language instruction documents that guide planning and execution. Open skill marketplaces enable users to assemble agents by co-activating community-contributed skills, but marketplace operators typically audit skills in isolation. As a result, individually benign skills may interact to redirect an agent toward unintended objectives, which we term隐含的意图implicit intents。检测此类意图具有挑战性，因为效果只能通过技能组合来显现，执行环境在准入时通常不可用，并且可能的共同激活空间随着市场规模呈指数级增长。在本文中，我们将隐式意图发现表述为技能组合的模糊问题，其中技能组合是被测试的单元，规划工件在执行之前暴露代理意图，并且与无技能基线的偏差充当差异预言机。基于这个公式，我们建议. Detecting such intents is challenging because the effect emerges only through skill composition, execution environments are often unavailable at admission time, and the space of possible co-activations grows exponentially with marketplace size. In this paper, we formulate implicit-intent discovery as a fuzzing problem over skill compositions, where skill compositions are the unit under test, planning artifacts expose agent intent before execution, and deviations from a skill-free baseline serve as a differential oracle. Yet the rise of Large Language Model (LLM) based agents is reshaping this paradigm into a more automated agentic SE[32]。代理现在可以在推理时对不同的任务进行计划、推理和行动，越来越多地用灵活的语言驱动行为取代人类编写的逻辑. Agents can now plan, reason, and act across diverse tasks at inference time, increasingly replacing human-written logic with flexible, language-driven behavior[39, 18, 15]。开发人员和用户现在不再通过编写新代码来扩展代理，而是贡献和利用. Open skill marketplaces such as ClawHub[31]已经出现大规模托管和分发这些技能，用户只需选择一组技能并共同激活它们即可组装代理，然后代理可以根据其组合的指令上下文进行推理并执行相应的任务have emerged to host and distribute these skills at scale, and a user can assemble an agent simply by selecting a bundle of skills and co-activating them, whereupon the agent can reason over their combined instruction context and implement corresponding tasks[25].

然而，这种便利性带来了按技能内容审核无法解决的安全问题However, this convenience introduces a safety problem that per-skill content audits cannot address[9]。市场运营商汇集了许多独立开发者的贡献并承认它们进行发布，这一过程的运作规模使得对每个共同激活进行联合审查是不可行的。他们一般只验证每个说明文档不包含明显的恶意注入就上架. Marketplace operators aggregate contributions from many independent developers and admit them for publication, a process that operates at a scale where joint review of every co-activation is infeasible. They generally verify only that each instruction document contains no obvious malicious injection before listing[25]，基于结构上错误的假设，即组合个人安全技能会产生可靠的代理。当多种技能共同激活时，法学硕士将其文档作为统一的上下文进行处理，共同塑造代理人的, resting on the structurally false assumption that composing individually safe skills produces a reliable agent. When multiple skills are co-activated, the LLM processes their documents as a unified context, jointly shaping the agent’s信念状态belief state，其内部表示任务需要什么以及要采取什么操作。这种联合推理可以将代理重定向到意想不到的目标，并且与对抗性提示注入不同，任何单一技能都不需要携带恶意负载才能发生这种重定向。例如，考虑总结财务贡献的贡献分析技能和处理结构化数据的 csv 处理技能，每种技能都不会单独引发审计标志，但它们的共同激活会指示代理尝试修改超出其只读授权的原始数据集文件，这是两种文档中都不会单独出现的紧急副作用。我们将此类非预期目标称为, its internal representation of what the task requires and what actions to take. This joint reasoning can redirects the agent toward unintended objectives, and unlike adversarial prompt injection, no single skill need carry a malicious payload for this redirection to occur. II 背景及相关工作Background and Related Work

本节确立了我们方法的背景和动机。我们首先讨论代理人工智能如何催生技能市场以及由此产生的安全差距，然后阐明我们提出的方法与传统的基于模糊测试的软件测试有何不同。This section establishes the background and motivation for our approach. We first discuss how agentic AI has given rise to skill marketplaces and the safety gap this creates, then clarify how our proposed method differs from the traditional fuzzing-based software testing.

Ⅱ-AII-A 代理人工智能作为一种新的软件范式。Agentic AI as a New Software Paradigm.

基于 LLM 的代理迅速改变了复杂软件任务的自动化方式，超越了手写程序逻辑的限制，涵盖了曾经需要显式代码的角色，包括软件开发、存储库级错误修复、多步骤工作流程自动化和特定领域的决策LLM-based agents have rapidly transformed how complex software tasks are automated, moving beyond the constraints of handwritten procedural logic to cover roles that once required explicit code, including software development, repository-level bug fixing, multi-step workflow automation, and domain-specific decision making[13, 34, 14, 46, 16, 41]。这种转变的核心是共享架构模式，即“计划然后行动”循环，其中代理首先推理出一个结构化的自然语言计划，将目标分解为可操作的步骤，然后通过调用工具或外部服务来执行每个步骤. Central to this shift is a shared architectural pattern, the plan-then-act loop, in which the agent first reasons a structured natural-language plan that decomposes the goal into actionable steps, then executes each step by invoking tools or external services[47, 38, 12, 15]。开放技能市场允许用户通过社区贡献的说明文档组装代理，从而进一步扩展了代理的功能，从而极大地扩展了代理在不同领域的功能. Open skill marketplaces have further extended agent capability by letting users assemble agents through community-contributed instruction documents, dramatically expanding what agents can do across diverse domains[25, 23]。然而，这种灵活性带来了意想不到的风险缺口。单独的良性技能可能会在规划过程中共同产生意想不到的目标，而这些目标都无法单独编码，并且操作员在不执行代理工作流程的情况下无法检测到这种风险，因为他们无法访问具体的部署环境. However, this flexibility introduces an unexpected risk gap. Individually benign skills can jointly produce unintended objectives during planning that neither encodes alone, and operators cannot detect this risk without executing agent workflows, as they lack access to a concrete deployment environment[43]。现有的法学硕士代理人的安全性评估并未涵盖这一差距。即时注入和代理红队预先假定带有对抗目标的恶意工件和执行代理的沙盒环境. Existing safety evaluations of LLM agents do not cover this gap. Prompt injection and agent red-teaming presuppose a malicious artifact carrying the adversarial objective and a sandboxed environment in which to execute the agent[8, 48, 4, 36]，而技能市场引入的风险没有明显的恶意载体，必须在没有部署访问权限的情况下进行筛选。我们发现了这一差距，并观察到先计划后行动的架构本身就指向了技能意图测试的解决方案。由代理生成的计划级工件在任何工具运行之前将代理的意图具体化，因此在代理计划上进行测试既足以探测隐含意图，又由于缺乏技能市场端的执行访问权限而必需。, whereas the risk introduced by skill marketplaces carries no explicit malicious carrier and must be screened without deployment access. We identify this gap and observe that the plan-then-act architecture itself points toward a solution for skill intent testing. The plan-level artifact generated by agent externalizes the agent’s intent before any tool runs, thus testing at the agentic plan is both sufficient to probe implicit intents and necessary given the lack of execution access for skill marketplace end.

Ⅱ-BII-B 基于模糊测试的软件测试。Fuzzing-Based Software Testing.

基于模糊测试的软件测试自动生成测试输入以发现软件故障，无需手动指定Fuzzing-based software testing automatically generates test inputs to uncover software faults without manual specification[24, 50, 17]，覆盖引导的变体使用执行反馈来引导这一代, and coverage-guided variants steer this generation using execution feedback[7, 3, 28, 11, 1]。在这一传统中，定向灰盒模糊测试向目标站点添加基于距离的信号. Within this tradition, directed greybox fuzzing adds distance-based signals toward target sites[2, 19]，差异测试用跨执行的输出比较取代了崩溃预言, differential testing replaces the crash oracle with output comparison across executions[30]，最近的工作将 LLM 作为输入生成器嵌入到循环中, and recent work embeds LLMs as input generators within the loop[22, 42, 44, 45, 5, 49]，并进一步完善调度和变异策略, with further work refining scheduling and mutation strategies along the way[21, 27]。然而，所有这些技术都是为程序构建的，其中输入是语法性的，并且预言机可以简单地询问执行是否崩溃。代理系统通过自然语言进行推理，而算作错误的是计划的语义属性，而不是输入的编程属性。. However, all of these techniques were built for programs, where inputs are syntactic and an oracle can simply ask whether execution crashed. Agentic systems instead reason over natural language, and what counts as a fault is a semantic property of a plan rather than a programmatic property of an input.技能模糊SkillFuzz使模糊测试适应这种语义基础。它不是搜索代码中的语法或逻辑错误，而是搜索技能组合漂移到基于 LLM 的代理的信念状态并在没有任何部署环境的情况下运行的隐含意图。adapts fuzzing to this semantic substrate. Rather than searching for syntax or logic errors in code, it searches for the implicit intents that skill composition drifts into an LLM-based agent’s belief state and operates without any deployment environment.

七VII结论Conclusion

技能市场通过组合来扩展法学硕士代理，但组合恰恰是每项技能审核失败的地方，因为它必须检测的有害的意外目标可能只存在于联合教学环境中。在本文中，我们将隐式意图识别为代理人工智能和软件工程交叉点的一类新的组合缺陷。我们表明，一旦将规划层视为测试面，检测此类缺陷就可以采用有原则的、无需执行的公式。我们提出了 SKILLFUZZ，这是第一个用于组合技能市场的模糊测试框架，并证明了在规划级别进行定向、合同引导的搜索可以揭示严重的、与模型无关的组合风险。执行层验证进一步确认，当标记的技能组合实际运行时，这些风险就会出现。总之，这些结果将隐含意图确立为技能市场的系统属性，并将 SKILLFUZZ 定位为准入时间审核的实用补充，即使技能生态系统继续扩大，也能实现成分风险的免部署测试。Skill marketplaces extend LLM agents through composition, but composition is precisely where per-skill auditing breaks down, as the harmful unintended objectives it must detect may exist only in the joint instruction context. In this paper, we identify implicit intents as a new class of compositional defect at the intersection of agentic AI and software engineering. We show that detecting such defects admits a principled, execution-free formulation once the planning layer is treated as a testing surface. We present SKILLFUZZ, the first fuzzing framework for compositional skill marketplaces, and demonstrate that directed, contract-guided search at the planning-level can surface severe, model-agnostic compositional risks. Execution-layer validation further confirms that these risks materialize when the flagged skill combinations are actually run. Together, these results establish implicit intents as a systemic property of skill marketplaces and position SKILLFUZZ as a practical complement to admission-time audits, enabling deployment-free testing for compositional risks even as skill ecosystems continue to scale.
