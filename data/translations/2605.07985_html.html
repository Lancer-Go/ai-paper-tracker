Second, because simulators cannot recognize when two configurations invoke the same underlying computation, they re-profile each from scratch. 这两种限制都不是分析所固有的。两者都源于对法学硕士推理的结构性理解的缺失，我们通过两个观察建立了这种理解。 首先，每个操作的每个输入维度都源自两个来源之一：模型配置参数（隐藏维度、头数）或传入请求特征（令牌计数、批量大小）。 其次，许多模型配置值在模型之间重复出现，因此很大一部分操作是在配置之间共享的：具有相同注意力几何的模型调用相同的操作，而不管分词器的差异如何。 因此，通过原点标记每个维度，分析器可以检测配置之间的等效操作，并消除冗余的分析运行。Neither limitation is inherent to profiling; both stem from a missing structural understanding of LLM inference, which we build on through two observations. First, every input dimension of each operation derives from one of two sources: model configuration parameters (hidden dimension, number of heads) or incoming request characteristics (token count, batch size). Second, many model-configuration values recur across models, so a large fraction of operations are shared across configurations: models with the same attention geometry invoke identical operations regardless of tokenizer differences. Thus, labeling each dimension with its origin lets a profiler detect equivalent operations across configurations and eliminate redundant profiling runs.

8 局限性Limitations

绕过 PyTorch 调度程序的操作（Operations that bypass PyTorch’s dispatcher (例如，e.g.,在 Triton 中实现的ones implemented in Triton[35]) 可能缺乏内核级污点；然而，它们的封闭模块直接从跟踪源接收受污染的输入，因此调用图仍然被完全覆盖。 Dooly 的 Tainted Runner 目前跟踪文本提示，但污点传播与模态无关，并通过污染输入源扩展到视觉或音频；适应只需要识别服务引擎中新模态的请求入口点。 最后，Dooly 在随机专家路由下分析 MoE 内核，捕获平均专家延迟；对数据相关路由进行建模是模拟器的责任，超出了本文的范围。) can lack kernel-level taints; their enclosing modules, however, receive tainted inputs directly from the trace source, so the call graph remains fully covered. Dooly’s Tainted Runner currently traces text prompts, but taint propagation is modality-agnostic and extends to vision or audio by tainting their input sources; adapting only requires identifying the new modality’s request entry points in the serving engine. Finally, Dooly profiles MoE kernels under random expert routing, capturing average expert latency; modeling data-dependent routing is the simulator’s responsibility, beyond the scope of this paper.

9 结论Conclusion

我们提出了 Dooly，一个用于 LLM 推理模拟器的配置无关、冗余感知的分析框架。 Dooly 利用了这样一个事实：跨配置、操作共享通用的特定于模型的参数：污点传播在其源头标记每个张量维度，以实现跨配置重复数据删除，而分层上下文解析则重用服务引擎的逻辑来隔离有状态操作，而无需手动检测。 Dooly 使研究人员和从业人员能够评估和优化各种配置的服务策略，同时降低分析成本。We presented Dooly, a configuration-agnostic, redundancy-aware profiling framework for LLM inference simulators. Dooly exploits the fact that across configurations, operations share common model-specific parameters: taint propagation labels each tensor dimension at its source to enable cross-configuration deduplication, while hierarchical context resolution reuses the serving engine’s logic to isolate stateful operations without manual instrumentation.
