††脚注文本：footnotetext:通讯至：Correspondence to:yomri@stanford.edu, ziyu.gan@outlook.com

LLM 代理越来越多地部署在需要对长期交互历史进行持续推理的长期任务上。大规模实现这一点需要代理跨会话持久存储、检索和更新自己的内存。丰富的智能体记忆系统生态系统已经出现，涵盖平面检索、LLM 介导的提取、整合事实存储和智能体控制流。然而，它们的系统级行为仍然没有特征。我们提出了代理记忆的第一个系统特征。首先，我们引入一种面向系统的分类法，沿四个轴对代理内存系统进行分类。其次，我们构建了一个阶段感知分析工具，将成本归因于构建、检索和生成。第三，我们描述了两个基准套件中的十个代表性系统的特征，揭示了设计选择如何在写入和读取路径上转移成本。最后，我们得出 10 条系统建议，涵盖施工调度、能力底线、查询量摊销、新鲜度-延迟权衡和车队规模管理。LLM agents are increasingly deployed on long-horizon tasks requiring sustained reasoning over extended interaction histories. Realizing this at scale requires agents to persistently store, retrieve, and update their own memory across sessions. A rich ecosystem of agent memory systems has emerged spanning flat retrieval, LLM-mediated extraction, consolidating fact stores, and agentic control flows. Yet, their system-level behavior remains uncharacterized. We present the first systems characterization of agent memory. First, we introduce a system-oriented taxonomy classifying agent memory systems along four axes. Second, we build a phase-aware profiling harness attributing cost to construction, retrieval, and generation. Third, we characterize ten representative systems across two benchmark suites, uncovering how design choices shift cost across the write and read paths. Finally, we derive 10 system recommendations covering construction scheduling, capability floors, amortization via query volume, freshness-latency tradeoffs, and fleet-scale management.

2.1 代理内存执行管道Agent Memory Execution Pipeline

代理内存系统将交互流转换为持久状态，可以 在未来的代理调用中重用。尽管实现方式差异很大， 大多数系统可以分解为七个阶段：摄取、内存构建、 存储、检索、快速组装、生成和维护。Agent memory systems transform an interaction stream into persistent state that can be reused across future agent invocations. Although implementations differ widely, most systems can be decomposed into seven stages: ingestion, memory construction, storage, retrieval, prompt assembly, generation, and maintenance.

摄入。Ingestion.摄取阶段接收原始交互流，其中可能包括用户辅助对话、工具调用、文档、执行跟踪和环境反馈。摄取定义了内存处理的单位：单独的回合、固定大小的块、滑动窗口或完整的会话。这种选择决定了写入粒度和下游构造操作的数量。The ingestion stage receives the raw interaction stream, which may include user-assistant dialogue, tool calls, documents, execution traces, and environmental feedback. Ingestion defines the unit of memory processing: individual turns, fixed-size chunks, sliding windows, or complete sessions. This choice determines write granularity and the number of downstream construction operations.

记忆建构。Memory construction.我们使用We use记忆建构memory construction表示从原始交互历史记录到持久内存记录的写入路径转换。施工采用以下四种形式之一：to denote the write-path transformation from raw interaction history into persistent memory records. Construction takes one of four forms:缺席absent（历史记录直接保留在提示中），(history retained directly in the prompt),确定性的deterministic（没有任何法学硕士的分块或索引），(chunking or indexing without any LLM),LLM介导LLM-mediated（在预定义点提取事实、摘要或结构化记录，可选择添加、更新或删除对先前记忆的整合），或(extraction of facts, summaries, or structured records at predefined points, optionally with add, update, or delete consolidation over prior memories), or代理的agentic（LLM 控制的写入、工具调用和记录突变）(LLM-controlled writes, tool invocation, and record mutation)[packer2023memgpt, chhikara2025mem0, xu2025amem, wang2025mirix].

存储。Storage.存储阶段将构建的内存保存在系统特定的代理数据库中，该数据库不一定是向量存储。存储器可以存储为原始提示缓冲区、倒排索引、密集向量索引、知识图或多存储组合耦合词汇、向量、图和结构化元数据。存储基底决定内存占用、更新成本、索引重建要求和可用的检索运算符。The storage stage persists constructed memories in a system-specific agent database, which is not necessarily a vector store. Memories may be stored as raw prompt buffers, inverted indices, dense vector indices, knowledge graphs, or multi-store combinations coupling lexical, vector, graph, and structured metadata. The storage substrate determines memory footprint, update cost, index rebuild requirements, and available retrieval operators.

检索。Retrieval.检索阶段选择与当前查询相关的内存记录。检索范围从单次稀疏或密集搜索到结合稀疏搜索、密集搜索、图遍历、重新排序和过滤的多级管道。在代理系统中，检索成为一个以工具为中介的控制循环，其中法学硕士决定何时进行搜索、查询哪种内存类型以及检索到的证据是否足够。The retrieval stage selects memory records relevant to the current query. Retrieval ranges from a single-shot sparse or dense search to multi-stage pipelines combining sparse search, dense search, graph traversal, reranking, and filtering. In agentic systems, retrieval becomes a tool-mediated control loop where the LLM decides when to search, which memory type to query, and whether retrieved evidence is sufficient.

迅速组装。Prompt assembly.检索到的记忆在生成之前被序列化到最终的模型上下文中。此阶段是外部存储系统和 LLM 服务堆栈之间的接口，产生最终应答生成调用的预填充长度。Retrieved memories are serialized into the final model context before generation. This stage is the interface between the external memory system and the LLM serving stack, yielding the prefill length of the final answer-generation call.

一代。Generation.生成阶段在当前查询和组装的内存上下文上调用任务 LLM。所有代理内存系统都汇聚于此，但到达时具有不同的提示长度和先前的编排成本。两个系统可能使用相同的 LLM 并产生相似的答案，同时施加截然不同的写入路径和读取路径工作负载。The generation stage invokes the task LLM on the current query and assembled memory context. All agent memory systems converge here, but arrive with different prompt lengths and prior orchestration costs. Two systems may use the same LLM and produce similar answers while imposing very different write-path and read-path workloads.

维护。Maintenance.维护阶段通过重复数据删除、整合、冲突解决、遗忘、压缩或重新嵌入来更新代理生命周期内的内存。在许多当前的系统中，维护很弱或不存在：内存无限期地累积，没有新鲜度或修剪策略，这对于状态持续增长并可能变得冗余或陈旧的长寿命代理至关重要。The maintenance stage updates memory over the agent’s lifetime through deduplication, consolidation, conflict resolution, forgetting, compression, or re-embedding. In many current systems, maintenance is weak or absent: memory accumulates indefinitely with no freshness or pruning policy, which becomes critical for long-lived agents where state grows continuously and may become redundant or stale.

5 讨论与结论Discussion & Conclusion

本文首次介绍了代理内存工作负载的系统特征。 在跨越四种范式的十个代理记忆系统中，我们发现占主导地位的 代理内存的成本不是查询时服务而是构建，并且 施工以结构嵌入和预填充为主，直接 当位于同一服务上时，延迟敏感的 QA 流量会产生压力 堆栈。秒中介绍的分类法。This paper presents the first systems characterization of agent memory workloads. Across ten agent memory systems spanning four paradigms, we find that the dominant cost in agent memory is not query-time serving but construction, and that construction is structurally embedding and prefill-dominated, and in direct tension with latency-sensitive QA traffic when co-located on the same serving stack. The taxonomy introduced in Sec.2.2预测这个 行为：范式成员资格决定构建成本形状、嵌入流量 模式、对构造模型选择的能力敏感性和检索尾部 宽度，使其成为超越代表的部署决策的系统镜头 此处评估代理记忆系统。 一些开放的挑战超出了我们当前的范围。多节点和多代理 部署引入了跨分布式的一致性和协调性要求 单节点表征无法捕获的内存存储。多模式记忆，持久保存和检索图像、音频和结构化观察 文本，是一个新兴且不太成熟的前沿领域，我们预计它将放大 建设成本、存储空间和检索复杂性挑战 此处确定。这项工作中开发的分类法和分析方法 为描述这些更丰富的环境的成熟特征提供了基础。predicts this behavior: paradigm membership determines construction cost shape, embedding traffic pattern, capability sensitivity to construction-model choice, and retrieval tail width, making it a systematic lens for deployment decisions beyond the representative agent memory systems evaluated here. Several open challenges extend beyond our current scope. Multi-node and multi-agent deployments introduce consistency and coordination requirements across distributed memory stores that single-node characterization cannot capture. Multimodal memory, persisting and retrieving images, audio, and structured observations alongside text, is an emerging and less mature frontier that we expect will amplify the construction cost, storage footprint, and retrieval complexity challenges identified here.
